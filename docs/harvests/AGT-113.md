# AGT-113 — premise revalidation: DEAD

**Verdict:** the defect AGT-113 names does not exist for `docs/RUNNER-GOV-M6-REQUIREMENTS.md`, and
the fix it prescribes would *remove* a guarantee that is already stronger than the one it asks for.
Recommend: close AGT-113 as premise-dead (no build, no kickoff).

## 1. What the ticket asserts

> "all 13 live M6 rules appear byte-verbatim as blockquotes with `canonical_doc` pointing at that
> file, and none sits under a `{{rule:ID}}` marker, so a registry edit leaves the hand-typed copy
> stale with nothing to catch it"

Two clauses. The first is **true**. The second — *"with nothing to catch it"* — is **false**, and it
is the whole load-bearing clause.

## 2. The file is the canonical home, and an unmarked quote in a canonical home is the definition,
not the defect

`docs/governance/RULES-SNAPSHOT.md:137-149` — all thirteen rows `M6-01`..`M6-13` carry
`canonical_doc = docs/RUNNER-GOV-M6-REQUIREMENTS.md#<own id>`.

`scripts/check-session-docs.js:1473`, inside `checkRuleTextOutsideHome()`:

```js
      if (rel === home) continue;
```

Check 12 — the check whose finding text the ticket paraphrases ("Render it instead: add the marker
and run `node scripts/render-rule-blocks.js --write`") — **skips a rule's own canonical home by
construction**. The marker exists to protect *restatements elsewhere*; the home copy is the thing
those restatements are compared against. Asking the home to carry a marker is asking the source to
cite itself.

Measured, not reasoned: `node scripts/check-session-docs.js` this session emits **zero** check-12
findings naming `docs/RUNNER-GOV-M6-REQUIREMENTS.md` for any `M6-*` rule. `node
scripts/render-rule-blocks.js` (default scan) emits **zero** findings mentioning that file at all.
The two tools AGT-113 invokes are already silent about it.

## 3. What actually guards this file is stricter than a marker

`tests/regression/ses-285-m6-autonomy.test.mjs`:

- `:110` — `M6_IDS = Array.from({ length: 13 }, ...)`; all thirteen, not the eight of the original gate.
- `:147` — `parseCanonicalDoc()`, regex `/^###\s+<a id="(M6-\d\d)"><\/a>[^\n]*\n+>\s(.+)$/gm`.
- `:176` — assertion 1: `doc.get(id) === r.statement`, byte-for-byte, quantified over all 13 ids.
- `:471` — `doc.size` must equal `M6_IDS.length`; a lost section is a red, not a silent skip.

Assertion 1 is graded **twice**: once over `RULES-SNAPSHOT.md`, once over the rows fetched live from
`public.governance_rules` (`theLiveRegistryAndBoardAgree`, `:413`). Run live this session with
credentials present — the suite prints exactly one `[NOT RUN]` (assertion 6's declared SES-386
retarget) and **`[PASS] ses-285-m6-autonomy.test.mjs`, exit 0**, so the live arm ran.

Now compare the two mechanisms on the exact failure the ticket fears — *someone edits the registry
row and the doc goes stale*:

| | `{{rule:ID}}` marker (`render-rule-blocks.js`) | `ses-285` (today) |
|---|---|---|
| compares against | `docs/governance/RULES-SNAPSHOT.md` only (`render-rule-blocks.js:61`, hard-fail if missing) | the offline snapshot **and** live `public.governance_rules` |
| catches a live-row edit before re-export | no | yes |
| covers | whichever quotes carry a marker | all 13, enumerated, plus a section-count assertion |

A registry edit that has not yet been re-exported is invisible to the marker mechanism and red to
`ses-285`. The ticket asks to add the weaker of the two to a file that already has the stronger one.

## 4. And the marker cannot coexist with the guard — re-measured

Probe at `scratchpad/agt113-probe.mjs`, importing the guard's own `parseCanonicalDoc`, re-run this
session against the real file:

```
BASELINE: 13 anchored rule sections (expected 13)
AFTER the rendered-block transformation: 0 sections
ISOLATED (a) prefix only:  13 sections | M6-01 => "**Rule M6-01** — No cycle may block..."
ISOLATED (b) marker only:   0 sections | M6-01 => undefined
```

Two independent kills, exactly as AGT-94 measured on its own twin:

- **(a)** `renderBlock()` (`scripts/render-rule-blocks.js:160`) emits `> **Rule ${id}** — ${statement}`.
  The sections still parse, but every captured statement now carries a `**Rule M6-NN** — ` prefix the
  registry row does not, so assertion 1's byte-for-byte equality fails 13/13.
- **(b)** The marker comment sits between the heading and the blockquote; the regex requires `\n+>`
  adjacency, so `parseCanonicalDoc` finds **zero** sections and `:471` fails first.

## 5. No narrower buildable variant exists

I looked for one and there is none worth building:

- *Marker + relax the guard* — that is AGT-94's revert reason verbatim ("RECONCILING THEM MEANS
  CHANGING THOSE GUARDS' ASSERTIONS"). It trades a live-registry byte check for a snapshot-only
  one. Strictly negative.
- *Marker after the blockquote, or a fenced variant* — `render-rule-blocks.js:80` recognises a marker
  only when `{{rule:X}}` is the first token of an HTML comment **above** the block it owns; moving it
  is a renderer change, not a doc change, and buys a weaker check.
- *Teach `parseCanonicalDoc` to strip the prefix* — the guard would then stop proving the doc says
  what the row says, which is the one property this file exists to have.

Every variant pays real bytes to make an existing, stronger guarantee weaker (pattern:67 — a
proposed element must justify itself against a bound that already exists; pattern:17 — extend the
structure that fits rather than stand up a parallel one).

## 7. Recommendation

Close `AGT-113` premise-dead with this harvest as the evidence. Keep `AGT-94` open on its own merits:
its twin file `docs/RUNNER-GOV-M5-REQUIREMENTS.md` has the same structural question, and the *real*

guards — a format decision, not a doc sweep. AGT-113 adds nothing to that call: its file is already
pinned to the live registry, which is the outcome the marker was only ever a proxy for.
