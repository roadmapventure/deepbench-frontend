## 2. Alternatives, and why the kickoff takes the one it does

- **A graded non-gating key in `scripts/verifier.js`** — the disposition `v7.0.644` filed and wrote into `ARCHITECTURE.md` §19v. **Rejected as unsound, and the doc is amended in the same ship (pattern 94):** the verifier runs at step 7a (`runner-cycle.md:3022`) and the ship card is filed at step 9 (`:4000`), so at grading time the card does not exist. This is not a guess — AGT-199 already shipped a finding kind, `state-render-card-missing`, whose whole reason for existing is that ordering. A key that reads a card the cycle has not written yet would report "not measured" on every honest cycle. It also self-certifies: `scripts/verifier.js` is in `SELF_CERTIFYING_PATHS`, so the ship that edits it forfeits the auto-done bar.
- **A completeness refusal in the same trigger.** Rejected for the reason `v7.0.644` measured and this session re-measured: 72 of 131 handles unlisted means a `BEFORE` refusal bricks step 9 for 40 of 58 cards. Completion is the same rule with the opposite failure direction.
- **Runbook prose telling step 9 to call the renderer.** Rejected. It costs the runbook trio (a `cycle-card.md` re-render and a `ses-413d` re-pin, 737 B of headroom left after R1) and it is the class of rule this platform has watched go unfollowed eight times (`SES-86` phase 3 onward). Pattern 10: when the correct value exists deterministically, no writer is put in charge of remembering it.
- **Appending in `render-claude-state.js` instead of the table.** Rejected: it fixes the bullet and leaves the row — the dashboard, the briefing and every later reader still see a partial card. One change, every home (pattern 163) means the row.
- **A second trigger, or a new table of recorded handles.** Rejected: `runner_record_citation_guard()` already fires `BEFORE INSERT OR UPDATE` on exactly the two tables and the columns that carry this text. A third block inside it is the whole change (pattern 17, and R1's own shape).

## 3. The order inside the function, and why it is not cosmetic

Blocks 1 and 2 refuse; block 3 appends. The append must run **last**, over the writer's own text: **3 of 285** `runner_decisions.summary` rows from the last 7 days cite a backlog row whose status is `removed`, so appending before block 1 would refuse a card because of a sentence the renderer wrote. Once appended, the same text is in `OLD` on every later write and block 1's grandfather clause keeps it silent. Block 2 is unaffected either way: `note_unverifiable_commit_shas` matches only a hex token following a commit claim, and **0 of 285** summaries carry one.

## 4. Sizing and downstream safety

Appended text measures **188 B on an average card and 861 B at worst** (the per-card sum of the missing `handle_sentence` values). `skeletonChars()` (`render-claude-state.js:211`) excludes bullet lines, so `SES-177`'s size guard does not see it, and `bulletProvenanceFinding` compares uuids against the cycle's own `runner_decisions` ids — the appended ids are exactly that set, so it stays null. `runner_items` and `runner_cycles` carry no length CHECK (six CHECK constraints between them; all are enum or format tests).

## 5. What this ship does not do

- **Two handles in four days were decided after their card was written** (`AGT-108` ticket-status +4h27m, `AGT-171` gate +15m). The trigger is `BEFORE INSERT OR UPDATE OF` eight text columns, so a later decision reaches the card only if a text column is updated afterwards. Named in the kickoff, not fixed: the alternative is an `AFTER INSERT` trigger on `runner_decisions` that updates the card, which re-enters this guard with the appended text as NEW and could abort a decision write — a far worse failure than an unlisted handle.
- **No backfill.** The 72 historical omissions stay as they are; only rows touched after the migration complete themselves. Task 3 touches the one row the ticket names.
- **Gate cards are out of scope** (`kind = 'ship'` only): a `gated_before_build` card is written before any handle exists.
- **R2 stands** and is the last remainder: the exclusion reason must come from `prime_directive_queue()`'s own predicate. Its `buildable` CTE carries ~12 exclusion clauses (`docs/design/agt-140-project-priority-pick.sql:511-573`); doing it honestly means extracting that WHERE into one shared core the queue and a per-ticket reason reader both call (pattern 14), not a second copy. Its own cycle, and it is the one remainder that touches the pick path — `AGT-173` cannot be written `done` before it.
