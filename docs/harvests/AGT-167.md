## 2. The design, and why this shape

**One predicate, plus the one function that cannot read it.** The ticket's own preferred fix: hoist the test into `pick_exclusions()`, so both ticket lanes of the queue, `project_blockers`, `gate_before_build`, `parent_score_probe`, `scripts/run-project.js` and `scripts/ticket-owner.js` read one clause and one sentence. `drain_epic_next()` keeps its own WHERE (AGT-173 set down folding it into the core: retirement semantics, side effects, its own census), so it gets the same test as one clause plus a census bucket — the bucket is the reason AGT-221 was once its own ticket (SES-196: a rejection with no census line is a silent empty).

**Why a new function, `noship_streaks()`.** `pick_exclusions()` speaks for all 1,617 board rows. Calling `ticket_noship_cycles()` once per row was measured live at **3,682 ms** (every row) and **1,517 ms** (open and partial rows only) on top of the function's own 713 ms; each call scans `runner_cycles` (2,965 rows, primary key only) and its `coalesce(b.backlog_id, c.item_id) = $1` cannot use an index. PostgREST cancels an rpc at 8 seconds. Computed once for the whole board the same rule costs **5.0 ms** (`EXPLAIN ANALYZE`, live: one seq scan, two hash aggregates, 98 rows out), and joined to `pick_exclusions()` back to back in one statement: 714 ms plain, 716 ms joined. No index is needed and none is added. To keep one home (pattern:14), `ticket_noship_cycles(text)` becomes a one-row reading of the new function — same identity, same grants. Live, read-only, before designing: the set form and the present function agree on all 1,617 board rows and on all 98 tickets that have a streak (0 mismatches).

**Open and partial rows only.** The clause is the pick's fence, so it speaks where a pick is possible. AGT-337 (`done`, streak 4) does not grow a second sentence beside "status done is not open or partial".

**Lane (c) drops its copy.** The streak now arrives through `buildable`; leaving the lane's own test would keep a live comment that says `pick_exclusions()` "deliberately carries no clause for it". It also removes 55 per-row calls from every queue read.

**The written rule moves in the same transaction (pattern:94).** OD-21 says the drain is "deliberately NOT fenced (`AGT-221`)". AGT-221 was the ticket to fence it — "left untouched on purpose" for want of the census bucket and AGT-167's then 22-file allowance — and it was removed unbuilt at the 2026-09-27 epic lock (AGT-688 lists it among the forty). So the sentence records a deferral, not a ruling against fencing, and this build is that deferred work. ## 4. Alternatives I set down

1. **The clause in `drain_epic_next()` only.** The ticket's first option. Leaves lane (b) of the queue page unfenced and still gives a held row no reason anywhere — half of (a), none of (b).
2. **The hold as a `gated_before_build` card** filed when a ticket reaches the cap (the card already takes a ticket out of both homes and puts it in front of the Development Manager). Attractive because the ruling would be the release. Set down: `gate_before_build()` writes `needs-desktop` ("waits on a session you attend"), so it would route every held ticket to John; it needs a writer on `runner_cycles` close; and a streak that resets on a ruling is a change to the count's rule. It is the shape R1 should weigh.
3. **Call `ticket_noship_cycles()` only for rows with no other reason** (55 rows, about 125 ms). Cheap, but a held row that is also flagged would not name its streak — and `pick_exclusions()` exists to give every reason.
4. **Retyping the three bodies into the migration.** 47 KB of transcription to prove; the splice makes byte-exactness a property of the mechanism (pattern:3).

## R. Three findings for T4 to file (none is this ticket's text)

**R1 — nothing but a ship or a terminal ruling releases a held ticket.** The streak ends only at a `shipped` cycle. A ticket ruled "re-scope, keep the id" stays at the cap and stays out of every lane; until v7.0.1104 a drain naming it was the unintended way back, and this build closes that door on purpose. Lane (c) has behaved this way since v7.0.642. What is missing is a recorded ruling that ends the streak (alternative 2 in §4 is one shape). It lets an agent put a held ticket back in the pick, which changes agent autonomy, so by the risk rule it is its own ticket. Evidence: `ticket_noship_cycles` / `noship_streaks` bodies; AGT-471 (open, 4 `gated_before_build` cycles 2026-11-15 to 11-18) is the first live row it will matter for once its flag clears.

**R2 — the weekly `board-repeat-worked` check counts lifetime non-shipping cycles, the fence counts the streak since the last ship.** `scripts/audit-board.js` `cycleCounts()` (lines 124-135) skips shipped cycles and never resets at one; `ticket_noship_cycles()` was changed to a streak in v7.0.946 and the JS twin was not. So the weekly list can name a ticket no lane is holding (the AGT-304 shape: many ships, old failures). After this ship it can read `rpc/noship_streaks` and stop being a second computation.

**R3 — the streak counts cycles that never attempted the ticket.** Of 232 ticketed non-shipping cycles, 153 are `gated_before_build`, 37 `failed`, 23 `did_not_run`, 17 have no outcome yet (in flight) and 2 `reverted`. `governance_rules` M6-11 says a ticket skipped because a rule filtered it "is not a no-ship, and never counts toward … a ticket's stuck count". The rule of the count is v7.0.946's and this build proves it did not move (gate arm 1); whether `did_not_run` and in-flight cycles belong in it is a separate question, and it matters more now that the hold is in every lane. AGT-237's 7 include 1 `did_not_run`.

Also seen, not filed by me: three `ZFIX-…` fixture rows from earlier test runs are still on the board (`ZFIX-64653` and `ZFIX-16727489` `removal proposed`, `ZFIX-42435609` `removed`), none from this pass.

CREATE OR REPLACE FUNCTION public.noship_streaks()
 RETURNS TABLE(backlog_id text, noship integer)
 LANGUAGE sql
 STABLE
AS $function$
  -- AGT-167 (v7.0.1104). THE ONE HOME of the no-ship streak: for every ticket with at least one,
  -- its non-shipping cycles since its last ship. A ticket with none has no row -- read it as 0.
  -- The rule is public.ticket_noship_cycles()'s own (v7.0.946), computed for the whole board in one
  -- pass so pick_exclusions() can read it without one scan of runner_cycles per ticket.
  with mine as (
    select coalesce(b.backlog_id, c.item_id) as backlog_id, c.started_at, c.outcome
      from public.runner_cycles c
      left join public.backlog_items b on b.id = c.backlog_item_id
     where coalesce(b.backlog_id, c.item_id) is not null
  )
  select m.backlog_id, count(*)::int as noship
    from mine m
    left join (select s.backlog_id, max(s.started_at) as last_ship
                 from mine s
                where s.outcome = 'shipped'
                group by s.backlog_id) ls on ls.backlog_id = m.backlog_id
   where m.outcome is distinct from 'shipped'
     and m.started_at > coalesce(ls.last_ship, '-infinity'::timestamptz)
   group by m.backlog_id;
$function$;

$function$;
