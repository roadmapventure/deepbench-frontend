## 3. Alternatives considered

**A. Build the fence on the uncorrected total-cycle measure (the ticket's literal words).**
Rejected. It would have excluded SES-424 after 4 of the 8 slices that finished it, and SES-422
after all 4 of the slices that finished it — turning a report that is wrong into a stop that is
wrong. `pattern:1` (eliminate the problem, don't bound it) and `pattern:162` (a check grades the
change, never the live world).

**B. A new `runner_settings` column for the per-ticket cap.** Rejected for this ship. It is the
cleaner semantics — Gate D's per-chain streak and a per-ticket no-ship count are different measures
(`SES-435` item (2) says so in its own words) — but `pattern:67` asks a new knob to justify itself
against a bound that already exists, and no row is within one cycle of either bound. The coupling
is instead **stated** in `governance_rules` OD-21, which is exactly the remedy OD-22's proposal 9
offers for the sibling case ("either promote the window to a column beside the ceiling it bounds,
**or state the coupling in the registry**"). If a later session wants the split, OD-21 now names
what it would be splitting.

**C. Fence `drain_epic_next`'s pick predicate too.** Deferred to its own row. Every exclusion in
that predicate carries a matching census bucket in the `v_pick IS NULL` branch and a term in the
`v_detail` sum — `SES-196`'s "never a silent empty", extended by SES-281, SES-305, SES-310 and
SES-424 slice 3. A fence without its bucket is the silent empty that branch exists to forbid, and
with it the change is a 28,264-byte re-emission of the body `AGT-109` cut out of `AGT-88` precisely
because it is VOLATILE, writes before-images on every call, and "is the one whose typo stops
picking entirely." Fencing **only** lane (c) also keeps `prime_directive_queue` lane (b) in
agreement with `drain_epic_next` — the property that pair of functions exists to hold.

**D. Fence the shared `buildable` CTE instead of lane (c).** Rejected: `buildable` feeds lane (b)
too, so fencing it would make the briefing page hide a named drain member that `drain_epic_next`
still picks. `buildable` stays the single admission predicate, untouched.

## 4. The guard test, and why repairing it is in scope

`tests/regression/agt-86d-board-checks.test.mjs:232-237` runs the real CLI against the live board
and asserts `board-repeat-worked` carries a finding at `backlog_items:SES-424`. That is an arm
pinned to a **mutable live occupant**: half (a) makes SES-424 terminal and half (b1) drops its
no-ship count to 0, so any correct repair of the thing it points at breaks it. Baseline run this
cycle: the file is **green** today, with credentials present, so the breakage is certain rather
than hypothetical. `pattern:124` — a bug a change introduces is fixed inside that change. The
replacement asserts the contract (every emitted finding names a non-terminal row whose no-ship
count is ≥ N), which survives any future board.

The fixture arm at `:82-95` keeps passing by accident — its cycle objects carry no `outcome` key,
and `undefined !== 'shipped'`. That is why Task 4 adds an explicit all-shipped negative: without
it, Task 2's change has no arm that would notice if it were reverted.

## 8. What the BUILD paid for that the design did not know

Everything in §1-§7 was measured at design time. These seven were bought at build time, each by a
refusal or a rollback, and each is the reason a later session should not re-derive it.

**(a) The lane anchor is ambiguous, and the migration caught itself.** `FROM buildable bu` occurs
**twice** in `prime_directive_queue` — occurrence 1 is lane (b) `drain`, occurrence 2 is lane (c)
`selfbuild`. Attempt 1's guard raised *"expected exactly 1 … found 2 — refusing to guess which lane
is the selfbuild one"* and applied nothing (confirmed: `ticket_noship_cycles` did not exist
afterwards). Lane (c) is uniquely identified by **closing the CTE**, so the anchor that shipped is
`E'    FROM buildable bu\n)'`, with the one-hit count asserted inside the migration. A
programmatic edit is only as safe as the uniqueness of its anchor, and the assertion is what makes
the difference between an edit and a coin flip.

**(b) Read the CHECK before writing a probe that moves a setting.** Attempt 2's probe did
`update runner_settings set chain_max_noship_streak = 0`, and
`ck_runner_settings_chain_streak` is `CHECK (>= 1 AND <= 20)`. The whole migration rolled back
atomically — correct behaviour, wasted cycle. The shipped probe uses **1**, the lowest legal value,
inside a subtransaction that is always rolled back.

**(c) The probe's lane-(b) half is VACUOUS, and saying so is the point.** The drain lane returns
**0** rows live, so both arms' *"the drain lane did not change"* assertion compares two empty
arrays. "The fence is confined to lane (c)" therefore rests on the source anchor in (a) and on the
selfbuild arithmetic, **not** on an observed drain row. An assertion over an empty set is not
evidence, and a later session reading only the migration would take it for some.

**(d) The filing contract is written down nowhere, and one of its five clauses fails SILENTLY.**
Task 1's INSERT was refused four times, each rolling back atomically (the id counter returned to
218 every time, so no ids were burnt — verified, not assumed): `tier` is NOT NULL with no default;
`ck_backlog_type_when_promoted` requires `type` on any tier other than `later`;
`ck_before_image_attribution` permits exactly ONE of `cycle_id` / `session_name` (the same shape as
`ck_decision_attribution`). Those three refuse loudly. The fourth does not: **`SES-295` / `M5-03`**
means a row whose `filed_at` is past `runner_settings.filing_lane_cutoff` with a blank
`scope_rationale` is **not buildable** — it lands successfully and then never appears in
`prime_directive_queue()` at all. A cycle that files without asserting its row REACHED the queue
files invisible tickets and never finds out. Task 1's own filing asserts it, in both directions
(AGT-219/AGT-221 present, AGT-220 deliberately absent because its project is paused).

**(e) `capture_migration_down()` cannot express a grant revert.** The down it generated for
`agt167_close_counter_execute` is a `CREATE OR REPLACE` of the function plus the overload assertion
— and `CREATE OR REPLACE` does **not** restore an ACL. So the captured down is honest about the
definition and silent about the privileges it was captured for. Classified `auto-downable`, which
for a grants-only migration overstates what running it would undo.

**(f) The fence's own migration tripped a `.claude/rules/` invariant.** Functions in this project
default **OPEN** — `pg_default_acl` grants EXECUTE to `anon`/`authenticated`/`service_role` by name
the instant one is created (`supabase-column-grants.md`, `SES-315` addendum), and
`agt167_noship_pick_fence` did not close `public.ticket_noship_cycles(text)`. Found by this cycle's
own Builder while reviewing a task that was not its own. Sized before acting rather than announced
as a breach: the function is SECURITY INVOKER and `runner_cycles`/`backlog_items` carry **zero**
anon/authenticated grants, so the call is refused under `SET LOCAL ROLE anon` either way — a latent
hygiene gap, never a live leak. Closed anyway in `agt167_close_counter_execute`, asserting both
directions plus that `prime_directive_queue()`'s own call still works.

**(g) The ship's own headline number moved, twice, and both moves are the ticket's point.** The
kickoff predicted `board-repeat-worked` going **3 → 0**; the real runs read **2 → 0**. Task 1 had
already taken SES-378 and SES-424 out of the population (a terminal row cannot fire) and AGT-168
had accrued cycles in the meantime. Both survivors were false positives under the corrected
measure — `ticket_noship_cycles` reads **1 of 7** for AGT-168 and **0 of 4** for SES-422. The
fence ships **latent**: at the live cap of 4 it refuses nothing today, and the four-state fixture
is the only proof it bites at all.
