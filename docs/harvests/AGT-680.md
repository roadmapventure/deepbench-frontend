## The choice

**Chosen: the reorder (the ticket's own stated fix).** Door (d) runs `--next` first and writes the
marker after it, naming the ticket the pickup printed. One runbook, one new test. Reach: the text a
redesign-first cycle reads; 0 rows, 0 functions. Undo: one `git revert`.

**Not chosen: `p_cycle` on `redesign_due_ticket()`.** It needs a migration, the zero-argument overload
dropped in the same migration with one `pg_proc` row asserted, the three named roles revoked, and
`runner_should_boot()` — which calls the zero-argument form in its facts row — re-pointed or left on
an argument-less path; `--next` would need `--cycle-id`. That is DDL on the boot gate to fix an
instruction that was simply in the wrong order. Pattern:8, pattern:65.

**Not chosen: the script writes the marker itself** (`--next --cycle-id`). Attractive (no model in
charge of the order), but it gives `redesign-pickup.js` a write on `runner_cycles`, which its own
header refuses ("this file owns none of them"), and the durable home for the cooldown is AGT-689's
decision, not this ticket's.

## What the fix does not do

1. **Durability (AGT-689, open).** The marker lives in `last_step`; step 0b's heartbeat overwrites it
   at every step boundary. Measured this cycle: marker written, next heartbeat, `AGT-251` named again.
   After this ship a door-(d) cycle picks the right ticket, but the 24-hour cooldown holds only while
   that cycle's `last_step` keeps the `redesign: <id>` prefix. The new door text says so and names
   AGT-689. AGT-689's own description states the reorder does not reach it; it is a separate, already
   filed ticket, so this is not a cap case and nothing was split or narrowed: every sentence of
   AGT-680's own text is satisfied by the reorder plus the two-direction measured run.
2. **The window between gate and pickup.** Two parallel redesign-first cycles can both run `--next`
   before either marks, and take the same ticket. The old order had the same window between its
   marker and nothing atomic. `open_redesign_attempt()` owns the attempt count; not measured here.
3. **`docs/runbooks/runner-cycle.md` L183** names the marker's format (`last_step` `redesign: <id>`)
   and points at this runbook; it states no order, so it is not wrong after the ship. The file is at
   380,973 bytes against agt-138's 380,980 ratchet, and any edit changes the card's sha line and
   makes it a fourth file. Left untouched on purpose.
