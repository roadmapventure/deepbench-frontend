## Design decisions, with the alternatives they beat

- **Week-two observation rows are produced by code and landed by John's hand.** `carryForward` re-observes an open finding only when this week's corpus still holds ≥ 2 of its sides (the same test `priorClusters` uses for "runnable"), copies the finding fields byte-for-byte so the fingerprint is identical, and writes it into the candidates file under `carried`. `--ingest` classes it `recurring` and appends it with `--apply`. Alternative (a): the cycle appends carried rows itself — rejected: 4d rule (1) and the L test both say only John's hand ingests, and a carried row is still an append to an append-only table nobody has re-read this week. Alternative (b): no observation rows; the brief and report derive "still open" from the latest row — rejected: slice 1's `unique (fingerprint, iso_week)` and `first_seen` were designed for observation rows, and only the weekly run can say whether the finding's evidence is still in the corpus (`gone` is that answer). Consequence stated plainly: the brief's latest-week table shows carried findings only after John lands the week's file; carried and new arrive in one file, so one `--apply` lands both — there is no partial state to forget.
- **`gone` is reported, never ruled.** A finding whose sides no longer locate has probably been fixed; the code says so with `located/total` and John sets `resolved`. Code never writes a status.
- **`ruled-out` by fingerprint OR by ≥ 2 shared homes.** The seed's guardrail is by fingerprint, but a model re-finding a ruled dispute words the fact differently (slice 2's measured reason for `reconcile`); the ingest gate uses both, the same 2-home rule `reconcile` uses, so the two dedups read alike. A `resolved` fingerprint seen again is `recurring` (appended): a regression is a fact worth a row, and the report's `First seen` line shows the history.
- **`recurring` includes the fixture's two resolved findings on a W38 re-ingest.** They arrive carrying `status: resolved` and land as resolved W38 copies. Harmless (a record) and only reachable by re-ingesting the fixture by hand; `carryForward` never carries a non-open row. Stated so nobody "fixes" it into a silent drop.
- **The stale detector imports `supportsTemperature` rather than restating the family.** Precedent: `scripts/check-anthropic-quota.js:43` imports from `../shared/models.js`. A literal `claude-fable-5-1` here would be a third home for the fact, which is the duplication this agent exists to find. The finding's last location is symbolic (`shared/models.js:NO_TEMPERATURE_PREFIXES`) rather than a line number, because `locationKey` strips only `:digits` and a line number drifts with every edit above it.
- **One finding with N locations, not N findings.** Matches the ledger's `4ef228c3` shape (one fact, eight locations) so `reconcile` re-finds it by shared homes rather than filing 22 rows.
- **The self-audit does not parse the seed SQL.** A second parser of Skill text is a second reading of it; the seed's six `NULL` temperatures are one grep (test P asserts exactly 6 `6000, NULL, 'platform'` and 0 `6000, 0, 'platform'`), and the live instrument (`--agent=<id>`) runs the day the rows exist. Exit 2 on zero rows is deliberate: `audit-corpus.js`'s own header refuses the false all-clear.
- **Fixtures are mapped to real rels by the test, not named after them.** `extractMarkdown(rel, text)` is pure; the test hands it `docs/runbooks/runner-cycle.md` etc. so the ledger's location keys match, while the files live under `tests/fixtures/` where check-session-docs does not scan them as governance. `db.json` carries the database-side statements directly in the statement shape (the extractor's DB half needs credentials and is the CLI's, not the fixture's).
- **No brief change.** `renderAuditLedger` filters open rows to the latest week; with carried rows landed weekly that is correct. Widening it to "latest row per fingerprint, any week" was considered and left out: it changes a generated doc's meaning with no John decision on record and costs a re-render; the failure mode it would guard (a week ingested without its carried block) cannot occur from one file.

## CLI

- **`audit-ledger.js --ingest`**: findings = `[...doc.findings, ...(Array.isArray(doc.carried) ? doc.carried : [])]`; one read `audit_findings?select=fingerprint,iso_week,status,locations&or=(fingerprint.in.(<all fps, comma-joined>),status.eq.not-a-defect)`; `classifyIngest(findings, rows, week)`; with `--apply`, for each `new` or `recurring` verdict in order: before-image first, then `toRow(finding, {week, foundBy, cycleId, id})` (unchanged call; `toRow` now honours `finding.found_by`, `finding.ruled_by`, `finding.ruled_at` when present); print `ingest <week>: <N> findings, <new> new, <seen> seen, <recurring> recurring, <ruledOut> ruled-out`; exit `!apply && (new + recurring) > 0 ? 1 : 0`.
- **`audit-corpus.js --agent=<id>`**: refuse with exit 2 when combined with `--no-db` or `--corpus`. Reads, in order: `agents?select=id,bio&id=eq.<id>`; `agent_capability_assignments?select=capability_slug&agent_id=eq.<id>` → `caps`; `capabilities?select=slug,description&slug=in.(<caps>)`; `capability_skill_profiles?select=skill_profile_slug&capability_slug=in.(<caps>)` → distinct `slugs`; `skill_profiles?select=slug,objective,method,output_desc,description,notes,traits,guardrails,llm_model,temperature,max_tokens&slug=in.(<slugs>)`. Zero Skill rows → stderr `audit-corpus: --agent=<id> has no Skill rows (no such agent, or no capability links) -- not run (exit 2 = could not run, never a pass).`, exit 2. Otherwise statements = `extractSkillRows(rows)` + capability descriptions + the agent bio (same shapes as `databaseStatements`), no files, `liveRuleTexts = []`; then the normal detect/print path.
- **`audit-corpus.js` summary and `--detect`**: `findings = [...detectDuplicates(statements, liveRuleTexts), ...detectStaleParameters(statements)]`; `--detect=<json>` writes `{findings}`; bare `--detect` prints `  duplicate · <locations joined " == ">` lines as before and `  stale-or-irrelevant · <n> locations` for the stale finding; the last line is `statements N (governance a, agent-data b, retired r) duplicates d stale s`.
- **`audit-cluster.js --collect`**: after the cluster loop, `const { carried, gone } = carryForward(rows, statements, week)`; doc = `{week, found_by: \`auditor:judgment:${firstModel || "none"}\`, note (unchanged), findings: newFindings, carried, gone}`; print `collect <week>: <C> clusters, <K> returned, <D> dropped, <R> re-found [<fps>], <E> exact, <X> ruled-out, <N> new, <carried.length> carried, <gone.length> gone -> <out>`. With `--no-db` rows are `[]` so both are 0.
