## 2. The design, and what it does not do

One pure function, `benchGroupsFor(groups, sharing)`: a private row is in the Private group only; any other row keeps its static groups with `"private"` removed. `tableOnlyAgent()` calls it with `[]`, `buildRoster()` applies it to every AGENTS entry whose row the read returned. With her static value set to `[]`, no AGENTS entry is private and the column is the only home: a static `"private"` could not make an agent private against a public row even if someone added one.

Why `buildRoster()` and not `mergeRoster()` (D1): `mergeRoster()` is the AGT-006 overlay, pinned by agt-006, and AGT-335/336/386 each left it unedited on purpose; `buildRoster()` is where the sharing rules already sit (the viewer filter, `isArchivedPrivate`). The prototype left agt-006, agt-335, agt-384 and agt-386 green.

Why Private ONLY (D2): `RosterScreen.jsx:241` lists a group by `benchGroups.includes(activeFilter)` and "All" is every non-private agent, so an agent in both `mi` and `private` would be missing from All and present under the `mi` group. AGT-332 chose "Private only" for her; the rule keeps that for every agent.

D3, the honest cost: `useRoster()` renders `rosterCache || AGENTS` before the read lands (AGT-006 D4). Her static entry is now `[]`, so on a cold first mount she is under All until the rows arrive, and stays there if the read fails. The three live table-only private agents (`marko-6mzcln`, `marko-fsoh0f`, `matt-chester-iuxls6`) already appear only when the read lands, so the Private group already fills on arrival; the settled view is identical to today's. Not verified in a browser.

D4: W lives in this harvest, which the platform commits, instead of a `docs/design/*.sql` mirror - a sixth file is over the 5-file cap and the gate ruling names the five. D5: her live `sharing` is not pinned by a test (pattern:162 - a check grades the change, not the live world; a reversal is a legitimate path and must not turn a test red). agt-164's live arm is left as it is.

Alternatives rejected: keep both homes and add a drift check (the defect stays, pattern:1, pattern:93 - already rejected by the cap ruling of 2026-11-10); set her row to private and leave the static value (two homes that happen to agree today); derive in `isPrivateAgent()` from a `sharing` field carried on the roster entry (every screen and three tests read `benchGroups`; a wider change for the same result).
