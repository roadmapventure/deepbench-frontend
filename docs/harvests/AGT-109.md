## What the ticket got wrong, corrected in the kickoff

The noship COALESCE is **not unregistered** — `OD-21` exists and states it: "read by
`public.drain_chain_gate()` with a COALESCE fallback of 2". What it lacks is a reader amendment,
not a home. And `chain_max_noship_streak` is NOT NULL with **live value 4**, not 2, so the fallback
has never once fired. Dropping it is value-preserving by construction, not by measurement.

## Why the QA is shaped the way it is

The reason this ticket was cut out of slice 1 is that `drain_epic_next` cannot be proven by "call,
apply, call again": it is VOLATILE and writes before-images and retirements on every call, so the
second call is not the same experiment, and calling it mid-chain mutates the runner's own record.
The answer is not to avoid calling it — it is to call it inside a single-statement
`BEGIN; …; ROLLBACK;`, which makes the call repeatable (every call starts from the same committed
state) and harmless (nothing commits). The same wrapper then carries the settings controls, which
is why QA B is a control per home rather than a digest comparison.

The controls are run **before** the migration as well. That is the whole discriminator: on the
unchanged tree `claim_stale_hours = 2` cannot move `backlog_mode`, because the function does not
read the column. If it moves before the migration, the experiment is void — hence the stop line.

`backlog_mode` is the cheap half: pure SQL, STABLE, four scalar arguments, no writes. One call with
a 3-hour-old claim discriminates the whole OD-08 change in one round trip.

## Alternatives considered

- **A static-only QA** (no literal left in the bodies). Rejected alone: it proves the text changed,
  never that the function reads the home. Kept as task 5 alongside the behavioural arms.
- **Two migrations, splitting `drain_epic_next` from the two small ones.** Rejected: one
  `CREATE OR REPLACE` each, no signature change, no dependency between them — two capture/apply
  pairs buy nothing and double the window in which one home has two readers (pattern:163).
- **A new test file.** Rejected: `agt-88-constant-homes.test.mjs` already owns this seam and its
  `EXPECTED` map must be edited anyway, since amending the registry breaks its AGT-109 assertion.
  A parallel file would leave the broken one red (pattern:17).
- **Registering the noship fallback as a new OD row.** Rejected: OD-21 is the home; a second row
  for the same fact is the defect this epic exists to remove.

## Risk notes carried into the kickoff

- Grants checked, both directions: `anon`/`authenticated` hold nothing on `runner_settings`, on the
  `backlog_active` view (which calls `backlog_mode`), or on the three functions. Making a pure
  function read a table is exactly the change that would 403 a public reader; here there is no
  public reader, so `supabase-column-grants.md` does not bind.
- A plpgsql CONSTANT initialiser evaluates at block entry, so a missing `runner_settings` row would
  leave `c_lane_cut` / `c_stale` NULL and silently empty the pick — a silent empty being precisely
  what `drain_epic_next:264` exists to prevent. Hence the explicit raise, which doubles as QA B's
  fail-closed control.
- The settings UPDATE inside a transaction locks row id=1 against parallel cycles (SES-382), so
  every control is one round trip and short-lived.
