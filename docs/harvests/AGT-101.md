## Alternatives considered

1. **Update the numbers to 4 ticketed / 2 resolved.** Rejected: it re-arms the same trap for the
   next ruling, a Reverse, or a carry into W38. pattern:1 — eliminate, don't bound.
2. **Delete part F's census entirely.** Rejected: the week's filing is real coverage (it is what
   proves the ingest landed and the guard protects it); only the *status count* is the defect.
3. **Restate the six statuses as a literal array in the test.** Rejected on the file's own stated
   rule (above) — a duplicate that silently agrees until it doesn't. One deliberate literal
   survives, in the task-3 assertion that pins `LEDGER_STATUSES` to what
   `audit_findings_status_check` names, so a schema change reddens once, on purpose.
4. **Assert the CHECK constraint live from the test.** Rejected: PostgREST cannot run that SQL and
   the test has no SQL channel; adding an RPC for it is a bigger change than the ticket.
