## 2. Where the 6,000 comes from

Its only home is `tests/regression/SES-177-claude-state-renderer.js:58`. `docs/kickoffs/v7.0.228-SES-177-claude-state-renderer.md` carries no `6000` / `~6k` (grep: zero hits); the message's "14,355 before the split" is the pre-split file size. The split (John's gated decision `37b22393`, 2026-08-24) moved the standing judgment paragraph — 7,643 chars then and now — into the brief, and the clause was written to catch that paragraph coming back. It measured the whole file because at v7.0.228 the whole file was ~2.4k and the paragraph alone was three times the bar; nobody was measuring the bullets, which carry `plain_after`/`plain_worth` prose that `SES-380` correctly says nothing bounds.

## 3. The three candidates, and why one wins

**(a) Renderer emits fewer sessions or a tighter per-session form.** Loses on three counts. Fewer than three bullets changes what John reads at the top of every session — a content decision with no John record. A per-bullet budget is truncation of his plain-language ship summary to satisfy a test, and its bar is still a fixed number chosen against prose whose length nothing bounds — it bounds the output, but by throwing away the part that was written for him. And it changes `renderBody` bytes, so the moment it lands every committed file on dev is drift under the pin (`SES-261`) until re-rendered — a red-by-construction cycle for no gain.

**(b) Move the ~6k bar with a stated reason and a new number.** Loses because the input is unbounded: the file was 6,443 at 20:5xZ and 5,044 at 23:5xZ on the same evening with no code change. Any whole-file number is a coin flip on the next verbose chain (and the `AGT-70` double render shows a single long card can appear twice). It only postpones — the constraint the ticket itself names.

**(c) Measure the part that is not a function of the ledger.** Chosen, with one correction to the ticket's wording: `CLAUDE-STATE.md` has **no** hand-maintained part any more — everything from `# DeepBench — Current State` to the `GENERATED` marker is `renderBody` output; the hand-maintained prose is in the brief. What the size clause was actually guarding is that the moved prose *stays moved*, and a re-inlining lands in the non-bullet part of the file. So the clause measures the **skeleton** — every line that is not a `- ` session bullet — which is bounded by construction (charter and paragraph constants, two version lines of fixed-width fields, one heading, one marker, ten uuids): 2,070 live, 2,096 on the long-sha fixture. Bar 3,000: ~900 above the widest honest skeleton, ~4,700 below the smallest undo. Plus a direct string clause (`**Next session:**` absent), which is the cheapest possible statement of the split holding in both directions — line 48 already asserts the string is present in the brief.

**Why it is not vacuous.** It fails on the undo fixture (skeleton ≥ 9,700) and on the string clause; the control asserts a *difference* on the ledger-growth fixture (old bar fails at 17,483, new passes at 2,096) and a *shared* failure on the undo fixture — the SES-213 / SES-261 pattern. Any other hand-edit is already caught by the pin-anchored `--check`, which stays the authenticity gate.

**What it does NOT do.** It does not bound the file's total length; a verbose chain can render 10k+ chars, and the charter's "keep it short" is now enforced only on the skeleton. If bullet length becomes a reading problem that is John's decision (truncate, fewer sessions, or a shorter `plain_after` convention on ship cards), not a guard's. It does not touch SES-213's ordering (render precedes the verdict at 7a — unchanged) or SES-261's pin, and it does not settle `SES-380`'s second half ("whose job the render is" / a hard freshness bound), which `SES-261` deliberately left as a separate ticket.

## 4. Renderer helper vs test-local filter

The `- ` filter could live in the test alone (two files instead of three). It goes in the renderer because that is where `renderBullet` defines the prefix, and every predicate in this test is imported from the script (DIR-603f44ea / SES-176). The rot direction is benign either way — a changed prefix would count bullets as skeleton and go red, never green — so this is the repo's idiom, not a safety argument.
