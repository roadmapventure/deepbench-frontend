## 4. The risk reading, and why staging

- The capability row, the Skill row and the link are not reachable through the ordinary doors while no
  agent holds the capability: `assembleCapabilityRows()` drops a holderless capability from `tools/list`
  and `tools/call` (`api/_lib/mcp.js`), `resolveCapabilityHolder()` throws "No agent currently holds
  capability" (`api/capabilities/execute.js:579`), and the agent-wide prompt path loads Skills only
  through assignments (`api/prompt/db-assembly.js:846`). **What this does not close:** a caller already
  inside the gate that names `capability_slug` and an `agent_id` directly still assembles the Skill —
  the executor's single-capability path does not check the assignment. I did not design a fix for that;
  it is pre-existing and true of every capability.
- The assignment row is the only one that changes what an agent may do: it puts the Skill in Susan's
  agent-wide prompt, lists `agent-authoring` to every MCP caller on the product lane (Susan is `product`,
  active), and makes a `claude-opus-5` call at `max_tokens 8000` available per use. It lands alone, last,
  under its own decision, so the undo is one row and John's approval covers one identifiable act.
- Is that row "a part that changes agent autonomy" that must ship as its own ticket? My reading: no.
  The capability is proposal-only (`requires_human_confirmation: true`, handler `store`); nothing Susan
  produces takes effect unsigned, and no ladder rung or auto-done setting moves. It is a permission
  change, which is John's alone (clause 7) — and the whole ticket is already gated on him. I name the
  disagreement surface here so the Development Manager can rule otherwise; I did not split the ticket.
- All four tables are in `rpc/reversible_tables` (17 names, read today), so `reverse_decision` is a real
  undo for T1 and T4.

## 5. Calls I made (reversible), beyond the kickoff's D1–D5

- In-process `runCapability()` instead of an HTTP POST: no base URL, no gate header, same executor.
- `any_agent: true` is passed by the caller script itself. It is a server-side script holding the service
  key, not an MCP client; `governance_unlocked` is NOT passed, so governance-, personal-lane and inactive
  targets stay refused. That keeps malcolm's 51 private documents out of reach by construction.

  `shared/models.js` `MODEL_PRICING['claude-opus-5']` ($0.005 / $0.025 per 1k), against the Lanes band
  $0-1. Above it the caller refuses rather than truncating (pattern:34). Chunked reading is not designed.
- No baseline was run: the related set for three new files is empty, which makes
  `scripts/pre-build-baseline.js` measure the full live suite — not worth spending in a cycle that builds
  nothing. The build measures it first.
