## 3. The redesign — staging, and why

The prior Task 2 changed two things at once: where Brent's Identity / Knowledge / Guardrails text comes from, and which REFLECT call runs (new prompt, new sections, new log row). They carry different risk:

| part | what changes | provable from | undo |
|---|---|---|---|
| A (this kickoff) | assembly source: `skill_profiles` via `assemblePrompt()` + `enrichPrompt()` | stored rows and file text, no model call | git revert of one file |
| B | REFLECT moves to `dan-ai-enrichment`; `callReflect()` leaves the route | only a live model call (`reflect_ran`, the `ai_activity_log` row, reading the plan) | git revert |
| C | `api/brief.js` leg, five analysts, delete `assembleContext()` | five capabilities seeded, live briefing A/B | revert + seed down |

Part A is separated because it is the part whose proof needs nothing but rows, and because §2 shows part B is a bigger content change than the prior design measured. That is the engineering reason for the staging: smaller reach (no model call added, changed or moved; retrieval query byte-identical via D2) and the part needing live-model evidence stands alone.

It also means this cycle's build has no step that needs a model API key, so the refused credential read is not sent, not routed through another tool and not reworded — the step that needed it is not in this stage at all. Part B is named in the STOP LINE as blocked for an unattended cycle, not disguised. The header refusal: the kickoff gives each header line verbatim so it is written once; if the classifier refuses any step anyway, the kickoff orders `--refuse` and a stop, no retry.

This is not a cap split: part A uses 2 files / 3 tasks of 3 / 4. It is the risk rule's staging call (parts with different risk are staged; none is irreversible or changes agent autonomy, so none is forced to be its own ticket), and it continues the scope call v7.0.723 already recorded (Brent first, ticket stays open). AGT-017 stays `partial`; parts B and C stay on the ticket (pattern:95 — its own "retire it" sentence is not refiled under a new id).

## 5. Alternatives rejected

- **Ship the prior Task 2 whole and defer only the REFLECT check.** Ships a changed model call (new prompt, Dan's sections in Brent's prompt) to dev with no evidence it works for Brent. Against the self-test rule, and it leaves the risky half unproven rather than unshipped.
- **Rewire with no REFLECT at all.** `executionPlan` would come back empty: a regression for Brent's runner.
- **`task_context.goal = taskDescription`** (the prior design). Changes the retrieval query string in a stage that cannot observe retrieval (no embedding key here either). D2 keeps `queryText`, byte-identical to today. Cost: the CURRENT TASK section reads `Goal: <url> government spending data download …`; part B will revisit when REFLECT also reads `task_context.goal`.
- **A control arm in the test.** `assemblePrompt` with no `capability_slug` returns the same 5 sections (it resolves the agent's assignment), so that is no control. `match_count` 10 against the default 5 is the row-derived fact; the static arm is the no-op discriminator.
