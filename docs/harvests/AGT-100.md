## 3. Alternatives weighed
- **Detect the checkout with rev-parse, then list** — two git calls where one suffices: `ls-files` itself exits 128 with the same `not a git repository` text outside a work tree. Rejected.
- **Keep the listing private to audit-corpus.js** (narrowest edit, pattern:65) — would leave two definitions of "tracked file" in the Auditor's two scripts, free to drift (pattern:14 says one shared core when two paths compute the same thing). The shared `trackedFiles()` costs one export and keeps `scanTree`'s behaviour byte-identical. Chosen.
- **Fall back to the disk walk on any git failure** — a missing git binary would silently read untracked data again, the very bug. `trackedFiles` returns null only for `not a git repository`; every other failure throws and audit-corpus exits 2 (pattern:165 fail closed, same convention as the script's other exit-2 lines).
- **Change --extra-root to refuse non-checkouts** — arm A's temp fixture and any ad-hoc folder root would break; the ticket names only the checkout case. Non-checkouts keep today's walk.
- **A new test file** — the residue note says "one function, one test arm; slice 6's file". Arm G in agt-86f, so the extra-root behaviour has one home.

## 4. What this does not do
- It does not filter tracked files by .gitignore rules for non-checkouts, and it does not read files a checkout has staged-then-deleted (git lists them; readFileSync fails; skipped — same as today's unreadable-file path).
- It does not change the corpus statement count on this repo's own half (corpusFiles() untouched) nor the summary line agt-70 parses.
