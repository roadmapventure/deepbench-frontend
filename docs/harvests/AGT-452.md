## 3. Form of the record (why this shape)

The ticket binds the file to agt-281's form: a header in prose, then one SQL block that asserts its own QA. agt-281's block is an applied migration (INSERTs); this ticket records and must not change a row, so the block is an asserting DO block: it reads each row by slug, compares every content column to a dollar-quoted literal (`$r452$...$r452$`, jsonb columns compared as `::jsonb`), counts each of the six bindings by all five columns, requires the capability's total to be 6 (both directions: nothing lost, nothing added), and raises `AGT-452 drift: <slug>.<col>` on the first difference. It writes nothing, contains no DELETE and no DROP (the MCP channel hangs 60 s on either), and can be run through execute_sql as a second, database-side drift check. Columns recorded: the 20 content columns (PCOLS); excluded: id, created_at, updated_at, created_by_*, updated_by_* (identity and bookkeeping, not the rule). Bindings recorded by capability_slug, skill_profile_slug, level, is_required, display_order (not id).

"Read from the database and not retyped" is met mechanically: `scripts/victoria-rows-mirror.js --write` performs one fixed PostgREST read and writes the section between two markers itself. The Builder never pastes MCP output (execute_sql returns JSON with escaped newlines; pasting 16 KB of that is retyping by another name). The markers follow the runbook-block convention `check-routine-prompt.js` already uses (`extractBlock`, BEGIN/END once each), pattern:17.

## 4. The guard (why byte equality)

The test imports the script's own `renderRecord` and `fetchRows` (SES-45: never re-implement the thing under test), renders the live rows, and compares the result to the file's section byte for byte. Any edit to any recorded column, any binding change, any lost row, and any hand-edit of the file turns it red with the first differing line. The offline arm proves the comparison can see one byte (a two-row fixture with one byte of one method changed renders differently) so arm B's green is not vacuous, and proves the tag-collision guard throws. Without credentials arm B declares NOT RUN by name (SES-180), never a silent pass. The MD5 comment line per row lets a human reader spot which row moved at a glance and lets QA 1 compare to `select slug, md5(method)` live.

## 5. Designer's calls (reversible, JOHN-0925-DESIGNER-DECIDES)

(i) Generated, never pasted or typed; a script, not a query the Builder copies.
(ii) An asserting DO block as the SQL form: agt-281's shape (a block with its own QA) without agt-281's writes.
(iii) Record the four rows the ticket names plus all six bindings. The north-star's text is not recorded (it is John's page with its own before-image mechanism) and vc-process-break-class's text is not (its mirror is docs/design/agt-309-process-break-class.sql); their bindings are.
(iv) Byte equality of render(live) and the file, with the one-byte control; no "contains phrase" assertion as the primary guard.
(v) The runbook's prompt block is byte-unchanged (check-routine-prompt.js compares it to the live routine); the runbook gains one stamp line and one bullet outside the block. ARCHITECTURE gains the one amendment header line. No CLAUDE-STATE edit here (the cycle's own).
(vi) Caps: 5 files / 5 tasks against 48 / 49. Natural size.

## 6. Alternatives not taken

- A plain INSERT mirror (restorable by applying it): a file that writes rows is one accidental apply away from changing the rows the ticket says not to change; and `reverse_decision()` plus the before-images are the restore path the platform already has.
- A test that only asserts the file exists or holds a phrase: cannot see drift, which is the whole ticket.
- Storing the rows in the test as fixtures: two homes for one fact (pattern:93); the file is the record, the test reads it.
- A generic "dump any skill row" tool: wider than asked (pattern:66); the four slugs and one capability are constants of the script, and a later ticket can widen them.
