# SES-64 — Regression test #24's outcome class was hardcoded rich-answer, even when the article was degraded

Moved here 2026-08-01 (`design-ses-64` close-out) per `CLAUDE-DESIGN.md`'s row-length-cap convention (`docs/FEATURES.md`'s row exceeded 2000 chars). `docs/FEATURES-ARCHIVE.md` carries the condensed shipped version; this file is the full investigation history.

## Original finding and investigation (as filed/amended in `docs/FEATURES.md`, 2026-07-29 through 2026-07-31)

**`Beta-gate (bucket 1)`. Regression test #24 is hardcoded `outcome_class: "rich-answer"`, but when the article cannot be read the *correct* answer is an honest gap — so the run fails a correct answer on the wrong rubric. Found live 2026-07-29 (`S-SES-62` QA), measured on the first run that could reach a verdict since `CHI-92`.** `scripts/chi-true-regression.mjs:191` sets the class statically; every other case gets it from `HONEST_GAP_IDS` (`:188`). But #24's class is not a property of the question — it depends on whether that run's card happened to be readable. On the QA run the Apple newsroom card returned **401**, `article_degraded: true`, and Marcus Webb — GEO CSO Expert correctly produced an honest gap: *"The article from Apple's newsroom could not be retrieved — the platform was unable to access the full text. I'm working from the headline alone"*, then reasoned from two cited Data Room facts. Owen — Proofreader scored it against the rich-answer bar and failed the single criterion `actionable_guidance_present`, critiquing that it "stops at retrieval instructions rather than delivering actionable channel positioning guidance." **`case_pass: false` on an answer that did exactly what `ci-answer-intent` instructs.** This is precisely the failure `AGT-36` built the `honest-gap` class (§5b, scored at `:349`) to fix — #24 is the one case that never got wired to it, because its class was written before the class existed. **Fix:** make #24's `outcome_class` conditional on that run's `article_degraded` — `honest-gap` when the article could not be read, `rich-answer` when it could. The value is already computed in `runNewsDoorCaseJourney()`; the ordering (class is needed by `scoreVerdict` during the journey, degraded is known before the answer call) needs checking. **Until this lands, a bucket-1 run reports a false FAIL on #24 whenever the card's article is unreadable.**

**Amended 2026-07-30 (`design-arch-beta-0729` pre-regression round 2) — the outcome is nondeterministic, and the other direction is worse.** Ran #24 on the deployed preview with `article_degraded: true` (same 401-class degradation this row describes) and it returned **`case_pass: true`, all three artifacts passing** — not the false FAIL predicted here. Cause: rich-answer `pass` comes from Owen's own holistic flag (`:364`, see `SES-65`), which varied between runs; on this run all three looped criteria passed while `asked_metric_present` was `false` and structurally invisible. **So a degraded, unread article can be analyzed and scored green.** That is a false PASS on the "nothing lying" bar, and it compounds with `CHI-95` (`api/fetch-article.js` returning 200 with a conversational refusal as article text). This row's fix is still correct and still needed; the justification strengthens — the current behavior is not "sometimes too harsh," it is *unpredictable in both directions*. **Round 3 (2026-07-30) observed the false-FAIL direction this row originally predicted**, completing the pair: same degraded-article condition, `case_pass: false`, `answer` failed `platform_language_detected` for honestly disclosing *"MacRumors headline only, no access to full article."* So the two rounds bracket the behaviour — green in round 2, red in round 3, same code, same condition.

~~**But reclassifying #24 to `honest-gap` will not by itself make it pass:** `AGT-53` shows the Guardrails Skill penalises the disclosure the honest-gap class requires, so this row and `AGT-53` have to land together or #24 simply fails the same criterion under the new class.~~ **Struck 2026-07-31 (`design-arch-beta-0729`, round 5): that pairing claim rested on the retracted "standards conflict" theory — `AGT-53` is a retired stub (content on `AGT-50`), and the conflict does not exist (`platform-language-guardrail` clause 3 permits gap disclosure). Measured proof in round 5: with the guardrail delivered (`AGT-44`/`AGT-54`, v7.0.7), Marcus Webb — GEO CSO Expert's degraded-article answer passed `platform_language_detected` outright, and on that run's own evidence it would have cleared all three honest-gap checks (`asked_metric_present` explicitly false, `actionable_guidance_present` true, no platform language). This row lands ALONE and very likely flips case 24 green by itself.** `CHI-95` remains related-but-independent (upstream honesty of the degradation signal), not a co-requisite. Four measured occurrences as of round 5: R2 green / R3 red / R4 green / R5 red on the same degraded condition.

## Design session (`design-ses-64`, 2026-08-01) — verification and kickoff

Verified live in code before writing the kickoff: `ctx` (the per-case scoring context) is a single mutable object threaded by reference through `runOneCase()` → `executeCaseJourney()` → `runNewsDoorCaseJourney()` → `runDirectCaseJourney()` → `judgeArtifact()` (which reads `ctx?.outcome_class`) → `finalizeCase()` (which records it). `runNewsDoorCaseJourney()` already computes `articleDegraded` (via `resolveNewsCardContext()`) *before* it calls `runDirectCaseJourney()` — so the ordering question this row raised checks out: setting `ctx.outcome_class` right after `articleDegraded` is known is sufficient, no reordering needed.

Also found in the same read: the console progress line's `[honest-gap]` marker (`classMarker`, `runOneCase()`) reads `caseObj.outcome_class` — the static per-case tag, never mutated — so it could never show for case 24 even after this fix. Folded into the same kickoff (John's approval, same conversation).

This is a runbook §8 baseline change (§5b: "Adding or removing a question from this class is a baseline change... John's approval") — case 24 is **not** added to `HONEST_GAP_IDS` (still fixed-membership, question-id-keyed); its class is computed per-run instead, a structurally different mechanism. Runbook §0/§5b/§7 amended in the same commit to document the new rule.

Kickoff: `docs/kickoffs/v7.0.23-SES-64-news-door-honest-gap-scoring.md`.
