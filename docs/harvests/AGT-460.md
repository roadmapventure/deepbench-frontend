Two consequences the kickoff carries:

- **§3e stays in `session-setup.md`.** It is a close step, and moving it would break five
  `ses-311` clauses whose slice boundary is `### 4.` in the same file. Keeping it also leaves
  `agt-451` untouched: its two pins are `node scripts/pre-build-baseline.js --kickoff=<the kickoff
  path>` — which also sits on `session-setup.md` **line 1**, so it survives the move regardless —
  and `  --pre-build-baseline=$S/pre-build-baseline-<the supervised cycle id>.txt` at `:493`,
  inside §3e.
- **`ses-320` needs a structural edit, not a path swap.** Its file-level negative control reads
  `git show <PRE_CHANGE_SHA>:<c.file>` and `catch`es a failure into `notRun`. Switching its
  constant wholesale would make that control silently vacuous — green, proving nothing — because
  `session-decisions.md` does not exist at that commit. So the clause gets a `beforeFile`
  (`before[c.beforeFile ?? c.file]`) and the control keeps reading `session-setup.md`.

The kickoff hands the builder the grep rather than the ten lines, plus the rule "a clause switches
only when its own asserted text moved", plus the two mixed files by name and the `ses-320`
exception. That is deterministic (a clause whose text moved fails when the file is run) and it
costs 400 bytes less than the enumeration.

## 4. The four feature calls (recorded, reversible; JOHN-0925-DESIGNER-DECIDES)

1. **The service key stays, behind one named module.** `scripts/lib/session-db.mjs` is the only
   file in the build that reaches Postgres; it exits 2 `no-credentials` without
   `SUPABASE_URL`/`SUPABASE_SERVICE_KEY`. The ticket's own sentence files the narrow-database-
   function credential design under Security separately, so building those functions here would
   scope the work to a dependency that has not landed (pattern:68). The module is the single seam
   that ticket later replaces (pattern:14/15).
2. **The split is one cut, not seven** — 110 "step N" citations keep the steps where they are; 43
   §3c-§3g citations move. Splitting per-section would strand the 110.
3. **The length rule amends `CAP-SESSION-SPLIT-SIGNS`** rather than adding a rule id or a Section 2
   list item (pattern:17). Section 2's own note says the rule numbers are load-bearing —
   `tests/regression/SES-61-suite-invocation.js` slices "rule 5" by its literal opening and eight
   files cite "Section 2 rule 5"/"rule 7" — so a new item renumbers all of them. The amendment
   appends a sentence between the pattern:172 sentence and the closing "Wall-clock duration is not
   a split trigger" one, which it does not contradict: ticket count and context size are not
   wall-clock.
4. **"Load the memory index and CLAUDE-DESIGN.md on demand" is out of scope here.** No artefact
   named "memory index" exists; what a session loads up front is set by `CLAUDE.md`'s router, and
   the ticket's own last sentence rides the `CLAUDE.md` half with the lean-lane escalation.

Dropped since pass 1: the `docs/design/agt-460-session-length.sql` mirror (the migration's text is
in Supabase's own migration history, and the 45 bytes bought a task fact elsewhere) and the
`.claude/skills/session-setup/SKILL.md` pointer edit (the loader still correctly points at the

## 7. Alternatives considered and dropped

- **Scripts only, no doc split.** Cheapest and it does remove the measured cost — but it leaves
  the procedure in two live homes, and pattern:95 forbids discharging one of the ticket's own
  sentences.
- **Keep the 900-line file and add a line-range index at the top.** Line ranges drift with every
  edit to the body; that is the defect, re-filed as a navigation aid.
- **A `docs/runbooks/session-setup/` subdirectory.** `buildProcedureDocs()` never recurses, so the
  parts would leave check 13's field of view — a quieter tree, not a safer one.
- **Hardcode 4 and 250,000 in the scripts** instead of the migration. Contradicts Section 2's own
  "thresholds are stored columns, never literals" and the ticket's "tested rather than asserted"
  (pattern:2, pattern:93).
- **Move §3e with the rest.** Semantically defensible (it is a verdict procedure) but it breaks
  five `ses-311` clauses and `agt-451`'s §3e pin for no reader benefit: it is run at close-out,
  which is exactly when a session is in `session-setup.md`.
