## 2. What is NOT proposed, and why

A `run-all.js`-side reclassification — a declared list of arms downgraded from FAIL to NOT RUN at
the runner — would be a hardcoded content judgment in the repo (**pattern:11**) and a blanket
"ignore these reds", which is the rubber stamp `SES-180` (c) exists to prevent. The kickoff says
so in CONTEXT and QA 4 asserts `run-all.js` does not appear in `git status --short`. Each arm
reports its own reading instead.

## 4. The QA discriminator, and why the obvious shortcut fails it

Each re-pointed arm must read the **same** verdict with its live fact flipped **and the opposite
verdict on the pre-change file** (`git show 4a14634:<path>` into a temp copy → still RED).
Relaxing a literal — widening `[]` to "or `['AGT-433']`", pinning `9` instead of `0` — satisfies
the first half and fails the second, because the pre-change file would then pass too. The second
QA clause adds a per-arm negative control (one in-memory mutation each) so that a declaration
cannot pass by declaring everything.
