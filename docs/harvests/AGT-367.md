## 2. The call (mine, recorded here, reversible)

1. **Derived, not written.** `runner_cycle_cause()` (immutable, scalar args) + view `runner_cycle_causes` give every row a cause from the columns it already carries. A written `cause` column would need every close-site in `runner-cycle.md` edited (the runbook is **380973 B against a `< 380980` ceiling** — 7 bytes of room) and would be a second home for a fact `last_step` already holds (pattern:93, pattern:14). A generated column was considered and rejected: a STORED generated column freezes the mapping at write time, so a later fix to the CASE would leave old rows wrong (pattern:3).
2. **Vocabulary as data.** `runner_waste_causes(cause, candidate_tickets, counts_as_waste, plain)` — John or a cycle re-points a candidate or flips `counts_as_waste` with an UPDATE, never a migration (pattern:2). `moved`, `routine_run`, `in_progress` are seeded `counts_as_waste = false`; everything else true, including `find_work` (it moves no ticket — the finding's own governing fact).
3. **Sized to what occurs** (pattern:57): the 10 `runner_should_boot()` reasons + `lanes_full_self`, `permission_stall`, `gated`, `ship_no_sha`, `reverted`, `find_work`, `unattributed` + the three non-waste states = 20 rows. A reason the gate adds later still classifies (the function returns the parsed reason) and shows with no candidate until a row is added — fail-honest, not fail-silent.
4. **One change, every home** (pattern:163): the standing brief gains the `Wasted cycles` group (counts + one rate, by cause, candidate beside it), and `audit_flow_checks()` arm (c) — the generator of this very finding — appends `; by cause: …` to its text and points its resolution at the view, so the next weekly finding arrives as a worklist. Arm (c)'s threshold arithmetic is untouched (no change to when it fires).
5. **Grants**: view and both functions are born open (SES-384 / SES-315 facts in `.claude/rules/supabase-column-grants.md`); the migration revokes `anon`/`authenticated` (functions also `PUBLIC`) by name and the trailing DO asserts both directions. `runner_cycles` itself grants nothing to anon today (measured: only `postgres` and `service_role` hold privileges).

## 3. Alternatives weighed

- **New `cause` column written at close** — rejected (§2.1).
- **Classify in JavaScript inside the brief** — rejected: two homes for one rule (brief + auditor SQL), and the ticket wants the cause "on its own row".
- **Edit `runner-cycle.md`** to mention the view — rejected for this cycle: 7 bytes of headroom; the brief group and the auditor finding are the homes a reader meets.
- **Count `routine_run` as waste** (the ticket's "shipped with no push_sha") — rejected: a routine's row never had a ticket to move; counting it would keep the number meaningless. It is reported, not hidden, on its own line with `counts as waste: no`.
