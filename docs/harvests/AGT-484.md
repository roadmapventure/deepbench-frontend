## 2. The call: which holding list, and which row

Candidates: `dev-mgr-findings` (planned, priority 99, one epic `48c63dac-4e5e-4287-8e72-01777fedbbf2` unlocked; decision ccab94da-81aa-4b9e-81ba-02cbfb376bb7, John 2026-09-29: every ticket the Development Manager files goes to Dev Mgr Findings) and `auditor-findings` (the Auditor's own list). Jerry's and Nathan's findings are reviewed by the same findings review as every other source (decision 34: one process for every source), and the manager has already been placing Nathan's there eleven times, so `dev-mgr-findings` is the list that fits without inventing a project (project creation is John's). Victoria's daily check promotes from that list into `go-to-market` on charter fit, which is the chain decisions 25 and 34 describe.

Variants weighed:
- (A) Two new rows `jerry`/`nathan` as the ticket words it -- dead on arrival: the resolver keys on `agent`. Would need a resolver change in `finding_group_epic` plus the offline mirror `scripts/audit-review.js routeGroup()` (two homes, pattern:14) for exact-`found_by` matching, and a precedence below 30 so the new rows beat `agent`. More code, same outcome.
- (B) Change the writer to `jerry:`/`nathan:` prefixes -- breaks AGT-161's agent-agnostic contract (`agt-121` part (a) greps for it) and leaves 26 historical rows under the old prefix.
- (C) **Chosen:** flip the existing `agent` row's `project_slug` NULL -> `dev-mgr-findings`. One data row, no code, no new overload, no mirror edit (`scripts/audit-review.js:481` only demands a pick when the route is NULL; the function returns at step 3a before reading `project`). It is the narrowest layer that works (pattern:8), data over code (pattern:2), extends the structure that already fits (pattern:17), and makes the last NULL route deterministic (pattern:10).
- Byproduct of (C), recorded: any future `agent:<slug>` writer (another product or personal lane agent) files under the capture list too. That is decision ccab94da's rule, not a widening. AGT-264's original reason for keeping `agent` NULL -- "agent:designer/agent:builder product defects would be misrouted into Agent Training" -- no longer applies, because the destination is a capture-only holding list, not an executing project.
- Reversal: the card-only down `update public.finding_routes set project_slug = NULL where precedence = 30 and source = 'agent';` (capture_migration_down refuses DML on an existing table by design -- `agt161_finding_routes_agent` is classified `refused`, down_sql empty, which is the precedent the kickoff asserts in T3 arm D).
