## The probe, and why `sha^` not `sha`

`materializeInputs()` renders `git diff <sha>^..<sha>`, so the object a depth-1 clone is missing is the **parent**. Measured both directions:

```
depth-1: git cat-file -e a176cc64^^{commit} -> non-zero   (also 7e4d4cb2)
full:    git cat-file -e a176cc64^^{commit} -> 0          (also 7e4d4cb2)
```

This is the whole reason the fix is not "catch the error and skip." `mat.errors` says *could not be read*, which is also what a corrupted object or a genuinely rewritten history would say. Gating the skip on an explicit reachability probe keeps "the digest rotted" red while "this checkout is shallow" goes NOT RUN. If the build takes the lazy form — skip on any materialise error — the QA's mutation control is what should catch it.
