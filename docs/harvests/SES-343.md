## The shape, and why it is opt-in in code rather than data on the Intent row

The Chief Architect lens (SES-338 review) said: presentation fields truncate with a note and still record; `verdict`, `backlog_id`, `version`, `auto_done_eligible` stay strict. Three ways to carry that:

1. **Declare severity on the schema** (`x-severity: "note"` per property in `vf-verdict-intent.traits.schema`). Cleanest as data (§19b), but it edits an active governance agent's Skill row, which §19v and `.claude/rules/agent-roster-inert.md` reserve for John's word, and SES-337 made those rows self-certifying for the Verifier. Rejected for this ticket; it is the right follow-up if John wants the cap itself to move.
2. **Make every `maxLength` overflow a truncation for every caller.** Would silently change `scripts/run-project.js:605` and `scripts/rank-backlog.js:159`, and would turn any future 8,192-style *rule* expressed as `maxLength` into a quiet trim. Rejected: the default must stay byte-identical.
3. **Opt-in `{ truncate: true }` at the two verifier call sites, with a code-side `DECISIVE_KEYS` list.** Chosen. The decisive four are already hand-read by name in `verdictIdentityMismatch()` (`backlog_id`, `version`) and `reconcileJudgment()` (`verdict`, `auto_done_eligible`), so naming them once more in the validator adds no new drift surface. Default callers and every existing test (`SES-181-verifier.js`'s 401-char `auto_done_reason` rejection, `agt-67`'s `"true"` mutant, `ses-367`'s missing-`account` control) keep passing untouched.

Why the cut string is exactly `slice(0, maxLength)` with no ellipsis: the recorded lens then satisfies the Intent's own contract, so a later re-validation of the row cannot fail on it. The note lives in `runner_verdicts.reasoning` via the `stored.note` interpolation already at L1218, which means no column, no migration, no schema read at a second site.

Why `truncateNote` names the four untouched keys: the row is the only place the fact "this verdict was cut, and the decision was not" survives, the same discipline `describeLadder()` and the override list already keep.
