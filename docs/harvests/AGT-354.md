## 4. The design, and why

Governing sections: ARCHITECTURE.md §19c (`knowledge_entries` is an agent's own training, read by itself only), §19b (no id, lane or slug branch in the executor), §19i (retrieval facts logged where they are provable), §1 (both halves of Competency feed Scaffold, `DAT-004`). Rules: `.claude/rules/supabase-column-grants.md` (a new table is born readable by `anon`, a new function is born executable by `anon` and `authenticated` by name) and `.claude/rules/supabase-function-signature.md`.

**The calls (mine, reversible — JOHN-0925-DESIGNER-DECIDES).**

- **D1. A piece is a row of a new table**, `knowledge_entry_pieces` (`entry_id` with `ON DELETE CASCADE`, `piece_no`, `content`, a 1536-wide `embedding`), not new columns on `knowledge_entries` and not a second copy of the item. The item row stays whole, so the MCP bundle and the Teach screen still hand over and show every item in full. Undo: the captured down.
- **D2. Fixed-size pieces with overlap**: 4,000 characters, overlapping 400 (a step of 3,600), cut only for an item over 12,000 characters. This is the standard practice (fixed-size chunking with overlap, about 1,000 tokens a piece), not a homegrown scheme (pattern:101). A phrase that straddles a cut is whole in one of the two pieces as long as it is under 400 characters. Each piece is embedded as `title + blank line + piece`, through the existing `embedEntryText()`, so every embedding call is logged exactly as today (one `knowledge-write` row per call). Undo: change two constants and re-run the repair.
- **D3. A new function, not a fourth overload.** `match_knowledge_pieces` is a new name; `match_knowledge`'s three overloads are not touched, so no signature changes and nothing that still calls the old name can break. Born closed, both directions asserted inside the migration.
- **D4. An item with no pieces is matched on its own embedding and returned as its first 12,000 characters** — exactly the text that embedding was made from. That bounds every match the moment T4 ships, before any item has pieces, and it is what an item whose pieces failed to write falls back to.
- **D5. The exclusion is an argument the caller passes.** Three of the four callers render no taught section and must keep finding short items, so the function takes `p_exclude_always_for` (an agent id) and only `ai-enrichment.js` passes it, and only when the prompt it is enriching actually holds the `taught` section (`sections.some(s => s.slug === "taught")`) — attributed from what the assembly did, not from configuration (pattern:32). It names no agent, capability or lane (§19b). The rule inside the function mirrors `lib/read-taught.js`: a `source = 'user'` row of that agent, in the caller's tenant, of at most 12,000 characters.
- **D6. A save whose pieces fail answers 500.** The item row is already saved at that point; the answer says the save did not finish, the item falls back to D4, and the check (T5) names it. The alternative — swallow the error and answer 200 — hides a gap from the one person who could retry. Known cost: a retry without an id saves a second copy.
- **D7. `DAT-004` slice 2 stays out.** The executor searching the long items for every agent is `DAT-004`'s own remaining slice (status partial); the ticket says to order the work, not fold it. This build removes what that slice was waiting on and ARCHITECTURE.md §1 is edited to say so.
- **D8. Whether Michelle's four items belong in her training is left alone**, as the ticket says.
- **D9. The top matches may be several pieces of one item.** Plain top-k over pieces, as piece retrieval normally works; `chunks` can then carry one id more than once, told apart by the new `piece_no`. A cap per item is one line of SQL if it is ever wanted.
- **D10. The label.** A piece renders as `--- KNOWLEDGE BASE ENTRY: <title> (part 3 of 9) ---`, so the reader of the prompt knows it is an excerpt. A whole item renders exactly as today.

**Staging (risk rule).** Every part is undoable and none changes what an agent may do on its own, so no part must ship alone. Order is safety: the migration is applied before any code that calls the function (T2 before T4 — `lib/rag.js` answers empty on a non-ok RPC, so the reverse order would silently empty all four search paths); the write side lands before the read side is proven; the nine get their pieces last because that needs the deployed code.

**Why one push, and why arm `g` is red at that push.** `docs/runbooks/runner-cycle.md` step 7 ships at ONE ship point. The nine can only get pieces from code that is deployed (next paragraph), so the push comes first. Arm `g` of `agt-345-taught-embeddings.test.mjs` is the only thing on the platform that runs the taught-items check, and it asserts the live sweep is clean; once the check also names a long item with no pieces, it is red from T2's apply until T8 finishes. I kept that red rather than blind the arm: it is the standing sensor for a tenth item, it names exactly the nine, and it is QA 2's before. The alternatives were worse — a second push (not allowed), an arm that ignores pieces (then nothing runs the sensor), or a NOT RUN while the table is empty (a truncated table would then read as "could not check"). The cost is real and stated: between the push and the end of T8 the suite on `dev` holds one red, and if T8 stops it stays red, naming the items still unsearchable.

**The route T8 takes, and the two 216,720-character items.** Measured in this container: `SUPABASE_URL` and `SUPABASE_SERVICE_KEY` are set, `OPENAI_API_KEY` is not, and the proxy refuses `api.openai.com` outright (`CONNECT` 403) — so reading the key from `runner_secrets` would not help; nothing here can embed. The dev deployment is reachable (it answers Vercel's protection page without the bypass header; the runbook's step 4 already uses `x-vercel-protection-bypass` from `runner_secrets`). So the route is the standing repair path AGT-345 established: one `PATCH /api/load-entries` per item carrying its own stored title, on the deployment that holds the key. `reembedOnEdit()` gains one clause for it (block K3): a long item with no pieces gets them on any such edit.

`api/load-entries.js` declares no time limit of its own and I could not measure the platform default from here. What I did to make the two largest items fit: pieces are embedded 16 at a time, so 61 pieces are 4 rounds, then one delete and one insert of 61 rows. I expect seconds. I did not prove it. **If either item does not answer 200 inside the route, the build stops and says so** (block B). Raising the route's limit is `api/load-entries.js`, a ninth file; batching the embedding call is `lib/vector-search.js`, also a ninth file. Neither is in this build and the Manager ruled on neither.

**Measured for the function (the 8-second PostgREST limit).** The designed SELECT, run read-only against the live rows with a 120-row stand-in for the pieces table: 43.8 ms. With 170 real rows and the primary key on `(entry_id, piece_no)` it needs no further index.

**Rejected.** New columns on `knowledge_entries` (an array of embeddings cannot be searched by pgvector). A fourth `match_knowledge` overload (`.claude/rules/supabase-function-signature.md` — an overload added beside three live ones is how `DAT-12` returned zero rows). A backfill script file (a ninth file, and it could not embed from here anyway). Excluding always-given items for every caller (three callers would lose the short items entirely).

-- DeepBench v7.0.1077 | docs/design/agt-354-taught-pieces.sql | AGT-354
-- Migration `agt354_taught_pieces` (mirror; applied by the orchestrator over the Supabase connector).
-- A long taught item is also stored as pieces, each with its own embedding, and one new search
-- function returns the matching piece. public.match_knowledge (3 overloads) is NOT touched.
-- Down: public.capture_migration_down, taken before the apply (drops the function, then the table).

create table public.knowledge_entry_pieces (
  entry_id   uuid        not null references public.knowledge_entries(id) on delete cascade,
  piece_no   integer     not null check (piece_no >= 1),
  content    text        not null check (length(content) between 1 and 12000),
  embedding  vector(1536) not null,
  created_at timestamptz not null default now(),
  primary key (entry_id, piece_no)
);

comment on table public.knowledge_entry_pieces is
  'AGT-354: the pieces of a knowledge_entries item longer than 12,000 characters. Written only by lib/knowledge-write.js writePieces(); read only by public.match_knowledge_pieces().';

-- Born closed (.claude/rules/supabase-column-grants.md): a new table is born readable by anon.
alter table public.knowledge_entry_pieces enable row level security;
revoke all on table public.knowledge_entry_pieces from public, anon, authenticated;
grant select, insert, update, delete on table public.knowledge_entry_pieces to service_role;

create function public.match_knowledge_pieces(
  query_embedding      vector(1536),
  match_threshold      double precision,
  match_count          integer,
  p_tenant_id          text default 'global',
  p_agent_id           text default null,
  p_exclude_always_for text default null
)
returns table (
  id uuid, title text, content text, category text, jurisdiction text, priority integer,
  triggers text[], status text, tenant_id text, agent_id text, teaching_note text,
  similarity double precision, piece_no integer, piece_count integer
)
language sql
stable
set search_path = public
as $fn$
  with scoped as (
    select e.id, e.title, e.content, e.category, e.jurisdiction, e.priority, e.triggers, e.status,
           e.tenant_id, e.agent_id, e.teaching_note, e.embedding,
           (select count(*)::integer from public.knowledge_entry_pieces k where k.entry_id = e.id) as piece_count
    from public.knowledge_entries e
    where e.status = 'active'
      and (e.tenant_id = p_tenant_id or e.tenant_id = 'global')
      and (p_agent_id is null or e.agent_id = p_agent_id or e.agent_id = 'legacy')
      -- an item the caller's prompt already carries whole (a user-taught item of that agent at or
      -- under 12,000 characters) is left out when the caller names the agent
      and (p_exclude_always_for is null
           or e.source is distinct from 'user'
           or e.agent_id is distinct from p_exclude_always_for
           or e.tenant_id is distinct from p_tenant_id
           or length(e.content) > 12000)
  ),
  cand as (
    -- an item with no pieces: matched on its own embedding, returned as the text that embedding
    -- was made from (its first 12,000 characters)
    select s.id, s.title, left(s.content, 12000) as content, s.category, s.jurisdiction, s.priority,
           s.triggers, s.status, s.tenant_id, s.agent_id, s.teaching_note,
           1 - (s.embedding <=> query_embedding) as similarity,
           null::integer as piece_no, s.piece_count
    from scoped s
    where s.piece_count = 0
    union all
    -- an item with pieces: each piece is a candidate, and the piece is what is returned
    select s.id, s.title, k.content, s.category, s.jurisdiction, s.priority,
           s.triggers, s.status, s.tenant_id, s.agent_id, s.teaching_note,
           1 - (k.embedding <=> query_embedding) as similarity,
           k.piece_no, s.piece_count
    from scoped s
    join public.knowledge_entry_pieces k on k.entry_id = s.id
  )
  select c.id, c.title, c.content, c.category, c.jurisdiction, c.priority, c.triggers, c.status,
         c.tenant_id, c.agent_id, c.teaching_note, c.similarity, c.piece_no, c.piece_count
  from cand c
  where c.similarity > match_threshold
  order by c.similarity desc, c.id, c.piece_no
  limit match_count;
$fn$;

-- Born closed: a new function is born executable by anon and authenticated BY NAME, and
-- REVOKE ... FROM PUBLIC alone leaves those standing (SES-315).
revoke all on function public.match_knowledge_pieces(vector, double precision, integer, text, text, text)
  from public, anon, authenticated;
grant execute on function public.match_knowledge_pieces(vector, double precision, integer, text, text, text)
  to service_role;

-- Assert both directions; never trust the success flag. Any raise rolls the whole migration back.
do $gate$
declare

  r   text;
  p   text;

      if has_table_privilege(r, tbl, p) then
        raise exception 'AGT354 gate: % holds % on %', r, p, tbl;
      end if;
    end loop;
    if has_function_privilege(r, fn, 'EXECUTE') then

    end if;
  end loop;

             where c.oid = tbl::regclass and a.grantee in ('anon'::regrole::oid, 'authenticated'::regrole::oid, 0::oid)) then
    raise exception 'AGT354 gate: % still carries a public grant in relacl', tbl;
  end if;

     or not has_table_privilege('service_role', tbl, 'SELECT')
     or not has_table_privilege('service_role', tbl, 'INSERT')
     or not has_table_privilege('service_role', tbl, 'DELETE') then

  const text = String(content ?? '');
