# SES-180 — Portable CI: build + regression + tripwire on every push, off John's machine

Harvest file for `SES-180`. The ticket's `backlog_items.description` carries the requirement and a
pointer here; the ship detail lives in this file (CLAUDE-DESIGN.md step 9 — a description over the
2,000-char cap moves its detail to a harvest and leaves a pointer).

Epic: **Selfbuild M3 - Independent Verification**. Class: **P10 - Tooling**.

**The requirement, unchanged:** the six enforced hard rules live in machine-local hooks and the
regression suite runs only where credentials happen to exist, so a push from a cloud cycle, a fresh
clone, or any other contributor is checked by nothing at all. Stand up CI running `npm run build`,
the regression suite with credentials, the grants assertions and the truth tripwire on every push to
`dev`. Red = no merge, regardless of author.

## (a) `v7.0.219`, runner cycle `7030c8f0`, 2026-08-24 — the workflow exists

`.github/workflows/ci.yml` shipped; `.github/` did not exist in this repo at all before it.

- **BLOCKING** `build` — `npm ci && npm run build` on every push/PR to `dev` and `main`.
- **REPORTING** (`continue-on-error`) — `scripts/check-session-docs.js` and
  `tests/regression/run-all.js`.

Both reporting jobs carried a stated reason. The tripwire is report-only **by contract** and always
exits 0, so gating on it there would have changed what the script promises everywhere else it runs.
The suite measured **50/50 with credentials and 49/50 without** — `CHI-31` failed with
*"SUPABASE_URL/SUPABASE_SERVICE_KEY must be configured (.env.local)"* — and **a test that CANNOT RUN
is not a test that FAILED**; gating before that distinction existed would have painted CI permanently
red and trained everyone to ignore it.

**The PAT workflow-scope blocker this ticket was filed around had lifted**, measured before designing
against it: a commit carrying a workflow file pushed successfully to a throwaway branch.

**Residue from (a):** the probe branch `probe/ses180-workflow-scope` could not be deleted —
`git push --delete` failed *"remote end hung up"* on 3 retries and no branch-delete tool existed in
that session; ref deletion appears proxy-blocked. Harmless (it carries the same `ci.yml` that
shipped) but John's to remove.

**NOT CLAIMED at (a):** that a CI run had gone green — at ship time none had executed.

## (b) `v7.0.224` — the skip-vs-fail distinction, declared and never inferred

`notRun(part, reason)` in `tests/regression/_lib/self-run.js`, drained by `run-all.js` on both the
pass and the fail arm. A test **declares** a part it cannot verify here; the declaration does not
change that test's own outcome, and `run-all.js` still exits 1 **iff** something FAILED. The unit is
the **part**, not the test, because all five of the tests that had a credential gap skip a *half* and
marking whole files skipped would throw away real passing assertions.

**Declared, never inferred** — nothing reads `process.env` or parses output on a test's behalf. A
harness that guesses at skips swallows real failures, which is the failure the ticket names.

## (c) `v7.0.286`, runner cycle `b9f90b84`, 2026-08-28 — the two reporting jobs become real gates

Both stated reasons for `continue-on-error` had been paid off by other tickets, so the caveat was the
only thing still making CI a rubber stamp.

**Measured in a clean clone at this ship, not reasoned about:**

| Check | Invocation | Result |
|---|---|---|
| regression, no credentials | `node tests/regression/run-all.js` | **87/87 passed, exit 0**, 23 parts declared not-run across 18 tests |
| tripwire, gating form | `node scripts/check-session-docs.js --gate` | **exit 0** — *"clear — no FLAG findings in the gating classes (checks 9/10/11)"*, over a report still carrying **38 FLAGs and 4 WARNs** in the non-gating classes |
| build | `npm ci && npm run build` | green |

The 49/50 that blocked (a) is now 87/87: the failing `CHI-31` half is one of the 23 declared parts.
The 38 non-gating FLAGs are the proof the tripwire's green is a *named gating set* rather than a
green achieved by looking at nothing — `--gate` (SES-199, `v7.0.242`) gates on FLAG findings in the
truth-registry classes only and fails **closed** when the registry cannot be read at all. SES-199's
own header names wiring that flag into CI as *"the follow-up, not this"*; (c) is that follow-up.

**What changed in `ci.yml`:** the `checks` job drops `continue-on-error`, its tripwire step runs
`--gate`, and its regression step carries `if: always()` so a red tripwire cannot conceal the suite's
result — steps stop at the first failure, so without it every push after one drift finding would
report a single problem while hiding however many others.

**Guarded by `tests/regression/SES-180c-ci-gates.js`**, in two halves because neither is sufficient
alone: three clauses parsed off the real `ci.yml` (no `continue-on-error`, `--gate` present and
recognised by the **imported** `gateModeRequested()`, `if: always()` present), each with its own
negative control run against the real file; and three behavioural arms driving the real
`run-all.js` over fixtures through its own `--dir` flag — a **declared** not-run part exits 0, a
**throw** exits 1, and a test that declares *and then* throws still exits 1, so a `notRun()` call can
never launder a real failure past the gate. The pre-change `ci.yml` fails the guard on all three YAML
clauses.

**One risk named rather than hidden:** the job's `name:` changes from *"(reporting only)"* to
*"(blocking)"*, and GitHub matches required status checks by job **name**. `dev` — where every runner
push lands — carries no protection at all (read live from the branches API at this ship:
`protected: false`). `main` **is** protected and whether its required-checks list names this job is
not readable from the runner's tools; if it does, John re-selects the new name in the branch settings.

## Still owed, and none of it the runner's

1. **Repository secrets** — `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` as GitHub repository secrets, so
   the credentialed halves and the grants assertions run in CI. Only John can add those; a runner
   must never print a secret, let alone install one. Until then those halves stay **declared
   not-run** — visible in the log, counted as neither pass nor fail, which is what makes the gate
   honest rather than vacuous.
2. **Branch protection** — the ticket's *"Red = no merge, regardless of author"* is a repository
   setting, not a file. (c) makes a failing check turn the **run** red; only John can make it
   binding.
3. **`probe/ses180-workflow-scope`** — the undeletable probe branch from (a), harmless, John's to
   remove.

**A dependency between (1) and the gate, found while building (c) and named because it will bite
exactly once:** adding the secrets in (1) does **not** simply strengthen the gate. Measured this
ship — with `SUPABASE_URL`/`SUPABASE_SERVICE_KEY` present the suite ran **87/88, exit 1**, the single
failure being `SES-177-claude-state-renderer.js` (*"the committed CLAUDE-STATE.md must match what the
ledger renders"*). That is the runbook's own documented **one-ship-behind lag**, not a defect: the
committed `CLAUDE-STATE.md` is rendered at a cycle's close-out and goes stale again the moment that
cycle's row closes `shipped`. Re-run after this cycle's mandated `render-claude-state.js`: **88/88,
exit 0.** So the gate is green in CI today *because* CI has no credentials, and (1) would turn the
now-blocking job red for most of the interval between cycles. Filed as its own ticket rather than
worked around here.
