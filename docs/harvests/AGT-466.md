## 2. A second defect in the shipped design: growth is only measured for a surface already alarming

`prevFromRows()` reads `prev_bytes` out of the sensor's own earlier `config-headroom` findings. A finding is filed only when a surface is under the 5% floor or already outgrowing — so a roomy surface never has an earlier week, and the growth rule can never be the first thing to fire on it. Live today: `1 prior config-headroom row(s) read; 1 of 4 surface(s) have an earlier week to compare`. `ds-knowledge-patterns` (19,416 of 24,576 B) has no growth memory at all. The ticket's "nothing measures growth" is still true for three of four surfaces.

## 3. Why this is a mechanism change, and what it deliberately does not do

- Prior mechanism: growth memory in `audit_findings` (needs credentials, exists only for alarming surfaces), the cadence owned by an `au-behavior` checklist line. That line is behind the agent-row gate — re-run today: `verdict gated`, rule `AGENT-ROW-AGREED-TICKET`, clause `no-authority` — and changing an agent row is John's alone. It is **not** delivered by another route here; it is named blocked and stays on the open gate card.
- New mechanism: a tracked history file, `docs/audits/headroom-history.json`, written for every surface on every Auditor run (`--record`) and pushed by the routine's existing step-6 `tail-push.js --files=` list; growth read from that file with no credentials and no REST; a pure `config-sensor-gap` check that makes a dark week a ledger row on the next run; no bare import, so a fresh clone runs it first time.
- Reach: one script, two runbook lines outside the prompt block, one new data file, one test. No database write, no DDL, no agent row, no `runner-cycle.md` or `cycle-card.md` byte. Undo: one `git revert`.
- Alternatives rejected: a new table (DDL — no build lane applies it, `AGT-289`/`AGT-548`; wider reach, harder undo); filing a weekly info finding per surface (spams the Development Manager's review); fixing `lib/activity-log.js`'s static import (that is `SES-429`, open — reused, not duplicated); making the step-3 merge fail on a missing input (`AGT-374`, open — reused).
- Not added: `cycle-card.md` and the 8,192-byte kickoff cap as surfaces — one-line additions later; not what the remaining ticket text asks.
- No test calls `rpc/runner_should_boot` (finding d292fb52: HTTP 500 57014 on 3 of 3) — every new arm is fixtures or a static source walk.
