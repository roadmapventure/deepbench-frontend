## 2. The RCA, answering the ticket's three questions

**(1) Which Auditor job owns it.** FULL REVIEW / capability `audit-config-review` (intent `au-config-intent`),
whose scope is already "DeepBench's own governance and tooling" — not corpus (statement-vs-statement) and not
board (ticket health). Two new `[code]` slugs, mine to name (JOHN-0925-DESIGNER-DECIDES):
`config-headroom` (capacity + growth, kind `other`, `finding_type gap`) and `config-pin-drift` (a generated
view or mirrored row no longer equal to its source, kind `contradiction`, `finding_type defect`).
`found_by` `auditor:headroom-checks` matches `runner_settings.finding_families` pattern `auditor:%`, so
`public.finding_family()` sets `family = paperwork` and the NOT NULL column needs no migration. The cadence is
the Auditor's Monday fire: `docs/runbooks/auditor-routine.md` step 1 (gather) and step 3's one ingest.

**The row half is GATED, and that is measured, not assumed.** `node scripts/agent-row-gate.js --ticket=AGT-466
--action=edit-active --json` answers `{"verdict":"gated","rule":"AGENT-ROW-AGREED-TICKET","clause":"no-authority",
"scope_origin":"victoria-placed"}`. So the checklist LINE in `au-behavior` cannot be written by this unattended
cycle. `AGT-496` (v7.0.890, §19v) hit exactly this and settled `partial` with the sentence left on the ticket;
AGT-466 follows it. This is why the kickoff does **not** touch `au-behavior` — and therefore why
`tests/regression/agt-86g-auditor-checklist.test.mjs` (arm A's `CHECKS`/`CODE_CHECKS` lists) and
`tests/regression/agt-102-routine-prompt-drift.test.mjs` (arm F asserts `au-behavior.objective` matches
`/twenty-four/`) are **not** in the file list. Both would have been required had the row been edited; writing
the row and not those two files is the shape that would have gone red.

**(2) What should leave `runner-cycle.md`.** Already ticketed: `SES-342` carries the harvest / selection /
sweep rules, `AGT-288` the immediate collision, `AGT-319` the card's 4th-file cost. Filing a fourth ticket for
the same work would be a `board-duplicate` finding of the Auditor's own making, so this build files none for it
and names the three instead. What this build adds is the missing precondition for that work: the number, weekly,
before the collision.

**(3) The standing cleansing routine.** Not ticketed anywhere — this build files ONE row for it: retire
superseded statements and pins that guard nothing, prune on a cadence, and report headroom where John reads it.
The briefing surface is deliberately inside that row, not inside this build: no briefing section today carries
headroom (`grep -n 'quota|headroom' scripts/build-briefing.mjs docs/runbooks/briefing-page.md` → nothing), so a
tile would be a NEW visible element, and that is John's call (pattern:84). The weekly audit report
(`audit-ledger.js --report=<W> --write`) already renders filed findings, so the sensor is useful the first
Monday after it ships without any surface change.

## 3. Design choices, and what they do not do

- **Extend, do not invent** (pattern:17): `scripts/audit-headroom.js` is `scripts/audit-board.js`'s shape — five
  frozen maps, pure `(snapshot, ctx) -> finding[]` checks, one `--out` file consumed by the same merge. No new
  table, no migration, no model call (pattern:9).
- **One home per bar** (pattern:93): the registry's bars are imported where they are exported (`ROW_BYTE_CAP`,
  `CARD_BYTE_CAP`), and the runbook's two bars live in test modules, so the test — not the script — binds them
  (`RUNBOOK_CEILING` is already exported; `PRE_CHANGE_BYTES` needs one word, hence the 4th file). A sensor that
  re-typed 380,980 would be the drift it exists to catch.
- **The binding bar, not the pretty one.** `SESSIONS.md:121` records a kickoff that computed 80 B of headroom
  against 381,000 when agt-138's ratchet left 59; a sensor reading the outer bar would overstate room by 35%.
- **Honest absence** (pattern:34, pattern:165): without credentials the growth fields read `none` and the
  summary says `not-run`, never `delta=0`; a skipped pin child is named, never counted green.
- **Grades the change, not the world** (pattern:162): every assertion in the new test runs over fixtures. The
  live run is printed. Parallel cycles (register B42) move `runner-cycle.md` mid-build, so `free=59` is a
  fixture number and a STOP condition, never a live assertion.
- **What it does not do:** no projection beyond four weeks; no pruning (that is the filed row); no briefing
  surface; `docs/SESSIONS.md`'s 1.5 MB rotation ceiling (`SES-268`) and the kickoff's own 8,192-byte cap
  (`AGT-519`, `AGT-537`) are not in the registry — each is a one-line addition once the shape is proved, and
  adding them now would widen the ticket past what it asks.

## 4. Cap and set

Class caps are 50 files / 51 tasks (P10 - Tooling, rung 60, streak 3). The complete green landing needs **4**
files and 4 tasks, well inside them; no split, no waive. Had the `au-behavior` row been writable, the same work
would be 6 files (adding agt-86g and agt-102) — still inside the cap.

Graded set, enumerated with the resolver and not a grep:
`node scripts/related-tests.js --files=docs/runbooks/auditor-routine.md,tests/regression/agt-86g-auditor-checklist.test.mjs,tests/regression/agt-102-routine-prompt-drift.test.mjs,tests/regression/agt-138-researcher-routine.test.mjs --json`
→ `count 11`. Over the 4 files the build actually touches the count is the same 11 (dropping the two
agt-86g/agt-102 paths removes no test, since both are related to themselves and to `auditor-routine.md`):
agt-102, agt-102-s2, agt-137, agt-138, agt-145, agt-146, agt-391, agt-424, agt-70, agt-86g, agt-86h. T3's new
file makes it 12.

`node scripts/baseline-red-set.js --tests=<those 11>` on the unchanged tree: **Red set 1 of 11** —
`tests/regression/agt-70-auditor.test.mjs`, `[FAIL] a fingerprint the ledger holds in SOME week must be
RECOGNISED, never re-filed as new. ledger says 3 new / 2 seen / 4 rec+ruled; got: ingest 2026-W38: 6 findings,
0 new, 4 seen, 1 recurring, 1 ruled-out`. The kickoff's own `Red:` line carries the PATH ONLY and the
assertion text sits on a `Detail:` line below it: `readKickoffBaseline()` (scripts/verifier.js:1332-1341)
splits a `Red:` line on commas and counts the pieces as test names, so a comma inside the quoted assertion
made one red read as two and refused the block (`kickoff-baseline-unparseable`, AGT-457). A shared-database ledger fixture (environment fact SES-382: cycles
run in parallel and shared-DB fixtures collide), standing, not this build's.

Coupling checked and found absent: `run-all.js` discovers test files with `readdirSync`, so a new test needs no
registration; `shared/ai-patterns.js` `SERVICE_CATALOG` governs `agent-log.js` rows and this check makes no
model call; `.claude/rules/` binds `src/`, `api/`, `lib/` and `shared/`, none of which this build touches;
`agt-86h` arm B is the one real constraint on a new script — every `--flag` the runbook passes must appear in
the script's first 130 lines.
