## 3. Alternatives weighed

- **A. A second hand-written six-literal inside agt-281.** Fixes the red, leaves two hand lists (agt-281, agt-452) that AGT-434 must find and edit together — the exact duplication class this ticket exists to remove (pattern:14, pattern:163). Rejected.
- **B. Import `EXPECTED_BINDINGS` from the agt-452 test file.** `self-run.js` gates on `isEntryPoint`, so it would not double-run, but the dependency direction is wrong: a guard is a leaf, and this ties two guards' module state together. Rejected.
- **C. Pin against the generated record** — parse its `-- capability_skill_profiles · requirement-check · <slug> · display_order N` lines as the expectation. Then a binding added live plus one `--write` is green with no human having declared anything, and the agt-452 hand list still refuses. That is alternative A with worse provenance. Rejected — and this is the direct answer to "re-pin against the generated record that AGT-452 shipped": the record declares nothing, so it cannot be the pin. What AGT-452 shipped that CAN be the pin is its module, which is where the one hand-written list now lives.
- **D. (chosen) Hoist `EXPECTED_BINDINGS` into `scripts/victoria-rows-mirror.js`** beside `SLUGS`/`CAPABILITY`, add a pure `bindingDrift()` there, and have BOTH tests import it. One hand-written list, one home, one place AGT-434 edits (pattern:17 — the module already owns Victoria's row vocabulary and agt-452 already imports eight names from it; pattern:93; pattern:3). The record keeps its job (byte drift), the constant keeps its job (the declared expectation), and `bindingDrift()` makes the pin two-direction in a form that can be PROVEN offline on fixtures — the only way to prove both directions without changing a row, which the ticket forbids.

## 4. The Designer's calls (JOHN-0925-DESIGNER-DECIDES; reversible — revert the commit)

1. **Pin against one hand-written constant in the mirror module, not the generated record** (§2-3).
2. **Two-direction via `bindingDrift()` with four named outcomes** — missing / extra / duplicate / order — proven in the offline arm. `assert.deepEqual` against the six is also two-direction, but gives no offline proof and a worse message. `duplicate` is included because AGT-434's own ticket text records that duplicate bindings happen. Contiguity of `display_order` (0..5) is deliberately NOT pinned: the AGT-452 record already pins each binding's exact `display_order`, and pinning `[0..n-1]` would make AGT-434's removal of order 0 red for a second, unrelated reason.
3. **`bind.json[1].level` becomes a lookup by slug** (`LIST_INTENT`, already imported at :75 and asserted equal to `vc-reorganize-intent` at :189), so the "sibling" assertion means what it says regardless of position.
4. **No ARCHITECTURE amendment.** A test re-pin changes no mechanism; §19v already names the AGT-452 record and its guard. No `.sql` mirror, no migration, no DO block: nothing is written.

Also, deliberately: **no DELETE and no DROP statement anywhere in the build, the QA or any teardown**, and no QA step that greps for those words. This chain measured the narrow fact today — an actual DELETE or DROP *statement* hangs the Supabase MCP channel at 60 s, while the word inside a literal is harmless (the AGT-452 record contains "deleted" inside `vc-reorganize-intent.method` and is fine). Nothing in this build needs either statement, so the ceiling is never approached.
