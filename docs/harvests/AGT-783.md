## 2. The rule, and the calls made (mine, reversible)

- **D1 selection by labels.** `LIBRARY_READ_FIRST` maps a capability to `{ sections, trust }`. It names no item id and no reader; the same two labels every Library item already carries decide. It sits beside `LIBRARY_SECTIONS` as its own map because `agt-644` pins the keys of `LIBRARY_SECTIONS` to the seven strategy capabilities (line 111) and `agt-722` pins that the writing capabilities are absent from it.
- **D2 a selected item is read whole.** `libraryPlan` puts the selected ids first with `sections: null`, so an item the search reached through one section is still read in full, and an item that is both selected and a hit appears once.
- **D3 no byte budget of its own.** The selected items are simply first in the same list the 60,000-byte loop walks. Six items today take about 9,000 bytes and leave about 51,000 for the ranked read. A second cap would be a knob with no bound to justify it (pattern:67). The exposure: if the principal authors many more `identity` documents, they crowd the ranked read; the guard's live arm prints the byte count every run, and its control (`the ranked read still follows the selected items`) goes red before the ranked read is squeezed out entirely.
- **D4 the live arm reports an edited live text, never fails it.** The four seeded md5s are counted and printed. A Page edit saved to the working folder becomes a new version on the next sync; that is the principal's edit, not a regression (pattern:162). What the arm asserts instead is the mechanism: every item the rule selects from the render's own catalog leads the text, and each unsectioned one equals its stored body.
- **Unchanged for every other capability.** `libraryFirst()` returns `[]` for a capability with no rule; with an empty `first`, `libraryPlan`'s three changed lines reduce to the old ones (an empty filter set, an empty spread, the same `seen`). The guard keeps the pre-change algorithm as `planBefore` and compares it, with hits and without, for every capability in either sections map that names no rule: 22 plans.
- **No new key in the render.** The library block's keys are unchanged (`catalog, counts, text, text_bytes, text_capped, ranked_by`), so no other capability's task context moves by a byte. The test derives the selected ids from the render's own catalog.
- **The deny list and the skips.** `libraryAllowed()` drops denied items and the private-section second line before the catalog exists, so `libraryFirst()` never sees them. `libraryPlan` applies `skipKinds`, `skipSections` and `skipIds` to the selected ids through the same `eligible` test the hits pass (a resume in `identity` of principal trust is selected by label and then skipped as text; the fixture proves it).
- **The step is appended, md5-gated.** Both the before-image and the update act only while md5(method) is the value read at design. A row edited since matches nothing and GATE 5 or GATE 3 raises; a second apply matches nothing either. `updated_at = now()` follows the shipped AGT-618 mirror.
- **One decision, recorded by the orchestrator** (T4 c), not inside the mirror, so the mirror's bytes do not depend on a cycle and its sha256 can be pinned (the AGT-781 shape). The mirror attaches to the newest open agent-row decision whose summary starts `AGT-783 step:` recorded in the last 2 hours.
- **Skill type (pattern:136).** The row stays type `intent`: the step is a method the weekly review runs, not text it reads, and it belongs to the one capability that row serves.
- **The runbook.** Two lines: the file's header convention (line 1), and step 6c in section (b), outside the four routine prompt blocks. The blocks are the routines' copies; this ticket touches no routine, and `agt-644`, `agt-651`, `agt-655`, `agt-722` pin the blocks' first lines and markers only. Line 13 of the runbook still says the Library text is capped at 200,000 bytes (it is 60,000 since AGT-647); that line is not this ticket's and is left alone.

function planBefore(catalog, hits, { wanted = new Set(), skipKinds = new Set(), skipSections = new Set(), skipIds = new Set() } = {}) {
  const byId = new Map(catalog.map(c => [c.id, c]));
  const eligible = c => c && !skipKinds.has(c.kind) && !(c.section && skipSections.has(c.section)) && !skipIds.has(c.id);
  const best = new Map(), whole = new Set(), sections = new Map();
  for (const h of hits ?? []) {
    const c = byId.get(h.source_id);
    if (!eligible(c)) continue;
    best.set(c.id, Math.max(best.get(c.id) ?? -Infinity, Number(h.score) || 0));
    if (h.section_id == null) whole.add(c.id);
    else { if (!sections.has(c.id)) sections.set(c.id, new Set()); sections.get(c.id).add(h.section_id); }
  }
  const trustRank = new Map(trustOrder(catalog).map((c, i) => [c.id, i]));
  const hitIds = [...best.keys()].sort((a, b) => best.get(b) - best.get(a) || trustRank.get(a) - trustRank.get(b));
  const inWanted = c => Boolean(c.section && wanted.has(c.section));
  const plan = hitIds.map(id => ({ id, sections: whole.has(id) || inWanted(byId.get(id)) ? null : sections.get(id) }));
  const seen = new Set(hitIds);
  for (const c of trustOrder(catalog.filter(c => eligible(c) && inWanted(c) && !seen.has(c.id)))) plan.push({ id: c.id, sections: null });
  return plan;
}
