## 2. What the redesign found that the first design could not have known

On 2026-10-13 two `Victoria Fill` lists were locked INSIDE the two executing projects. A project can now hold more than one locked list. `finish_project_batch()` (read live, md5 `52bcacfbade4dcd576c7729cf61aebd0`) checks `project_batch_state().proposal_due` for ONE epic and then writes `projects.status` = `done` (or `paused` when perpetual) for the WHOLE project. Under the v7.0.749 predicate, applied as written today, the sensor would have named both `Victoria Fill` lists, and an agreed review would have set `tooling` to `done` with 67 open or partial tickets and `dev-manager-capabilities` to `paused` with 17 — the only two executing projects, so the board would have had nothing pickable. The still-live AGT-240 predicate has the same shape (it only waits for `delivered` to become `done`); it is harmless today only because `--prepare` cannot fire.

So D5 is not optional polish: the ticket's own sentence is "a **project** reaching zero open tickets marks itself finished".

The unapplied mirror also carried a whole `runner_should_boot()` body read on 2026-10-03. The open audit finding in `docs/audits/2026-W46.md` (line 1246) proposes applying that mirror. Applied today it would erase AGT-610's and AGT-642's branches (redesign-first, the card branch) from the gate. T1 rewrites the file so that text can no longer be applied by anyone.

A shadow `public.project_batch_state_agt291()` exists live (12 columns, the per-list predicate), in no tracked file, with EXECUTE granted to PUBLIC, anon and authenticated — the browser's key can read every project slug, list name and count through it. It is the v7.0.749 attempt's own litter, so closing it belongs here (pattern:124); dropping it needs a DROP and stays with `AGT-583`.

## 3. The calls (mine, reversible — JOHN-0925-DESIGNER-DECIDES)

- **D1 (kept)** `left` = members `open` or `partial`. `delivered` is built and waits only on John's release; a finish line that waits on `done` waits on John.
- **D2 (kept)** a `paused` project's list can finish (`finished_at IS NULL` already separates "paused by John" from "paused because finished").
- **D3 (kept)** the sensor is `review_due` and the gate ORs its count into `work_to_find` as `detail.finish_due`.
- **D4 (kept)** `--prepare` claims a list for 24 hours through a conditional PATCH of `epics.proposal_attempted_at` (shipped in v7.0.749; untouched here).
- **D5 (new)** finished is a PROJECT fact. A list is due only when its project is `executing` or `paused`, the list is locked, unfinished and has members, **no locked unfinished list of the same project has an open or partial member**, and **the project has not finished a list since this one locked**. The last clause stops a perpetual project (finish → `paused`) from proposing once per sibling list: after one list finishes, its older zero-left siblings are not due; a list locked AFTER that finish (the project restarted) is.
- **D6 (new)** the sensor lives in a NEW function, `public.project_finish_line()` = `project_batch_state()`'s ten columns plus `review_due` and `proposal_attempted_at`. `project_batch_state()` keeps its identity and its ten columns; only its body changes. The finished state keeps one home (pattern:14): the new function calls the old one and adds only the claim window.

Known edge, accepted: two zero-left locked lists of one project are both due until one finishes. `pickDue()` takes the first by slug then name and claims it; if two lanes each claimed one, `finish_project_batch()` re-reads `proposal_due` and refuses the second (the first's `finished_at` is later than the second's `locked_at`). Cost of the rare case: three wasted model turns, no wrong write.

## 4. Why this mechanism (the Redesign line's reason, at length)

A `RETURNS TABLE` change cannot be made by `CREATE OR REPLACE`, so widening `project_batch_state()` owes a DROP — the one statement kind the connector holds for a confirmation no unattended cycle can give. The redesign does not send that statement by another route; it removes the need for it. Engineering consequences, each real on its own:

- **Nothing is dropped.** A dropped function loses its ACL and, between the DROP and the CREATE, does not exist for `finish_project_batch()` and `apply_finish_line_backfill()`, which both call it. A body replace has no such window and keeps the grants (`{postgres, service_role}`).
- **The undo is a captured body restore**, `auto-downable`, for both existing functions.
- **The gate is edited, not rebuilt.** Three exact insertions into the LIVE text under an md5 guard (AGT-642's own pattern), instead of a 270-line body copied from a reading that is now two tickets stale.
- **Statement kinds are the ones a cloud cycle has already landed**: `agt590_sweep_isolation_hold` (2026-11-13, v7.0.1016, an unattended redesign) applied `create or replace function` + `revoke`/`grant` + `do` through `apply_migration`.

Rejected: `ALTER FUNCTION … RENAME` then a fresh CREATE (reaches the dropped-and-recreated state by another road — clause 4 — and `capture_migration_down()` refuses in-place ALTERs); a second overload of `project_batch_state` (`.claude/rules/supabase-function-signature.md`: PostgREST cannot resolve it); adopting the shadow's name as the permanent API (a ticket id in a function name; pattern:53); computing `review_due` in each reader (two homes for the claim window).

The migration keeps the NAME `agt291_finish_sensor` on purpose: `capture_migration_down()` upserts on `up_name` (`on conflict (up_name) do update`), so T2's capture replaces the stale 2026-10-03 down with today's bodies, and applying a migration of that name clears the ledger orphan AGT-562 prints at every ship (ledger-wide 2 → 1).

CREATE OR REPLACE FUNCTION public.project_batch_state()
 RETURNS TABLE(slug text, status text, perpetual boolean, epic_id uuid, epic_name text, locked_at timestamp with time zone, finished_at timestamp with time zone, members integer, "left" integer, proposal_due boolean)
 LANGUAGE sql
 STABLE SECURITY DEFINER
 SET search_path TO 'public', 'pg_catalog'
AS $function$
  -- AGT-291 D1: `left` = members open or partial (delivered is built). D2: executing OR paused.
  -- D5: finished is a PROJECT fact -- a batch is due only when no locked unfinished list of its
  -- project holds an open or partial member, and the project finished no list since this one locked.
  WITH b AS (
    SELECT p.id AS project_id, p.slug, p.status, p.perpetual, e.id AS epic_id, e.name AS epic_name,
           e.locked_at, e.finished_at,
           count(i.id)::integer AS members,
           (count(i.id) FILTER (WHERE i.status IN ('open', 'partial')))::integer AS "left"
      FROM public.projects p
      JOIN public.epics e ON e.project_id = p.id
      LEFT JOIN public.backlog_items i ON i.epic_id = e.id
     GROUP BY p.id, p.slug, p.status, p.perpetual, e.id, e.name, e.locked_at, e.finished_at)
  SELECT b.slug, b.status, b.perpetual, b.epic_id, b.epic_name, b.locked_at, b.finished_at,
         b.members, b."left",
         (b.status IN ('executing', 'paused') AND b.locked_at IS NOT NULL AND b.finished_at IS NULL
          AND b.members > 0
          AND NOT EXISTS (SELECT 1 FROM b o
                           WHERE o.project_id = b.project_id
                             AND ((o.locked_at IS NOT NULL AND o.finished_at IS NULL AND o."left" > 0)
                                  OR o.finished_at > b.locked_at)))
    FROM b
   ORDER BY b.slug, b.epic_name;
$function$;

AS $function$

         (s.proposal_due AND (e.proposal_attempted_at IS NULL

         e.proposal_attempted_at
    FROM public.project_batch_state() s
    JOIN public.epics e ON e.id = s.epic_id

$function$;
