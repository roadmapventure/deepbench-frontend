## 3. The design, and what it does not do

Three edits in one migration (`agt455_drain_score_exemption`), one mirror, one guard test, one ARCHITECTURE line:

1. `drain_epic_next(uuid)`: the gate line is **deleted** (replaced by comment H1). Every row of that pick is `runner_drain_scope s ... WHERE s.directive_id = d.id` with `d.status = 'queued'` — a named member of a queued drain by construction. Writing `OR <member>` there would be a tautology dressed as a clause.
2. `pick_exclusions()`: the AGT-427 CASE head becomes `b.need_score >= 3 OR EXISTS (<member of a queued drain-epic directive's scope>)`. THEN branches (the two reason sentences) unchanged, so every reader of those sentences (`project_blockers`, `run-project.js passOverNote()`) is untouched.
3. `prime_directive_queue()` lane (c): `AND bu.need_score >= 3` as a **lane rule**, the same placement AGT-173 gave the noship fence ("this lane's rule, not a property of the ticket"). Without it a scored-2 drain member passes `buildable` and is listed under `selfbuild` as well as `drain` — which breaks the ticket's sentence "the selfbuild lane keeps the gate exactly" and turns red the two live AGT-427 pins that grade `lane === "selfbuild"` (`tests/regression/agt-140-project-priority-pick.test.mjs:431,501` and `tests/regression/ses-281-m5-pick-enforcement.test.mjs:373,487`). With it, both pins stay green with no edit — which is what keeps this ticket inside 3 files.

What it does not do: it does not touch the ORDER BY of either pick (`pickKeys()` in agt-140 still parses the agt-427 mirror's `row_number() OVER (ORDER BY ...)`); it does not change any reason sentence; it does not add a census line to `drain_epic_next`'s blocked detail (the gate no longer exists there, so there is nothing to census); it does not exempt a member once its drain retires (status `done`) — the exemption follows the queued directive, which is John's naming, and ends when the directive does.

Alternatives weighed:
- Append the migration to `docs/design/agt-427-scored-pick.sql` (the ticket's first-named mirror) — rejected: three tests read that file (`agt-140`, `ses-281`, `agt-456`) and `pickKeys()` regex-parses its first `row_number() OVER (ORDER BY` block; a second `prime_directive_queue` body in it is a drift risk for nothing. The ticket allows "or a sibling".
- Put the guard arms into the agt-140 suite instead of a new file — rejected once the lane (c) rule removed the need to edit it; a per-ticket guard with mirror needles is the current shape (AGT-450, AGT-456).
- Create a shared `in_queued_drain_scope(uuid)` helper for both homes (pattern:14) — rejected: `drain_epic_next` needs no predicate at all, so there is only one home that evaluates it; a new function adds an EXECUTE surface that must be revoked by name (SES-315 addendum) for no second caller.
- Exempt only members of an *exclusive* drain — rejected: the ticket's words are "a member of a queued drain-epic directive's scope"; exclusivity is AGT-456's pick-holding property, not John's naming.
