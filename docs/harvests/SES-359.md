**P10 - Tooling.**

## Use case

session-setup §3f (SES-331) lets a session assemble a governance agent's prompt with `scripts/agent-prompt.js`, but nothing requires it. Measured 2026-09-10: The Designer has 2 logged calls and The Builder 1, all first-run fixtures; 0 of the tickets done since 2026-09-08 carry `kickoff_link`; all 23 Governance Agents kickoffs were written by the attended session by hand and every build was a Claude Code agent spawned with a hand-written prompt. The architecture says DeepBench builds itself with its own agents; the practice is Claude Code with a runbook.

## Build

`CLAUDE-DESIGN.md` Step 4 and session-setup 3c/3f change reader: the kickoff is the `design-kickoff` assembly's returned `kickoff_markdown` written to `kickoff_path` with `kickoff_link` + `design_status='designed'` in one write; the coding agent is spawned with the `build-ticket` assembly on the orchestrator lane, never a prompt the session composes; the session's verdict row records the sha it graded (SES-345's join key). The hand-built path is retired with a ledger entry; one named exception survives for edits to the governance agents' own Skill rows (self-certification, AGT-67). Each run logs through `agent-log.js` with `call_source='session'`.

## QA that discriminates

The first ticket shipped attended after this change has all four rows and a Designer + Builder log row each; on origin/dev SES-347 (shipped attended 2026-09-10) has `kickoff_link` NULL and no Designer or Builder row.

## Scope added 2026-09-10 (John: "do it", after the API-spend scan)

Every kickoff carries a **lane declaration** for every model call it will make: `session` (subscription, the default for governance and tooling work), `executor` (API dollars, allowed only when the executor is the thing under test or the ticket is product-facing live QA), or `none`, each with one line of reason and a rough dollar band for any executor call. Lives in three places, one wording: `CLAUDE-DESIGN.md` Step 4's mandatory kickoff structure, the kickoff template, and the Designer's `ds-kickoff-intent` output schema (a required `lanes` array). The Verifier refuses a kickoff-backed ship whose log rows show an executor call the kickoff did not declare.

QA that discriminates: a kickoff with no lane declaration fails `check-session-docs` and the Designer's schema; SES-348's kickoff declares `executor` with its dollar band, SES-343's declares `session`.
