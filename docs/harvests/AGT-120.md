## 4. Why the table is closed this way

`.claude/rules/supabase-column-grants.md` (SES-78a): new tables are born anon-readable, so `REVOKE ALL` is required. `REVOKE ALL` also removes TRUNCATE, REFERENCES, TRIGGER and the PG17 MAINTAIN that `information_schema` cannot see (DAT-20). The DO block therefore also reads `relacl`. The test asserts the observable pair: anon refused (not a 404, which would pass on a missing table) AND service 200. RLS is not used because no browser path reads the table.

## 7. Alternatives considered

- **Reuse `career_records` with a lane column.** Rejected. Nathan must never read it, and a shared table would put a personal-lane trust boundary behind a row filter.
- **Market facts in Knowledge Skills.** Rejected. Product-lane Skills are anon-readable (relacl above), and prices, prospects and competitor judgments are not public.
- **One capability with eleven intents.** Rejected. The ticket says one Capability plus Skill per job, and eleven capabilities let the broker offer each job separately.
- **Pin `is_active=false` in the test,** as AGT-82 did. Rejected (ruling 10).
- **Store the moat as a standing `message` and IP as `feature_benefit` rows.** Rejected. Mixing kinds breaks the one-kind-one-meaning rule (pattern:54), and the IP register needs its own required fields.
- **Keep `conversation` read-only.** Rejected (ruling 16). Napkin prospect notes would stay trapped outside the store Nathan reasons over.
