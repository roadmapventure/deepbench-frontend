## Why the fix lands where it does

**The builder, not the caller.** The `--data` file is the invoker's; the only place that can
refuse a stale one on every path is the script that consumes it (pattern:8, the narrowest layer
that works; pattern:17, extend a structure that already fits). The refusal is shaped exactly like
`:411`'s version refusal, which is the precedent in the same file: required argument, no default,
exit 2, reason stated in the message.

**The one sanctioned writer, not a wording.** Step 9's completion sentence was hand-authored 41
times tonight and drifted 7 ways. A correct value exists deterministically — the count of
`runner_skips` rows with `resolved_at IS NULL AND briefed_at IS NULL` — so no model may be in
charge of it (pattern:10, and after instruction-level drift go structural, never a third
wording). `cycle-heartbeat.js` already has the shape this needs: a pure `parseArgs` the test
drives directly, an injectable `doFetch`, and exit codes as a contract.

**Why the derived string says what it measures and not what it concludes.** `--tail` could try
to assert "published" / "not published", but nothing records a publish. It records the fact it
can prove (pattern:33/34 — if it can't be verified, don't show it; render honest absence):

- n = 0 → `9 — tail complete: 0 skip rows unbriefed`
- n > 0 → `9 — tail deferred: <n> skip rows unbriefed (no publish stamped)`

Under (5b) the stamp runs only after a republish returns, over exactly the rows with
`briefed_at IS NULL AND resolved_at IS NULL`, so n > 0 at the tail is proof this tail's stamp did
not run. The word a reader needs — deferred or complete — is now computed from that, and the
number is in the string so the claim is checkable.

## Alternatives weighed and rejected

1. **Widen `runner_cycles_outcome_check` to admit `deferred`, or add a `tail_state` column with
   readers.** Rejected for this cycle, and this is the scope call. It is a migration plus every
   reader of the column, and it belongs with `AGT-192` and `AGT-233` — the "step 9 grades
   nothing" family — because a general grader over a declared vocabulary is one build, not three
   tickets each inventing half of it (pattern:65, park the general mechanism; pattern:120, ship
   the working per-instance version and file the normalization). It is a generalization, never
   AGT-188's own acceptance criterion, so filing it discharges nothing this ticket owes
   (pattern:95).
2. **Compare `data.for_version` against `--version` instead of a cycle id.** Rejected: a cycle
   that is `gated_before_build` has `version IS NULL` (4 such rows tonight) while its cycle id
   always exists from step 1. The cycle id is the identity; the version is the masthead. The
   kickoff keeps the version comparison as a *second*, conditional assertion — when the fetched
   row's `version` is non-null it must equal `--version` — which catches a mismatched masthead as
   well, on one read the builder was already positioned to make.
3. **A model or a reviewer told to check the `--data` file's freshness.** Rejected outright:
   pattern:9 — never spend a model call where a deterministic mechanism serves.
4. **Rewriting the 41 historical `last_step` strings.** Not done, deliberately. A check grades
   the change, never the live world (pattern:162); rewriting stored records of cycles this change
   did not run in would falsify the history it is trying to make readable.

## The honest limit of the fix

`data.cycle_id` is authored, so a cycle that pastes its own id onto a predecessor's prose still
builds a stale page. No mechanical check can read prose for whose night it describes. What the
gate removes is the *silent* path — the one that actually happened, where nobody typed anything
wrong and the stale file simply carried through. Naming this is the point; a gate sold as
stronger than it is becomes the next unfalsifiable artifact.
