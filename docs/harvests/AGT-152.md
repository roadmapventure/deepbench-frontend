## 2. The premise, corrected

John's rule (walkthrough Q3, 2026-09-25): every switch undoable in one step. Today `apply_model_assignment()` writes the switch, images the row, and hands back a `reverse_decision(...)` hint that cannot work, twice over:

1. `model_assignments` is not in `k_allowed` → the image is counted `refused` at the top of the loop.
2. Even once it is, the PK is two columns and `pk_value` is a slash-joined string → `reverse_decision()` reaches `v_pk_cols = 2` and refuses again.

So the ticket's fix (widen both lists) is necessary and not sufficient. The kickoff adds the missing half: a single-column PK on `model_assignments` and images keyed by it. Every other table on the allowlist already has a uuid `id` PK (pattern 17: make the new table look like the fifteen, rather than teach `reverse_decision()` a second addressing scheme).

`updated_at` matters and helps: the row's `updated_at = now()` is written in the same transaction as `record_decision()`, so `updated_at = decided_at`, the written-since guard (`v_updated > v_decided`) does not fire, and the restore counts as `restored` (verified), not `restored_unverified`. After `review_model_watch()`'s self-revert the row's `updated_at` is later than the original switch's `decided_at`, so a Reverse of the *original* switch is refused as written-since — correct: the revert is the live decision, and it is the one to reverse.

Defect (2): the lane branch of the sync trigger moves every Skill whose `llm_model` equals the old lane model, including a Skill a capability row assigned separately. Fix at the data layer (pattern 8): one predicate, `lane_member_skills(model)`, that excludes any Skill named as `default_intent_slug` by a capability that has its own `model_assignments` row — used by the trigger and by both imaging sites in `apply_model_assignment()` / `review_model_watch()` (pattern 14: the set imaged must be the set moved, or a later capability switch would be clobbered by a lane reverse). The `is not null` filter is load-bearing: 16 capabilities have no default intent and a `NOT IN` containing NULL matches nothing.

## 3. Alternatives weighed

- **Teach `reverse_decision()` composite PKs** (pk_value as a JSON object naming every PK column). Generic, would survive a future composite table, but touches the addressing core at five `execute format(...)` sites of the most-pinned function on the platform (ses-316, ses-364, ses-399), for one table nobody else shares the shape with. Rejected as the wider change (patterns 8, 65).
- **Inline the exclusion in three places** instead of `lane_member_skills()`. Three copies of one membership rule drift (pattern 14). Rejected.
- **One migration for the PK swap and the functions.** `capture_migration_down()` nulls `down_sql` for the whole call on any refusal, so naming the table would erase the six functions' auto-down. Two ups: `agt152a_model_assignments_pk` (table, `refused`, card-only — disclosed exactly as `ses254_epic_id_review_only` was) and `agt152b_reversible_model_assignments` (six functions, `auto-downable`). Hand-writing the table's down is forbidden by runner-cycle.md step 6 and not proposed.
- **Suppress the sync trigger during a Reverse.** Not needed: the restore of the `model_assignments` row fires the trigger, which moves `lane_member_skills(new model)` back — the same rows the decision imaged — and the direct restores of those 54 images then rewrite identical values. Order-independent and idempotent.
- **Put defect (3) in this slice.** Five files would be needed (migration, ses-364, ses-399, agt-143, ses-378d). The two re-pins to 16 cannot be deferred — the widening turns two green tests red (pattern 124) — so defect (3) is the slice that moves.

Model: `claude-fable-5-1`, the judgment lane in `runner_model_lanes` — schema and undo semantics of the ledger are judgment-dense; the lane's own degrade to `claude-opus-5` under `fable_pace` applies at pick time. Lanes: session; executor none ($0).

## 5. Discoveries to file (evidence-only; not this ticket)

- **Lane membership by equality merges lanes that share a model.** `runner_model_lanes`: orchestrator `claude-opus-5` (33 Skills), judgment `claude-fable-5-1` (54). A judgment switch to `claude-opus-5` would make 87 rows indistinguishable, and the next orchestrator switch — or a Reverse — would drag all 87. `skill_profiles` has no lane column; AGT-143 chose equality. Not a defect today (no two lanes share a model); a structural row (lane column or a `capability→lane` map) is its own design.
- **`apply_model_assignment()`'s `v_reverse` hint** becomes true only after this ship; the agt-144 SQL header (lines 24–28) records the old refusal and stays as history until AGT-152b annotates it.
