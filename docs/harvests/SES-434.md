Runbook 7b names deferral as a decision; the rule is instruction-level and has now failed three times on one ticket family → pattern:10, go structural.
Proposed ticket (P10 - Tooling, S, 1 cycle, project moat-support): *"A hand write of a judgment column on backlog_items is imaged by the table itself: an AFTER UPDATE trigger writes a runner_before_images row (session_name = 'hand-write:' || current_user, pk = id, row_data = OLD) whenever defer_status, defer_reason, status, tier or priority_class changes and no image for that pk exists in the current transaction."* QA that would fail if nothing changed: in a rolled-back block, `UPDATE backlog_items SET defer_status='yes', defer_reason='x' WHERE backlog_id=<fixture>` with no prior image → exactly one new image with `row_data->>'defer_status'` = the OLD value; the same UPDATE preceded by a 7b image → no second image.
