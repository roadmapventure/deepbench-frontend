## The harvest's replacement string was defective — the finding that changes the build

`docs/harvests/AGT-147.md` "The shape" states `agt-70`/`agt-86h` "do not pin this cell (grep verified)". Re-verified fresh, that is wrong in the way that matters. `tests/regression/agt-86h-auditor-routine.test.mjs:163-165`:

```js
const ids = [...new Set(md.match(/claude-[a-z]+-[0-9][0-9a-z-]*/g) ?? [])];
assert.ok(ids.length >= 1, "the runbook names the orchestrator model");
for (const id of ids) assert.ok(lanes.has(id), `${id} is not a MODEL-LANES-SNAPSHOT id`);
```

It does not pin the *cell*; it pins the *file* to holding **at least one** `claude-*` id. `grep -oE "claude-[a-z]+-[0-9][0-9a-z-]*" docs/runbooks/auditor-routine.md` returns exactly **one** hit, on line 10 — the id the ticket asks to delete. Applying the harvest's string alone turns a green `agt-86h` red. This is why the kickoff ships 4 files, not the 3 the ticket filed.

The amendment inverts the claim rather than deleting the arm: the file must now cite `public.model_assignments`, and the per-id snapshot loop (line 165) is kept, so a stale or unknown id appearing later is still caught. The old assertion graded the *old* premise; after AGT-142 it graded the world backwards (pattern:162, pattern:94).
