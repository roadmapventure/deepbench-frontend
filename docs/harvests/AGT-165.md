### (c) The URL cannot be a string in the repo

Thirteen mentions of `https://deepbench-frontend-git-dev-roadmapventures-projects.vercel.app` across
`docs/` and zero mentions of any other host: the repo does not know its production URL.
`vercel.json` rewrites `/api/mcp` → `/api/capabilities/execute?transport=mcp`, so the *path* is
identical on every deployment. `window.location.origin + "/api/mcp"` is therefore correct by
construction on whichever host the tester opens, and cannot go stale when the deployment moves —
pattern:35 (live-wired from its real source) and pattern:2 (data-driven over hardcoded).

not. If John hands the tester a protected preview URL rather than a production one, the connector
fails at step 2 no matter what the page says. That is a deployment choice, not a page element.

## 4. The nav-entry conflict, stated rather than obeyed silently

`.claude/rules/autonomous-surface-changes.md` binds `src/screens/**`, `src/AppShell.jsx` and
`src/main.jsx` in Automated-mode sessions, and says: "New screens ship route AND nav entry behind a
flag (a data row, `HAR-41`…)". Honouring the nav clause means editing `src/AppShell.jsx` — a fourth
file — against a 3-file cap that pattern:72 reserves to John. Three reasons the exception is the
right call rather than a corner cut:

1. The ticket's own words are "a page on DeepBench the tester opens by URL, no login". A nav entry
   puts an outside-tester onboarding page into John's chrome, where it has no use.
2. `src/lib/featureFlags.js`'s reader resolves every unknown answer to **false** — no row, failed
   fetch, malformed override. Gating the one page the tester must reach behind that reader makes a
   network blip indistinguishable from "the page does not exist". Wrong failure direction for
   onboarding, right for the surfaces the rule was written about.
3. The zero-deleted-lines half of the rule is honoured exactly: `src/main.jsx` gains one import and
   one `<Route>`, nothing is removed, and no existing screen or `AppShell.jsx` is touched.

pattern:94 says don't silently patch against a locked rule and don't silently obey it either, so the
amendment is filed as its own row (kickoff §7 (c)) rather than smuggled into this ticket's diff.

## 5. Alternatives considered and rejected

- **A static `public/connect.html`.** Served ahead of the `/(.*)` rewrite, so it would work and would
  cost no route. Rejected: it can carry no `src/tokens.js` value, so it either hardcodes hex (the bug
  `.claude/rules/design-tokens.md` names) or looks like a different product (pattern:53).
- **Adding the page to `TeachScreen.jsx`** as a panel. Rejected: the ticket asks for a page reached by
  URL with no login, and editing an existing screen risks the zero-deleted-lines rule for no gain.
- **Printing `MCP_API_KEY` from an env var at build time.** Rejected on pattern:139 and on the
  runbook's own "No key value ever belongs in this repo" — and it would ship the governance lane to
  the open internet, which is a worse outcome than the ticket's own goal.
- **A live `tools/list` probe on the page** to prove the connector works. Rejected: it is a second
  mechanism, it needs `/api/mcp` reachable from the browser through the HAR-33 gate, and it is not
  what the ticket asked for. Filed-adjacent: the W40 audit already carries "one connection check per
  client" against this ticket, ruled to wait for the project's next proposal.
