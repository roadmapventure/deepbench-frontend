## Why a delta, not a week-scope, and not notRun()

Three candidate shapes were weighed.

1. **`notRun()` when the state is absent.** Rejected: the state is not absent. Credentials
   resolve and the ledger answers. `notRun()` here would stop verifying something verifiable and
   would let a real ingest regression through silently — the parts already have a correct
   `notRun()` guard for the genuinely-absent-credential case at lines 1098–1102 / 1381–1385.
2. **Week-scope to `WEEK` (the ticket's first suggestion), i.e. `iso_week=eq.2026-W37` against
   `FIXTURE.findings.length`.** This is the AGT-101 precedent and would go green today (W37 is
   exactly 6). Rejected as the primary form because part Q's own subject is a **W38** dry ingest:
   a W37-scoped count is blind to the exact regression Q exists to catch. It also still grades the
   live world — W37 gaining one legitimate row reddens the suite again, which is the defect class
   this ticket is meant to end.
3. **Before/after delta (chosen).** Snapshot both counts before the part's first spawn, assert
   unchanged after. This is what each pair's own comment already promises — "must leave both
   exactly where it found them" (line 1128) and "Nothing above passed `--apply`" (line 1494). It
   covers every week, it cannot be reddened by the ledger growing, and it tightens rather than
   loosens: it fails on a one-row move, which the literal `6` could not distinguish from ordinary
   growth. `pattern:1` (eliminate, don't bound), `pattern:3` (reproducible over convenient),
   `pattern:162`.

Residual risk, named and accepted rather than engineered around (`pattern:67`): a peer cycle
writing `audit_findings` *during* the part would flake the delta (SES-382 — cycles run in
parallel). The window is seconds and the ledger is written only by `audit-ledger.js --apply`
under John's weekly gate. Week-scoping would not remove this risk either. No machinery added.
