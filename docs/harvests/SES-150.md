# SES-150 — an attended session can record a board before-image

`public.backlog_items`' `SES-150` row is the pointer; this file holds the ship record. Written at
close-out because the row's own description crossed the 2,000-char cap that
`scripts/check-session-docs.js` check 3d enforces — the detail moves here, the row keeps a pointer,
and nothing is deleted.

## The gap, read live rather than recalled

`runner_before_images.cycle_id` was `uuid NOT NULL` with an FK to `runner_cycles(id)`, while
`CLAUDE-DESIGN.md` tells **every** session to record a before-image for each `backlog_items`
UPDATE (citing `ARCHITECTURE.md` §19v). An **attended** session has no cycle row, so it had nothing
to put in the column and structurally could not comply.

Found live three times, and **disclosed every time rather than skipped**:

| Where | What happened |
|---|---|
| `docs/SESSIONS.md:1819` | `SES-148`'s close shipped with its before-state in prose; the gap was filed as `SES-150` |
| `docs/SESSIONS.md:1514` | `SES-165`'s filing — *"impossible for an attended session"* |
| `docs/SESSIONS.md:1526` | `SES-166` — *"disclosed, not skipped silently"* |

Three honest disclosures are not an audit trail. A before-value living in `SESSIONS.md` prose is a
fact with a second home and is **not restorable by a Reverse** — the property §19v exists for.

## The mechanism, and why the other two were rejected

Migration `ses150_before_image_attended_sessions`: `cycle_id` loses `NOT NULL`, `session_name text`
is added, `ck_before_image_attribution` requires **exactly one** of the two, and a second check
refuses a blank `session_name`.

Of the three mechanisms the ticket named:

- **A parallel table** gives one fact two homes. Every reader would have to know to union them, and
  the first reader that forgets reads a partial audit trail as a complete one.
- **Scoping the doc rule to Automated mode** resolves the contradiction by *giving up* the audit
  trail for exactly the writes John's own attended sessions make — on a milestone named Truth
  Infrastructure. It makes the docs consistent and the ledger worse.

**`ck_before_image_attribution` is the half a later editor will read as redundant tidying on top of
"make `cycle_id` nullable". It is not.** Dropping `NOT NULL` alone lets an Automated cycle insert an
**unattributed** before-image — a row satisfying §19v's *"no before-image, no write"* while naming
nobody, which is a worse ledger than the gap being closed. The XOR is load-bearing in both
directions: a row carrying **both** columns makes *"which session wrote this"* ambiguous at the one
moment a Reverse needs the answer.

`session_name` is `text` and deliberately **not** an FK: attended sessions have no table of their
own — that absence *is* this ticket — and inventing one is a second feature.

**Grants, read live first (`.claude/rules/supabase-column-grants.md`):** `anon` and `authenticated`
hold zero privileges of any kind on this table — only `postgres` and `service_role` — so the
additive column needs no grant and `DAT-18`'s posture is unchanged.

why arm 2 could not have passed on the old build.

| **2 (the ticket)** | `cycle_id` **null**, `session_name` set | ACCEPTED | **ACCEPTED** |
| 3 | neither set | REJECTED | REJECTED |
| 4 | both set | REJECTED | REJECTED |
| 5 | `session_name = '   '` | REJECTED | REJECTED |

Both fixture rows deleted afterwards, table re-asserted at 0 for `table_name='zz_ses150_fixture'`.
A before-image of a before-image insert is an infinite regress, so the fixtures are recorded here
instead of in the ledger — named, not quietly skipped.

## What shipped, and what was deliberately not touched

`CLAUDE-DESIGN.md`: the mechanism stated **once** in the Backlog Capture standing rule (which
column, whose, exactly one, both failure directions, when the gap ended), with pointers from the
three instruction sites — the tier re-sweep rule, step 9, step 5c. A session reads step 9, not the
standing rule twenty screens above it.

`tests/regression/SES-150-before-image-attribution.js` guards both halves. The rule is read out of
the doc, never restated; every clause carries a negative control; the file-level control is
`origin/dev`'s own guide, on which the test FAILS. Its live half is non-mutating by construction —
it asserts a *refusal*, so a pass writes nothing — and discriminating by which error it demands: a
`NOT NULL` violation there means the migration did not land.

**`ARCHITECTURE.md` §19v was NOT edited, deliberately.** Architecture supersessions are the gated
lane, and §19v's sentence — *"every **Automated-mode** write records the prior row state first"* —
stays true. What changed is that `CLAUDE-DESIGN.md` stops citing it as authority for an obligation
it never placed on attended sessions. **Whether §19v should be widened to state the attended
obligation outright is John's call**, named on the ship card rather than taken here.

The instruction surface was swept before editing (Sonnet 5 subagent, whole repo, all file types):
five sites in two files — `CLAUDE-DESIGN.md` 135/255/282 and §19v's two. Root `CLAUDE.md`,
everything under `.claude/`, and `docs/STANDARDS.md` carry none, so there is no `needs-desktop`
remainder.
