## C. The design, and why each call is made (all reversible; JOHN-0925-DESIGNER-DECIDES)

**C1. Signature and return type unchanged (mechanism, not convenience).** `.claude/rules/supabase-function-signature.md`: a changed argument list or return type makes a second overload that `CREATE OR REPLACE` does not replace. Keeping `(uuid, text) returns table(finalized integer, promoted integer, closed integer)` makes the replace a true in-place replace, keeps the cycle tail's and `run_window_finaliser()`'s three-column read, and keeps `ses-320-delivered-exit`'s three-key `SWEEP_OUT` pin. The migration still asserts exactly one overload of each function (§B4).

**C2. The per-row outcome sits on the decision row** (pattern:17, pattern:93). Finalised is already per-row (`status`, `finalized_at`); promoted is already per-row (`ladder_applied_at`); the missing outcome is the refusal, so `runner_decisions` gains `refused_at`, `refusal_reason` and the hourly record gains `refused`, `refusals`. Differences from v7.0.959:
- the handler writes only when the reason CHANGED, and `refused_at` is the first refusal of the current streak. v7.0.959 re-stamped every hour and wrote a before-image each time: 24 images a day per stuck row, for ever.
- the row's ordinary before-image stays inside the row's subtransaction (as the agt-423 mirror has it), so a refusal leaves exactly one image — the handler's — and only on a change.
- the hourly record lists STANDING refusals (`status='open' and refused_at is not null`), which is what a reader of a stall needs and does not depend on the same-transaction `now()` trick.
- a refused row clears both columns the moment it finalises.
- `exception when others` does not trap `query_canceled`, so a statement timeout still aborts the whole call and reaches `run_window_finaliser()`'s error row. That is the wanted behaviour: a timeout is the sweep being broken, not a row being refused. (PL/pgSQL documented behaviour; stated from the manual, not exercised this turn.)
- if the handler's own two writes raise, the whole sweep aborts and the hourly row carries the error. Swallowing that would be the "swallowed reason" the ticket forbids.

**C3. The HOLD is a cut-off constant `c_hold` in the function body** (pattern:18). A window with `expires_at < c_hold` finalises with no `ladder_apply_signal` call and its `ladder_applied_at` left as it was (null for the arrears). A window that expires at or after the cut-off pays exactly as the live body pays today — M6-07 is deferred for the outage's windows, not weakened for new work (pattern:166). The Builder sets `:H` to the next whole UTC hour after the apply; §B4 refuses a cut-off that is in the past (something expired-before-apply would be paid) or more than 3 hours ahead (too much fresh work held). Held signals stay readable as `status='final' and ladder_work_class is not null and ladder_applied_at is null and expires_at < ':H'`, each with the finalise's before-image; nothing about them is decided here.
- Rejected: stamping the arrears as applied (v7.0.959) — a data statement that decides what the ladder will ever count; ruled out.
- Rejected: removing the ladder call outright until the arrears are ruled — that weakens M6-07 for new work on my authority.
- Rejected: reading the cut-off from `runner_migration_downs.captured_at` — a capture followed by a refused or delayed apply would leave a stale cut-off and pay the gap.
- Rejected: a standing "older than N hours is held" rule — a new permanent ladder rule, not this ticket's.

**C4. A per-run bound `c_max`, sized by a measurement, with refused rows sorted last** (pattern:67 — the bound it answers to is the 120 s `statement_timeout`; pattern:1). v7.0.959 rejected a bound without timing anything. 9,777 subtransactions, each with a before-image insert, inside one statement is untimed; if it does not fit, nothing commits and every later :17 fails the same way — the present stall with a new cause. T3 times 500 rows in a transaction that always rolls back, and `c_max = min(5000, floor(100000 / ms) * 100)` targets 20 s a run (one sixth of the statement timeout, one third of the 60 s tool ceiling). Checked in node: ms 800 → 5000, 4000 → 2500, 13000 → 700, 99,999 → 100, 120,000 → 0 (STOP). The 5,000 ceiling is there because a 500-row sample is not evidence for a 10,000-row run. Steady state needs about 10 windows an hour (9,777 in 39 days), so any `c_max` ≥ 100 keeps up; the backlog drains in `ceil(9,777 / c_max)` runs — T5 makes up to 8 by hand and the hourly run takes the rest.
- `order by d.refused_at nulls first, d.expires_at`: with a bound and plain expiry order, the oldest refused rows would hold the head of every batch, and enough of them would stall the platform again. Never-refused rows go first; refused rows are retried with the capacity left.
- Unverified: more than 64 subtransactions in one transaction overflows the per-backend subtransaction cache and slows other sessions' visibility checks while that transaction is open. That is general Postgres behaviour recalled from memory, not measured here; the bound limits it either way.

**C5. Schema is its own migration, applied before the probe.** The probe has to run the new function body, which reads `refused_at`; adding the columns inside the probe would hold an ACCESS EXCLUSIVE lock on `runner_decisions` for the probe's whole duration. So `agt590_outcome_columns` (four additive columns, 0 rows rewritten, no behaviour) goes first. Its down is honestly `refused` — `capture_migration_down()` refuses an in-place ALTER by design, and the only undo is a column drop, which the tool layer holds for an attended confirmation (cycle a2fcf5a4, AGT-548). v7.0.959 named only the two functions in its capture so the ALTER never reached the ledger; this design captures it and reports the card-only range at 8a, as `ses254_epic_id_review_only` did. The function migration's down is `auto-downable`.

**C6. New migration names** (`agt590_outcome_columns`, `agt590_sweep_isolation_hold`). Cycle 637e7515 may have captured a down under `agt590_sweep_per_row_isolation` before it was refused; I could not read `runner_migration_downs`. A new name keeps the ledger unambiguous and makes the test's `captured_at` lookup return this build's row. The content is a different migration; this is not the refused one renamed.

**C7. What this does about the refusal.** Nothing is worded around it. The build still applies two migrations to the live database and runs a sweep; whether this environment's check lets an unattended Builder do that is not something a design can settle. What changed is engineering: no data statement outside the functions, no autonomy change, the schema separated from the function replace, the catch-up bounded and proven in a transaction that cannot commit. If a step is refused, the kickoff's STOP LINE sends the Builder to `--refuse` with the nine facts and nowhere else.

## B2. The sweep's handler (replaces the agt-423 mirror's `exception when others then … end;`)

```sql
    exception when others then
      -- The row's own subtransaction is rolled back: the decision stays `open` and is retried.
      v_why := left(sqlstate || ' ' || sqlerrm, 2000);
      if r.refusal_reason is distinct from v_why then
        insert into public.runner_before_images (cycle_id, session_name, table_name, pk_value, row_data)
        values (p_actor_cycle, p_actor_session, 'runner_decisions', r.id::text, to_jsonb(r));
        update public.runner_decisions d
           set refused_at = coalesce(r.refused_at, now()), refusal_reason = v_why
         where d.id = r.id;
      end if;
    end;
```

## B4. `agt590_sweep_isolation_hold` — the closing block, section (g)

```sql
do $qa$
declare v_n integer; v_res text; v_src text; f text;
begin
  foreach f in array array['sweep_decision_windows', 'run_window_finaliser'] loop
    select count(*)::integer into v_n
      from pg_proc p join pg_namespace n on n.oid = p.pronamespace
     where n.nspname = 'public' and p.proname = f;
    if v_n <> 1 then
      raise exception 'AGT-590 QA: % overload(s) of public.%, expected exactly 1 (.claude/rules/supabase-function-signature.md)', v_n, f;
    end if;
  end loop;

  select pg_get_function_result(p.oid), p.prosrc into v_res, v_src
    from pg_proc p join pg_namespace n on n.oid = p.pronamespace
   where n.nspname = 'public' and p.proname = 'sweep_decision_windows';
  if v_res <> 'TABLE(finalized integer, promoted integer, closed integer)' then
    raise exception 'AGT-590 QA: the sweep returns %, not the three SES-320 columns', v_res;
  end if;
  if position('exception when others' in v_src) = 0 or position('c_hold' in v_src) = 0 then
    raise exception 'AGT-590 QA: the deployed sweep lacks the per-row handler or the hold cut-off';
  end if;

  foreach f in array array['public.sweep_decision_windows(uuid, text)', 'public.run_window_finaliser()'] loop
    if has_function_privilege('anon', f, 'EXECUTE') or has_function_privilege('authenticated', f, 'EXECUTE') then
      raise exception 'AGT-590 QA: EXECUTE on % is still held by anon or authenticated (SES-315: revoke by name)', f;
    end if;
    if not has_function_privilege('service_role', f, 'EXECUTE') then
      raise exception 'AGT-590 QA: service_role lost EXECUTE on % -- the revoke was too wide', f;
    end if;
  end loop;

  if not (timestamptz ':H' >= now() and timestamptz ':H' <= now() + interval '3 hours') then
    raise exception 'AGT-590 QA: the hold cut-off is not 0-3 hours ahead of this apply -- set :H in both places and apply the corrected file';
  end if;
end $qa$;
```

A raise on the cut-off means the file's `:H` is stale. Correcting `:H` in both places and applying the corrected file is a different statement with a different cut-off; it is not a retry of a refused action. A permission refusal is a different thing and goes to `--refuse`.

## B5. The timed probe (T3) — one statement, and it cannot commit

```sql
do $probe$
declare
  t0 timestamptz; v_ms numeric; s record;
  v_before text; v_after text; v_ref integer; v_281 integer;
begin
  select md5(coalesce(string_agg(l::text, '|' order by l::text), '')) into v_before from public.runner_ladder l;

  execute $ddl$
    -- T1 (b): the whole `create or replace function public.sweep_decision_windows(...) ... $function$;`
    -- statement from docs/design/agt-590-sweep-isolation-hold.sql, verbatim, c_max = 500.
  $ddl$;

  t0 := clock_timestamp();
  select * into s from public.sweep_decision_windows(null, 'agt-590 probe');
  v_ms := round(extract(epoch from clock_timestamp() - t0) * 1000);

  select count(*)::integer, (count(*) filter (where d.refusal_reason like '23514 %AGT-281%'))::integer
    into v_ref, v_281
    from public.runner_decisions d
   where d.status = 'open' and d.refused_at is not null;

  select md5(coalesce(string_agg(l::text, '|' order by l::text), '')) into v_after from public.runner_ladder l;

  raise exception 'PROBE ms=% fin=% pro=% clo=% refused=% agt281=% ladder_same=%',
    v_ms, s.finalized, s.promoted, s.closed, v_ref, v_281, (v_before = v_after);
end $probe$;
```

- The closing `raise` aborts the statement, which rolls back the function replace (DDL is transactional), every finalise, every ticket close, the queue recompute and every before-image. The answer arrives as the error text. The repo has the precedent: `ses-320b-window-finaliser.test.mjs` records the finaliser's exception branch being "exercised in a rolled-back DO block".
- It contains no top-level `DROP`, `DELETE` or `TRUNCATE`.
- Reach while it runs: row locks on up to 500 decisions (other sweeps skip them) and on the delivered tickets behind any ship row among them (a cycle writing one of those tickets waits for the probe's seconds). Hence "outside :12–:20", clear of the :17 run.
- `agt281=0` with `refused=0` at the probe means AGT-281's refused row is not among the first 500 by expiry. That is not a failure of the probe; QA 1's second half is then proven by T5, and "0 refused after the drain" is a FAIL there.
- No answer inside the 60 s tool ceiling means more than 120 ms a row. Nothing is committed. The kickoff says STOP: a bound under 100 rows would not be a design I timed.

## G. Alternatives rejected

- DROP + CREATE with five OUT columns (AGT-423 as written): a second overload risk, a broken `SWEEP_OUT` pin, and a top-level DROP.
- A new `runner_sweep_refusals` table: a second home for a per-decision fact, born readable by `anon` (SES-384) and needing its own revoke and zero-grant-row QA.
- `record_skip()` for the refusal: it attributes by cycle, and the pg-cron path has none.
- Finalising the decision but skipping only the ticket close: the decision would read `final` over a ticket that never closed.
- An unbounded first run on the argument that the hourly caller is bound enough: untimed.
- A `p_limit` parameter: a signature change, hence a second overload to drop and assert.
- Loosening `backlog_done_requires_verdict()` or writing a decision over AGT-281's block: forbidden by the ticket; AGT-281 is John-named.
