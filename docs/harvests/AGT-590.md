## 2. The design calls, and why (JOHN-0925-DESIGNER-DECIDES, all reversible)

1. **No signature change, therefore no DROP.** `.claude/rules/supabase-function-signature.md` requires a DROP of the stale identity only when the identity or return type changes. Keeping `returns table(finalized integer, promoted integer, closed integer)` makes `CREATE OR REPLACE` a true in-place replace: one overload by construction (the migration still asserts it), the ACL survives (asserted both directions anyway), and the one statement the tool gate hangs on is never issued. It also keeps `tests/regression/ses-320-delivered-exit.test.mjs` green — its live sweep arm asserts the deployed function's keys equal `SWEEP_OUT = ["finalized","promoted","closed"]`, which AGT-423's five-column design would have broken (its own cycle notes flagged that seam). And the two callers survive untouched: runner-cycle.md (7b)'s "three numbers" sentence and `run_window_finaliser()`'s `select s.finalized, s.promoted, s.closed into r`.
2. **The per-row outcome lives on the decision row** (pattern:17, pattern:93). Finalised and promoted were already per-row facts (`finalized_at`, `ladder_applied_at`); the missing one is the refusal, so `runner_decisions` gains `refused_at timestamptz, refusal_reason text` (`SQLSTATE || ' ' || SQLERRM`, so the 23514 is on the row verbatim). A refused row stays `open` past expiry, is retried every :17, and clears its refusal columns the moment it finalises. The hourly record gains `refused integer not null default 0, refusals jsonb` (AGT-423's shape), derived by `run_window_finaliser()` from `refused_at >= now()` — `now()` is constant per transaction and the sweep stamps it, so the predicate is exact. Grants: `information_schema.role_table_grants` for both tables lists `service_role` only (anon/authenticated hold nothing), so the new columns expose nothing new; `runner_decisions` has one trigger (`UPDATE OF reasoning`), unaffected.
3. **Arrears stamp, re-measured.** Of the 8,677 open-expired rows, 4,428 carry `ladder_work_class` with `ladder_applied_at` null: `requirement-check` 4,178 (bug_fix 1,948, tooling 1,499, enhancement 391, determinism_removal 234, invention 105, agent_creation 1) and 250 of other kinds (tooling 169, bug_fix 81). `requirement-check` has never been a promote signal: 0 finalised rows of that kind carry a class. `ladder_apply_signal()` promotes on every 5th signal with no reset (SES-107) and `class_autonomy.extra_files = greatest(0, rung − 13)` has no ceiling; the unstamped catch-up would hand bug_fix ~2,029 signals. Stamping the 4,178 preserves the status quo; it is AGT-423's §4(f) with this cycle's id, before-images on every row, one `record_decision` (kind `ticket-status`, backlog `AGT-590`) naming them as the undo. `runner_decisions` is not in `reversible_tables()`, so the before-images ARE the undo, and the reasoning says so.
4. **The 250 genuine signals pay out per M6-07** ("the ladder promotes on a decision nobody reversed — at the sweep"). Arithmetic from the live ladder: `bug_fix` rung 1 streak 5 + 81 → streak 86, promotions at 10,15,…,85 = 16 → **rung 17** (extra_files 4, `auto_done` true since rung ≥ 3); `tooling` rung 47 streak 0 + 169 → streak 169, 33 promotions → **rung 80** (extra_files 67, already 34 today). That is the rule doing what it says over 30 days of windows the outage held open; a Designer may not weaken a John rule (pattern:166), so it is reported in the STOP LINE rather than suppressed. `promoted` counts applied signals, not rung moves, hence 250.
5. **Expected catch-up numbers** (14:15Z; the open-expired count grows ~180/day): `finalized` = 8,677 − 1 = 8,676; `closed` 40 — 41 distinct `delivered` tickets sit behind the 67 ship rows, 1 (AGT-281) has a `block` latest verdict, 0 lack a verdict, and AGT-454's second ship row finds no delivered row left; `refused` 1 = `199f27ef`. A pass is discriminating only if all three hold together: a 0-refused run means AGT-281 was written done (forbidden), and a 0-finalised run means nothing changed.
6. **Timeout.** `statement_timeout` is 2 min cluster-wide; the MCP tool ceiling is 60 s. Per-row subtransactions do not commit per row, so a timeout commits nothing — the kickoff says do not retry, because the :17 cron (120 s, no tool ceiling) performs the same idempotent catch-up. No `p_limit` parameter (pattern:67): the hourly caller is the bound that already exists.
7. **Down capture** names the two functions only (both exist → `auto-downable`, prior definitions captured). Naming the altered tables would classify the whole capture `refused` with `down_sql` NULL (what happened to AGT-423) for no gain: the only down of an additive nullable/defaulted column is `alter table … drop column`, a destructive statement the same gate would hold, so it is written as a header comment in the mirror.
8. **runner-cycle.md (7b) not edited.** 380,920 B against the agt-138 ratchet at 380,980, sha pinned in `docs/runbooks/cycle-card.md`, `BYTES_AT_SHIP` pinned in `ses-413d`: a one-line edit is a four-file job (AGT-288). Nothing in (7b) becomes false.
9. **AGT-423** is superseded by this ship, not built twice; its retirement is a status disposition for the manager's review, reported in the STOP LINE. **AGT-281**'s exit stays John's: it needs a ship/ticket-status decision or his Accept dated at or after verdict 38959e02.

## 3. Alternatives rejected

- DROP + CREATE with five OUT columns (AGT-423 as written): unbuildable unattended (the gate), and breaks the ses-320 key pin.
- Loosening `backlog_done_requires_verdict()` or writing a decision over AGT-281's block: forbidden by the ticket; would fabricate a ratification.
- Finalising the decision but skipping only the ticket close: the decision would read `final` while the ticket stayed `delivered` forever; per-row rollback keeps the row retryable and closes AGT-281 automatically the hour after its ratification arrives.
- A new `runner_sweep_refusals` table: a second home for a per-decision fact, plus the new-table-born-readable-by-anon trap (SES-384); the decision row already exists.
- `record_skip()` for the refusal: writes its before-image with `cycle_id` only, and the pg-cron path has no cycle (AGT-423 §3 measured the same).
