The arithmetic closes: 81 rows x 238 ms = 19.3 s, plus the queue's 2.7 s, is the 21 s measured. `runner_pct_per_cycle()` is a STABLE `sql` function whose body is an aggregate (a median over `usage_window_cycles`), so the planner cannot inline it and calls it once for each row it prices. The gate grew from 15 s (2026-11-11, ticket) to 21 s today because the board grew; it will keep growing with every pickable ticket.

**The designed body, measured before this kickoff was written.** The live definition with the three replacements below applied, run as a plain query beside the live body in one block: 3,103 ms and 3,089 ms against 21,431 ms, with `should_boot` equal, `reason` equal (`lanes_full` at that moment) and `detail` equal on all 43 keys once `checked_at` is removed. New md5 `269eba5a36ca5cde76fbc7462f3344e5` (16,193 characters; live `4e2611ce347baf21db33753996efa463`, 16,035). Each of the three from-strings matched the live body exactly once.

**The migration wrapper, dry.** The §S1 block was run with its `execute n;` line swapped for a notice. Both md5 guards passed, all three pairs matched once, the grant and overload asserts passed, and the block then refused with `the new body took 21050 ms, not under 6000` -- because the old body was still in place. So the time bar is proven to fail when the change does nothing. What was NOT run is the replacement itself; that is T2.

## The whole symptom (AGT-618)

Symptom: a REST read of `runner_should_boot()` cancelled at the 8 s statement timeout. Occurrences seen this cycle: 1 (orchestrator's driver run) + 2 (my timed reads) + 8 transport incidents across 6 regression tests (`agt-127`, `agt-150` x2, `agt-265`, `agt-642`, `ses-297`, `ses-353`) = 11. The ticket adds 3 timed reads and 4 driver runs on 2026-11-11. One cause explains all of them: the per-row price call. The 11 of today are reproduced; the 7 of 2026-11-11 are attributed by the same mechanism and were not re-run. Unexplained remainder: 0.

Board search for the cause (`runner_pct_per_cycle`, `57014`, "statement timeout" in open tickets): only AGT-637 itself covers it. AGT-620 is the same class on another rpc and the anon key. AGT-698 covers how a transport NOT RUN is graded. AGT-681 covers `agt-642-blocked-first.test.mjs` being invisible to run-all.

## Why this variant

- **(a) make the call affordable -- chosen.** Three replacements in one function, same answer, 21 s to 3 s. It removes the defect instead of bounding it (pattern:1), at the narrowest layer (pattern:8), with no new knob (pattern:67).
- **(b) read a stored detail.** No stored copy of the gate's answer exists to read; building one is a new table, a writer and a staleness rule for a number that is cheap once the per-row call is gone.
- **(c) raise the role's statement timeout.** Leaves a 21 s gate that grows with the board, needs an `ALTER ROLE` that `capture_migration_down()` refuses by design, and widens every service-key REST call, not this one.
- **Rewriting `runner_pct_per_cycle()` itself** would also help the other three callers (R1) but changes a function four callers share; not needed to deliver this ticket.

A CTE marked `MATERIALIZED` read through an uncorrelated scalar subquery is evaluated once whatever the planner decides about the join; a plain cross-joined subquery can be flattened back into a per-row call, which is why the design does not use one.

## What this does not do

After the build the driver reads its instrument, but at `max_lanes` 1 the gate still counts the asking cycle as a live lane, so the driver will most likely stop on `lanes_full` about itself. That is AGT-570 (partial): its gate half is unapplied. The Manager takes the pick only when both have landed. The ticket's own text ("the REST path returns 200 with should_boot") is met by this build; "step 5(d) stops recording an unread manager" is met for the unread instrument and not for the lane wall.

## Risk

One function body, no signature, grant, owner, volatility or COMMENT change. Reach: every reader of the gate -- the pre-boot fire, `run-project.js` (two reads), `model-assignment.js`, `model-trial.js`, and nine SQL functions that name it. They receive the same answer. Undo: the down captured in T2(a). The block rolls itself back on any raise, including its own time bar. Known hazard outside the design: AGT-673 -- a guarded function replacement was refused at Builder launch on 2026-11-16 and applied in another lane the same week; the STOP LINE covers a refusal.

-- DeepBench v7.0.1050 | docs/design/agt-637-price-read-once.sql | AGT-637 -- the boot gate reads the price of a cycle once.
-- Migration `agt637_price_read_once`.
--
-- THE DEFECT, measured 2026-11-17: runner_should_boot()'s `pickable` CTE multiplies every queue row
-- by public.runner_pct_per_cycle(), a STABLE sql function holding an aggregate (a median over
-- usage_window_cycles), which the planner cannot inline and therefore runs once PER ROW. One call
-- costs 238 ms and the board held 81 pickable rows, so the gate took 20,890 ms. PostgREST runs as
-- authenticator (statement_timeout 8s; service_role inherits it), so every REST read of the gate
-- answered HTTP 500 57014 after 8.4 s and scripts/run-project.js exited 2 before pass one.
--
-- THE CHANGE. Three exact replacements of the live body, each asserted to match exactly once, under
-- an md5 guard on the body this was written against. The price is read once into a MATERIALIZED CTE
-- (`ppc`) and the two places that called the function read that row instead. No signature, grant,
-- owner, volatility or COMMENT change; no other function is touched. Measured on the live board
-- before shipping: the same answer (should_boot, reason, and every detail key but checked_at) in
-- 3,103 ms instead of 21,431 ms.
--
-- UNDO: public.capture_migration_down() on public.runner_should_boot(), called BEFORE this is
--   applied, holds the prior body (md5 4e2611ce347baf21db33753996efa463). By hand: run this block
--   with each pair's two halves swapped and the two md5 literals swapped.

do $agt637$
declare
  d text := pg_get_functiondef('public.runner_should_boot()'::regprocedure);
  n text;
  pairs text[][] := array[
    -- 1. the price of one cycle, read once
    array[E'pickable AS (\n  SELECT q.pos, q.lane, q.ref, q.title,',
          E'-- AGT-637: the price of one cycle, read ONCE per call. Written inline it ran once per pickable row.\nppc AS MATERIALIZED (\n  SELECT public.runner_pct_per_cycle() AS v\n),\npickable AS (\n  SELECT q.pos, q.lane, q.ref, q.title,'],
    -- 2. each row is priced from that one reading
    array[E'round(bi.predicted_cycles::numeric * public.runner_pct_per_cycle(), 2) AS pct_of_week',
          E'round(bi.predicted_cycles::numeric * (SELECT k.v FROM ppc k), 2) AS pct_of_week'],
    -- 3. and the detail reports the same reading
    array[E'    ''pct_per_cycle'',        public.runner_pct_per_cycle(),',
          E'    ''pct_per_cycle'',        (SELECT k.v FROM ppc k),']
  ];
  i int;
  hits int;
  t0 timestamptz;
  ms numeric;
  r record;
begin
  if md5(d) <> '4e2611ce347baf21db33753996efa463' then
    raise exception 'AGT-637: runner_should_boot() is not the body this migration was written against (md5 %); re-read it before applying', md5(d);
  end if;
  n := d;
  for i in 1 .. array_length(pairs, 1) loop
    hits := (length(n) - length(replace(n, pairs[i][1], ''))) / length(pairs[i][1]);

      raise exception 'AGT-637: replacement % matched % times, expected exactly 1', i, hits;
    end if;
