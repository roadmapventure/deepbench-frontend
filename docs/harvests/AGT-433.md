## 3. The migration's self-proof (GATE) — why rolled-back sub-blocks

A `DO` block's `begin ... exception` is a subtransaction: a RAISE inside it undoes the sub-block's writes and the handler runs. So the GATE can call the real writer on a real ticket (AGT-383) with 0, read the score back, and raise a sentinel (`P0433`) that both proves the read and rolls back the decision row, the before-image and the UPDATE — no fixture insert, no residue, and the migration continues. The 6 / -1 / 2.5 probes end in `check_violation` from the function's own guards (the cast guard turns '2.5'::smallint's `invalid_text_representation` into `check_violation`; -1 and 6 hit the range guard), before `record_decision` — nothing to roll back, but the sub-block wraps them anyway so a surprise write could never survive.

Omitting edit (b) makes ZERO end in the `1-5` error instead of `AGT433 0`; omitting (a) makes the writer's UPDATE hit the old CHECK (23514). Either way the GATE raises and `apply_migration` applies nothing — the check grades the change (pattern:162).

The ALTER of the constraint is an in-place ALTER that `capture_migration_down()` refuses by design (runner-cycle.md step 6): the rollback class is card-only and the card says so; the function IS captured (1 object). A hand-authored down is not written (the runbook forbids "authored from memory"), but for the record the inverse is `drop constraint ck_backlog_need_score; add constraint ck_backlog_need_score check (need_score is null or need_score between 1 and 5)`, legal only after the two re-score decisions are reversed.

The writer's ACL was not measured (no anon key in this environment; the AGT-280 mirror carries no GRANT/REVOKE for it). `CREATE OR REPLACE` keeps the existing ACL, so this ticket changes nothing there; if the Builder reads `has_function_privilege('anon', ...)` true while in the migration, that is a pre-existing SES-315-class finding to FILE, not to fix here.

- Widening the CHECK to `>= 0` by `ALTER ... VALIDATE` tricks: unnecessary — all live values are 1-5, the ADD CONSTRAINT validates instantly on this table.
