## 2. Design choices

- **Where the guard goes.** Into `scripts/rank-backlog.js`, in the shape `scripts/ticket-owner.js`:1034-1042 already carries, because the runbook's own step 4e says of that shape *"The script checks this itself, so running the command IS the check"* — one home per fact, and it is the script (pattern:9, pattern:10, pattern:17).
- **Where the day key comes from.** Imported from `ticket-owner.js`, not re-implemented. There are already two `chicagoDay()` definitions in the tree (`scripts/ticket-owner.js`:476 and `scripts/lib/briefing-automation.mjs`:48); a third would be the defect this ticket is about, in code. A shared `scripts/lib/chicago-day.mjs` that all three import is the fully correct answer and it is **out of scope here** (it would edit two files that this ticket does not name, for a duplication that is not the ticket's) — filed as residue below rather than built (pattern:64, pattern:65). Import safety was verified, not assumed: `import('./scripts/ticket-owner.js')` runs nothing, its `main()` sitting behind the `process.argv[1]` check.
- **Injected reader, not a network arm.** `rankedTodayCycle(startedAt, read = sb)` takes its reader as an argument so the regression arm is deterministic and offline (pattern:3) — SES-382 says shared-database fixtures collide between parallel cycles, and SES-393 says CI clones at depth 1, so a live-DB arm here would be flaky for reasons unrelated to the change.
- **`--dry-run` is not exempt.** The precondition answers before any board read, so a dry run says `already run today` too. A dry-run exemption would leave the measured failure mode (a 150 KB prompt assembled for nothing) reachable.
- **Byte ceiling.** `runner-cycle.md` is 380,003 B against SES-336's 381,000 (asserted by `agt-133-run-tail-review.test.mjs`:50, `agt-137`:42, `agt-86h`:58, `ses-385b`:51). All three step edits delete more than they add, so no byte-removal hunt is needed first.
- **Alternative rejected:** correcting *"three today"* to *"five today"*. It is one line and it would be stale again within the month — the same line has now drifted twice. Deleting the count is the fix the ticket asks for.
