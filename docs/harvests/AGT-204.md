# AGT-204 — harvest (design, v7.0.637, cycle `a4217066-8418-4c1b-9339-40e36797ba10`)

Reasoning, measurements and rejected alternatives behind `docs/kickoffs/v7.0.637-AGT-204-cost-columns-nullable.md`. The build reads the kickoff, not this.

## 1. Premise revalidation — alive, and every leg re-measured

The ticket came out of this chain's own finding (`e5922187-882d-4d02-b37c-3ca3303cc2c1`, raised by cycle `cfc9071f` when it shipped `AGT-176` part c as `v7.0.626`). I re-measured all three legs rather than inheriting them.

- **The NOT NULL is still there.** `information_schema.columns` for `public.runner_cycles`: `est_subscription_cost_usd`, `api_cost_dev_usd`, `api_cost_qa_usd` are all `numeric`, `is_nullable = NO`, `column_default = 0`. So the ticket's claim that `api_cost_qa_usd` has the same shape is correct.
- **And it really bites.** A probe that writes and then aborts:
  ```sql
  do $$ declare s text:='dev:SUCCEEDED'; q text:='qa:SUCCEEDED'; tgt uuid;
  begin select id into tgt from public.runner_cycles order by started_at desc limit 1;
    begin update public.runner_cycles set api_cost_dev_usd=null where id=tgt;
    exception when others then s:='dev:REFUSED '||sqlstate; end;
    begin update public.runner_cycles set api_cost_qa_usd=null where id=tgt;
    exception when others then q:='qa:REFUSED '||sqlstate; end;
    raise exception 'PROBE(rolled back) target=% | % | %', tgt, s, q; end $$;
  ```
  returned `PROBE(rolled back) target=956c44a0-0350-43c8-9ce4-75ca833d2fe9 | dev:REFUSED 23502 | qa:REFUSED 23502`. The outer `raise` rolls the whole block back, so nothing was written to get the answer.
- **v7.0.626's resolver is on dev.** `lib/activity-log.js:151` `export const SUBSCRIPTION_LANES`, `:162` `export function resolveCycleCost`; `scripts/settle-ship.js:83` imports both, `:385` calls it, `:387` prints the row counts. The skip is at `:241`: `if (cost.usd !== null) cyclePatch.api_cost_dev_usd = cost.usd;` — the code names its own limit in the header at `:29-35` and again at `:213-218`.

## 2. Why nothing is backfilled

`select count(*) … from public.runner_cycles`: **729** rows. `api_cost_dev_usd = 0` on **729**, `> 0` on **0**. `api_cost_qa_usd = 0` on 726, `> 0` on 3 — `56357816…` `v7.0.466` **1.2537**, `04a3ac3b…` `v7.0.473` **2.2656**, `611599f8…` `v7.0.481` **3.5144** (written by `verifier.js`'s `addQaCost`, the only writer that has ever produced a non-zero here).

Every one of those zeros may be an honest measured zero — `AGT-176`'s own close-out established that no `call_source='executor'` row has ever existed, so a cycle that spent nothing correctly reads 0. Replacing them with NULL would assert an absence nobody measured and would erase the very 0-versus-NULL distinction the ticket exists to create (`pattern:165` — spend is read, not estimated). So the migration is `DROP NOT NULL` and nothing else: no `UPDATE`, and the default stays `0` so no existing writer changes behaviour.

## 3. The down capture, and why `refused` is the right answer

`public.capture_migration_down(uuid, text, jsonb)` was read in full. Two facts decide the call:

- `p_objects` must be a non-empty JSON array or the body `raise`s `capture_migration_down: p_objects must be a non-empty JSON array of {kind, identity}`. That is `AGT-193`, open and gated on John, so the object list is real: `[{"kind":"table","identity":"public.runner_cycles"}]`.
- For `kind in ('table','index')` where `to_regclass(identity)` is **not** null, the body appends to `v_refused` with the reason *"the table already exists, so the up ALTERs it -- a lossless down for an in-place alteration is not derivable from the object's current state alone"*, and any refusal sets `classification = 'refused'` with `down_sql = null`. So the expected return is `refused / 0 / 1 / null`.

Naming the NOT NULL as a `constraint` object instead does not help: an existing constraint refuses on the same principle, and the identity form (`<name> on <schema.table>`) would need a name PG generates. `runner-cycle.md:2856-2862` and `:1798-1800` both state the consequence plainly — a red range containing a `refused` migration is **card-only**, not auto-rollbackable — and that a hand-authored down is the *"authored from memory"* the design forbids. The kickoff therefore tells the Builder to expect the refusal, record it, and mark the card, rather than treating it as a failure.

`AGT-184` (`v7.0.627`, this chain) adds the other half: the up must go through `apply_migration`, never `execute_sql`, or it leaves no `supabase_migrations.schema_migrations` watermark and `scripts/rollback-on-red.js:259` `rangeIsCodeOnly()` then calls the range code-only.

## 5. Alternatives considered and rejected

- **Also harden `addQaCost`.** Rejected: `verifier.js` grades this very ship, the hazard cannot fire until something writes a `qa` NULL, and touching the grader in the same cycle risks the verdict. Files as **F2**.
- **Leave `api_cost_qa_usd` alone.** Rejected: the ticket names both, symmetry costs no file, and a half-nullable pair invites the next session to re-measure the same thing (`pattern:163`).
