## 2. What this pass found that the cap case did not

**The browser reads the first block too.** Six reads in `src/` take `content?.[0]?.text` off an `/api/brief` reply: `DashboardScreen.jsx:172, 215, 253`, `PersonnelScreen.jsx:287`, `TestTeamScreen.jsx:67`, `analyzer/AIReviewTab.jsx:68`. `api/brief.js:128` returns `callClaude()`'s reply unchanged. Claude Sonnet 4.6 does not think unless asked; Claude Sonnet 5.5 runs adaptive thinking when `thinking` is omitted (claude-api skill, thinking table), so the reply can begin with a `thinking` block and every one of those screens would print "No response". That is a bug the id move creates (pattern:124), and it has one server seam: `callClaude()`. I decided to drop `thinking` / `redacted_thinking` blocks there rather than edit four screens -- narrowest layer that works (pattern:8), no visible change, and safe because `/api/brief` is single-turn: no caller replays the assistant content, and the blocks arrive with empty text by default. Reversible: delete S4's middle line.

**The routine's environment already reaches the API.** `deepbench-runner` (`env_01GuEzm2nCHbCB5SumvQVEQ1`, the environment this cycle and the model-watch run in) has a limited allowlist that does not name `api.anthropic.com`, yet an unauthenticated `GET https://api.anthropic.com/v1/models?limit=1000` from it returned Anthropic's own `401 authentication_error` (`x-api-key header is required`), through both `curl` and Node's `fetch`. So the host is reachable; only the key is missing from my hands. Both doc pages also answer 200 from here.

**The prompt block names the scrape.** The runbook's pinned prompt block (`MODEL-WATCH-ROUTINE-PROMPT-BEGIN`..`END`) says "A cheap read of the two Anthropic pages". Editing the block drifts the live routine's prompt until John's `RemoteTrigger update` (the runbook's own update rule), and `agt-146` arm B grades the block. I left it byte-identical and followed the runbook's AGT-502 precedent: the body outranks the block, and S6 says so in step 1.

## 3. Design choices and what each does not do

- **Probe by running the shipped functions.** T4's P1/P2 call `callReflect()` and `callClaude()` after the edits, so the request sent is the product's own, not a copy of it. P0 is the runbook's new command itself. No probe script is committed: a sixth file was not waived.
- **Each id moves only on its proof.** `P1 chars 0` puts `HAIKU` back; a `P2 FAIL` that survives one tool-variant swap puts `SONNET` back; a non-200 P0 puts the runbook back. Whatever is put back keeps AGT-522 open for it.
- **The web-search variant.** The skill lists `web_search_20260209` for Sonnet 5.5 and says older models keep the basic one; it does not say Sonnet 5.5 rejects `web_search_20250305`. Unmeasured, so P2 measures it and the swap happens only on a failure that names the tool. `api/fetch-article.js` and `tests/regression/HAR-27-web-search-max-uses.js` hold the same literal and are not touched.
- **`/v1/models` is not the deprecations page.** It lists what the key is served: no retirement dates. The release watch keeps reading the deprecations page. I confirmed `id`, `display_name`, `created_at`, `max_input_tokens`, `max_tokens`, `capabilities` in the skill's reference; the ticket's `line` field I did not confirm, and the step uses only `id`.
- **`limit=1000`** is from recall of the Models API reference, not measured (auth is checked before the query string). The command treats `has_more` as could-not-read, and P0 proves the 200 before the runbook ships.
- **REFLECT's `max_tokens: 1024` is unchanged.** Thinking counts toward it on Haiku 5.5 (default effort `medium`). A plan cut short still returns its text; a reply that is all thinking returns `""`, which `assembleContext()` already tolerates. Not tuned here: no measurement says it needs it.
- **Not designed, though tempting:** a "no longer served" trigger (an assigned id absent from the list). It is the only way the platform would learn a floor became a retirement, but the Fix does not ask for it (pattern:90). P0 reports whether `claude-haiku-4-5-20251001` is still served; a rule is a separate ticket.
