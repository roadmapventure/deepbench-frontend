## 3. Why two slices (D1)

The full ticket touches four files — `src/data/agents.js`, `src/screens/RosterScreen.jsx`, `tests/regression/agt-164-brittany.test.mjs`, `tests/regression/agt-69-governance-section.test.mjs` — against the cycle's cap of 3. Variants weighed:

- **Keep `agt-69`'s literal alive by prepending Private at render time or by renaming `all`** — rejected: it games the pin and duplicates the nav list in the desktop and mobile branches (pattern:14, pattern:90 — an unrequested structural oddity is a defect).
- **Put "private" into `BENCH_FILTERS` first** — rejected: `navItems` is `[all, ...groups, ...]`, so Private would land second; John's order is Private, All. `BENCH_FILTERS` stays the plain-groups list and Private is positioned, exactly as "all" already is (RO-10's own comment).
- **One 4-file kickoff** — rejected: the cap is the class's and the Designer may not widen it (pattern:72); STANDARDS §2 names the split (`S[X]a/S[X]b`) as the remedy, and the AGT-280 / AGT-281 precedent is a ticket held `partial` across slices.
- **Chosen:** slice 1 = data (agents.js + agt-164), slice 2 = UI (RosterScreen.jsx + agt-69). Data first because AGT-334 (Connect button on the personnel file) reads private membership and is the next ticket in the same session. The interim state after slice 1 — Brittany visible under All only, Platform Wide count 9 — is on dev only and is honest (pattern:34).

This is not a refile of the ticket's own acceptance criterion (pattern:95): no new ticket is opened; AGT-332 stays `partial` and slice 2 is the next cycle on AGT-332.
