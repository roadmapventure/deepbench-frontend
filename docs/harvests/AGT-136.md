**Gap attribution is a trigger on the one intake, not a script step.** `JOHN-0925-FINDINGS-STANDARD` makes `audit_findings` the single intake for every source, so an AFTER INSERT trigger is the one place every gap passes (pattern:9 — deterministic, no model; pattern:163 — one change, every home). The row's `fingerprint` is the audit finding's own — a second fingerprint author was rejected (`fingerprintFor()` is JavaScript and cannot run in the trigger; pattern:14).
