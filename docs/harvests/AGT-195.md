## 2. The three candidates, decided on evidence

### (a) The call — a symptom, not the defect

Cycle `c1d1fb0c` wrote `record_skip('needs-john')` at 02:06:13 on a ticket whose
`runner_before_images` row (`pk_value 7bcdb219…`, captured 02:22:51) shows `design_status = null`.
That write is genuinely wrong: `docs/runbooks/runner-cycle.md:2162-2163` says so in bold —

> **The `needs-john` third of that trio is a LEGACY-ROW path only, since `M6-01` RETIRED the flag
> (`SES-315`): a row already carrying it is still skipped and still recorded, and no cycle creates a
> new one.**

But the cycle is over and nothing about it is fixable. Naming the call the defect fixes nothing and
leaves the next cycle free to repeat it. **Rejected.**

### (b) The un-narrowed `reason_kind` vocabulary — cannot carry the rule, and its home is not lying

The `<gated|removal-proposed|needs-john|needs-desktop|permission-gate|other>` placeholder at
`runner-cycle.md:2635` is an inline enumeration of the live CHECK, read fresh:

```
ck_skip_reason_kind  CHECK (reason_kind = ANY (ARRAY['gated','removal-proposed','needs-john',
                                                    'needs-desktop','permission-gate','other']))
```

Two reasons this is not the defect:

1. **The narrowing is already written, 473 lines earlier in the same file** (`:2162-2163`, quoted
   above). The runbook is not missing the rule; the function is.
2. **The CHECK must keep allowing `needs-john`.** `AGT-110` carries `design_status = 'needs-john'`
   today (the only such ticket on the board, `updated_at 2026-09-24`), and a legacy row is still
   *recorded* through this same function. A table CHECK is a per-value predicate — it cannot express
   *"unless this ticket's own row carries the flag."* Only the function, which can read
   `backlog_items`, can.

Cost, separately: a one-line `:2635` edit costs **three files** (`SES-377` re-render of
`docs/runbooks/cycle-card.md`, plus `BYTES_AT_SHIP` re-pinned in
`tests/regression/ses-413d-questions-scoreboard.test.mjs`) for zero behavioural change. That coupling
is already escalated to John as a rules call. **Rejected.**

### (c) The missing uniqueness — the ticket grain was never the invariant

```
uniq_open_skip   UNIQUE (backlog_id, reason_kind) WHERE (resolved_at IS NULL)
```

and `record_skip()`'s own idempotence lookup keys exactly that pair:

```sql
SELECT * INTO v_old FROM public.runner_skips
 WHERE backlog_id = p_backlog_id AND reason_kind = p_reason_kind AND resolved_at IS NULL;
```

The function is **faithful to its declared grain**, and three independent homes declare that grain:

- `scripts/build-briefing.mjs:378-379`: *"The join takes the FIRST row per backlog_id ordered by
  queue because backlog_id is NOT unique (CHI-48 holds two rows, SES-97)."*
- `runner-cycle.md:2641-2645`: *"A repeat skip of the same ticket **for the same reason** bumps
  `skip_count` and `last_skipped_at` on the existing row rather than adding a second one."*
- The index itself.

And the live board: **22 tickets hold more than one open skip row right now** — AGT-168, AGT-79,
CHI-16, CHI-70, LAV-30, LAV-31, LOG-134, LOG-58, LOO-21, LOO-24, SES-156 (3), SES-160 (3), SES-177,
SES-180, SES-182, SES-183, SES-191 (3), SES-244, SES-344, SES-378, SES-54, SES-82. Ten of them are
`gated` + `needs-john`: two genuinely different asks (a card to tap, a question to answer). A
`CREATE UNIQUE INDEX … (backlog_id) WHERE resolved_at IS NULL` **cannot even be created** against
that data, and collapsing ~26 rows to satisfy it would delete asks §10 exists to carry. **Rejected
as this ticket's fix** — filed instead, because whether the grain *should* narrow is John's call: it
removes rows from his page.

### Verdict — the missing PRECONDITION, in `record_skip()`

`pg_get_functiondef('public.record_skip(uuid,text,text,text,text,text)')` (one overload, no
ambiguity) validates nothing about `p_reason_kind` beyond the table CHECK and never reads
`backlog_items` at all. The rule exists in prose and is unenforced — pattern:10 (after
instruction-level guards fail, go structural), pattern:93 (the live source, not the doc line),
pattern:8 (the narrowest layer that actually works). Corroborating live source: `pick_blocking_flags()`
returns `{needs-desktop}` — AGT-88/OD-15's single home for the blocking-flag vocabulary, with
`needs-john` already absent.

## 5. Alternatives considered and dropped

- **Silently rewriting `needs-john` to `other`** inside the function: would hide the ask in §10.1
  with no signal, and pattern:34 (render honest absence) plus pattern:51 (a failure lands somewhere
  actionable) both argue against it. A `RAISE` that names the `gated_before_build` card and the
  step-(7b) handle fails closed *and* tells the caller where to go.
- **Supersede-in-place** (one row, `reason_kind` rewritten): destroys the audit trail the
  `resolved_at` / `resolved_cycle` columns exist for, and collides with the documented
  `skip_count` semantics.
- **Widening `reverse_decision()`'s allowlist to `runner_skips`** so Task 2 is Reverse-able: the
  function's own comment excludes the runner's evidence tables deliberately. The undo is a one-line
  UPDATE, stated in the kickoff's §6.
- **A runbook edit alongside the code**: refused on the SES-377 three-file coupling, and unnecessary
  once the refusal message itself carries the correct path.
