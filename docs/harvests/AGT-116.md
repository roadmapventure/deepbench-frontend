## Why a fetch watcher and not message matching

- The ticket's own remedy wording is "`notRun()` on 503/504/57014". The first idea is to match those strings in the thrown message inside `run-all.js`'s catch. I rejected it. `LOG-132`'s assertion message contains the literal text "A 57014 here is the … statement_timeout firing" whatever the status was, and 101 test files build messages as `HTTP ${res.status}`. A regex over prose is the id-decoy problem: the code appears in the prose whether or not the event happened. It would also launder a multi-arm aggregate (`N arm(s) failed:`) whenever any one arm mentioned a 503.
- The structural version watches what the calls actually did (pattern:32). It wraps `globalThis.fetch` and records an incident only for requests to the `SUPABASE_URL` origin, and only for 502/503/504, a 5xx body with `PGRST002` or `57014`, or a network error code. It reaches child processes through `NODE_OPTIONS=--import`, because 66 credentialed tests spawn scripts. It is scoped by origin so deliberate unreachable-URL controls (`ses-344b`'s `http://127.0.0.1:1`) never count. Most children inherit `process.env`, and the few that replace `env` get no watcher. That fails in the safe direction: the test stays FAIL.
- Known limitation, named: `LOG-132`'s anon arm grades that the 57014 cap does **not** fire. If a change makes the view slow enough to trip it, the watcher records an incident, and the test reads NOT RUN (exit 2, still blocking) instead of FAIL. The ship still blocks. Only the label is weaker.

## Why exit 2, and why the verifier is untouched

- The existing `notRun()` semantics are "information, never a failure", and the file still `[PASS]`es. Applied to a whole test that threw during an outage, that would turn a 40-minute outage into a green suite and an approve. That would be a laundering hole this feature creates (pattern:124), so it must close in the same ship. `run-all.js` therefore exits **2** (the platform's "could not run" convention) when nothing FAILed but at least one whole test was transport-not-run.
- `scripts/verifier.js` `gateStatus` maps any non-zero exit to `red`, and `tests/regression/SES-181-verifier.js:143` pins `exitCode: 2 → "red"`. So an outage still blocks, fail-closed, and `regressionDelta`'s "red with no named failure" branch keeps it red. The FAIL list, the thing the ticket measures, stays identical. Mapping exit 2 to `skipped` / COULD NOT RUN would be the more honest label, but it changes a pinned verifier rule and touches a second self-certifying file. It is filed as a follow-up, not done here.
- `run-all.js` is in `SELF_CERTIFYING_PATHS` (`verifier.js:556`), so this ship cannot auto-done whatever it does. That is expected.

## Per-flipper shapes, and the alternatives dropped

- `agt-133` arm D: exit 3 is `NOTHING_TO_REVIEW` (`audit-review.js:76,415`), which is not a defect. Every Monday the new ISO week starts empty, so the arm is red every Monday morning until a finding lands. Only exit 3 becomes notRun. Exits 1 and 2 stay FAIL.
- `SES-177` / `SES-261`: the ticket describes them as comparing "against what the live ledger renders right now". Since SES-261 the check has been **pin-anchored** (`render-claude-state.js:570-607`: it fetches exactly the pinned rows and cards). AGT-199's tail re-render removed the card-missing drift, and the file measures exit 0 today. So exit 1 (drift) remains a real defect in the committed file and stays FAIL, which keeps `STANDARDS.md` §2 rule 5's measured case (cycle `860efe52`) valid with no amendment (pattern:94). Only exit 2 (could not run) becomes notRun.
- `agt-68`: the dropped alternatives were a retry loop (it hides the race rather than naming it) and pinning a fixture board (the arm's whole claim is equality with the live function). A seqlock-style read → act → re-read is the standard technique for a consistent read of moving state.
- `LOG-132`: the dropped alternatives were raising the bar (it must sit strictly between 1,313 ms shipped and 2,872 ms retired, and the file asserts that) and a statistical test (over-built). Min-of-N timing is standard benchmarking practice: the minimum is the least noisy estimate of the true cost, and three reads cost about 4 s.
- Retry-on-503 inside the watcher was rejected. It makes blips green but still reports a sustained outage as FAIL, and it silently changes what every test measures.
- Process isolation per test was rejected for `run-all.js`'s own reason (SES-215 header): it would put `takeNotRun()`'s buffer across a process boundary.

## Decisions recorded (reversible, mine per JOHN-0925-DESIGNER-DECIDES)

1. The transport watcher is scoped to the `SUPABASE_URL` origin. Structural, not message regex.
2. Exit 2 for a transport-only not-run. The verifier is untouched. Relabeling in `gateStatus` is filed.
3. The `SES-177`/`SES-261` drift exit stays FAIL. Only could-not-run becomes notRun.
4. `LOG-132` uses min-of-3.
5. The Windows `0xC0000409` crash is filed as its own finding, not fixed here.
