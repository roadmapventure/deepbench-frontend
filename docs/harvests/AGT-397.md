## Designer calls (reversible; AGT-136 not shipped, so recorded here and in the kickoff)

1. **Resume relocation deferred to slice 2.** Reason: measured above — ResumeTab.jsx has no hiding prop. The alternatives were (a) edit ResumeTab.jsx (4th file, cap 3, no waiver), (b) copy the Vitals/Skill Ladder JSX into FutureViewTab.jsx (a redraw — forbidden by the rule John's words produced), (c) hide the column from outside with a scoped `<style>` or `visibility:hidden` on the grid's first child (a redraw by CSS, and leaves a 240px blank). Slice 2 must edit ResumeTab.jsx anyway to place the Identity editor where those two cards are, so relocating them there is one change in one ship (pattern:163) instead of two edits of the same column. Consequence in slice 1: Proposed Resume = today's Resume. The slice's literal sentence ("Resume's left column shows nothing where Vitals and the Skill Ladder were") is NOT met in slice 1; it is met in slice 2.
2. **Default arrangement is `current`.** Zero visual change for anyone until the switch is flipped; the switch itself is John's spec (pattern:97, pattern:84). `stored` null or any unknown value resolves to `current`.
3. **Quick Stats stays one component with a `show` prop.** The card holds Documents (stays, AGT-402) and the four parked stats; splitting the card into two components would be a redraw. The same JSX renders with the triple list filtered.
4. **Switch mirrored above the mobile tab bar** (pattern:59). The ticket names the left nav, which is desktop-only (:2066); the mobile chip bar reads the same `NAV_GROUPS`, so without the mirror a phone could never reach Proposed.
5. **`?tab=future` deep link under `current` falls back to `profile`** — the same guard shape AGT-339 uses for `activity` (:2022).
6. The Intelligence Configuration strip is "Discuss" on the register; the slice (John-named scope) places it in Readiness and levels. Followed the slice.
7. Reports Run lives inside the Quick Stats card, so it travels with that component into Readiness and levels rather than Work.

## Mechanism choices

- **Dev flag** = a HAR-41 `feature_flags` data row (`agt-397-layout-switch`, enabled true — John 2026-09-12: on by default in dev) AND the existing `IS_ADMIN_HOST` export from `src/AppShell.jsx` (localhost, 127.0.0.1, `-git-dev-*.vercel.app`). The row is shared by every environment, so "production never shows it" is the host gate, by construction; the row gives John an off switch without a deploy. No new code constant.
- **Remembered per browser** = `localStorage` key `agt397-layout`, read once at mount, written on change, every access in try/catch (private windows throw).
- **FutureViewTab.jsx takes rendered items as data** (`groups[].items: ReactNode[]`) and never imports from PersonnelScreen.jsx: no circular import, and the seven card components stay defined in PersonnelScreen.jsx, which is what keeps agt-344's hex-literal pin (exactly 10) and log-143b's `.from("bench_report_cards")` / `FeatureBadge id="LOG-143"` pins green without editing those tests (3-file cap).
- `autonomous-surface-changes.md` asks for zero deleted lines in `src/screens/*`. Extraction moves lines within PersonnelScreen.jsx (deletions + additions). The rule's purpose — no bare appearance change — holds: `current` renders the same JSX through the extracted components, and the switch/tab are flag- and host-gated. No script enforces the line count (grep of scripts/ for `numstat` / `autonomous-surface`: none); the Verifier reads this note.
