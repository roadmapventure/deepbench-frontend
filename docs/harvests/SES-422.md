## 2. Why this slice, and not another

The ticket's use case is *a good ship reddened for reasons unrelated to the change*. Of the six, exactly three produce that symptom directly: the two tests that pin live counts/identities and the fixture that collides. They are also the cheapest: three test files, no migration, no schema, no runbook. Caps are 3 files / 4 tasks (+0/+0), so a fourth file — the SES-407 migration or an `agents`-side change — would not fit, and mixing a migration with test rewrites would make the verifier's red set unreadable.

Alternatives considered and set aside:

- **Advisory lock around fixture-owning tests (SES-382 option 2).** Serialises peers across CI and every cycle; a held lock under a crashed run becomes a new source of noise. Per-run ids remove the shared address instead of guarding it.
- **A control that skips loudly when the fixture row is held (option 3).** The ticket itself warns it becomes a control that can never fail. Rejected.
- **Sweeping stale `ses330-fixture-*` rows at test start.** A cross-run DELETE can kill a peer's in-flight fixture mid-assertion — trading one collision for another. Not done; a stranded row from the OLD fixed id no longer blocks anyone once the id is per-run.
- **Pinning agt-70's live arm to a fixture corpus.** The fixture arm already exists (`:1150`, `--corpus=<resolved> --no-db`, exact counts). The live arm's job is "both detectors ran on the real corpus and agree with the file", which is what the new assertion says. Ticket SES-404 offered either route; this is the cheaper one and it keeps a live arm.
- **Keeping identity assertions in agt-79 behind an `OR the row already carries the fix` pair.** That is what `:998-1025` already does and it is still a board snapshot — the moment a NEW row qualifies (SES-404 did, per SES-405), it reds. Properties over the census's own `detail`/`fix` plus one live row read are the smallest replacement that still bites.

## 3. Discriminators, and why each is not vacuous

- **agt-70.** The new `BAND` regex requires both bands with integer counts; a one-band string is asserted to fail in-test. The count-equality against `d.json` ties the summary line to the detector output (`audit-corpus.js:620` says they read one pair of arrays) — a summary that prints `duplicates 0` without detecting would fail, which is the false-all-clear the header at `:79-81` warns about.
- **agt-79.** (a) `rate` positive finite — the `:1040` arithmetic still checks every `cost-snapshot-missing` fix against it. (c) `claim-on-closed` must be on a closed row with the exact two-null fix. (d) `cycles-over-quote` must carry a `detail` whose actual exceeds its predicted — the census's own numbers must justify the finding. (e) `oneToOne` refuses a derivable whose live row type is not a `TYPE_MAP` key — the exact SES-405 discriminator ("a genuinely NON-derivable spelling classed derivable must still fail"), proven pure with `"Architecture"` (13 live rows carry that type today).
- **ses-330.** Two concurrent runs both green is the direct inverse of the filed symptom; the `already exists` controls remain and can still fail (an id collision would mean `randomUUID` broke or a peer copied the id).
