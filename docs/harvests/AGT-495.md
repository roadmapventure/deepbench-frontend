## 2. The design, and why this shape

**The rule lives in the function, in-call, and writes nothing to the passed drain.** Five splices:

1. DECLARE gains `v_passed uuid[]`, a counter and the oldest blocked drain's five return values.
2. The scan's WHERE gains `AND id <> ALL (v_passed)`.
3. The blocked branch no longer returns: it appends the drain to `v_passed`, remembers the oldest one's row, and `CONTINUE`s.
4. The "nothing queued is left" branch answers the oldest blocked drain's own `blocked` row first (with `; N later queued drain(s) also blocked` when more than one was passed), then the old `retired` / `none`.
5. The `pick` row's `blocked_detail`, which was always NULL, carries the mark when the pick was handed past a blocked drain: `passed N blocked drain(s) - oldest <epic> (<id8>): <its census>`.

The loop still terminates by construction: every pass removes one row from the scan's set, the same way a retirement does, and the 32-iteration backstop is untouched.

**Calls I made (JOHN-0925-DESIGNER-DECIDES; each reversible by the captured down):**

- **D1 — the mark is the answer, not a stored column.** The ticket says "mark the blocked drain … keeping the blocked drain's slot the way the pick already passes a blocked ticket". The pick passes a blocked ticket by predicate: the ticket's blockage is a fact on its own row (`blocked_by`, `delivered`, a flag, a claim, a gate card) and is re-read live, so the ticket returns the instant its blocker lands. A drain's blockage is nothing but its members' rows — the census already names them. A second, stored "blocked" stamp on `runner_directives` would be a copy of a live fact (pattern:93) that something must clear (pattern:16), and a stale stamp is exactly a drain that never gets its slot back. So the drain row is not written at all — which *is* the slot: status `queued`, `created_at` untouched, read first on the next call — and the mark travels on the row the call returns, which step 5 records in the cycle. If the Development Manager wants the mark stored, it is one additive column and one UPDATE in the same branch; it was not needed to prove the claim, and I could not read the table's triggers to design a write safely.
- **D2 — when no later drain picks, the answer is byte-identical to today's** for the single-drain case: the oldest blocked drain's `blocked` row and census. Fall-through behaviour for the cycle is unchanged, and so is the five-outcome vocabulary.
- **D3 — `unscoped` still stops the scan.** A drain with no named list is a different word on purpose (`SES-142`) and the ticket does not ask for it to be passed. Unrequested edge cases are defects (pattern:90).
- **D4 — a standing probe function, not a one-shot gate.** AGT-483 shipped its proof as a migration's trailing gate and needed a second cycle (v7.0.858) because nothing in the suite could go red if the change were reverted. `public.blocked_drain_probe(uuid)` is that lesson applied in the first ship: the migration grades it before and after the splice, and the regression guard grades it on every run. It measures and never asserts; every write is inside a sub-block that ends in sentinel `P0495`.
- **D5 — the runbook is not edited.** `docs/runbooks/runner-cycle.md` has its sha256 pinned in `docs/runbooks/cycle-card.md` and sits 7 bytes under `agt-138`'s 380,980 ratchet, so one sentence there is two more files — past the 3-file cap. The five outcomes and what a cycle does on each are unchanged, so no instruction a cycle follows becomes wrong; one descriptive sentence (line 2229, "acts on the first `pick` / `blocked` / `unscoped` / `none`") goes stale and is in §R. `docs/ARCHITECTURE.md` carries the rule in this ship (§S3).

**The probe, both directions (what the ticket's QA asks for):**

- A (2020-01-01) names U — open, `blocked_by` X (open, named nowhere): A can neither retire, nor reach all-delivered, nor pick. "A drain holding one unretirable member."
- B (2020-01-02) names W — open and workable.
- Call 1 → direction 1: must be `pick` / B / `ZFIX-49503`, carrying the mark; A still `queued`, still dated 2020-01-01.
- Call 2 (W now blocked too) → with no real drain queued: `blocked` / A, the oldest.
- H (2019-12-31, one REAL already-finished ticket that sits in no scope, only read) → Call 3 → direction 2: H retires (`done`, `acted_cycle`, one before-image); A and B, short of their finish lines, are still `queued`; B was still `queued` after it was picked from.

The fixtures reach H's finish line without ever writing a ticket `done`, so `backlog_done_requires_verdict()` is neither touched nor exercised. The three drains are `exclusive = false`: `drain_epic_next()` never reads that column and a fixture should not hold AGT-456's clause over anything.

**Dry run, mine, on a local PostgreSQL 16.15** holding a minimal schema and the recorded body (its `pg_get_functiondef` hashed to `057d8de7…` there too, so the mirror text is what the catalog returns):

- the migration applies in one transaction; `drain_epic_next(uuid)` md5 `057d8de7bd3780b67c12986ce2c5cbb6` (29,382 bytes) → `86a0ca8c6d2285d5f5f21e5dd2f80482` (31,503 bytes);
- probe before the splice: `out1 blocked, dir1 A, out2 blocked, dir2 A, h_status3 done, residue 0`;
- probe after: `out1 pick, dir1 B, pick1 ZFIX-49503, mark1 "passed 1 blocked drain(s) - oldest Tooling (…): 1 named member(s) still open and none is claimable now; 1 blocked on another ticket (ZFIX-49501 (blocked by ZFIX-49502))", out2 blocked, dir2 A, detail2 "…; 1 later queued drain(s) also blocked", h_status3 done, h_before_images 1, a/b queued, residue 0`;
- the real-life shape too (a real queued drain holding one `delivered` and one `removed` member, a second real drain with work behind it): before `blocked` for the first, after `pick` from the second with the mark, the first still `queued`;
- a second apply is refused (`function "blocked_drain_probe" already exists`), and EXECUTE on both functions reads anon false / service_role true.

PostgreSQL 16 is not the project's 17, and my schema is not the live one: the live apply is still the proof, which is why the migration carries its own before/after gate.

## 3. What this does not do

- It does not build a second exit (discharged by the 2026-10-17 `delivered` path), does not loosen `backlog_done_requires_verdict()`, and does not touch the sweep (AGT-590) or the finaliser.
- It does not change `pick_exclusions()`: AGT-456's rule that an exclusive drain holds the pick from tickets *outside every drain* is John's and stands. The ticket's fix is "a rule for later drains".
- It does not change `prime_directive_queue()` — see §R.

## 4. Alternatives I set down

- **A stored mark** (`blocked_since` / `blocked_detail` columns on `runner_directives`): D1. Rejected for this ship; cheap to add later.
- **Re-typing the whole function** into the migration: 31 KB of text that must match the live body to the byte, when the catalog can supply it. The splice form is the platform's own (AGT-455, AGT-483).
- **Passing `unscoped` too**: D3.
- **Editing the runbook sentence**: D5 — two more files.
- **Also teaching `prime_directive_queue()`'s `drain` CTE the same rule**: it is the STABLE mirror the boot gate reads, and after this ship the two can disagree in one configuration (§R). I left it out because (i) the ticket's fix and both directions of its QA are about `drain_epic_next()`; (ii) I could not read that function's live body, and its `buildable` set is `pick_exclusions()`, whose exclusive clause would still hide a non-exclusive later drain's members, so "the same rule" there is a design question of its own; (iii) the gate already answers in 18 s over REST (AGT-637) and I could not EXPLAIN a new correlated read. It is filed with its evidence rather than guessed at.

## R. The one finding T4 files

> **Since AGT-495 the drain picker and its read-only mirrors can disagree about which drain is live.** `public.drain_epic_next(uuid)` now passes a blocked oldest drain and can pick from a later queued one. Four readers still take only the single oldest queued drain-epic directive: `public.prime_directive_queue()`'s `drain` CTE (`ORDER BY d.created_at LIMIT 1` — the STABLE read `runner_should_boot()` and `drain_chain_gate()` count pickable work from, by design never calling the picker), `scripts/build-briefing.mjs:682`, `scripts/lib/briefing-automation.mjs:105` and `scripts/render-standing-brief.js:2082`. Consequence when an older drain is blocked and a later one has work: a later-drain member that is scored below 3, or that sits outside a blocked *exclusive* drain's scope (`pick_exclusions()`, AGT-456), is in no lane of `prime_directive_queue()`, so the boot gate can count nothing pickable while the picker would pick — the cycle that would reach the later drain may not boot. The pages name the blocked drain as the standing one, which is true but silent about the pass. And `docs/runbooks/runner-cycle.md` line 2229 still says the scan "acts on the first `pick` / `blocked` / `unscoped` / `none`" (its sha256 is pinned in `docs/runbooks/cycle-card.md`). Latent while no drain is queued (0 on 2026-11-09). Evidence: `docs/design/agt-455-drain-score-exemption.sql` (the CTE), `docs/design/agt-495-blocked-drain-passes.sql`, this harvest §4.

### S1 — `docs/design/agt-495-blocked-drain-passes.sql`

````sql
-- DeepBench v7.0.1036 | docs/design/agt-495-blocked-drain-passes.sql | AGT-495 -- a blocked drain passes the pick to the next queued drain and keeps its slot; public.blocked_drain_probe(uuid) proves both directions on rolled-back fixtures, at the apply and on every suite run.
--
-- THE MIRROR of migration `agt495_blocked_drain_passes`. Everything below the VERBATIM marker is
-- the migration as designed (kickoff docs/kickoffs/v7.0.1036-AGT-495-blocked-drain-passes.md).
-- The Designer had no database read: public.drain_epic_next(uuid) is therefore NOT retyped here.
-- It is read from the catalog and spliced on five anchors, each of which must be there exactly
-- once, so a body that has moved since the repo's last record (docs/design/agt-482-claim-stop-fence.sql
-- plus AGT-483's one ORDER BY line) is refused, never guessed at.
--
-- THE RULE (John's pattern 147: go past a blocked item, it keeps its slot). Until this migration
-- the function read the single oldest queued drain-epic directive and RETURNed on `blocked`, so
-- one drain whose members can neither finish nor all be delivered held the pick from every later
-- queued drain. Now a drain read as blocked is passed inside the same call: its row is not
-- written (status stays `queued`, created_at untouched, so it is read first again next call and
-- picks the moment a member frees up), and the mark is the answer itself -- a `pick` handed over
-- from a later drain carries `blocked_detail = 'passed N blocked drain(s) - oldest <epic> (<id8>): <its census>'`.
-- When no later drain picks, the answer is the oldest blocked drain's own `blocked` row, as before.
--
-- NOT TOUCHED: the retirement predicate, the 2026-10-17 delivered exit, the pick predicate, the
-- census sentences, `unscoped` (still stops the scan), public.backlog_done_requires_verdict(),
-- public.pick_exclusions() (AGT-456's exclusive hold over tickets outside every drain stands),
-- public.prime_directive_queue() (its `drain` CTE still reads the oldest queued drain only --
-- filed as a finding by this ship, see the kickoff's STOP LINE). The sweep half is AGT-590.
--
-- DOWN: public.capture_migration_down(<cycle>, 'agt495_blocked_drain_passes', the two identities)
-- before the apply; the down restores drain_epic_next's prior body and drops the probe.
-- Guard: tests/regression/agt-495-blocked-drain-passes.test.mjs. Governing: docs/ARCHITECTURE.md section 19v.
--
-- ---- THE MIGRATION, VERBATIM ---
-- F: the probe. It MEASURES and never asserts (the AGT-483 parent_score_probe form): three
-- fixture drains dated before every real one, three fixture tickets, three calls of
-- drain_epic_next(), all inside one sub-block that ends in sentinel P0495, so every write --
-- including the retirement of fixture drain H and its before-image -- is rolled back.
--   A (2020-01-01) names U: open, blocked_by X (open, named nowhere) -> A can neither retire nor pick.
--   B (2020-01-02) names W: open and workable.
--   H (2019-12-31, added before call 3) names one REAL ticket that is already done/removed and
--     sits in no drain scope -> H is at its finish line. The real ticket is only read.
-- All three drains are exclusive = false: drain_epic_next() never reads that column, and a
-- fixture must not hold AGT-456's exclusive clause over anything.
CREATE FUNCTION public.blocked_drain_probe(p_cycle_id uuid DEFAULT NULL)
RETURNS jsonb
LANGUAGE plpgsql
VOLATILE
AS $fn$
declare
  v_cycle uuid;
  v_epic  uuid;
  v_fin   uuid;
  v_fin_id text;
  v_u uuid; v_x uuid; v_w uuid;
  v_a uuid := gen_random_uuid();
  v_b uuid := gen_random_uuid();
  v_h uuid := gen_random_uuid();
  v_real int;
  v_out1 text; v_dir1 uuid; v_pick1 text; v_mark1 text; v_a_st1 text; v_b_st1 text; v_a_slot boolean;
  v_out2 text; v_dir2 uuid; v_det2 text;
  v_out3 text; v_h_st3 text; v_h_cyc boolean; v_h_img int; v_a_st3 text; v_b_st3 text;
  v_items int; v_dirs int; v_scope int; v_imgs int;
begin
  -- runner_before_images.cycle_id is an FK to runner_cycles(id), so drain_epic_next() needs a
  -- cycle that really exists; a caller with none of its own (the regression suite) gets the newest.
  v_cycle := coalesce(p_cycle_id, (select id from public.runner_cycles order by started_at desc limit 1));
  if v_cycle is null then
    raise exception 'blocked_drain_probe: no cycle id passed and public.runner_cycles is empty';
  end if;

  select count(*)::int into v_real
    from public.runner_directives where type = 'drain-epic' and status = 'queued';

  -- an epic the pick predicate will accept a member of: its project executes (SES-340) and it
  -- holds no unresolved milestone design gate (M5-09), which would block W for a reason that is
  -- not this probe's subject.
  select e.id into v_epic
    from public.epics e
   where public.epic_project_executing(e.id)
     and not exists (select 1 from public.backlog_items g
                      where g.epic_id = e.id and g.title ilike 'M_ design gate%' and g.status <> 'done')
   -- Tooling first: the epic parent_score_probe() stands its own fixtures in, so the shape is proven there.
   order by (e.id = 'ced3a7d0-5382-47f2-9163-ad21c176de6b') desc, e.id
   limit 1;
  if v_epic is null then
    raise exception 'blocked_drain_probe: no epic of an executing project is free of an unresolved design gate -- the probe has nowhere to stand a workable member';
  end if;

  select b.id, b.backlog_id into v_fin, v_fin_id
    from public.backlog_items b
   where b.status in ('done', 'removed')
     and not exists (select 1 from public.runner_drain_scope s where s.item_id = b.id)
   order by b.id
   limit 1;
  if v_fin is null then
    raise exception 'blocked_drain_probe: no done/removed ticket outside every drain scope -- fixture drain H has no finished member to name';
  end if;

  begin
    insert into public.backlog_items
      (backlog_id, tier, title, status, source_file, row_ordinal, epic_id,
       scope_origin, need_score, queue, filed_at, size_stamp)
    values
      ('ZFIX-49501','later','Probe fixture U -- open and waiting on X, so drain A can neither retire nor pick','open','agt495-probe',1,v_epic,'john-named',4,999981,'2026-08-01','S'),
      ('ZFIX-49502','later','Probe fixture X -- the open blocker, named in no drain','open','agt495-probe',2,v_epic,'john-named',4,999982,'2026-08-01','S'),
      ('ZFIX-49503','later','Probe fixture W -- open and workable, the one member of drain B','open','agt495-probe',3,v_epic,'john-named',4,999983,'2026-08-01','S');
    select id into v_u from public.backlog_items where backlog_id = 'ZFIX-49501';
    select id into v_x from public.backlog_items where backlog_id = 'ZFIX-49502';
    select id into v_w from public.backlog_items where backlog_id = 'ZFIX-49503';
    update public.backlog_items set blocked_by = v_x where id = v_u;

    insert into public.runner_directives (id, type, status, epic_id, exclusive, body, created_at)
    values (v_a, 'drain-epic', 'queued', v_epic, false,
            'AGT-495 PROBE FIXTURE drain A (blocked, dated 2020-01-01). Rolled back by sentinel P0495.', '2020-01-01'),
           (v_b, 'drain-epic', 'queued', v_epic, false,
            'AGT-495 PROBE FIXTURE drain B (workable, dated 2020-01-02). Rolled back by sentinel P0495.', '2020-01-02');
    insert into public.runner_drain_scope (directive_id, item_id, backlog_id)
    values (v_a, v_u, 'ZFIX-49501'),
           (v_b, v_w, 'ZFIX-49503');

    -- CALL 1, direction 1: A is blocked, B behind it has work.
    select q.outcome, q.directive_id, q.backlog_id, q.blocked_detail
      into v_out1, v_dir1, v_pick1, v_mark1
      from public.drain_epic_next(v_cycle) q;
    select d.status, (d.created_at = '2020-01-01'::timestamptz) into v_a_st1, v_a_slot
      from public.runner_directives d where d.id = v_a;
    select d.status into v_b_st1 from public.runner_directives d where d.id = v_b;

    -- CALL 2: B is blocked too, so no fixture drain picks -- the oldest blocked drain answers.
    update public.backlog_items set blocked_by = v_x where id = v_w;
    select q.outcome, q.directive_id, q.blocked_detail
      into v_out2, v_dir2, v_det2
      from public.drain_epic_next(v_cycle) q;

    -- CALL 3, direction 2: H, the oldest of all, is at its finish line; A and B are not.
    insert into public.runner_directives (id, type, status, epic_id, exclusive, body, created_at)
    values (v_h, 'drain-epic', 'queued', v_epic, false,
            'AGT-495 PROBE FIXTURE drain H (at its finish line, dated 2019-12-31). Rolled back by sentinel P0495.', '2019-12-31');
    insert into public.runner_drain_scope (directive_id, item_id, backlog_id)
    values (v_h, v_fin, v_fin_id);
    select q.outcome into v_out3 from public.drain_epic_next(v_cycle) q;
    select d.status, (d.acted_cycle = v_cycle) into v_h_st3, v_h_cyc
      from public.runner_directives d where d.id = v_h;
    select count(*)::int into v_h_img
      from public.runner_before_images i
     where i.cycle_id = v_cycle and i.table_name = 'runner_directives' and i.pk_value = v_h::text;
    select d.status into v_a_st3 from public.runner_directives d where d.id = v_a;
    select d.status into v_b_st3 from public.runner_directives d where d.id = v_b;

    raise exception sqlstate 'P0495' using message = 'AGT-495 probe: fixtures measured, rolling them back';
  exception when sqlstate 'P0495' then
    null;   -- every write above is undone; the measurements survive in the variables
  end;

  -- the residue, read AFTER the sentinel.
  select count(*)::int into v_items from public.backlog_items    where source_file = 'agt495-probe';
  select count(*)::int into v_dirs  from public.runner_directives where body like 'AGT-495 PROBE FIXTURE%';
  select count(*)::int into v_scope from public.runner_drain_scope where directive_id in (v_a, v_b, v_h);
  select count(*)::int into v_imgs  from public.runner_before_images
   where table_name = 'runner_directives' and pk_value in (v_a::text, v_b::text, v_h::text);

  return jsonb_build_object(
    'out1', v_out1,
    'dir1', case when v_dir1 = v_a then 'A' when v_dir1 = v_b then 'B' when v_dir1 = v_h then 'H' when v_dir1 is null then null else 'other' end,
    'pick1', v_pick1,
    'mark1', v_mark1,
    'a_status1', v_a_st1,
    'b_status1', v_b_st1,
    'a_slot_kept', v_a_slot,
    'out2', v_out2,
    'dir2', case when v_dir2 = v_a then 'A' when v_dir2 = v_b then 'B' when v_dir2 = v_h then 'H' when v_dir2 is null then null else 'other' end,
    'detail2', v_det2,
    'out3', v_out3,
    'h_status3', v_h_st3,
    'h_acted_by_cycle', v_h_cyc,
    'h_before_images', v_h_img,
    'a_status3', v_a_st3,
    'b_status3', v_b_st3,
    'real_queued', v_real,
    'finished_member', v_fin_id,
    'residue', jsonb_build_object('items', v_items, 'directives', v_dirs, 'scope', v_scope, 'images', v_imgs),
    'fn_md5', md5(pg_get_functiondef('public.drain_epic_next(uuid)'::regprocedure)),
    'cycle_id', v_cycle);
end
$fn$;
````
