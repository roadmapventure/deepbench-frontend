## Why two slices

The whole ticket touches PersonnelScreen.jsx and TeachScreen.jsx. A third file is the test. The only test that drives code inside PersonnelScreen.jsx compiles it with esbuild (`log-143b-report-card-surfaces.test.mjs`), and that test is red on this laptop today: it prints PASS, then node dies at exit with `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c, line 94` (baseline script: exit 3221226505; alone, twice: same crash). A new test built the same way would be born red. The pattern that is green here is AGT-339's: the logic lives in a plain `src/lib/` file the test imports directly. That makes the file list lib + screen + test = 3, the cap, with no room for TeachScreen.jsx. The cap is John's to waive, not mine (pattern:72), and the split loses nothing: slice 1 is usable alone (the Teach page keeps working as it does today), and slice 1 already reads `?add=`, so slice 2 is a one-file redirect.

7. The mock's buttons carry no AI badge; the badge stays on the upload form's own save button.

## Calls I made

1. Landing form is the upload form (`add=file`), as slice 1 chose: every Teach link promised an upload.
2. `trainable` false. The old page never checked the flag. The Training tab's two add buttons are not gated on it either (only Edit / Delete are, `PersonnelScreen.jsx:1502`). So `/bench/<non-trainable>/teach` typed by hand opens the same upload form that a click on "+ Upload a file" on that agent's Training tab opens today - no new reach, no reach removed. Gating the add buttons is a functionality change to the Training tab, outside change (f); it is already on record in the design doc, section 6.
3. `encodeURIComponent(agentId)` in the target: `useParams` hands back the decoded id, and putting a decoded value back into a URL unencoded is the one way this redirect could change which agent it lands on. Roster ids are plain slugs, so it is a no-op today.
4. `replace`, so Back from the Training tab goes to where the trainer came from, never back into the redirect.
5. Behaviour that goes with the old page: after a save the trainer now stays on the Training tab list (the item just saved is visible) instead of being sent to the Profile tab; the mock "Projected Impact" (+3 skill, labelled mock on the page itself), "What Changes" and "Onboarding Checklist" panels are gone. None is on the layout John approved.
6. The test extends slice 1's file rather than adding a new one: same ticket, same pure no-esbuild shape, and it leaves room in the 3-file cap for the stale comment in agt-164.

## Alternatives rejected

- A pure `addFormPath(agentId, kind)` in `src/lib/taughtItems.js` imported by both the screen and the test: a real function call in the test, but a third source file and an abstraction with one caller. Arm (f) gets the same proof by pulling the template out of the screen source and resolving it for a sample id, with a control that fails when the id is dropped.
- Deleting `TeachScreen.jsx` and pointing the route at an inline `<Navigate>` in `main.jsx`: a file deletion (needs approval) and a router edit, for the same behaviour.
- Editing `TestTeamScreen.jsx:347` to link straight to the Training tab: one fewer hop for that one link, but old bookmarks and anything else that reaches `/teach` would still need the redirect, so it is extra, not instead.
- Rendering the redirect only for trainable agents: widens scope (call 2).
