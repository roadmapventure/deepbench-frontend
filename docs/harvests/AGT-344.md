## Why two slices

The whole ticket touches PersonnelScreen.jsx and TeachScreen.jsx. A third file is the test. The only test that drives code inside PersonnelScreen.jsx compiles it with esbuild (`log-143b-report-card-surfaces.test.mjs`), and that test is red on this laptop today: it prints PASS, then node dies at exit with `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c, line 94` (baseline script: exit 3221226505; alone, twice: same crash). A new test built the same way would be born red. The pattern that is green here is AGT-339's: the logic lives in a plain `src/lib/` file the test imports directly. That makes the file list lib + screen + test = 3, the cap, with no room for TeachScreen.jsx. The cap is John's to waive, not mine (pattern:72), and the split loses nothing: slice 1 is usable alone (the Teach page keeps working as it does today), and slice 1 already reads `?add=`, so slice 2 is a one-file redirect.

## Slice 2 (exactly)

`src/screens/TeachScreen.jsx` becomes a redirect: `/bench/:agentId/teach` -> `/bench/:agentId?tab=training&add=file` (`<Navigate replace>`), so the route in main.jsx and the link in TestTeamScreen.jsx stay as they are and no file is deleted. Plus its test. I chose the upload form as the landing form because every existing Teach link promises an upload; `add=note` is the other value if the note form is preferred.

## Calls I made, and what I did not do

1. Brent's 26 agent-written rows keep today's card and are not in the three counts. Decision 5 limits "always given" to what a user taught, and `lib/read-taught.js` treats every non-user row as a record.
2. Counts: Taught items is every user-taught item, on or off; Always given and Looked up count active ones only, because `readTaught` reads `status = active` and a switched-off item is not given (pattern:33, 39). The chip on a switched-off card still states its size class; the mock has no disabled variant and the Disabled button carries the state.
3. The mock draws the character count on FILE cards and not on the NOTE card; the design doc's sentence (c) says each card carries its count. I followed the mock, the artifact John approved (pattern:90). One line to change if it is wanted on notes too.
4. A taught card renders exactly what the mock card shows. Run id, trigger chips, priority, the italic note block and "What X Learned" are not on it; the full text and the teaching note are one click away in Edit.
5. Editing a file: today's edit form plus a text box under its "Previously indexed document" box, reusing the note form's label and count line. Nothing else in that form changes.
6. The note form line past the limit reads "looked up by search" - the mock only draws the under-limit state; the words are the card chip's.
7. The mock's buttons carry no AI badge; the badge stays on the upload form's own save button.
8. Text sizes: elements that stay keep today's sizes (the mock is drawn larger throughout); new form elements take the mock's 12/13.
9. Kept as today because the mock is silent: the "How Background Knowledge Works · Layer 02" box, the "Exhibit I · Training Courses" header with Export JSON and its count line, the empty state, the upload form and its right-hand column, the single "✕ Cancel" while a form is open.
10. Not done, for the Development Manager's findings list: the "How Background Knowledge Works" copy now contradicts decision 2 (it says training is retrieved by search; user-taught items are always given). Changing it is a copy change nobody approved.
11. Not done: `TeachScreen.jsx` does not check the `trainable` flag (already recorded in the design doc, section 6).

## Alternatives rejected

- Whole ticket in one kickoff with a source-text-only test: fits the cap, but the QA would only prove strings exist, not that the counts and chips are right.
- Rendering a shared form inside TeachScreen: needs exports out of a 1,930-line screen and keeps two homes; a redirect makes "single home" literally true.
- Mapping the saved row locally after a save: three hand-built shapes of one entry. One `toEntry` and a re-fetch is one shape (pattern:14) and removes the fake id.
