## 2. The decisions (mine, reversible — JOHN-0925-DESIGNER-DECIDES; AGT-136's recorder not yet shipped)

**D1 — project priority is the FIRST key.** Order of keys after this ship: `projects.priority` → filing lane (M5-02) → `queue` → `predicted_cycles NULLS LAST` (M5-07). Why first and not after the filing lane: the projects table is John's execution authority (`SES-340`) and he set 1/2/3 himself on 2026-09-25; the filing lane is a Selfbuild-era review-bucket rule inside the board. Lane-first would let any pre-cut ticket in a priority-3 project jump priority-1 work — the same inversion the ticket names, in another key. Live effect of the choice today: none (zero pre-cut tickets in executing projects), so it is recorded rather than observed. pattern:69, pattern:146.

**D2 — an admitted enhancement from a non-executing project sorts after every executing project.** `buildable.project_priority = CASE WHEN pj.status = 'executing' THEN pj.priority END`, `NULLS LAST`. Alternative rejected: sorting by the paused project's own priority (e.g. `moat-support` priority 1) would put a paused project's enhancement ahead of the executing priority-1 project. Live effect today: none (no admitted enhancement in the lane). In `drain_epic_next` the epics join already carries the executing fence, so `pj.priority` there is always an executing project's.

**D3 — "exactly one executing project" is retargeted in this ticket, not filed.** Homes measured: `docs/runbooks/runner-cycle.md:72-73` ("exactly one row is `executing` at a time, and that row IS the execution authority"), `:2081-2082` (step 5(b): "the one `public.projects` row with `status = 'executing'` (`moat-support` today)"), and `tests/regression/ses-340-projects-govern.test.mjs` clause (a) `assert.strictEqual(executing.length, 1, …)` plus clause (b) `deepStrictEqual([...servedProjects], [executing[0].id])`. The ses-340 test is already RED on the unchanged tree for exactly this reason (baseline block in the kickoff). Three projects execute by John's word (2026-09-25, projects.notes on the two new rows); the ordering this ticket adds is what makes several executing projects coherent, so the sentence is part of this change's homes (pattern:94, pattern:163). Not touched: `moat-support`'s own notes, `CLAUDE-STATE.md` (no such claim), `RULES-SNAPSHOT.md` (no such claim — grepped).
