# SES-287 — harvest (v7.0.507, cycle 03c7e9a6)

Reasoning, measurements and alternatives for the one-cycle revert guard. **Not required reading**;
every fact the build depends on is in `docs/kickoffs/v7.0.507-SES-287-one-cycle-revert-guard.md`.

## 1. Premise revalidation — three claims, one of them dead

The ticket names three defects. I checked each against the tree at `f85505d3` and against live
Supabase rather than against the ticket text.

### Defect 1 — "the anchor is the newest `runner_green_states` row, not the newest concluded green". DEAD.

The *code* claim is literally true — `readGreenAnchor()` (`scripts/rollback-on-red.js:575-579`)
reads `runner_green_states?order=observed_at.desc&limit=1`. But that table is no longer a cycle's
memory: `SES-352` (v7.0.452) made it a projection of CI's own record, and the projection is live.

```
trg_anchor_green_from_ci  AFTER INSERT OR UPDATE OF jobs, ref
  ON public.ci_run_conclusions FOR EACH ROW EXECUTE FUNCTION anchor_green_from_ci()   tgenabled = O
trg_prune_runner_green_states  AFTER INSERT ON public.runner_green_states (retention 50)
```

Measured live this turn:

| question | answer |
|---|---|
| `ci_run_conclusions` rows | 314 |
| distinct concluded greens | 107 |
| `runner_green_states` rows | 50 (= `GREEN_STATE_RETENTION`) |
| anchors NOT backed by a concluded green | **0 of 50** |
| newest-50 concluded greens missing from the cache | **0** |
| rows where `observed_at = concluded_at` | **50 of 50** |
| observed_at-vs-concluded_at ordering inversions | **0** |
| newest anchor vs newest concluded green | identical (`cba4d325…`, 2026-09-15 17:32:07Z) |

The raw "107 vs 50" gap is retention pruning, not staleness — that is the misreading this section
exists to prevent. Restricting to the newest 50 concluded greens, the cache holds **all** of them.
`tests/regression/SES-352-green-anchor-from-ci.js` documents the pre-ship state that matched the
ticket exactly: newest anchor 2026-09-02 15:08Z against a newest green of 2026-09-10 03:24Z, 63
greens with no anchor. That is the defect the ticket describes, and it was fixed.

**Consequence for the build: do not touch line 576.** Rewriting the read to query
`ci_run_conclusions` directly would duplicate `anchor_green_from_ci()`'s predicate (including its
load-bearing `ref = 'dev'` branch guard) in a second home — the exact two-homes-for-one-rule failure
`SES-352`'s clause (C) was written to prevent.

### Defect 2 — the range is never checked against the cycle it is attributed to. ALIVE.

`decide()` reaches `REVERT_AND_CARD` at lines 368-378 and 381-390, both building
`revertPlanFor(greenAnchor.commit_sha, headSha)`. Nothing between the anchor check (337) and either
return measures the span. `attributionOf()` (207-216) resolves only the **head** sha to one cycle,
so the plan is attributed wholly to the last pusher by construction.

Live precedent, `docs/SESSIONS.md:1296`: the engine returned `revert-and-card` over
`de6e08e8..95cf5fee` — six commits from four cycles (`ab2948c6` v7.0.343 SES-183, `6be8379a`
v7.0.344 DAT-21, `b0d37c31` SES-258, and the head's own) — and filed card `b7aef844`. The cycle
declined on three measured grounds; ground (2) is register B37 (`docs/runbooks/runner-cycle.md:432`):
a successor never adjudicates a predecessor's shipped delivery.

### Defect 3 — the card states the plan in the past tense. ALIVE.

`buildIncidentCard()` line 420: `const reverted = decision.action === ACTIONS.REVERT_AND_CARD;`
— `action` is what was *decided*, never what was *done*. Lines 445-451 then render
"`was reverted to the last green state`" and "`dev is back at green … by revert-forward`". The
engine's own header (line 20-22) is explicit that this branch's action "is executed by the CYCLE
behind its push gates", and the file never runs git. The same live incident had to have its card
rewritten by hand because it asserted in past tense an execution that never happened.

**Verdict: premise ALIVE on 2 of 3 claims.** Designing against claim 1 would have been work against
a fixed defect, so the kickoff names it dead in CONTEXT to stop a builder "restoring" it.

## 2. Why the shas are passed in rather than derived

`decide()` is pure and has no git; `readPushingCycles()` returns `{id, push_sha, version}` with no
ancestry. Three options considered:

1. **Time window** — treat cycles whose push falls between `anchor.observed_at` and now as in-range.
   Rejected: cycles run in parallel (register B42), so the window is approximate, and an approximate
   basis for "may I revert three predecessors' work" is precisely the wrong place for an estimate.
2. **Shell out to `git rev-list` inside the engine.** Rejected: it would make `decide()` impure and
   untestable, and the header's authority boundary ("never runs git") is load-bearing.
3. **Pass the list in, like `--migrations`.** Chosen. It is the established precedent in this very
   file (header lines 55-58), the runbook already computes the sibling
   `public.migrations_in_range(green, current)`, and the absent-list semantics are already written
   and already guarded: *"unknown is not innocent."*

## 3. Fail-closed direction, stated explicitly

The engine is LIVE — invoked four times in the last two hours by cycles on this board, returning
card-only on the standing red each time. Every branch this slice adds moves toward **card**, never
toward revert:

- no `--range-shas` → card (unknown is not innocent)
- range spans >1 cycle → card (B37)
- any commit in range claimed by no cycle → card (an attended push is not this machine's to undo)
- single cycle, and it is the attributed one → unchanged behaviour

A missing CI row remains *stale, not bad*; unknown is never red; and no partial schema rollback is
introduced — `schemaPlanFor()` is untouched.

## 4. Scope — why slice 1 stops where it does

`predicted_cycles` is 2. The caps (16 files / 17 tasks) are not the binding constraint; the runbook
is. Making the cycle actually *pass* `--range-shas` requires editing step 4a of
`docs/runbooks/runner-cycle.md`, which is **380,902 bytes against the SES-336 ceiling of 381,000** —
a step edit must first remove bytes, which is its own piece of work with its own review surface.
Slicing there keeps this ship to one file of logic plus its guards, and leaves the engine strictly
safer in the interim.

Also deferred to slice 2: the affirmative half of defect 3 — once a cycle executes a revert, that
execution should be recorded so a card can truthfully report it. This slice only stops the false
claim; it does not build the true one.

## 5. Fixture collision found while designing

Both `tests/regression/SES-182-rollback-on-red.js:67` and
`tests/regression/ses-373-card-only-self-decides.test.mjs:107` define a local `revertableFacts()`
that must reach `REVERT_AND_CARD` (SES-182 line 91, ses-373 lines 138-139, the latter explicitly as
a negative control: *"the control fixture must reach REVERT_AND_CARD, or the (A) negative control
proves nothing"*). The new guard cards any range with no `rangeShas`, so both fixtures go card-only
and both suites fail unless each gains `rangeShas: [HEAD]`. Both already define
`HEAD = "abc1234def5678"` and `CYCLES = [{ id: "cyc-1", push_sha: HEAD, … }]`, so a one-commit range
maps to exactly one cycle which is also the attributed one — a one-line edit in each file. This is
why the kickoff's file count is 4 and not 2.
