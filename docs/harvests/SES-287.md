## Why the scope is 4 files, not 17

Caps were 17 files / 18 tasks. The cheapest thing that proves the claim is the settle path plus
the range wiring, because the two are one mechanism: a gate nobody feeds cannot be observed, and a
plan nobody reports back on cannot be settled. Everything else the ticket touches is measured
closed above, and re-touching it would be re-litigating three shipped slices.

## Alternatives considered and rejected

- **File the revert card decided at build time.** Rejected: at the moment the engine files it, the
  plan genuinely has not run. That is the same lie in the opposite direction, and it is what card
  `000cb93c` did.
- **`accept` for an executed revert, `retired` for a declined one.** Rejected: `accept` is the one
  value `trg_runner_items_accept_clears_flag` keys on and it reads as John's approval, which no
  unattended cycle has. `retired` (`SES-300`: withdrawn as an ask, a record and never an open
  question) is honest for both, and the prose carries which outcome it was. 90 live rows already
  use it.
- **Have the engine decide whether to revert and then record it.** Rejected outright: the engine
  never runs git and never pushes — the push gates live in the cycle, and a script with its own
  push authority is the `SES-019` shape.
- **Skip the runbook edit and ship the settle path alone.** Rejected: the revert branch would stay
  unreachable, so the new code would never run and the QA could only ever be fixture-deep.
