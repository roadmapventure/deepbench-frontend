### (b) A refusal priced at 0 under a billing rule that changed — alive

`api/prompt/request-receivable.js:695-699` carries the assertion in capitals: *"NOT BILLED, AND THE ROW MUST SAY SO WITH A 0."* Two call sites write it:

- `:700-709` — the first-turn refusal gate (`LOG-149`), `billed: false`.
- `:806-816` — the parse-retry refusal gate, also `billed: false`. **The ticket names only the first.** `pattern:163` (one change, every home) makes the second a kickoff fact rather than a discovery for the Builder.

`api/capabilities/execute.js:1295-1297` converts it: `costUsd: mc.billed === false ? 0 : undefined`. And `lib/activity-log.js:211` shows why flipping the flag is sufficient and safe — an explicit `costUsd` wins outright, `undefined` prices from the four token columns, and an unpriced model or a token-less row lands **NULL, never 0**. So `billed: true` on a refusal that carried no usage produces NULL, not a phantom dollar: the fix cannot itself invent a measurement.

The advisor finding's source is the Anthropic release note dated 2026-09-24, *Billing Changes for Refusals*: `bio`, `frontier_llm`, `reasoning_extraction` are charged at the serving model's rates. `cyber` and `uncategorized` stay unbilled, so they keep the asserted 0 — that 0 is a real measured zero and must survive.

### The fourth zero, and why the fix must not paper over it

The parent runner's claim was checked directly with `mcp__Claude_Code_Remote__get_session` (`session_id` omitted) this session. The response carries **no `external_metadata.usage` object**: only `container_cc_version 2.1.283`, `context_usage {max_tokens 1000000, used_tokens 0}`, `last_served_model`, `rate_limit_info`. So `SES-409`'s three-reading measurement is **untakeable on this platform build**, and `est_tokens_dev`/`est_tokens_qa` NULL is the honest value — the runbook already says so at `:4076-4081` (*"tool unavailable → both NULL, never a number"*) and cycles obey it, recording `tokens_basis: get_session unavailable` in `notes`.

That is the working precedent the design copies. There are four states to keep apart, and the tokens half already keeps three of them:

| state | value | how a reader knows |
|---|---|---|
| measured, and it really was zero | `0` | basis says `measured` |
| nothing billable happened (subscription lane) | `NULL` | basis says `no-billable-rows` |
| the platform cannot measure it | `NULL` | basis says the tool was unavailable |
| rows exist, the split does not | `NULL` | basis says `unsplit` |

A value alone can carry at most two of these. A value plus a basis carries all four, and it costs one line of `notes` — no column, no migration, no new surface. That is the whole design (`pattern:17`, `pattern:34`).

## 2. Alternatives considered and rejected

- **A `combined_tokens` column on `ai_activity_log`** (the ticket's own second branch for (a)). Rejected: a migration, a grant (`.claude/rules/supabase-column-grants.md` — the anon key reads this table, and a new column is fail-closed), a backfill question, and a reader that nobody has asked for — against a defect whose last occurrence is a single row and whose correct path already exists. Filed-not-built, named in the STOP LINE (`pattern:65`, `pattern:120`).
- **Coercing `--output-tokens=0` to NULL inside `scripts/agent-log.js`.** Structurally stronger than a runbook sentence and genuinely tempting. Rejected on cap arithmetic, not on merit: it is a fourth file once its own value test is counted, and the cap is 3. It is also the wrong layer for the *instruction* defect — the runbook is what tells a cycle to compose the pair. Worth filing if (a) recurs after this guard.
- **A new `scripts/settle-ledger.js` to compute the dollars.** Rejected: `pattern:8` — fix at the narrowest layer that works. The value is one SQL expression; a script to run one expression is a new file, a new test, and a new thing to keep in step with the runbook that would still have to name it.
- **Backfilling the historical 0s to NULL.** Rejected and explicitly forbidden in the STOP LINE. `pattern:157`: a remediation scoped to named rows is John's to ask for; and `reverse_decision()`'s allowed-table list excludes `ai_activity_log` (`SES-399`), so a mistaken sweep there is not reversible. The fix changes what gets written from now on.
- **Widening (b) to every `billed: false` site.** Rejected: `:551` is an Anthropic *rejection* (HTTP 4xx, request refused at the door) and is genuinely unbilled. Its 0 is a measured zero and stays.
