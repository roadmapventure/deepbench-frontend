## The design, and what it does not do

Each of the three alarms writes one `john_alerts` row keyed by `fingerprint`:

| site | fingerprint | replaces |
|---|---|---|
| 4a-ter deploy-quota crossing | `deploy-quota:<CST day>` | the `DEPLOY QUOTA ALERT` notes-marker scan |
| 4a-quater IP spend-gate block | `ip-block:<masked_ip>:<blocked_at>` | nothing — `ip_block_alert_claim()` already stamps rows |
| 4a-quinquies cadence hole | `cadence:<suppressionKey>` | the suppressionKey notes-marker scan |

Why the fingerprint and not the notes markers: `john_alerts.fingerprint` is UNIQUE
(`john_alerts_fingerprint_key`, measured from `pg_constraint`), so `on conflict (fingerprint) do
nothing` is atomic under parallel cycles (pattern:19) and needs no hand scan (pattern:10 — go
structural). The markers existed only to dedupe pushes; the row's own key does that. Cost: a hole
or day that was pushed before this ship may write one row once; that is one inherited row, ever,
and it is honest (4a-quater's own "nothing was backfilled" precedent).

Why `john_call` NULL and `ref_table='runner_cycles'`: `john_call` is CHECKed to
`rules|money|production|hiring|switch` or NULL and these are alarms, not calls; the cycle row's
`notes` already carry the figures, so the cycle id is the honest reference. `source='runner'` is
the value the runner's existing alert rows already use.

What this slice does NOT do: it does not design the notification path (`NOTIFICATIONS-OFF` says
"until a notification path is designed"); it does not touch header stamps (`stamps[0]` is pinned by
ses-424c, and the v7.0.610 stamp's "REPORTED NOT FIXED" clause is history the ratchet already
excludes); it does not touch `scripts/decide-gated-card.js:384` (`pushed to John: <n>` prints an
RPC return field, outside "runbook/cards"); it leaves `john_alerts` rows `4e9ce6a4`/`55e4e3d6`
unclaimed because the table has no state for "answered by the Designer" — reported for (7e).
