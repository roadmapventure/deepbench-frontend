## Why a fourth count (D1-D4)

The finding is about the strip: three zeros above 26 cards. The ticket offers a fourth count or card labels. An own record's card already renders differently from a taught card (category chip, run id, priority, "What Brent Learned"), so the cards are distinguishable today; the strip is the part that reads as broken. The count is the smaller change and the one that answers the finding.

It counts every non-taught entry at any status, mirroring how `taught` counts, so "Taught items" plus the new number equals the number of cards listed (pattern:39, pattern:41). It renders only above zero and last (pattern:57, pattern:115): a created agent that has only been taught sees today's three counts, unmoved.

The label uses the agent's first name and the word "records", which is the word `lib/read-taught.js` already uses when it frames these rows for the agent (pattern:53). Alternatives I weighed: "Written by Brent" (plain, but a second name for the same object), "Own records" (shorter, but whose?), "Self-recorded" (jargon).

`taughtCounts()` keeps its three keys because `tests/regression/agt-344-training-tab.test.mjs` lines 55-56 `deepEqual` the object; a fourth key would turn that test red and add a fourth file.
