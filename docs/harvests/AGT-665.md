## 2. What the live data changed in the design

1. The competitor name is model-worded free text. 9 of the 18 distinct names end in a bracketed remark, for example: GovSpend (MCP server on purchasing data, not the commodity code); Periscope / mdf commerce (current Code platform provider); Public Consulting Group (with OpenGov, Sourcewell MSA). The ticket says company=name and also says no reasoning may cross into the shared store. On live data those two sentences conflict. Call 1 resolves it toward the privacy sentence: company is the name cut at its first space-bracket. The same cut makes the within-answer collapse work (GovSpend appears under 4 spellings).
2. Nathan's competitor list cannot be matched by equality or by domain today. 81 live rows (kind competitor, status not retired); 0 carry data.domain; titles are shaped Name - description (12 of 81 have no dash at all, and those are mostly do-it-yourself and matrix rows). Equality on the title matches 0 of the 12 companies. Call 2 reads matched by name as: the list name equals the company, or starts with the company followed by a space. That matches GovSpend, Hazel and OpenGov, which are genuinely on the list. The domain arm is kept as the ticket states it and is tested, but it has no live row to act on yet.
3. checked_on is only required to be non-empty by marketCheckErrors, while seen_on is a NOT NULL date. All 21 live values are YYYY-MM-DD, but a free-text value would make the lead insert fail after the records had landed. The builder falls back to the run date when checked_on is not date-shaped.
4. validateLeads (AGT-155) is reused unchanged and run inside validateStrategyAnswer, so a competitor url that is not https or carries a tracking form refuses the whole answer before anything is written (Call 3). 0 of the 28 live urls would be refused.
5. A lead read or insert that fails after the strategy insert must not exit 2: the runbook tells the caller to send a refused write back and write again, which would store the records twice. So the failure prints one stderr line, leads is 0 and the exit code stays 0 (Call 4). Because the dedupe makes filing repeatable, the next write that names the company files it.

## 4. A discovery, not fixed here -- for review

The ticket's inbox rule matches by company or URL host, any status. On today's data the host arm made 2 correct merges and 0 wrong ones. Structurally it can lose a lead: market-check urls are often third-party pages (5 of the 13 live hosts: a council agenda, two news sites, a pricing blog, a trade paper), and every career lead's public_url is a linkedin.com job url, so linkedin.com is permanently in the inbox. A competitor cited from a host that is already in the inbox for a different company is skipped silently and stays skipped. I kept the rule as the approved ticket words it (pattern:90) and named the finding in the STOP LINE so it is filed with this evidence rather than patched inside the build. The smallest fix, if the review wants one: match the inbox by company or by full url instead of host.

## 5. Alternatives weighed

- Filing leads inside the same request as the records (one transaction): not available through PostgREST inserts to two tables; the ticket's own rule is records first.
- A live write arm in the test: rejected. strategy_records rows are never deleted by this platform's rules and a fixture offer would be read into the consultant's next render. The offline arms cover the builder, the dedupe, the refusal and the call order with a fake client; the first live proof is the next real strategy write that stores an offer or roadmap (the Monday weekly review re-checks every offer and roadmap).
- A unique index on market_leads: a migration and a second risk level; not needed for a single weekly writer.
- Changing readCompetitors to return a cleaner name: it also feeds the career alert render (EXTRA_READS), so it stays byte-same.
