## 2. Alternatives weighed, and why the design is what it is

- **A new `runner_verdicts.regression_fails` column (a migration).** The ticket's own text authorises it ("carries its failing list on `runner_verdicts` or through `verifier.js --json`"). Rejected: the file states its own convention twice (`:1599-1603`, `:2306-2310`) — a new fact reaches the ledger through the free-text column or the payload, never a new column — a migration would consume a file slot against a 3-file cap, and it buys nothing the payload does not (the Verifier's `qa_evidence` is written from `--json`, which is exactly what the ticket asks the subset claim to quote). pattern:17.
- **The verifier measuring its own baseline** (stash, throwaway worktree, or `git checkout` of the parent sha). Rejected outright: this script's founding property is verdict-only — "CANNOT EDIT… touches no file in the tree" (charter, Multi-agent verification item 1). It would also cost a second ~20-minute suite inside the gate.
- **The baseline as the previous verdict row's stored list** (self-maintaining; the previous graded sha on a linear `dev` is this ship's parent). Attractive — pattern:16 — but it needs the column above, and under parallel cycles (`SES-382`, register B42) the newest prior row is not reliably this ship's parent. Deferred rather than dismissed: once the payload carries the list, that variant becomes a one-column follow-up with no code change to the delta itself.
- **Landing inert, with the arming as a separate attended runbook line** — the `SES-376` / `SES-359` precedent in this same file. Rejected: the runbook has 3,375 bytes of headroom (measured, above), so the arming fits in this ship, and a fix whose subject is a standing false block should not ship unable to clear one. pattern:1.
- **Grading the delta on counts rather than names.** Rejected: `279/296 → 280/297` is exactly the reading that hid the defect. Counts move when a test file is added; names are what "a red I did not cause" means. pattern:39/40.

## 3. Why AGT-116 does not gate this ship

The ticket says AGT-116 "should land first or with this one". It is still `open` and unclaimed, so this design had to earn the right to go first, and it does so by direction rather than by assurance:

1. The delta can move the gate **only** red → green, and only when every `[FAIL]` name in the graded run also appears in the handed baseline.
2. A flake that is green in the baseline and red in the graded run is therefore *newly red by name* and the gate stays **red** — the same block the platform takes today. Nondeterminism cannot manufacture an approve.
3. No baseline, an unreadable one, or an empty one → the absolute exit code stands. Fail closed, named in the reason rather than defaulted silently.
4. The residue is stated in the kickoff rather than hidden: the reverse flake (red in the baseline, green in the graded run, red next cycle) is charged to the *next* ship — a false block on the wrong ticket. That is AGT-116's to remove, and the two lists this ship records are the evidence AGT-116 needs to characterise the flakes.

So the trade the ticket warns about — "a permanent false block for an intermittent one" — is not taken: the permanent false block goes, and the intermittent one that remains is the one that already exists.
