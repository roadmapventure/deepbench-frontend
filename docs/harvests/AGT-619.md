## 2. The whole symptom (AGT-618): every place the dollar is derived

`pg_proc.prosrc ilike '%model_pricing%'` or `'%input_per_1k%'`, `pg_views`, `pg_matviews`, and `git grep`:

1. `shared/models.js` `computeCallCost()` -- per-model cache-read rate, else 0.10x. The one pricing writer is `lib/activity-log.js`; `api/prompt/ai-enrichment.js` and `scripts/agent-log.js` write rows with no dollar.
2. `public.get_ip_stats(text)` -- flat 1.25 / 0.10, stored dollar ignored. `ip_spend_report` (a view, `postgres` and `service_role` only) reads it through a lateral call, so it follows.
3. `public.mcp_caller_gate(text)` -- the same flat rule, not named by the ticket. Carried into stage B.
4. `public.apply_model_assignment(jsonb,uuid,text)` -- reads and writes the sheet, derives no spend.

Rows on which the answers differ today: 5 rows on 4 addresses carry cache-read tokens for one of the two models and a `caller_ip`. ## 3. The primary-key question, settled: NOT in this build; filed (§R F1)

The Manager asked whether the attended build also moves the primary key so a retired rate and its successor can both stand. It does not, and here is the reasoning.

- **What the move would touch.** `model_pricing_pkey` is `(model)`; `model_catalog_model_id_fkey` references it, and a foreign key cannot point at "the one open row per model". `apply_model_assignment()` -- the security-definer function the model-watch routine writes the sheet through -- reads the sheet by `model` four times, updates rates in place once and inserts once, and images each row under `pk_value = model`. Both gate joins and the mirror's select would change too. That is a different reach from five additive columns and two function bodies, and John's risk rule stages parts of different risk separately.
- **How often the harm has happened.** `runner_before_images` holds 550 images of `model_pricing` since 2026-09-29 (529 with row data). Across them and the live sheet, no model has ever held two different rate pairs: zero in-place rate changes on record.
- **What this build does about it instead.** The lineage it ships must not become silently false at the first rate change. Stage A's trigger moves a row's `effective_from` to the instant a rate is written in place, so a stamped ledger row with `created_at` earlier than its sheet row's `effective_from` is exactly a row priced at a rate the sheet no longer holds. That set is countable with one join and is empty today. Stored dollars never move: after stage B the gates read the stored figure first, so a rate change restates only rows that carry no stored dollar.
- **What stays true and is said plainly.** Until F1 ships, the sheet cannot show the old rate itself; `retired_at` exists and nothing sets it. Nothing here has to be redone for F1: `pricing_row_id` references `model_pricing(id)`, which F1 keeps.

## 4. Calls made in this kickoff (mine, reversible)

- **D1** the primary key stays `(model)` (section 3).
- **D2** no backfill. A stamp records what the write path did; inferring one for the 2,686 rows priced earlier would be a claim nobody recorded (43 of them, short-form Haiku ids from June, do not even recompute at today's sheet).
- **D3** `effective_from` is `not null default now()`, as the ticket words it: existing rows carry the apply instant, the moment the sheet began keeping dates. `updated_at` was rejected as a backfill source -- the routine bumps it on a refresh that changes nothing.
- **D4** no public grant on `model_pricing`. The browser already receives the sheet as the generated block in `shared/models.js`; the block now carries `id` and `effective_from`, so the AI Audit half can show rate and date without a new grant.
- **D5** the gates keep their inner join. AGT-742 (open) owns "the sum drops every model with no sheet row".
- **D6** `computeCallCost()` keeps its return shape; `pricingRowId(model)` is a second export over one shared lookup. The ticket's "returns the row id alongside the dollar" would have changed a function 8 source files and 5 tests call.
- **D7** no shared SQL helper for the dollar rule. Two bodies hold one expression; the new test's arm (c) pins it in both and arm (d) checks the gate against the JS book on live rows.
- **D8** `lib/activity-log.js` stamps only when it priced the row itself. A caller-supplied `costUsd` (a refused call's 0, a session row's null) came from no rate row.
