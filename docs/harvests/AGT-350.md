## 3. The Designer calls, and what each does not do

1. **The owner list** - seven names: the six data-centre owners measured above plus `Amazon.com, Inc.`, which the ticket names ("Amazon and similar") and which has not been seen in the cache. That string is the name ipinfo publishes for Amazon's networks as I recall it, not a measurement; if it is wrong the cost is exactly the fallback John was already told about (the row reads "Home or office" until the name is corrected). I added no other unmeasured owner. The list is a declared constant with the tab, as the ticket says; moving it to data is a separate ticket if the list starts to churn.
2. **The Last column** - time only (`2:44 PM`, the mock) while every connection of the agent falls on one Central day; once they span more than one day every row prints `Oct 3, 2:44 PM`. It is decided from the data, never from the clock, so the same rows always print the same text and the test needs no fake "now". It does not print a year or `CT`: the Connections card directly above already prints the first and last connection in full (`Oct 3, 2026, 11:49 AM CT`). Alternative weighed: "time only when the row is from today" - rejected because it makes the view depend on the reading time and a one-day-old sample would change under John's approved mock.
3. **Phone width** - the network name takes a full line of its own and Type, Count, Last sit on the line beneath; the header row follows the same shape, so all four labels stay. One grid, three columns on a phone and four on desktop, so nothing wraps mid-value at 375 px. Alternative weighed: hiding a column on phones - rejected, it drops approved content.
4. **Unknown network** - when the address has no resolved owner the Type cell is an em dash, not "Home or office": the platform does not know, and saying so is not a new category. None of `brittany`'s 16 rows is in this state today.

Standing-rule items, not calls: a `FeatureBadge id="AGT-350"` on the card (STANDARDS.md Section 5 checklist), version header lines, tokens only.

## 4. Why these three files

`activityView` is the tab's one author of words and numbers and `ActivityTab` only lays them out, so the column names travel in the view (`columns`) and the screen adds none. Coupled tests checked: `agt-334`, `agt-337` and `log-143b` read `PersonnelScreen.jsx` but pin nothing inside `ActivityTab`; `agt-339-activity-tab.test.mjs` reads card 2 only through `row[0]`, which stays the network name, so it passes unchanged and a new test file carries this ticket's arms. `tests/regression/run-all.js` discovers every `.mjs` in the folder; no registration.
