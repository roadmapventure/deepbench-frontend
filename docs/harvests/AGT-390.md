## Designer calls (recorded, reversible)

1. **The shared agent_configs writer is `insertAgentConfig()` in `lib/knowledge-write.js`.** It does not get a new lib file. That module becomes the one writer for everything an agent is taught: taught items and rules. The route and the handler both call it, so there is no second inline insert (pattern:14). Undo: move it to its own file later.
2. **The key name reaches the handler as `handler_context.caller_key_name`.** It is not read from `visitorId`, because a keyless caller's `visitorId` is a derived tag and would mislabel `origin_caller` (pattern:32).
3. **Capabilities and assignments are written as one array POST per table.** The call order stays `POST agents, POST capabilities, POST agent_capability_assignments`. Each table gets both rows or neither, and the undo deletes both slugs in one call.
4. **A guardrail's title is not stored.** `agent_configs` has only `name` and `text`, and `name` holds the side, always or never (John 0b2bd8e3). The title comes back in `saved.title` only.
5. **The Teach target is always the holder.** `any_agent` is forced false before `bundleTarget()`, which applies the own-knowledge rule (AGT-338).
6. **DeepBench routes set `origin` on the server.** The browser body cannot claim `mcp`. `embedAndUpsertEntry` sets the tag only when it is truthy, so an upsert by id never blanks a tag.
7. **Dates show in America/Chicago (pattern:140).** The format is `Oct 5, 2026`.
8. **The confirm text `Delete this guardrail permanently?`** mirrors the existing `Delete this output format permanently?`.
9. **A client guardrail row shows text, tag and Delete, and does not use ConfigCard.** Set Default and User Selectable mean nothing for a guardrail, and John's ruling 0b2bd8e3 names exactly those three things.
10. **The Training tab shows the tag on taught items only.** Records the agent wrote itself have `origin` null and show no tag, which is honest absence (pattern:34).
11. **The docs ride the kickoff commit, done by the attended session.** The build does not touch them. The text is below. The runbook gets **no new stamp line**, because `tests/regression/agt-338-runbook-pins.test.mjs:81-83` holds the stamp block at exactly 5 with v7.0.776 first. The paragraph names AGT-390 and v7.0.792 inline instead.
12. **The orphan sweep replaces a 13th file edit.** `agt-338-connect-team-address.test.mjs:188-190` cleans up only `<id>-knowledge`, which would leave `<id>-teach` orphans. Arm (h) of agt-390 sweeps them instead. `run-all.js:174-176` sorts the files, so agt-390 runs after agt-338-* in the same suite run. The orphan test ("no `agents` row for the slug's id") cannot hit a live agent. `createPrivateAgent` writes `agents` before `capabilities`, its undo deletes `capabilities` before `agents`, and agents are archived, never deleted. A direct edit to that test can follow when the cap allows.
13. **The screen merges `origin` into `toEntry` output** at its two loaders, so `src/lib/taughtItems.js` is not edited (cap).
