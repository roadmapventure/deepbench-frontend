Rule `AGENT-ROW-AGREED-TICKET` enumerates only the five roster tables, yet its prose licenses
editing "an agent's identity, behavior, **knowledge or guardrails** rows". The mechanism is
narrower than the rule's own words. I did **not** touch the rule block: its quoted lines are
rendered from `public.governance_rules` and its text is John's decision (`20a06cf3`, amended
`38a1c566`). Extending the engine to match the rule is the right move; rewording the rule is not
mine.

## Why the build is 2 files, not 3

`node scripts/check-api-function-count.js` reads **12/12** Vercel Hobby functions, 0 remaining, so
no new `api/` route can exist. A new handler is therefore
`api/_lib/handlers/agent-authoring-write.js` plus a two-line registration in
`api/prompt/request-receivable.js` (`HANDLERS`, line 132) — two files — which with the migration
mirror and the guard makes four, over the cap of three.

The cap is not what decided the split, though. `AGT-250` has no design at all
(`design_status` NULL, `kickoff_link` NULL), so nothing yet says what Susan emits. A handler
written now would invent AGT-250's output contract from the consumer side and hardcode a payload
shape its producer has never agreed to. Defining the *write contract* first is the correct
direction — the destination columns and constraints are the hard boundary, and AGT-250 then
targets a signature that exists. `predicted_cycles` is 2, so the two-slice shape is the ticket's
own, and `AGT-251` stays `partial` rather than being refiled (pattern 95).

## Alternatives considered and rejected

- **A handler that embeds and writes, no database function.** Rejected: the before-image must
  precede the write in the same transaction, and a Node handler making six REST writes cannot
  promise that. The atomic path belongs in SQL (pattern 19).
- **Write `knowledge_entries` with a NULL embedding and backfill later.** Rejected as D1: the
  column is `vector(1536)`, and a NULL leaves a passage the Personnel File displays as present and
  no retrieval can ever find. Fail closed instead.
- **Let the function create missing `capabilities` rows.** Rejected as D2: §19u decision 6 gives
  taxonomy creation to a brokered owner (`HAR-39`, still open at queue 687).
- **Amend `docs/ARCHITECTURE.md` as the third file.** Rejected: main's copy is 1,300 commits stale,
  so a §19v edit landing on a main-cut branch would diverge from dev's. The engine change plus its
  guard is the durable record; the doc amendment belongs to whichever cycle merges main forward.
- **Ask John to waive the 3-file cap (pattern 72).** Not needed — 2 files suffice, and the ticket
  is already going to him for design approval.

## Schema facts the tasks rest on

- Single-column `uuid` primary key on all six destination tables; `updated_at` exists on
  `agent_configs` only. So a Reverse reports `restored` for `agent_configs` rows and
  `restored_unverified` for the rest — D4's mechanism, and the reason the QA asserts the sum.
- `knowledge_entries.embedding` is `vector(1536)`.
- `runner_decisions.kind` has no CHECK, so `'agent-authoring'` needs no migration to the vocabulary.
- `ck_decision_attribution` and `ck_before_image_attribution` are both
  `(cycle_id IS NOT NULL) <> (session_name IS NOT NULL)`: a runtime authoring write passes
  `session_name` and leaves `cycle_id` NULL.
- `runner_decisions.backlog_id` CHECK is `^[A-Z]+-[0-9]+[a-z]?$`.
- `node scripts/agent-row-gate.js --ticket=AGT-251 --action=edit-active` → **BUILD**, no card.
