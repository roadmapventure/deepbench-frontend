## Design choices, and what was rejected

1. **Restore the branch at its SES-368 position and keep `orchestrator_model()`.** The ticket says so, and it is the cheapest variant that makes the code match M5-16 again. The branch text is byte-identical to the line that ran live in `ses395_judgment_lane_fallback` (position 11019 of that migration's statements). Rejected: dropping `orchestrator_model()`, because the ticket keeps it and the `ses-297` live arm and detail readers use its keys. Rejected: any "degrade first, refuse later" threshold, because John has not ruled one.
2. **Build the up from the live `pg_get_functiondef`, not a hand-written body.** Any later change to the function is kept, and the diff is two comment swaps plus one line. The trailing DO block asserts overload count, the branch, the absence of the misattributed "Live fix" text, and grants in both directions (SES-315 addendum). `CREATE OR REPLACE` with the same signature keeps grants and the COMMENT.
3. **Compact numbered item 4, not the SES-368 paragraph verbatim.** The old reason 4 was about 1,500 bytes and the runbook had 85 bytes of headroom (380,915 of 381,000). The compact item keeps the formula, the calendar, the precedence against the wall and the detail keys, and it corrects the attribution. The net change is −206 bytes, ending at 380,709.
4. **No header stamp on the runbook.** There are 5 stamps against the cap of 5, and SES-400 (v7.0.498) set the precedent of no stamp at this ceiling.
5. **A new `ses-297` clause, `the-pace-is-numbered-refusal-4`.** Restoring `REASONS` alone only checks that the string `` `weekly_pace` `` appears in the gate block. A paragraph that names `weekly_pace` while saying it no longer refuses would pass that. Measured: the clause is true on the edited runbook, false on the unchanged one, and false on a copy that names `` `weekly_pace` `` in the unnumbered paragraph. Its control makes it false.
6. **The test stamp is replaced, not appended.** The 8-line live-fix stamp states John's sentence as the reason for the removal. The ticket asks for the attribution corrected, so that stamp goes and the v7.0.510 stamp takes line 1.
7. **The fixture lifts `weekly_rest_pct` to 101.** On days 6 and 7 the wall (85) sits below the pace line (85.71, 100), so the pace refusal cannot be the observed reason there with real budgets. Lifting the wall inside the rolled-back transaction makes the check independent of the day. The first entry should also flip on day 7: before the fix it would read `unaffordable` (headroom 0), after it `weekly_pace`. That is derived from the ladder, not measured; the measurement was taken on day 6.
8. **Model.** The build applies a migration to the production boot gate and edits three guarded files under a byte ceiling, so it goes to the judgment lane (claude-opus-5 while `judgment_model()` answers `fable_rest`).

## What this does NOT do

- It does not make the Opus-pinned routine switch models. `orchestrator_pace` becomes a reported value, visible on a `weekly_pace` refusal row or on a mid-cycle read.
- It adds no degrade threshold and does not touch `routine-prompt.md` or `ses-355`, which already list seven reasons (`ses-355` clause `seven-refusals-named`, green).
- It cannot rewrite the live-fix migration's header in `schema_migrations`. The new function comments carry the correction instead.

## Discovery for The Development Manager (not filed by this design run)

**A live register rule was contradicted by a migration and nothing went red.** M5-16's statement names the exact refusal and its position. The live fix removed the branch and rewrote the one test that encodes it (`REASONS`, the oracle) in the same commit. So the registry, check 9/10/11 and `ses-297` all stayed green while the code broke a `live` rule, from 2026-09-15 16:57Z until this ship. The process gap is that no guard compares a register statement's named refusal set with the gate's closed `REASONS` set, or with the function body. A guard that derives the expected refusals from `governance_rules` rather than from the test's own list would have failed on `e46a4a24`. I recommend classing it **P10 - Tooling** and quoting it with its own cycle count. The same gap covers M5-15, whose statement names `meter_stale`.
