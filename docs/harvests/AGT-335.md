## Why a second function instead of editing mergeRoster
Editing `mergeRoster()` to append would turn `agt-006` arm (c) red and force a fourth file. `buildRoster()` wraps it: the overlay rule and its test stay exactly as shipped, the new behavior has its own pin, and the file count holds at 3.

## Defaults chosen and why
- Brittany's entry (`agents.js` 283) is the approved blank start: zeros for money and training. Table-only agents get the same zeros.
- Absent text renders `"—"`; quip is `""` because a quip is agent-voiced copy and the hook must not author one.
- `benchGroups: []`: the row shows under "All" and under no group. `AGT-332` (in flight, not on dev) adds the Private filter and owns that membership; claiming a group here would collide.
- `trainable` from `agent_origin = 'customer'` (Bob and Brittany are the two customer rows today) so Add Training reaches the Teach screen for a created agent and stays locked for a system row someone forgot to add to `agents.js`.
- `hiredOn` from `created_at`, month and year in US Central.
- Inactive rows are shown with the flag carried: creation lands `is_active = false` by rule, and hiding those would defeat the use case. The broker roster is fenced separately (`lib/project-manager.js`).

## The module cache
`PersonnelScreen.jsx` 1597 and `TeachScreen.jsx` 81 fall back to `agents[0]` when the id is not found. Because D4 renders `AGENTS` first, a table-only agent's file would open as Chloe's until the fetch lands, and Personnel's capability fetch would fire for the wrong id. Caching the last built roster at module level fixes the Bench -> card click path, which is the use case. A cold deep link still shows the fallback briefly; fixing it needs a screen edit and is listed for filing.

## Alternatives not taken

- Put the neutral config in `AVATAR_CFG` under a `default` key: a fourth file, and tests enumerate `AVATAR_CFG` keys as agent ids (`agt-120`, `agt-164`).
