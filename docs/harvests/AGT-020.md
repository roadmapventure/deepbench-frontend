## Decisions (The Designer's, recorded and reversible — JOHN-0925-DESIGNER-DECIDES)

1. **Which level is the lever: the fired intent's link.** A capability has one link level per Skill; identity/behavior/guardrails/knowledge links carry their own. INTENT-MODEL.md:65 names Level "quality of execution", and the intent is the work. The fired-intent gate already exists at db-assembly.js L293 (`if (intentSlug && sp.slug === intentSlug)`), which also keeps `dan-ai-enrichment/prompt-synthesis` (an L3 intent loaded through `enrichment_capability_slug`) from injecting an L3 line into every enriched call. Identity/behavior link levels stay unread — slice 2 or never; measured, they are 51/53 of 54 at L2 and carry no signal today.
2. **Directive text is data, not code.** pattern:11 forbids a content judgment in the repo; VOICE (AA-127) is the one hardcoded platform constant and is deliberately not extended. A four-row lookup `public.skill_levels(level pk 1..4, name, execution_directive)` with a foreign key from `capability_skill_profiles.level` gives (a) PostgREST embedding on the three existing selects — zero extra round trip, the LOG-67 shape; (b) referential integrity on a column that today accepts any integer; (c) a row edit, not a deploy, to retune depth wording (pattern:8).
3. **Rendering: one line appended to the INTENT section**, order 5, stable phase (HAR-02b) — the capability's config is per-capability-constant, so the cacheable prefix is unchanged. Format `Execution depth: L<n> <Name> — <directive>`. Fail-open: no embed → no line → byte-identical to today (proved by the T3 pure half).
4. **Grants:** `REVOKE ALL ON public.skill_levels FROM anon, authenticated` — only the service key (db-assembly) reads it; a future browser display would need an explicit SELECT grant (fail closed, the direction `.claude/rules/supabase-column-grants.md` prefers).
5. **The four directive strings** are execution-depth instructions only, deliberately silent on tone/confidence so slice 2 can carry those columns without rewording these rows.

## Alternatives weighed

- Hardcoded L1..L4 map in db-assembly.js: cheapest by bytes, rejected by pattern:11/2 — the strings are model-facing content.
- Store the directive as a trait on the Behavior Skill: wrong grain — level is per capability-skill link, not per Skill row.
- Separate fetch of `skill_levels` per assembly instead of an FK embed: one more round trip on the hot path and no integrity gain; rejected.
- Skip the FK to keep `capture_migration_down` from refusing: the refusal is a documented result (runbook step 6), the hand undo is one DROP CONSTRAINT, and the integrity is worth it.

## Decisions (The Designer's, recorded and reversible — JOHN-0925-DESIGNER-DECIDES)

1. **Source: the FIRED intent's own `skill_profiles` row, same gate as the depth line.** Level is per link; tone/confidence are per Skill row, but the gate is the same (`intentSlug && sp.slug === intentSlug`): the intent is the work, and a stacked or enrichment intent must not set the register any more than it may set the depth. No select change — `skill_profiles(*)` already carries both columns onto every profile, so S5's "exactly 3 embeds" stays true.
2. **Rendered verbatim, one line each: `Tone: <tone>`, `Confidence: <confidence>`, after the depth line.** The `Label: value` shape mirrors the behavior branch's `Reasoning style:`/`Writing style:` lines (L282-283) — pattern:17, an existing shape rather than a new one. The value is content (pattern:11/90) and ships as written in the row; `.trim()` plus a non-blank test keeps a stray space from producing an empty `Tone:` line.
3. **Independent of the depth row.** A tone renders even when `skill_level` is null (P8). The fkey makes that case unreachable through a write today; keeping the two levers independent means a future fifth level or a level row edit cannot silently drop the register lines.
4. **No CHECK constraint, no enumeration.** The live values have already left both documented enumerations; a CHECK would fail on `high`/`analyst`/`precise` today or force a data rewrite outside this ticket's scope. The register is free text John edits per row (pattern:8). ARCHITECTURE.md L470's "(scale TBD)" is left for slice 3 to restate as "free text, read verbatim" — it sits in the LOCKED vocabulary table, and one doc slice should carry all four stale homes at once (pattern:163).
5. **Format/behavior/knowledge rows' tone stays unread.** Format's 5/5 population is the best-populated signal, but the remainder names the depth line, i.e. the intent section; rendering format tone inside the FORMAT section is a different mechanism and a different section, not "riding along." Named as not done, not as residue — nobody asked for it.
6. **Slicing at the cap.** Code + guard + one doc home = 3 files. ARCHITECTURE.md wins the third slot over SKILL-PROFILE-MODEL.md because it is the governing section the kickoff cites and its schema block is now factually incomplete (no `skill_levels`). Slice 3 is doc-only and mechanical: SKILL-PROFILE-MODEL.md §5 L154-172 (level is read as the depth line) and §6 L208-209 (enumerations → live free-text values), AGENT-COMPETENCY-MODEL.md L170-171 ("never read" → read on the fired intent) and L409-420 (item 4/5's "later-bucket vision" is now built), ARCHITECTURE.md L470. The 3-file cap is John's to waive, not mine (pattern:72); slicing keeps every home named rather than dropped.

## Alternatives weighed

- One combined line `Register: tone technical; confidence measured`: fewer bytes in the prompt, but invents a label ("Register") the model has never seen in this platform and couples two independent columns; rejected for two `Label: value` lines.
- Render tone/confidence from the Behavior or Format Skill instead: wrong rows for "riding along with the depth line", and behavior is 2/22 populated; rejected.
- Add a CHECK on `tone`/`confidence`: see decision 4.
- Skip the test file and spend the third slot on SKILL-PROFILE-MODEL.md: a QA that cannot go red without a model call fails the "fails if nothing changed" bar, and STANDARDS §4 requires the Node guard; rejected.
- A full `run-all.js` as the only proof: 30-75 minutes on a shared slot; the kickoff's §6 is provable with the one targeted test plus two `agent-prompt.js` renders and one read-only SQL count, and T4 still runs the suite before shipping.
