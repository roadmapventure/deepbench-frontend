### 10.2 The design choice — why a second exported list, not a wider `KINDS`

Every importer of `KINDS` (grep over tests/ and scripts/): ses-378c, ses-378f, ses-378g, ses-378h, agt-187, agt-198. Three of them pin the closed four:

- `ses-378c-staff-watch.test.mjs:198-206` — `deepStrictEqual([...KINDS].sort(), [four])`, message: "mirrored by the table's CHECK constraint".
- `agt-187-kickoff-green-attested.test.mjs:255-260` — `strictEqual(KINDS.length, 4)`, message: "A fifth was ruled dead for AGT-187 and cannot appear without the migration this session does not run." The harvest's slice-3 note missed this third pin: widening `KINDS` is a FIVE-file change (script, 378c, 378g, 187, runbook), not three.
- `ses-378g-judgment-kinds-caller.test.mjs:125-131` — every `KINDS` entry must grep as `--kind='<k>'` in `docs/runbooks/runner-cycle.md`, "a vocabulary entry with no caller records nothing". The runbook is 380,985 bytes against the SES-336 ceiling of 381,000 (15 bytes of room).

Three variants weighed:

- **A. Widen `KINDS` to five, re-pin 378c/187, add a `--kind='gap finding'` runbook line for 378g.** Five files, over the P9 cap of 3; and the runbook line would document a CLI call nothing runs — the trigger writes the row. A false caller is the kind of fact pattern:33 forbids showing. Rejected.
- **B. Widen `KINDS`, and teach 378g to exempt trigger-written kinds.** Four files (script, 378c, 378g, 187). Still over cap, and it moves three green pins to say something weaker. Rejected.
- **C (chosen). `KINDS` stays the CLI vocabulary; `TRIGGER_KINDS = ["gap finding"]` and `RECORDED_KINDS = [...KINDS, ...TRIGGER_KINDS]` are exported beside it; ses-378h arm (d) — the only reader asking "may the table hold this kind?" — checks `RECORDED_KINDS`.** Two files. `parseArgs` (staff-watch.js:366, :394 — the only consumer of `KINDS` inside the script; `--since-days` and `--promote` do not filter by kind) keeps refusing `--kind='gap finding'`, which is correct: the CLI must not be able to forge a trigger attribution. 378c, 378g, 187 stay green unedited (pattern:17 — extend the structure that fits; pattern:8/65 — narrowest layer). Lines 125 and 253 of ses-378h, which check RUNBOOK call sites against `KINDS`, correctly stay on `KINDS`.

What C does not do: it does not make the script's vocabulary self-reading from `pg_constraint` (pattern:2 would prefer the CHECK as the single source). That would put a SQL read in a CLI argument parser and in six test imports; the two lists agree by a test instead — the same shape §19t uses for `MODEL_PRICING`. If a sixth kind is ever added to the CHECK, ses-378h (d) reds again the moment a row lands, which is the right alarm.

Also measured: `.claude/rules/` holds no file naming `staff-watch` or `runner_staff_findings`; `docs/ARCHITECTURE.md` names neither — the governing sections are §19v (2543, Heal) and §19b (1089, vocabulary as data). The `gap finding` string also appears in `scripts/db-health-watch.js:18`, `docs/design/agt-237-db-health.sql:395` and `agt-277`'s test, all meaning an `audit_findings` row of type gap, not this kind — unrelated, untouched. The parseArgs message "not one of the four recorded kinds" (line 395) stays true of the CLI's four and is pinned by nothing; left unedited to keep the diff to the two files.
