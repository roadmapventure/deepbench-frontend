## 4. Design and what I turned down

Chosen: keep the step's HEAD run exactly as it is, capture its output and exit code, and only when it is red re-run the red names on the `$BASE_SHA` tree. A name red on both is printed `[STANDING]` and not graded; anything else fails the job. The comparison is the new `scripts/ci-new-reds.js`, which reuses `failingTestsFrom()` from `scripts/verifier.js` (pattern:14 -- the one line-anchored `[FAIL]` parser, by name, the same rule AGT-586 and the delta re-grade use) and spends no model call (pattern:9).

- **Subtract the base's red names from `$RELATED` before the HEAD run** (the ticket's first wording). Turned down: it needs the base run on every push, green or red, and it hides the standing reds from the log. Running the base only after a red costs nothing on the 302 green pushes.
- **Read a stored standing-red set** (a table or a file). Turned down: nothing measures that set on a schedule (AGT-606), and a stored list goes stale; the base tree in the same job, against the same database, is a before/after pair by construction (pattern:162).
- **Move the worktree and symlink into the script.** Turned down: the step already owns `$BASE_SHA` and the fetch; the script stays a pure comparison plus one child process, which is what lets the guard drive it offline with a fixture.
- **Edit `docs/runbooks/runner-cycle.md` step 4a.** Not needed: 4a already reads a blocking failure as a real red, and that reading becomes true. Leaving the runbook alone also avoids the card and byte-pin drag (pattern:163 checked: `git grep AGT-573` outside kickoffs and harvests finds only ci.yml, the guard and the backlog snapshot).

Fail-closed choices (D2): HEAD exit 1 with no parseable test file name fails; a base run that exits anything but 0, or exits 1 without naming a red, fails; HEAD exit 2 passes through as exit 2, unchanged from today. A test that does not exist at the base is new by definition.

What this does not do, said plainly:
- A push that makes an already-red test fail for a second reason still reads `[STANDING]`. The comparison is by name, as everywhere else on the platform.
- A green blocking job still speaks only for the tests the push's diff selected. What changes is that the answer no longer depends on whether the diff happened to select someone else's red. The whole tree stays with the weekly full run (AGT-391).
- The base tree runs against HEAD's installed packages. A push that changes dependencies grades the base under the new ones.
- The base re-run doubles the suite's database use for the red names only, and takes the test slot a second time, one run after the other.

Risk (John's rule 6e94edcb): one staged ship is right -- all three files are text in the repository, the reach is the conclusion CI writes for each push, and one `git revert` undoes all of it. Nothing touches a row, a function or an agent's autonomy.
