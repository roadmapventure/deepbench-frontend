# AGT-628 — reasoning harvest (not required reading for the build)

## 1. The premise, revalidated live (2026-11-09, tree `b534d98`)

**The script half.** `scripts/settle-ship.js` `writeCost()` composes `notes` at :645
(`prior.includes(clause) ? prior : …${prior} | ${clause}`), PATCHes `runner_cycles` with
`Prefer: return=representation` at :693-695, and then grades the representation key by key at
:698-704 with `String(got ?? null) === String(want ?? null)`. `notes` is one of the two keys in
`cyclePatch`, so the whole string is graded for equality.

**The database half.** `docs/design/agt-173-card-citation-guard.sql` (AGT-173, `v7.0.652`):
`trg_runner_cycles_notes_citations` is `BEFORE UPDATE OF notes` on `public.runner_cycles` and runs
`runner_record_citation_guard()`. Its block 3 (:265-275 of that file) does, unconditionally and
with no exception path:

```sql
select string_agg(h.handle_sentence, ' ' order by h.decided_at) into v_append
  from public.cycle_reversal_handles(NEW.id, NEW.item_id) h
 where position(h.handle_token in v_new) = 0;
if v_append is not null then
  NEW.notes := btrim(concat_ws(E'\n\n', NEW.notes, v_append));
end if;
```

`cycle_reversal_handles()` returns one row per `runner_decisions` row at that cycle carrying the
same `backlog_id` (plus migration-downs), `handle_sentence` =
`format('Reversible through decision handle %s (%s): %s.', id, kind, summary)` and `handle_token` =
`left(id::text, 8)`. So the stored row is always the patch PLUS a sentence for every handle whose
first 8 characters the patch did not already carry.

## 2. Alternatives weighed

- **Append through `scripts/cycle-note.js` instead** (the ticket's other option). Rejected:
  `cycleNote()` verifies only that one row came back and prints lengths — it asserts nothing about
  the clause, so the cost write would lose its only proof that the basis landed. The narrow fix
  keeps the assertion and corrects what it asserts (pattern:65).
- **Keep equality but strip the trigger's sentences before comparing.** Rejected: it re-implements
  the trigger's format in JavaScript, so the check breaks the next time AGT-173's wording moves.
- **Bound the retries** (give up after N). Rejected on pattern:1 — eliminate the problem, do not
  bound it.
- **Key the idempotence on the ticket** (any `ticket-status` row for this ticket). Rejected:
  `resettleTicket()` (AGT-167b) calls `applySettle()` precisely to change `partial` → `delivered`,
  and a ticket-wide key would reuse the earlier decision and lose the re-settle's own reasoning.
  Keying on the exact summary (which carries the status) makes a genuine re-settle mint and a
  retry reuse.
- **Re-image on reuse.** Rejected: on a re-run `row` is the already-settled row, so a second
  before-image would record `delivered` as the prior state and a `reverse_decision()` would restore
  nothing useful (§19v, "No before-image logged → the write does not happen" — its intent is the
  TRUE prior, not a second copy of the new value).
- **Fix the trigger.** Out of scope and the wrong layer: the appended sentence is the shipped
  feature (AGT-173 completeness), and AGT-518 already tracks a different symptom of the same
  appender. Named, not touched.
