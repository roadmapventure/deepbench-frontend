## The staging call: an attempt, not attended-only

The two halves carry different risk, and the risk rule asks for a staging decision with its reason.

- Half 1 is three edited lines and one new pure function in a tracked file. Reach: the text of re-grade verdicts written after the ship. No status, verdict, exit code or stored row changes. Undo: git revert.
- Half 2 writes a live agent Skill row. The platform's own gate answers `gated` for an unattended cycle on this ticket. It is undoable (the row's before-image) and it does not change autonomy -- the code already withholds the auto-done bar for both CI files -- so it does not have to become its own ticket; it has to wait for an attended session.

Parking the whole ticket would hold back a text fix that needs nobody's presence, and leave every re-grade reading as a statement about dev in the meantime. Building half 1 and naming half 2 as blocked is what the redesign rule describes: a part only a gated action could deliver is named as blocked, never disguised. Nothing in the kickoff sends, reroutes or rewords the gated write. The ticket closes `partial` and stays `needs-desktop`; the orchestrator parks the remainder after the ship.

`agt-67-verifier.test.mjs` is deliberately left alone. Binding `SELF_CERTIFYING_CI_FILES` to the live row before the row names those files would turn that test red on dev until an attended session arrives. The binding travels with the row edit.

## Mechanism: why read a field nobody writes yet

Three variants:

1. Always print "count unavailable". Cheapest, but it is a hardcoded statement about data the function never looked at, and it would stay wrong after CI starts publishing.
2. Read `tests_run` off the job entry, print it when it is a non-negative integer, otherwise say CI published none. One extra line; the text is derived from the row. Chosen.
3. Also make ci.yml publish the count. That edits a `SELF_CERTIFYING_CI_FILES` member, changes the report job's payload and its guard tests (SES-255, agt-194, agt-573), and a malformed workflow stops all grading. A third file family and a different risk level; filed as a discovery.

The ticket's own text accepts either "carry the count" or "say the count is unavailable", so variant 2 satisfies its sentence in full; the ci.yml writer is new work, not this ticket's residue.

What "tests run" counts: regression test files the job's `run-all.js` executed. A selective run with an empty related set would be 0, which is exactly the green the ticket worries about.

Known roughness: on a zero-verdict re-grade the build gate's line also reads `tests run: not published by CI`, though the Build job runs no tests. True as written, and one wording for all three gates keeps the function free of per-gate branches.
