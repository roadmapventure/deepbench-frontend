## 3. The four decisions I made (recorded, reversible, no John call)

- **(i) The block lives in `docs/runbooks/personal-agent.md`, id null.** The ticket names that file. `check-routine-prompt.js` resolves `file` under `docs/runbooks/`, so no new runbook is needed, and `id: null` is the honest value until the attended session creates the routine (AGT-102's placeholder is exactly what an invented id costs).
- **(ii) Not added to `scripts/sync-routine-models.js`.** That registry GETs each trigger by id and asserts a read-back; an entry with no id would break `--plan`/`--verify` and its suite. The attended session adds it with the real id. Named in the kickoff's STOP LINE so it is not lost.
- **(iii) The alert channel is derived from `source`, not a new kind.** A sibling of AGT-268's `postingOrigin` (pattern:17 - extend the structure that already fits; pattern:8 - narrowest layer that works). No 12th `career_records` kind, no `career_records_kind_check` change, no migration, no backfill, and the raw `source` still never reaches the prompt (Rule #1, 19d/19e).
- **(iv) Sunday reads ONLY alert postings; Monday gets the stamp only.** The `career-linkedin-alerts` render already measures 1,535,220 bytes (AGT-155's design SQL). Adding all 310 posting rows to a weekly market watch would balloon that prompt for no gain, and John's Q5 asks only that the Sunday and Monday runs read the LinkedIn posting records. Monday already reads the reviewed write-backs, so it needs only the channel label - no READ_MAP or filter change there.

## 4. Alternatives considered and rejected

- **Amend only the two routine prompts.** The ticket's literal wording ("amend the ... prompts so their renders include posting records with source linkedin-alert") cannot be satisfied by prompt text alone: what a render loads is `READ_MAP`/`KIND_FILTERS`, not the routine's words. Prompt-only would be theatre - a change that does nothing, which is what the discriminating QA is built to catch.
- **A 12th `posting`-like kind, or re-pointing alert write-backs at a dedicated row.** Needs a migration and a check-constraint change, and would leave the 0 existing rows and every future reader to be taught a second shape.
- **Filtering by `data.status` instead of `source`.** `status` is a field the answer writes, so it is not a provenance discriminator - the exact hole AGT-268 recorded.
- **Adding the routine live from this cycle.** Ruled ATTENDED by the Dev Manager on 2026-09-28, and `update_trigger`/creation by an agent is refused on this account (SES-140, AGT-145, AGT-155). The kickoff therefore hands John a paste-ready body instead.
