## 3. The alternatives, and why keep-and-preserve wins (Designer decision, reversible)

1. **Refuse when `up_name` exists under a different cycle** (the ticket's fail-closed option). Dead on this platform's own evidence: the recapture that overwrote the witness was AGT-184's legitimate re-land of the SAME name — the one act that cured the ledger orphan `ledgerOrphansIn()` flags. A refusal would have forced a new name, the orphan `agt138_researcher_route` would have stayed orphaned forever, and every red range would read card-only for good. Refusing also errors the runbook's own step-6 instruction on every honest re-apply.
2. **Version the row** (drop `UNIQUE (up_name)`, one row per capture). Breaks every reader in §2 that destructures one row or asserts `length === 1`, and `readMigrationDowns()`'s "absent means not captured" semantics. It also duplicates what `runner_before_images` already does: the function images the row before every upsert, and `2f12bb39` is the proof that the chain is complete for a recapture. Versioning is a parallel structure next to one that already fits (pattern:17).
3. **Add `recaptured_by_cycle` / `recaptured_at` columns.** Works, but an `ALTER TABLE` on an existing table is `refused` by `capture_migration_down` by design, making THIS ship card-only, and it adds two columns whose only reader would be the new test (pattern:67). `prior_ddl` already carries the current down's own `captured_at`; adding `captured_by_cycle` beside it makes the current down fully self-describing at zero schema cost, and the ship stays auto-downable (the down is the prior function body plus the overload-drop assertion).
4. **Chosen: keep the row, preserve first provenance, refresh the down.** `captured_by_cycle` and `captured_at` = the FIRST capture, never touched by the upsert. `down_sql`, `prior_ddl`, `classification` = the CURRENT down (a re-applied name legitimately needs the down for its latest apply; the prior body is in the before-image). `prior_ddl.captured_by_cycle` = the cycle that derived the current down. Not versioned.

What the choice does NOT do: `readDownsCapturedBy(<recapturing cycle>)` will no longer list a name that cycle re-captured. That is correct for its only consumer — `ledgerOrphansIn()` detects orphans BY NAME, and a re-captured name already has a watermark from its first landing (or gains one from the re-land), so the recapturing cycle contributes nothing to orphan detection either way.

## 4. Why the repair is sourced from the image, not typed

The kickoff's Task 2 UPDATE joins `runner_before_images 2f12bb39…` and takes `captured_by_cycle`, `captured_at` from `row_data` and the recapturing cycle from the image's own `cycle_id`, guarded by `d.captured_by_cycle = b.cycle_id` (the image is the pre-upsert state of exactly that overwrite). The literal values in the kickoff (`bd03a2e4…`, `2026-09-26 11:58:57.643738+00`) are the ASSERTION after the update, read live this cycle, not the source of the write. The repair writes its own before-image first under this cycle's id (§19v), and the guard test's arm B asserts that image exists — a repair with no image is the write §19v forbids.

## 5. Why the discriminating proof lives in the migration's `DO`, not only in the test

`pg_proc`, `pg_get_functiondef` and a BEGIN/ROLLBACK are unreachable over PostgREST (SES-310), and a permanent test must never write the live ledger (SES-196/218/275). So the two-capture probe runs inside the migration's own transaction, ends with `RAISE EXCEPTION 'AGT207_UNDO'` caught by the block's handler (an inner `BEGIN … EXCEPTION` is a subtransaction), and leaves zero rows — the AGT-195 (v7.0.632) precedent. On the unchanged body the probe's first assertion (`captured_by_cycle` still the first cycle) raises and the migration aborts rather than reporting success — `.claude/rules/supabase-function-signature.md`: never trust the success flag. The `down_sql`-changed assertion is the second direction: a body that refused the second call would fail it.

`captured_at` cannot discriminate inside one transaction (`now()` is transaction-stable), which is why the probe discriminates on the cycle id.
