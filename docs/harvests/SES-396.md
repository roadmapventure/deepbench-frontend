## Why this slice and not another

The ticket has three build items. Two of them (the `ds-knowledge-environment` Skill row, and the baseline step inside `ds-kickoff-intent`) are writes to an **active** agent's rows, which §19v P5 reserves for an attended session — the same gate that left SES-376's clauses (D)/(E) declared NOT RUN in CI on card `1d57ebca`. The third depends on SES-378's staff watch, which does not exist. A kickoff that told an unattended Builder to do any of them would end in `gated_before_build` and burn the cycle.

What is left is not nothing, and it is the half with the longest shelf life: **the facts themselves**, written down in one place with a grammar a machine can check, plus the exact renderer whose output the gated row will hold. That makes the attended session a paste with no judgment in it, and it ships the test that will go red the day the row drifts from the file — pre-armed, declaring itself NOT RUN by name until the row exists, rather than passing quietly (§19k; the SES-393 convention shipped today).

Rejected alternatives:

- **Design the Skill row anyway and let the Builder discover the gate.** This is the failure the orchestrator measured on SES-376. The cost is a whole cycle and the finding is already known.
- **Put the baseline step in `runner-cycle.md` step 6 instead of the Skill row.** The runbook has 98 bytes of headroom against a pinned ceiling; the edit would have to delete runbook text to make room, which is a different ticket with a different risk.
- **Build the mechanical red-test baseline runner (item 2's ungated half) instead.** A script that runs the named tests on the unchanged tree is easy; the part that makes it *happen* is the instruction in `ds-kickoff-intent`, which is gated. Shipping the runner with nothing calling it is a script nobody runs — the shape this platform has already watched go inert. It belongs in slice 2, in the same attended commit as the Skill-row edit that invokes it.
- **Extend `scripts/check-session-docs.js` rather than adding a new checker.** That file is in the Verifier's `SELF_CERTIFYING_PATHS`, so touching it refuses the delivery the auto-done bar for a reason unrelated to the work. A standalone `scripts/check-*.js` is the existing pattern and costs nothing.

## Why the QA discriminates

Three arms that cannot all pass by accident. (1) A red-before pin: on `origin/dev` the validator exits 2 because the file it reads does not exist, so an empty change cannot show green. (2) Five mutation controls — a bad date, a missing pipe, a duplicate line, a `SOURCE` of `SES-99999` absent from the board snapshot, and the file removed — each with its own expected exit code. The `SES-99999` arm is the one that matters: a validator that only checks shape would pass it, and the register's whole value is that a line names a real finding. (3) The byte pin against the future row, which must announce itself `[NOT RUN]` naming `ds-knowledge-environment`; a green there with no row present would mean the arm is vacuous.
