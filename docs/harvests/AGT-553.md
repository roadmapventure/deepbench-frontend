## 2. Why it was parked, and what I will not do

The first kickoff (v7.0.1085) had one database write: a BEFORE INSERT trigger plus a two-line edit of `apply_requirement_verdict()`. The connector's migration call raised a confirmation prompt and timed out with nobody to answer. That is a gate, and the rule is the same as for a refusal (CLAUDE.md SES-019; redesign runbook clause 4): this design does not send that write again, does not send it through another tool, and does not reword it. No task in the kickoff touches a database object.

## 3. The new measurement that makes a smaller build worth shipping

The first harvest left 61 malformed rows "unexplained": a 16-hex fingerprint beside a place-less location, door unknown. I recomputed `fingerprint()` over every stored row and compared it with the stored value.

| class | all time | last 30 days | door |
|---|---|---|---|
| `apply_requirement_verdict()` not-needed rows (83-character key, bare string) | 221 | 4 | past the intake (database function) |
| fingerprint not 16 hex, not the above | 64 | 31 | past the intake (hand insert: slug, md5, sha256) |

So the 61 are explained, and none is left over: the intake itself admitted them. Their shapes: 50 bare strings (`"scripts/x.js"`), 4 `{file}`, 4 `{file, symbol}`, 2 `{text}` alone, 1 `{path}`. Their writers are all cycles and attended sessions filing hand-written JSON through the CLI (`runner:cycle:<uuid>` 36, `runner-cycle-53254e08` 7, six others); none came from a tracked caller. The newest is 2026-11-18. Control for the method: 2,541 of the 2,677 well-formed rows also match their recomputed digest (the rest are the three health functions' md5 keys and well-formed hand inserts).

A validator at the intake, with no database change, would have refused 61 of the 346 and 30 of the last 30 days' 65 (46%).

## 4. The redesign: scope, not route

Built now (2 files, 3 tasks):

1. `intakeProblems()` in `scripts/audit-ledger.js` — one validator for the week, every location and the fingerprint (the ticket's "build it to take all three fields"). AGT-202's two week refusals move into it word for word and still answer first and alone. `ingestFindings()` calls it before the read, so a refused batch costs no read, no before-image and no row.
2. `tests/regression/agt-553-ledger-intake-guard.test.mjs` — three offline arms. All three fail on the unchanged tree and pass with T1 applied (run on a copy of the tree, not the clone).

Removed from this build and named as blocked in the kickoff: the trigger, the `apply_requirement_verdict()` edit, the SQL mirror task, the three test re-pins (they were needed only because of the trigger) and the live arm D.

Why this is a redesign and not a way round the gate: the part that was gated is not delivered at all. The reach drops from every INSERT into the table (900 rows in 30 days) to the callers of one function; the undo drops from a captured migration down to one `git revert`; and the build has no window in which three shipped tests are red for other lanes.

Decisions I made (JOHN-0925-DESIGNER-DECIDES), each reversible:

- **A bare-string location is refused, not wrapped.** The contract requires `location` and `text`; wrapping would invent the `text`. `fingerprint()` already keys a bare string correctly, so the 50 string rows dedupe today; what they lack is the quoted words, and `renderReport()` prints them as `undefined`. The refusal message says what an entry is.
- **A dry run refuses too.** A verdict computed from an empty location key is the misleading answer this ticket is about.
- **One malformed finding refuses its whole batch**, as a missing finding type already does.
- **A finding carrying a `fingerprint` other than the ledger's is refused**; one carrying none is fingerprinted as today.
- **Arm C pins the parked SQL's pattern to `FINGERPRINT_FORM`.** One assertion, so the database half, whenever it is applied, refuses the same form the intake does (pattern:14).

## 7. Hazards checked

- **The weekly carry.** `carryForward()` copies a stored row's `locations` verbatim, so an old open row with one place-less entry would refuse the Auditor's whole weekly batch. Measured: of the 21 fingerprints whose latest row is `open`, 0 are carriable (two or more well-formed entries) and hold a malformed entry. Carried findings carry no `fingerprint` key.
- **Tracked callers.** Eight files call `ingestFindings()` besides the CLI; every one builds `{location, text}` entries in code (`staff-watch.js` L293, `ticket-owner.js` L1541, `market-agent.js` L314, `db-health-watch.js` L138, `decide-gated-card.js` L237, `backlog-review.js` L96) or passes a model answer whose contract requires `location` (`auditor-write.js`, `audit-run-review.js`). 0 of the 61 rows came from any of them.
- **`api/_lib/handlers/auditor-write.js` is not edited.** Its `usable()` filter does not look inside a location, so an Auditor answer with one place-less entry now refuses that turn's batch. Exposure on record: 0.
- **Related tests.** `scripts/related-tests.js` over the two touched files and the SQL the test reads names 19 existing tests plus the new one. Uncredentialed, on the unchanged tree: 1 red of 19 (`agt-133-run-tail-review.test.mjs`, standing). With T1 and T2 applied on a copy: the same 1 red of 25 (the 19, the new test, and five more that reach the intake through a caller: agt-159, agt-160, agt-172, agt-280, agt-86a).
- **The CLI, credentialed, dry run** (writes nothing): the probe in the kickoff exits 1 with `1 new` on the unchanged tree and exits 2 with the location refusal on the copy.

### Block S — the validator (T1). sha256 d279e47aaefd5124ad17f9e8747daa0bfea022007cbd5e7216cad07f691b1ea9, 1,367 bytes, 18 lines

```js
// ---- BEGIN S
// AGT-553 -- the ONE validator of what the intake admits: the week, every location, the fingerprint.
// FINGERPRINT_FORM is the pattern the parked trigger in docs/design/agt-553-ledger-shape-guard.sql holds (agt-553 arm C pins the pair).
export const FINGERPRINT_FORM = /^[0-9a-f]{16}$/;
export const WEEK_FORM = /^\d{4}-W\d{2}$/;
export function intakeProblems({ week, findings, thisWeek = isoWeek(new Date()) } = {}) {
  if (!WEEK_FORM.test(String(week))) return [`week must be YYYY-Www (got ${JSON.stringify(week)}) -- omit it to stamp this ISO week.`];
  if (String(week) > thisWeek) return [`week ${week} has not begun -- this ISO week is ${thisWeek}; omit week to stamp it.`];
  const out = [];
  (Array.isArray(findings) ? findings : []).forEach((f, i) => {
    const locs = Array.isArray(f?.locations) ? f.locations : [];
    if (!locs.length) out.push(`findings[${i}].locations must hold at least one {location, text} entry`);
    locs.forEach((l, j) => {
      if (typeof l?.location !== "string" || !l.location.trim()) out.push(`findings[${i}].locations[${j}].location is required and non-empty (an entry is {location, text}, never a bare string)`);
    });
    if (f?.fingerprint != null && f.fingerprint !== fingerprint(f)) out.push(`findings[${i}].fingerprint is not the one this ledger computes (${fingerprint(f)}) -- omit it`);
  });
  return out;
}
// ---- END S
```

//   A  intakeProblems() -- the one validator: week, every location, the fingerprint.
//   B  ingestFindings() refuses each malformed shape BEFORE any read or write and names the field;
//      a well-formed finding lands and is found again by its fingerprint on its second sighting.
//      CONTROL: the same stored row under a 64-character value is not found -- the defect itself.
//   C  the parked migration text holds the same pattern FINGERPRINT_FORM holds, so the database
//      half, when an attended session applies it, refuses what the intake refuses.

import assert from "node:assert/strict";
import fs from "node:fs";
import path from "node:path";
import { fileURLToPath, pathToFileURL } from "node:url";
import { selfRun } from "./_lib/self-run.js";

const ROOT = path.resolve(path.dirname(fileURLToPath(import.meta.url)), "..", "..");
const LEDGER = path.join(ROOT, "scripts", "audit-ledger.js");
const MIRROR = path.join(ROOT, "docs", "design", "agt-553-ledger-shape-guard.sql");
const CYCLE = "18dee91d-5b95-4398-a892-c29be0220b3f";
const DAY = 86400000;
const PLACE = "(an entry is {location, text}, never a bare string)";

function finding(extra = {}) {
  return {
    kind: "contradiction",
    locations: [{ location: "docs/agt553.md:12", text: "t" }],
    governing_fact: "agt-553 shape probe",
    confidence: "high",
    proposed_resolution: "refuse it at the door",
    finding_type: "defect",
    ...extra,
  };
}

function stubs(rows = []) {
  const posted = [];
  let reads = 0;
  return {
    posted,
    get reads() { return reads; },
    get: async () => { reads++; return rows; },
    post: async (t, b) => { posted.push({ t, b }); },
  };
}

async function run() {
  const failures = [];
  const arm = async (name, fn) => {
    try { await fn(); console.log(`    ok  ${name}`); }
    catch (e) { failures.push(`${name}: ${e.message.split("\n")[0]}`); console.log(`    FAIL ${name}: ${e.message.split("\n")[0]}`); }

  const LAST = isoWeek(new Date(Date.now() - 7 * DAY));

    assert.equal(typeof intakeProblems, "function", "scripts/audit-ledger.js must export intakeProblems()");
    assert.deepEqual(intakeProblems({ week: THIS, findings: [finding()] }), [], "a well-formed finding has no problems");
    assert.equal(fingerprint(finding()), "b27daecac5269cd4", "the fixture's digest, computed by the ledger");

    assert.deepEqual(intakeProblems({ week: THIS, findings: [finding({ locations: [] })] }),

    assert.deepEqual(intakeProblems({ week: "2026-W99", findings: [finding({ locations: [] })], thisWeek: "2026-W47" }),
      ["week 2026-W99 has not begun -- this ISO week is 2026-W47; omit week to stamp it."],
      "the week answers first and alone (AGT-202's rule, now here)");
    assert.deepEqual(intakeProblems({ week: "W47", findings: [] }), ['week must be YYYY-Www (got "W47") -- omit it to stamp this ISO week.']);

    for (const [bad, field] of [
      [finding({ locations: [{ text: "t" }] }), "findings[0].locations[0].location"],
