## 3. What the build does, and why this shape

Two refusals, one rule, and the one tracked writer that broke it:

1. **`intakeProblems()` in `scripts/audit-ledger.js`** — one validator taking the week, every location and the fingerprint (the ticket's "build it to take all three fields"). AGT-202's two week refusals move into it word for word; `ingestFindings()` calls it before the read, so a refused batch costs no read, no before-image and no row. A finding that carries a `fingerprint` the ledger would not compute is refused; one that carries none is fingerprinted as today.
2. **Trigger `audit_findings_shape` (BEFORE INSERT)** — the ticket's "fails closed for every future writer". It tests the fingerprint's form and that every entry is an object with a non-empty `location`. Both messages name the command to file through.
3. **`apply_requirement_verdict()`** — two lines, so Victoria's not-needed door keeps working under the trigger: the key becomes the first 16 hex of sha256 over `agt-280:not-needed:` plus the proposal (the namespace moved inside the hash; SQL and Node agree: the migration probe's key is `5552f399a6aa6c1a` in both), and the location becomes `{location: "requirement-check:not-needed", text: <proposal>}`.

Decisions I made (JOHN-0925-DESIGNER-DECIDES), each reversible:

- **A trigger, not a CHECK.** A CHECK added NOT VALID is still enforced on every UPDATE, so it would refuse a ruling on any of the 346 old rows — the trap `agt-131` arm D already records for the dropped `audit_findings_found_by_single`. A trigger on INSERT leaves old rows rulable.
- **BEFORE, not AFTER.** An AFTER trigger would leave every existing refusal code in place and cost three fewer files, but it cannot be probed safely: a live probe that an absent trigger failed to stop would land in an append-only table for good. A BEFORE trigger lets the standing test carry `kind: "not-a-kind"`, so a probe stops at the kind CHECK even when the trigger is missing. The price is three one-literal re-pins (agt-131 arm D, agt-86a arm V, agt-280) whose probes were themselves malformed.
- **Its own function, not an edit to `audit_findings_guard()`.** The guard's UPDATE/DELETE band is the append-only rule; replacing that function to add an INSERT test widens the reach for nothing. Named `audit_findings_shape`, it fires after `audit_findings_family` and `audit_findings_guard` (name order), so the one-source refusal still answers first and agt-132 arm F is unchanged.
- **The table tests the form, not the value.** Recomputing the digest in SQL would be a second home of `fingerprint()` (pattern:14) and would refuse the three health functions above, which key their own rows by a 16-hex md5. So a hand insert with a made-up 16-hex key and well-formed locations still lands; the carry re-fingerprints such a row once and it is stable after that.
- **A bare-string location is refused, not wrapped.** The output contract requires `location` and `text`; wrapping would invent the `text`.
- **A dry run refuses too.** A dry run over a place-less finding prints a verdict computed from an empty location key, which is the misleading answer this ticket is about. The type check stays apply-only, as AGT-131 argued.

### Block S — the validator (T1)

```js
// ---- BEGIN S
// AGT-553 -- the ONE validator of what the intake admits: the week, every location, the fingerprint.
// FINGERPRINT_FORM is the same pattern trigger audit_findings_shape() holds (agt-553 arm C pins the pair).
export const FINGERPRINT_FORM = /^[0-9a-f]{16}$/;
export const WEEK_FORM = /^\d{4}-W\d{2}$/;
export function intakeProblems({ week, findings, thisWeek = isoWeek(new Date()) } = {}) {
  if (!WEEK_FORM.test(String(week))) return [`week must be YYYY-Www (got ${JSON.stringify(week)}) -- omit it to stamp this ISO week.`];
  if (String(week) > thisWeek) return [`week ${week} has not begun -- this ISO week is ${thisWeek}; omit week to stamp it.`];
  const out = [];
  (Array.isArray(findings) ? findings : []).forEach((f, i) => {
    const locs = Array.isArray(f?.locations) ? f.locations : [];
    if (!locs.length) out.push(`findings[${i}].locations must hold at least one {location, text} entry`);
    locs.forEach((l, j) => {
      if (typeof l?.location !== "string" || !l.location.trim()) out.push(`findings[${i}].locations[${j}].location is required and non-empty`);
    });
    if (f?.fingerprint != null && f.fingerprint !== fingerprint(f)) out.push(`findings[${i}].fingerprint is not the one this ledger computes (${fingerprint(f)}) -- omit it`);
  });
  return out;
}
// ---- END S
```
