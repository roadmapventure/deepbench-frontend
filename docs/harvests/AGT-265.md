## 3. Design choices and the alternatives not taken

1. **Lanes = three more claude.ai routines of the same prompt block and cron.** Alternative: one routine spawning four sessions — no tool does that from a routine, and a lane that dies would take its siblings' visibility with it. Alternative: staggered crons (`25 1-22/3`, …) — `scheduler_gate()` grades a fire "manual, never paced" when off the `cron_minute` grid, so a stagger would mislabel every lane fire; same cron keeps the grid honest and B42 allows parallel fires. Chains still run in-session per lane, so the 3-hour cadence stays a heartbeat, not the pace (pattern:144).
2. **Lane cap in `runner_should_boot()` as refusal 7 `lanes_full`, after `db_pressure`, before `gate_cards_to_rule`.** Literal reading of "lanes above it refuse to boot": a 5th fire must not boot even in rule-cards-only mode. A live lane is an open `runner_cycles` row with the runner stamp whose `coalesce(heartbeat_at, started_at)` is ≤ 20 min old — the SES-103 tripwire's own bound, so no new liveness knob (pattern:67). The count is not atomic across four simultaneous fires; it is bounded by the number of routines, which is 4 = `max_lanes`, so the race cannot exceed the cap by construction today. It matters once John raises routines above `max_lanes`.
3. **Test line = a table-backed semaphore, `test_slots`, with one plpgsql acquire under `pg_advisory_xact_lock(265)`.** Alternative: a bare session-level advisory lock — dies with the connection, invisible in a table, cannot carry "waiting" for the matrix. Alternative: reuse `runner_lease` — it is the publish lease and a second meaning on one row is the SES-45 defect. Capacity lives in `runner_settings.test_slot_capacity` (1 on NANO; John moves it without a migration, pattern:2). Grant only on `db_health_level() = 'green'`, the ticket's word; amber waits.
4. **Expiry = 10 minutes without a heartbeat**, the publish lease's TTL, so the two ledger rows share one number. The holder beats every 60 s while the suite runs (`withTestSlot`), so a suite of any length holds; only a dead process expires.
5. **The rule lives in `run-all.js` and `verifier.js`, not in the runbook.** A credentialed suite run takes a slot by itself, wherever it is launched from (step 7 baseline, 7a verifier, an attended `node tests/regression/run-all.js`, CI with secrets) — "never runs a suite outside a slot" becomes a property of the command, not a sentence a cycle must remember. The verifier acquires BEFORE spawning so the 20-minute gate timeout is never spent waiting, and hands the child `DEEPBENCH_TEST_SLOT=held` so the inner `run-all.js` does not queue behind its parent (deadlock). agt-116's stub suites get `off`.
6. **Max wait 60 min = `db-pressure.js` `DEFAULT_MAX_MINUTES`**, then exit 2 as a transport not-run (AGT-116's vocabulary) — the gate reads it red, never a false approve.
7. **"built, waiting for a test slot"** is written by the slot module to `runner_cycles.last_step` through the existing `cycle-heartbeat.js` export whenever `DEEPBENCH_CYCLE_ID` is present (the verifier passes `--cycle-id`), and `ticket_matrix.lane_status` reads it structurally from `test_slots` joined to the open cycle (pattern:99). The step-7 baseline run has no cycle id on its command line (a runbook edit I chose not to spend bytes on), so a baseline wait shows on the `test_slots` row as `hostname:pid` only.
8. **Lane stamps are normalized, not listed.** `check-routine-prompt.js` replaces `DEEPBENCH-RUNNER-AUTOMATED-trig_[A-Za-z0-9]{20,}` with the canonical id on both sides for `runner` only; the AGT-102 placeholder (`<routine id>`) never matches, so that defect stays detected. The three ids are still recorded — in `sync-routine-models.js ROUTINES` and the prompt doc's ids table — by the attended session once they exist.
9. **Runbook bytes.** Net edit ≤ +48 B against 64 B of room: header tail −17, `eight`→`nine` −1, one 66-byte ladder line. Line 127 (the SES-298/302 archive pointer, ~200 B, pinned by no test) is the reserve if the concurrent step-7/7a directive edit eats the room.

## 4. What this variant leaves out (named, not hidden)

- **The step-7 baseline wait is not attributed to a ticket** in the matrix (see 3.7). A 33-byte `DEEPBENCH_CYCLE_ID=<your cycle id>` prefix on runbook line 2915 fixes it once the runbook has room.
- **No register row** (M6-15) and no `RULES-SNAPSHOT.md` re-export — `max_lanes` and `test_slot_capacity` are settings, not rules; file a register row if the class-understanding loop asks for one.
- **`hard_stop` is missing from the runbook ladder and from ses-297 `REASONS`** — pre-existing since 09-27; the attended session files it (evidence: `pg_get_functiondef` shows the branch; runner-cycle.md:133 says eight).
- **Fixture collisions between parallel cycles (SES-382)** are reduced by capacity 1 (one suite at a time) but not fixed: a suite may still collide with a lane that is mid-migration.
- **CI's credentialed regression job queues too** — that is the ask; a CI run may take up to 60 min longer under load.
- **A lane's abort-path branch name** `session/cycle-<UTC-yyyymmdd-hhmm>` can collide when two lanes boot in the same minute and both abort; the push of a session branch is the lost-claim path only.
- **`WebSearch` in the routines' `allowed_tools`** stays John's switch (routine-prompt.md).
- **Throughput proof.** Today `pickable_count` = 0, so "throughput up vs 1 lane" is measurable only once the board has buildable work; measure ships/24h against the 33 recorded here.
