## 3. The variant chosen, and what it does not do

One function, `effective_need_score(uuid)`, called from the four readers in place of the raw column
(pattern:14 one shared core, pattern:17 extend the structure, pattern:163 one change every home).
In `prime_directive_queue()` the splice is the `buildable` projection alone: `bu.need_score` keeps
its name, so both lane sorts and lane (c)'s gate pick up the lifted score with zero further edits.

Alternatives weighed and set aside:
- **A generated column / trigger that writes the lifted score into `need_score`.** Rejected: it
  would overwrite Victoria's grade, the one value `apply_requirement_verdict()` owns (pattern:10),
  and AGT-280's trigger refuses other writers.
- **Only `pick_exclusions()` + the sort.** Rejected: the ticket says "counts toward the project's
  ten", which is `countable_tickets_per_project()`; and `drain_epic_next()` leads with the same key
  by design ("that agreement is the property this pair of functions exists to hold").
- **Transitive inheritance (grandparent to child).** Not asked; the ticket says "that parent's
  score". A recursive CTE would also need a cycle guard. Filed nowhere: it is residue the closing
  scope can absorb if a chain ever shows it.

What it does not do: it does not move the child into the parent's project (decision 11's "moves
into the same project" is Victoria's move door, AGT-480, not the pick); it does not change the
exclusion sentence; it does not touch PARKED; it does not add an index on `blocked_by` (the
correlated subquery runs over ~1k rows per call, well inside the pick's budget - revisit if the
queue's latency is ever measured, pattern:67).

## 5. The Designer's calls (JOHN-0925-DESIGNER-DECIDES; each reversible by one migration)

1. **One level.** "The higher of its own score and that parent's score" - the ticket's words
   (pattern:90). Transitive is a separate decision if a chain ever needs it.
2. **Which parents lend.** Only an `open`/`partial` waiting ticket whose epic's project is
   `executing` (decision 11: "a parent in an active project"). A done, delivered or removed parent
   is not waiting; a paused project's parent must not elevate work in an executing one.
3. **An unscored blocker inherits.** `GREATEST` skips NULLs, so own NULL + parent 5 = 5. AGT-427's
   "NULL is not 0" is kept for a ticket with no scored parent: both NULL stays NULL and still reads
   `not yet scored (waits for Victoria)`. This is what unblocks the Victoria Fill chains the moment
   Victoria grades the head of each.
4. **The exclusion sentence keeps the own score; PARKED stays its own verdict.** `need_score 1 is
   below 3` is only reachable when the effective score is below 3 too, so it is never false; and
   `PARKED (0)` is a written Victoria verdict with its own exclusion in `countable_tickets_per_project()`
   (P5) - widening it is a John-visible rule change, not this ticket.
5. **`drain_epic_next()` takes the key too.** One change, every home (pattern:163); the two
   functions' first key must agree or the drain lane and the drain pick disagree about the same
   member.
