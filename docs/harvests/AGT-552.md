## 2. The call: where a role prompt renders (JOHN-0925-DESIGNER-DECIDES, reversible)

**Home = `identity` when the bundle holds an identity-type Skill, else the FIRST `behavior`-type Skill; claimed once per bundle.**

- Identity first: §19w R1 maps a role prompt to an Identity Skill; `buildLabel()` renders the identity section as `ROLE & IDENTITY` (`db-assembly.js:679`); `agent-bundle.js:36-37` already describes the identity branch as the role prompts' home; `SKILL_ORDER` (`:101`) puts identity (2) before behavior (3) and `sections.sort` at `:525` fixes the rendered order, so the role prompt stays early in the prompt.
- Else behavior: michelle's shape (two behavior Skills, no identity Skill) would otherwise render her role prompt 0 times -- the other failure direction the ticket forbids ("no section the agent is entitled to is dropped").
- Once per bundle, not once per branch: with two Skills of the home type both branches would still push it (michelle today: 2, both in `behavior`). A `roleClaimed` flag inside `buildSections()` makes the second caller of the home type get `[]`.
- Intent gating: `traits.intent_allowlist` can skip a Skill before the branch runs (`:209-213`). Live: 47 identity/behavior Skills, 2 gated (`ci-identity`, `ci-behavior`), both carrying the identical list `["ci-answer-intent","ci-answer-display-intent","ci-submission-ack-intent","ci-resolution-ack-intent"]`. An intent that gates out the identity Skill gates out the behavior Skill too, so `rolePromptHome()` reading the un-gated list cannot strand a role prompt on any live data. Limit, named: an identity Skill gated out while a behavior Skill passes would drop the role prompts on that intent; no such pair exists.

## 3. Alternatives rejected

1. **Post-loop placement** (build sections without role prompts, then prepend them to the identity-else-behavior section before the sort at `:525`): equally deterministic, but it reorders identity content (today: agents card, role prompts, objective, method) and so changes bytes for every agent with an identity Skill and a role prompt. Rejected on pattern:3 (stable output) -- the chosen form keeps every current section byte-identical except for the removed repeats.
2. **Gate-aware home** (hoist the `intent_allowlist` predicate into a pure function read by both the loop and `rolePromptHome()`): correct under the edge in §2, but zero live exposure and three more edit sites in a file four rules bind. Rejected on pattern:67 (an extra element must justify itself against an existing bound); the limit is named in the kickoff instead.
3. **Delete the behavior push only**: smallest diff, but drops michelle's role prompt entirely (behavior-only bundle). Rejected -- the ticket's both-directions QA would go red on the drop.
4. **Amend `docs/ARCHITECTURE.md` §19w:3029** ("role prompts rendered twice") as a 4th file: refused by the bare 3-file cap; that line is a dated 2026-10-06 discovery measurement and stays as history. Not a cap case: the build is complete in 3 files.
