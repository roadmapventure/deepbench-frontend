## 4. Design detail that did not fit the kickoff

- **Why the migration keeps the name `agt138_researcher_route`.** `up_name` is
  `runner_migration_downs`' unique key and the join key for the orphan query. A migration named
  `agt184_*` would move the watermark and leave `agt138_researcher_route` orphaned forever, so the
  repair would not be observable by the very check that finds it. Re-capturing under the original
  name uses the function's own `on conflict (up_name) do update`, which refreshes
  `captured_by_cycle`/`captured_at` to this cycle and writes a fresh `runner_before_images` row —
  §19v satisfied, and the classification stays `refused` because `public.finding_routes` still exists.
- **Why the insert is safe to re-apply.** PK `(source, finding_type)` and
  `on conflict (source, finding_type) do nothing`, so against the live row it writes nothing. Its
  value is the `schema_migrations` row `apply_migration` records alongside it.
- **Why `cycleDowns` defaults to `[]` rather than unknown.** `decide()` already defaults `downs`,
  `migrations` and `cycles` to `[]`; the fail-closed direction is kept where it belongs, at the read —
  `main()` `fail(2)`s on a REST error rather than deciding on a partial picture. A permissive default
  is unreachable in production because `main()` always supplies the value, and it keeps the five
  baseline-green files (which never pass the key) green. Their code-only fixtures still returning
  `revert-and-card` is itself one leg of the QA triple.
- **Honest limit.** The sensor is the captured down. A cycle that writes DML over PostgREST *and*
  captures nothing leaves no trace for either mechanism; only the writer-side guardrail reaches that
  case, which is why Task 4 files it rather than dropping it.
