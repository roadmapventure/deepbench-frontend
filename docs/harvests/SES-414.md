## Design choices, and what was rejected

1. **The final-day predicate is the Chicago wall clock minus one hour being a Thursday.** `P` := `extract(dow FROM (now() AT TIME ZONE 'America/Chicago') - interval '1 hour') = 4`. It is true from Thursday 01:00 through Friday 00:59:59 local, which is exactly 24 real hours every week, because US DST changes fall on Sundays. Rejected: `week_day_index = 7`. The gate's week counts 86,400-second days from Friday 01:00, so on DST weeks day 7 starts an hour off. Measured (SQL and the JS oracle agree at 12 instants):
   - Thu 2026-11-05 00:30 CST is day 7 but not the final 24h, so day-7 logic would allow 85–90 one hour early (fail-open).
   - Thu 2027-03-18 01:30 CDT is final but still day 6. With `P`, the day-6 pace line (85.71) still refuses 85.71–90 for that one hour. That is fail-closed and is M5-16's own calendar, noted below, not changed.
2. **The resolver and step 3 (a) are in the build** (see above); without them the ticket ships a no-op.
3. **One predicate text in two functions, no helper function.** A `runner_final_day(ts)` helper would be one home, but it adds an object with its own grants, COMMENT and down. The duplication is guarded three ways: the migration's post-condition requires `P` byte-identical in both `prosrc`; the §6 QA exercises both functions at the same simulated instants; and `ses-297`'s live arm asserts `resolve_day_token_cap(NULL).rest_pct === detail.wall_pct` on every run.
4. **The column lives on `runner_budget`, `integer NOT NULL DEFAULT 90`**, beside `weekly_rest_pct` (the ticket names it). A new month's row takes the default, so the rule is on by default (Dev Flags On By Default); John owns the number.
5. **Detail keys.** `wall_pct` is the number graded; `wall_stop` is the column that supplied it (`final_day_rest_pct`|`weekly_rest_pct`), which is "detail names which stop applied"; `final_day_rest_pct` is reported like `weekly_rest_pct`. With no budget row all three are NULL, and the wall stays NULL-safe, so `no_budget_row` still wins.
6. **One migration, capture names the table, expected class `refused`** (2 captured, 1 refusal), the `ses389_meter_stale_gate` precedent. Rejected: splitting the ALTER from the function changes. One push is one red range, so a range containing the refused ALTER is card-only either way.
7. **QA simulates the clock.** `now()` cannot be moved, so the §6 block re-creates both live functions as `pg_temp` copies with `now()` replaced by an instant, inside a transaction that raises. The fixture reading's `taken_at` is `greatest(now(), t) + 1 min`, so it is always the newest and never `meter_stale`, and `scheduler_on` is forced true. Static calls re-plan correctly after each `CREATE OR REPLACE`: results differ per instant, measured.
8. **Runbook edits are byte-budgeted:** +202 bytes to 380,911 (< 381,000 for `agt-79`), no stamp (5 of 5, the SES-400/SES-410 precedent). The item-3 sentence sits after the B35 citation line, which stays unique and keeps its retirement word (`ses-400` green). Step 3's three `≥ weekly_rest_pct` become `≥ rest_pct`, so the resolver's number is the one the cycle checks.
9. **`ses-297`.** `finalDay` joins the clock-only calendar, with three new fixed instants including the DST discriminator. The oracle grades the wall on the stop in force, the live arm asserts the new detail keys, and the resolver must agree. New clause `the-final-day-stop-is-in-refusal-3` requires `final_day_rest_pct` between refusal markers 3 and 4, plus `detail.wall_stop`. Measured: it fails on today's runbook (exit 1, *lost clause*), passes on the edited copy, and its control defeats it.
10. **The Knowledge row** is named by the ticket, and `AGENT-ROW-AGREED-TICKET` needs a decision handle plus a full-row before-image. It is written last, after fetch/rebase, so its pin matches the pushed card (the SES-410 sequence).
11. **Model.** A migration on the production boot gate and the day-cap resolver, plus guarded docs under a byte ceiling, is judgment-dense, so it goes to the judgment lane (`claude-opus-5` while `judgment_model()` answers `fable_rest`, else `claude-fable-5-1`).

## Discoveries for The Development Manager (not filed by this design run)

1. **The ticket's "every place" list was assembled from memory and missed the two places that would have made the ship a no-op.** They are the resolver's `rest_wall_hit` (enforced by `run-project.js`) and runbook step 3 (a). This is the SES-410 miss in a new costume. The process gap: nothing derives "who reads this setting" mechanically. A sweep of `pg_proc.prosrc` plus a repo grep for the column name finds all of them in two queries, and it is cheap enough to be a design-step instrument (P10 - Tooling).
2. **M5-16's calendar drifts an hour on DST weeks.** `week_day_index` counts 86,400-second days from Friday 01:00, so from the Sunday change until Friday the pace line moves at 00:00 CST (fall) or 02:00 CDT (spring) local, not 01:00. It matches M5-16's literal "day 1 is the first 24 hours", so it may be intended. It is worth a John ruling only if he reads the week as local days.
3. **On this Windows machine several suites print `[PASS]` and exit non-zero on a libuv teardown assert** (`ses-280`, `export-governance-snapshot.js`). A baseline or gate that reads exit codes alone misreports them.
