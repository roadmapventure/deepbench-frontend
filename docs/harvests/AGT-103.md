## 3. Shape, and why

**One anchor, replaced in place.** The 1b/9b builders built each new body by taking the live `pg_get_functiondef` and replacing one anchor, asserting it occurs once. The same here: the single `SELECT b.epic_id INTO v_epic … 'AGT-86'` line becomes a name-resolved lookup over `epics` JOIN `projects` with a count guard. Resolved by name, not by uuid, because the uuid is a live fact the database already holds (pattern:2, pattern:93) and John's rule is worded as a name. The guard is `count(*) <> 1` rather than `STRICT` so the message names the count and the ticket ("need exactly one (AGT-103)"), which is what "failing loud" means here.

**Where the RAISE sits.** The anchor lives inside `IF v_n > 0` in step 3, after `record_decision()` and the counter bump. That is fine: an unhandled PL/pgSQL exception aborts the calling statement, and over PostgREST a call is one transaction, so the decision row and the counter update roll back with it. The harvest notes the alternative — resolving the home in step 1 before any write — and rejects it: it would refuse a review that files no ticket when the epic is missing, which the ticket did not ask for, and it would change the refusal text a `carry`-without-reason probe reads, breaking the write-proof probe shape 9b established.

**Grants.** `.claude/rules/supabase-column-grants.md` (SES-315): `CREATE OR REPLACE` keeps the existing ACL, but the migration re-states the revoke-by-name and the `service_role` grant and asserts both directions in its `DO`, as 9b did — "never trust the success flag".

**Down first.** `capture_migration_down(cycle, 'agt103_auditor_home', [{function, public.apply_audit_review(uuid, text, text, jsonb)}])` before `apply_migration`. The 9b capture (`runner_migration_downs.up_name = 'agt86_s9b_checklist_edits'`, `auto-downable`, 13,814 bytes) contains `'AGT-86'` and not `checklist_edits` — proof by example that the capture reads prior state. AGT-103's capture will therefore contain both `'AGT-86'` and `checklist_edits`, and never `Auditor Enhancements`; arm D asserts the first and the last.

## 4. Why the Node test is shaped as it is

PostgREST cannot read `pg_get_functiondef` (SES-275, SES-182e), and the only way to reach the new line is to file a ticket — a write. So:

- The **behavioural proof** is the migration's own trailing `DO`, in a sub-block that inserts its own fixture finding (the ledger has 0 open/carried rows, so coverage refuses nothing — 9b's §16.10 lesson), files ONE root-cause ticket, asserts its `epic_id` and its project slug, and rolls back via `RAISE 'AGT103_OK'`. Sub-block B renames the epic inside a rolled-back block and proves the loud refusal.
- The **Node arms** read only: M reads the migration ledger through `rpc/migrations_in_range` (a migration is recorded only after its `DO` passed, so "it is in the ledger" carries the `DO`'s proof); D reads `runner_migration_downs`; C re-runs the write-proof probe and the anon refusal and re-reads counts. Each is red on the unchanged tree (no such migration, no such down row).
- Rejected: asserting "every `audit-review` ticket filed after the ship is in the epic" — vacuous until the next review runs (pattern:162, a check grades the change, not the live world).
