## How attribution is established — the decision

Two sources, both already in the platform, neither needing a new field:

1. **Verifier → Designer (`verdict block attributable to the kickoff`)**: the verifier's own prepended
   kickoff finding. It is the FIRST clause of `reasoning`, before any red gate, and the block is forced by
   the kickoff check itself, so "attributable to the kickoff" is not a judgment the session makes — it is the
   verifier's stated cause. A red gate with no such opening is the Builder's ship and NOT this finding; the
   runbook paragraph says so in words so a session cannot widen it.
2. **Builder → Designer (`kickoff lacked a fact`)**: the Builder's `deviations` entries. `SES-376`'s rule
   lists what a kickoff must carry (file list, exact strings, commands, QA numbers); a deviation saying the
   build had to read the harvest, re-measure or re-derive one of those is the session's read, the same way
   rule (c) at step 5 is the session's read of the driver's exit 2.

Rejected: (a) a new `attribution` payload key in `verifier.js` — it would spend the third file slot on
restating a string the code already prepends, and the regression file can pin those strings without editing
the script (`ses-378g` (c) drives `kickoffCapFinding` / `kickoffLaneFinding` and compares to the runbook's
words); (b) a `runner_verdicts` column — SES-122b/SES-345 precedent says no column without a join need, and
the agt-67 shape guard compares the two lanes' key sets; (c) having `verifier.js` write the finding itself —
its founding property is verdict-only, one row; (d) a schema key on `vf-verdict-intent` — a Skill row of an
active governance agent, John's word, and the lane it would serve is not run.
