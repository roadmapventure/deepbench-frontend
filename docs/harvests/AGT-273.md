Three non-cycle holders, capacity 1: CI holds the only slot and two more CI runs sit ahead of any
lane, because `v_held` counts every holder and `v_pos` every waiting row regardless of origin. That
is the ticket's "one CI run can starve a build with no rule saying it may", observed live.

**Decision (JOHN-0925-DESIGNER-DECIDES): CI holders draw their own reserved pool, not the lane
pool.** The ticket asks for that call to be decided and recorded, not necessarily built, and its
three regression criteria are all ladder criteria. Building it needs a second capacity column, a
per-pool `v_held` and a per-pool `v_pos`, plus its own QA — roughly 1.5 KB of kickoff against the
8,192-byte cap (pattern:168), so task 6 files it as its own **P10 - Tooling** row citing these three
rows (pattern:65, pattern:120). The discriminator for that row: a lane acquire is granted while three
`cycle_id` NULL rows are ahead of it.

The pool test must be structural — `cycle_id IS NULL`. `holderId()` (`scripts/test-slot.js:46`) is
`env.DEEPBENCH_CYCLE_ID ?? "<hostname>:<pid>"`, and the live hostname is `vm`, so the ticket's
"holder `runnervm*`" pattern matches nothing today (pattern:99).

## Alternatives considered

1. **Put the whole ladder, green included, in one jsonb.** Rejected: `test_slot_capacity` is John's
   knob and its one home (pattern:14/15). Green stays in the column, the ladder holds only the
   non-green rungs, and the allowance takes `LEAST(column, rung)` so the ladder can only ever narrow.
2. **Amend `runner_should_boot()` in the same cycle** (the v7.0.730 design did). Rejected: the ticket
   is about the test-slot gate. `governance_rules` `M6-14` names `runner_should_boot()` and
   `drain_chain_gate()` and says nothing about slots, so nothing in the register goes stale from a
   test-slot-only change, and `ses-411-rule-vs-function.test.mjs` keeps its binding untouched. The
   boot gate's own amber-stops-everything behaviour is a separate item.
3. **Revoke a held slot when health drops.** Rejected: the lease is 10 minutes and expires on its
   own; killing a suite mid-run throws away the work and would make a suite's result depend on a
   reading that arrived after it started. Stated in the kickoff as what this does not do.
4. **Widening the return signature** of `test_slot_acquire` with a `pool` column. Rejected: a changed
   `RETURNS TABLE` cannot be `CREATE OR REPLACE`d, which would force a DROP and re-grant
   (`.claude/rules/supabase-function-signature.md`). Identity args and the six return columns stay
   byte-identical, so the replace is a true replace and no overload can appear.

## Grant surface (read, not assumed)

`information_schema.role_table_grants` for `public.runner_settings`: only `postgres` and
`service_role`, all privileges; `anon` and `authenticated` hold **nothing**, and there is no column
list. A new column therefore needs no grant (`.claude/rules/supabase-column-grants.md`'s fail-closed
note does not bite here). A new *function* does default open, so `test_slot_allowance()` revokes from
`PUBLIC, anon, authenticated` by name and grants `service_role`, with the trailing `DO` asserting
both directions, exactly as `docs/design/agt-265-lanes-test-slot.sql:433-438` does.

`capture_migration_down(p_cycle_id uuid, p_up_name text, p_objects jsonb)` takes a non-empty JSON
array of `{kind, identity}`; `record_decision` takes `(p_cycle_id, p_session_name, p_kind,
p_backlog_id, p_summary, p_reasoning, p_ladder_work_class)`, and `runner_decisions` has no CHECK on
`kind` — `concurrency` is an existing kind (43 rows). `runner_before_images` columns are
`(id, created_at, cycle_id, table_name, pk_value, row_data, session_name, decision_id)` with
`CHECK ((cycle_id IS NOT NULL) <> (session_name IS NOT NULL))`.
