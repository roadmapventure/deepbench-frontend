## §Why a scratch re-build of the Builder turn, and why it is write-free by construction

Options weighed:

1. **Replay the Builder turn read-only** (AGT-148's shape). Cannot reach the turn's contract — the Builder's answer is a pushed tree; a read-only Builder produces nothing scorable. Rejected.
2. **Full cycle re-run** (design + build + verify). 34–76 minutes per cycle and pushes, ledger rows, board writes that cannot be refused without breaking the cycle. Rejected, as AGT-148 §Why already found.
3. **Builder turn in a detached scratch worktree at the ship's parent commit, scored by the runner** (chosen). The kickoff exists at `<push_sha>^` for every real ship checked (AGT-148, 144, 143), and each ship's `git diff-tree` file list equals the kickoff's named files exactly (3 = 3 in all three) — so "files within the kickoff" is a real property of real ships, and the same rule grades the candidate. The scratch has no `.env.local`, the child `claude` process has `SUPABASE_*` deleted from its env, and `--allowedTools` names no `git push`, no `agent-log.js`, no `cycle-heartbeat.js`, no MCP: the Builder's own method says "creds from runner_secrets by name" — with no key it cannot read them, and with no push tool it cannot ship. Writes are unreachable, not forbidden (pattern 10, 19). `git add`/`git commit` are allowed because the Builder's method commits before it pushes; a commit in a detached scratch worktree removed in `finally` is a file on disk and nothing else. `node_modules` is a junction to the repo's own, so `npm run build` and the suite run at all; nothing is installed.

Scoring is the runner's, never the agent's word (pattern 9, 162): the changed-file set is read from git, the gates are `verifier.js --dry-run` (line 438: writes nothing, needs no credentials) run by `model-trial.js` after the turn, and `passed` needs every required key of `bd-build-intent`, a non-empty changed set inside `kickoffFiles(kickoff)`, and exit 0. The Builder's `outcome` will not be `pushed` (the push is refused) and `push_sha` will be empty; the contract asks for the keys' presence, not for a sha — the kickoff says so, so a Builder that stops honestly at the refused push still scores on its build. Live tests that need a service key go `notRun` in the scratch on the candidate's side while the real ship had them; that makes the candidate's bar slightly softer on the live parts and identical on the offline suite, build and hygiene. Stated here; not corrected, because correcting it means handing a trial a key (AGT-148 took the same stance).

Base commit: `<push_sha>^` rather than AGT-148's `--before=started_at`. The kickoff and the ship are separate commits by the same cycle (kickoff at step 6, ship at step 7), and the parent of the ship is exactly the tree the real Builder started from; `--before=started_at` can land on an earlier commit when a concurrent session pushed between the two. The design entry keeps its `--before` base — its kickoff does not yet exist at its own start.
