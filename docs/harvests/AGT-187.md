## 2. The choice the ticket left open, and why it lands where it does

Three options were on the table.

1. **Return the refusal to the Designer.** The checker is a CLI; it cannot return anything to anyone.
   What it CAN do is stop addressing its caller. Taken, as task 1.
2. **Record who supplied the line.** `--check-kickoff` cannot write a row: it runs ahead of the
   credential check by deliberate, documented design (`scripts/verifier.js:2246-2256`) so that step 6
   can run it before a cycle has anything to authorise. So the attestation has to be computable from
   the file plus what the Designer returned. Step 6 statement 3 already says "write the returned
   `kickoff_markdown` to the returned `kickoff_path`" — so "who supplied the line" IS "do the file's
   bytes equal the answer's `kickoff_markdown`". Taken, as task 2, through the `--answer=<path>`
   convention this platform already uses (`rank-backlog.js`, `ticket-owner.js`, `market-agent.js`,
   `audit-review.js`) — pattern:17, not a new mechanism.
3. **Move the re-run obligation into the runbook.** Already there, and already violated: step 6
   statement 3 calls exit 1 a NAMED DEVIATION, forbids writing the draft as the kickoff, and names the
   `"no_lanes":true` re-assembly. Re-wording it a fourth time is the guard pattern:10 forbids.

What this does NOT do, stated plainly: `--answer` is optional this cycle, so a caller that omits it
still gets exit 0 — but that green now says `attested: false` and names what it graded, so no cycle can
cite it as proof of a Designer declaration (pattern:34, honest absence). Making the flag REQUIRED is the
right end state and is deliberately not this ship: it would turn `ses-359`, `ses-376`, `ses-378h` and
`scripts/model-trial.js:201` red at once, and step 6 would have to pass the flag — which forces the
runbook edit ruled out below. File the follow-on as its own row.
