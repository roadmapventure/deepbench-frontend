## 3. Decisions D1–D7 — the reasons

- **D1 — two slices.** The full ticket touches six files: `src/components/ConnectAgentPopup.jsx` (new), `src/screens/PersonnelScreen.jsx`, `tests/regression/agt-334-connect-popup.test.mjs` (new), `src/screens/ConnectScreen.jsx`, `tests/regression/agt-165-connect-page.test.mjs`, and the AGT-334 test again for the redirect arm. Cap is 3 (pattern:72 — not mine to waive). Variants: (i) make `/connect` the redirect first — rejected: the redirect would land on a personnel file with no popup, a broken interim state. (ii) delete ConnectScreen.jsx and route `/connect` in `main.jsx` — rejected: a file deletion needs John's approval on record (memory: file merge/deletion approval) and gains nothing over a thin redirect. (iii) **chosen:** slice 1 ships the buttons and popup, fully usable; `/connect` keeps its old page one cycle longer (honest interim, pattern:34). AGT-334 stays `partial` (the AGT-332 precedent, pattern:95 — no refile).
- **D2 — CopyBlock copied, not imported.** Importing it would need `export` added to ConnectScreen.jsx — a 4th file. Slice 2 deletes the ConnectScreen copy, so the END state has one `CopyBlock` (pattern:14). The duplicate lives exactly one cycle and is named in the STOP LINE.
- **D3 — `setActiveTab("training")`.** The Roster button navigates to `/bench/<id>?tab=training`; inside PersonnelScreen `activeTab` is seeded from `?tab=` only at mount, so `navigate()` to the same path would not switch tabs. Same destination (the Training tab), the mechanism that works on this screen (pattern:8).
- **D4 — `?connect=1` + `isPrivateAgent` guard; ✕ and Escape.** The redirect target slice 2 needs; the guard keeps a hand-typed `?connect=1` on a non-private agent inert. Dismissal follows AccessGateModal's explicit rule (no backdrop click, lines 104–106) — the one popup pattern with a John decision on record.
- **D5 — address as a prop, built once in PersonnelScreen.** Session finding: AGT-338 later adds a team address beside the agent's own; a popup that takes `address` (and later `teamAddress`) makes that a one-line change. The template `${window.location.origin}/api/mcp/${agent.id}` has one home (pattern:14, pattern:53). Rule #1: no agent id typed anywhere (§19e).
- **D6 — `CONNECT_TOOLS` is data.** John: "more tools such as Gemini and Grok will be added later, so the tool list is data" (ticket). Pills, default selection and steps all derive from the array (pattern:2).
- **D7 — mobile placement.** John: "put the same two buttons in the mobile persona block under the same rule". The block is centered; a centered row directly under the quip (above the 3-stat grid) keeps the stat grid intact. One `BadgeActions` component feeds both sites (pattern:14, pattern:59 — mirrored in the same pass).

## 8c. PersonnelScreen inserts — `BadgeActions` and I1–I3, verbatim

```jsx
// FEATURE: AGT-334 — the ID Badge / persona actions. One component, two mounts (desktop card, mobile
// persona block). "+ Add Training" on trainable agents (the Training tab, the Roster button's
// destination); "Connect <first name> to AI" on private agents only (isPrivateAgent reads the agent's
// own row — Rule #1). Styles: STYLE-GUIDE §7 Primary CTA and Secondary/ghost, sized for the card.
function BadgeActions({ agent, onAddTraining, onConnect, style }) {
  const firstName = agent.name.split(" ")[0];
  return (
    <div style={style}>
      {agent.trainable && (
        <button onClick={onAddTraining} style={{background:`linear-gradient(135deg, ${T.brass}, ${T.brassDeep})`,border:"none",color:T.navy,padding:"6px 12px",fontFamily:display,fontSize:12,fontWeight:700,cursor:"pointer"}}>+ Add Training</button>
      )}
      {isPrivateAgent(agent) && (
        <button onClick={onConnect} style={{background:"transparent",border:`1px solid ${T.line}`,color:T.mutedDeep,padding:"5px 12px",fontFamily:body,fontSize:12,cursor:"pointer"}}>{`Connect ${firstName} to AI`}</button>
      )}
    </div>
  );
}
```
