## 2. Which layer — and why not the handler

`git grep -n "await assemblePrompt({"` returns 18 non-doc call sites. `agent-bundle.js:179` is the
only one that omits `capability_slug`; `api/plan.js:153`/`:286`, `api/capabilities/execute.js:1849`
and all 14 `scripts/*` sites pass one. So:

- Deduping in **`db-assembly.js`'s agent-wide branch** fixes the one path that duplicates, for the
  bundle and for any future agent-wide caller, at the layer that produced the duplicate rows
  (pattern:8 narrowest layer that actually works; pattern:14 one shared core).
- Deduping in **`agent-bundle.js`'s `sections` map** would hide the symptom while the prompt path
  kept assembling 44 rows, and would not hold for the next agent-wide caller. Rejected.
- Deduping **before `buildSections()` (`:882`) for every path** would touch every capability-scoped
  assembly on the platform for no measured gain. Rejected.

## 3. Why the key is `slug` alone

`level`/`skill_level` are consumed only for the fired Intent (`:336`), so collapsing rows that differ
only in `level` could in principle drop a declared execution depth. Measured: of the 39 repeated
(agent, skill) pairs, **0** carry more than one distinct `level`. A `slug` + `level` key would
therefore buy nothing today and would silently keep repeating whenever a level differs. First
occurrence wins so array order, `display_order` and the pinned-rows-first contract
`mergePinnedSkills()` relies on are all unchanged; the pins merge runs later (`:844`) and filters by
`pinnedSlugs`, so the two are independent. Returning the same array reference when nothing was
duplicated keeps every non-repeating agent byte-identical — the contract `mergePinnedSkills()`
already states for itself.

## 4. One consequence, stated in the kickoff

The dedupe sits before `buildSignatureConfig()` (`:829`), so an **agent-wide** assembly's
`signature_config.assembled_skill_slugs` now lists each slug once. No production caller logs an
agent-wide signature — `agent-bundle.js:229` passes its own `callFacts` and no `signature_config`,
and every signature-logging caller is capability-scoped — so no live pattern match moves
(`.claude/rules/ai-pattern-signature.md`).

## 5. The residue, and why it is not this ticket

Role prompts are pushed into the `identity` section (`:288-291`) **and** the `behavior` section
(`:300-302`). So one role prompt renders **2** times in a bundle for an agent holding **one**
capability — before and after this build, independent of capability count. That also violates
`.claude/rules/agent-data-visibility.md:16`, but it is a different defect (origin AA-66's additive
identity assembly) whose fix changes every assembled prompt on the platform, capability-scoped calls
included. AGT-429's title and finding are the per-capability repeat; the overlap is filed as its own
row with the measurement above rather than patched inline (pattern:65, pattern:96), and AGT-429's own
criterion is never refiled under a new id (pattern:95).

No `docs/ARCHITECTURE.md` amendment is owed: the code is being brought into line with a rule the repo
already states. Nothing live contradicts a locked section (pattern:94 does not fire).

  ```js
  export function dedupeSkillProfilesBySlug(rows) {
    const a = Array.isArray(rows) ? rows : [], seen = new Set(), kept = [];
    for (const sp of a) {
      if (sp?.slug && seen.has(sp.slug)) continue;
      if (sp?.slug) seen.add(sp.slug);
      kept.push(sp);
    }
    return kept.length === a.length ? rows : kept;
  }
  ```
