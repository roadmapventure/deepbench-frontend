## 3. The scoping decision, and what was rejected

The ticket asks for two things. One — apply both migrations — cannot be done by this cycle at all: AGT-289
(no build lane can apply DDL), AGT-548 (committing DDL times out at 60s writing nothing), this cycle is
unattended, and §2(a) means one of the two would be an irreversible unattended DDL change. The other — make
the ledger-orphan read a ship-gate hard stop instead of one test arm — is code, fits two files, and is what
the kickoff builds. `AGT-562` stays open; nothing claims it closed (pattern:95, pattern:132).

**Rejected: a whole-ledger orphan gate.** It is the literal reading of the ticket and it is wrong. Two
orphans stand right now and one cannot be cleared without an attended apply, so the gate would refuse every
ship on the platform from the commit that landed it — a second wedge with the same shape as the one the
ticket is about. `ciConclusionFinding`'s own header in `scripts/verifier.js` already argues this for CI:
"a CI read that could flip a gate would re-grade every ship on the platform at once, on a fact about
GitHub's schedulers rather than about the change." Orphans from other cycles are a fact about the platform's
history, not about this change (pattern:162).

**Rejected: a dated waiver list naming the two known orphans.** It would let the whole-ledger gate ship
without wedging, but it bounds the problem instead of eliminating it (pattern:1) and the list is a
hand-maintained content judgment in the repo (pattern:11).

**Chosen: gate on the orphans THIS cycle captured; print the whole-ledger count always.** A down this cycle
captured with no applied up IS this ship being unfinished — the ticket's own sentence, read at the ship it
belongs to. It needs no waiver list, it fails closed for every future cycle, and it cannot wedge the
platform because a cycle that captured nothing is clear by construction. The whole-ledger count still gets
read and printed on every ship, so the two standing orphans become visible at every ship instead of in one
suite arm (pattern:33, pattern:34).

**Reuse, not a parallel mechanism.** `scripts/rollback-on-red.js` already exports `ledgerOrphansIn` (pure,
`known:false` when the downs are unreadable — the fail-closed reading this gate needs) and
`readDownsCapturedBy(base, key, cycleId)`. Nothing new is written for either half (pattern:17). And runbook
step 7a already passes `--cycle-id=` with credentials (`docs/runbooks/runner-cycle.md:3039`), so the gate
arms itself with no runbook edit — which also avoids the 381,000-byte ceiling on that file.
