## 2. Governing architecture

- §19v (self-building platform): the runbook is the source and the routine holds a copy (routine-prompt.md's convention, adopted by auditor-routine.md line 15); the Auditor's CODE layer asks deterministic questions as scripts (`audit-board.js`), so a byte comparison is code, never a model call (pattern:9, pattern:10).
- §19b: the script is a check, not a capability; no route, no capability row, no agent named in data (Rule #1: the finding names the routine id and the file, never an agent).
- §19k: no model call means no `ai_activity_log` row and no `SERVICE_CATALOG` slug — `shared/ai-patterns.js` stays untouched, as the ticket's own scope predicted.
- pattern:162: the check grades the copy against its source; it does not judge the live world beyond that.

## 3. Design decisions (with the alternatives not taken)

1. **One script, two modes.** `--prompt` compares a prompt text with the block; `--note --cycle` turns a builder's affirmative drift note into the same finding. Alternative: a second inline `node -e` in the runbook for the notes — rejected, it would be a second home of the finding shape (pattern:14).
2. **Same fingerprint for both routes.** Both modes emit the same two location homes (`routine/<id>/prompt`, `docs/runbooks/<file>`) and the same count-free governing fact, so a drift found by the auditor's own comparison and the same drift reported by a builder note are ONE ledger row; a note-mode finding carries `confidence: medium` because it is the builder's claim, unverified. `--routine` changes the id in location 1, so runner and auditor drifts are two rows (QA control).
3. **Normalisation: line endings AND trailing newlines.** The ticket says line endings only; a prompt written with a heredoc or `cat >` always ends in `\n` while the extracted block does not, so a strict rule would fire every Monday on a phantom. Trailing-newline stripping is the smallest widening that removes that false positive and nothing else; a single character elsewhere still fires (QA B).
4. **The builder-note filter is a regex over free prose,** because routine-prompt.md prescribes no wording and pushing new wording to the runner's live prompt is John's word (SES-355) — out of this slice. The filter: mentions the routine prompt, mentions drift, and does not carry one of the four measured "no drift" phrasings. False negatives are possible; the script side (slice 2 below) is the structural fix (pattern:10).
5. **Before-image by cycle_id, not session_name,** for the agt-86g arm F reason in §1.
6. **`[code]` on the new check** because scripts run it before the Auditor's judgment is called; the checklist's own sentence about `[code]` is amended in the same UPDATE so it stays true (a rule-two-wordings finding against itself would be embarrassing).
7. **Model: mechanical lane.** Every string, query and exit code is given in the kickoff; there is no judgment step (pattern:125 — a short run on the judgment lane would not be cheaper here because there is nothing to judge).
8. **No `--week` flag.** The step-3 merge takes the week from `$W`; a per-source week is unused, so the flag was dropped from the design when the kickoff needed bytes.
