## 2. The design and the four recorded calls (JOHN-0925-DESIGNER-DECIDES; all reversible)

**Call 1 — an empty related set at step 7 measures the FULL suite, with no `--full` knob.** A kickoff with no path footprint (no backticked repo path, no `tests/regression/...` line) is exactly the data-only case; the only set that can grade a change with no files is everything a Supabase write could flip. Deterministic (pattern:9, 18); no knob because nothing in either runbook would pass one (pattern:67). Cost: one per-file pass over the suite at step 7, only on such kickoffs. Why this does not collide with step 6's `kickoff-baseline-narrower` check: that check compares the kickoff block's `measured` (per-test lines) with the file's — and a kickoff whose block HAS per-test lines has them read as declared files by `declaredFiles()`'s `BARE_TEST` rule (measured on the fixture: `k-named.md` counted 4 declared), so its set is never empty and the full-suite branch never fires; a block without per-test lines has `measured: null` and is NOT GRADED there (the AGT-457 escape). The union the ticket's second sentence implies ("the paths the kickoff's own BASELINE block declares") is therefore ALREADY in the set — I prototyped it and it changed nothing, so it is not built.

**Call 2 — at 7a an empty `--related=` grades the set the baseline in force MEASURED.** Precedence is the verifier's own: the `--pre-build-baseline=` file (what step 7 measured, which includes the kickoff block's named tests per the point above), else the kickoff block. Coverage then holds by construction (graded ⊆ measured). The ticket's wording names the kickoff block; the pre-build file is the same closure measured by the cycle, credentialed, and is what the runbook hands — so it comes first. Never the full suite here: AGT-391's design is that 7a grades the related set, and a zero-file delivery's related set is what was measured for it.

**Call 3 — with no `--related=` the graded width is the whole suite.** This is the ticket's first Fix sentence mechanised on the grading side: a run that grades the full suite against a per-test baseline narrower than it is now exit 2 `baseline-narrower-than-graded-set` (cannot-run, no row, no streak cost) with a prose line naming the remedy, instead of a never-measured block. Measured harm it removes: verdict 2375cc65. Neither runbook path reaches this branch; it is the deviation path, and it now fails closed and loud (pattern:162, 165).

**Call 4 — the guard is arms G/H of `tests/regression/agt-451-pre-build-baseline.test.mjs`, not a new file.** Two reasons: (a) a test the build ADDS cannot be in a pre-build baseline, so the AGT-457 coverage check refuses the ship at 7a — AGT-529 (open) and hit by the previous cycle (57ffd54e, AA-169) today; a kickoff that knowingly walks into an open defect is not a design; (b) the AGT-451 file already holds the fixture tree, `offlineEnv()`/`credentialedEnv()`, `node()` and the verifier/script spawns the new arms need (pattern:17, 14). The STANDARDS §4 "named for the ticket it guards" clause is bent here on purpose and recorded; the file's line-1 stamp names AGT-572.

**Not built, and why:** the new-test face (a graded test absent from any pre-build measurement because the build created it) is AGT-529's — filed, open, named in the ticket as "the test-adding half". `AGT-537` (block cannot fit the cap) and `AGT-541` (no fence against a same-tree baseline) are adjacent and untouched.
