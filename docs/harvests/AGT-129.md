## The delivered_at correction — measured against the live schema

Timestamp columns present: `created_at, updated_at, claimed_at, revalidated_at, filed_at, cost_snapshot_at`. Status values live: open 579, done 267, delivered 44, partial 45, removal proposed 52, removed 13.
- Candidates for "shipped in the last 7 days", counted 2026-09-25:
  - `backlog_items.status in ('delivered','done') and updated_at >= now()-7d` → **28** rows (26 delivered, 2 done). No trigger maintains `updated_at` (only `backlog_done_requires_verdict` is on the table), so it is application-written — a re-touch of an old done row would over-include, which the judgment job tolerates.
  - `runner_decisions kind='ship'` by `decided_at` → 2 rows, both inside the 28. The other 26 (AGT-82…AGT-127, SES-418…SES-424) reached `delivered` this week with no ship decision this week — `runner_cycles` outcomes this week are `shipped` (47), never `delivered`, and `runner_cycles` has no `backlog_id` (it carries `item_id`/`backlog_item_id`).
  - `runner_verdicts` in 7 days: 38 rows, all `block`, 0 `approve` — verdict time would return zero shipped rows this week.
  So `updated_at` is the only column that returns this week's actual delivered set; the runbook line names it and the count.
- board-health's projection lists `delivered_at` for open/partial rows, which can never carry a ship time: the key is dropped and the description window becomes `filed_at` or `revalidated_at` in 14 days (57 of 629 open/partial rows today).

## Shape chosen and what it does not do

- `--task-file=<path>`, with `-` meaning stdin — the Unix convention (pattern:101, a standard practice, not homegrown), one flag rather than two. `--task=` stays byte-for-byte as it was (pattern:65, pattern:90): runner-cycle.md steps 4b/6/7 and this cycle's own assembly keep working and that runbook is not touched (ses-413d byte-pins it; the file was already 20 B off its pin before this ticket).
- Read synchronously with `fs.readFileSync(0)` for stdin — a TTY with no pipe would block, which is acceptable for an operator flag and is documented in the FLAGS line. Both flags together is an error rather than a precedence rule (pattern:3: no silent choice).
- `audit-cluster.js` gets a tiny exported `promptCall(task, {json})` so the seam is testable without credentials (pattern:14: both spawns call one builder). It feeds stdin (`--task-file=-`) rather than a second file, because the task file on disk holds `{capability, intent, task_context}`, not the bare `task_context`.
- `personal-agent.js`'s header sentence ("agent-prompt.js takes the task_context on the command line … which will not fit") becomes slightly stale. Left alone on purpose to stay inside the ticket (pattern:65); its design (records read in-process) still stands. Residue, not a ticket.
- No change to `api/prompt/db-assembly.js`: the script still assembles nothing (§19b); a 270 KB `task_context` renders through AI-44's TASK DETAILS exactly as the executor would.
