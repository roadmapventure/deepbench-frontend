## 3. Why three routines, not one and not five

- The ticket's own Fix line says "do the same for every routine whose live prompt carries the
  stop". A ticket closes only when every sentence in its own text is satisfied (pattern:95), so the
  auditor alone would not close it.
- Researcher and market are the urgent two: their runbooks say John pastes the block into the live
  routine. Pasted as they stand today, each would delete his own stop from a live routine -- a John
  rule removed by a mechanical paste (pattern:166). The weekly drift finding is only its sensor.
- The three share one byte-identical paragraph, so one literal, one helper and one test prove all
  three (pattern:163 -- one change, every home, one ship).
- `victoria-reorg` and `model-watch` run different wordings, and `model-watch`'s presupposes a
  schedule-gate paragraph that is also live-only. Each needs its own literal, and `model-watch`
  needs a call on whether the schedule gate enters the block. `AGT-517` is open and already owns
  that, so I reused it rather than duplicate it (pattern:65). After this ships, `AGT-517`'s
  remainder is those two blocks.

## 4. The needs-desktop ruling (D1)

The flag says no unattended cycle should pick the ticket up because the fix "needs an attended
session at the machine that can read and write the routine". Against the evidence:

- Every write in the kickoff is to a tracked file. No task writes a routine; the live routine
  already runs the stop.
- No task reads a routine either. P is in the tracked tree (13 files hold its closing sentence) and
  on the ledger's own finding rows, so the build never needs the routine as a source.
- Even the design-time read was taken from a cloud session with a read-only tool.

Ruling: `needs-desktop` is mis-set on `AGT-567`; an unattended cycle can build it. The same
reasoning applies to `AGT-517` (its Fix is also a paste into runbook blocks). It does not apply to
`AGT-263`, whose Fix is a push to the live runner routine -- that one is genuinely attended.

Nothing in the design edits a live routine's stored prompt, writes under `.claude/`, touches
`docs/runbooks/runner-cycle.md` (so `cycle-card.md`'s pinned hash is unaffected and no re-render is
needed), or merges `dev -> main`. `never_send` was empty; no task re-sends, re-routes or re-words a
refused action.
