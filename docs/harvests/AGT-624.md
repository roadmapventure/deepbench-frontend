## The rule, and why this shape

A ruled ask stands while every cycle that recorded its fingerprint did so at or before the newest answered ask's `asked_at`. One finding row from a cycle that ask had not seen re-opens it.

- The ticket's test compared "standing = any ruled ask" (0 new / 15 standing). That is a mute: it never re-files. The ticket's own Fix text asks for an evidence trigger, so the design keeps one.
- The count at the time of the ask is not stored anywhere except inside the question sentence. Parsing prose for a number was rejected; a column was rejected (D2). The count is re-derived from `runner_staff_findings.created_at` against the ask's `asked_at`, both of which already exist.
- `asked_at`, not `answered_at`, is the cut: the ruling answered the sentence as asked, and a sighting that landed between ask and answer was not in it.
- A second later row from an already-seen cycle does not re-open (the test's `cccc` arm) -- the bar counts distinct cycles, so the trigger does too.
- "A different detail" needs no code: `fingerprintFor()` hashes agent, kind and normalised detail, so a different detail is a different fingerprint with no prior ask.

## Decisions I made (reversible)

- D1 evidence derived, not stored. D2 no bump column: under D1 a standing fingerprint has had no new cycle, so a bump could only count re-runs of `--promote`, and the real count already lives in `runner_staff_findings` (pattern:93, pattern:67). The ticket's sentence "the recurrence bumps a count on the standing row" is therefore answered by decision, not by a column; if the Development Manager wants the column it is one migration and one UPDATE, a separate reversible change. D3 different detail = different fingerprint. D4 no cleanup of the 440 rows (they are the ruling history, and the newest per fingerprint is what the rule reads).
- `asksToFile()` is not changed and the unanswered read is not changed, because `tests/regression/agt-172-staff-watch-record-promote.test.mjs` pins both (three drives of the Set, and a regex on the read). The new set is unioned in by `promote()`. agt-172 also refuses the characters `asked_at=` anywhere in the source; the new read uses `order=asked_at.desc` and does not trip it.
- `order=asked_at.desc` on the new read so that, if PostgREST ever caps the page, the newest ask per fingerprint is the part that survives.
