**Surface by surface, read from the diffs:**

- **`SES-45` — check 14, the recreated-logic lint** — touched `scripts/check-session-docs.js`, which *is* one of the verifier's three gate scripts. But the check ships at **WARN** severity and `GATING_CHECKS` remains `{"9","10","11"}`, so the gate's blocking behaviour is unchanged — and the verifier's own `SELF_CERTIFYING_PATHS` test **refused it the auto-done bar** (`runner_verdicts`, `06:02:39Z`: *"this delivery changes scripts/check-session-docs.js -- the verification itself"*). It shipped `delivered` and still awaits John.
- **`SES-210` — a verdict card is retired by its own verdict** — changed `public.briefing_open_cards()` by migration, the **only** migration in the window, landing `06:49:36Z`, **eleven minutes before expiry**. This is the closest call in the record.

**Three things settle it:**

1. **Specificity governs over recency.** These are the same person's words from the same afternoon and must be read together rather than ranked by timestamp. A named, shaped, sequenced approval is the more specific instruction; John wrote it knowing the window was minutes from being declared.
2. **Clause 3's purpose was not engaged.** Its context is a *Sonnet-served* window — the guard exists so a lower-capability serving model does not touch authority surfaces unattended. **All three ships ran on Opus 5**, the standing configuration, after John personally reopened the scheduler at `02:45Z` with exactly these approvals at the head of the queue. 3. **The cycles had no compliant alternative.** Clause 2 says card the uncertainty; `58db64ae`'s preamble forbids re-flagging these tickets `needs-john`. Carding would itself have disobeyed a directive.

> **VERDICT (A): No violation.** `58db64ae`'s named approvals govern these three tickets; clause 3 governs everything unnamed, and nothing unnamed was touched. **No remedy is owed** — clause 3's own remedy ("gate for post-Friday") is moot, and a revert would undo work John explicitly ordered.

**What honesty requires conceding, and it is not smoothed over:** the strictly safest reading was to hold all three for four more hours. `SES-210`'s migration shaved clause 3 as thin as it can be shaved while still being inside the window. If John intended clause 3 to override his own named approvals even for Opus-served cycles, that migration is a violation of the letter. ## C. The tag mechanism scored 0 for 27 — and would have lied

Clause 5 required every ship card and cycle row to be tagged `model:sonnet-window`. **Not one of the 27 rows carries it.** Two rows carry the substring `sonnet-window` in prose — and both are **Opus-served ship cycles**, the two cycles the tag was least about.

**So a tag-driven backward pass would not merely have failed; it would have returned the inverse of the truth** — the exact-string query returns the empty set, and the substring fallback returns the two Opus cycles and none of the twenty-three Sonnet ones. This audit was possible only because the window has clean timestamp boundaries and `runner_cycles.model` is written **structurally on every row**. It keyed on `started_at` and `model`: two columns no cycle has to remember.

Several Sonnet cycles *did* note their model variance in free prose (*"running as claude-sonnet-4-6, not Opus 5"*) — clause 1 honoured by spirit. None used the tag. Twenty-three separate cycles each independently failed to copy one string from a directive into a notes field, while every one of them correctly wrote the structural fields.

**This is the platform's oldest finding wearing a new shirt** — `scripts/verifier.js`'s own header records it "eight times over": *a rule each cycle must remember to apply is a rule that gets silently forgotten.* The window now supplies a 27-cycle controlled demonstration.

> **VERDICT (C): The clause-5 tag performed exactly as this platform's history predicts a hand-applied rule performs — 0 for 27, with the only matches being false friends. Replace it; do not restate it.**

**The repair — make a window a row, not a string:**

1. **Windows become data.** A `runner_windows` row (or `runner_directives` with `expires_at`, which `60d35b49` already carried — the only window directive that did): `name`, `starts_at`, `expires_at`, `constraints jsonb`.
2. **Tagging becomes a trigger.** A `BEFORE INSERT` on `runner_cycles` (and `runner_items`) stamps the active window's name into a **real column**, never `notes`. The backward pass becomes one `WHERE window = …`.
3. **Window bans become verifier input.** `scripts/verifier.js` already reads the diff for `SELF_CERTIFYING_PATHS`; teach it to read the active window's `constraints` the same way. That converts §A's genuinely hard adjudication into a logged machine decision next time.

The **rest** wall is not what caught them (`weekly_rest_pct` was 97 at `07:42Z`, so 92 passed). The **token** wall did: the last reading was 73 hours old, which pins the day cap to the `stale-floor` rung of **3M**, and the morning's three ships had already spent ~7.55M. **Eight consecutive cycles closed "did not run — token wall" between `07:42Z` and `14:42Z`, burning 4,545,000 estimated tokens to produce nothing** — roughly seven hours of runner time lost not to a budget constraint but to a stale *reading* of one.
