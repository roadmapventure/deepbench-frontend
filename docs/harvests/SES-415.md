## Eight lessons, each a candidate criterion, with its evidence and the agent that must apply it

**L1. A check grades the change, never the live world.** Applies to: the Designer (writes the QA), the Builder (proves a red is not its own), and the Development Manager and Verifier (separate outside causes).
Evidence:
- SES-371: the test went red when a 7-day window aged out.
- SES-386 and SES-401: guards graded board state and an empty queue.
- SES-404: a test asserts on the live corpus.
- SES-405: a hard-coded two-ticket list.
- SES-393: evidence rebuilt from git history that CI's shallow clone lacks.
- SES-380 and SES-381: a generated file's size and drift.
- SES-382: shared fixtures collide under parallel cycles.
- SES-403: ships blocked for outside causes had no exit but John.

Criterion: a test reads live state only if it declares NOT RUN when that state is absent. Before a red is called the ship's, it is run on the unchanged tree.

**L2. A change has more than one home, and one ship changes all of them.** Applies to: the Designer.
Evidence:
- SES-410: the function, runbook, test oracle and the Development Manager's card copy all carried the removed stop, and the kickoff missed the copy.
- SES-400: registry, runbook and snapshot disagreed.
- SES-411: a live rule contradicted the function with no red.
- SES-399, SES-364 and SES-407: twin undo allowlists and before-image keys.
- SES-408: the environment register and the Designer's Knowledge row.
- SES-381: rendered versus committed state.

Criterion: the kickoff lists every home of what it changes, and the build changes them together. The homes include registry + snapshot, runbook + card + `dm-knowledge-cycle-card`, function + test oracle, and twin allowlists.

**L3. Know the environment before designing.** Applies to: the Designer (reads the register) and the Builder (adds what it learns).
Evidence:
- SES-393: CI clones shallow.
- SES-406: a laptop path runs in the cloud.
- SES-379: the Builder pushes before the verifier runs, so the git diff is empty.
- SES-367: the session prompt path lacked an injected field.
- SES-412: a working Builder writes no heartbeat, so the stall alarm lies.
- SES-396: 6 of the 9 tickets the runner filed on 2026-09-12 were environment facts.

Criterion: design against `docs/runbooks/environment-facts.md`. A build that discovers a fact appends it, which is SES-408.

**L4. A budget rule is only as good as its sensor.** Applies to: the Designer and the Development Manager.
Evidence:
- SES-389: a 22-hour-old reading was trusted.
- SES-374, SES-388 and SES-398: the reader depended on John's laptop.
- SES-390 and SES-395: a second meter (Fable) was ignored.
- SES-409: cycles hand-estimate tokens about six times low.
- SES-392: the laptop reader fails silently (deferred).

Criterion: a gate on a number checks the number's age and source and fails closed. Usage is taken from recorded figures, never estimated.

**L5. A John rule is never removed or weakened without his words naming that change. Adding a degrade does not remove a stop.** Applies to: all agents and every attended session.
Evidence: SES-410 (John: "i never said remove the stop.") and SES-411.
Criterion: John is quoted only for what he said. A change that weakens a live rule cites the rule and his words, or it does not ship.

**L6. Decisions belong to the staff. John keeps only money, production releases, and hiring or switching on agents.** Applies to: the Development Manager.
Evidence:

- SES-378, SES-402 and SES-397: the staff cannot yet decide.
- SES-394: an agreed agent was gated three times.
- SES-385: a half-shipped ticket kept a stale design flag.
- SES-403: blocked ships waited on John.
- 98 undecided cards on 2026-09-16.

Criterion: decide and record the undo. A build's finding is decided before the next pick:
- fix now under the same ticket when it is that ticket's own residue;
- later, with a scope reason and a home;
- or drop, with the evidence.

**L7. What a fresh agent must read has a byte budget.** Applies to: the Designer and the Development Manager.
Evidence: SES-376 (kickoffs of 18-56 KB), SES-377 (a 365 KB runbook re-read each cycle) and SES-409.
Criterion: a kickoff is at most 8 KB, and a cycle reads the card, not the runbook. Reasoning goes to the harvest.

**L8. Every recorded promise is keepable.** Applies to: the Builder.
Evidence: SES-399 (an undo could not restore a backfill), SES-407 (418 before-images keyed by ticket text) and SES-364.

## Design choices, and what each does not do

1. **The tag lives in the md and reaches the table through the exporter — never hand-typed into Supabase.** The exporter is "the one bridge" (`SES-004`); a second writer is a second thing to drift. Two forms of the tag: an entry marker `*Applies to:* …` for the ten new criteria, and one `*Applies to (section default):* …` line under each existing `## ` heading so the 161 older rows are backfilled without touching a single criterion's text (the quote gate's residue and `SES-246`'s identity assertion therefore cannot move). The map of section → default is in the md, not in code, so there is one home. What this does not do: it tags the 161 coarsely — `Working with John`, `The record itself` and the seed set default to `all`. Cycle 2 refines those per entry.
2. **`applies_to text[]` with a CHECK, default `{all}`.** An array because L1 alone binds four roles. `pattern:0` gets `{all}` from the default. The alternative — a single text role per row — would force ten rows into one owner each and misstate L1, L5, L6.
3. **Rule #1 (§19d/§19e) is not touched.** The tag names a *role slug* on library data that a capability will later read (`SES-416` joins it at assembly); it is not one agent's Skill data naming another agent, and no route is hand-rolled. Cited §19b for the same reason.
4. **The corpus is this file, written by the Designer at design time**, on the `SES-004` model (Supabase text a ship gate must not fetch is copied verbatim into a harvest). Every passage below is followed by the row it came from, so the new test's LIVE arm can re-fetch the row and prove the passage is not fabricated — the one hole a harvest-grounded quote leaves open, and one the `SES-004` guard could not close.
5. **The cheapest QA that fails if the change did nothing:** the negative control (the gate on a tree without this file must report a miss on a criterion ≥ 162), and the dry-run facts in the kickoff's §6.

## Alternatives set aside

- Grounding the ten criteria in `docs/SESSIONS.md` instead of a harvest: the passages are ticket descriptions and decision reasoning that live only in Supabase; SESSIONS.md is a session log, not the board.
- Tagging via a join table (`decision_pattern_roles`): more ceremony for ten rows and a coarser backfill; a column with a CHECK is enough and `--check` can compare it.
- Making the section default a `SECTION_ROLES` constant in the exporter: a second home for a fact the md can carry on one line.

## What cycle 2 carries (stated in the kickoff §1)

- Explicit `*Applies to:*` markers for the older criteria whose section default is coarse, reviewed one by one (the sections defaulting to `all`: seed set 1–5, Working with John 81–157 range, The record itself 92–100).
- One sentence each in `docs/runbooks/runner-cycle.md` 7b and `docs/runbooks/session-setup.md` 3d: criteria carry a role tag; a decision cites the ones tagged for its role first.
- Any criterion of 162–171 the Builder had to leave out because its passage would not ground gets its evidence found or is dropped with the reason.
