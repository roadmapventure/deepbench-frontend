## The design in one paragraph

A second pg_cron job, `test-slot-tune`, runs `public.test_slot_tune()` one minute behind the health tick. It moves `runner_settings.test_slot_capacity` by the rule in the kickoff's §4, writes each move to `public.test_slot_moves` with the readings that caused it, and records a `runner_decisions` row so the standing brief lists it (`scripts/render-standing-brief.js:1860` reads open decisions) and `reverse_decision()` can undo it from the before-image.

## Calls I made, and why

**The rule moves `test_slot_capacity` itself; no second "current width" column.** The allowance, the acquire, `scripts/test-slot.js --status` and the AGT-273 test all read that one number already. A new state column would need the allowance replaced and four readers changed. This also answers the session's note that the trial setting must stay consistent with any new state column: there is none. (pattern:17, pattern:8.)

**Stored capacity never goes below 1.** The ticket says "lock at 0 on red". The ladder's red rung already grants 0 for as long as a red reading is in the 15-minute window. Storing 1 gives "restart the climb from 1 once green" for free.

**A separate cron job, not an edit of `db_health_tick()`.** The live tick body was rewritten in place by AGT-276 with a text replace; a third edit of a body I cannot read is a blind fix. A separate job also means a failing tuner can never stop health readings. Cost: one minute of extra lag, against five already built in.

**The bar is every reading in the wait, not the newest.** Today's trial: 21:25Z green (swap-in 228, iowait 5.5%, swap 495 MB), 21:30Z green (108, 2.7%, 508 MB), 21:35Z RED (1212 >= 1200). One healthy reading says little on this machine. All readings in the 20 minutes must be green and under 650 MB / 675 pages/s / 16% — the session's own bar, each about 10% under the amber line (720 / 750 / 18). A missing number fails.

**Honest limit of that bar.** It would not have stopped today's raise: both readings before it were far inside the lines. No bar built on past readings can see load that has not arrived. So the protection that matters is the next call.

**A level that came down is not retried for 24 hours.** Any `down` or `lock` from capacity C bars every target at or above C. Red at 3 leaves 2 reachable; red at 1 bars all climbing for a day. Without it the line would go 1 -> 2 -> red -> 1 -> 2 every half hour whenever runs queue. I chose 24 hours over 6 because each failed probe costs a red window, and the 2026-09-28 raise to 3 ended in an outage four hours later. The migration seeds today's failed 2, so the tuner does not repeat the trial tonight.

**Wait 20 minutes.** Four readings, about two and a half suite runs at 8 minutes each. It is also the gap between any two moves, so ceiling 5 is at least 80 minutes from 1. Longer waits would not have caught today's red either, so I did not buy more delay.

**`enabled` is true.** John said build it. The switch exists so a session can freeze the line without a migration.

**Ceiling.** `test_slot_ceiling` 5 is John's number in its own column. If someone sets capacity above it by hand the tuner brings it back and records that.

**Every move is a decision row.** The ticket asks that the standing brief can show moves. The brief already lists open decisions, so no brief code changes. Volume is bounded by the wait and the cool-off.
