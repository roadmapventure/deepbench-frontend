## 3. Why the shape is a declared flag and not a reader of the remainder prose

The obvious design is to read `--remainder=`'s text and infer branch (c). It was rejected:
`stopLineClosesPartial()`'s history (AGT-128, then AGT-634) is two shipped corrections to a regex
over kickoff prose, the second because a clause *describing* behaviour fired a status write. A prose
matcher here would write `defer_status` — a cell that removes a ticket from the queue — on a
sentence it misread. The branch choice is a judgment the runbook already assigns to the closing
cycle; what is missing is only a place to put the answer. So the answer is declared
(`--defer-reason="<condition>"`) and the script writes exactly what it was handed (pattern:9,
pattern:10).

Alternatives weighed and not taken:
- **A new column or a `runner_questions` pointer** — `SES-247` already considered and rejected this; every case has a column.
- **Editing the runbook's step-7 command block to mention the flag** — `runner-cycle.md` is 380,9xx bytes against the `SES-336` ceiling, and AGT-326/AGT-319 drag `cycle-card.md`, `BYTES_AT_SHIP` and a card re-render into any edit. The branch's instruction is already there; what the operator needs is the prompt at the moment of settling, which `renderPlan()` gives for free.
- **A `--defer` door that writes only the two cells** — a second door for one write; `planSettle()` already owns the patch (pattern:14, pattern:15).
- **Flagging all six rows this cycle** — re-running a settle from 2026-09/10 mints a decision and a before-image under THIS cycle's attribution over another cycle's ship. Filed as a backfill instead.
- **Making `ticket-owner.js` check 12 detect the unflagged six** — a detector over prose, out of scope; a candidate for the backfill ticket.

## 4. The coupling that decides the design: `ses-305` arm (1)

`tests/regression/ses-305-deferred-never-picked.test.mjs` asserts, credentialed, that **every open
deferred ticket carries a NULL queue** — `status=not.in.(done,removed)`, so a `partial` is in scope.
`defer_status` alone does not clear `queue`; `recompute_backlog_queue()` does (the operational
defaults census: a row loses its number when `defer_status` is `yes` or `stuck`). A writer that set
the flag and stopped would turn that suite red on the next run. Hence D3: the deferral branch runs
the recompute itself, non-fatally, and reads the queue back. The pick is already safe without it —
`prime_directive_queue()`'s buildable CTE carries
`COALESCE(b.defer_status, '') <> ALL (ARRAY['yes','stuck'])` (docs/design/agt-238-leverage-first.sql:97) —
so the recompute is about the suite's invariant and the board's display, not about the exclusion.

`ck_backlog_defer_status` admits `no / maybe / yes / stuck` (quoted in `ses-305`'s own NOT-RUN
message), so `'yes'` needs no migration.

## 5. Risk reasoning behind the kickoff's `risk` block

- The patch change is invisible without the flag: both `ses-385b:140` and `agt-506:297` deep-equal the three-cell patch, and they are the structural stop on a fourth key appearing by accident. They stay green unedited, which is why T1 is specified as "same three keys, same order".
- The recompute re-derives every queue number. No before-image is taken, for the reason `close-session.js` step 5 takes none: the numbers are derived (register B4) and re-running the call restores them. It is wrapped so a housekeeping failure cannot take the settle's exit code down (`retireStaleShipCards()`'s shape at step 6).
- T4 moves exactly two cells on one row, under one `runner_decisions` row with a full-row before-image, so `reverse_decision()` undoes it.
- Nothing here is irreversible and nothing changes agent autonomy, so no part needs to ship alone (RISK RULE, AGT-610).
