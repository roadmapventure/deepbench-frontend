## The constraint that shaped the design, and the one nobody had measured

Slice 1 planned this slice as "a judgment-lane run per topic cluster … attended via `agent-prompt.js --agent=auditor` once John has applied the seed, or as a hand-composed sub-agent prompt if he has not". Two facts measured this session change *how* that runs, not *what*:

1. **This Builder cannot spawn a sub-agent.** The environment sets `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1`, and the Builder is itself the cycle session's sub-agent. A kickoff that says "spawn each cluster via the `Agent` tool" would fail at the first cluster. The way through is the platform's own existing pattern: `scripts/read-usage-meter.js:131` already shells the `claude` CLI headlessly (`claude -p "/usage"`, SES-374). Measured here: `claude -p --model claude-fable-5-1 --allowedTools Read --output-format json --max-turns 3` from a **scratch cwd** reads an absolute path in the clone and answers in 2 turns with ~6.9K cache-creation tokens (the same call from the clone's own cwd loaded 46.8K — the project's CLAUDE.md and rules — and printed a workspace-trust warning; from the scratch cwd it loads neither). The JSON carries `usage` and `duration_api_ms`, which is what `agent-log.js` needs. Subscription tokens, $0 API — the ticket's declared lane.
2. **"Re-find by fingerprint" cannot be literal for a blind run.** `fingerprint()` = kind | locationKeys | `normalize(governing_fact)`, and `governing_fact` is free text the model writes. A blind run that finds the same dispute will word the fact differently and mint a different fingerprint — which is exactly how a weekly audit would file six copies of its own first week. So the slice adds a code-side **reconciliation**: a finding sharing ≥ 2 `locationKey`s with a ledger row is the same dispute (two homes in common), reported as `re-found:<fp>`, and is *not* written into the candidates. Exact fingerprint matches are counted for the record, not asserted. The fingerprint itself is slice 1's decision and is not touched.

And the one honest limit: **`4ef228c3` (temperature) cannot be re-found from the corpus.** The corpus has 0 statements saying the judgment lane's API rejects `temperature` — that fact lives in `api/prompt/request-receivable.js:274-279`, and `api/` is not one of the five homes. The 7 `pz-*/temperature` statements are in the corpus; their contradicting side is not. The kickoff says so and the QA asks for ≥ 3 of 4, with the fourth's absence reported. That absence is itself a finding about the corpus (a live-voice fact with no doc home), named on the card.

## Pure functions

`scripts/audit-cluster.js` exports, all pure (no network, no disk, no exit):

- `anchorsOf(st)` → `Set<string>`: every match of `/\b[a-z][a-z0-9]*(?:_[a-z0-9]+)+\b/g` and `/\b[A-Z]{2,5}-\d{1,3}[a-z]?\b/g` in `st.text`; every backticked span `` /`([^`\n]{3,40})`/g `` whose inner text matches `/^[A-Za-z0-9_.\-\/:]+$/` (a trailing `()` stripped); and, when `locationKey(st.location)` does not end in `.md`/`.js`/`.json`/`.yml`, every middle segment of the location (between first and last `/`) matching `/^[a-z0-9]+(?:-[a-z0-9]+)+$/`. Anchors matching `/^\d+$/` dropped.
- `buildClusters(statements, {maxStatements = 40, textCap = 1200} = {})` → `[{name, kind: 'anchor', spread, homes, statements}]`: index anchor → statements; keep anchors with 2..`maxStatements` statements spanning ≥ 2 distinct `locationKey`s; `spread` = distinct `source` values, `homes` = distinct `locationKey`s; sort by `spread` desc, `homes` desc, `name` asc; walk in order and drop a cluster whose statement-id Jaccard with any already-kept cluster ≥ 0.6; each emitted statement is `{id, source, location, text, retired, truncated}` with `text` cut to `textCap` chars and `truncated = original.length > textCap`.
- `locateStatements(statements, loc)` → statements with `locationKey(s.location) === locationKey(loc.location)` whose `normalize(s.text)` contains at least one window of `normalize(loc.text)` — windows of 40 chars starting at 0, 20, 40, … (a text shorter than 40 chars is one window).
- `priorClusters(rows, statements)` → `{clusters, unrunnable}`: for each row with `status === 'open'`, locate every location; `located ≥ 2` → cluster `{name: 'prior-' + fingerprint, kind: 'prior', statements}` (deduped by id, emitted like `buildClusters`' statements); else `unrunnable.push({fingerprint, located, total})`.
- `capabilityFor(cluster)` → `{capability: 'audit-agent-data', intent: 'au-agent-data-intent'}` when every statement's `corpus === 'agent-data'`, else `{capability: 'audit-governance-corpus', intent: 'au-corpus-intent'}`.
- `validateFindings(result, cluster, byId)` → `{kept, dropped: [{finding, reason}]}`: `result.findings` must be an array; a finding is kept only if `kind` ∈ the five, `confidence` ∈ high/medium/low, `governing_fact` is a string ≤ 300, `proposed_resolution` a string ≤ 400, `locations` has ≥ 1 entry, and for every entry a cluster statement has the identical `location` and `normalize(entry.text)` is a substring of `normalize(byId.get(statement.id).text)` (the full, untruncated text).
- `reconcile(findings, rows)` → `[{finding, verdict, match}]` where `verdict` ∈ `new | re-found | ruled-out`, `match` = the fingerprint of the first row (ledger order) sharing ≥ 2 `locationKey`s with the finding (`ruled-out` when that row's `status === 'not-a-defect'`, else `re-found`), and `exact = fingerprint(finding) === row.fingerprint` counted in the returned summary `{new, reFound, ruledOut, exact}`.

## CLI contract

Common: `arg()` parsing as `audit-ledger.js`; creds via `SUPABASE_URL` / `SUPABASE_SERVICE_KEY` unless `--no-db`; exit 0 ran, 2 could not run (bad input, missing creds, REST failure, log refused). Entry-point guard as slice 1's scripts.

- `--build --statements=<json> --week=<YYYY-Www> --out-dir=<dir> [--max-clusters=12] [--no-db]`: read the statement table; ledger rows via `audit_findings?select=*` (none with `--no-db`); `prior` = fingerprints of rows with `iso_week = week`; clusters = `priorClusters(...).clusters` then `buildClusters(...)`, cut to `max-clusters`; write `<dir>/<NN>-<name>.task.json` (NN two-digit from 01) with the File shapes' task shape; print `build <week>: <C> clusters (<p> prior, <a> anchor), <U> prior unrunnable` followed by one `  unrunnable <fp>: <located>/<total> located` line each.
- `--run --dir=<dir> --cycle-id=<uuid> [--limit=N] [--dry-run] [--no-db]`: for each `*.task.json` in name order lacking a sibling `.result.json` (at most `limit`): model = `runner_model_lanes?lane=eq.judgment` `model_id`; prompt source = `assembled` when `agents?id=eq.auditor&select=id` returns a row — then spawn `node scripts/agent-prompt.js --agent=auditor --capability=<cap> --intent=<intent> --task=<JSON of task_context>` for the text and the same with `--json` for `llm.model` (which replaces the lane model when set) — else `exception:seed-file` with the Exception prompt. Spawn `claude -p --model <model> --allowedTools Read --output-format json --max-turns 6` (`spawnSync`, `input` = the prompt, `cwd` = `<dir>`, `encoding utf8`, `maxBuffer` 64 MB); parse stdout as JSON, take `result`, cut from its first `{` to its last `}` and `JSON.parse`; on any failure the result file is `{error, raw}`. Write `<NN>-<name>.result.json` (File shapes). Unless `--dry-run`, then spawn `node scripts/agent-log.js --agent=auditor --capability=<cap> --model=<model> --ai-type=<cap> --feature=<cap>:<intent>:depth1 --input-tokens=<in> --output-tokens=<out> --latency-ms=<duration_api_ms> --cycle=<cycle-id> --json`; a non-zero exit stops the run with exit 2 (the log row is mandatory). Print per cluster `run <NN> <name>: <k> findings · <source> · <model> · in <in> out <out> · log <id>`; `--dry-run` prints `run <NN> <name>: dry · <source> · <model>` and spawns nothing but the `agents` probe.
- `--collect --dir=<dir> --statements=<json> --week=<YYYY-Www> --out=<json> [--no-db]`: for each task with a result: results carrying `error` count as `unparseable` (dropped); else `validateFindings` then `reconcile` against all ledger rows (`audit_findings?select=*`, none with `--no-db`); write `--out` = `{week, found_by: 'auditor:judgment:<model of the first result>', note: 'candidates from the judgment run — NOT ingested; John reads, then node scripts/audit-ledger.js --ingest=<this file> --week=<week> --cycle-id=<cycle> --apply', findings: [new only, in cluster order]}`; print `collect <week>: <C> clusters, <K> returned, <D> dropped, <R> re-found [<fps comma-joined>], <E> exact, <X> ruled-out, <N> new -> <out>`.
