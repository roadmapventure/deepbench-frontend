## Why `partial` + a `gated_before_build` card, and not a new kind (my call, reversible)

`partial` needs no verdict, clears `design_status` and keeps the row in the pick path, so a ship
that is merely ungraded is re-pickable as unfinished rather than invisible as `delivered` —
the safe side of the same asymmetry `AGT-167` recorded (`RESETTLE_FROM`). A new `runner_items.kind`
would violate the live CHECK and render on no surface John reads (`build-briefing.mjs` renders §5
from `ship`/`test` and §6 from `gated_before_build` and nothing else) — the same argument
`rollback-on-red.js:649-656` already recorded for its incident card. The card's `backlog_id` is the
ticket on purpose: `main()`'s census at :970 reads undecided `gated_before_build` rows by
`backlog_id`, so on the NEXT settle `decideStatus()` returns `partial` with the reason "an undecided
`gated_before_build` card is open on this ticket" until John rules. The refusal's own sentence stays
the card's `value_case`, so the record says which nothing it was.

`--release` is a fourth door rather than a step inside the ordinary settle, because
`q-claim-release-order` (`SES-106`, John) puts the release AFTER the push and the settle runs before
it. That is the same reason `--ship` is its own invocation.

## The `dm-knowledge-cycle-card` repin

`scripts/render-cycle-card.js` main() gates `--write` through `writeGate()` (`AGT-112`, `v7.0.577`):
a render that CHANGES the card is refused without `--ticket`, `--cycle-id` and credentials, and when
allowed it writes the card and then falls into `syncKnowledge({repin: true})` in the same process.
`repinKnowledge()` records its own `agent-row` decision naming the ticket and the change ("re-pin
dm-knowledge-cycle-card <from> → <to>"), writes one `runner_before_images` row carrying the FULL
prior `skill_profiles` row, PATCHes, and reads back.

So the repin cannot be separated from the card without re-opening the four-hour drift `AGT-112`
closed — the coupling IS the fix, and `pattern:19` says gate a dangerous operation through the
atomic correct path rather than blocking it. `AGENT-ROW-AGREED-TICKET`'s first limb does not apply
(AGT-595 is `victoria-placed`, not `john-named`), but the second does: an unreversed
`runner_decisions` row naming both the ticket and the change — which is exactly the row
`repinKnowledge()` writes. My call, recorded and reversible: **run it under AGT-595**, and file one
new `Tooling` row for the gap the Development Manager flagged — that a card-moving ticket's own text
should name the repin — rather than leaving that gap unrecorded (`pattern:96`). The new row's id is
