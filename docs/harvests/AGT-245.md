## Why a picker and not a backfill

49 pairs × 2 full regression suites = 98 suite runs. That is not a session; it is a background process.
The ticket's sentence — *each ticket blocked only by standing reds gets a fresh verdict and can close* —
is satisfied by a tail that takes the next pair every cycle with nobody naming it (`pattern:16`,
tracking systems must be self-maintaining; `pattern:9`, never spend a model call where a deterministic
mechanism serves). The mechanism is the deliverable; the remaining 47 are it running.

## Alternatives considered

1. **Run all 49 now.** Rejected: 98 suites, and the slot line is shared with 5–7 concurrent cycles.
2. **A new `regrade_progress` table.** Rejected — slice 1's stance holds: progress is derivable live
   from `runner_verdicts.reasoning`, and a second table is a second thing to keep true (`pattern:93`).
3. **Let the picker park on a refusal and report it.** Rejected: a permanently-refusable row (a ticket
   the board has moved to `done`) would stall the queue forever. Skipping forward costs one extra REST
   read and needs no state.
4. **A knob capping how often `(7a-ter)` runs.** Rejected on `pattern:67` — `withTestSlot` plus
   `db_health_level()` already bounds it, and a refused slot is exit 2 recording nothing.
5. **Have The Development Manager choose the pair per cycle.** Rejected: the choice is a deterministic
   walk over a frozen file. A model asked to pick from 49 rows would sometimes pick a different one,
   and a re-grade that is not reproducible is not evidence (`pattern:3`, `pattern:10`).

## The ruling on the 15 refused

14 are `interleaved` — a peer's commit sits inside `base..ship`, so the ship tree is not this ticket's
change alone and re-running the suite there grades the peer's work and files it under this ticket. One
is `no-version` (`AGT-202`, a NULL `version` on the verdict row, so no own commit resolves). No honest
delta verdict exists for any of them inside this lane, ever, and approximating a pair is exactly what

`(7a-bis)` `--regrade` lane, which costs nothing per pair and clears them the moment `Tripwire +
regression (blocking)` is green on `dev`. Recorded as one `runner_decisions` row of kind `directive`
(task 4) so a cold session finds the ruling on the board rather than in a doc (`pattern:92`).
