## Why this slice runs no suite, measured

`public.test_slots` has capacity 1 (`runner_settings.test_slot_capacity`), a 10-minute lease with a 60 s heartbeat, and `test_slot_acquire()` grants only while `db_health_level()` is green — AGT-237's pressure hold is already inside the slot. This session's caller measured one `run-all.js` waiting ~25 minutes behind four peers before its first test, and one earlier attempt killed while still queued. A real pair (two legs) is one slot wait plus two suite durations; the builder's own cycle already spends two slot acquisitions (baseline capture, 7a). Adding a pair here is the difference between a cycle that finishes and one that does not, so the mechanism is proven on the real `AGT-101` trees with a one-liner suite that does not touch the slot, and the first real pair is slice 4.

## Design choices, and the alternatives measured against them

- **One slot per pair, legs back to back.** Trees older than `v7.0.689` (AGT-265) have no `takeTestSlot()` in `run-all.js` at all — a script that simply ran the old tree's suite would bypass the line and run beside a peer's suite on the NANO instance. `withTestSlot()` from the current tree wraps both legs and the children get `DEEPBENCH_TEST_SLOT=held`. Back-to-back legs also answer slice 1's caveat: sharing boundary trees across pairs (89 trees) puts a pair's two legs hours apart against a live database that drifts; 112 legs in 56 same-world pairs is the honest count.
- **The own-test rule.** A test file the ship's own diff added or changed, red on the ship leg, is charged to the ship even when the base leg is also red today. Without it, a test the ship genuinely broke that also fails on the base tree under today's drift would be counted standing and launder an approve. It is deterministic (`git diff --name-only base ship -- tests/regression/`) and only ever moves a name toward red.
- **`--suite=` implies `--dry-run`.** The override exists so the guard and the QA can prove worktree placement and delta direction without the slot; a recordable override would let any command write a verdict.
- **Refusals over approximations:** `superseded` (the ticket's latest verdict is no longer the frozen one), `deps-changed` (package files differ between base and ship, so a shared `node_modules` symlink is not the tree's own), `<leg>-leg-did-not-run` (no `[PASS]`/`[FAIL]` line — a transport not-run or a crash before the first test), `slot-not-granted`, `not-regression-only` (hygiene or build red on the prior row — those 4 rows are out of this slice's predicate).
- **Row shape.** Same `verdictRowFor()`/`insertVerdict()` as both other lanes (exporting the latter is the one `verifier.js` edit), `graded_sha` = the ship's own tree (unlike the original row, which since SES-336 records dev HEAD at grade time), `auto_done_eligible=false` as `--regrade` does. `record_ship_decision()` with `p_push_sha = ship_sha` keeps step 7's `push_sha = graded_sha` assertion true; SES-320's `sweep_decision_windows()` then moves the ticket to `done`.
- **Rejected: teaching CI to grade by delta so `regradable_ships()` fills.** Under delta grading at CI, a red a ship introduced is in the next run's baseline and invisible — the "blocked on its own diff stays red at dev head" negative control that SES-403 relies on stops holding. It would also touch `ci.yml`'s John-only lane. Not designed.
- **Rejected: a partial-suite real leg** (`run-all.js` has no filter flag; `--dir` only).
