## 4. What would break — inbound references, and a correction to how they were counted

The literal-path grep (`.claude/<full path>`) gives these totals outside `.claude/`:
`design-tokens.md` 44, `ai-pattern-signature.md` 45, `capabilities-are-data.md` 39,
`agent-section-rendering.md` 30, `supabase-column-grants.md` 23, `session-setup/SKILL.md` 17,
`session-hygiene/SKILL.md` 12, `triage/SKILL.md` 4, `discovery` 1, `reframe` 1.

**Those totals are misleading in both directions and must not be used as the risk measure.**

- **They over-count.** The large majority are `docs/kickoffs/*.md`, `docs/SESSIONS.md`,

  pointer that breaks when the file moves; rewriting them would be falsifying history (§19v).
- **They under-count.** The grep matched **full paths only**, so every reference written in
  **directory form** was missed — and `CLAUDE.md`'s own pointer table uses directory form for
  `.claude/skills/session-hygiene/` and `.claude/rules/`. Re-measured on the directory form,

Every live referrer of the three move candidates, by contrast, sits **outside `.claude/`** —
so an unattended cycle can update all nine of them.

## 5. The proposal (phase 2 — needs John)

**Extract the procedure body of the three churning skills to `docs/runbooks/`, leaving each
`SKILL.md` as a thin loader.** Exactly the shape `CLAUDE.md` already uses to route sessions, and
exactly the shape B41 used for `inflight/`.

| Move | From | To |
|---|---|---|
| 1 | `.claude/skills/session-setup/SKILL.md` body | `docs/runbooks/session-setup.md` |
| 2 | `.claude/skills/session-hygiene/SKILL.md` body | `docs/runbooks/session-hygiene.md` |
| 3 | `.claude/skills/triage/SKILL.md` body | `docs/runbooks/triage.md` |

Each `SKILL.md` keeps its YAML frontmatter (`name`, `description`) and becomes one line: *read
`docs/runbooks/<name>.md` and follow it.* The nine live referrers are repointed in the same
commit.

**Why the frontmatter must stay in `.claude/`:** the harness discovers skills by
`.claude/skills/*/SKILL.md` and triggers them from the `description`. Deleting the file deletes
the skill. The split is load-bearing in the right direction — the census says the churn is in
the **body**, and the description is the half that has barely changed.

**Explicitly NOT in scope, each for two measured reasons:**

- **`.claude/rules/*` (14 files) — leave alone.** 12 of 14 have a single creation commit and
  none in the last 14 days; and 22 live source files name those paths (§4).
- **`.claude/skills/discovery/`, `.claude/skills/reframe/` — leave alone.** One commit each,
  none in 14 days, one referrer each. Moving them buys nothing.
- **`.claude/settings.json`, `.claude/launch.json` — leave alone.** Config, not process prose,
  and `CLAUDE.md` already records that the operative hook settings live at
  `C:/Projects/.claude/` outside this repo entirely.
- **§19v protections are untouched.** The gated harness / screen / agent surfaces stay
  attended-only; this changes where three process documents live, nothing about who may change
  what.

### What this is worth, quantified

Of the **10** real `.claude/` commits in the last 14 days (39 raw, less the 29 that touched only
the already-relocated inflight files), **7 — 70% — touched one of these three bodies**, and
would have been ordinary `docs/runbooks/` commits an unattended cycle could make. The residue
left behind in `.claude/` is **3 commits in 14 days** across the 14 `rules/` files, both config
files and `discovery`/`reframe` together — a surface that has blocked nothing (§3).

Stated the other way, so the claim is not oversold: this does not empty `.claude/`. It moves the
70% that churns and leaves the 30% that does not.

### The honest caveat, stated rather than discovered later

**This proposal does not unblock the four items already waiting — and cannot.** Performing the
extraction is itself a `.claude/` write (three `SKILL.md` files rewritten), so no unattended
cycle can execute phase 2 either. It needs **one session John attends**. The right ask is
therefore that the same sitting does both: perform the three extractions **and** land the
carded one-liners that are already blocked (`SES-118`'s `'missing',` → `'open',`, `SES-117`'s
check-3c wording). One attended session clears the standing backlog and removes the mechanism
that produced it.

**And a bound on the claim:** this makes needs-desktop tickets *rarer*, not impossible. A future
edit to a loader — changing which runbook a skill points at — is still a `.claude/` write. The
census says that is a once-in-a-lifetime edit against a body that moved six times in fourteen
days, which is the trade being proposed, stated as a trade.
