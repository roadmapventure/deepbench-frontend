## Original description (verbatim, as filed 2026-08-29 and amended through 2026-09-02)

**FOUND LIVE 2026-08-29T21:0x–21:29Z by session cycle-20260829-2040, THREE TIMES IN ONE HOUR, each time on the ticket the calling cycle had itself closed minutes earlier.** `drain_chain_gate()` returned `continue` naming `SES-246` twice and `SES-245` once — in every case a ticket the closing cycle had just set `partial` with a **declared remainder it had explicitly recorded as not buildable in this cycle**.

**THIS IS `SES-154`'s DEFECT IN ITS FOURTH COSTUME**, and that ticket's own sentence transfers exactly: *"otherwise the drain hands the same delivered ticket back every cycle and never advances."* The three costumes already fixed are `delivered` (`SES-154`), the three `design_status` flags (`SES-196`), and `blocked_by` (`SES-218`). The population this one names is the remaining hole: **a `partial` whose remainder is not buildable now for a reason that is NOT another open ticket** — it awaits a decision of John's recorded as a `runner_questions` row, or the closing cycle judged it deserves its own cycle (a design choice, a self-certifying-path edit).

**THE ONE-LINER THIS FORBIDS, for `SES-218`'s own reason:** `AND b.status <> 'partial'`. `partial` is not uniformly do-not-re-pick — `SES-51` and `SES-180` each shipped a further half from `partial` — so the blanket clause strands exactly the tickets John's criterion protects.

**WHAT THE CYCLES DID INSTEAD, and why two of the three are not a fix:** on `SES-246` and `SES-004` the flag written was `needs-john`, which is TRUE in both cases (the remainder is a question put to him). On `SES-245` it would have been FALSE — the remainder is a scoped decision a cycle can make — so nothing was written and the chain was **ended by hand**. A rule that only works when the remainder happens to be John's is not a rule.

**SHAPE TO CONSIDER (not decided — this is the design work):** the honest fact is *"this remainder is not buildable now, and here is why"*, which today has no column. `blocked_by` is the precedent and is deliberately keyed on `backlog_items.id`; the missing sibling is something like `blocked_note` + a `blocked_until_decided` pointer at a `runner_questions.qid`, so the pick predicate can exclude it with a `NOT EXISTS` over the question's live `status` — **re-admitting the ticket automatically the moment the question is answered, with no write anyone must remember** (`SES-218`'s own boundary: a rule each cycle must remember is a rule that gets silently forgotten).

**Cheap to reproduce:** close any Selfbuild ticket `partial` and call `drain_chain_gate(<that cycle id>)`.

DECIDED 2026-09-02 (John, session design-m5-milestone-0902): epic stays M5 (his call); one of five tickets John named as prerequisites — verbatim "These are functions i need built before we start M5: Ses-295, ses-284, ses-283, ses-247, ses-260" — built ahead of the remaining M5 required work (SES-303, SES-277).

RULED 2026-09-02 (session design-ses-247-0902, v7.0.380): the fourth costume closes by decision tree, not by a new column. A partial whose remainder (a) awaits another ticket → blocked_by (auto-clears, SES-218); (b) awaits a decision → under M6-01 the closing cycle DECIDES now, records it, and either builds or leaves the partial re-pickable (John's criterion: a buildable remainder comes back); (c) is genuinely not buildable now for a non-ticket reason (a machine John has, an external party) → defer_status = yes with defer_reason naming the condition — enforced in the pick path since SES-305 (never the retirement predicate), reported in the drain census every fire, cleared by whoever resolves the condition. The forbidden one-liner (status <> partial) stays forbidden. Recorded at runner-cycle.md's partial/remainder section; drain_chain_gate() inherits via drain_epic_next(). Of the three 2026-08-29 hand-backs, two were questions for John (now a decision the cycle makes) and one a scoped decision the cycle could make — none needed a new mechanism.
