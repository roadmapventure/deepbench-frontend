- `scripts/verifier.js` `kickoffBuilderModelFinding` reads the first `Model:` line against the live `orchestrator` lane (`claude-opus-5`); `kickoffAnchorFinding` counts with `docs/kickoffs` and `docs/harvests` excluded. ## 3. Alternatives weighed

1. **Replace `knowledge_entries` with `taught` / `records` outright.** Cleanest shape, but it breaks the published required key (a data write to the Intent row, with its migration-down capture) and AGT-162's pin (a fourth file). Rejected for the cap and because nothing in the use case needs it.
2. **Keep the raw `knowledge_entries` and add the two framed groups.** Zero pin risk, but every item's text is handed over twice - 448 KB of duplicated text for `bob` - and the unframed copy is exactly what the outside tool ignored. Rejected.
3. **Chosen (D1): framed groups plus `knowledge_entries` as an index.** One entry per active row (`id, title, chars, kind`), so the required array, the length pin and the `call_facts.knowledge_entries` count all hold unchanged; the text exists once, under its framing. Reversible by a later ticket that updates the Intent schema and retires the index.
4. **Route the read through `lib/search-harness.js` `queryContent`.** That broker has no query-free `knowledge_entries` store branch; adding one widens a shared harness for a read the handler already makes directly (pattern:8). Not taken.
5. **Export the 12,000 from `lib/knowledge-write.js`.** Right end state (one declaration), a fourth file today. Named in the STOP LINE as a finding; `AGT-343` edits that file anyway.
