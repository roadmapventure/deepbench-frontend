## 4. Design and alternatives
- Where the clause lives: `pick_exclusions()` (chosen) vs a WHERE on lane (c) only. The chosen home covers both lanes and `project_blockers` (the stranger shows a reason on the board: `outside the exclusive drain`), pattern:14/17. Lane (b) is unaffected in practice (members are never "outside").
- Membership semantics with several exclusive drains: a ticket is pickable if it is a member of ANY queued exclusive drain (union). A per-drain "its scope" reading would strand a second drain entirely.
- "Open member" = status NOT IN ('done','removed'), the retirement pair `c_finished` in `drain_epic_next`; delivered counts as open, consistent with the runbook ("the retirement predicate must NOT exclude delivered").
- Default true for every row incl. cap-split drains (call i): `rule_capped_ticket` inserts without naming the column; its parts are already serialized by blocked_by, so exclusivity costs only the idle lanes John's rule asks for. Reversal is one `UPDATE runner_directives SET exclusive = false WHERE id = …`.
- `add_to_drain` chain rule (call ii): if an open member is already blocked_by the ticket, chaining the ticket behind TAIL would make a cycle (member → ticket → TAIL → … → member) and deadlock the drain; the ticket joins the scope with its own blocked_by untouched, which is exactly the "blocker added this way is picked" use case. Otherwise it is chained behind TAIL as the ticket text says.
- Refusal order in add_to_drain: author, reason, directive, ticket exists, finished, member, epic — so a done ticket outside the epic reports [finished]; the GATE's [outside the epic] case uses AGT-398 (open, epic 2da16d99).
- Decision kind: `ticket-scope` reused from `rule_capped_ticket`, the only other drain-scope writer (DRAIN-CAP-SPLIT). `reverse_decision()` k_allowed already lists backlog_items, runner_directives, runner_drain_scope; a before-image with row_data NULL is deleted on reverse (same as rule_capped_ticket's scope rows).
- `runner_should_boot()` unchanged (call iii): `work_to_find` boots a find-work-only fire that classes findings and builds no ticket; John's sentence is about tickets picked up. Also no change to `drain_epic_next(uuid)` — it never returns a non-member, and calling it from a test retires live drains (SES-196/218/275 refusal).
- Fixture strategy: `epic_lock_guard` (AGT-240, Tooling locked_at 2026-09-29, accepts_findings false), `requirement_gate` (AGT-280) and `backlog_requires_finding` (AGT-238) all pass a row with `scope_origin = 'john-named'`; `backlog_items` UNIQUE (source_file, row_ordinal); `runner_items.backlog_id` must match `^[A-Z]+-[0-9]+[a-z]?$` → fixture ids ZFIX-4560N.
