## 2. What SES-418 actually asked, sentence by sentence

1. *"Make the insert per-row tolerant"* — **rejected** by AGT-79 (v7.0.518) on its own grounds:
   a night is one unit, *"there is no partial night"*; a part-written ledger makes `notes` counts
   disagree with the rows, and `recordNightly` would stamp a half-landed night as landed.
2. *"(or validate the batch against the live constraint before sending it)"* — **never built, and I
   reject it too.** The reasoning is the same one that killed the first half, followed one step
   further: because there is no partial night, a pre-send check cannot *save* a night. It can only
   fail earlier, with a nicer message, and discard exactly the same 300+ findings. What SES-418
   actually wanted — the two vocabularies can never drift apart silently — is delivered by the
   shipped ordering protocol (`scripts/ticket-owner.js:14-18`: the CHECK widens first, in
   `docs/design/agt-166-unrevalidated-slug.sql`, and the code learns the slug second) together with
   sentence 3. So the whole-array POST stays, **by decision rather than by omission** — and that
   distinction is the entire point of writing it on the row.
3. *"guard it with a test that feeds the script's own slug vocabulary against the live CHECK"* —
   **built**, AGT-79 part N, `tests/regression/agt-79-ticket-owner.test.mjs:1156`. It POSTs one array
   of `CHECKS.length` rows with `return=representation` and asserts both the returned slugs and the
   count, so a narrower constraint refuses outright and a dropped row fails the count.
4. *"ALSO UNPROVEN: no night has yet filed a remainder-stranded row … the first clean nightly run is
   the evidence this ticket should close on"* — **proven**: 93 rows, 14 nights (§1).

## 4. AGT-179's own instruction that I refused

*"replace the unrelated ship_summary"* cannot be done, and should not be.

- `information_schema.columns` shows **no `ship_summary` column** on `backlog_items`. The finding's

- `ship_summary` is *derived* by the work-quality assembly as *"latest `runner_cycles.notes` for that

- **0** `runner_cycles` rows name SES-418 (`item_id = 'SES-418'` → 0; no row links by `item_id` or
  `backlog_item_id`). The string the audit read — *"Seventh continuation, of cycle 0f571e00… "* — is

wrong string (`pattern:89`, `pattern:94`), and file the real defect as its own row: where no cycle
names a ticket, the assembly should render honest absence, not another cycle's fact
(`pattern:34`, `pattern:32`). Filed by Task 4, not fixed here (`pattern:96`).

## 6. Design choices, and the ones I rejected

- **Prepend, not append.** The only reader that grades this row reads `description (first 1500)`
  (`auditor-routine.md:89`) and the description is already 1192 chars. Appended, the answer would sit
  almost entirely outside the window of the check that raised the question (`pattern:5`).
- **The assertion handle is the marker `DISPOSITION 2026-09-27`, never the string `AGT-79`.**
  Measured: `description not like '%AGT-79%'` is already **false** before the write — the text says
  *"widened by the AGT-79 v7.0.518 peer while this session ran"*. A QA keyed on `AGT-79` would pass on
  the untouched row. This is the single most likely false green in this ticket and the kickoff says so.
- **No regression test pins SES-418's description.** That would grade the live world, not the change
  (`pattern:162`). The row write is graded by the migration's own before/after select and by a real
  reversal; the code change is graded by the `[NOT RUN]` count.
- **No `capture_migration_down()` call.** The migration creates, drops and retypes nothing, so there is
  no object for it to classify. The down for a data change is the before-image chain, the shape
  `docs/design/agt-166-intake-homing.sql` used; `backlog_items` is in `reverse_decision()`'s `k_allowed`
  list (source read live). `updated_at` is untouched per `SES-316`.
- **Rejected: a generic "closed row whose text still asks" check.** `remainder-stranded` (SES-385) and
  `unrevalidated-30d` (AGT-166, last night) already are that mechanism, and `quality-shipped-vs-asked`
  is what produced this finding. The gap was never detection; it was that a finding was filed and the
  row never answered. Building a fourth detector would be the wrong layer (`pattern:8`, `pattern:17`).
- **Rejected: widening this into "every closed row carrying an off-row disposition".** One item per
  kickoff (`pattern:64`). Caps are 22/23 and I am using 3 files and 4 tasks; the honest shape is small.
