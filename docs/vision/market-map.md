### Rules — seven tests plus named exclusions

A feature is **P2 - Inventive** only if it passes all of tests 1–3. Tests 4–5 further rank how strong a P2 candidate is; test 6 is a soft flag, not a disqualifier; test 7 sharpens what "inventive" means when a candidate is being scored.

- [C-MAP-28] (HIGH) **Test 1 — Not-yet-built.** The feature does not exist in DeepBench today. Deepening something already built or already underway is P5 - Enhancements (`ARCHITECTURE.md:2544`), never P2, no matter how new the deepening is. — *grounds:* John, live in chat, 2026-09-14: "these are enhancements to existing features, and should go to that class."
- [C-MAP-29] (HIGH) **Test 2 — Real demand.** Someone has actually asked for it or hit its absence — John's own stated want, a trusted-beta-tester ask, a live demo-evaluator's question, or documented outside pain (community forums, industry reports) — not speculation about what might be nice. — *grounds:* John, live in chat, 2026-09-14: "what people are asking for."
- [C-MAP-30] (HIGH) **Test 3 — The real competitors structurally won't build it.** The competitor set is Copilot, ChatGPT, and Claude — not the vertical multi-agent frameworks in the categories above (John, live in chat, 2026-09-14: "I see co-pilot, chat-gpt, and claude as my biggest competitors"). A candidate passes only if it is too vertical, too accountability/trust-heavy for a mass-market consumer product, or in conflict with that competitor's own business model (e.g., a paid resale marketplace cuts into their own API revenue) — not merely "they haven't shipped it yet." **Named exclusions, still real and valuable capabilities, just disqualified from counting as P2 by this test:** multi-agent orchestration (real, shipped, §19d Agent Loop — excluded because frontier labs are racing to ship it as infrastructure, not because it isn't genuine), persistent agent memory (`AGT-60`, reclassified P6), and agent self-training/self-improvement (the self-building platform, §19v — P1/P3, not P2; see the catalog). DeepBench cannot out-resource that race on any of the three. — *grounds:* John, live in chat, 2026-09-14: "as soon as they allow multi-agent communication, agent knowledge storage and behavior/reasoning self improvements/training... deepbench is no longer valid."
- [C-MAP-31] (HIGH) **Test 4 — Durability.** Even where test 3 holds today, ask how long a well-resourced fast-follower would need to clone it if they changed their mind. A feature clonable from a screenshot in a sprint is weak P2; one that requires years of accumulated data, a domain relationship, or case history is strong P2. **Clarification (2026-09-16):** a competitor operating inside someone else's chat interface (a clever prompt in ChatGPT or Claude, not persistent governed software) has zero durability by definition — it doesn't clear this test regardless of how impressive the output looks on LinkedIn. — *grounds:* Claude's recommendation (SaaS/moat-strategy synthesis — counter-positioning is real but not permanent), confirmed by John in chat 2026-09-14; the interface-vs-software clarification from John's own observation, live in chat, 2026-09-16: "everytime i talk to someone or see someone bragging on linked in... i know they are doing work inside of an interface like Claude or chatgtp - not actually creating software."
- [C-MAP-32] (HIGH) **Test 5 — Compounding asset.** Does shipping it make DeepBench's own accumulating asset (trained Skills/Capabilities content, provenance/attribution history, case history) more valuable the longer the platform runs — or is it a one-time UI/workflow feature a competitor could clone without inheriting any of that asset? Ties directly to §0b: "the deeper the DEEP, the more valuable the BENCH." — *grounds:* Claude's recommendation, confirmed by John in chat 2026-09-14.
- [C-MAP-33] (MED, soft flag not a disqualifier) **Test 6 — Starting-market fit** (renamed from "beachhead fit," 2026-09-16, John: plainer word). Does it deepen the specific vertical DeepBench is actually positioned to win first — government procurement/agencies via the NIGP lineage (`customer.md` C-CUST-16) — rather than being generically novel with no named buyer? A feature can still be worth building without this, but it ranks lower than one that hits the starting market. **Reads together with the platform being business-agnostic by design (John, founding concept):** the starting market is a deliberate first narrowing of a generic capability, not a ceiling on what DeepBench can serve. — *grounds:* Claude's recommendation, confirmed by John in chat 2026-09-14.
- [C-MAP-34] (HIGH) **Whitespace decays — recheck, don't lock forever.** A "the real competitors structurally won't build this" claim (test 3) can go stale overnight — a lab ships something, a startup launches. Every P2 classification carries an implicit recheck, not a permanent status. — *grounds:* carried forward from the retired C-MAP-27; still true, now attached to the right test.
- [C-MAP-35] (HIGH) **Test 7 — Intelligence-native, not code-native.** The strongest P2 candidates are not UI screens, data tables, or deterministic workflow logic (`enable_web_search`/schema/routing — the kind of thing the Capability Badge Rule, `ARCHITECTURE.md §12`, already separates from real AI work). The bar: does the value come from the model's own reasoning, decisioning, and communication — replacing a judgment call, a direction-setting decision, or an answer a human previously had to personally provide — rather than from code someone wrote? A feature can pass tests 1–6 and still be a "coded" feature dressed as inventive; the strongest candidates need no new deterministic logic at all, only a new *framing* for capability the model already has. — *grounds:* John, live in chat, 2026-09-14: "something that is more intelligence oriented - shows ai reasoning, decisioning, and communication - something that does not have to be coded, and would previously take a human to direct, decide, and provide an answer."

### Strategy — how a P2 candidate actually gets found and validated

- [C-MAP-49] (HIGH) **Source candidates from three places only — never internal speculation alone.** (1) John's own stated wants, weighted highest (`evidence-sources.md` C-src-20: his words outrank inference everywhere in the corpus). (2) Live evaluator or customer questions — what someone asked for while looking at the real product. (3) Outside industry research, dated and cited. An idea that only exists because it sounded clever in a design session does not clear Test 2. — *grounds:* inference from the session's own working pattern, 2026-09-14 through 2026-09-16.
- [C-MAP-50] (HIGH) **Never trust a "the real competitors won't build this" claim without checking it live.** The discipline that makes Test 3 honest rather than wishful: run a dated web search naming real, current products before writing the claim down. This is not optional caution — it already reversed two candidates this session (`C-MAP-54`, `C-MAP-55`). — *grounds:* live findings, 2026-09-15/16.
- [C-MAP-51] (MED) **Prefer candidates that also hit Test 5 (compounding) and Test 6 (starting-market) over ones that only pass 1–3.** A candidate can be genuinely P2 and still be a weak first pick if it doesn't compound the DEEP asset or serve the starting market — rank, don't just admit. — *grounds:* inference from the seven-test structure itself.
- [C-MAP-52] (MED) **Recheck on a cadence, not once.** Carried from `C-MAP-34`: whitespace closes overnight, so a confirmed P2 entry is a snapshot, not a permanent grant. — *grounds:* carried forward from C-MAP-27/34.

### Research method — the inventor's questions (added 2026-09-16, John: "what questions do you ask and what needs to be researched")

The concrete checklist behind the Strategy above — what to actually ask and go check before an idea earns a Candidates entry:

- [C-MAP-62] (HIGH) **What is the buyer doing instead, right now, with no DeepBench?** The real substitute — a manual process, a competitor tool, nothing — is the thing being displaced. If the honest answer is "nothing, they don't feel the pain," it fails Test 2 regardless of how clever the idea is.
- [C-MAP-63] (HIGH) **Is someone already charging money for a narrow slice of this?** A startup or product selling even a thin version is a demand signal (Test 2) and a competitor to name (Test 3/4) at the same time — `C-MAP-54`'s AskVerdict/MindMesh finding came directly from asking this.
- [C-MAP-64] (HIGH) **Why, specifically, would Copilot/ChatGPT/Claude not build this — business model conflict, mass-market design, or liability — and is that reason still true today?** A vague "they probably won't" is not a Test 3 pass; naming the actual mechanism is.
- [C-MAP-65] (HIGH) **What are people complaining about in the last 30 days, not the last year?** Recency matters more than volume — a two-year-old complaint may already be solved. Sources: mainstream tech press (TechCrunch, Fortune, WSJ), named analyst surveys (Gartner, McKinsey, Dynatrace-style reports), and community (Reddit, Discord, Hacker News) — spread across all three, not just one.
- [C-MAP-66] (MED) **What does DeepBench's own usage data show people trying and failing to do?** `ai_activity_log` behavioral evidence — retries, abandoned tasks, manual workarounds — is real demand even with zero explicit asks.
- [C-MAP-67] (MED) **If DeepBench didn't build this, would the buyer build it themselves or hire a consultant?** Distinguishes a real budget line from a nice-to-have.
- [C-MAP-68] (HIGH) **Who has tried this before, and what happened?** Find the closest named products and state what each has and lacks with a dated source — the exact table format `AGT-77`'s adversarial moat verification already used. Skipping this is how a candidate turns out to already be commoditized after it's been pitched, not before.
- [C-MAP-69] (HIGH) **Does this require something only DeepBench has — its specific data, its specific architecture, or John's own judgment — or could a fast-follower assemble it from public parts in a sprint?** The Test 4/5 check, asked as a direct question rather than left implicit.
- [C-MAP-70] (MED) **Is this a real business outcome (revenue, risk, compliance, time saved) or an impressive AI trick?** The Test 7 check in plain words — would a buyer's finance or compliance team care, or only an engineer?
- [C-MAP-71] (MED) **What would have to be true in 12 months for a competitor to make this obsolete?** Forces the whitespace-decay recheck (`C-MAP-34`/`52`) to happen before shipping, not after a lab announcement makes it moot.
