## CONTEXT

The Agent Console (LAV screen, `/`) has a ~10s dead window between clicking Run and the first
sign of life. This isn't new: `LiveAgentViewScreen.jsx:1-3` (`LAV-13`, shipped v7.0.41) already
records John hitting this live — *"a run's first delegation can be 10+ seconds out; until then
the canvas is empty... a steady badge read as a frozen screen"* — and shipped a pulsing status
badge as a stopgap. This session replaces the stopgap with a real countdown-dial overlay, per a
visual reference John supplied (`deepbench-console-loader.html`).

**Corrected premise from discovery (important for the coding session to understand, not just
implement):** there is no event that creates the first agent node — every roster agent renders a
`.lav-node` card unconditionally from first paint (`AgentNetwork.jsx:1575-1633`), which is *why*
the resting canvas reads as dead rather than merely quiet. What John actually means by "an
agent's avatar appears" is a real, named mechanism: **"Choreographed" mode** (a toggle,
`LiveAgentViewScreen.jsx:438`, defaults on) holds unengaged agents in a **bench queue**
(`computeTargets()`, `AgentNetwork.jsx:487-498`, literally the "queue" — a vertical stack at
`x: STACKX`) and promotes the first engaged agent to the **`LEAD` slot** on the choreograph arc
(`AgentNetwork.jsx:477-479`) the instant `net.engaged` gets its first entry. `engaged` and
`activeId` are both set inside the same `if (id)` block in `deriveNetwork()`
(`AgentNetwork.jsx:303-313`) — the first `runHops` entry carrying *any* `agentId` (a real
delegation or a quiet assembly-work fetch, either one), not specifically a `delegation`-typed
event. That is the real, verified dismissal trigger.

The screen already exposes everything needed to derive it: `canvasRunHops`
(`LiveAgentViewScreen.jsx:500`) is the run-scoped hop list already fed to `AgentNetwork`, and
`running`/`awaiting` are existing hook state — no new state machine, per John's explicit
constraint.

## TASKS (4)

1. **New component `src/components/ConsoleBootDial.jsx`.** Visual structure ported from
   `deepbench-console-loader.html` (concentric SVG rings + 6°-spaced tick marks, a sweep
   element, a large numeral, a caption line, corner ornaments) — **every hardcoded hex in that
   reference becomes a `tokens.js` reference** (`T.brass`/`T.brassLight`/`T.navyDeep`/etc.), the
   numeral uses `display` (Fraunces), the caption uses `mono` (JetBrains Mono).
   - **Counter:** a `useRef` holds the run's start timestamp, set once on mount (`if
     (!startRef.current) startRef.current = Date.now()` — the standard guard that makes React 18
     StrictMode's dev-only double-invoke a no-op instead of a restart). A `requestAnimationFrame`
     loop (started in a mount effect, cancelled in its cleanup) recomputes whole elapsed seconds
     each frame and only calls `setState` when the integer actually changes — never runs while
     the component isn't mounted.
   - **Caption line:** shows the run's real status text, passed in as a `statusMessage` prop
     (see Task 2) — not invented canned "stage" copy. Fall back to a static, neutral line (e.g.
     "Starting run…") only when `statusMessage` is null.
   - **45s ceiling, riding the same clock:** once the internal elapsed-seconds value reaches 45,
     the component renders `null` on its own (self-hides) rather than waiting for the parent to
     stop passing it as mounted — this is the "can never orphan on a hung request" guarantee.
     This is the one place a clock legitimately gates dismissal; it does not replace the
     event-driven unmount in Task 2, it backstops it.
   - **`prefers-reduced-motion`:** matched via a media query (CSS `@media` in the component's own
     scoped `<style>`, or `window.matchMedia` — coding session's choice); slows the sweep's
     rotation and removes the breathing-scale animation. Do not disable the seconds counter or
     the fade transitions.
   - Reuse global `fadeIn`/`borderPulse` for enter/exit and any pulsing accent; add **no new
     global keyframes**. A component-scoped keyframe (like `AgentNetwork.jsx`'s own
     `lavRipple`/`lavOrchFlash`) is fine if the visual genuinely needs something none of the
     three existing ones cover (e.g. the tick-mark radar sweep wedge) — keep any such addition
     scoped to this component's own `<style>` tag, never `tokens.js`.
   - Exact copy (dial title, caption fallback wording) is the coding session's judgment within
     the constraints above and the established "Console" terminology (`LAV-14`) — keep it short
     and revisable, this is a Tier-1 wording call, not a locked term.

2. **Derive the mount/unmount boolean in `LiveAgentViewScreen.jsx` — no new state.**
   ```js
   const booting = running && !awaiting && !canvasRunHops.some(h => h.agentId);
   ```
   Pass `booting` and `statusMessage={status?.message ?? null}` into **both** `<AgentNetwork>`
   call sites (`LiveAgentViewScreen.jsx:814` mobile, `:1008` desktop — line numbers approximate,
   confirm against current file). Do not add a new state variable, ref, or effect at the screen
   level for this — the boolean is a pure derivation of `running`/`awaiting`/`canvasRunHops`,
   all of which already exist and already reset correctly per-run via the existing
   `runStart`/`question_boundary` mechanism (`LiveAgentViewScreen.jsx:479-484`). Verify (don't
   assume) that this reset behavior actually produces `booting: true` again on a second run in
   the same session before calling this task done.

3. **Mount point in `AgentNetwork.jsx` — both layouts.** Accept `booting`/`statusMessage` as new
   props on the component's top-level signature. Render
   `{booting && <ConsoleBootDial statusMessage={statusMessage}/>}` as an absolutely-positioned,
   inset-0 child of `.lav-stagewrap` — the wrapper class shared verbatim by both the mobile
   return (`AgentNetwork.jsx` ~L1355) and the desktop return (~L1471), which is what makes one
   component work unmodified on both layouts (confirmed both are `position:relative` via the
   same `NET_CSS` rule). Explicit `z-index` above `.lav-orch-flash` (10) so it sits over the
   resting node grid / mobile solo-card on both layouts. Add `<FeatureBadge id="LAV-16"/>` next
   to each branch's existing badge(s) — never remove `LAV-1`/`MOB-4`.

4. **Node.js test** (scratchpad only, never staged): unit-test the `booting` derivation directly
   (extract it as a small pure function if that makes it testable in isolation, or replicate the
   exact expression against fixture `canvasRunHops`/`running`/`awaiting` values — either way,
   import/exercise the real logic, not a hand-copied re-implementation). Assert: true the instant

   run; true again on a fresh run once `canvasRunHops` resets. Plus `npm run build` must pass.
