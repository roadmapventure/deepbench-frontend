**How that is handled here, and why this shape and not either of the two obvious ones:**

- **Not "make it fail."** The check would ship red, and a permanently-red gate is a gate the suite
  learns to ignore — the outcome `SES-180` shipped `continue-on-error` to avoid.
- **Not "put it in the allowlist."** A sanctioned broker and a known debt sitting in one list is how
  debt becomes architecture: the next reader cannot tell them apart, and the entry stops being a
  finding.
- **Shipped instead: two separate sets.** `BROKER_FILES` (sanctioned by §19c) and
  `DECLARED_EXCEPTIONS` (known debt — each carries its reason and its ticket id, and the script
  **prints every one on every run**, green or not). The debt stays visible on every invocation, and
  a *new* violation still fails. A frontend read of the Library is John's call to close, not the
  runner's to quietly re-title as compliance — so it is also filed as its own ticket (§6) and named
  on the ship card.

## 5. Scan scope — stated, because an unstated scope is where a grep check quietly goes vacuous

- **Scanned:** `api/`, `lib/`, `src/`, `shared/`, `scripts/`.
- **Not scanned:** `tests/` — a regression test importing the broker is testing it, which is the

- **The scanner reads the repo's own files from disk**, so a new file is covered the moment it

  contact with a future session, and it is why the allowlists name *permitted* files rather than the
  scanner naming *files to check*.

## 6. QA plan — discriminating, per the step-7 bar

The question the bar asks is *"would it still pass if the change did nothing?"*

- **Negative control (the load-bearing arm):** the guard writes a fixture file that imports
  `lib/librarian.js` from a non-allowlisted path and asserts the **real, imported** scan function
  flags it. A checker that returned `[]` unconditionally — the way `SES-199`'s rubber stamp exit(0)'d
  on every path — fails this arm.
- **Positive control:** the same function, run over the real repo, returns **zero** unsanctioned
  importers — proving the check is green because the codebase is clean, not because the scanner
  matches nothing.
- **Both directions on the exception mechanism:** a declared exception is *reported* and does not
  fail; a violation in a file that is **not** declared *does* fail. A one-directional assertion
  passes on a scanner nobody can trip.
