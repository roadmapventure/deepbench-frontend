# THE FIX SHAPE, AND WHY IT IS NOT ONE OF THE TICKET'S THREE

`SES-215` named three candidate shapes and asked that the cost of (c) be measured before choosing.
None of the three is what shipped, and the deviation is named here rather than buried (the `SES-196`
convention):

- **(a) — a placeholder value the reader recognises and skips on.** Fixes *this* reader for *this*
  variable. The next pair of tests sharing any other variable is the same bug again. Worse, the
  sentinel string `"regression-placeholder"` would then have two homes — the seven writers and the
  reader — which is the exact fact-with-two-homes failure this platform has paid for repeatedly.
- **(b) — consumers read a purpose-specific variable.** For `LOG-41` that means dropping its
  `VITE_SUPABASE_ANON_KEY` fallback. That silently converts a real assertion into a permanent NOT
  RUN wherever only the `VITE_` name is supplied, which is weakening the coverage the ticket's own
  BOUNDARY forbids weakening.
- **(c) — one process per test.** It does generalise, and its cost is not the startup time the
  ticket worried about: `run-all.js` reads each test's declared not-run parts out of a **module-level
  buffer** (`takeNotRun()`, `SES-180 (b)`). Across a process boundary that buffer is unreachable, so
  (c) forces the runner to re-read its own declarations by parsing stdout — a second reader of an
  unversioned format, i.e. `SES-45`'s *"a second implementation agreeing with itself"*. It would also
  put `SES-28`'s self-run guard and `SES-61`'s suite-invocation meta-test back in scope. That is an
  `L`, and this ticket is stamped `S`.

**What shipped instead is the generality of (c) without its cost, in one file:** `run-all.js`
snapshots `process.env` before each test and restores it afterwards. This is John's directive read
literally — *"isolate **or restore** the env var around the offending tests"* — with the restore
placed once, in the runner, rather than seven times in the writers. It fixes the whole class (any
variable, any pair of tests), it leaves `takeNotRun()` in-process and untouched, and it costs one
shallow object copy per test file.

**The property that makes it correct rather than merely tidy:** every test in this suite must already
pass under a direct `node <file>` run (`SES-28`'s self-run guard makes that run real). A per-test env
restore is precisely what makes the in-suite environment equal the standalone one — so it does not
invent a new contract, it enforces the one the suite already claims.

# WHAT MUST NOT BE DONE

- **Do not delete or weaken `LOG-41`'s anon arm.** It asserts both directions of `DAT-18`'s grant
  posture and is real coverage. The defect is that it ran against a fake key, never that it exists.
- **Do not add `continue-on-error` to the regression job**, and do not skip the test. `SES-180 (c)`
  made this job a real gate on every push; a green-by-exemption suite is the thing the gate exists
  to prevent.
- **Do not "strengthen" the restore into a whole-process reset** (e.g. re-reading `.env`). The
  snapshot is the parent process's env as it stood when the run began; that is the only baseline the
  runner can honestly claim.
- **Do not special-case `VITE_SUPABASE_ANON_KEY`.** A named-variable restore is (a) wearing a
  runner's clothes, and it would not have caught the *next* variable.
