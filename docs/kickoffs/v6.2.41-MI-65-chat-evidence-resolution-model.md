## 2. CONTEXT

Design-session walkthrough with John (worktree `design-mi65-ia-0714`), traced live in the code rather than assumed:

Today, the moment Priya's hypothesis test result comes back, **two things happen simultaneously**: `onSelectHypothesis` pushes a full card (headline + Supports/Complicates/Consider, byline, elapsed caption) into chat via `setMessages` (L2081), *and* `setHypFlow` (L2082) puts Evidence into its `"result"` stage showing the identical content plus the actual decision UI (Info Only / Store as Forecast buttons, and — if Store as Forecast — a full Elena→Nadia commit flow ending in a `ConfirmationCard` review, all Evidence-only). Chat's card looks finished (full analysis, a "Formatted by" byline, an elapsed-time caption) but isn't — nothing is decided yet at that point. The real outcome only reaches chat later, as a bare one-line `hyp_discard` message: `"Kept as info only — nothing stored in the Data Room."` or `"Saved — Nadia (Data Expert) logged this. Find it anytime under Agent & Data Info → Analysis."` — no analysis content, easy to miss in scrollback.

John's question, confirmed as the fix: **should all decisions/interactions stay in Evidence, and only the finalized piece land in chat?** Yes — this reframes the "duplication" complaint entirely. It isn't that two columns show the same thing; it's that chat shows the *wrong* thing (a stale mid-flow snapshot) at the wrong time, and the real outcome shows up too thin, too late. Fix: defer the chat push from test-completion time to resolution time, and fold the resolution outcome into the same card instead of a separate disconnected line.

**No new mock cycle** — confirmed with John. This reuses the existing `hypothesis_test` card's exact visual treatment (border/header/byline/elapsed-caption, `STYLE-GUIDE.md` §20 actor-first header unchanged) verbatim; the only new visual element is a resolution-stamp line inside the existing card, color-coded using the Supports/Complicates/Consider palette already established in the same card (`T.moss`/`T.flag`/`T.mutedDeep`), not a new pattern.

**Confirmed with John:** the confirmation review's "Edit" path (user tweaks Nadia's proposed action, loops back into Evidence for another review round) is **not** terminal — no chat push until it actually resolves (accept/reject after however many edit rounds).

**Zero mobile-specific code needed, by construction** — `InteractColumn`/`MessageBubble` are the single shared component tree for both desktop and mobile (`STYLE-GUIDE.md` §21, the `bare` prop composition from `MI-51`/`MI-45`), so this change applies identically on both without a second code path.
