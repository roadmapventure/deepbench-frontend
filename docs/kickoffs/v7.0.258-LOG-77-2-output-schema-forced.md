## 3. THE DECIDED SHAPE

- **Write time, one site, read off the body actually sent — never re-derived from inputs.** `buildCallBody()` sets `tool_choice: { type: 'tool', … }` on exactly the forced branch (two returns: the `hasSplit` branch and the fallback, `:264-273`) and `{ type: 'auto', … }` whenever harness tools or web search are present (`needsAutoChoice`, `:215`). So the ground truth is `callBody.tool_choice?.type === 'tool'`, computed in `callModel()` **after** `buildCallBody()` and returned on the turn.
- **`traits.schema` is NOT a substitute, and this is the whole reason the fact is needed.** A `can_request_help` or web-search intent has a schema *and* `tool_choice: 'auto'` — schema-present ≠ schema-enforced. Deriving this from config would be confidently wrong on exactly the rows that distinguish the pattern.
- **Boolean, omitted when false** — the `LOG-49` fact-2 posture (`if (inputReferencesOtherDeliverable) facts.input_references_other_deliverable = true`). Absent means "not forced / unknowable", never "false". A text-output call has no `tool_choice` at all and correctly never gets the key.
- **No `execute.js` change, verified rather than assumed.** `runLoop()` takes `callModel()`'s whole turn (`execute.js:1161`) and hands it to `sendRequest()` as `precomputed_turn` (`:1403`); the facts ride back as `_terminal_log.call_facts` and merge onto the surviving agent-turn row (`LOG-91`, `request-receivable.js:1180-1187`). Both of `sendRequest()`'s branches are threaded so the non-precomputed callers (`api/plan.js`, `confirmation.js`) are covered too.
- **No Supabase migration.** `log_row_signature()` is `COALESCE(l.call_facts,'{}') || jsonb_build_object(<derivations>)`, so a new write-time key reaches the assembled signature wholesale, with no view change.
