## 2. CONTEXT

`CreateWorkOrderScreen.jsx` uses a strict two-column grid (`STYLE-GUIDE.md` §15, locked 2026-06-23): `gridTemplateColumns: "42% 1fr"`, left column has a fixed-`minWidth:200` PM picker card and a 2-column deliverable-tile grid, right column renders plan output. This predates the mobile-development line and has zero `useIsMobile()` handling — confirmed by reading the file directly, no `isMobile` reference anywhere in it.

At a real 390px mobile viewport this doesn't reflow: 42% of 390px is ~164px of usable left-column width, but the PM picker card's hard `minWidth:200` overflows that column regardless, squeezing the divider and right column to near-illegible widths. Deliverable tiles compress to ~78px each. Confirmed by reading the actual grid CSS, not guessed.

Design was iterated live against an interactive HTML mock recreating the real broken grid first, then the proposed fix, at [claude.ai/code/artifact/e204903c-84a1-4aea-8ba1-7f564afb0d0e](https://claude.ai/code/artifact/e204903c-84a1-4aea-8ba1-7f564afb0d0e) — John reviewed and approved live.

**Locked decisions (all confirmed by John, do not re-litigate):**
1. **No overlay pattern needed, unlike `DB-23`.** This grid is fluid (`42%/1fr`), not a fixed-px sidebar competing for space — it collapses to a single stacked column below the mobile breakpoint. Left-column content (Steps 1-3 + Generate Plan) first, right-column output (Step 4: title, plan summary, step cards, questions, Approve & Launch) directly below once a plan exists — the same top-to-bottom reading order the desktop grid already implies. No content dropped, no new interaction pattern.
2. **One JSX tree, not a duplicated `if (isMobile) return (...)` branch** (unlike `AppShell.jsx`/`DashboardScreen.jsx`). The only mobile-conditional pieces are a handful of style values: `gridTemplateColumns`, the divider's border, and the deliverable-tile grid's column count. Everything else (all the interactive logic, state, handlers) is already shared and untouched.
3. **Deliverable tiles** (Step 1): `gridTemplateColumns` goes from `'1fr 1fr'` to `'1fr'` on mobile — each tile was compressing to ~78px, illegibly narrow.
4. **PM picker cards** (Step 2): already `display:flex; flexWrap:wrap`, no structural change needed — the fixed `minWidth:200` stops being a problem once the column itself is full-width (~358px at 390px viewport minus padding) instead of ~164px.
5. **Divider:** the 1px vertical `borderRight` between columns (`STYLE-GUIDE.md` §15) is omitted on mobile — nothing left to divide once it's one column.
6. **Single-PM label fix (`AW-30`), both desktop and mobile:** when exactly one agent has a "Project Manager" role, John's call — the current "Step 2 — Select a Project Manager" label reads as if the system is blocking the user from proceeding, when there's nothing to actually choose between. Change the label text (only) to **"Step 2 — FYI, Your project manager is:"** — same font/size/case/style as the existing label, condition is purely on `pmAgents.length === 1` (not hardcoded to Michelle by name) so it reverts to "Select a Project Manager" automatically the moment a second PM agent is added to the roster. **No other behavior changes** — the card stays exactly as clickable/selectable as it is today; John asked for the label text only, nothing else.
7. **`STYLE-GUIDE.md` §15 gets a mobile addendum** documenting the collapse rule and the two mobile-conditional style values, same pattern every other mobile session this cycle has followed for its own locked section.

## 8. NODE.JS TEST

```js
// test-S-MOBILE-WO-01.mjs
// Pure logic tests — no app imports. Mirrors CreateWorkOrderScreen.jsx's pmAgents derivation
// and the single-PM label condition (Category B).

let pass = 0, fail = 0;
function assert(desc, cond) {
  if (cond) { console.log(`  ✓ ${desc}`); pass++; }
  else       { console.error(`  ✗ ${desc}`); fail++; }
}

function derivePmAgents(agents) {
  return agents.filter(a => a.role?.toLowerCase().includes('project manager'));
}
function step2Label(pmAgents) {
  return pmAgents.length === 1 ? "Step 2 — FYI, Your project manager is:" : "Step 2 — Select a Project Manager";
}
function gridColumns(isMobile) {
  return isMobile ? "1fr" : "42% 1fr";
}
function tileGridColumns(isMobile) {
  return isMobile ? "1fr" : "1fr 1fr";
}

// T1: single PM agent — FYI label
const oneAgent = [{ id: "michelle", role: "Project Manager" }, { id: "bob", role: "Data Analyst" }];
const pm1 = derivePmAgents(oneAgent);
assert("T1a: exactly 1 PM agent derived", pm1.length === 1);
assert("T1b: label is the FYI variant", step2Label(pm1) === "Step 2 — FYI, Your project manager is:");

// T2: multiple PM agents — original select label, unchanged
const twoAgents = [{ id: "michelle", role: "Project Manager" }, { id: "diego", role: "Project Manager" }, { id: "bob", role: "Data Analyst" }];
const pm2 = derivePmAgents(twoAgents);
assert("T2a: 2 PM agents derived", pm2.length === 2);
assert("T2b: label is the original select variant", step2Label(pm2) === "Step 2 — Select a Project Manager");

// T3: zero PM agents (edge case — should not crash, falls to select variant since !== 1)
const pm0 = derivePmAgents([{ id: "bob", role: "Data Analyst" }]);
assert("T3a: 0 PM agents derived, no crash", pm0.length === 0);
assert("T3b: label falls back to select variant, not FYI (never true for an empty list)", step2Label(pm0) === "Step 2 — Select a Project Manager");

// T4: role matching is case-insensitive (mirrors the existing .toLowerCase() call)
const mixedCase = [{ id: "michelle", role: "PROJECT MANAGER" }];
assert("T4a: case-insensitive role match still finds 1 PM agent", derivePmAgents(mixedCase).length === 1);

// T5: grid column values
assert("T5a: mobile grid is single column", gridColumns(true) === "1fr");
assert("T5b: desktop grid is unchanged 42%/1fr", gridColumns(false) === "42% 1fr");
assert("T5c: mobile deliverable tile grid is single column", tileGridColumns(true) === "1fr");
assert("T5d: desktop deliverable tile grid is unchanged 2-column", tileGridColumns(false) === "1fr 1fr");

console.log(`\n${pass + fail} tests — ${pass} passed, ${fail} failed`);
if (fail > 0) process.exit(1);
else console.log("ALL TESTS PASS");
```
