## 2. CONTEXT

Desktop's `AuditColumn` renders 5 drawers via one shared component, `Drawer` (`SharedUI.jsx`) — Agent Routing, Agents, Data Sources, Analysis, Agent Reasoning (confirmed via grep: these are the component's only 5 call sites, all in this one file). Only Agent Routing passes `maxHeight` (`280`, `MI-34`) — a static internal cap with `overflowY:"auto"`; the other four drawers already grow unbounded to fit their content (this is `MI-41`'s already-logged, still-open finding: `AuditColumn`'s outer wrapper has no height cap of its own, so a tall drawer already pushes the page past the viewport today — currently framed as an unintended bug for those four, since nobody asked for it there). This session makes that same "grow past the fold" behavior *deliberate and user-controlled*, scoped to just the Agent Routing drawer via a drag handle — it does not touch `MI-41`'s open question for the other four drawers.

**Confirmed design (John, one question at a time):**
1. Drag floor is the existing default (`280`) — cannot shrink below it, only grow.
2. Drag ceiling is `min(80vh, the drawer's real content height)` — refuses to grow past what the content actually needs (no empty padding space) or past 80% of the viewport.
3. Not persisted — resets to `280` on every page reload, plain component state.
4. Plain brass/treasury grip bar at the bottom edge of the drawer's content area, only rendered when the drawer is open and resizable; resize cursor (`ns-resize`) on hover.

## 5. TASKS

### Task 1 — `src/components/SharedUI.jsx`: opt-in drag-resize on `Drawer`

`Drawer` (~line 323) gains one new optional prop, `resizable = false` — backward-compatible, every existing call site (Agents/Data Sources/Analysis/Agent Reasoning, none of which pass it) is byte-unaffected.

- New internal state: `const [dragHeight, setDragHeight] = useState(null)` — `null` means "use the passed `maxHeight` unchanged" (the pre-existing behavior). Reset happens for free — this is plain component state, unmounts/remounts (and therefore resets) on every page load, matching the "not persisted" decision.
- A ref (`contentRef`) on the drawer's content wrapper div (the one that currently gets `maxHeight`/`overflowY` when `maxHeight` is passed) to read its true, unclamped content height via `contentRef.current.scrollHeight` — `scrollHeight` reports full content height regardless of the `overflowY:"auto"` clip, so this works whether or not the box is currently scrolled/clamped.
- Extract a pure, testable helper (Architect Review: reuse/testability, matches the existing pattern of `groupDataSources()`/`buildActivitySummary()` — small pure functions pulled out of render logic specifically so Node tests don't need a real DOM):
  ```js
  // clamps a candidate drag height to [floor, min(contentHeight, viewportHeight * 0.8)]
  export function clampDrawerHeight(candidateHeight, floorHeight, contentHeight, viewportHeight) {
    const ceiling = Math.min(contentHeight, viewportHeight * 0.8);
    return Math.max(floorHeight, Math.min(candidateHeight, ceiling));
  }
  ```
  Exported alongside `Drawer` (same file) so the Node test can import and assert it directly.
- Effective height each render: `dragHeight == null ? maxHeight : clampDrawerHeight(dragHeight, maxHeight, contentRef.current?.scrollHeight ?? maxHeight, window.innerHeight)`.
- Grip handle: rendered only when `resizable && open`, a thin horizontal bar (`height: 6`, full width, `cursor: "ns-resize"`, brass on hover — matches the existing treasury palette, no new colors) positioned at the bottom of the content wrapper (outside the `overflowY:"auto"` clip, so it's always reachable regardless of scroll position). `onMouseDown` captures the starting mouse Y and starting effective height, then attaches `mousemove`/`mouseup` listeners on `window` for the drag (removed on `mouseup`) — `setDragHeight` called on each `mousemove` with the raw candidate (`startHeight + (currentY - startY)`); clamping happens at render time via `clampDrawerHeight`, not inside the drag handler, so the handler itself stays simple and the clamp logic is the one place covered by the Node test.
- No change to `Drawer`'s existing `maxHeight`-not-passed behavior (the other 4 drawers) — the new logic only activates when `resizable` is explicitly true.

## 6. DESIGN RULES

- The floor is always the passed `maxHeight` — never shrinkable below the drawer's own default.
- The ceiling is always `min(80vh, real content height)` — never empty padding space, never past 80% of the viewport.
- Dragging past the content ceiling simply stops growing the box (no error, no visual glitch) — the user's cursor may move further than the box does; this is expected, not a bug to chase.
- Not persisted across reloads — always starts at the default height.
- Only Agent Routing opts in this session; the shared `Drawer` component's default behavior for every other consumer is unchanged.

## 7. SCOPE RULES

- Does NOT touch `MI-41`'s open finding (the other 4 drawers' own lack of a height cap) — different, already-logged item, not this session's job.
- Does NOT add a resize handle to the mobile pinned Agent Routing feed — that's a completely different render path (`MobileBody`, not `Drawer`), out of scope by construction (John's ask was desktop-only).
- Does NOT persist the resized height anywhere (no localStorage, no Supabase) — confirmed with John.
- Serverless function count: unchanged (no `api/` file touched).
