## CONTEXT

**Bug (AA-144), found 2026-07-07 during `S-ARCH-DELEGATION-REQUIRED-01`'s own post-fix live verification — a distinct, pre-existing bug, not caused by that session's fix.**

`api/capabilities/execute.js`'s `runLoop()` has two different shapes a completed `delegateResult` can take:

- **Ordinary terminal dispatch** (`sendRequest()` in `request-receivable.js`, line ~396): returns `{ ...result, content: parsedResponse, patterns_used, violations, debug, ... }` — real output lives under `.content`.
- **Final delegation** (`execute.js` line ~390-397, the `turn.tool_input.is_final === true` branch): returns `{ status: 'final_delegation', ...delegateResult.content, patterns_used: finalPatterns, display_agent_card, display_agent_id, selection }` — the delegate's real fields are spread flat at the top level. **No `.content` key at all.**

`AA-126`'s empty-content guard (execute.js line ~371):
```js
if (!delegateResult.content || Object.keys(delegateResult.content).length === 0) {
  throw new Error(`delegate_to_agent: ... returned no content for a final delegation ...`);
}
```
checks `delegateResult.content` before accepting a final delegation. This is correct when `delegateResult` came from an ordinary `sendRequest()` call. But when a `delegate_to_agent(is_final:true)` hand-off **recurses** — the delegate itself terminates via a *second*, nested `is_final` delegation — `delegateResult` here is itself a flat `final_delegation`-shaped object with no `.content` key. The guard reads `undefined`, and throws "returned no content" even though the nested call produced perfectly good content (just spread flat instead of nested).

**Live-observed 2026-07-07:** the "fail" MI seed question ("How is our authorized reseller network performing in Vietnam?" — `EXAMPLE_QUESTIONS`, `src/screens/MarketIntelligenceScreen.jsx:44`) hit exactly this error text after `delegate_to_agent` had genuinely fired (confirmed via grep that `AA-126`'s empty-content branch only runs when `turn.is_delegate_call` is true). The exact recursion depth/path (was Marcus picked as his own display agent, did a third-level hop occur) wasn't captured by the script that surfaced it — this is a plausible, code-grounded root cause, not yet reproduced with a full call-stack trace, but the shape mismatch itself is confirmed by direct code read, not assumed.

**Why this belongs in the "MI Loop — Solid & Fast" priority track (John, 2026-07-07):** this is a live crash on the exact chat path the 3 seed questions exercise, and the fix is a harness-level shape normalization — not a patch scoped to one question. Sequenced first (ahead of `AA-112`/`AA-121`) because it's the most direct "does the chat actually work" bug still open, with a root cause already nailed down to two specific lines.

**Related, deliberately NOT part of this session's scope:** `lastHelpSelection` (execute.js line ~322-323) reads `delegateResult?.content?.reasoning ?? null` after a `request_help` hop to the `project-manager` capability — the identical shape-confusion pattern, in theory. **Task 1 — Extract and fix `buildFinalDelegationResult()` in `api/capabilities/execute.js`.**

Add a new named export, placed near the other small helpers (e.g. right above `runLoop()`):

```js
// FEATURE: AA-144 -- extracted from runLoop()'s inline is_final block so the shape-normalization
// fix below is unit-testable without hitting Supabase/Anthropic. Fixes AA-126's empty-content
// guard misfiring on a NESTED final_delegation: delegateResult may itself be a flat
// final_delegation-shaped object (no `.content` key) when an is_final hand-off recurses into a
// second is_final hand-off. The single-line fix: always mirror the real content under a `.content`
// key on every final_delegation result, in addition to the existing flat spread -- this makes the
// shape self-describing/consistent at any recursion depth, so a nested guard check (or any future
// reader) can rely on `.content` being populated whenever real content exists, same invariant the
// ordinary sendRequest() shape already provides. The flat spread is unchanged -- byte-identical to
// today for the frontend (MarketIntelligenceScreen.jsx's callCapability() returns `result` verbatim
// whenever `result.status` is set, so an added `content` key is additive, never breaking).
export function buildFinalDelegationResult({ delegateResult, targetAgentId, targetCapabilitySlug, targetIntentSlug, finalPatterns, displayAgentCard, lastHelpSelection }) {
  const content = delegateResult.content;
  if (!content || Object.keys(content).length === 0) {
    throw new Error(`delegate_to_agent: ${targetAgentId}/${targetCapabilitySlug}${targetIntentSlug ? '/' + targetIntentSlug : ''} returned no content for a final delegation (violations: ${JSON.stringify(delegateResult.violations || [])})`);
  }
  return {
    status: 'final_delegation',
    content,
    ...content,
    patterns_used: finalPatterns,
    display_agent_card: displayAgentCard,
    display_agent_id: targetAgentId,
    selection: lastHelpSelection,
  };
}
```

Note: this is almost identical to the current inline code — the ONLY behavioral change is the added `content,` line. The guard condition, the flat spread, and every other field are unchanged.

import { strict as assert } from 'assert';
