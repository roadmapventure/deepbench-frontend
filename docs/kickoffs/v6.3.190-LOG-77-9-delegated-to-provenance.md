## 2. CONTEXT

When a reviewing capability (live case: Owen Marsh — The Proofreader, `qg-review-intent`) fails a candidate answer and delegates back to the very agent/capability that produced it to regenerate, the log today records only "a delegation happened" — indistinguishable from a linear chain or ordinary orchestration. That re-dispatch-of-the-producer hop is the one structural fact that distinguishes an evaluation-gated loop; Susan Smith — Trainer formally ruled (MISSING SIGNAL, `design-log-72b-0728`) she cannot author Evaluator-Optimizer criteria without it.

**The decided shape (John, 2026-07-28, this design session — do not re-litigate):**
- **Write time (Log Writer, generic):** on every `delegate_to_agent` turn row, capture two verbatim facts, **no comparison, no conclusion**: `call_facts.delegation_target` (who the model dispatched to) and `call_facts.task_provenance` (the producer keys the execution's `task_context` arrived carrying). No verdict is read anywhere — the verdict postdates the delegation and on a successful retry is never declared as a fail at all (measured live, trace `3559ac69`).
- **Read time (Displayer view):** derive boolean `delegated_to_provenance` — target matches provenance on `agent_id` AND `capability_slug` — exactly the `integration_followed` posture: emitted `true`/`false` only when both backing facts carry both keys, **omitted otherwise** (unknowable ≠ false).
- **Signature:** `delegated_to_provenance` joins `SIGNATURE_FIELDS` at **position 7, directly after `integration_followed`** (16 → 17 entries — John's placement call). The two backing facts are **plumbing, never criteria keys** (they contain literal agent ids; the signature is agent-agnostic, §19k locked constraint 2 — same exclusion as `span_id`/`parent_span_id`).

### Task 1 — `api/prompt/request-receivable.js`: the pure extractor (shared home with LOG-49's extractor)

Directly below `extractSelfReportedClaims`, add:

```js
// FEATURE: LOG-77-9 -- ARCHITECTURE.md §19k `delegated_to_provenance` backing facts. Verbatim
// capture only, no comparison, no conclusion (§19i: the writer captures links, never the
// conclusion) -- the derived boolean lives in the Displayer view, never here. The three keys are
// the platform's own delegation vocabulary (delegate_to_agent's schema / §19d's task_context
// candidate source) -- generic, never a capability-specific read.
export const PROVENANCE_KEYS = ['agent_id', 'capability_slug', 'intent_slug'];

// Returns { delegationTarget, taskProvenance }, each null when it has no string-valued keys --
// preserving the "omit the key entirely when empty" contract (mergeCallFacts null handling).
export function extractDelegationProvenanceFacts(toolInput, taskContext) {
  const pick = (src) => {
    if (!src || typeof src !== 'object' || Array.isArray(src)) return null;
    const out = {};
    for (const k of PROVENANCE_KEYS) {
      if (typeof src[k] === 'string' && src[k] !== '') out[k] = src[k];
    }
    return Object.keys(out).length > 0 ? out : null;
  };
  return { delegationTarget: pick(toolInput), taskProvenance: pick(taskContext) };
}
```
