## 1. CONTEXT

DeepBench is live on the open internet on `main`, with API auto-reload credits. Anyone with the URL can trigger real model calls without limit. John's design (settled in `S-HAR-33-design`, 2026-08-08):

- Everything keys off the existing `ip_org_cache` table (one row per unique caller IP) — **no separate whitelist, no environment-variable allowlists.** John manages access by editing rows.
- `permission` ∈ `blocked` / `trial` / `unlimited`. US callers default to **trial** ($5 spend cap, per-row adjustable via `spend_limit_usd`); non-US callers are **blocked** on their first model call; **unlimited** is the whitelist value John sets by hand.
- Crossing the cap **writes** `permission='blocked', block_reason='spend_cap'`. Geo blocks write `block_reason='geo'`. John unblocks by editing the row (raise `spend_limit_usd`, or set `trial`/`unlimited`).
- Spend is **computed from `ai_activity_log` tokens × `model_pricing` rates at check time** — never stored as a running total (cannot drift; `ai_activity_log.cost_usd` is legacy, 43/33,427 rows, never use it).
- Blocked visitors can still browse the site and its read-only data — only model-triggering API calls are refused.
- A refusal is a structured 403 JSON the frontend (part b) turns into a friendly popup. The model is never called; a refused request costs $0.
- The gate must **fail open** on its own infrastructure errors (Supabase unreachable, malformed row): cost protection must never become an outage for good users. Log the error to console (visible in Vercel function logs) and let the request through.

**The migration below is ALREADY APPLIED** by the design session (columns, `model_pricing`, `get_ip_stats()`, `ip_spend_report`, index). Do not re-run it. It is reproduced here as the schema contract you are coding against.

```sql
-- Reference only — applied 2026-08-08 by S-HAR-33-design via Supabase MCP
alter table public.ip_org_cache
  add column permission text not null default 'trial'
    check (permission in ('blocked','trial','unlimited')),
  add column user_label text,
  add column spend_limit_usd numeric not null default 5.00,
  add column blocked_at timestamptz,
  add column block_reason text
    check (block_reason is null or block_reason in ('spend_cap','geo','manual')),

  returns table (llm_calls bigint, total_tokens bigint, cost_usd numeric)
  -- sums tokens×rates incl. cache multipliers (creation 1.25x, read 0.10x input rate),
  -- joined on model_pricing; EXECUTE revoked from public/anon/authenticated
```

## 4. TASKS (3)

### Task 1 — `middleware.js` (NEW, repo root — the only committed code file)

Vercel Edge Middleware. This does not count against the 12-serverless-function limit (`api/` count stays 12/12).

```js
export const config = { matcher: '/api/:path*' };
```

Flow, in order (each step exact):

1. **Pass through immediately, zero Supabase reads:** `OPTIONS` requests (CORS preflight), and the browse-safe read pairs `GET /api/agent-configs`, `GET /api/load-entries`. Everything else on `/api/*` is a potential model/embedding trigger and is gated.
2. **Bypass header:** if `req.headers.get('x-db-gate-bypass') === process.env.GATE_BYPASS_SECRET` (and the env var is non-empty), pass through. This is the exemption for Claude QA scripts and regression drivers (John-approved). Never log the secret.
3. **Derive caller IP** exactly like `lib/request-context.js`'s `deriveCallerIp` (first entry of `x-forwarded-for`, trimmed; Vercel overwrites client-supplied XFF so this is not client-spoofable in production) — the value MUST match what `ai_activity_log.caller_ip` stores, or spend sums miss. Country from the `x-vercel-ip-country` header. **No IP derivable (local `vercel dev`) → pass through** (fail open).
4. **Fetch the row:** `GET {SUPABASE_URL}/rest/v1/ip_org_cache?caller_ip=eq.{ip}&select=permission,spend_limit_usd,block_reason,country` with `SUPABASE_SERVICE_KEY`.
   - `permission='unlimited'` → pass.
   - `permission='blocked'` → refuse (step 6) with the row's `block_reason`; also fire-and-forget increment `blocked_attempts` (+ set `blocked_at=now()` if null) via `context.waitUntil`.
   - `permission='trial'` or no row → step 5.
5. **Trial checks:**
   - Country present and ≠ `'US'` → upsert the row (`permission='blocked'`, `block_reason='geo'`, `blocked_at=now()`, `country`, `blocked_attempts=1` or +1) and refuse with reason `geo`. (Upsert `on_conflict=caller_ip` with `resolution=merge-duplicates` — the row may already exist from logging.)
   - Otherwise call `POST {SUPABASE_URL}/rest/v1/rpc/get_ip_stats` with `{"p_ip": ip}`. If `cost_usd >= spend_limit_usd` (row's value, default `5.00` when no row): upsert `permission='blocked'`, `block_reason='spend_cap'`, `blocked_at=now()`, increment `blocked_attempts`, and refuse with reason `spend_cap` **including the stats**. Else: if no row existed, fire-and-forget insert a minimal `trial` row (`caller_ip`, `country`) so John sees every IP that ever hit a model route; then pass.
6. **Refusal shape (the part-b contract, exact):** HTTP 403, `Content-Type: application/json`, plus the same three CORS headers `vercel.json` sets on `/api/*`. Body:
   ```json
   { "deepbench_gate": true,
     "reason": "spend_cap" | "geo" | "manual",
     "ip": "<caller ip>",
     "stats": { "llm_calls": 137, "total_tokens": 412806, "cost_usd": 5.02 } }
   ```
   `stats` is present only for `spend_cap` (from `get_ip_stats`, `cost_usd` rounded to 2 decimals). For a stored `blocked` row, `reason` is the row's `block_reason` (fallback `"manual"` if null).
7. **Any thrown error / non-OK Supabase response anywhere → `console.error` one line and pass through** (fail open). No retries, no latency budget beyond the two sequential fetches.
