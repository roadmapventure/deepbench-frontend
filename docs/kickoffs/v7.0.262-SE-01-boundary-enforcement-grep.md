## 2. CONTEXT

`ARCHITECTURE.md` carries two **[LOCKED]** boundary rules that nothing mechanical enforces:

- **§5** — *"No capability route calls `/api/rag-query` via internal HTTP. All RAG retrieval imports
  `queryRAG` from `api/lib/rag.js` directly. `api/rag-query.js` remains as a thin public handler for
  external/frontend callers only."*
- **§6** — *"No AI calls in Railway. No Playwright in Vercel. This line is permanent."*

The ticket's own history is the argument for the ship: the equivalent grep was run **by hand once**,
on 2026-07-02, came back clean, and was never runnable again. A boundary checked once is a boundary
that holds until the next person who has not read §5 adds a `fetch("/api/rag-query")` inside a route
because it is the obvious thing to do.

**PREMISE REVALIDATED LIVE THIS CYCLE, not recalled** (`SES-87`, register B7). `scripts/` holds ten
`check-*.js` scripts and **none** covers §5 or §6 — the gap is real. Both boundaries currently
**PASS**, which is the right moment to install a check: it pins a clean state rather than shipping a
red one.

## 3. THE PROPERTY THIS SHIP TURNS ON

**A mention is not a call, and this check fails uselessly if it cannot tell them apart.** The naive
grep — `grep -r "/api/rag-query"` and `grep -ri playwright` — returns four hits on today's clean
tree, and **all four are legitimate**:

| Hit | Why it is NOT a violation |
|---|---|
| `src/screens/TestTeamScreen.jsx:51` — `fetch("/api/rag-query")` | §5 sanctions this **by name**: `api/rag-query.js` exists *for* frontend callers. `src/` is not a capability route. |
| `scripts/check-ai-logging-coverage.js:51` — `"/api/rag-query"` in a route list | A check script naming a route, not calling it. |
| `src/screens/FetchScreen.jsx:180` — `· Playwright` | UI label text shown to a user. |
| `shared/ai-patterns.js:20` — `'Playwright-controlled browser execution…'` | A capability *description* string. |

So the naive check reports 4 violations where there are 0 — and a check that cries wolf on its first
run is deleted or allowlisted into vacuity within a week. This is `SE-06`'s own lesson (14 files
mention "librarian" in prose) arriving at the second boundary, and the shape of the fix is the same:
**match the mechanism, not the noun.**

- §5 fires on an **internal HTTP call** — `fetch`/`axios`/`got`/`request` whose URL contains
  `/api/rag-query` — and **only inside `api/`**, because "capability route" is what the rule scopes.
- §6 fires on an **import/require of playwright**, never on the word.

## 7. DECLARED NOT-RUN — the half this repo cannot check

**"No AI calls in Railway backend" is NOT enforced by this script, and that is a boundary of the
repo, not an omission of effort.** `ARCHITECTURE.md` §7 is explicit that Railway is a **separate
repo** — `roadmapventure/deepbench-backend` — and this session's GitHub scope is
`roadmapventure/deepbench-frontend` only. A grep run here can say nothing about a tree it cannot
read.

The half that **is** enforceable here is the other side of the same §6 sentence — *no Playwright in
Vercel* — and that ships. The Railway half needs either a check that runs in the backend repo's own
CI or a cross-repo runner; it is named on the ship card as `SE-01`'s declared remainder rather than
quietly folded into a green result. **Do not "fix" this by scanning a vendored copy or by asserting
the absence of a directory that was never in this repo** — an assertion that cannot fail is worse
than a missing one, because it reads as coverage.

## 8. WHAT THIS DOES NOT DO, said rather than left to be found

- **It is a grep and claims only what a grep can.** A URL built by concatenation
  (`fetch(BASE + path)`) or a dynamic `import(pkg)` evades it. That is not a hole to plug with
  cleverer patterns: every violation this class of boundary has actually suffered was written plainly,
  because nobody bypassing an architecture rule is hiding — they are unaware. Aimed at the mistake,
  not at an adversary.
- **It does not wire itself into `verifier.js`'s gates.** Adding a fourth mechanical gate changes what
  `approve` means for every ticket in the Selfbuild family and is a governance change, not a tooling
  one — that is John's call on a card, and `SES-181`'s own charter premise ("no change certifies
  itself") is the reason a cycle does not grant it to itself.
