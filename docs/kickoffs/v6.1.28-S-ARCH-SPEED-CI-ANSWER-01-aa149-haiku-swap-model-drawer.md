## 1. CONTEXT

Real production data (`ai_activity_log`, `tenant_id in ('global','apple-demo')`, excluding all synthetic test tenants) shows Marcus's `ci-answer-intent` (Sonnet, `channel-intelligence`) is **37.6% of all real LLM time platform-wide** — 93 calls, avg 28.5s, more than 2x the next-largest single intent. This is the top Speed priority per `AA-149`'s live-measured finding (`session/speed-rootcause-0708`, 2026-07-08): hand-off/routing overhead is real but small (6-9%) and noisy; the actionable lever is raw generation time on the heaviest Sonnet hops.

**Design-session live test (2026-07-08, this session, 4 real questions x 2 models against the dev URL via an isolated test-only intent slug, zero live-traffic risk):**

| Question | Sonnet | Haiku | Result |
|---|---|---|---|
| Japan growth | 24.7s | 9.4s | 2.6x faster. Citations/confidence_tier/needs_review match. |
| Greater China decline | 27.5s | 8.3s | 3.3x faster. Citations match exactly, same nuance. |
| Nordholm claims/utilization | 27.2s | 10.5s | 2.6x faster. Citations match exactly, same dual-driver reasoning. |
| EMEA co-op QoQ change | 33.1s | **51.8s (slower)** | Haiku unnecessarily called `request_help`/delegated on a simple "the data doesn't cover Q2" case, ballooned to 7,593 tokens and tripped the durable-checkpoint/resume path before finishing. Final content was still correct once resumed. |

3 of 4 real questions: Haiku matches Sonnet on citation accuracy, `confidence_tier`, and `needs_review` correctness at 2.6-3.3x speed. 1 of 4: Haiku took an unnecessary delegation detour on ambiguous "did this change" phrasing — same fragile checkpoint/resume machinery `AA-151` already flags as a live risk elsewhere. This session ships both the model switch and a small instruction guard against that specific detour, plus a way to see per-model results in the Agents drawer going forward (any future model experiment on any intent becomes visible automatically, not just this one).

**Confirmed via `information_schema`:** `ci-answer-intent`'s prompt is dominated by its 5-chunk RAG retrieval (the actual sourced Data Room content it must cite), not verbose instructions — ~5,000-5,600 combined input+output tokens per call, `max_tokens: 1500` already tight. This is why the fix is a model-tier change, not a prompt trim (trimming RAG breadth would directly cut the sourced material Marcus is required to cite from).

**No harness/loop/platform code is touched.** `execute.js`, `request-receivable.js`, and `db-assembly.js` stay byte-identical — model selection is entirely Skill-Profile data (`skill_profiles.llm_model`, read by the existing generic `assemblePrompt()`), the same mechanism that already differentiates every other intent in this system.

**Test-data note:** a temporary isolated skill profile (`ci-answer-intent-haitest`) and its `capability_skill_profiles` link were created directly by this design session to run the comparison above — never reachable by Marcus's real routing (`ci-routing-intent` never emits that slug), zero live-traffic risk. **Task 0 below deletes both rows** — do this first, before the real `ci-answer-intent` update, so there is never a window with two Haiku-tagged rows live at once.

```js
// FEATURE: AA-149 -- extracted from the fetchAll().then() callback so the aggregation math
// (now including per-model breakdown) is unit-testable without mocking Supabase/React. Same
// classifyRow()-driven kind bucketing as before, byte-identical output for every existing
// caller -- this only adds a new byModel sub-bucket inside each kind, never removes anything.
export function buildActivitySummary(scopedRows, turnTimestampsByAgent) {
  const map = {};
  for (const row of scopedRows) {
    if (!map[row.agent_id]) map[row.agent_id] = { calls: 0, totalCost: 0, costCount: 0, byKind: {} };
    const d = map[row.agent_id];
    d.calls++;
    if (row.cost_usd) { d.totalCost += parseFloat(row.cost_usd); d.costCount++; }

    const { kind, include } = classifyRow(row, turnTimestampsByAgent);
    if (!include) continue;
    if (!d.byKind[kind]) d.byKind[kind] = { calls: 0, totalLatency: 0, latencyCount: 0, maxLatency: null, byModel: {} };
    const k = d.byKind[kind];
    k.calls++;
    if (row.latency_ms) {
      k.totalLatency += row.latency_ms;
      k.latencyCount++;
      k.maxLatency = k.maxLatency == null ? row.latency_ms : Math.max(k.maxLatency, row.latency_ms);
    }

    const modelKey = row.model || 'unknown';
    if (!k.byModel[modelKey]) k.byModel[modelKey] = { calls: 0, totalLatency: 0, latencyCount: 0, maxLatency: null };
    const km = k.byModel[modelKey];
    km.calls++;
    if (row.latency_ms) {
      km.totalLatency += row.latency_ms;
      km.latencyCount++;
      km.maxLatency = km.maxLatency == null ? row.latency_ms : Math.max(km.maxLatency, row.latency_ms);
    }
  }
  Object.values(map).forEach(d => {
    d.avgCost = d.costCount ? d.totalCost / d.costCount : null;
    Object.values(d.byKind).forEach(k => {
      k.avgLatency = k.latencyCount ? Math.round(k.totalLatency / k.latencyCount) : null;
      Object.values(k.byModel).forEach(km => {
        km.avgLatency = km.latencyCount ? Math.round(km.totalLatency / km.latencyCount) : null;
      });
    });
  });
  return map;
}
```
