## 2. CONTEXT

**Premise revalidated live at pick time, and it is the whole ticket.** `thread()`,
`orphanThreads()`, `readingSlot()` and `readingRecordedLine()` read `state` and **only** `state` —
not one of them queries Supabase. `briefing-template.html` shipped a hardcoded **empty**
`briefing-state` block, so a cycle rebuilding the page structurally from the template published
that blank block and **John's entire ask history and every meter reading left the page**, while the
page still looked finished.

His own taps were never the problem: `doc()`, the page's self-publish, serialises the **live**
state, so a tap preserves its own thread. Only a **rebuild** wiped.

## 6. DESIGN RULES

- **The DB is the home; the page is a render.** The seed regenerates state rather than the page
  carrying it forward, which also retires the `v7.0.166` "two homes" problem for readings.
- **A sentinel, not a blank.** Valid empty JSON is indistinguishable from a correct state once
  published and is the most natural thing for a later editor to "restore" while tidying. The
  default is now something that cannot be mistaken for a state.
- **Forgetting must be loud.** The banner uses the page's existing red-defect vocabulary — the same
  choice as the line a NULL `plain_*` summary draws.
- **Never claim data was lost.** The ledger is untouched by an unseeded rebuild. The honest message
  is *"this page is not showing you everything"*, never *"your threads were deleted"*.
