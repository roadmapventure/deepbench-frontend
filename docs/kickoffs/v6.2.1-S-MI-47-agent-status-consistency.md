## 2. CONTEXT

John found this live, screenshotting a real Q&A turn on the deployed MI screen, and flagged three things:

**1. Two-tone styling looks inconsistent, not intentional.** `S-MI-42` (v6.1.43) added a `kind: 'scripted' | 'orchestration'` field to `workingStatus` — `'orchestration'` (a live delegation event straight from the harness) renders bold/upright/dark-ink, `'scripted'` (a macro-hop status line) renders italic/muted/normal-weight. This was a deliberate design choice at the time (distinguish "a real routing decision just happened" from "routine status"), but reads to John as broken inconsistency, not a signal. **His call: remove the two-tone distinction entirely — every status line renders in the original light/italic/muted style, regardless of `kind`.**

**2. The "expect…" time estimate silently disappears the moment a real delegation fires.** `setStatus(message, {expectation, kind})` (line ~1458) currently destructures `{ expectation = null, kind = 'scripted' } = {}` — any call that doesn't explicitly pass `expectation` gets it hard-reset to `null`. `onDelegationProgress` (every live handoff) never passes `expectation` at all, so the moment the first real handoff fires mid-turn, whatever chain-level estimate was already showing (e.g. "expect > 45s" after `intent_routing` resolved) gets wiped for the rest of the turn.

**Separately, John also wants a running total-elapsed clock that doesn't exist today** — only a per-agent clock exists (resets to 0 every handoff, via the `key={startedAt}` remount). Walked through with him directly (see conversation): the exact value needed already exists in the code as a local `turnStart` const (`submit()` ~1497, `onSelectHypothesis()` ~1556), used today only to compute the *final* "Full Agent Routing & Answer Given in Xs" caption after the turn ends. This session lifts it into live `workingStatus` state (`turnStartedAt`) so it can also drive a live-ticking display during the turn, carried forward across every handoff instead of reset.

**Approved format** (locked with John, exact wording): `<total elapsed> (<per-agent time> this Agent) - question ><estimate>`, e.g. `17s (0s this Agent) - question >45s`. The existing "expect" label is renamed to "question" throughout (`formatExpectation()`'s output and the one hardcoded initial-floor string in `submit()`).

**3. The Agent Routing drawer skips real hops.** The drawer (`AuditColumn`, fed by `pipelineEvents`/`logEvent()`) and the live chat status line (fed by `onDelegationProgress`/SSE) are two separate event pipelines. The chat line sees every real handoff (`request_help`, `critique`, `delegate_to_agent`, `delegation_return`); the drawer only ever receives the small set of coarse checkpoint events (`intent_routing`, `qa_answer`, `proofreader`, `agent_selection`, `display_format`, etc.) logged at 4-5 fixed points per turn. A turn can flash 3-4 live handoff messages in the chat and only 2-3 rows ever land in the permanent drawer — John's exact "Marcus back-to-back, missing what happened between" observation. **His call: log every handoff shown in the chat as its own permanent drawer row too**, alongside the existing coarse rows (this session does not remove or replace any existing event type — it adds two new ones).

**Explicitly out of scope (spun off separately, `task_b7f55ec0`):** why the Librarian/RAG lookup and other silent backend mechanisms (roster lookup, guardrails-check, Dan Bingham's prompt-enrichment calls) never emit any event at all. That's a deeper backend-instrumentation question with no existing event-emission hook to extend — a different kind of session than this one, which only touches the two pipelines that already exist and already fire.

### Task 2 — `MarketIntelligenceScreen.jsx`: total-elapsed clock, carried across every handoff

**2a.** `setStatus` (~1458) — carry `turnStartedAt` forward across calls within the same turn (only set fresh when `workingStatus` was `null`, i.e. a new turn), and stop clobbering `expectation` to `null` by default — only overwrite it when a caller explicitly passes a value:
```js
const setStatus = (message, { expectation, kind = 'scripted' } = {}) =>
  setWorkingStatus(prev => ({
    message,
    startedAt: Date.now(),
    turnStartedAt: prev?.turnStartedAt ?? Date.now(),
    expectation: expectation !== undefined ? expectation : (prev?.expectation ?? null),
    kind,
  }));
```
This is additive/backward-compatible: every existing call site that omits `expectation` (lines 457, 471, 491, 1602, 1616, 1655 — e.g. `"Owen is reviewing…"`, `"Elena is consolidating this into memory…"`) now carries forward whatever `expectation` was already set (or stays `null` if this is the first call of a fresh turn, e.g. `onCommit`'s Elena step — matches today's documented "no chain, no estimate" behavior for those flows, since `workingStatus` is `null` going in). Explicit-`null`-passing call sites (the `est != null ? formatExpectation(est) : null` pattern at ~1478/1562) are unaffected — `undefined !== null`, so an explicit `null` still writes through.

**2b.** Update the call site (~1345) to pass the new prop:
```js
{workingStatus && <AgentWorkingIndicator key={workingStatus.startedAt} message={workingStatus.message} startedAt={workingStatus.startedAt} turnStartedAt={workingStatus.turnStartedAt} expectation={workingStatus.expectation}/>}
```
(`kind` prop dropped from this call site too — no longer read by the component, per Task 1a; still present on the `workingStatus` object itself for Task 3's use.)

**2c.** Update the `workingStatus` state comment (~1448): `// { message, startedAt, turnStartedAt, expectation, kind } | null`.

No other call site changes needed — `key={workingStatus.startedAt}` still forces a remount per handoff (correct, resets the per-agent clock's own tick loop cleanly), and `turnStartedAt` being a stable, carried-forward timestamp means `now - turnStartedAt` computes correctly across remounts without needing a second non-remounting component.

let pass = 0, fail = 0;
function check(name, cond) {
  if (cond) { pass++; console.log(`PASS: ${name}`); }
  else { fail++; console.log(`FAIL: ${name}`); }
}

// ── setStatus() merge/carry-forward semantics — Category B ──────────────────
function makeSetStatus(getPrev) {
  return (message, { expectation, kind = 'scripted' } = {}) => {
    const prev = getPrev();
    return {
      message,
      startedAt: 2000, // fixed for test determinism
      turnStartedAt: prev?.turnStartedAt ?? 2000,
      expectation: expectation !== undefined ? expectation : (prev?.expectation ?? null),
      kind,
    };
  };
}

check("first call of a turn (prev null) sets turnStartedAt fresh", (() => {
  const setStatus = makeSetStatus(() => null);
  const r = setStatus("Marcus is thinking…", { expectation: "question < 2m" });
  return r.turnStartedAt === 2000 && r.expectation === "question < 2m";
})());

check("handoff call (no expectation passed) carries turnStartedAt AND expectation forward", (() => {
  const prev = { message: "x", startedAt: 1000, turnStartedAt: 500, expectation: "question > 45s", kind: "scripted" };
  const setStatus = makeSetStatus(() => prev);
  const r = setStatus("Marcus Webb is asking Michelle Manning who should help…", { kind: "orchestration" });
  return r.turnStartedAt === 500 && r.expectation === "question > 45s";
})());

check("explicit expectation overrides carried-forward value", (() => {
  const prev = { message: "x", startedAt: 1000, turnStartedAt: 500, expectation: "question < 2m", kind: "scripted" };
  const setStatus = makeSetStatus(() => prev);
  const r = setStatus("...", { expectation: "question > 14s" });
  return r.expectation === "question > 14s";
})());

check("explicit null expectation is honored, not treated as 'no value passed'", (() => {
  const prev = { message: "x", startedAt: 1000, turnStartedAt: 500, expectation: "question > 45s", kind: "scripted" };
  const setStatus = makeSetStatus(() => prev);
  const r = setStatus("...", { expectation: null });
  return r.expectation === null;
})());

check("fresh turn with no historical estimate stays null (onCommit's Elena step, unchanged behavior)", (() => {
  const setStatus = makeSetStatus(() => null);
  const r = setStatus("Elena is consolidating this into memory…");
  return r.expectation === null && r.turnStartedAt === 2000;
})());

check("second hop of a multi-hop flow (Elena -> Nadia) carries turnStartedAt across, no reset", (() => {
  let state = null;
  const setStatus = (message, opts) => { state = makeSetStatus(() => state)(message, opts); return state; };
  setStatus("Elena is consolidating this into memory…");
  const nadia = setStatus("Nadia is drafting a data patch…");
  return nadia.turnStartedAt === 2000; // same as Elena's call, not reset
})());

// ── formatExpectation() — Category B, renamed label ──────────────────────────
function formatExpectation(ms) {
  const roundedSec = Math.ceil(ms / 1000 / 5) * 5;
  const m = Math.floor(roundedSec / 60);
  const s = roundedSec % 60;
  return m > 0 ? `question > ${m}m ${s}s` : `question > ${s}s`;
}
check("under 60s uses 'question > Xs'", formatExpectation(14000) === "question > 14s");
check("at/above 60s uses 'question > Xm Ys'", formatExpectation(90000) === "question > 1m 30s");
check("no lingering 'expect' string anywhere in output", !formatExpectation(45000).includes("expect"));

// ── describePipelineEvent() new cases — Category B ───────────────────────────
function describePipelineEvent(evt) {
  switch (evt.type) {
    case "delegation":
      return { capability: null, summary: evt.data.message, color: "T.navyMid" };
    case "delegation_return":
      return { capability: null, summary: evt.data.message, color: "T.moss" };
    default:
      return { capability: null, summary: "", color: "T.muted" };
  }
}
check("delegation event summary passes through the precomputed message unchanged", (() => {
  const r = describePipelineEvent({ type: "delegation", data: { message: "Marcus Webb is asking Michelle Manning who should help…" } });
