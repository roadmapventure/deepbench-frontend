## Premise, revalidated live before building

Read from `pg_get_viewdef('public._backup_schema_ddl')` this cycle, not recalled. The `acl-raw`
section emits

```
'-- relacl for public.' || relname || ': ' || coalesce(relacl::text, '(default)')
```

at `sort_key` 11 — a **comment** — and the view contains no `GRANT` derived from live ACL state
anywhere. There is no `pg_attribute.attacl` section at all. Premise holds, and the census that
goes with it: 68 `acl-raw` rows over 56 tables + 12 views, **0** of them `(default)`; 34 columns
carrying `attacl` (27 on `ai_activity_log`, 7 on `ip_org_cache` — exactly the ticket's figures);
4 grantees, all standard Supabase roles.

**The fix location is the VIEW, not the script**, which is the thing an editor gets wrong here and
which `v7.0.250` already paid for: schema DDL is generated server-side and pulled verbatim, so
patching `dump-supabase.mjs` — which lives in `roadmapventure/deepbench-backups-offsite`, not this
repo — would have changed nothing.

## What shipped

Migration `ses216_backup_schema_ddl_executable_grants`. `CREATE OR REPLACE VIEW` with an identical
column list, so the view's own grants survive and no overload can exist. **224 executable
statements now emit**, where 0 did:

| | count | what |
|---|---|---|
| `sort_key` 12 | 220 | relation grants, one per (relation, grantee, `is_grantable`) |
| `sort_key` 13 | 4 | column grants, one per (relation, grantee, privilege) |
| `acl-raw` | 68 → **70** | provenance record, widened to sequences so it cannot disagree |

**Two measured findings the ticket did not name**, both kept in scope because the ticket's own
success condition (a restored platform the browser can read and write) fails without them:

- **Sequences were captured in no form either.** `acl-raw`'s relkind filter is `('r','p','v','m')`,
  so the 2 public sequences were absent — yet `ai_activity_log_id_seq` carries `anon=rwU`, without
  which `anon`'s `INSERT` fails on a restored platform *with the table grants already correct*.
- **`MAINTAIN` is real and `information_schema` cannot see it** (`DAT-20`). The emission is derived
  by `aclexplode()`, which reports it; a repair built on `role_table_grants` would silently drop a
  privilege the live ACL holds.

### The four properties an editor must preserve

Written into the migration header so they travel with the code:

1. **The column ACLs are not optional, and omitting them rebuilds the `LOG-124` leak.** On this
   build `ai_activity_log`'s relation grant to `anon` is `GRANT INSERT, MAINTAIN … TO anon;` and
   carries **no `SELECT`**; the `SELECT` arrives as a 27-column list with raw `caller_ip` absent.
   The tempting repair for the dark AI Audit screen — `GRANT SELECT ON ai_activity_log TO anon` —
   republishes every visitor's IP.
2. **Sequences need the `SEQUENCE` keyword and a different privilege vocabulary**, hence the
   `relkind` CASE.
3. **A grant is emitted only for an object some other section creates.** The `_backup%` exclusion
   mirrors the `views` section byte-for-byte, because this view never defines the two `_backup_*`
   views (`SES-214`, already carded, deliberately not fixed here). A grant on a relation the set
   never creates does **not** degrade gracefully — it aborts the restore on *"relation does not
   exist"*, turning a documented defect into a hard failure.
4. **Derived by `aclexplode()`, never by parsing ACL text.** `is_grantable` is grouped on rather
   than assumed false; grantee `0` renders as the bare keyword `PUBLIC`, never `quote_ident`'d.

## QA — measured, both directions, and rolled back

The decisive arm is a **round-trip fixture inside a deliberately-failing `DO` block** (the
`SES-147`/`SES-196` pattern), run against production and rolled back by its own `RAISE`. One
variable: capture the emitted statements from the healthy view, strip
`anon`/`authenticated`/`service_role` off five relations, replay, compare.

```
statements_replayed = 224
baseline            = 2848348fbcb76545fc3c3f643e51dcb9
stripped            = 3762ac49ee9722fa5f52380880ae7489   (differs from baseline: t)
after_empty_replay  = 3762ac49ee9722fa5f52380880ae7489   (still stripped: t)   <-- NEGATIVE CONTROL
restored            = 2848348fbcb76545fc3c3f643e51dcb9   (equals baseline: t)
anon table-level SELECT on ai_activity_log = f   (must be false)
anon column SELECTs on ai_activity_log     = 27  (must be 27)
anon SELECT on raw caller_ip               = f   (must be false)
```

The fingerprint is an **exploded**-ACL digest (`aclexplode` over `relacl` and `attacl`, sorted),
not the ACL text, so a faithful restore cannot pass on `aclitem[]` ordering luck. **The negative
control is the emission this replaced**: replaying what it produced — nothing — leaves the
stripped fingerprint unmoved, which is the defect stated as a measurement. Production was
re-read after the block: fingerprint `2848348f…`, unchanged.

Asserted separately, both directions per `SES-101`: the view's own grants survived the replace
(`service_role` `true`; `anon` / `authenticated` `false`) and its column list is unchanged. The
property-3 invariant was measured on the live view — 68 relations granted, 68 created,
**0 orphans**, `_backup%` grants 0 against `_backup%` views created 0.
