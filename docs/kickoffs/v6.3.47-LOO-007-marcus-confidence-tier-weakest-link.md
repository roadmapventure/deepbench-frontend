## 1. CONTEXT

Found live 2026-07-16 during `LOO-006`'s own Category L verification (`continuity-regression-0716`): 7 live re-runs of the identical Nordholm co-op-budget question produced `confidence_tier: sourced` ×3, `inferred` ×2, `synthesized` ×2 — despite `temperature=0` already pinned on `ci-answer-intent` (`AA-154`). Root-caused further in this same design session (`loo-007-confidence-tier-0716`): not a determinism ceiling. Checked `ci-answer-intent`'s full `method` and its schema's `confidence_tier` field description directly — neither one anywhere defines how to resolve `confidence_tier` when an answer's citations span more than one `data_type`. The Nordholm answer genuinely does: it cites one `sourced` chunk (an industry benchmark) and one `synthesized` chunk (the Nordholm scenario record itself). With no rule to anchor a consistent choice, Marcus's own classification varies run to run.

**Why this was blocked on `AGT-023` first, now resolved:** authoring a resolution rule against the `data_type` domain only makes sense once that domain is itself correct. `AGT-023` fixed Eleanor's write schema (removed illegal `learned`, added `consolidated`) — `ci-answer-intent`'s own `confidence_tier` enum (`sourced`/`inferred`/`synthesized`/`na`) was never wrong itself, but the rule this session writes needs to reference `data_type` correctly, and that domain is now settled.

**The fix (John's direction, confirmed live during design):** `confidence_tier` reflects the *weakest* — least-verified — `data_type` among every citation actually used in the answer. If any cited source is `synthesized`, the whole answer is `synthesized`, even if another cited source is `sourced`. Never average, never let the strongest source win.

**Explicitly out of scope, logged separately, not this session:** `AGT-025` (whether `synthesized` is even the right term for fabricated/hypothetical scenario content, vs. `scenario` — confirmed live to be a real naming collision with this platform's existing, correct use of "synthesis" elsewhere, `shared/ai-patterns.js`'s `AA-190b` precedent). Confirmed not a dependency of this session — the weakest-link rule works identically regardless of what the value is eventually called; a future rename would need to touch this session's own authored rule text as one more site in its blast radius, same as it touches `AGT-023`'s schema and `LOO-006`'s `synthesized_as_fact` guardrail rule name.
