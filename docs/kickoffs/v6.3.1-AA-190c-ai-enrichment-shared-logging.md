## 1. CONTEXT

Third and final "known live gap" site from `AA-190`'s original investigation (the other 6 remaining sites — `execute.js`, `request-receivable.js` ×2, `project-manager.js`, `extract.js`, `knowledge-write.js` — are separately queued, not this session).

`api/prompt/ai-enrichment.js`'s REFLECT (STEP 3) and Intelligent Synthesis/Prompt Compression (STEP 4) steps both call real Anthropic completions, and both already capture real token usage into local variables (`reflectTokensUsed`, `synthesisTokensUsed`) — but two bugs sit in how that data reaches `ai_activity_log`:

1. **Hand-rolled logging, not the shared service.** Both sites (lines 283-297, 300-314) are independent `fetch('.../ai_activity_log')` calls — exactly the pattern `AA-190` site 1 found and started closing platform-wide.
2. **Stale/wrong `patterns_used` slugs.** The reflect block hardcodes `patterns_used: ['reflection']` — `AI-50c` (2026-07-14) renamed the catalog slug to `reflect` and this write site was never updated, so **18 real, fully-costed Reflection calls have been invisible in the AI Audit screen since that rename shipped**. The synthesis block hardcodes `patterns_used: ['prompt-chaining']` — wrong pattern entirely; `AA-190` site 2 (this design session, same day) confirmed the correct slug is `intelligent-synthesis` (now displaying as "Prompt Compression"), and fixed `SERVICE_CATALOG`'s `ai-enrichment` entry to list it — but the write site itself still emits the old string.

**Third bug found reading this session, not previously flagged:** both blocks sum input+output tokens into one number (`reflectTokensUsed`/`synthesisTokensUsed`, e.g. line 199: `(reflectData.usage?.input_tokens || 0) + (reflectData.usage?.output_tokens || 0)`), then log the *entire sum* as `input_tokens` with `output_tokens: 0` hardcoded (lines 291-292, 308-309). Since Anthropic's output-token rate is 5x the input rate (`COST_PER_1K_OUTPUT` vs `COST_PER_1K_INPUT`, `useAIActivity.js`), this **prices every REFLECT/Synthesis call at the cheap input-only rate**, understating its real cost. Anthropic's response already returns `input_tokens`/`output_tokens` as separate fields (`reflectData.usage.input_tokens`/`.output_tokens`) — the split is being computed and then immediately thrown away.
