## 1. CONTEXT

Three related Continuity-track bugs, all found 2026-07-15 during `S-ARCH-COMPETENCY-MODEL-design`, converged in one design-session walkthrough with John (2026-07-16) because two of them share the same fix mechanism and the third shares the same file/primitive class.

**`LOO-001` — Michelle can recommend the requesting agent back to itself.** `getRosterCandidates()`/`fetchRoster()` (`lib/project-manager.js`) returns every agent unfiltered — confirmed live, no exclusion of the calling agent. Live-verified this session: **every one of the platform's 14 capabilities is currently single-holder** (e.g. `channel-intelligence` → marcus only, `project-manager` → michelle only) — so whenever a described skill need matches only the requester's own capability, Michelle's own honest reasoning can conclude "best fit: the requester," which is structurally meaningless (an agent's already-stuck reasoning isn't fixed by asking itself again) and burns a real hop off the budget for zero new information.

**`LOO-002` — Michelle's schema has no legitimate "no good fit" output.** Live-verified via direct Supabase query this session: `agent-selection-intent`'s `traits.schema` requires `recommended_agent_id`/`recommended_capability_slug` as non-null strings, with no null/no-match path. Named directly in `docs/FEATURES.md` as a real contributor to `AA-194`'s actual live incident (the Sam Reyes misroute) — when nobody genuinely fits, Michelle is forced to pick her least-bad candidate and write confident-sounding reasoning for a choice she doesn't believe in.

**`LOO-004` — `resolveCapabilityHolder()` skips the `is_active` check.** Live-verified: the function's Supabase query (`agent_capability_assignments?capability_slug=eq...&select=agent_id&limit=1`) has no `is_active` filter, unlike the roster broker's own separate gate (`isActiveAgent()` in `lib/project-manager.js`). This function runs on every `request_help` call platform-wide (always resolves `project-manager`) and every consequential-action critique dispatch — currently latent (zero agents are `is_active: false` today, confirmed live), but the day any agent is deactivated with its `agent_capability_assignments` row left behind, every hand-off platform-wide would silently resolve to a defunct holder.

**Design principle established this session, applied to all three fixes (`ARCHITECTURE.md` §19d sniff test):** `LOO-001`/`LOO-002` are fixed as **reasoning, not filtering** — no code excludes the requester from the candidate list. Instead, the requester's identity is threaded into the same `task_context` payload Michelle already reads (a new `requesting_agent_id` field, generic and always-present, not agent-specific), and her own Skill content is taught to recognize a self-only match as no different from no match at all, using the no-match output `LOO-002` builds. `LOO-004`, by contrast, is legitimately a code-level fix: `resolveCapabilityHolder()` was never a reasoning decision to begin with — `ARCHITECTURE.md` §19d explicitly carves out its two call sites (`project-manager` for `request_help`, `critique_capability_slug` for the consequential-action gate) as pure single-holder infrastructure resolution, not candidate selection. Adding `is_active` there tightens an existing structural gate; it doesn't take away a judgment call from any model, because no model was ever making one.

Explicitly **not** in scope this session (found during the same walkthrough, logged separately per the Backlog Capture rule): `RO-16` (a live `is_active` toggle on the Roster/Personnel screens) — blocked on a real gap (`RosterScreen.jsx`/`PersonnelScreen.jsx` both read the static `AGENTS` mock array via `useAgents()`, never live Supabase `agents` rows) that needs its own design session to resolve the write-path architecture. Logged in `docs/FEATURES-NEXT.md`, not touched here.

### Task 3 — `execute.js`: `is_active` check in `resolveCapabilityHolder()`

File: `api/capabilities/execute.js`, `resolveCapabilityHolder()` (~line 207-219).

Current:
```js
async function resolveCapabilityHolder(capability_slug) {
  const supabaseUrl = process.env.SUPABASE_URL;
  const supabaseKey = process.env.SUPABASE_SERVICE_KEY;
  if (!supabaseUrl || !supabaseKey) throw new Error('Supabase not configured');
  const headers = getSupabaseHeaders(supabaseKey);
  const res = await fetch(
    `${supabaseUrl}/rest/v1/agent_capability_assignments?capability_slug=eq.${encodeURIComponent(capability_slug)}&select=agent_id&limit=1`,
    { headers }
  );
  if (!res.ok) throw new Error(`Failed to resolve holder of capability "${capability_slug}"`);
  const rows = await res.json();
  if (!rows.length) throw new Error(`No agent currently holds capability "${capability_slug}"`);
  return rows[0].agent_id;
}
```

New:
```js
// FEATURE: LOO-004 -- adds the same is_active gate lib/project-manager.js's isActiveAgent()
// already applies elsewhere; this primitive never had one. A deactivated holder is treated
// identically to "no agent holds this capability" -- same error, no new error shape, no new
// decision logic. Two-query shape (not a PostgREST embed) matches the existing isActiveAgent()
// idiom in this codebase rather than introducing a new pattern.
async function resolveCapabilityHolder(capability_slug) {
  const supabaseUrl = process.env.SUPABASE_URL;
  const supabaseKey = process.env.SUPABASE_SERVICE_KEY;
  if (!supabaseUrl || !supabaseKey) throw new Error('Supabase not configured');
  const headers = getSupabaseHeaders(supabaseKey);
  const res = await fetch(
    `${supabaseUrl}/rest/v1/agent_capability_assignments?capability_slug=eq.${encodeURIComponent(capability_slug)}&select=agent_id&limit=1`,
    { headers }
  );
  if (!res.ok) throw new Error(`Failed to resolve holder of capability "${capability_slug}"`);
  const rows = await res.json();
  if (!rows.length) throw new Error(`No agent currently holds capability "${capability_slug}"`);
  const agentId = rows[0].agent_id;
  const activeRes = await fetch(
    `${supabaseUrl}/rest/v1/agents?id=eq.${encodeURIComponent(agentId)}&select=is_active`,
    { headers }
  );
  if (!activeRes.ok) throw new Error(`Failed to verify active status for capability "${capability_slug}" holder "${agentId}"`);
  const activeRows = await activeRes.json();
  if (!activeRows?.[0]?.is_active) throw new Error(`No agent currently holds capability "${capability_slug}"`);
  return agentId;
}
```
