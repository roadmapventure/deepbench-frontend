## 2. CONTEXT

**The user-visible problem:** all six By Pattern rows show `<$0.01`. Real spend is ~$31.

**Why (verified live):** the rollup view computes cost as `sum(ai_activity_log.cost_usd)`, but only **43 of ~22,500** rows carry a stored `cost_usd` and **none** of the classified ones do. Cost on this platform is derived at read time from tokens by `computeCallCost()` (`AA-181`) — Total Cost, By LLM, By Agent and By Service all already do this. By Pattern (added by `LOG-38`) reads the empty SQL column instead.

**This is the second attempt. The first (v6.3.187, `30c2311`) was reverted (`bc74d1e`) — read this before designing anything:** its cost math was correct (15/15 live, classified total $31.29) but it obtained the row→pattern mapping by **paging `ai_call_patterns` directly from the browser**, which exceeds the `anon` role's **3 s `statement_timeout`**. It failed on the first page, and because that read shared one `Promise.all`/`try` with the rollup reads, the failure blanked the entire By Pattern section including the reclassification count. Two lessons now binding on this retry:
1. **Do not add any new query against `ai_call_patterns` or any expensive view.** The panel must not pay a second traversal.
2. **Per-source fallback, never all-or-nothing.** A failure in one read must not remove content another read already fetched successfully.

**The approach that removes the problem instead of working around it (measured, not assumed):** the rollup query *already* traverses exactly the rows we need to attribute. Returning their ids costs almost nothing — benchmarked on the real DB at **2,719 ms with `array_agg(ai_activity_log_id)` vs 2,687 ms without: +32 ms, ~1%** — and adds **zero** round trips. Payload is small: 3,687 ids ≈ 21 KB total (largest pattern 2,648 ids ≈ 15 KB). The client then sums the per-row `cost` values it *already holds in memory* from `hydrateFromSupabase()`.

**Why summing in the client, not in SQL — two reasons, both load-bearing:**
- **Pricing stays in one place.** `computeCallCost()` is the single source of truth for rates; a `CASE WHEN model LIKE …` price table in SQL would be a second copy that silently drifts the next time a rate changes.
- **The dedup comes free and stays consistent.** `hydrateFromSupabase()` already zeroes the `cost` of `AI-51`-paired duplicate rows. This matters enormously here: **1,731 of request-routing's 2,629 classified rows (66%) are paired duplicates** — a naive SQL token-sum would report ~$26.24 against a Total-Cost basis of ~$10.48, reintroducing the reconciliation bug `LOG-92` just fixed.

**Calls stay raw, cost is deduped — deliberate, and already how this screen behaves.** `computeByLLM()` counts every row while summing dedup-zeroed cost; By Agent likewise. So a pattern row's Calls reconciles with Total Calls (raw, per `LOG-92`) and its Cost with Total Cost (deduped). Do not change call counts here — raw-row semantics are owned by `LOG-91`.

**Known, accepted limitation (state it, do not try to fix it):** these costs ride the same rollup query that currently runs at ~2.7 s against the 3 s ceiling and fails intermittently (`LOG-99`, escalated and blocking nothing here). When that read fails the pattern rows are already absent today; costs simply go absent with them. This change adds **no new failure mode** and makes nothing slower by more than ~1%. `LOG-99` remains the reliability fix; `LOG-102` remains the honest-failure-surface fix.

Recreate `ai_pattern_classification_rollup` with one extra column. **Change nothing else** — same columns, same names, same ordering, same grouping:

```sql
CREATE OR REPLACE VIEW ai_pattern_classification_rollup AS
SELECT pattern_slug,
       pattern_name,
       pattern_description,
       (count(*))::integer AS call_count,
       COALESCE(sum(cost_usd), (0)::numeric) AS cost_sum,
       array_agg(ai_activity_log_id) AS log_ids
FROM ai_call_patterns
GROUP BY pattern_slug, pattern_name, pattern_description
ORDER BY ((count(*))::integer) DESC;
```

`cost_sum` is deliberately **kept** (it is the degraded fallback, see Task 2). Migration name: `log_97_rollup_log_ids`. This is a plain view — `§19k`'s "plain view, never materialized" rule still holds, and no pattern name, price, or criteria logic is added to SQL (`.claude/rules/ai-pattern-signature.md` stays satisfied).

### Task 2 — Sum the in-memory costs (`src/hooks/useAIActivity.js`)

`fetchPatternClassification()`: add `log_ids` to the existing `select(...)` string and carry it onto each classified entry as `logIds: r.log_ids || []`. **No new query, no extra request.** Leave `cost: Number(r.cost_sum) || 0` in place as the fallback value.

`usePatternClassification(log = [])`: accept the log and override each pattern's cost with the summed in-memory value, falling back to the view's `cost_sum` whenever the ids or the log are unavailable:

```js
// FEATURE: LOG-97 -- cost per pattern = sum of the hydrated log entries' own `cost` values, which
// computeCallCost() derived from tokens at hydrate time and which hydrateFromSupabase() already
// zeroed for AI-51-paired duplicates -- so these totals reconcile with Total Cost by construction.
// The ids ride along on the rollup read that already happens (+~1%, no new round trip); the first
// attempt at this feature paged ai_call_patterns separately and blew the anon 3s statement timeout.
const costBySlug = useMemo(() => {
  if (!log.length) return new Map();
  const costById = new Map(log.map(e => [e.id, e.cost || 0]));
  const out = new Map();
  for (const p of state.classified) {
    if (!Array.isArray(p.logIds) || p.logIds.length === 0) continue;
    let sum = 0;
    for (const id of p.logIds) sum += costById.get(id) || 0;
    out.set(p.slug, sum);
  }
  return out;
}, [log, state.classified]);

const classified = state.classified.map(p => ({
  ...p,
  cost: costBySlug.has(p.slug) ? costBySlug.get(p.slug) : p.cost,
}));
```

Return `{ ...state, classified }`. Import `useMemo` if not already imported. **`usePatternClassification()` called with no argument must keep working** (default `log = []` → empty map → every row falls back to `cost_sum`, i.e. exactly today's behavior).

  else { fail++; console.log(`  FAIL  ${name} ${detail}`); }

// --- F. The view now returns log_ids, one per counted call, in ONE request ---
const t0 = Date.now();
const { data: rollup, error: rErr } = await supabase
  .from('ai_pattern_classification_rollup')
  .select('pattern_slug, call_count, cost_sum, log_ids');

const rows = [];
{ let from = 0;
  while (true) {

      .select('id, model, input_tokens, output_tokens, ai_type, agent_id, feature, created_at, cost_usd')
      .order('created_at', { ascending: false }).range(from, from + PAGE_SIZE - 1);
    if (error) throw new Error(error.message);

    if (!data || data.length < PAGE_SIZE) break;

const IN = { 'claude-haiku-4-5':0.001,'claude-haiku-4-5-20251001':0.001,'claude-sonnet-4-5':0.003,'claude-sonnet-4-6':0.003,'text-embedding-3-small':0.00002 };

const computeCallCost = (model, i, o) => {
  const m = NORM[model] || model;
  const ir = IN[m] ?? IN[model], or = OUT[m] ?? OUT[model];
  if (ir == null && or == null) return null;
  return ((i||0)/1000)*(ir||0) + ((o||0)/1000)*(or||0);

// AI-51 pairing, same rule as pairedAgentTurnIds()
const WRAPPERS = new Set(['channel-intelligence','hypothesis-evaluation','quality-gate','pipeline-triage','memory-consolidation','data-analysis','project-manager','screen-controls','html-display']);
const wrapperTimes = new Map();

const costById = new Map(rows.map(r => [r.id,
  paired.has(r.id) ? 0 : (r.cost_usd != null ? parseFloat(r.cost_usd) : (computeCallCost(r.model, r.input_tokens, r.output_tokens) || 0))]));

ok(`classified total is materially non-zero (got $${total.toFixed(2)})`, total > 5);

  ok(`request-routing deduped ($${dd.toFixed(2)}) is materially below raw ($${raw.toFixed(2)})`, dd < raw * 0.75);

ok('no log => falls back to cost_sum', fallback({logIds:[1,2]}, 0) === 'cost_sum');
ok('no ids => falls back to cost_sum', fallback({logIds:[]}, 100) === 'cost_sum');
