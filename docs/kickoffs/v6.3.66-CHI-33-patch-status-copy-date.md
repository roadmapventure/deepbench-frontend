## CONTEXT

Three bugs found live-testing `CHI-33` (Column 2 live news feed) against the real deployed dev preview, all root-caused before this doc was written:

1. **Stuck status line.** After `fetchNewsCards()` completes (on mount or Clear), "Jordan is routing this to Alex…" and its elapsed timer stay on screen indefinitely. Root cause, confirmed by code read: every real chat turn (`submit()`'s internal flow) calls `setWorkingStatus(null)` when it finishes; `fetchNewsCards()` uses the same `onDelegationProgress` status-writer (`onProgress` param) but never clears it afterward, on either its success or catch path.
2. **Click-to-analyze misroutes to a dead end.** Clicking a card sends the confirmed question, but Marcus's `ci-routing-intent` classifies it as `escalate` — one of his 5 real routed intents — and the screen shows a static placeholder (`ESCALATE_PLACEHOLDER`, `MarketIntelligenceScreen.jsx` line ~404) instead of ever answering. Root cause: the message copy ("Can you see if the latest news, `<headline>`, affects any channel program positioning?") reads as an open-ended investigative ask to Marcus's classifier, not a direct question. **Confirmed this is a copy problem, not an architecture problem** — real Escalate (Nadia's `data-escalate-intent`, checked live against Supabase) is a heavy, human-confirmed Data-Room-write pipeline, never going to be the right endpoint for a quick in-chat analysis reply even fully built. Fix is a reworded question, not a routing/enum change (that option was considered and explicitly rejected this session — removing `escalate` from Marcus's enum is platform-wide, breaks the screen's own advertised "five ways to work with the Data Room" copy, and Escalate deserves its own real front-door session later, not a side effect of this patch).
3. **Article date already available, never shown.** `card.published_at` is real, live, populated data — confirmed directly against a real `durable_hops` row (`web-search-news`, `2026-07-18`): all 3 real cards carried genuine ISO dates (`"2026-07-15"`, `"2026-07-16"`, `"2026-07-09"`). `NewsCard()` (line ~1512) never renders it — pure frontend omission, no backend/schema/Skill Profile change needed.
4. **Loading-state copy doesn't signal activity (John's request, not a bug).** While `newsCards` is still `null` (genuinely in flight, on mount or right after Clear), Column 2 today shows the same static sentence it always has ("Once Marcus has an answer or a theory to test..."), which reads as idle even though Jordan is actively searching. John's ask: swap in a live "Grabbing the latest headlines... `<elapsed>`" line for this specific in-flight state, so the screen visibly signals activity the instant it's opened — the same live-elapsed-timer idiom `AgentWorkingIndicator` (line ~572) already uses in the chat pane, reused for its timer math (`formatElapsed()`) but not its full component (that one's styled/sized for the chat pane, not this box).

### Task 3 — Show the article date on each card

**File:** `src/screens/MarketIntelligenceScreen.jsx`

In `NewsCard()` (~line 1512), render `card.published_at` when present, formatted as a plain readable date (not raw ISO), same conditional-render pattern already used for `card.snippet`:

```js
function NewsCard({ card, loading, onClick }) {
  const formattedDate = card?.published_at
    ? new Date(card.published_at + "T00:00:00").toLocaleDateString("en-US", { month: "short", day: "numeric", year: "numeric" })
    : null;
  return (
    <div onClick={onClick} style={{background:T.cardAlt,border:`1px solid ${T.lineSoft}`,padding:"10px 12px",cursor:"pointer",opacity:loading?0.6:1}}>
      <div style={{fontFamily:body,fontSize:12.5,fontWeight:600,color:T.ink,marginBottom:3}}>{card?.headline}</div>
      {card?.snippet && <div style={{fontFamily:body,fontSize:11,color:T.muted,lineHeight:1.4,marginBottom:5}}>{card.snippet}</div>}
      <div style={{fontFamily:mono,fontSize:9.5,color:T.mutedDeep,textTransform:"uppercase",letterSpacing:"0.04em"}}>
        {card?.source}{formattedDate ? ` · ${formattedDate}` : ""}{loading ? " · Loading…" : ""}
      </div>
    </div>
  );
}
```

```jsx
// FEATURE: CHI-33-patch -- live elapsed line for Column 2's true in-flight state (newsCards ===
// null), reusing AgentWorkingIndicator's tick-every-second + formatElapsed() idiom without pulling
// in its full chat-pane-specific layout (badges, AIDiamond icon) -- this renders inline inside the
// existing empty-state box instead.
function NewsCardsLoadingLine({ startedAt }) {
  const [now, setNow] = useState(() => Date.now());
  useEffect(() => {
    const id = setInterval(() => setNow(Date.now()), 1000);
    return () => clearInterval(id);
  }, []);
  if (!startedAt) return "Grabbing the latest headlines...";
  return `Grabbing the latest headlines... ${formatElapsed(now - startedAt)}`;
}
```

Returning a plain string (not JSX) from this component is intentional — the call site above renders it directly inside an existing `<div>`, matching how `getEvidencePanelSentence(null)` already returns a plain string in the same slot; no wrapper element needed.
