## 6. DESIGN RULES

- **The ticket must name its own execution environment.** A ticket that can only run on John's
  laptop and does not say so will be picked up by a cloud cycle, which will find no archive and
  burn a cycle discovering what this document already knows.
- **Format inheritance is non-negotiable.** `SES-90` writes into the same file `SES-79` wrote:
  one imperative line, then a concrete `Seen in:` instance, appended to the existing seven
  themed sections rather than starting a parallel structure.
- **Evidence rules are inherited too.** Every `Seen in:` must be real and checkable against the
  local transcript it came from. A fabricated instance teaches a wrong prior to every downstream
  autonomous decision — `JOHN-DECISION-PATTERNS.md`'s own header states this.
- **Privacy is a live constraint here, unlike in `SES-79`.** The in-repo corpora are already in
  git. The local archive is not: it is John's full transcript history and may contain secrets,
  credentials, customer data, or personal material that has never been in a repository. `SES-90`
  extracts *criteria*, and its `Seen in:` citations must be short decision quotes with a session
  reference — never bulk transcript text pasted into a committed file.
