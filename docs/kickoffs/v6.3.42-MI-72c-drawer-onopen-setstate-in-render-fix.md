## CONTEXT

`MI-72b` gave `Drawer` an `onOpen` callback, fired on the closed→open transition, to refresh the Agents drawer's data. Live QA (design session, real browser, real Supabase data) found a genuine React console error on every open, not present before `MI-72b`:

```
Warning: Cannot update a component (`MarketIntelligenceScreen`) while rendering a different component (`Drawer`). To locate the bad setState() call inside `Drawer`, follow the stack trace...
  at Drawer (SharedUI.jsx)
  at AuditDrawersBody (MarketIntelligenceScreen.jsx)
  ...
  at MarketIntelligenceScreen (MarketIntelligenceScreen.jsx)
```

**Root cause, confirmed by direct code read of the shipped `MI-72b` commit (`f59ef21`):** `Drawer`'s `toggle()` calls `onOpen()` — which bumps `MarketIntelligenceScreen`'s `agentsRefreshKey` state — **from inside `setOpen`'s functional-updater callback**:

```js
const toggle = () => {
  setOpen(o => {
    if (!o && onOpen) onOpen(); // <-- side effect (a different component's setState) inside a state updater
    return !o;
  });
};
```

React updater functions passed to `setState` must be pure — no side effects, and definitely no calling another component's setter from inside one. React can (and does, in this exact case) invoke the updater during its render phase, so a side effect inside it reads as "setting state on a different component while rendering a third one," exactly the observed warning. `MI-72b`'s own Node test (`test-mi-72b.mjs`) simulated the *logical* "fires only on closed→open" semantics in plain JS — it could not catch this, since it's a real-React-render-phase purity violation, only visible via an actual browser render. This is exactly why `MI-72b`'s kickoff called for live manual QA in addition to the Node test.

## TASKS (1 of 4 max)

### Task 1 — `src/components/SharedUI.jsx`: fix `Drawer`'s `toggle()` — compute `willOpen` outside the updater, call `onOpen` before `setOpen`, never inside it

Replace:
```js
const toggle = () => {
  setOpen(o => {
    if (!o && onOpen) onOpen();
    return !o;
  });
};
```
with:
```js
const toggle = () => {
  const willOpen = !open;
  if (willOpen && onOpen) onOpen();
  setOpen(willOpen);
};
```
This reads `open` directly (safe — `toggle` is a plain event-handler closure over the current render's `open` value, not itself a functional updater), calls `onOpen()` as a normal side effect in the event handler body (before the state update, matching the original intent — refresh should start as soon as the user opens it), then calls `setOpen` with a plain boolean, not a function. Behavior (fires exactly once, only on closed→open) is unchanged — only the *mechanism* changes, from "side effect smuggled into an updater" to "side effect in the handler, state set normally."

## NODE.JS TEST

Run with `node test-mi-72c.mjs`, delete before committing. This bug class (React render-phase purity) isn't directly reproducible in a pure-Node reimplementation the way `MI-72b`'s test tried — that gap is exactly what let this ship. This test instead asserts the **shape** of the fix statically (Category B logic, on the actual function extracted as a string) so a future regression back to the updater-callback pattern is mechanically caught, not just relied on for review:

```js
// test-mi-72c.mjs
import { readFileSync } from 'fs';

let pass = 0, fail = 0;
function check(name, cond) {
  if (cond) { pass++; } else { fail++; console.error(`FAIL: ${name}`); }
}

const src = readFileSync(new URL('../../src/components/SharedUI.jsx', import.meta.url), 'utf8');
const toggleMatch = src.match(/const toggle = \(\) => \{[\s\S]*?\n  \};/);
check('A1: toggle() function found in SharedUI.jsx', !!toggleMatch);
const toggleBody = toggleMatch ? toggleMatch[0] : '';

// B1: onOpen must NOT be called inside a setOpen(...) callback argument
const setOpenCallbackShape = /setOpen\(\s*\w+\s*=>\s*\{[\s\S]*?onOpen\(\)[\s\S]*?\}\s*\)/;
check('B1: onOpen is not called inside a setOpen functional-updater callback', !setOpenCallbackShape.test(toggleBody));

// B2: onOpen() call exists somewhere in toggle() (the fix didn't just delete the feature)
check('B2: onOpen() is still called somewhere in toggle()', /onOpen\(\)/.test(toggleBody));

// B3: setOpen is called with a plain value/expression, not an inline arrow function, in toggle()
const setOpenPlainShape = /setOpen\(\s*(willOpen|!open|open\s*[!=]==?\s*false)\s*\)/;
check('B3: setOpen() is called with a plain boolean/expression, not a functional updater', setOpenPlainShape.test(toggleBody));

if (fail === 0) {
  console.log(`ALL TESTS PASS (${pass}/${pass})`);
} else {
  console.error(`${fail} FAILED, ${pass} passed`);
  process.exit(1);
}
```

Note: this test reads the real source file (a static-shape check), not a pure logic reimplementation — an intentional exception to "no app imports" for this one case, since the bug class is about *how* the code is structured, not what it computes. Keep the regex loose enough to tolerate reformatting but strict enough to catch the exact anti-pattern.
