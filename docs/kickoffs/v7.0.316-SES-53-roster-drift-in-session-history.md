## Premise revalidation (step 6, `SES-87`) — it HOLDS, but the ticket's file name is now wrong

The ticket's one worked example is *"the 2026-07-29 `S-AGT-37` entry calls her 'Nadia Rahman —
Data Analyst'; `agents.js:211` says `name: "Nadia Farouk", role: "Data Expert"`."*

Read live this cycle rather than taken from the ticket:

- `src/data/agents.js:211` still reads `name: "Nadia Farouk", role: "Data Expert"`. The source of
  truth has not moved.
- **`grep -n "Rahman" docs/SESSIONS.md` returns nothing.** The named instance is not in the file
  the ticket names.
- It was **archived, not fixed.** `S-AGT-37` now lives in `docs/SESSIONS-ARCHIVE-2026-0607.md`,
  where `Nadia Rahman — Data Analyst` survives at lines 595, 6848 and 6872.

So the premise is alive and the ticket's *scope sentence* is what decayed — which is exactly why
the ticket says **"sweep `SESSIONS.md` for other roster drift rather than fixing this one
mention"**. A spot-fix of the named line would have found nothing and closed a live defect as
dead. The sweep is taken over the session-history corpus — `docs/SESSIONS.md` **and** the archive
it spills into — because that pair is one document that was split by size, and the ticket's harm
model (*"a single wrong name propagates into every session that quotes the entry"*) does not care
which half a session reads.

## What the sweep measured, before anything changed

A deterministic detector (roster parsed from `agents.js`; every `Full Name — Role` site in the two
files compared against it) plus an independent `Sonnet 5` sweep of the same corpus, cross-checked
against each other. The detector's own first two versions were wrong and are recorded because the
second failure is the instructive one: matching the role slot **against the roster's list of
roles** reports zero findings on a corpus that demonstrably contains `Nadia Rahman — Data
Analyst`, because a drifted role is by definition not in the roster. The role slot has to be
captured generically and compared afterwards.

## Boundaries this build holds

- **`src/data/agents.js` is read, never written.** It is the source of truth; a sweep that
  "fixed" the roster to match the prose would invert the ticket.
- **The one site quoting the defect is not corrected.** `docs/SESSIONS-ARCHIVE-2026-0607.md:6872`
  is the `SES-53` filing itself — *"this file records her as 'Nadia Rahman — Data Analyst';
  `agents.js:211` says Nadia Farouk — Data Expert"*. Correcting that sentence deletes the record
  of the defect and makes the ticket unreadable. It is left verbatim, and the regression guard
  carries an explicit exemption for it rather than a line number, so a re-flow of the file cannot
  silently turn the exemption into a hole.
- **`docs/backlog/BACKLOG-SNAPSHOT.md` is NOT hand-edited**, though it contains the same quoted
  string. It is generated from `public.backlog_items` by `scripts/export-backlog-snapshot.js`; the
  string is the ticket's own description, and it is correct there for the same reason.
- **Nothing but names and roles changes.** No rewording, no reflowing, no tidying of adjacent
  prose in a 7,000-line history file.

## Named deviation, disclosed rather than buried (the `SES-196` convention)

**Shortened-role possessives are left alone, and that is a decision, not an omission.** The
detector also flags `Susan Smith — Trainer's …` (roster: `Trainer Agent`) at nine sites and
`Owen Marsh — Proofreader's …` (roster: `The Proofreader`) at one. These are *prose contractions
of the right role*, not attributions of a different one: no second agent answers to "Trainer" or
"Proofreader", so nothing is misidentified and nothing propagates wrongly. They are excluded on
that test — **ambiguity with another roster member**, stated so the next sweep applies the same
line rather than re-deriving a different one.

`Bob Whitfield — Procurement Analyst` is included by exactly that test and is worth naming as the
boundary case: the roster carries `Junior Procurement Analyst` (Chloe Okafor) and `Senior
Procurement Analyst` (Mike Alvarez) beside Bob's `Professional Procurement Analyst`, so the
shortened form is not a contraction — it is a role three people could answer to.

## QA bar

- The detector run over the corpus reports **0** findings after the change and **N > 0** before —
  the same script, the same corpus, one variable. That is the discriminating test: it cannot pass
  if the change did nothing, because its pre-change run is recorded here as failing.
- Every corrected string is re-read from the shipped file, not from the edit plan.
- `npm run build` green; `tests/regression/run-all.js` green where it applies.
- The guard carries its own **negative control**: it asserts the retired forms

  it — proving a difference from the old state rather than a property both states share.
