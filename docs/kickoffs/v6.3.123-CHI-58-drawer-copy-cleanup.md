**Governing principle, confirmed with John this session and applied to every task below:** Column 2 (Evidence) shows *content*; live status/progress narration belongs in chat (Column 1's `AgentWorkingIndicator` strip already covers "something is happening," per the exact precedent `CHI-44` already established). A task that looks like "add a shorter status line to the drawer" is wrong under this principle — the fix is to remove the status narration from the drawer entirely, not shrink it.

**Task 1 — News drawer gets an "Analyzed" mark on reopen.** Today nothing tracks which article was actually analyzed; `newsCardLoadingUrl` is transient (clears the instant the fetch finishes), so reopening the News drawer after asking about a headline shows no trace of which one it was. Reuses the exact visual pattern the Candidates drawer's "Chosen" badge already established (bordered highlight + small uppercase label) rather than inventing a new one.

**Task 2 — Candidates drawer: title stops carrying a full sentence; narration lines removed.** `Drawer`'s `title` prop currently bakes the entire chosen-summary sentence in (`` `${intentLabel} Candidates — N offered, chose: "..."` ``) — splits into a plain title + one-line body recap. Per the governing principle above, the "Priya is generating candidate theories. Live progress is shown below." box and the generic `getEvidencePanelSentence()` subhead both get removed outright (not replaced with a shorter version) — Column 1 already narrates the generating state.

**Task 3 — Result drawer: remove the redundant recap + section title; status line moves to chat.** The "Submitted theory" block duplicates what the (still-visible, collapsed) Candidates drawer's own chosen-summary already shows. The "Theory Evidence" section title adds no information (the drawer's own title already says "Result"). "Full Agent Routing & Answer Given in Xs" is a status line — per the governing principle, it belongs in chat as a terminal narration bubble, not in Column 2. The code already anticipated this exact move: the comment at the `testElapsedMs` assignment site (`onSelectHypothesis`'s test-landing block) reads *"testElapsedMs carries onto hypFlow so the eventual chat card (Task 3/4) can still caption real test time"* — written when `MI-65` deliberately removed the old chat push, expecting this session to add the replacement.

**Task 4 — Result drawer stops auto-collapsing when Draft Forecast arrives.** This is a confirmed, deliberate reversal of `CHI-50`'s original choice (documented in its own code comment: *"once Nadia's proposal lands, Draft Forecast is the new arrival that should auto-open — Result still exists underneath, just collapses"*). Under this session's governing principle, a new drawer *arriving* isn't itself a reason to visually collapse content the user may still be reading — that "something new happened" signal belongs to chat, not to yanking Column 2 shut. Result stays open (not just present-collapsed) through the Draft Forecast transition; both can be open simultaneously, same "2 drawers open at once" behavior the manual-override mechanism already supports elsewhere (confirmed, `CHI-55`'s close-out notes). Implemented as a generic extension to `useDrawerStack()` (an optional "also stays open alongside" pairing), not a hyp-specific hack, so a future drawer pair needing the same relationship doesn't need a second bespoke mechanism.
