## 2. CONTEXT

`MarketIntelligenceScreen.jsx` is the Channel Sales Intelligence screen — three logical panels (Interact/chat, Evidence/Theory, Audit/Agent Routing) shared verbatim between desktop (a static 3-column grid, `S-MARKET-INTEL-01a` onward) and mobile (`S-MI-45`'s chat-primary split + full-screen Evidence/Activity overlays).

**John's live complaint, walked through in this design session (S-MI-51-design):** asking a real seed question (the EMEA co-op question) surfaces a plain text link ("Review This Answer →") only when the answer happens to be internally flagged — nothing tells the user what they got or what to do about it. Clicking it opens Evidence as a hidden overlay behind a small button with a pulsing dot as the only cue. Theory generation then runs silently for ~30s with zero visible progress on mobile, because the one progress indicator that exists (`AgentWorkingIndicator`) lives inside the chat pane, which the Evidence overlay covers entirely. The end decision (Discard / Track as Assumption / Make Permanent) has no explanatory copy, and two of the three options silently lead into a **second**, unannounced Accept/Reject/Edit confirmation card.

**Locked decisions from this design session (do not re-litigate):**

1. **Mobile: Chat and Evidence become a permanent tab bar**, replacing both `InteractColumn`'s static avatar/name/caption header (always "Marcus Webb · Channel Intelligence," never varies — pure dead weight) and the small Evidence/Activity button row. Evidence tab is **disabled** (unclickable) until a theory flow is active (`!!hypFlow`), then **flashes** when it has content the user hasn't looked at. Chat flashes back symmetrically when a new answer lands while the user is on the Evidence tab.
2. **"Agent & Data Info" replaces "Activity"** and moves to the top of the page, next to the page title — not inside the tab row. Same full-screen overlay behavior as today's Activity panel (back-button dismiss only).
3. **Elapsed/expect/agent-status becomes a permanent strip**, visible under either tab regardless of what's active — this is the same `AgentWorkingIndicator` data that used to be trapped inside chat's scrollback, invisible the instant Evidence covered it. This is the direct fix for the 30-second dead-air bug.
4. **Question box, Send, and a new Clear link become permanent**, reachable regardless of tab. Clear resets chat + any active flow back to the seed-question empty state — same end state as a page refresh, no confirm dialog.
5. **Agent Routing feed stays exactly where it is** (pinned, bottom, unchanged content/behavior) — not part of the tab switch.
6. **Correction found mid-design-session, relevant to item 5:** `FEATURES.md` lists `MI-50` (a bottom-edge scroll-hint fade + bouncing chevron on this same routing feed) as "📋 Kickoff written," and `CLAUDE-STATE.md` recommends it as a not-yet-done next session with a kickoff path that was never actually created. **Neither is accurate — the code is already live** (`routingCanScrollMore`/`routingFeedRef`/`checkRoutingScroll`, `MarketIntelligenceScreen.jsx` lines ~1411-1460, confirmed by direct read). Task 4 corrects both tracking files; Task 1 preserves this existing behavior unmodified while relocating its container.
7. **The whole review→theory→decide sequence becomes deliberate, agent-attributed actions**, not auto-fired calls: every `qa` answer (not just internally-flagged ones) ends with an explicit choice — *"Good with this analysis, or would you prefer deeper theories?"* — **Good, thanks** / **Have Priya (Forecast/Theory/Performance Expert) generate a few theories →**. Theory selection keeps the candidate-card mechanic but relabels to *"Review or Select a theory to include in the analysis"*, with a soft-link *"...or write your own explanation"* that reveals a textarea + Save only when clicked (replacing the always-visible textarea + "Use this hypothesis"). After a theory is chosen, testing is **not** auto-fired — a new intermediate stage shows the chosen theory and an explicit **Have Priya (Forecast/Theory/Performance Expert) test this theory →** button.
8. **Priya's real output is shown honestly**: the guaranteed verdict (Supports / Complicates / Consider, same shape as `MessageBubble`'s existing `hypothesis_test` rendering) always renders; key data points/chart render only when present, captioned as agent-judgment-dependent, never promised.
9. **The end decision collapses from 3 buttons to 2**: Discard/Track as Assumption/Make Permanent → **Info Only** / **Store as Forecast**. Both existing backend calls (Elena's `reasoner-intent`, unconditional; Nadia's `data-patch-intent`, always confirmation-gated) are unchanged underneath.
10. **The Accept/Reject/Edit confirmation is reframed, not restructured**: one line added above the existing `ConfirmationCard` — *"Nadia (Data Expert) drafted this Data Room entry — review it before it's saved:"* — so it reads as reviewing the actual save, not a surprise second decision. Same three buttons, same underlying calls.
11. **First-name + role at every new-agent-invocation moment** (the two Priya CTAs, the confirmation intro, the recall-pointer message) — not full last name, and not on transient status-strip ticks (those stay first-name-only with no role, unchanged existing convention, `STYLE-GUIDE.md` §5a).
12. **On commit, tell the user exactly where the saved item can be found**: *"Saved — Nadia (Data Expert) logged this. Find it anytime under Agent & Data Info → Analysis."* (Nadia's `data-patch-intent` write already surfaces there today via `groupDataSources()`'s "Analysis" bucket — confirmed by direct read, no backend change needed.)
13. **The Theory/Forecast/Correct intent switcher UI is removed** from `EvidenceColumn` — but the underlying intent routing is **not**. A user typing "run a forecast on X" or "correct the record about Y" directly into chat still classifies via `runIntentPipeline()`/`ci-routing-intent` and enters the flow at that intent unchanged (`enterHypothesisFlow({ intent: result.intent, ... })`, line ~1580) — only the mid-flow visible toggle (three buttons letting the user switch intent after entry) goes away. `hypFlow.intent` is still set and passed through unchanged; it's simply no longer rendered as a switchable control.
14. **Desktop's 3-column layout is untouched.** Every behavioral change above lives in shared components (`InteractColumn`, `EvidenceColumn`, `MessageBubble`) already reused verbatim by desktop's grid — so the guided-journey content applies there for free. The one thing that does **not** carry to desktop: the permanent status-strip promotion (item 3) is a mobile-only fix for a bug that doesn't exist on desktop (Evidence and Chat are already simultaneously visible there) — desktop's `AgentWorkingIndicator` stays exactly where it already renders, inside the chat message list.
