## CONTEXT

Root-caused in `investigate-marcus-timeout-0722` (a discovery session, not a defect in previously-shipped code): `channel-intelligence`/`ci-answer-intent` (Marcus) intermittently hits "aborted due to timeout" on long chat sessions because `MarketIntelligenceScreen.jsx`'s `conversationContext()` sends the **entire, unbounded** chat transcript on every turn — confirmed against real `ai_activity_log` data: average 8,468 input tokens/10.4s latency, but outliers hit 20,886–26,951 input tokens and 45–49s latency, tracking almost linearly with token count.

Fix direction (research-validated against real industry practice, not just this platform's own convention — LangChain's `VectorStoreRetrieverMemory`, CrewAI's short-term/long-term memory split): replace the unbounded dump with a bounded retrieval — last-N turns verbatim, plus similarity-retrieved older turns, capped regardless of conversation length.

**This session (`SCA-1`) builds the backend infrastructure only** — the new store, the retrieval mechanism, and its logging. It does **not** touch `MarketIntelligenceScreen.jsx` or wire anything into the real chat flow — that's `SCA-2`, blocked on this session landing first. Nothing in this session is user-visible yet.

### Task 1 — Generalize `embedAndSearch()` to accept any scope key, not just `data_room_tag`

**File:** `lib/vector-search.js`

`embedAndSearch()` is currently hardcoded to scope by `data_room_tag` (`if (!queryText || !dataRoomTag) return empty`, `p_data_room_tag: dataRoomTag` in the RPC body) — the exact shared primitive `the_library`/`the_reasoning` already both use. Reusing it for `Conversations` (scoped by `session_id`, not `data_room_tag`) requires generalizing this one function rather than writing a fourth parallel embed+search implementation — this is the actual "shared service, not a new parallel one" call the Architect Review's own multi-site-bug-pattern check requires.

Change the signature to accept a generic scope pair instead of the hardcoded `dataRoomTag` param:

```js
export async function embedAndSearch({ rpcName, queryText, tenantId, matchCount, supabaseUrl, supabaseKey, openaiKey, formatEntry, contextIntro, scopeParam = 'p_data_room_tag', scopeValue }) {
  if (!queryText || !scopeValue) return { context: "", chunks: [], matchCount: 0, usage: null };
  const { embedding: queryEmbedding, usage } = await embedText(queryText, openaiKey);
  const rpcRes = await fetch(`${supabaseUrl}/rest/v1/rpc/${rpcName}`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', apikey: supabaseKey, Authorization: `Bearer ${supabaseKey}` },
    body: JSON.stringify({
      query_embedding: queryEmbedding, match_threshold: 0.3, match_count: matchCount,
      p_tenant_id: tenantId || 'global', [scopeParam]: scopeValue,
    }),
  });
  // ...rest unchanged
}
```

**Byte-identical for every existing caller** (`lib/librarian.js`, `lib/search-harness.js`): neither passes `scopeParam`, so it defaults to `'p_data_room_tag'`, and they already pass their tag as `dataRoomTag` — update their 2 call sites to pass it as `scopeValue` instead of `dataRoomTag` (a rename, not a behavior change — confirm via `git diff` that the RPC body sent is byte-identical to before for both callers).

### Task 2 — New `Conversations` table + `match_conversations` RPC (Supabase, no code file)

Via Supabase MCP `apply_migration`:

```sql
create table conversations (
  id               uuid primary key default gen_random_uuid(),
  tenant_id        text not null default 'global',
  session_id       text not null,
  capability_slug  text not null,
  role             text not null check (role in ('user', 'assistant')),
  content          text not null,
  embedding        vector(1536),
  created_at       timestamptz not null default now()
);

create index conversations_session_idx on conversations (tenant_id, session_id, created_at);

create or replace function match_conversations(
  query_embedding vector,
  match_threshold float,
  match_count int,
  p_tenant_id text,
  p_session_id text
)
returns table (id uuid, content text, role text, capability_slug text, created_at timestamptz, similarity float)
language sql stable
as $$
  select
    id, content, role, capability_slug, created_at,
    1 - (embedding <=> query_embedding) as similarity
  from conversations
  where (tenant_id = p_tenant_id or tenant_id = 'global')
    and session_id = p_session_id
    and 1 - (embedding <=> query_embedding) > match_threshold
  order by embedding <=> query_embedding
  limit match_count;
$$;
```

**Not brokered through `lib/search-harness.js`.** Confirmed by reading its current code this session: `search-harness.js` exists specifically to unify `the_library`/`the_reasoning` because *both* have a real trust boundary (Eleanor-only; `data_room_tag`/`uber_access`) — its own header comment states "the trust boundaries are not merged, only the public surface is." `Conversations` has no such boundary — it's system-managed session plumbing (auto-written, auto-read, no agent ever chooses to access it), closer in kind to `durable_hops` than to `the_library`/`the_reasoning`. It gets its own plain module (Task 3), same shape as `lib/rag.js`'s unbrokered `queryRAG()`.

**RLS:** left disabled on this new table, matching every existing table in this project today (confirmed via Supabase advisory — all 25 tables). Not this session's job to change — that's `DAT-9`, a deliberate platform-wide pass, not a one-off enable on a single new table.

### Task 3 — New `lib/conversations.js`: write + retrieve

**File:** `lib/conversations.js` (new)

```js
import { embedContent, embedAndSearch } from './vector-search.js';
import { logActivity } from './activity-log.js';

export async function writeConversationTurn({ tenantId, sessionId, capabilitySlug, role, content, traceId = null }) {
  const supabaseUrl = process.env.SUPABASE_URL;
  const supabaseKey = process.env.SUPABASE_SERVICE_KEY;
  const openaiKey = process.env.OPENAI_API_KEY;
  const embedStart = Date.now();
  const { embedding, usage } = await embedContent(content, openaiKey);
  logActivity({
    tenantId: tenantId || 'global', agentId: null,
    aiType: 'similarity', feature: 'conversation-memory-write',
    model: 'text-embedding-3-small',
    inputTokens: usage?.total_tokens ?? null, outputTokens: 0,
    latencyMs: Date.now() - embedStart,
    patternsUsed: ['rag', 'embeddings'], traceId,
  });
  const res = await fetch(`${supabaseUrl}/rest/v1/conversations`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', apikey: supabaseKey, Authorization: `Bearer ${supabaseKey}`, Prefer: 'return=minimal' },
    body: JSON.stringify({ tenant_id: tenantId || 'global', session_id: sessionId, capability_slug: capabilitySlug, role, content, embedding }),
  });
  if (!res.ok) throw new Error(`writeConversationTurn failed: ${res.status} ${await res.text()}`);
}

export async function queryConversations({ sessionId, queryText, tenantId, matchCount = 5, traceId = null }) {
  const supabaseUrl = process.env.SUPABASE_URL;
  const supabaseKey = process.env.SUPABASE_SERVICE_KEY;
  const openaiKey = process.env.OPENAI_API_KEY;
  if (!sessionId) return { context: "", chunks: [], matchCount: 0 };
  const embedStart = Date.now();
  const result = await embedAndSearch({
    rpcName: 'match_conversations', queryText, tenantId, matchCount,
    supabaseUrl, supabaseKey, openaiKey,
    scopeParam: 'p_session_id', scopeValue: sessionId,
    formatEntry: m => `--- ${m.role.toUpperCase()} (${new Date(m.created_at).toISOString()}) ---\n${m.content}`,
    contextIntro: "The following are relevant prior turns from this same conversation:",
  });
  logActivity({
    tenantId: tenantId || 'global', agentId: null,
    aiType: 'similarity', feature: 'conversation-memory-retrieval',
    model: 'text-embedding-3-small',
    inputTokens: result.usage?.total_tokens ?? null, outputTokens: 0,
    latencyMs: Date.now() - embedStart,
    patternsUsed: ['rag', 'embeddings'], traceId,
  });
  return result;
}
```

`session_id` is a **required** parameter on both functions — no default, no optional fallback — same enforcement precedent as `data_room_tag` on `queryLibrary()`. `SCA-2` (not this session) is responsible for actually calling these from the real chat flow and combining `queryConversations()`'s output with a last-N-turns-verbatim window; this session proves the store and retrieval work correctly in isolation.

```js
// test-sca-1-api.mjs -- SCA-1 live verification: write/retrieve/isolation against the real Conversations table.
import { writeConversationTurn, queryConversations } from './lib/conversations.js';

const TENANT = 'global';
const SESSION_A = `test-sca1-a-${Date.now()}`;
const SESSION_B = `test-sca1-b-${Date.now()}`;

let failures = 0;
function check(cond, label) {
  if (cond) console.log(`PASS: ${label}`);
  else { console.error(`FAIL: ${label}`); failures++; }
}

// 1. Write 3 turns to session A on different topics, 1 turn to session B.
await writeConversationTurn({ tenantId: TENANT, sessionId: SESSION_A, capabilitySlug: 'channel-intelligence', role: 'user', content: 'What is the smartphone growth trajectory in emerging markets?' });
await writeConversationTurn({ tenantId: TENANT, sessionId: SESSION_A, capabilitySlug: 'channel-intelligence', role: 'assistant', content: 'Emerging market smartphone growth is concentrated in India and Southeast Asia, driven by rising middle-class income.' });
await writeConversationTurn({ tenantId: TENANT, sessionId: SESSION_A, capabilitySlug: 'channel-intelligence', role: 'user', content: 'What is the training compliance gap at Vitrine Tech in Brazil?' });
await writeConversationTurn({ tenantId: TENANT, sessionId: SESSION_B, capabilitySlug: 'channel-intelligence', role: 'user', content: 'This is an unrelated turn from a completely different session.' });
console.log('PASS: 4 turns written without throwing');

// 2. Relevance: querying about emerging-market growth should rank the growth-related turn highest.
const relevant = await queryConversations({ sessionId: SESSION_A, queryText: 'emerging market smartphone growth trends', tenantId: TENANT, matchCount: 5 });
check(relevant.matchCount > 0, 'retrieval returned at least one match');
check(relevant.context.includes('India and Southeast Asia'), 'the semantically relevant turn was retrieved (not a generic keyword match)');

// 3. Isolation: session A's retrieval must never include session B's content.
check(!relevant.context.includes('unrelated turn'), 'session isolation held -- session B content did not leak into session A retrieval');

// 4. Isolation, the other direction.
const otherSession = await queryConversations({ sessionId: SESSION_B, queryText: 'unrelated turn', tenantId: TENANT, matchCount: 5 });
check(otherSession.context.includes('unrelated turn'), 'session B retrieves its own content correctly');
check(!otherSession.context.includes('emerging market'), 'session B does not see session A content');

// 5. Required-param enforcement.
const noSession = await queryConversations({ sessionId: null, queryText: 'anything', tenantId: TENANT });
check(noSession.matchCount === 0 && noSession.context === "", 'missing session_id returns empty, not an unscoped platform-wide search');

// Cleanup -- delete both test sessions' rows, zero residue.
const supabaseUrl = process.env.SUPABASE_URL, supabaseKey = process.env.SUPABASE_SERVICE_KEY;
for (const sid of [SESSION_A, SESSION_B]) {
  await fetch(`${supabaseUrl}/rest/v1/conversations?session_id=eq.${sid}`, {
    method: 'DELETE', headers: { apikey: supabaseKey, Authorization: `Bearer ${supabaseKey}` },
  });
}
console.log('Test rows cleaned up.');

if (failures > 0) { console.error(`\n${failures} check(s) failed.`); process.exit(1); }
console.log('\nAll checks passed.');
```
