## The block format

````
<!-- {{rule:B40}} · rendered from public.governance_rules — do not hand-edit the quoted line(s)
     below. Edit the registry row, re-export docs/governance/RULES-SNAPSHOT.md, then run
     `node scripts/render-rule-blocks.js --write`. Checked by that script's default --check mode. -->
> **Rule B40** — Claim a backlog ticket atomically via claimed_by/claimed_at columns at pick time
> (any session, manual or scheduled); a claim expires after 24h so a dead session can't strand a
> ticket.
````

- **A marker is recognised only when `{{rule:ID}}` is the FIRST token inside an HTML comment.**
  This is the `SES-180` self-flagging trap handled up front rather than after it fires: prose that
  *writes about* the syntax (this kickoff, `session-hygiene.md`, the ticket text) never puts the
  marker at the head of a comment, so it is inert. The `MARKER_PLACEHOLDERS` set from check 11
  (`ID`, `<ID>`, `RULE-ID`, …) is carried too, for the same reason it exists there.
- **The rendered block is the maximal run of `>` lines starting on the line immediately after the
  comment closes.** No closing marker, nothing to leave dangling.
- **Multi-line statements are supported** (a stored `\n` becomes a further `> ` line), so a rule
  whose text later grows a second sentence does not silently render half.

## QA plan — discriminating, per step 7

The question each test must survive is *"would it still pass if the change did nothing?"*

1. **`--check` clean on the real repo** → 0 findings. *Alone this is NOT QA* — it passes trivially
   on a repo with no blocks at all, which is exactly the state check 11 shipped into.
2. **The discriminating pair, one fixture, one variable.** Copy a converted doc to a temp file,
   corrupt **one word** inside the rendered line, run `--check` against the copy → must FLAG and
   name both texts. Same copy uncorrupted → 0 findings. A checker that merely *found markers*
   passes the second and fails the first.
3. **`--write` round-trip:** `--write` on the corrupted copy restores the byte-exact registry text;
   a second `--write` reports no change (idempotent).
4. **Live composition with SES-176:** `node scripts/check-session-docs.js` must stay clean. These are
   the **first real `{{rule:ID}}` markers in the repo**, so this run is also check 11's first live
   exercise rather than another clean run over zero markers.
5. `npm install && npm run build` green; `node tests/regression/run-all.js` green.
