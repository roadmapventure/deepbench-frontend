## 2. CONTEXT

**Read side only.** John (2026-07-03): reasoning content should be usable by any agent answering a question in its Data Room — "it becomes the company's culture, so they get the same answers" — not a bespoke retrieval call bolted onto one capability. `the_library` already proves the pattern: `fetch_instruction.source` is a generic Skill Profile trait, read by `fetchSection()`, with zero capability-specific code. `the_reasoning` becomes a second valid value for the exact same mechanism.

**No change needed in `db-assembly.js`.** Its `knowledge` branch already passes through whatever `traits.source` and `traits.data_room_tag` a Skill Profile declares (`AG-30`/`AG-33`, confirmed live 2026-07-03 by reading the file) — nothing there is hardcoded to `"the_library"` specifically. A future Skill Profile that sets `traits.source: "the_reasoning"` will reach `fetchSection()` correctly with zero changes to `db-assembly.js`. Confirmed by reading the file this design session, not assumed.

**Retargeting the existing `the_library` fetch is a small, already-regression-tested swap, not a rewrite.** `lib/search-harness.js`'s `the_library` branch (built last session) is a thin pass-through to `lib/librarian.js`'s existing, unchanged `queryLibrary()` — `S-ARCH-REASONING-LAYER-01a`'s M1/M2 Node test already proved this produces an identical result to calling `queryLibrary()` directly. This session's own Category M test (below) re-proves it live, through a real existing capability (`channel-intelligence`), not just through the two libraries directly.

**Field name compatibility.** `queryLibrary()`'s return shape includes `_librarian: { granted, tier }` (unchanged). `lib/search-harness.js`'s new `the_reasoning` branch returns `_access: { granted, tier }` instead (built last session, different key — it isn't Eleanor's broker). `fetchSection()`'s existing `_librarian_tier` output field is read by downstream code (`S-APPLE-02b`, noted in `ai-enrichment.js`'s own comments ~line 139) — this session makes it read either key (`result._librarian?.tier || result._access?.tier`) rather than renaming the output field itself, so nothing downstream needs to change.

**Why this session can safely resume `S-APPLE-04b`/`S-ARCH-HITL-RESUME-02` once shipped:** those two sessions were parked specifically because the hop-budget bug traced back to an architecture gap, not a bug in their own code. That gap is now closed — `the_reasoning` exists, is queryable, and is reachable by the same generic mechanism every other Knowledge Skill Profile already uses. `S-APPLE-04b` resumes as its own session, retargeting Nadia's actual capability onto this now-real infrastructure.

// test-s-arch-reasoning-layer-01b-api.mjs — Category F, L, M tests for S-ARCH-REASONING-LAYER-01b

const SUPABASE_URL = process.env.SUPABASE_URL;
const SUPABASE_KEY = process.env.SUPABASE_SERVICE_KEY;
const HEADERS = { 'Content-Type': 'application/json', apikey: SUPABASE_KEY, Authorization: `Bearer ${SUPABASE_KEY}` };

let pass = 0, fail = 0;
function check(label, cond) {
  if (cond) { console.log(`PASS: ${label}`); pass++; }
  else { console.log(`FAIL: ${label}`); fail++; }
}

function testCategoryF() {
  console.log('\n--- Category F: environment ---');
  check('SUPABASE_URL set', !!SUPABASE_URL);
  check('SUPABASE_SERVICE_KEY set', !!SUPABASE_KEY);
  check('OPENAI_API_KEY set', !!process.env.OPENAI_API_KEY);
  check('ANTHROPIC_API_KEY set', !!process.env.ANTHROPIC_API_KEY);
}

async function testCategoryL() {
  console.log('\n--- Category L: live enrichPrompt() through both the_library and the_reasoning sources ---');
  const { writeContent } = await import('./lib/search-harness.js');
  const { enrichPrompt } = await import('./api/prompt/ai-enrichment.js');

  // Seed a real the_reasoning row so the fetch has something to retrieve (S-ARCH-REASONING-LAYER-01a
  // proved the write path; this test proves the READ path reaches it through the real pipeline).
  const seed = await writeContent({
    requestingAgentId: 'nadia',
    store: 'the_reasoning',
    tenantId: 'global',
    data_room_tag: 'apple-cso-data-room',
    content: 'S-ARCH-REASONING-LAYER-01b test opinion: Japan GEO growth correlates with upgrade-cycle timing, not price sensitivity.',
    source_chunk_ids: [],
    source_question: 'S-ARCH-REASONING-LAYER-01b Node test seed row.',
    confidence: 'medium',
  });
  check('Seed: the_reasoning row written for this test', seed.success === true);

  try {
    const promptRequest = {
      sections: [
        {
          slug: 'test-library-section', type: 'rag', order: 1, label: 'Test Library',
          fetch_instruction: { source: 'the_library', match_count: 5 },
        },
        {
          slug: 'test-reasoning-section', type: 'rag', order: 2, label: 'Test Reasoning',
          fetch_instruction: { source: 'the_reasoning', data_room_tag: 'apple-cso-data-room', match_count: 5 },
        },
      ],
      task_context: 'Japan GEO growth upgrade cycle timing',
      tenant_id: 'global',
    };

    const result = await enrichPrompt({ prompt_request: promptRequest, agent_id: 'nadia' });
    check('L1: enrichPrompt() completed without throwing', !!result);
    check('L1: no fetch_errors reported', (result.debug?.fetch_errors || []).length === 0);
    check('L1: the_library section rendered (non-empty or empty-but-no-error, both acceptable)', 'test-library-section' in result.sections || result.debug?.sections_assembled >= 0);
    check('L1: the_reasoning section retrieved the seeded opinion', JSON.stringify(result.sections).includes('upgrade-cycle') || JSON.stringify(result).includes('upgrade-cycle'));
  } finally {
    if (seed.entry?.id) {
      await fetch(`${SUPABASE_URL}/rest/v1/the_reasoning?id=eq.${seed.entry.id}`, {
        method: 'PATCH', headers: HEADERS, body: JSON.stringify({ status: 'archived' }),
      });
    }
  }
}
