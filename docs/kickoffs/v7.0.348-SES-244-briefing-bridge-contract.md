## Root cause (diagnosis delegated to a Fable 5 subagent per B21)

Four links, each independently evidenced; **no single one is the cause**, which is why three
previous framings were each partly right:

1. **The guard is per-conversation, not per-publish.** Tool contract: *"a publish to an artifact
   this conversation has not read or published is refused."* Corroborated in-repo —
   `docs/SESSIONS.md:3023`: the toll is *"paid once per session, not per republish"* (first publish
   refused twice and cost an 1,834-line read; the second, six minutes later, published with no toll).
2. **Size decides the read's *channel*.** An owned artifact *"comes back as raw HTML (a large page is
   saved to a local file)"*. Every size ever measured on this page — 198.3 KB (2026-08-24), 439 KB,
   473.1 KB — was already on the file-save branch, so the inline threshold sits somewhere **below
   198.3 KB** and has never been located.
3. **Reading that file has no bounded completion time unattended** (register B39): the gate is a
   permission prompt rendered only in the human-facing UI. Measured parks: ~9h20m, ~8h05m, and one
   that never returned — every clearance happened while John was at his desk.
4. **John rejected the standing-permission escape** (`27b5d8cb`, option (a) REJECTED).

**Killed by that diagnosis, so no later cycle re-proposes it: shrinking the page.** The

## What this cycle ships, and what it deliberately does not

**Ships — the contradiction, removed.** `runner-cycle.md` step 9 says the republish is mandatory and
*"a cycle must never end without it"*; `27b5d8cb` forbids an unattended cycle doing it. Both are law,
they are directly opposed, and since 16:16Z **every cycle has had to reconcile them by hand** — the
one-fact-two-homes failure this repo has paid for at `SES-116`, `SES-113` and `SES-86` phase 3.
`SES-257`'s own text names it: *"SO THE TWO RULES NOW CONTRADICT EACH OTHER."* Both homes of the
republish instruction — `runner-cycle.md` step 9 and `briefing-page.md` regeneration step 2 — are
reconciled in the same commit, because reconciling one is how the two files drift.

**Does NOT ship, named rather than left to be found:** the durable (b) build itself — taps and cards
living in Supabase so the page becomes a pure render. The reason is not scope appetite, it is
verifiability. The only runtime channel a published artifact has to Supabase is the `mcp` capability
(artifact CSP blocks all page-initiated fetch/XHR), and **an unattended cycle cannot observe one real
request/response pair through it, because it cannot publish.** Writing an unverified runtime call
into the tap handler of John's only decision surface risks losing the very taps the ticket exists to
protect. That half therefore belongs to a session that can publish and watch it work — which is
precisely what the bridge is for. `SES-244` stays **`partial`** with that remainder declared on its
ship card.

This is John's own precedent, not an invention: on `SES-155` he ruled (gated card `869e76ca`,
Accept) to build the DB side *additively* and *"do NOT repoint `briefing_state_seed()` in this
build — the retire + seed repoint is a deliberately separate later step, to run only after … the
page can be rebuilt so the threads are verified end-to-end."* Same split, same reason.
