## 1. CONTEXT

**Found 2026-07-14 while John reviewed the live AI Audit screen after `AI-50c` shipped.** Two questions surfaced a real, quantified bug and a stale hardcoded value.

### Bug 1 (priority): `agent-turn` rows double-count real cost and real pattern-call counts

`execute.js`'s `logAgentTurn()` writes a row for **every** turn in the delegation loop. `request-receivable.js`'s `sendRequest()` writes a **second** row for the same turn whenever it's terminal (non-delegating) — both rows carry **identical** `input_tokens`/`output_tokens`, because they describe the exact same underlying model call from two different logging vantage points (confirmed live: e.g. row 9615 `channel-intelligence` and row 9614 `agent-turn`, same tokens, ~100ms apart, same agent).

`useAIActivity.js`'s `SERVICE_CATALOG` entry for `agent-turn` already documents the intended design: *"Carries no cost_usd by design (the real billed cost is already attributed to the capability-level row `sendRequest()` writes separately)... $0 cost, as intended."* That intent holds at **write** time (no `cost_usd` is ever written for `agent-turn` rows) but is **not honored at read time** — `hydrateFromSupabase()` and `useAgents.js`'s `buildActivitySummary()` both derive cost from tokens via `computeCallCost()` whenever `cost_usd` is null, with no exception for `agent-turn`. Since `agent-turn` rows almost always have real tokens, they now contribute real dollars a second time.

**A blanket "always zero agent-turn cost" fix would be wrong.** A *pure delegating* turn (`is_delegate_call: true`) never gets a paired `sendRequest()` write at all — its `agent-turn` row is the *sole* record of that spend. Zeroing it would silently drop real cost. The distinction that matters: is this specific `agent-turn` row paired with a nearby same-agent capability-level (wrapper) row, or not?

**This exact problem shape was already solved, live, for latency** — `useAgents.js`'s `classifyRow()`/`CAPABILITY_WRAPPER_TYPES`/`PAIR_WINDOW_MS` (built for `S-MI-20`), which pairs a wrapper row (`ai_type` in a known set, `feature === 'request-receivable'` — confirmed via direct Supabase query: 100% of `channel-intelligence`/`quality-gate`/`project-manager`/etc. rows carry this exact literal `feature` value) against a nearby `agent-turn` row for the same `agent_id` within `PAIR_WINDOW_MS` (2000ms). This session reuses that same proven pairing logic, applied to cost (and pattern-call counts) instead of latency.

**Quantified live (Supabase MCP query against real production data, `rallojeqnkgtxgsdsnqm`, `tenant_id='global'`):** 1,107 `agent-turn` rows are paired with a nearby wrapper row; their combined cost is **$5.5782** — roughly 24% of the current $22.82 Total Cost. Pairing rates by capability: `channel-intelligence` 353/470 (75%), `project-manager` 263/419 (63%), `screen-controls` 148/178 (83%), `quality-gate` 131/177 (74%), `hypothesis-evaluation` 85/153 (56%), `pipeline-triage` 22/39 (56%), `data-analysis` 3/24 (12%), `memory-consolidation` 5/19 (26%), `html-display` 3/13 (23%).

**Adjacent gap, same root cause, not fixed by `AI-50c`:** `computeByPattern()`'s `total` (per-pattern call count) has the identical double-count — a paired `agent-turn`/wrapper pair both carry the same real `patterns_used` (since `AI-50a2`) and both increment that pattern's call count. This session fixes both cost and call-count together, since both stem from the same paired-row problem and the same fix mechanism resolves both.

### Bug 2: `AIActivityPanel.jsx`'s "Services Active" stat hardcodes a stale denominator

Line ~219: `["Services Active", \`${servicesActive}/14\`]` — a literal `14`, never updated as `SERVICE_CATALOG` grew. `SERVICE_CATALOG` has 32 real entries today. This is what produced the "21/14" John saw — a mathematically impossible ratio (more active than the stated total).

### Task 1 — `useAIActivity.js`: shared pairing constants + `pairedAgentTurnIds()`

**1a.** Move `CAPABILITY_WRAPPER_TYPES` and `PAIR_WINDOW_MS` from `useAgents.js` into `useAIActivity.js`, exported, byte-identical values (this file is already the canonical shared cost/pattern module — `useAgents.js` already imports `computeCallCost` from here, same direction, no circular risk):

```js
export const CAPABILITY_WRAPPER_TYPES = new Set([
  "channel-intelligence", "hypothesis-evaluation", "quality-gate", "pipeline-triage",
  "memory-consolidation", "data-analysis", "project-manager", "screen-controls",
  "html-display",
]);
export const PAIR_WINDOW_MS = 2000;
```

**1b.** Add a new exported pure function, placed near `computeByPattern()`:

```js
// FEATURE: AI-51 -- agent-turn rows are written for EVERY turn in the delegation loop
// (logAgentTurn()); sendRequest() ALSO writes a second row for the SAME turn when it's
// terminal (non-delegating) -- both carry identical tokens/patterns_used, describing the
// same real call from two logging vantage points. A pure delegating turn has no such
// sibling and is the sole record of that spend/pattern-use -- must not be zeroed. Reuses
// the exact same nearby-timestamp pairing check useAgents.js's classifyRow() already
// proved live for LATENCY dedup (S-MI-20), applied here to cost + pattern-count instead.
// Returns the Set of row `id`s for every agent-turn row that has a same-agent capability-
// wrapper row (feature === 'request-receivable') within PAIR_WINDOW_MS -- callers should
// treat those specific rows as already-counted via their paired sibling.
export function pairedAgentTurnIds(rows) {
  const wrapperTimesByAgent = new Map();
  for (const row of rows) {
    if (CAPABILITY_WRAPPER_TYPES.has(row.ai_type) && row.feature === 'request-receivable') {
      const t = new Date(row.created_at).getTime();
      if (!wrapperTimesByAgent.has(row.agent_id)) wrapperTimesByAgent.set(row.agent_id, []);
      wrapperTimesByAgent.get(row.agent_id).push(t);
    }
  }
  const paired = new Set();
  for (const row of rows) {
    if (row.ai_type !== 'agent-turn') continue;
    const rowTime = new Date(row.created_at).getTime();
    const wrapperTimes = wrapperTimesByAgent.get(row.agent_id) || [];
    if (wrapperTimes.some(t => Math.abs(t - rowTime) < PAIR_WINDOW_MS)) {
      paired.add(row.id);
    }
  }
  return paired;
}
```

```js
import { pairedAgentTurnIds, computeByPattern } from './src/hooks/useAIActivity.js';

let failures = 0;
function assert(cond, label) {
  if (!cond) { failures++; console.error(`FAIL: ${label}`); }
  else { console.log(`PASS: ${label}`); }
}

// Test 1: a terminal turn -- agent-turn row paired with a nearby wrapper row (same agent, <2s apart)
const rows1 = [
  { id: 1, ai_type: 'agent-turn', agent_id: 'marcus', created_at: '2026-07-14T20:00:00.000Z' },
  { id: 2, ai_type: 'channel-intelligence', feature: 'request-receivable', agent_id: 'marcus', created_at: '2026-07-14T20:00:00.100Z' },
];
const paired1 = pairedAgentTurnIds(rows1);
assert(paired1.has(1) && !paired1.has(2), 'terminal turn: agent-turn row (id 1) flagged paired, wrapper row (id 2) is not');

// Test 2: a pure delegating turn -- agent-turn row with NO nearby wrapper row at all
const rows2 = [
  { id: 3, ai_type: 'agent-turn', agent_id: 'michelle', created_at: '2026-07-14T20:05:00.000Z' },
];
const paired2 = pairedAgentTurnIds(rows2);
assert(!paired2.has(3), 'pure delegating turn: agent-turn row (id 3) NOT flagged paired -- sole record, must keep its cost');

// Test 3: different agent -- a wrapper row for a DIFFERENT agent within the time window must not pair
const rows3 = [
  { id: 4, ai_type: 'agent-turn', agent_id: 'owen', created_at: '2026-07-14T20:10:00.000Z' },
  { id: 5, ai_type: 'quality-gate', feature: 'request-receivable', agent_id: 'marcus', created_at: '2026-07-14T20:10:00.050Z' },
];
const paired3 = pairedAgentTurnIds(rows3);
assert(!paired3.has(4), 'different agent_id: no false pairing across agents even with close timestamps');

// Test 4: outside the 2000ms window -- must not pair
const rows4 = [
  { id: 6, ai_type: 'agent-turn', agent_id: 'priya', created_at: '2026-07-14T20:15:00.000Z' },
  { id: 7, ai_type: 'hypothesis-evaluation', feature: 'request-receivable', agent_id: 'priya', created_at: '2026-07-14T20:15:05.000Z' },
];
const paired4 = pairedAgentTurnIds(rows4);
assert(!paired4.has(6), 'outside PAIR_WINDOW_MS (5s apart): no pairing');

// caller has already zeroed/emptied it (mirrors hydrateFromSupabase()'s own mapping)

  { cost: 0, patternsUsed: [] },              // paired agent-turn row, zeroed by the caller

const bp5 = computeByPattern(log5);
```
