## 3. Why "the top of the page" is a real fix and the trim was not

The block's offset is the sum of everything emitted above it. Today that is: the platform's injected
frame-runtime (fixed, ~25 KB, not ours), then — in the template — the provenance comments, the fonts
`<link id="f">`, the whole stylesheet `<style id="s">`, and `<div id="page"></div>`.

**Every one of those except the runtime grows on its own schedule, and three of them grow on every
ship.** A trim removes accumulated bytes once; it does not change the fact that the block sits
*downstream* of everything that accumulates. Moving the block *upstream* of all of it changes the
quantity from "grows without bound" to "a constant plus a fixed platform preamble."

Measured offsets in the template before the change:

```
0        <title>                     (SES-138's 8192-byte window)
2,015    first provenance comment
8,664    <link id="f">
8,881    <style id="s">
33,150   <div id="page"></div>
33,767   briefing-state              <-- everything above it is a growth surface
```

After the change the block sits at **~2,015** — immediately below the `SES-138` title guard and
**above** the first provenance comment, so every future stamp piles up *below* it and the ratchet
that has now fired three times cannot fire again.

## 4. The two writers — and why fixing only one would look fixed and not be

This is the part an editor will get half right. **Two different code paths produce the served page,
and both must move the block:**

1. **The cycle's rebuild** — `docs/runbooks/briefing-template.html` → `scripts/build-briefing.mjs`
   → publish. This is the page a cycle republishes.
2. **The page's own self-publish** — `doc()` inside the template's `<script id="code">`, called on
   every one of John's taps via `claude.use('artifact').publish(doc())`. **This is the page the
   harvest usually reads,** because the last writer before a harvest is normally John, not a cycle.

`doc()` currently emits the stylesheet into `<head>` and the state block after `<body><div
id="page"></div>` — so a template-only fix leaves the block sitting behind the whole stylesheet on
exactly the documents John's taps produce. `doc()` therefore emits `#f` and `#s` in the **body**,
matching the template's own structure (which is where they already live, and is proven to serve).

## 5. Ordering constraint that must not be broken

`SES-138`: the Artifact publisher scans only the **first 8192 bytes** of a published file for a
title tag, and John finds this page by its name. The state block is ~10 KB, so it can never go
*above* the title. Final order, both writers:

```
<title>                    <- first, SES-138 window intact
<!-- SES-138 title guard -->
<!-- SEED SENTINEL -->     <- moves with the block, stays immediately above it
briefing-state             <- HERE
<!-- provenance comments --> <- all future stamps land below the block
<link id="f">, <style id="s">
<div id="page"></div>
<script id="code">
```

## 8. The honest bound

This fixes the **offset**, not the **mechanism**. The page is still a buffer that has to be read
back out of its own HTML, and the read is still served head-first under a budget nobody has
documented. What changes is that the block is now upstream of every growth surface we control
rather than downstream of all of them, so the failure mode stops being "inevitable, on a timer."
The mechanism's real retirement is Part 3's board item — the briefing moving into the app behind
real auth — which John has explicitly held until after the Selfbuild project ends.
