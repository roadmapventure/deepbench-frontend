# TASKS

**Task 1 — the migration (`ses150_before_image_attended_sessions`; lives in the database, not this repo).**

Of the three mechanisms the ticket named — *"make `cycle_id` nullable with a `session_name` column, add a parallel table, or scope the doc rule to Automated mode explicitly"* — **the first**, and the other two are rejected for stated reasons rather than taste:

- **A parallel table** gives one fact two homes: every reader of the ledger would have to know to union them, and the first reader that forgets reads a partial audit trail as a complete one. This platform has paid for that shape repeatedly.
- **Scoping the doc rule to Automated mode** resolves the contradiction by *giving up* the audit trail for exactly the writes John's own attended sessions make — on a milestone named **Truth Infrastructure**. It makes the docs consistent and the ledger worse.

```sql
alter table public.runner_before_images alter column cycle_id drop not null;
alter table public.runner_before_images add column if not exists session_name text;
alter table public.runner_before_images add constraint ck_before_image_attribution
  check ((cycle_id is not null) <> (session_name is not null));
alter table public.runner_before_images add constraint ck_before_image_session_name_nonempty
  check (session_name is null or length(btrim(session_name)) > 0);
```

**`ck_before_image_attribution` IS THE HALF AN EDITOR WILL BE TEMPTED TO DROP** as redundant on top of "make `cycle_id` nullable". It is not tidying. Dropping `NOT NULL` **alone** lets an Automated cycle insert an **unattributed** before-image — a row that satisfies §19v's *"no before-image, no write"* while naming nobody, which is a **worse** ledger than the gap being closed. The XOR is load-bearing in both directions: a row carrying **both** columns makes *"which session wrote this"* ambiguous at the moment a Reverse needs the answer.

`session_name` is deliberately `text` and **not** an FK: attended sessions have no table of their own — that absence *is* this ticket — and inventing one is a second feature. The non-empty check stops `''` from satisfying the XOR while carrying no attribution.

**Grants, read live before writing (`.claude/rules/supabase-column-grants.md`):** `anon` and `authenticated` hold **zero privileges of any kind** on this table — only `postgres` and `service_role`. The additive column therefore needs no grant, and `DAT-18`'s no-public-writes posture is unchanged.
