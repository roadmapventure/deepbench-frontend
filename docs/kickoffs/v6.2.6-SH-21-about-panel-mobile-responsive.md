## 2. CONTEXT

`AboutPanel.jsx` (the "About DeepBench" panel, `SH-05`) is a right-side slide-over triggered from `AppShell.jsx`'s header — on desktop via the "About" button, on mobile via `S-MOBILE-NAV-01`'s hamburger drawer → Platform → "About DeepBench" (already wired, `onHelp` callback unchanged by that session). The panel itself has never been touched by any mobile session — it renders identically regardless of viewport today.

At mobile width this breaks in two ways:
1. **Tab bar** — 7 tabs (Purpose/Architecture/Quick Start/Revenue/Roadmap/Showcase/Who is John), each `flex:1` at `fontSize:8`, `padding:"9px 4px"`. At a 82%-of-390px panel width (~320px), that's ~45px per tab — labels like "Architecture" or "Quick Start" would truncate to unreadable ellipsis slivers.
2. **Multi-column grids** — `ArchitectureTab`'s 9-tile "By the Numbers" stat grid (3 columns) and `RoadmapTab`'s Now/Next/Later comparison (3 columns, each with 2-4 text chips) would be cramped past legibility at mobile content width (~280px after padding).

**Locked decisions (confirmed live with John, do not re-litigate):**
1. **All 7 tabs stay in scope** — no content trimmed for the mobile pass (unlike `AZ-19`, which scoped its 12 desktop tabs down to 2). This session is a pure layout/responsive fix, not a content-scoping exercise.
2. **Reuse `STYLE-GUIDE.md` §24's drawer width** (`82%` / `maxWidth:340`) instead of a new mobile-specific width value — one drawer-width convention platform-wide.
3. **Tab bar becomes horizontal-scroll on mobile**, same fix `AZ-19` just applied to Spend Analyzer's workflow strip for the identical "too many items, narrow screen" shape — not a dropdown, not a second-row wrap.
4. **Stat grid drops 3→2 columns on mobile; Roadmap grid drops 3→1 column on mobile** — judged per grid by content density, not a blanket single-column rule (see new `STYLE-GUIDE.md` §26).
5. **Backdrop-tap-to-dismiss is retained on mobile** (already the desktop behavior via `onClick={onClose}` on the backdrop) — this is a reference/navigational panel, same reasoning as the hamburger drawer's dismiss rule (§24), not `MI-45`'s back-button-only content-overlay rule.
6. **`AboutPanel.jsx`'s two ambiguous "Bench" mentions stay untouched** — `RO-12` already deliberately deferred these (one plausibly renames, one plausibly shouldn't); this session is layout-only and does not resolve that separate question.
7. **Desktop is completely untouched.** Every change is gated by `useIsMobile()`; at ≥768px the panel renders pixel-identical to current `dev`.

## 6. DESIGN RULES

- Per `STYLE-GUIDE.md` §26 (locked by this session): panel width reuses §24's `82%`/`maxWidth:340` exactly, not a new value
- Tab bar: horizontal scroll (`overflowX:"auto"`), tabs sized to content (`flex:"0 0 auto"`), never shrink text below the 11px floor — 9px here is an existing exception already used by the desktop tab bar (8px), both predate this rule and are left as-is
- Grids: judge column count per grid by content density, not a blanket single-column mobile rule — 2-item comparisons stay 2-col, dense numeric tiles go 3→2, 3-way text comparisons go to 1-col
- Backdrop-tap-to-dismiss unchanged/retained on mobile (already existing behavior, no new code needed — confirm, don't regress)
