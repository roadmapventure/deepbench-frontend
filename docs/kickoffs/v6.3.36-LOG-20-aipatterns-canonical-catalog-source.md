## 1. CONTEXT

Found 2026-07-16 during a design session auditing the AI Audit screen and MI screen's pattern-name accuracy (`S-AUDITLOG-design`). `src/aiPatterns.js`'s `AI_PAT` object is a hand-typed duplicate of pattern display strings (e.g. `TASK_PLANNING: "Tool Use · Structured Output · Streaming"`), used by 8 other screens (`StepList.jsx`, `RosterScreen.jsx`, `PersonnelScreen.jsx`, `DashboardScreen.jsx`, `CreateWorkOrderScreen.jsx`, `TaskInstructionsScreen.jsx`, `AIReviewTab.jsx`, `ResumeTab.jsx`) for step/task-card badge labels — entirely independent of `shared/ai-patterns.js`'s `PATTERN_CATALOG`, which `AA-190b` already established as the canonical source both the AI Audit screen (`useAIActivity.js`) and server-side logging (`lib/activity-log.js`) treat as ground truth.

Verified live this session: no current drift exists (no stale pre-`AA-190b` names like "Agent Delegation"/"Intelligent Synthesis"/"Transfer Learning" appear in any displayed `AI_PAT` string). But nothing structurally connects the two files — a future rename in `PATTERN_CATALOG` (the same kind of fix `AA-190b` just made) would require someone to remember to hand-update `aiPatterns.js` separately, with no test or mechanism to catch a miss. This session closes that gap by making `AI_PAT`'s strings *derive* from `PATTERN_CATALOG`'s own `name` field via slug lookup, instead of being independently hand-typed — so the next rename reaches these 8 screens' badges automatically.

`AGENT_PATTERNS` (which references `AI_PAT.*` by key, not by string) needs no change — it inherits the fix through `AI_PAT`.

## 4. TASKS (max 4)

### Task 1 — `src/aiPatterns.js`: derive `AI_PAT` strings from `PATTERN_CATALOG` instead of hand-typing them

Add this import at the top of the file (before the existing `export const AI_PAT` block):

```js
import { PATTERN_CATALOG } from '../shared/ai-patterns.js';

// FEATURE: LOG-20 -- looks up each slug's real display name in the canonical PATTERN_CATALOG
// (shared/ai-patterns.js -- the same catalog useAIActivity.js and lib/activity-log.js already
// treat as ground truth, per AA-190b) instead of a hand-typed duplicate string, so a future
// rename there reaches these badges automatically. Falls back to the raw slug (never
// "undefined") if a slug is ever removed from the catalog -- a visible fallback, not a crash.
const patternNamesBySlug = new Map(PATTERN_CATALOG.map(p => [p.slug, p.name]));
function names(...slugs) {
  return slugs.map(slug => patternNamesBySlug.get(slug) || slug).join(' · ');
}
```

Then replace the existing `AI_PAT` object:

```js
export const AI_PAT = {
  TASK_PLANNING:           "Tool Use · Structured Output · Streaming",
  AGENT_ROUTING:           "RAG · Structured Output",
  CHAT_RESPONSE:           "RAG · Prompt Chaining · Streaming",
  PROMPT_ASSEMBLY:         "Prompt Chaining · RAG",
  KNOWLEDGE_TRAINING:      "RAG · Embeddings",
  KNOWLEDGE_REINFORCEMENT: "Embeddings · Structured Output",
  AUTONOMOUS_RESEARCH:     "ReAct · Browser Automation · Streaming",
  AI_REVIEW:               "RAG · Prompt Chaining",
  // DB-22 — full pattern set across the entire Create New Task → Assign Work flow
  CREATE_TASK_FULL: "RAG · Embeddings · Tool Use · Structured Output · Streaming · Prompt Chaining",
};
```

with:

```js
// Pattern label strings — sourced from PATTERN_CATALOG via names() (LOG-20), not hand-typed.
// Every string below is byte-identical to the pre-LOG-20 hardcoded value today; the Node test
// asserts this exactly, so this is a sourcing change only, not a display change.
export const AI_PAT = {
  TASK_PLANNING:           names('tool-use', 'structured-output', 'streaming'),
  AGENT_ROUTING:           names('rag', 'structured-output'),
  CHAT_RESPONSE:           names('rag', 'prompt-chaining', 'streaming'),
  PROMPT_ASSEMBLY:         names('prompt-chaining', 'rag'),
  KNOWLEDGE_TRAINING:      names('rag', 'embeddings'),
  KNOWLEDGE_REINFORCEMENT: names('embeddings', 'structured-output'),
  AUTONOMOUS_RESEARCH:     names('react', 'browser-automation', 'streaming'),
  AI_REVIEW:               names('rag', 'prompt-chaining'),
  // DB-22 — full pattern set across the entire Create New Task → Assign Work flow
  CREATE_TASK_FULL: names('rag', 'embeddings', 'tool-use', 'structured-output', 'streaming', 'prompt-chaining'),
};
```

## 7. NODE.JS TEST

Category M applies (`STANDARDS.md` Section 4) — this session touches `PATTERN_CATALOG`/`aiPatterns.js`'s `AI_PAT` constants directly.

Add `test-log-20.mjs` at repo root (delete after verification):

```js
// Category M: confirms AI_PAT's new PATTERN_CATALOG-sourced strings are byte-identical to the
// pre-LOG-20 hardcoded values (zero visible regression), and that every slug used actually
// resolves against the real catalog (no silent raw-slug fallback masking a typo).
import { AI_PAT, AGENT_PATTERNS } from './src/aiPatterns.js';
import { PATTERN_CATALOG } from './shared/ai-patterns.js';

let pass = 0, fail = 0;
function check(label, actual, expected) {
  const ok = actual === expected;
  console.log(`${ok ? 'PASS' : 'FAIL'}: ${label}${ok ? '' : ` (got "${actual}", want "${expected}")`}`);
  ok ? pass++ : fail++;
}

// Every AI_PAT string must render byte-identical to its pre-LOG-20 hardcoded value.
check('TASK_PLANNING unchanged', AI_PAT.TASK_PLANNING, 'Tool Use · Structured Output · Streaming');
check('AGENT_ROUTING unchanged', AI_PAT.AGENT_ROUTING, 'RAG · Structured Output');
check('CHAT_RESPONSE unchanged', AI_PAT.CHAT_RESPONSE, 'RAG · Prompt Chaining · Streaming');
check('PROMPT_ASSEMBLY unchanged', AI_PAT.PROMPT_ASSEMBLY, 'Prompt Chaining · RAG');
check('KNOWLEDGE_TRAINING unchanged', AI_PAT.KNOWLEDGE_TRAINING, 'RAG · Embeddings');
check('KNOWLEDGE_REINFORCEMENT unchanged', AI_PAT.KNOWLEDGE_REINFORCEMENT, 'Embeddings · Structured Output');
check('AUTONOMOUS_RESEARCH unchanged', AI_PAT.AUTONOMOUS_RESEARCH, 'ReAct · Browser Automation · Streaming');
check('AI_REVIEW unchanged', AI_PAT.AI_REVIEW, 'RAG · Prompt Chaining');
check('CREATE_TASK_FULL unchanged', AI_PAT.CREATE_TASK_FULL, 'RAG · Embeddings · Tool Use · Structured Output · Streaming · Prompt Chaining');

// Category M: every slug this file references must exist as a real, named PATTERN_CATALOG entry
// (i.e. no fallback-to-raw-slug ever fires for a known-good slug — that would signal a typo).
const catalogSlugs = new Set(PATTERN_CATALOG.map(p => p.slug));
const usedSlugs = ['tool-use','structured-output','streaming','rag','prompt-chaining','embeddings','react','browser-automation'];
for (const slug of usedSlugs) {
  check(`slug "${slug}" exists in PATTERN_CATALOG`, catalogSlugs.has(slug), true);
}

// Category M: no active:false pattern is referenced by any AI_PAT string (would mean a
// roadmap/inactive pattern is shown as a live badge).
const inactiveNames = new Set(PATTERN_CATALOG.filter(p => !p.active).map(p => p.name));
const anyInactiveUsed = Object.values(AI_PAT).some(str => str.split(' · ').some(name => inactiveNames.has(name)));
check('no inactive PATTERN_CATALOG entry appears in any AI_PAT string', anyInactiveUsed, false);

// AGENT_PATTERNS still references AI_PAT by key correctly (unchanged structure).
check('AGENT_PATTERNS.PP-01 still resolves to TASK_PLANNING', AGENT_PATTERNS['PP-01'].patterns, AI_PAT.TASK_PLANNING);

console.log(`\n${pass} passed, ${fail} failed`);
if (fail > 0) process.exit(1);
```

Run with `node test-log-20.mjs`. All checks must PASS. Delete the file after.
