## 2. CONTEXT

The server half is live: a recovered hop returns an `in_progress` body carrying `recovery`. The client's `resolveInProgress()` already loops on those bodies on **every** call site (streamed and plain-JSON alike) — that is why the design routes visibility through the response body instead of SSE events (audit finding: the event path can't reach `workingStatus` on non-streamed sites and would re-open the LOO-25 closeout trap). This session makes the recovery visible: status line says the platform hit a snag and self-recovered, and the displayed "expect > X" extends by the re-run's cost so the user never watches elapsed blow past a stale promise. John's exact ask (2026-07-28): "its ok to let the user know you hit a snag and selfed recovered and then back on the elapsed time and agent. make sure to add to elapsed time expected so the user knows its ok."

### Task 1 — `resolveInProgress()` plumbing (+ the two wrappers)

```js
async function resolveInProgress(result, onProgress = null, isStale = () => false, onRecovery = null) {
  let iterations = 0;
  while (result.status === "in_progress") {
    if (isStale()) return result;
    // FEATURE: HAR-17 -- a recovery continue is not a budget checkpoint: it must not eat the cap
    // sized for MAX_LOOP_DEPTH budget rounds (a successful recovery sequence could otherwise be
    // killed client-side at 10 -- the exact outcome §19o forbids).
    if (result.recovery) {
      if (onRecovery && !isStale()) onRecovery(result.recovery);
    } else if (++iterations > MAX_CONTINUE_ITERATIONS) {
      throw new Error(`Chain did not complete after ${MAX_CONTINUE_ITERATIONS} continuations (job_id: ${result.job_id})`);
    }
    /* existing fetch unchanged */
    result = onProgress ? await readSSEResult(res, onProgress) : await res.json();
  }
  // FEATURE: HAR-17 -- an already-terminal failed row (duplicate/late continue) must never flow
  // into result rendering as if it were content.
  if (result.status === 'failed') {
    throw Object.assign(new Error(result.error || 'chain failed'), { status: 500 });
  }
  return result;
}
```

`callCapability()` and `resolveConfirmation()` gain an `onRecovery = null` param threaded straight through to `resolveInProgress()`. No other signature changes.

### Task 2 — `workingStatus` gains raw `expectationMs`; one shared recovery-status writer

2a. Everywhere `workingStatus` is set with an expectation (the `formatExpectation(est)` sites and every `LIVE_EXPECT_FALLBACK`/`buildEndStatusEstimate` live-indicator site), also store the raw ms: grounded estimates store their computed `est`; fallback sites store `120000` (the "< 2m" ceiling as ms). State shape comment at the `workingStatus` declaration updated: `{ message, startedAt, turnStartedAt, expectation, expectationMs, kind }`.

2b. One shared writer (near `onDelegationProgress`), used by every `onRecovery` wire-up:

```js
  // FEATURE: HAR-17 -- recovery visibility, John's exact design 2026-07-28: tell the user we hit a
  // snag and self-recovered, keep the same turn/timer identity, and EXTEND the displayed
  // expectation by the re-run's own p90 cost so the promise stays honest. Chat status only --
  // the Agent Routing drawer deliberately shows nothing (supersedes §19o's drawer wording).
  const onRecoveryStatus = (recovery) => {
    setWorkingStatus(prev => {
      if (!prev) return prev; // no live status line owns this turn -- nothing to annotate
      const rerunMs = agentActivity?.[recovery.agent_id]?.byKind?.[recovery.intent_slug]?.byDepth?.depth0?.p90 || 60000;
      const newMs = (prev.expectationMs || 120000) + rerunMs;
      return { ...prev,
        message: "Hit a snag — recovered automatically, continuing…",
        expectation: formatExpectation(newMs), expectationMs: newMs,
        kind: 'orchestration' };
    });
  };
```

Respect the CHI-75 ownership rules exactly as the existing status writers do — if `setWorkingStatus` is gated through an owner check helper, go through it, never around it. The message deliberately does NOT reset `startedAt`/`turnStartedAt` (same timer, honest elapsed). Subsequent normal status writes (next hop's own message) naturally replace the snag message — that is the "then back on the elapsed time and agent" part of John's design and needs no timer.

// test-har-17c.mjs — HAR-17c logic tests (Categories B/C/D; pure Node, no app imports).
// These mirror the exact expressions used in the screen; if an expression differs in the final
// code, update the mirror here to match BEFORE running (never let them drift silently).
let pass = 0, fail = 0;
const ok = (c, l) => { if (c) { pass++; console.log('  PASS', l); } else { fail++; console.error('  FAIL', l); } };

// B1: recovery iterations don't consume the cap
{
  const MAX = 10; let iterations = 0, killed = false;
  const bodies = [...Array(6)].map(() => ({ status: 'in_progress', recovery: { fault: 'anthropic-transient' } }))
    .concat([...Array(9)].map(() => ({ status: 'in_progress' })), [{ status: 'ok' }]);
  for (const b of bodies) {
    if (b.status !== 'in_progress') break;
    if (b.recovery) continue;
    if (++iterations > MAX) { killed = true; break; }
  }
  ok(!killed && iterations === 9, 'B1 six recoveries + nine budget rounds survive a cap of 10');
}

// B2: budget-only chains still hit the cap (guard not weakened)
{
  const MAX = 10; let iterations = 0, killed = false;
  for (let i = 0; i < 12; i++) { if (++iterations > MAX) { killed = true; break; } }
  ok(killed, 'B2 eleven budget rounds still throw');
}

// B3: expectation extension math incl. fallback and missing-p90 paths
{
  const formatExpectation = (ms) => { const s = Math.ceil(ms / 1000 / 5) * 5; const m = Math.floor(s / 60); return m > 0 ? `expect > ${m}m ${s % 60}s` : `expect > ${s % 60}s`; };
  const extend = (prev, p90) => { const rerun = p90 || 60000; const newMs = (prev.expectationMs || 120000) + rerun; return { expectation: formatExpectation(newMs), expectationMs: newMs }; };
  ok(extend({ expectationMs: 65000 }, 30000).expectationMs === 95000, 'B3a grounded + p90');
  ok(extend({ expectationMs: null }, null).expectationMs === 180000, 'B3b fallback 120s + default 60s bump');
  ok(extend({ expectationMs: 65000 }, null).expectation === 'expect > 2m 5s', 'B3c formatted string extends');
}

// C1: failed-status guard throws with a safe message when error is undefined
{
  const t = (result) => { if (result.status === 'failed') throw Object.assign(new Error(result.error || 'chain failed'), { status: 500 }); return result; };
  let threw = null; try { t({ status: 'failed' }); } catch (e) { threw = e; }
  ok(threw && threw.message === 'chain failed' && threw.status === 500, 'C1 failed body throws, undefined error safe');
  ok(t({ status: 'final_delegation' }).status === 'final_delegation', 'C1b non-failed passes through');
}

// D1: recovery writer is a no-op when no status line exists; preserves timer identity when it does
{
  const onRecovery = (prev, recovery, p90) => { if (!prev) return prev; const rerun = p90 || 60000; const newMs = (prev.expectationMs || 120000) + rerun; return { ...prev, message: 'Hit a snag — recovered automatically, continuing…', expectationMs: newMs, kind: 'orchestration' }; };
  ok(onRecovery(null, { fault: 'x' }, 1000) === null, 'D1a no live status -> untouched');
  const prev = { message: 'working', startedAt: 111, turnStartedAt: 222, expectationMs: 50000, kind: 'scripted' };
  const next = onRecovery(prev, { fault: 'x' }, 10000);
  ok(next.startedAt === 111 && next.turnStartedAt === 222 && next.expectationMs === 60000 && /snag/.test(next.message), 'D1b timer identity preserved, expectation extended');
