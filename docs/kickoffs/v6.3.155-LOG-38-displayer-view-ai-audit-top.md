## 2. CONTEXT

**Problem (plain):** The AI Audit "By Pattern" list is built from the frozen, sometimes-wrong `ai_activity_log.patterns_used` field (the source of the false-`rag` label). The new pipeline captures a real per-call signature in `ai_activity_log.call_facts` (Log Writer — `LOG-37`/`LOG-67`/`LOG-49`, all ✅ Done) and defines governed patterns with match-rules in `pattern_vocabulary.criteria` (Pattern Definer — `LOG-66`, ✅ Done). The missing middle piece is the read-time matcher that turns a signature into a pattern name. This session builds it.

**The signature → name match (§19k):** for each call, assemble its signature = `ai_activity_log.call_facts` plus a read-time-derived `model_modality` from `ai_activity_log.model`, then test it against every gold pattern's `criteria` with a bounded 3-operator grammar (equality/presence, `in`, numeric `>`). A call matching nothing falls out. The pattern **name is never written to the log** — derived live, every read (`§19k` locked constraint 1).

**Live data this session must reproduce (verified 2026-07-27):**
- `ai_activity_log`: 20,232 rows total; 864 carry a `call_facts` signature.
- RAG `criteria` = `{"model_modality":"generative","retrieval_method":{"in":["similarity-search","mixed"]},"retrieved_chunk_ids":{">":0}}`.
- ~124 signature rows satisfy RAG's stored retrieval facts (all generative-model calls, so `model_modality` derives to `generative`) → Section 1 ≈ 124.
- Section 2 ≈ 20,232 − 124 ≈ **20,108**.
- Row `20245` (project-manager / agent-selection, `retrieval_method=mixed`, one chunk, haiku) **matches RAG**. Row `20250` (quality-gate, no retrieval facts) and every null-`call_facts` history row **do not** — the false-`rag` dissolution, in miniature.

### Task 1 — Supabase migration: the Displayer view (apply via Supabase MCP `apply_migration`, name `log38_displayer_view`)

Four DB objects. `create or replace` throughout (idempotent). Project `rallojeqnkgtxgsdsnqm`.

```sql
-- 1. The generic matcher — the ONLY code, hardcodes no pattern (§19k constraint 5/6).
-- Supports exactly the bounded 3-operator grammar (§19k "Signature field value vocabulary"):
--   {"k": v}            -> equality / presence, via jsonb @> (scalar equality OR array containment)
--   {"k": {"in":[...]}} -> enumeration (scalar in list, or any array element in list)
--   {"k": {">": n}}     -> numeric: array-length > n (or scalar-numeric > n)
-- Every criteria key must be satisfied (AND). A key absent from the signature => no match (honest).
create or replace function pattern_criteria_matches(sig jsonb, crit jsonb)
returns boolean language plpgsql immutable as $$
declare k text; v jsonb; sval jsonb;
begin
  if crit is null then return false; end if;
  for k, v in select key, value from jsonb_each(crit) loop
    sval := sig -> k;
    if jsonb_typeof(v) = 'object' and v ? 'in' then
      if sval is null then return false; end if;
      if jsonb_typeof(sval) = 'array' then
        if not exists (
          select 1 from jsonb_array_elements(sval) e
          where e in (select jsonb_array_elements(v->'in'))
        ) then return false; end if;
      else
        if not (sval in (select jsonb_array_elements(v->'in'))) then return false; end if;
      end if;
    elsif jsonb_typeof(v) = 'object' and v ? '>' then
      if sval is null then return false; end if;
      if jsonb_typeof(sval) = 'array' then
        if not (jsonb_array_length(sval) > (v->>'>')::numeric) then return false; end if;
      else
        if not ((sval#>>'{}')::numeric > (v->>'>')::numeric) then return false; end if;
      end if;
    else
      if not (sig @> jsonb_build_object(k, v)) then return false; end if;
    end if;
  end loop;
  return true;
end;
$$;

-- 2. The Log Displayer view: per log row -> each gold pattern it matches (0..n rows/call).
-- model_modality is derived here at read time (§19k: text-embedding-* -> embedding, null -> none,
-- else generative) and merged into the signature; it is NEVER stored in call_facts.
-- LEFT-JOIN semantics: unmatched calls simply produce no row here (surfaced by their absence).
create or replace view ai_call_patterns as
select
  l.id            as ai_activity_log_id,
  l.created_at,
  l.cost_usd,
  pv.pattern_slug,
  pv.name         as pattern_name,
  pv.description  as pattern_description
from ai_activity_log l
join pattern_vocabulary pv
  on pv.criteria is not null
 and pattern_criteria_matches(
       coalesce(l.call_facts, '{}'::jsonb)
         || jsonb_build_object('model_modality',
              case when l.model is null then 'none'
                   when l.model like 'text-embedding-%' then 'embedding'
                   else 'generative' end),
       pv.criteria
     );

-- 3. Section 1 rollup — one row per matched pattern with count + summed cost.
-- (Cost is summed per (call,pattern) match; while only one pattern has criteria a call matches at
--  most one pattern, so no double-count today. Cross-pattern cost-splitting is LOG-41's refinement.)
create or replace view ai_pattern_classification_rollup as
select pattern_slug,
       pattern_name,
       pattern_description,
       count(*)::int              as call_count,
       coalesce(sum(cost_usd),0)  as cost_sum
from ai_call_patterns
group by pattern_slug, pattern_name, pattern_description
order by call_count desc;

-- 4. Section 2 — the single "needing reclassification" number: every logged call that matched no
-- gold pattern (new or old, empty or rich signature — John's explicit call, one total, no breakdown).
create or replace view ai_pattern_reclassification_count as
select count(*)::int as reclassification_count
from ai_activity_log l
where not exists (
  select 1 from ai_call_patterns m where m.ai_activity_log_id = l.id
);

-- 5. Grants — the browser (anon) client reads these, same as it already reads pattern_vocabulary.
grant select on ai_call_patterns, ai_pattern_classification_rollup, ai_pattern_reclassification_count
  to anon, authenticated;
```

### Task 2 — `src/hooks/useAIActivity.js`: add the classification fetch + hook

Mirror the existing `fetchPatternVocabulary()` / `usePatternVocabulary()` shape exactly (same error posture: warn + resolve to an empty/`null` result so the panel degrades gracefully, never crashes). Add near them:

```js
// FEATURE: LOG-38 -- the Log Displayer read path. Section 1 = ai_pattern_classification_rollup
// (patterns whose pattern_vocabulary.criteria matched real logged signatures); Section 2 =
// ai_pattern_reclassification_count (single total of everything unmatched). The pattern NAME is
// derived in the view at read time (ARCHITECTURE.md §19k) -- this hook never classifies client-side.
export async function fetchPatternClassification() {
  try {
    const [rollup, recl] = await Promise.all([
      supabase.from('ai_pattern_classification_rollup').select('pattern_slug, pattern_name, pattern_description, call_count, cost_sum'),
      supabase.from('ai_pattern_reclassification_count').select('reclassification_count').single(),
    ]);
    if (rollup.error) throw rollup.error;
    if (recl.error) throw recl.error;
    const classified = (rollup.data || []).map(r => ({
      slug: r.pattern_slug,
      name: r.pattern_name,
      desc: r.pattern_description,
      total: r.call_count,
      cost: Number(r.cost_sum) || 0,
      active: true,
    }));
    return { classified, reclassificationCount: recl.data?.reclassification_count ?? 0 };
  } catch (e) {
    console.warn('[LOG-38] pattern classification fetch failed; By Pattern section will show empty', e);
    return { classified: [], reclassificationCount: 0 };
  }
}

export function usePatternClassification() {
  const [state, setState] = useState({ classified: [], reclassificationCount: 0, loaded: false });
  useEffect(() => {
    let alive = true;
    fetchPatternClassification().then(r => { if (alive) setState({ ...r, loaded: true }); });
    return () => { alive = false; };
  }, []);
  return state;
}
```
