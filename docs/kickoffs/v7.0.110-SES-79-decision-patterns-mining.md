## 6. DESIGN RULES

- **The file's own format is the contract:** a one-line **criterion** in the imperative, then a
  concrete **`Seen in:`** instance. Nothing abstract, nothing without an instance.
- **Only criteria that would change a future decision.** A one-off call is history, not a
  criterion. This is the file's own stated filter and it is the main quality gate.
- **Every `Seen in:` must be real and checkable.** A fabricated or misremembered instance is
  worse than a missing criterion — it teaches a wrong prior to every future autonomous choice.
  Each retained instance is grepped back against `docs/SESSIONS.md` / `docs/FEATURES-ARCHIVE.md`.
- **No new terminology, no canonical renaming** — that is the gated lane (§19v). The pass
  distills criteria in John's existing vocabulary; it never coins a term.
- **The seed criteria are kept, not rewritten.** They are John-authored ground truth from a real
  retrospective; the pass adds around them.
- **Attribution honesty:** a criterion inferred from Claude's own narration of a session is still
  evidence of John's decision only where John's response is recorded. Where the log records a
  Claude-side conclusion with no John response, it is not a John criterion and does not go in.
