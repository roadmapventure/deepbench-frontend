## 2. CONTEXT

**Problem (LOG-91, Observability).** One real model call is logged as two `ai_activity_log` rows whenever an agent's loop turn is terminal: `runLoop()` calls `callModel()` once, logs the turn via `logAgentTurn()` (an `agent-turn` row), then hands the same turn to `sendRequest()` as `precomputed_turn` — which writes a second row (`feature='request-receivable'`, `ai_type=capability_slug`) with the **same** `usage` tokens (`request-receivable.js` STEP 1: `usage = precomputed_turn.usage`). Verified live 2026-07-28: 1,154 span-paired duplicates (100% identical tokens), 1,004 written in the last 24h — active, not historical.

**John's decisions (this design session, all explicitly confirmed):**
1. Fix the double-write at the source (not display-time filtering).
2. The **agent-turn row survives** as the single record, absorbing the wrapper's unique facts (task link, RAG/enrichment facts, guardrails outcome). Rationale verified live: the Displayer view (`ai_call_patterns`) parses `intent` only from the `capability:intent:depthN` composite feature; `platform_services.match_keys` has no dependency on loop-written wrapper rows; `capabilitySlugForRow()` already attributes agent-turn rows by feature head.
3. Historical provable pairs get **merge-then-remove** (design session runs that data pass via Supabase MCP after this session's fix is deployed and QA'd — NOT this session's job, see SCOPE RULES).

**CORRECTION (2026-07-28, design session, John's explicit call) — dispatch latency is a real column, never a `call_facts` key.** An earlier revision of this doc specced `call_facts.dispatch_latency_ms`. That is **wrong and must not be built**: `call_facts` is the base of the Displayer's §19k signature, and the view's performance rests on `SELECT DISTINCT signature` collapsing the table before `pattern_criteria_matches()` runs. Measured live this session: **24,826 rows → 720 distinct signatures today; a per-call millisecond value makes it 24,826** — a 34× blow-up on a query with a 3 s `anon` statement timeout that `LOG-99` only just brought to ~289 ms. The column **`ai_activity_log.dispatch_latency_ms` (integer, nullable) already exists** — the design session applied migration `log_91_dispatch_latency_ms` and verified it; **do not re-apply it**. John approved going to **4 files** (one over the cap) rather than dropping the measurement or splitting Task 3.

**Concurrency note (added after rebase onto v6.3.203):** the parallel `S-LOG-81` session shipped `isCountableCall()` — AI Audit *counting* is already immune to the duplicate pairs (a paired agent-turn half is stamped `isPairedDup` at hydrate time and excluded). That makes this session purely a write-path/data-hygiene fix: the raw table, cost dedup, and direct-SQL consumers still see doubles until this ships. `isPairedDup` is stamped from `pairedAgentTurnIds()`'s result (hydrate, ~line 787/806), so Task 3's legacy-window scoping automatically stops fresh rows from ever being stamped — do **not** modify `isCountableCall()` itself.

**No data loss — John's explicit requirement.** Every fact either row holds must exist on the surviving row. The two fields where the rows hold different values for the same concept are both preserved: `latency_ms` keeps the turn's model-call latency (what the screen displays today via `classifyRow()`), and the wrapper's model-through-dispatch latency (AI-43 semantics) is preserved in `call_facts.dispatch_latency_ms`. `patterns_used` is written as the union of both rows' lists (frozen legacy, never read for classification — §19k).

### Task 1 — `api/prompt/request-receivable.js`: precomputed path stops logging, returns its facts

In `sendRequest()`:
- **STEP 4's `logActivity()` call (~line 804) becomes conditional:** execute only when `precomputed_turn` is null. Every non-loop caller (`api/plan.js`, `confirmation.js`) passes no `precomputed_turn` and is byte-identical.
- When `precomputed_turn` is set, do **not** write the row; instead attach the would-have-been-logged facts to the return object as a new `_terminal_log` key:
  ```js
  _terminal_log: {
    task_id: task_id || null,
    patterns_used: patternsUsed,          // the same array STEP 4 builds today
    call_facts: callFacts,                // the same mergeCallFacts(buildCallFacts(...), signature_config) STEP 4 builds today
  ```

- The guardrails `logActivity()` (~line 722, `ai_type:'guardrails-check'`) is **untouched** — that is a genuinely separate Haiku call and keeps its own row.

    - **`sendRequest()` path:** wrap the `sendRequest()` call so the held turn row is **always** written exactly once — on success, merged with `result._terminal_log` (and `_terminal_log` stripped from the returned result so it never leaks to clients); on `sendRequest()` throw, written plain (as today's pre-branch write would have) before the error propagates. `try/catch`-rethrow or `finally` — coding session's choice, but the "exactly one write, success or throw" guarantee is the spec.
- The existing fire-and-forget character of `logAgentTurn()` is preserved (it is not awaited today at this call site; keep it that way).

## 8. NODE.JS TEST (full code — `test-log-91.mjs`)

```js
// test-log-91.mjs -- S-LOG-91 (v6.3.204) single-write-per-model-call logic tests.
// Run: node test-log-91.mjs   (delete before committing; regression twin persists separately)
import { pairedAgentTurnIds, classifyRow, PAIR_LEGACY_CUTOFF_MS, CAPABILITY_WRAPPER_TYPES, PAIR_WINDOW_MS } from './src/hooks/useAIActivity.js';

let pass = 0, fail = 0;
const t = (name, cond) => { if (cond) { pass++; console.log(`  PASS ${name}`); } else { fail++; console.log(`  FAIL ${name}`); } };

// --- A. Legacy-window scoping of the AI-51 pairing heuristic -------------------
const LEGACY = new Date(PAIR_LEGACY_CUTOFF_MS - 86400000).toISOString();   // 1 day pre-cutoff
const LEGACY2 = new Date(PAIR_LEGACY_CUTOFF_MS - 86400000 + 1000).toISOString();
const FRESH = new Date(PAIR_LEGACY_CUTOFF_MS + 86400000).toISOString();    // 1 day post-cutoff
const FRESH2 = new Date(PAIR_LEGACY_CUTOFF_MS + 86400000 + 1000).toISOString();

const legacyPair = [
  { id: 1, ai_type: 'agent-turn', agent_id: 'a1', created_at: LEGACY, feature: 'channel-intelligence:ci-answer-intent:depth0' },
  { id: 2, ai_type: 'channel-intelligence', feature: 'request-receivable', agent_id: 'a1', created_at: LEGACY2 },
];
const freshPair = [
  { id: 3, ai_type: 'agent-turn', agent_id: 'a1', created_at: FRESH, feature: 'channel-intelligence:ci-answer-intent:depth0' },
  { id: 4, ai_type: 'channel-intelligence', feature: 'request-receivable', agent_id: 'a1', created_at: FRESH2 },
];

const pairedLegacy = pairedAgentTurnIds(legacyPair);
t('legacy-era pair still dedups (agent-turn id flagged)', pairedLegacy.has(1));
const pairedFresh = pairedAgentTurnIds(freshPair);
t('post-cutoff identical shape is NOT paired', !pairedFresh.has(3));

const turnTimes = new Map([['a1', [new Date(FRESH).getTime()]]]);
const freshWrapper = classifyRow(freshPair[1], turnTimes);
t('post-cutoff wrapper row always counts (include: true)', freshWrapper.include === true);

const legacyTurnTimes = new Map([['a1', [new Date(LEGACY).getTime()]]]);
const legacyWrapper = classifyRow(legacyPair[1], legacyTurnTimes);
t('legacy wrapper row still excluded when paired', legacyWrapper.include === false);

// --- B. Merged-payload contract (pure recreation of Task 2's merge rules) ------
// Contract: union patterns, turn-half call_facts precedence, dispatch latency preserved,
// task_id threaded. The live proof that execute.js implements this is Category L (Section 9);
// the regression file proves the display half against real imports.
const turnHalf = { patterns_used: ['agent-delegation'], call_facts: { tool_calls: ['delegate_to_agent'] }, latency_ms: 2100 };
const wrapperHalf = { task_id: 'task-77', patterns_used: ['rag', 'guardrails'], call_facts: { rag_chunk_ids_by_section: { s1: ['c1'] } }, dispatch_latency_ms: 3400 };
const mergedPatterns = Array.from(new Set([...turnHalf.patterns_used, ...wrapperHalf.patterns_used]));
const mergedFacts = { ...wrapperHalf.call_facts, ...turnHalf.call_facts };   // NO dispatch latency here
t('patterns union has both halves, no dupes', mergedPatterns.length === 3 && mergedPatterns.includes('rag') && mergedPatterns.includes('agent-delegation'));
t('merged facts keep wrapper rag facts', !!mergedFacts.rag_chunk_ids_by_section);
t('merged facts keep turn tool_calls (turn precedence)', mergedFacts.tool_calls[0] === 'delegate_to_agent');
// The regression this guards: a per-call millisecond value in call_facts makes every row's
// §19k signature distinct (720 -> 24,826 measured live), re-crossing LOG-99's 3s anon timeout.
t('dispatch latency is NOT in call_facts', mergedFacts.dispatch_latency_ms === undefined);
t('both durations still preserved (separate homes)', wrapperHalf.dispatch_latency_ms === 3400 && turnHalf.latency_ms === 2100);

console.log(fail === 0 ? `ALL TESTS PASS (${pass})` : `${fail} FAILURES (${pass} passed)`);
if (fail > 0) process.exit(1);
```
