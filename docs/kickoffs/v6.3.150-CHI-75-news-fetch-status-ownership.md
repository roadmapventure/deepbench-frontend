## CONTEXT

**Bug (John, live, 2026-07-27):** on page load the news web-search (`fetchNewsCards()`) fires automatically. If the user asks a question *while it's still running*, the chat working-status line shows briefly, then **goes blank for ~10s, then re-appears**. John asked whether this means multi-agent work can't run concurrently.

**Root cause (verified by direct code read this session):** it is **not** a concurrency limit — the news fetch and the question are two independent `callCapability()`/`/api/capabilities/execute` calls that genuinely run in parallel. It's a **single-slot UI ownership bug**. There is one `workingStatus` state slot ([L3140](src/screens/MarketIntelligenceScreen.jsx:3140)), and both flows drive it (both pass the shared `onDelegationProgress` as `onProgress`). When the news fetch **completes**, it unconditionally runs `setWorkingStatus(null)` ([L3294](src/screens/MarketIntelligenceScreen.jsx:3294), and the failure path [L3301](src/screens/MarketIntelligenceScreen.jsx:3301)) — guarded only against a *Clear* (`isStale()` checks `clearGenerationRef`), **not** against a question being in flight. `web-search-news` runs ~13–43s, so it routinely finishes mid-question and **wipes the question's live status to blank**. The line stays blank until the question's *next* hop fires its own `setStatus` (a long model hop ≈ the ~10s gap). John's captured "re-appear" ("Owen is asking Michelle who should help…") is simply the next hop re-populating the slot.

**Fix (targeted — John's explicit choice of option A over a general owner-token model):** make the news fetch's status-clear **ownership-aware** — only clear the status if no chat question is currently in flight. A `chatTurnActiveRef` set true/false across `submit()`'s lifetime is the "a question owns the status right now" signal. `submit()` is the only flow that overlaps the one-shot news fetch (the fetch runs only on mount/Clear; by the time a hypothesis-test or commit is reachable it has long finished), so guarding `submit()` covers the real bug. A ref (not state) because `fetchNewsCards` is async and closes over stale state — a ref read at completion time is always current.

**Not in scope (stated so it isn't mistaken for an oversight):** the general "any two concurrent flows can't stomp each other" owner-token model (option B) — deliberately deferred; if a future flow ever fetches in the background concurrently with a chat turn, revisit then. The co-located `CHI-64` console-noise bug (unseeded `lastEventAtRef` in `fetchNewsCards`) is a *different* symptom in the same function and is **not** touched here.

// test-chi-75.mjs — pure Node, no app imports.

let pass = 0, fail = 0;
function assert(cond, label) {
  if (cond) { pass++; console.log(`PASS: ${label}`); }
  else { fail++; console.log(`FAIL: ${label}`); }
}

// --- Mirror of Task 1c: the news fetch clears the shared status ONLY if no chat turn owns it ---
function newsClearsStatus(chatTurnActive) { return !chatTurnActive; }

// --- Simulate the reported scenario end to end on the shared single slot ---
function scenario(steps) {
  // steps mutate { status, chatTurnActive }; return the timeline of status values
  const state = { status: null, chatTurnActive: false };
  const timeline = [];
  const setStatus = (v) => { state.status = v; timeline.push(v); };
  const newsComplete = () => { if (newsClearsStatus(state.chatTurnActive)) setStatus(null); else timeline.push(state.status); };
  steps({ state, setStatus, newsComplete });
  return timeline;
}

// Case 1: news finishes while a question is in flight -> question status survives (the bug fix)
{
  const t = scenario(({ state, setStatus, newsComplete }) => {
    setStatus("Jordan is routing…");        // news fetch's own status
    state.chatTurnActive = true;             // user submits
    setStatus("Marcus is thinking…");        // question takes over
    newsComplete();                          // news finishes MID-QUESTION
  });
  assert(t[t.length - 1] === "Marcus is thinking…", "question status survives a news fetch completing mid-question (no blank gap)");
  assert(!t.includes(null), "status never went blank while the question was in flight");
}

// Case 2: news finishes with no question in flight -> its own status clears (unchanged normal case)
{
  const t = scenario(({ setStatus, newsComplete }) => {
    setStatus("Jordan is routing…");
    newsComplete();
  });
  assert(t[t.length - 1] === null, "no chat turn: news fetch still clears its own status");
}

// Case 3: pure guard logic
{
  assert(newsClearsStatus(true) === false, "chat turn active -> news does NOT clear");
  assert(newsClearsStatus(false) === true, "no chat turn -> news clears");
}

console.log(`\n${pass} PASS, ${fail} FAIL`);
if (fail > 0) { console.log("ALL TESTS PASS: NO — fix before committing"); process.exit(1); }
console.log("ALL TESTS PASS");
