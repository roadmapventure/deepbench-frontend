## 4. STUB DEFINITIONS

None. The data the column needs already exists and was verified live this session:

- `public.epics` exists, with `name`; `backlog_items.epic_id` is its FK.
- The resolution is a plain `LEFT JOIN`, proven against the live board:

```sql
SELECT b.queue, b.backlog_id, coalesce(e.name,'') AS epic, b.priority_class, b.status,
       coalesce(b.design_status,'—') AS design_status,
       left(regexp_replace(coalesce(b.description,''),'^\*\*P[0-9]+[^*]*\*\*\s*',''),70) AS gist
  FROM public.backlog_items b
  LEFT JOIN public.epics e ON e.id = b.epic_id
 WHERE b.queue IS NOT NULL ORDER BY b.queue LIMIT 12;
```

  → 12 rows, `epic = 'Automation'` on 10, `''` on SES-131 and AGT-015.

## 6. DESIGN RULES

- **Blank, never a dash.** `coalesce(e.name,'')` — an em-dash in this column would read as a
  *value* ("epic: —"), and §8's Design status column already spends the dash on a real absence.
  A ticket in no epic is not a ticket with an unknown epic.
- **Resolve through the FK, never through prose.** `epics.name` via `epic_id`, matching
  `SES-111`'s standing property that an epic is an FK and never text in `body`.
- **Escape it.** `esc()`, like ID and Class — the epic name is table content, not render-time
  literal.
- **Position is the spec's, not the renderer's convenience.** Queue · ID · **Epic** · Class ·
  Status · Design status · Title, exactly as §8 of `BRIEFING-REDESIGN-0822.md` states it.
- **Do not reinstate the struck sections.** The matrix stays the only forward view (`SES-124`).
