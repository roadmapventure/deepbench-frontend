## What was fixed

`B31` and `B32` both claimed `docs/runbooks/runner-cycle.md#B31` / `#B32`. That file declares
neither: `anchorResolves()` accepts a heading slug, an explicit `<a name>`/`{#x}`, or the
register-entry form `**B31 —`, and `runner-cycle.md` has none of the three for either rule — its
only headings are the four phase headings. The rows were pointing at a home that never existed.

Both now read `docs/runbooks/runner-cycle.md#phase-1--judgment-first`, which is **true**: `B31`'s
retired cycle-lease text lives in step 0's parallel-cycles block and `B32`'s override rung in step
3's budget walls, both inside Phase 1. Before-image first, then the row; then
`scripts/export-governance-snapshot.js` so the repo copy matches.

**The fix an editor will reach for first, and why it was not taken:** adding a
`**B31 —** <statement>` register line to `runner-cycle.md` would make the anchor resolve — and
would hand-copy the statement into a doc that is not its home, which **check 12** (shipped 20
minutes earlier, `v7.0.243`) exists to flag. Using the `{{rule:ID}}` rendered form instead does not
help either: that renders as `> **Rule B32** —`, which `anchorResolves()`'s register-entry pattern
does not match. **That mismatch between SES-175's render format and check 10's anchor forms is a
real finding of this cycle, named rather than fixed** — it is a change to what check 10 accepts, not
registry hygiene, and belongs to whoever takes that up next.
