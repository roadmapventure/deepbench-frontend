## CONTEXT

**This is not a fix to Marcus's reliability/latency issue.** That issue is `AA-120` (`S-ARCH-LOOP-LATENCY-02`, v6.0.28, commit `557a19d`) — already shipped and independently re-verified: a fresh live call completed in 26.1s with Marcus's two delegation-loop turns now logged and fast (2.8s/3.0s, down from an unlogged ~13.6s gap). Nothing in that mechanism is touched by this session.

`AA-120`'s own fix added `logAgentTurn()` to `execute.js`, which now writes a real `ai_activity_log` row (`ai_type: 'agent-turn'`) for every delegation-loop turn, for any capability — generic, not Marcus-specific. `v6.0.28`'s own QA checklist (item 280 in that kickoff) flagged the risk this session closes: **`useAIActivity.js` has no catalog entry recognizing `'agent-turn'`**, so while these rows count correctly toward raw totals (`totalCalls`/`totalCost`), they're invisible in the AI Audit dashboard's By-Type and By-Service breakdowns. Confirmed live during `S-ARCH-LOOP-LATENCY-02`'s coding-session QA (2026-07-07), logged as `AA-122`. Doesn't crash anything — purely a dashboard display gap.

**Scope correction from this session's own design discussion:** the obvious-looking fix ("add `agent-turn` to `AI_TYPES`") is not what the established convention actually does. Reading `SERVICE_CATALOG`'s last 6 entries (`pipeline-triage` through `memory-consolidation`, added across `S-APPLE-03b` through `S-APPLE-05`) shows every one of them was added as a `SERVICE_CATALOG` entry **only** — never added to `AI_TYPES` (a closed list, unchanged since the platform's phase-1/2 PRD, `byType`'s `Object.keys(AI_TYPES)` iteration), and each carries an explicit comment that no `AI_TYPE_TO_SERVICE` entry is needed because the raw `ai_type` string already equals the `SERVICE_CATALOG` `slug` exactly, resolved by the existing `AI_TYPE_TO_SERVICE[e.type] || e.type` fallback (`byService`, ~line 337). `agent-turn` fits this exact shape — same fix, same precedent, no deviation.

**This means `agent-turn` stays out of By-Type after this session, same as `channel-intelligence`/`quality-gate`/`hypothesis-evaluation`/`pipeline-triage`/`agent-directory`/`data-analysis`/`data-room-custody`/`screen-controls`/`html-display`/`pdf-assembly`/`memory-consolidation` already are today.** That is pre-existing, accepted behavior across 11 prior entries, not new breakage introduced here — By-Type is effectively a legacy view at this point; By-Service is the catalog that's been kept current. Flagged for John, not decided unilaterally: a platform-wide fix (a fallback bucket so any untracked `ai_type` still surfaces in By-Type) is a separate, bigger session, not folded in here.

**Not a routing/self-routing change.** `SERVICE_CATALOG` is descriptive metadata for a human-facing dashboard — it labels rows after they're written, it does not choose an agent or a capability at runtime. `logAgentTurn()` itself (unchanged this session) is already capability-agnostic and agent-agnostic. Nothing in this session adds an agent name to any data structure or touches `request_help`/`delegate_to_agent` — `ARCHITECTURE.md` §19d/§19e are unaffected.

**Cost/latency note for the record:** `agent-turn` rows carry no `input_tokens`/`cost_usd` by design (`AA-120`'s `logAgentTurn()` doesn't log them — the real billed cost is already attributed to the capability-level row `sendRequest()` writes separately, and `logAgentTurn()` is explicitly an *additional* row, not a replacement). So this service will correctly show real call counts and real avg latency, but `$0` cost, in By-Service. That's expected, not a bug — do not add token/cost estimation to `logAgentTurn()` in this session, out of scope.
