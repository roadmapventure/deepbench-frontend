## 2. CONTEXT

`a` captures `call_source` / `caller_ip` / `device_type` / `visitor_id` / `request_host` on every logged call. Nothing renders it. This session builds the **By Platform User** drawer and fixes one wrong default `a` shipped with.

**Task 1 is a correction to `a`, and it is the reason this session ships in this order.** `a` defaults `call_source` to `ui` whenever no automation header is present — which silently labels every script as a human. Measured on the first hour of live data: **283 of 333 calls (79.3% of cost) were scripts wearing the `ui` label**; only **48 calls** came from an actual browser. The drawer's headline number is precisely the one John asked for (him vs. Claude vs. the public), so shipping it on that default would make the drawer wrong in exactly its most important cell. Per §19i there is no backfill, so every hour this default stays wrong is permanently mislabelled history.

**The browser signal must NOT be the User-Agent.** This design session's own QA scripts sent a spoofed Chrome UA and would be classified as browsers by any UA-based rule. Use the `Sec-Fetch-*` family instead — real browsers always send it, plain scripts do not.

**Two tables already exist** (migration `log_121b_caller_org_and_known_callers`, applied by the design session — **do not write a migration**):

- `ip_org_cache (caller_ip pk, org, city, region, country, resolver, resolved_at)` — one row per distinct IP ever seen.
- `known_callers (match_type, match_value, display_name, note, created_at, pk(match_type, match_value))` where `match_type ∈ ('visitor_id','caller_ip')` — the label table. Editing it renames a caller with no deploy.

**Decisions locked with John, do not re-litigate:** drawer named **By Platform User**, positioned **after By Agent**, holding **two sections** (By Source, then By Caller), collapsing as one unit. Lookup provider is **ipinfo.io**. Table named `known_callers`, deliberately *not* `platform_users` — the real identity model is deferred part (c) and must stay free to claim that name.

## 5. TASKS (6)

**Task 1 — `lib/request-context.js`: `ui` must mean a real browser.**

Add a fourth legal `call_source` value, `script`, and change the default:

- Legal values become `ui` | `script` | `regression` | `session-test`. An explicit, allowlisted `x-db-call-source` header still wins over any inference; an unrecognized value still lands `null` (unchanged from `a`).
- With **no** explicit header, infer: **`ui` if the request carries any real-browser signal, otherwise `script`.**
- Browser signal = any of `sec-fetch-site`, `sec-fetch-mode`, `sec-ch-ua`, **or** an `origin`/`referer` whose host equals `req.headers.host`. Browsers always send at least one; `curl`, Node `fetch`, and the repo's own scripts send none.
- **Do not use the User-Agent for this.** It is trivially and routinely spoofed — this session's own predecessor sent a desktop Chrome UA from a Node script. `device_type` keeps using UA/client hints as `a` shipped it; that is a different question and stays unchanged.
- Cookie minting stays gated on `call_source === 'ui'`, which now means genuine browsers only — a strict improvement, since scripts were previously minting cookies they could never return.

**Task 2 — new file `lib/ip-org-resolver.js`: resolve an IP's org exactly once, ever.**

Export one function, `resolveOrgIfUnseen(ip)`:

- Return immediately for a null/empty IP, a loopback/private address (`127.`, `10.`, `192.168.`, `172.16–31.`, `::1`, `fc00::/7`), or anything that isn't a plausible IP.
- `SELECT` from `ip_org_cache` by `caller_ip`. **A hit returns with no outbound call** — that is the whole point; steady state is zero lookups.
- On a miss: `GET https://ipinfo.io/{ip}/json` with a short `AbortSignal.timeout` (5s), then upsert `{caller_ip, org, city, region, country, resolver:'ipinfo.io', resolved_at}`. Use `ON CONFLICT DO NOTHING` — two concurrent invocations racing the same new IP is normal and harmless.
- **On any failure — non-200, timeout, malformed body, network error — upsert the row anyway with `org = null`.** A permanent negative-cache entry is required: without it a rate-limited or unroutable address is retried on every single call forever, which is the one way this design could turn into per-call network traffic.
- **Never throws, never rejects, never awaited by anything on the request path.** Wrap the whole body in try/catch returning undefined.
- **Never imports or calls `logActivity()`** (see Section 3).
- Read the ipinfo token from `process.env.IPINFO_TOKEN` **if present**, and work without it if absent — the anonymous tier is sufficient at this volume. Do not add a required env var; a missing token must degrade to the anonymous endpoint, not to an error. Add the optional var to `docs/ENV-VARS.md`.

**Task 3 — `lib/activity-log.js`: trigger the resolve inside the write that already happens.**

- After the existing `fetch(...)` POST promise is created, chain the resolve onto the same promise already handed to `waitUntil()` — do **not** add a second `waitUntil()` call and do **not** `await` anything before the POST is issued.
- Guard on `ctx.callerIp` being present; skip entirely otherwise.
- The row write must not depend on the resolve in any way: if the resolve hangs or fails, the log row is already written and unaffected.
- No new parameters, no signature change, no change to any of the 45 call sites.

**Task 4 — `src/hooks/useAIActivity.js`: aggregate, and resolve display names.**

**`LOG-124`: `hydrateFromSupabase()` must stop asking for `*`.** Replace the `select('*')` at ~L821 with an **explicit column list** that includes `caller_ip_masked` and **excludes `caller_ip`**. Enumerate every column the hook actually consumes — read the current table definition rather than guessing, and note that omitting one silently blanks a metric rather than erroring. This is what makes part 2's `REVOKE` safe; a lingering `select('*')` would 403 the whole audit the moment it lands.

Fetch `ip_org_cache` (selecting `caller_ip_masked`, **not** `caller_ip`) and `known_callers` alongside the existing `platform_services` read (same `Promise.all` shape already there), then expose two new arrays plus one count on the hook's return object:

- **`bySource`** — one row per source, each `{ source, calls, cost, pctCost, avgCost, lastSeen }`. `calls` uses the existing `isCountableCall()` (`LOG-81`'s single definition — do not invent a second one); cost uses the existing per-row `cost` already computed at hydrate time. The `ui` source splits into **three** display rows by resolved caller identity: `UI — <name>` for each labelled caller, and `UI — Public` for the rest. Non-`ui` sources render as one row each. A `null` `call_source` renders as `Unattributed`.
- **`byCaller`** — one row per caller, `{ label, device, org, city, calls, cost, firstSeen, lastSeen, ips[] }`.
- **`platformUserCount`** — distinct callers, for the new stat tile.

**Identity resolution order, most specific first:**
1. `known_callers` match on `visitor_id` → that `display_name`.
2. `known_callers` match on `caller_ip` → that `display_name`.
3. Unlabelled, `request_host` is the production host (`deepbench.roadmapventure.com`) → `Public`.
4. Unlabelled, any other host (the dev preview) → `Internal (QA)`.

**`visitor_id IS NULL` rows must group by `caller_ip_masked`, never be dropped and never collapsed into a single anonymous lump** — that is a hard constraint inherited from `a`, where NULL legitimately means "first request of a visit, or a client that refuses cookies." Label such a group by its org (or the masked IP when the org is unresolved).

**Join the org cache on `caller_ip_masked`, not `caller_ip`** — neither side's real column is readable by the frontend after part 2, which is exactly why the design session added the generated column to *both* tables. (Two different networks could in principle collide on the same masked value; at this platform's scale that is a non-issue, and the alternative — exposing real addresses to the public key — is the thing `LOG-124` exists to stop.)

**Never render a full IP anywhere.** The value the frontend holds is already blurred (`xxx.xx.33.12`); do not attempt to reconstruct, un-blur, or re-request the real one.

**The two sections' totals must reconcile exactly.** They are two cuts of the same row set. Assert it (Task 5), don't assume it.
