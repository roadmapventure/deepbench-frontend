## CONTEXT

Found live 2026-07-21 (design session `design-0720`) from John's screenshot of a real failure: clicking a news article (a Google Fi promo) to analyze it against the channel program always fails. Marcus Webb — GEO CSO Expert generates a candidate answer restating the article's terms; Owen Marsh — The Proofreader blocks it every time with `rule_violated: citation_missing`.

**Root cause, confirmed by direct code + live Supabase read, not guessed:**

1. Marcus's `ci-answer-intent` Skill already has a rule (`CHI-33-patch2`, v6.3.67) telling him supplied background material (an attached article, via `task_context.article_content`) is a given, established fact he should reference directly — no Data Room citation required for it. This part already works as intended.
2. `runQaWithQualityGate()` (the screen's own orchestration function) passes that `backgroundContext` object into Marcus's call only. Owen's `qg-review-intent` review call two steps later — and the `ci-answer-display-intent` formatting call after that — never receive it (`MarketIntelligenceScreen.jsx:1138-1144`, `:1185-1189`). Owen is structurally blind to the article: he sees only `candidate_answer`/`citations`, with no way to tell a legitimate article-sourced claim from a fabricated one, so he blocks on `citation_missing`.
3. Compounding gap: Marcus's own `CONFIDENCE_TIER RESOLUTION` rule only defines how to pick a tier when blending one or more Data Room citations of different reliability — it has no defined behavior for an answer citing **zero** Data Room records (entirely article-grounded). Marcus falls back to `confidence_tier: na`, which Owen's own (separate, correct) rule blocks, since `na` is reserved for meta-commentary, never a substantive claim.

**Fix, confirmed live with John:**
- Thread the same `backgroundContext` object through all 3 calls `runQaWithQualityGate()` makes — not a special case for Owen specifically, the same structural pass-through pattern already used for Marcus's call, extended to the rest of this one pipeline function.
- Give Owen an explicit rule for verifying (not rubber-stamping) a claim against supplied background material when present.
- Give Marcus an explicit `confidence_tier: sourced` rule for the zero-Data-Room-citation, entirely-article-grounded case, closing the undefined-behavior gap that produced the illegitimate `na` fallback.

**Explicitly out of scope, confirmed with John:** no new platform-wide "carry context across any multi-call chain" primitive in the shared `api/capabilities/execute.js` executor — checked directly, that layer is deliberately stateless per-call (`AA-83`'s explicit param list, no cross-call session state), and the Market Intelligence screen is the only place today chaining multiple top-level capability calls this way. Promote to a shared harness primitive if/when a second screen needs the same pattern (same discipline as `AA-192`'s shared-service check), not preemptively.

**Process fix, same session:** `CLAUDE-DESIGN.md`'s Architect Review gained a new check (`Search by shape, not by name`) — this session's own first-draft fix missed the screen's already-proven hop-tracking/Agent-Routing mechanism because it searched narrowly for the literal thing it assumed it needed, instead of first asking what this screen already tracks that shape of problem for. See `CLAUDE-DESIGN.md` Step 4 for the full entry.
