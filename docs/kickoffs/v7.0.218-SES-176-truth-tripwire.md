## The architectural constraint that shaped this build, quoted rather than re-derived
The obvious implementation reads `governance_rules` over the network. `check-session-docs.js`'s own
header forbids it, and says why:

> *"Why the snapshot file and not Supabase directly: this script is a session-start tripwire and the
> session-hygiene skill's own standing rule is 'keep every check cheap — sizes and greps, never a full
> read.' A network round trip does not belong in this path, and **a checker that silently no-ops when
> credentials are absent would reintroduce exactly the false all-clear being fixed here.**"*

`governance_rules` is additionally `service_role`-only (`SES-174` locked `anon`/`authenticated` to zero
privileges), so a session-start read could not work without credentials even in principle. The
answer is the pattern this repo already uses for `backlog_items`: **a deterministic, in-repo snapshot,
regenerated into every ship commit set** (`SES-83` (c)). That file does not exist yet, so this ticket
ships the exporter alongside the checks — the checks are unbuildable without it.

## Design — three checks, each decidable, none fuzzy
**Check 9 — a retired rule stated in live voice.** For each rule whose `status` is not `live`, find
occurrences of its **rule ID** in the canonical docs and read a ±280-character window around each. A
window carrying retirement vocabulary (`retired`, `superseded`, `struck`, `replaced`, `no longer`,
`do not reinstate`, …) is correct and passes; a window with none is a FLAG. ID-anchored rather than
statement-anchored on purpose: the registry's `statement` is `SES-174`'s **paraphrase**, so matching it
verbatim against prose would find nothing and ship a check that can never fire.

**Check 10 — every `canonical_doc` pointer resolves.** 84 rules across 4 files
(`docs/RUNNER-GOV-0820-REQUIREMENTS.md` 40, `docs/STANDARDS.md` 30, `CLAUDE.md` 12,
`docs/runbooks/runner-cycle.md` 2), all carrying a `#anchor`. The file must exist and the anchor must be
locatable in it.

**Check 11 — every `{{rule:ID}}` marker resolves** to a row in the registry. Measured: **0 real markers
exist today** (the only two `{{rule:` strings in the repo are inside `BACKLOG-SNAPSHOT.md` ticket
*text*, which is data, not a marker), because `SES-175` — which introduces them — is `needs-john`. This
check is therefore a **forward guard**: it is proven to fire by fixture, and it is stated here as a
guard rather than presented as catching something today.

## Deliberately NOT in this ticket, and why — said plainly rather than quietly dropped
The ticket names four checks. Two ship in full (its "every `{{rule:ID}}` and doc pointer resolves"), and
check 9 covers "no retired rule's distinctive phrase in live voice" in its **ID-anchored** form. The
remaining two — *"no rule text outside its canonical home except rendered blocks"* and *"no duplicate
procedure homes"* — both require a definition of **"distinctive phrase"** that the ticket does not
give, and matching `SES-174`'s paraphrased `statement` against prose produces a checker that is
confidently wrong in both directions. Those are a design decision, not an implementation detail, so the
ticket closes **`partial`** with them named, rather than `delivered` with two checks quietly missing or
shipped as theatre. The ticket's *"a hit files a ticket heal-engine-style"* is likewise deferred: filing
is a second feature (atomic id-block claim + `--apply` path) and would break the scope cap.
