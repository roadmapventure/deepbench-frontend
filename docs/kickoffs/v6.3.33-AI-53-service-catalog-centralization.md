## CONTEXT

`AI-53` (`docs/FEATURES.md`): `SERVICE_CATALOG`'s `document-extraction` entry (`serviceType: 'ai'`) describes the real Claude Sonnet 4.5 call in `api/brief.js` that generates structured metadata for an uploaded training document — but `api/extract.js`'s deterministic PDF/DOCX/TXT parser (zero AI, zero cost) also writes `feature: 'document-extraction'` for an entirely unrelated code path. Compounding this: `api/extract.js` hardcodes `ai_type: 'deterministic'` for *both* its actions (document parsing and CSV upload), so `byService` can't tell them apart from each other either — they collapse into one shared `'deterministic'`-derived fallback bucket in the AI Audit screen's "By Service" view.

Second, related finding from the same investigation: `knowledge-reinforcement`'s catalog entry declares `patterns: ['Embeddings','Structured Output']`, but its real call site (`lib/knowledge-write.js`'s `embedAndUpsertEntry()`) only ever logs `patternsUsed: ['embeddings']` — a stale hand-maintained claim, not backed by what the service actually does.

**Third finding, surfaced by rebasing onto `origin/dev` mid-session:** `src/aiPatterns.js`'s `AI_PAT.KNOWLEDGE_REINFORCEMENT` constant (used by 8 screens for step/task badges) hardcodes the identical stale claim — `names('embeddings', 'structured-output')` = "Embeddings · Structured Output". A concurrent session (`LOG-20`) had just changed this file's *sourcing* (pattern names now looked up from `PATTERN_CATALOG` instead of hand-typed) but explicitly preserved the *content* byte-identical, since correcting it wasn't `LOG-20`'s scope. Left alone, fixing `SERVICE_CATALOG`'s entry in this session while leaving `AI_PAT` as-is would create a new Category M cross-reference contradiction (`STANDARDS.md`) between the two files describing the same service. Folded in per John's explicit call.

**Root cause, found during design-session investigation (Architect Review, shared-service check):** `api/extract.js` and `api/brief.js` are Vercel backend routes; `SERVICE_CATALOG` (the only place service slugs are defined) lives in `src/hooks/useAIActivity.js`, a Vite frontend file the backend cannot import from. Each backend route has no shared source to pull a real slug from, so each just hardcodes its own literal — exactly how the collision happened, and exactly what would happen again with the next new route. `shared/ai-patterns.js` already exists and already solves this for `PATTERN_CATALOG` (`AA-190b`: "both the Vite frontend and Vercel serverless backend import the exact same array instead of the frontend defining its own copy server-side write sites have no way to reach"). `SERVICE_CATALOG` was never given the same treatment — this session does that.

Second root cause: `SERVICE_CATALOG`'s `patterns` array is a hand-maintained static list, spread as-is into `byService`'s display data (`AIActivityPanel.jsx`'s `ServiceRow`, a cosmetic subtitle under the service name — separate from the real trust-boundary-gated `computeByPattern()`/`byPattern` view per `ARCHITECTURE.md §19i`). Nothing keeps it in sync with what a service's calls actually log over time. This session makes it self-deriving from real logged data instead.

**Use case this fixes:** the AI Audit screen ("AI Transparency · DeepBench") exists so real call counts/costs/patterns per service can be trusted. Today, uploading a training doc on the Teach screen mixes a free deterministic parse and a real paid Claude call under one label, and the Knowledge Reinforcement service's pattern badge claims something it never actually does — both undermine what the screen is for.
