## 1. CONTEXT

`AI-46` (found 2026-07-07): `ai_activity_log` has no shared identifier linking every row produced by one user-triggered interaction (one Send click's full delegation chain) — confirming where time/cost actually went requires manually chaining rows by timestamp adjacency and `feature`/`agent_id` guesswork. Verified live: no `trace_id`/`request_id` column exists in the current schema (checked directly via `information_schema.columns` — 14 columns, none of them a chain identifier).

**Why this isn't a simple column add:** `execute.js` already has a `job_id` — but it is not the same concept. `job_id` identifies one `durable_hops` **row**, created fresh each time a chain needs to checkpoint (pause/resume across serverless invocations). A single top-level interaction can span **multiple** `job_id`s — e.g. Owen's review checkpoints under one `job_id`, then dispatches to Marcus, whose own nested chain checkpoints under a second, different `job_id` (this is exactly the mechanism `AA-195`, shipped last session, fixed the resume path for). `trace_id` needs to be the **one** identifier that stays constant across all of them — generated once at the genuine top-level entry, and persisted into every `durable_hops` row a chain creates along the way, so a resumed hop recovers the same value instead of losing it.

**This is session a of 3** (split at design time, John's explicit call, given file count and the risk of touching the same recursive checkpoint/resume loop `AA-195` just fixed):
- **a (this session):** generate + persist the identifier. Touches only the harness/schema layer.
- **b (next):** thread it through `request-receivable.js`/`ai-enrichment.js`'s own `logActivity()` calls.
- **c (next):** wire the still-missing `queryRAG()`/`queryContent()` embedding `logActivity()` calls (`LOG-09`) and accept `trace_id` there too, plus fix the unrelated `FetchContext.jsx` `logAICall` crash (`LOG-10`).

This session's diff is inert on its own — no reader consumes `trace_id` yet (that's b/c) — but is fully independent, live-testable, and safe to ship first: every row this session's code touches keeps writing everything it writes today, plus one new column.
