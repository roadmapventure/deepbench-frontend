## CONTEXT

Third and final piece of the `CHI-49`/`50`/`51` cluster (`design-chi-51-0721`), now unblocked — both `CHI-49` (Theory Candidates/Result split, `v6.3.106`) and `CHI-50` (Draft Forecast drawer, `v6.3.108`) are shipped.

**The problem, two related gaps confirmed live with John:**
1. **Drawers get destroyed on resolve.** Today, `onDiscard()` (Info Only) and `onResolveConfirmation()`'s accept/reject branches both end with `setHypFlow(null)` — wiping Candidates/Result/Draft Forecast entirely the instant a theory cycle concludes. Every other drawer in this cluster (News, Analysis) persists, collapsed and reopenable, once it's no longer current; Theory's own drawers don't, for no good reason beyond "that's what the code already did." Deliberately scoped to *within one theory cycle only* — a 2nd, unrelated theory/question later still fully replaces `hypFlow`/`qaEvidence` (that's `CHI-47`'s separate, larger, still-deferred scope: cross-question history).
2. **Once resolved, nothing should auto-open — not even the old fallback.** `CHI-43`'s core rule is "newest defaults open, previous collapses." John's explicit exception: once a flow fully *resolves* (nothing new is coming next), that rule should stop applying entirely — every drawer collapses to its header and the user manually picks what to read, rather than `computeAutoCurrent` falling back to whatever's next in priority (today: Analysis, unconditionally, the instant Theory's own key stops claiming top priority).

**The fix, confirmed live with John across this session's walkthrough:**

**Part A — consolidate the drawer-open mechanism into one real service.** Today "which drawer is open" is scattered across 5 separate pieces of `EvidenceColumn` local state (`computeAutoCurrent()`, `manualOverride`, the reset/auto-scroll `useEffect`, `isDrawerOpen()`, `handleDrawerToggle()`) — grown incrementally across `CHI-43`/`44`/`45`/`46`/`49`/`50`, never consolidated. John's direct call: extract all five into one hook, `useDrawerStack()`, so a 6th drawer type (or a future resolution-having flow) extends it by adding one priority entry, not touching five call sites. `EvidenceColumn` calls it once and gets back `{isOpen, toggle}`.

**Part B — resolution-aware suppression, built into the new hook as a first-class input, not a special case.** `useDrawerStack()` takes a `resolved` boolean (today: sourced from a new `isHypResolved(hypFlow)` — hyp is the only flow with a resolution concept right now; the hook itself doesn't hardcode "hyp," it just takes whatever boolean the caller passes) and a `freshDeps` array. The instant `resolved` transitions true, auto-open suppresses entirely (nothing becomes `autoCurrent`, `isOpen()` returns false for every key unless manually overridden) — and stays suppressed until `freshDeps` (here: `[qaEvidence, newsCards]`, i.e. a genuinely new question or new content arriving) next changes. This is what makes "nothing auto-opens once resolved" *not* also break "a brand-new question two minutes later should still auto-open Analysis normally" — a real edge case caught during this session's own Architect Review (`SES-012`'s counter-example check), not something the original `FEATURES.md` row's plain-English description fully specified.

**Part C — persistence itself.** `onDiscard()`/`onResolveConfirmation()` stop nulling `hypFlow` — instead set a new `hypFlow.resolution` field (`"info_only"`/`"stored"`/`"rejected"`, reusing the exact vocabulary `onResolveConfirmation`'s own `task_context.resolution` already uses two lines above each call site). Since Candidates/Result/Draft Forecast are all gated on `hypFlow`/`hypFlow.hypothesisTest`/`hypFlow.confirmation` being present — never on `resolution` — they keep rendering, collapsed, reopenable, with zero drawer-JSX changes needed. `selectEvidenceFooterKind()` and the Result drawer's own `!hypFlow.confirmation` instructional gate both need a `!hypFlow.resolution` guard added so stale decision controls/copy don't reappear once resolved.

```jsx
// FEATURE: CHI-51 — generic drawer-stack orchestration service (STYLE-GUIDE.md §40/§29's shared
// pattern, consolidated out of 5 previously-separate pieces of EvidenceColumn local state:
// computeAutoCurrent(), manualOverride, the reset/auto-scroll effect, isDrawerOpen(),
// handleDrawerToggle()). A caller uses this one hook instead of hand-rolling those pieces itself
// — a future 6th drawer type extends the `priorityChecks` list, not five call sites.
//
// priorityChecks: ordered array of [key, isActive] pairs — first active entry wins (list
// highest-priority first). scrollRef: the scroll container to reset-scroll on a genuine
// transition. transitionDeps: extra values (beyond the computed current key itself) that should
// also count as "a genuine transition" — e.g. a stage advancing without the key changing.
// resolved: true once some tracked flow has concluded — today sourced from isHypResolved(hypFlow)
// by this hook's one real caller, but this parameter itself is generic, not hyp-specific; a
// future resolution-having drawer type would pass its own equivalent signal here, not add a
// parallel mechanism. freshDeps: values whose next change ends the post-resolution quiet period
// (a brand-new question, new content arriving) — deliberately separate from transitionDeps, since
// "the same flow advancing a stage" and "something genuinely new arriving" are different events.
function useDrawerStack(priorityChecks, scrollRef, transitionDeps, resolved, freshDeps) {
  const autoCurrent = priorityChecks.find(([, active]) => active)?.[0] ?? null;
  const [manualOverride, setManualOverride] = useState(null); // {key, open} | null

  useEffect(() => {
    setManualOverride(null);
    if (scrollRef.current) {
      scrollRef.current.scrollTo({ top: scrollRef.current.scrollHeight, behavior: "smooth" });
    }
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [autoCurrent, ...transitionDeps]);

  // FEATURE: CHI-51 — once `resolved` transitions true, suppress auto-open until freshDeps' next
  // genuine change. Two separate effects, deliberately not one: `resolved` staying true forever
  // (it's a permanent field once a theory cycle concludes) must not itself keep re-suppressing on
  // every render — only the true transition (false→true) should flip suppression on.
  const [suppressed, setSuppressed] = useState(false);
  useEffect(() => { if (resolved) setSuppressed(true); }, [resolved]);
  useEffect(() => {
    setSuppressed(false);
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, freshDeps);

  const effectiveAutoCurrent = suppressed ? null : autoCurrent;
  const isOpen = (key) => (manualOverride && manualOverride.key === key ? manualOverride.open : key === effectiveAutoCurrent);
  const toggle = (key) => (willOpen) => setManualOverride({ key, open: willOpen });

  return { isOpen, toggle };
}
```

// test-chi-51.mjs — pure Node, no app imports.

let pass = 0, fail = 0;
function assert(cond, label) {
  if (cond) { pass++; console.log(`PASS: ${label}`); }
  else { fail++; console.log(`FAIL: ${label}`); }
}

// --- Mirror of Task 1's priorityChecks.find(...) selection logic ---
function pickAutoCurrent(priorityChecks) {
  return priorityChecks.find(([, active]) => active)?.[0] ?? null;
}
function isHypInResultPhase(hypFlow) {
  return !!(hypFlow && (hypFlow.stage === "testing" || hypFlow.stage === "result" || hypFlow.stage === "committing" || hypFlow.confirmation));
}
function isHypAwaitingConfirmation(hypFlow) {
  return !!(hypFlow && hypFlow.confirmation);
}
function isHypResolved(hypFlow) {
  return !!(hypFlow && hypFlow.resolution);
}
function buildPriority(qaEvidence, hypFlow, newsCards) {
  return [
    ["hyp-draft", isHypAwaitingConfirmation(hypFlow)],
    ["hyp-result", isHypInResultPhase(hypFlow)],
    ["hyp-candidates", !!hypFlow],
    ["qa", !!qaEvidence],
    ["news", newsCards !== undefined],
  ];
}
function selectEvidenceFooterKind(qaEvidence, hypFlow) {
  if (hypFlow?.confirmation && !hypFlow.resolution) return "hyp-confirmation";
  if (hypFlow?.hypothesisTest && hypFlow.stage === "result" && !hypFlow.resolution) return "hyp-result";
  if (qaEvidence && !qaEvidence.reviewChoice) return "qa-review";
  return null;
}

// --- Category A: priority selection unchanged from CHI-49/50's own behavior (regression guard) ---
{
  assert(pickAutoCurrent(buildPriority(null, null, [])) === "news", "nothing active: news (unchanged baseline)");
  assert(pickAutoCurrent(buildPriority({ text: "a" }, null, [])) === "qa", "qaEvidence only: qa (unchanged)");
  assert(pickAutoCurrent(buildPriority({ text: "a" }, { stage: "generating" }, [])) === "hyp-candidates", "generating: hyp-candidates (unchanged)");
  assert(pickAutoCurrent(buildPriority({ text: "a" }, { stage: "testing", chosenText: "x" }, [])) === "hyp-result", "testing: hyp-result (unchanged)");
  assert(pickAutoCurrent(buildPriority({ text: "a" }, { stage: "result", chosenText: "x", confirmation: { proposed_action: {} } }, [])) === "hyp-draft", "confirmation landed: hyp-draft (unchanged)");

// --- Category B: isHypResolved across every real resolution value ---
{

  assert(isHypResolved({ stage: "result" }) === false, "no resolution field: not resolved");
