## 2. CONTEXT — a live outage, with the fix already measured

**By Pattern is broken right now.** John reported it empty; verified live: the classification query takes **3,186–3,203 ms** against the `anon` role's **3,000 ms `statement_timeout`**, so it fails on every panel open. It is no longer intermittent.

**Why it crossed today** — three things stacked: `ai_activity_log` growth (22,650 rows), `S-LOG-77-9` (v6.3.190) adding a **7th** criteria-bearing pattern *and* the `delegated_to_provenance` derivation (join-filter evaluations went ~131k → **~155k**), and `LOG-97`'s `log_ids` column (+32 ms, ~1% — small, but counted).

**Root cause:** `ai_call_patterns` puts the entire §19k signature assembly — including two correlated span `EXISTS` subqueries — *inside the join condition*, so it is rebuilt **once per (row × pattern)**: ~155,000 assemblies + 155,000 `pattern_criteria_matches()` invocations per panel open, growing with both the log and the vocabulary.

**The fix, measured on the real database this session:** the signature is a pure function of the row, and **22,650 rows collapse to just 582 distinct signatures**. Assemble each row's signature once, match only the **distinct** signatures against the vocabulary, then map results back to rows by signature equality (a hash join).

| Query | Now | After | Result identity |
|---|---|---|---|
| rollup (`call_count`, `cost_sum`, `log_ids`) | 3,203 ms | **288 ms** | 3,734 rows, **0 different** either direction |
| reclassification count | (same path) | **361 ms** | 19,222 — consistent with 22,650 − 3,428 distinct classified |

**11× faster, ~2.7 s of headroom** instead of a few hundred ms. Matching work drops from ~155,000 evaluations to **582 × 7 = ~4,074**, and — critically — it now scales with *distinct signature shapes*, not with log size.

**A hypothesis this session tested and DISPROVED — do not re-try it:** `pattern_criteria_matches` is `IMMUTABLE` but flagged `PARALLEL UNSAFE`, which looked like free parallelism. Flipping it to `PARALLEL SAFE` produced **no gain** (3,203 → 3,203 ms; and 2,344 → 2,318 ms combined with the CTE — noise). The planner does not parallelize this shape. **The flag was reverted to `PARALLEL UNSAFE`**, leaving the database as found. Recorded so no future session burns time on it.

**Architecture compliance (both still hold, verify before finishing):** the result stays a **plain view, never materialized** (`CREATE VIEW` with in-query `WITH … AS MATERIALIZED` CTEs is still a plain view — nothing is stored, every read recomputes). No pattern name, no per-pattern branch, no price table, no hardcoded criteria enters SQL — matching stays fully generic over `pattern_vocabulary.criteria`. The signature assembly is copied **verbatim** from the current definition; this session changes *evaluation strategy only*, never semantics.

### Task 1 — Recreate `ai_call_patterns` with signature dedup (Supabase MCP `apply_migration`, project `rallojeqnkgtxgsdsnqm`, migration name `log_99_signature_dedup`)

**Before writing anything, run `SELECT definition FROM pg_views WHERE viewname = 'ai_call_patterns';` and copy the signature assembly expression verbatim from it** — do not retype it from this doc. If it differs from what this kickoff shows (another session may have added a field), use the live one and note the difference in your report.

```sql
CREATE OR REPLACE VIEW ai_call_patterns AS
WITH sig AS MATERIALIZED (
  SELECT l.id, l.created_at, l.cost_usd,
    COALESCE(l.call_facts, '{}'::jsonb)
    || jsonb_build_object('model_modality', CASE WHEN l.model IS NULL THEN 'none' WHEN l.model LIKE 'text-embedding-%' THEN 'embedding' ELSE 'generative' END)
    || CASE WHEN l.feature ~ '^[^:]+:[^:]+:depth[0-9]+$' THEN jsonb_build_object('intent', split_part(l.feature, ':', 2)) ELSE '{}'::jsonb END
    || CASE WHEN (l.parent_span_id IS NOT NULL) OR (l.span_id IS NOT NULL AND EXISTS (SELECT 1 FROM ai_activity_log c WHERE c.parent_span_id = l.span_id)) THEN jsonb_build_object('sub_calls_chained', true) ELSE '{}'::jsonb END
    || CASE WHEN l.span_id IS NOT NULL THEN jsonb_build_object('integration_followed', (EXISTS (SELECT 1 FROM ai_activity_log t WHERE t.span_id = l.span_id AND ((t.created_at > l.created_at) OR (t.created_at = l.created_at AND t.id > l.id)) AND ((t.call_facts ->> 'input_references_other_deliverable')::boolean IS TRUE)))) ELSE '{}'::jsonb END
    || CASE WHEN ((l.call_facts -> 'delegation_target' ->> 'agent_id') IS NOT NULL AND (l.call_facts -> 'delegation_target' ->> 'capability_slug') IS NOT NULL AND (l.call_facts -> 'task_provenance' ->> 'agent_id') IS NOT NULL AND (l.call_facts -> 'task_provenance' ->> 'capability_slug') IS NOT NULL)
            THEN jsonb_build_object('delegated_to_provenance', ((l.call_facts -> 'delegation_target' ->> 'agent_id') = (l.call_facts -> 'task_provenance' ->> 'agent_id') AND (l.call_facts -> 'delegation_target' ->> 'capability_slug') = (l.call_facts -> 'task_provenance' ->> 'capability_slug')))
            ELSE '{}'::jsonb END AS signature
  FROM ai_activity_log l
),
uniq AS MATERIALIZED (
  SELECT DISTINCT signature FROM sig
),
matched AS MATERIALIZED (
  SELECT u.signature, pv.pattern_slug, pv.name AS pattern_name, pv.description AS pattern_description
  FROM uniq u
  JOIN pattern_vocabulary pv
    ON pv.criteria IS NOT NULL AND pv.superseded_by IS NULL
   AND pattern_criteria_matches(u.signature, pv.criteria)
)
SELECT s.id AS ai_activity_log_id, s.created_at, s.cost_usd,
       m.pattern_slug, m.pattern_name, m.pattern_description
FROM sig s JOIN matched m ON m.signature = s.signature;
```

Column list, names, order and types are **identical** to the current view — `ai_pattern_classification_rollup` and `ai_pattern_reclassification_count` sit on top unchanged and must not be edited.

## 8. NODE.JS TEST — `test-log-99.mjs` (full code; run `node --env-file=.env.local test-log-99.mjs`; delete before committing)

```js
// test-log-99.mjs — S-LOG-99 (v6.3.194) — classification read path under the anon timeout
// Category F (Supabase alignment + the anon-role timing that is the actual failure condition).
// NOTE: this test MUST use the anon key — the service role has no statement_timeout, so it
// cannot reproduce or disprove the failure this session exists to fix.
import { createClient } from '@supabase/supabase-js';

const supabase = createClient(process.env.VITE_SUPABASE_URL, process.env.VITE_SUPABASE_ANON_KEY);
let pass = 0, fail = 0;
const ok = (name, cond, detail = '') => {
  if (cond) { pass++; console.log(`  PASS  ${name}`); }
  else { fail++; console.log(`  FAIL  ${name} ${detail}`); }
};
const timed = async fn => { const t = Date.now(); const r = await fn(); return { ...r, ms: Date.now() - t }; };

// 1. The rollup — the exact request the panel makes (LOG-97 shape, with log_ids)
const rollup = await timed(() => supabase
  .from('ai_pattern_classification_rollup')
  .select('pattern_slug, pattern_name, pattern_description, call_count, cost_sum, log_ids'));
ok(`rollup succeeds as anon (${rollup.ms}ms)`, !rollup.error, rollup.error?.message);
ok(`rollup well under the 3s anon timeout (${rollup.ms}ms < 2000ms)`, !rollup.error && rollup.ms < 2000);
ok('rollup returns pattern rows', (rollup.data?.length ?? 0) > 0);
ok('every row still carries log_ids matching call_count (LOG-97 intact)',
   (rollup.data || []).every(r => (r.log_ids || []).length === r.call_count));

// 2. The reclassification count — the other read the panel makes
const recl = await timed(() => supabase
  .from('ai_pattern_reclassification_count').select('reclassification_count').single());
ok(`reclassification succeeds as anon (${recl.ms}ms)`, !recl.error, recl.error?.message);
ok(`reclassification under 2000ms (${recl.ms}ms)`, !recl.error && recl.ms < 2000);
ok('reclassification count is a positive integer', Number.isInteger(recl.data?.reclassification_count) && recl.data.reclassification_count > 0);

// 3. Arithmetic still reconciles: distinct classified + unclassified === total rows
const PAGE = 1000;
const pageAll = async (table, cols) => {
  const rows = []; let from = 0;
  while (true) {
    const { data, error } = await supabase.from(table).select(cols).range(from, from + PAGE - 1);
    if (error) throw new Error(`${table}: ${error.message}`);
    rows.push(...(data || []));
    if (!data || data.length < PAGE) break;
    from += PAGE;
  }
  return rows;
};
const { count: totalRows } = await supabase.from('ai_activity_log').select('id', { count: 'exact', head: true });
const distinctClassified = new Set((rollup.data || []).flatMap(r => r.log_ids || [])).size;
ok(`identity: distinct classified (${distinctClassified}) + reclassification (${recl.data?.reclassification_count}) === total (${totalRows})`,
   distinctClassified + (recl.data?.reclassification_count ?? -1) === totalRows);

// 4. Repeatability — a timeout that only bites on a cold cache would still break the panel
for (let i = 1; i <= 3; i++) {
  const r = await timed(() => supabase.from('ai_pattern_classification_rollup').select('pattern_slug, call_count, log_ids'));
  ok(`repeat run ${i} succeeds and stays fast (${r.ms}ms)`, !r.error && r.ms < 2000, r.error?.message);
}

console.log(fail === 0 ? `\nALL TESTS PASS (${pass})` : `\n${fail} FAILURES (${pass} passed)`);
if (fail > 0) process.exit(1);
```
