## CONTEXT

Two renames, bundled into one session because they touch the same file and John wants them done together, before `AA-116` (the next queued session) builds new code on top of correct terminology.

**1. "Stress Test" → "AI - Hypothesis Test."** John flagged that "Stress Test" reads as a software-testing term (load/stress testing code), not what the feature actually is — Priya Nair evaluating a director-submitted... a **user**-submitted hypothesis against the Data Room and returning a supports/complicates/consider verdict. John sees this as a platform differentiator worth its own branding, not just a label fix.

**2. "director" → "user."** John was reading "director" in the codebase and thought it might be an agent name. Confirmed it is not — no agent in `agents.js`'s 21-row roster is named or titled "director" or "GEO Director." It's the platform's internal term for the human operating the screen. John wants it generalized to "user" since the human can hold any real-world role, not just "director." Resolved explicitly as plain `"user"` — not "HITL User" (HITL is an existing, differently-scoped platform term: a Bench/Work-Order step-gate *type*, see `AboutPanel.jsx`'s own glossary and `PATTERN_CATALOG`'s `hitl` entry — "director" covers plain conversational actions too, not just review-gate moments, so collapsing the two would misname most of "director"'s actual uses) and not "GEO User" (John: drop the qualifier, just "user" everywhere).

**Explicitly NOT in scope — do not touch:** the already-`[Locked]` tagline *"Does this impress a procurement director AND a VP of Product?"* in `ARCHITECTURE.md`, `AGENT-ARCHITECTURE.md`, `DeepBench-Business-Context.md` — that's a real-world buyer-persona job title used for pitch purposes, a different usage entirely, confirmed with John.

This is a pure rename/terminology session — no new mechanism, no new AI call, no new UI element. `AA-116` (genuine multi-candidate routing for the renamed capability) is the very next session, deliberately sequenced after this one.
