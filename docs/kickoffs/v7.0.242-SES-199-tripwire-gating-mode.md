## What shipped

`--gate`, a second invocation. Same report, then a gate verdict: **exit 1** when any finding falls
in the gating set, **exit 0** otherwise. Without the flag nothing changes at all — no gate line,
always exit 0 — because that bare form is what CI runs today.

## The gating set, and why both halves of it are a decision

```js
const GATING_CHECKS   = new Set(["9", "10", "11"]);
const GATING_SEVERITY = "FLAG";
```

**Classes 9/10/11 — the truth-registry checks.** These are the ones that ask *"do two files still
tell the same story?"*: a retired rule still stated in live voice, a `canonical_doc` that does not
resolve, a `{{rule:ID}}` marker naming no registry row. The ticket draws this exact line in John's
own review — *"the over-cap description flags are plainly advisory, while a rule statement drifted
from its registry row plainly is not."* Checks 1–8 are size and shape ratchets; a doc a few KB over
baseline is a thing to tidy, never a reason to refuse a change.

**FLAG, not FLAG+WARN — and this is the half that was measured rather than chosen.** The script
already spends the severity distinction carefully: check 10 argues about *itself* that a stale
anchor is *"a stale anchor rather than a missing home — WARN, not FLAG."* Gating on FLAG reuses a
judgement the script already makes per finding instead of laying a second axis over the top of it.
Live board at this ship: classes 9/10/11 hold **0 FLAGs and 2 WARNs** — `B31`/`B32`'s stale anchors,
which are `SES-202`'s own ticket. **So the gate ships green.** Gating on WARN too would have shipped
a job red on arrival for drift another ticket already owns, which trains everyone to ignore it — the
rubber stamp's twin failure, not its fix.

**Fail-closed comes for free, and it is the property not to lose.** `loadRules()` already reports
both unreadable-snapshot cases (*missing*, *parses to zero rows*) as **check-9 FLAGs**, so a run
that could not read the registry at all **fails** the gate rather than passing it. A gate that goes
green having looked at nothing is the precise defect this ticket exists to close, and the guard
asserts it directly so a later edit cannot quietly reclassify those two findings out of the set.

## What this ticket deliberately does NOT do

`.github/workflows/ci.yml` is **unchanged**. The ticket's own boundary: *"This ticket makes the
CHECK capable of failing; making the FAILURE block a merge is his"* — branch protection and
repository secrets are John's alone (M2 gate review item 8, never to be carded). Switching CI's
invocation to `--gate` is the follow-up and is named on the ship card rather than done here.

## QA — discriminating, every case with its negative control

The suite guard (`tests/regression/SES-199-tripwire-gating.js`) imports `GATING_CHECKS`,
`GATING_SEVERITY`, `gatingFindings` and `gateModeRequested` **from the shipped script**, never a
copy — so a later widening of the set moves these assertions with it and shows up in this file's
diff.

| Case | Result | Negative control |
|---|---|---|
| check-10 FLAG gates | 1 gating finding | the same FLAG on check 1 (a size ratchet) → 0 |
| 21 advisory findings (18× check 3d + 3c/3e/6) | 0 | — the live board's real shape |
| check-10 **WARN** does not gate | 0 | the identical text at FLAG → 1, so the severity test is not passing because nothing gates |
| unreadable registry fails the gate | 1, both cases | — |
| `--gate` is opt-in | `--gate` true; bare and `--worktree=…` false | `--gateway` → false, so a future `--gate-list` cannot silently start failing runs |

**End-to-end through the real CLI, with the flag as the only variable** — the discriminating pair:

- fixture worktree with **no** `RULES-SNAPSHOT.md`, `--gate` → `GATE: FAILED — 1 FLAG finding`,
  **exit 1**
- **same fixture, same board, no `--gate`** → **exit 0**
- that fixture with the real snapshot copied in but none of the docs its rules point at → `GATE:
  FAILED — 4 FLAG findings` (check 10, canonical docs absent), exit 1 — the gate firing on real
  registry drift rather than only on the missing-file path
- the **live** repo, `--gate` → `GATE: clear — no FLAG findings in the gating classes`, exit 0

Proof type: **live end-to-end** (the shipped CLI, real exit codes) plus unit assertions on the
imported policy. Not a seam proof.
