## Boundaries this build holds

- **Restoring a recorded verdict is TRANSCRIPTION, never a decision the runner makes.** Each of the
  three is independently evidenced — the committed markdown at `v7.0.171` carrying his timestamp,
  plus `SES-133`'s own filing. `provenance` on each row says exactly that, which is what
  `ck_vision_claim_decided` exists to force. **A claim with no such record stays `proposed`**, and
  this build promotes none.
- **No markdown was touched.** The status column is the home; editing the corpus files to "match"
  would give one fact two homes, which is the defect this platform has paid for at `SES-116`,
  `SES-113` and `SES-86` phase 3.
- **The guard is one-directional on purpose.** It flags a `proposed` row whose own text records a
  decision. It does **not** require a ratified row to carry a prose marker, and it never parses
  `claim_text` to decide status — that would rebuild the two-homes defect facing the other way.
