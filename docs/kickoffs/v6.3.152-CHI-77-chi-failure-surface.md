## CONTEXT

**Use case.** A user asks a Channel Intelligence question. The full agent pipeline runs — Marcus answers, Owen's quality gate reviews, the display agent formats — and something throws *after* Marcus's answer (an intermittent, transient failure; verified live 2026-07-27 that the backend returns HTTP 200 on every call, so the throw is a streamed `error` event, a stream that ended without a `result`, or a client-side post-processing error, never a non-2xx). The user sees **"Something went wrong reaching Marcus — try again."** and the ~60–100s of work is gone. Two things are wrong with that surface:

1. **The reason is silently discarded.** `onSend`'s catch only does `console.error(…, e.message)` — the real cause exists solely in the browser console, so neither the user, John, nor a repro run can recover *why* it failed. This is the **one** async catch on this screen that drops the reason: the four sibling catches (hypothesis generation, hypothesis test, commit, resolve-confirmation) all already emit an `"error"` Pipeline Log event (MI-29) that renders in the Audit Pipeline Log (Column 3) as a red row *"Ran into a problem partway through — {reason}"*. `onSend` was left out of that pattern.
2. **The message is misleading.** "reaching Marcus" is wrong — Marcus *was* reached (he produced the answer); the break is downstream of him.

**The fix** extends the existing, proven MI-29 mechanism to `onSend`'s catch (surface the reason into Column 3, where the audit trail already lives) and replaces the misleading copy with an honest fault report. Per `ARCHITECTURE.md` §19j, a failure notice is the platform reporting on its own state — a **fault report, explicitly allowed** — not screen-authored agent content. "Try again" **stays**: this failure is transient (unlike `CHI-66`'s deterministic drawer re-crash), so retrying is genuinely the right advice.

**Attribution decision (Tier-2, design session's call):** the emitted error event is attributed to `agent_id "marcus"` — the conversational front-door agent, consistent with the screen's "Chat with Marcus" framing — because `onSend` can't know *which* hop threw (Marcus / Owen / Michelle / Eleanor / display). This is honest: the row's *text* claims only that the platform broke partway through, and the `{reason}` string carries the real technical detail (which itself names the failing capability, e.g. `quality-gate qg-review-intent failed: 500`). `RoutingHopCard` renders `"marcus"` cleanly (avatar + name); a neutral non-roster id would print an ugly raw string.

**Out of scope (own rows, already logged this session):** durable *server-side* recording of client failures (`CHI-78`-adjacent, touches `api/`) is **not** here — the Pipeline Log is session-ephemeral by design. The intermittent failure itself is `CHI-78`; the `delegation_complete` durationMs warning was already tracked as `CHI-64` (re-confirmed live 2026-07-27, not a new row).

## TASKS (2)

### Task 1 — string-safe reason extractor

Add a module-scope helper immediately after `buildHopEvent()` ([L1018](src/screens/MarketIntelligenceScreen.jsx:1018)). It must be string-safe: the thrown value may be a real `Error` (with `.message`/`.status`/`.detail` — see the stream-error path L546 and the resolve path L1265), a plain string, or any object, and `.message` may be `undefined`.

```jsx
// FEATURE: CHI-77 — extracts a human-readable reason from a caught error for the Pipeline Log's
// "error" row. String-safe by construction (STANDARDS.md String Safety): the thrown value can be a
// real Error, a bare string, or an arbitrary object, and .message can be undefined. Surfaces the
// .status and .detail that callCapability's throws (L546 stream-error, L1265 resolve) already carry
// and that onSend's catch currently drops on the floor. Pure string in, pure string out.
function describeCaughtError(e) {
  const base = (e && typeof e.message === "string" && e.message) ? e.message : String(e);
  const status = (e && e.status != null) ? ` (status ${e.status})` : "";
  const detail = (e && typeof e.detail === "string" && e.detail) ? ` — ${e.detail}` : "";
  return `${base}${status}${detail}`;
}
```

```js
// test-chi-76.mjs — pure Node, no app imports.

let pass = 0, fail = 0;
function assert(cond, label) {
  if (cond) { pass++; console.log(`PASS: ${label}`); }
  else { fail++; console.log(`FAIL: ${label}`); }
}

// --- Mirror of Task 1: describeCaughtError ---
function describeCaughtError(e) {
  const base = (e && typeof e.message === "string" && e.message) ? e.message : String(e);
  const status = (e && e.status != null) ? ` (status ${e.status})` : "";
  const detail = (e && typeof e.detail === "string" && e.detail) ? ` — ${e.detail}` : "";
  return `${base}${status}${detail}`;
}

// Real Error from callCapability's !res.ok throw (L1222): message names the failing capability
assert(describeCaughtError(new Error("quality-gate qg-review-intent failed: 500")) === "quality-gate qg-review-intent failed: 500", "plain Error message passes through");

// Stream-error path (L546): Error with .status and .detail attached
{
  const e = Object.assign(new Error("model overloaded"), { status: 529, detail: "upstream timeout" });
  assert(describeCaughtError(e) === "model overloaded (status 529) — upstream timeout", "status + string detail appended");
}

// status present, detail null (resolve path L1265 shape)
{
  const e = Object.assign(new Error("resolve accept failed: 500"), { status: 500, detail: null });
  assert(describeCaughtError(e) === "resolve accept failed: 500 (status 500)", "null detail omitted, status kept");
}

// "Stream ended without a result event" (L550) — bare Error, no status/detail
assert(describeCaughtError(new Error("Stream ended without a result event")) === "Stream ended without a result event", "no status/detail: message only");

// String Safety: message undefined, thrown non-Error, and object detail must never crash or leak "[object Object]" into status/detail
assert(describeCaughtError({}) === "[object Object]", "object with no message: String(e) fallback, no throw");
assert(describeCaughtError("boom") === "boom", "thrown string: used directly");
assert(describeCaughtError(null) === "null", "null: String(null), no throw");
{
  const e = Object.assign(new Error("bad"), { status: 500, detail: { nested: true } });
  assert(describeCaughtError(e) === "bad (status 500)", "object (non-string) detail is ignored, not stringified into junk");
}
{
  const e = Object.assign(new Error(""), { status: 0 });
  // empty message -> String(e) === "Error"; status 0 is != null so it shows (0 is a real status)
  assert(describeCaughtError(e) === "Error (status 0)", "empty message falls back to String(e); status 0 is not dropped");
}

console.log(`\n${pass} PASS, ${fail} FAIL`);
if (fail > 0) { console.log("ALL TESTS PASS: NO — fix before committing"); process.exit(1); }
console.log("ALL TESTS PASS");
```
