## 2. CONTEXT — a real finding from the live build log, not a hypothesis

`ABT-1d`'s deepen attempt shipped, and the Vercel build log for commit `13de040` shows it **succeeding** — and then the tile still not updating:

```
platform-stats: deepened shallow clone for an accurate commit count
platform-stats: commit count not trusted (shallow clone) — preserving stored value
platform-stats: updated OK (dev_toolchain_services preserved at 6, commits_dev 1533)
```

Both lines fired in the same run. `git fetch --unshallow` returned success, but the **second** `git rev-parse --is-shallow-repository` check (the one guarding the count, ~line 108) still reported `true`, so the count was discarded unread. Why Vercel's git still reports shallow after a successful unshallow is not established, and this session does not need to establish it.

**The insight:** that flag check is redundant *and* actively harmful. The script already reads the stored row and refuses any computed count lower than it (the monotonic guard) — and a genuinely shallow checkout produces ~10, which that guard rejects on its own. Gating on the flag adds no protection the comparison doesn't already give, while throwing away counts that may be perfectly correct — which is exactly what happened above.

**The fix:** always compute the count, and let the comparison decide. Every case stays safe:

| Situation | Computed | Outcome |
|---|---|---|
| Truly shallow, deepen failed | ~10 | `10 < 1533` → omitted, stored value preserved ✓ |
| Deepen worked (flag stale or not) | ≥ 1533 | written — the tile finally advances ✓ |
| `git` missing or throws | none | omitted, preserved ✓ |
| History rewritten (force-push) | lower | omitted, preserved — safe, and vanishingly rare ✓ |

### Task 1 — `scripts/platform-stats.js`: stop gating the count on the shallow flag

In the `commits_dev` block (~lines 102–120), **remove the `is-shallow-repository` branch** so the count is always computed:

```js
let commits_dev = null;
let commitsReason = "";
try {
  commits_dev = parseInt(git("git rev-list --count HEAD"), 10);
  if (!Number.isFinite(commits_dev) || commits_dev <= 0) {
    commits_dev = null;
    commitsReason = "git returned no usable count";
  }
} catch (err) {
  commits_dev = null;
  commitsReason = `git unavailable (${err?.message?.split("\n")[0] || err})`;
}
```

Everything downstream — the stored-row GET, the `computed < stored` comparison, the omission of `commits_dev` from the PATCH body when it can't be trusted, and its log line — stays exactly as it is. **That comparison is now the single guard, and it must not be weakened or reordered.**

Keep `ABT-1d`'s deepen attempt (~lines 85–100) unchanged: it still runs, still logs, and now its success can actually pay off.

Update the comment above the block so it explains the new reasoning rather than the removed one: the count is always computed because a shallow checkout is caught by the monotonic comparison below, which is cause-agnostic and does not depend on git's shallow flag being accurate after a fetch.

## 8. NODE.JS TEST (save as `test-abt-1e.mjs`, run `node --env-file=.env.local test-abt-1e.mjs`, delete before committing)

**Ordering note carried from `ABT-1d`:** the shallow-clone test clones `file://$PWD`, which reads *committed* HEAD — so commit the script change before running this test, or the clone silently exercises the old code. Nothing gets pushed until the test passes.

```js
// test-abt-1e.mjs — S-ABT-1e verification
import { execSync } from "node:child_process";
import { readFileSync, mkdtempSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";
import assert from "node:assert";
let pass = 0;
const ok = (c, m) => { assert.ok(c, m); console.log("PASS:", m); pass++; };

const src = readFileSync("scripts/platform-stats.js", "utf8");
const countBlock = src.slice(src.indexOf("let commits_dev"), src.indexOf("const stats ="));
ok(!/is-shallow-repository/.test(countBlock), "count block no longer gates on the shallow flag");
ok(/rev-list --count HEAD/.test(countBlock), "count is always computed");
ok(/--unshallow/.test(src), "ABT-1d deepen attempt retained");
ok(/--soft/.test(src) && /VERCEL_GIT_COMMIT_REF/.test(src), "ABT-1c soft + preview guards retained");

const url = process.env.SUPABASE_URL || process.env.VITE_SUPABASE_URL;
const key = process.env.SUPABASE_ANON_KEY || process.env.VITE_SUPABASE_ANON_KEY;
const get = async () => (await (await fetch(`${url}/rest/v1/platform_stats?id=eq.1&select=*`,
  { headers: { apikey: key, Authorization: `Bearer ${key}` } })).json())[0];
const before = await get();

// A shallow clone whose origin is unreachable: deepen fails, count computes small,
// and the monotonic guard alone must protect the stored value. Exit 0 in soft mode.
const dir = mkdtempSync(join(tmpdir(), "abt1e-"));
const clone = join(dir, "repo");
execSync(`git clone --depth 1 file://${process.cwd().replace(/\\/g, "/")} "${clone}"`, { stdio: "pipe" });
execSync(`git -C "${clone}" remote set-url origin file:///nonexistent-abt1e`, { stdio: "pipe" });
let exitCode = 0, out = "";
try {
  out = execSync(`node "${join(clone, "scripts/platform-stats.js")}" --soft`,
    { cwd: clone, encoding: "utf8", env: { ...process.env, SUPABASE_URL: url, SUPABASE_ANON_KEY: key } });
} catch (e) { exitCode = e.status ?? 1; out = String(e.stdout || ""); }
console.log(out);
ok(exitCode === 0, "unreachable-origin shallow run still exits 0 (deploy-safe)");
ok(/looks truncated/.test(out), "monotonic guard — not the shallow flag — rejected the small count");
const afterShallow = await get();
ok(afterShallow.commits_dev === before.commits_dev, `stored commits_dev protected (${before.commits_dev})`);
ok(afterShallow.dev_toolchain_services === before.dev_toolchain_services, "toolchain preserved");

// Full-depth run writes a real count.
execSync("node scripts/platform-stats.js", { encoding: "utf8" });
const after = await get();
ok(after.commits_dev >= before.commits_dev, `full-depth count written (${after.commits_dev})`);

console.log(`ALL TESTS PASS (${pass})`);
```
