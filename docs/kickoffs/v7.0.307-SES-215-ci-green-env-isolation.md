## The premise, revalidated live rather than recalled

`v7.0.305` shipped the fix itself and it works: run `33236634108` shows `LOG-41` declaring its
anon arm **not-run** instead of failing 401, which is the defect `SES-215` was filed for. What is
red is `SES-215`'s **own guard**, `tests/regression/SES-215-env-isolation.js`, on two assertions:

```
[FAIL] SES-215-env-isolation.js -- the retired runner failed the fixture for some OTHER reason
       than the env leak -- got:
  [PASS] a-leaks.js
  [PASS] b-reads.js
  [FAIL] retired-run-all.mjs -- retired-run-all.mjs does not export a default async function
regression suite: 2/3 passed
```

**The directive's hypothesis is corrected rather than carried forward.** It named *"Node 24 on the
runners vs the repo's Node 22 assumption; or a fixture file shape/path difference"*. Reproduced on
**Node v22.22.2 in this clone at 06:47Z, byte-identical output** — so it is not a Node-version
difference at all, and it reproduces on every machine, not only CI. The second half of the guess is
right, and there is a second defect underneath it that no environment can dodge.

## Two defects, both in the guard's part 4 (the file-level negative control)

**Defect 1 — the control runner is written INTO the fixture directory it is about to scan.**
`controlPath = path.join(fixture, "retired-run-all.mjs")`, and `run-all.js` discovers tests with
`readdirSync(DIR).filter(f => (f.endsWith(".js") || f.endsWith(".mjs")) && f !== "run-all.js" &&
!f.startsWith("_"))`. `retired-run-all.mjs` matches all three tests, so the control runner picks
**itself** up as a third fixture test, fails to import it as one, and reports `2/3`. The
`status === 1` assertion above it then passes **for the wrong reason** — which is the part worth
reading twice: the control appeared to be working while measuring nothing.

**Defect 2 — the control's SOURCE is `origin/dev`, which on CI is the commit under test.**
`retiredRunnerSource()` runs `git show origin/dev:tests/regression/run-all.js`. That was the
retired file exactly once — locally, before the fix was pushed. The moment `v7.0.305` landed,
`origin/dev`'s copy **is the fixed runner**, so the control restores the environment, `b-reads.js`
passes, and the leak the assertion looks for can never appear. On CI it is worse than stale: the
workflow uses `actions/checkout@v4` at its default depth, which creates `refs/remotes/origin/dev`
pointing at **the very commit being tested** — so on CI the "retired" control is *by construction*
the current file, on every run, forever. Verified rather than assumed: `origin/dev`'s copy carries
`delete process.env[key]` (the fix); `f7f3cd0^` (= `4d87cc6`, the commit before `v7.0.305`) carries
neither `snapshotEnv` nor the delete-half.

This is the guard grading its own change — the same class `SELFBUILD-CHARTER.md` item 3 and
`scripts/verifier.js`'s `SELF_CERTIFYING_PATHS` exist to refuse.

## What ships (1 source file, 3 tasks)

`tests/regression/SES-215-env-isolation.js` only. No `src/`, `api/`, `lib/`, schema or site change.

1. **Write the control runner outside the fixture directory.** Its own `mkdtemp` directory, so the
   fixture holds exactly the two files it declares. Costs nothing: the control's `_lib/self-run.js`
   specifier is already rewritten to an absolute `file://` URL, so its location is free. The
   guard additionally asserts the fixture directory holds exactly `a-leaks.js` + `b-reads.js` and
   that the control suite reports `2/2`, never `2/3` — so defect 1 cannot come back silently as a
   passing `status === 1`.
2. **Pin the git control to the pre-fix commit, not to a moving branch.** `f7f3cd0^` is resolved by
   *content*, not by a hardcoded SHA: walk `git log` for `tests/regression/run-all.js`, take the
   newest commit whose copy does **not** contain the restore, and use that. Unreachable (shallow
   clone — which is exactly CI) → the existing `notRun()` path, unchanged.
3. **Add a control that always runs, so CI is not left with none.** The git control declares
   not-run on CI by construction, and a guard whose only control is absent where it gates the push
   is not measuring anything there. The always-run control is the shipped runner with the
   `added-keys-are-deleted` mutation applied — the same `breaks()` that part 2 already proves is
   non-vacuous — asserted to LOSE on the same fixture with the leak message.

**Not weakened, and stated because the directive's words are *"WITHOUT weakening the
assertion"*:** the real-file control is kept, not replaced. The reconstruction is **added**
alongside it. Where both can run, both run.

## The edit this ship forbids

**Do not "fix" this by deleting the file-level control, and do not re-point it at `origin/dev`.**
A control taken from the branch the fix lands on is a control that agrees with the shipped file the
day after it ships — `SES-213`'s lesson (*assert a DIFFERENCE from the retired behaviour, never a
property both implementations share*) applied to the ref rather than to the code. And do not move
the control runner back into the fixture directory to "keep the temp dirs down": that is defect 1,
and it presents as a **passing** `status === 1`.
