## 1. CONTEXT

**This is a bug-fix session, not a feature session.** Investigating why Column 2 (Theory Evidence) charts haven't appeared in several sessions, this design session found — via 3 live calls against the deployed dev `/api/capabilities/execute` — that the visualization mechanism itself (`AA-117`/`MI-13`) works perfectly, but the real production hand-off for `AI - Hypothesis Test`'s display formatting (Priya → `request_help` → Michelle → `delegate_to_agent` → Alex) returns **zero card content at all** (no `headline`/`supports`/`complicates`/`key_data_points`/`visualization`), 100% reproducible across 2 independent live runs.

**Root cause, confirmed by direct code read, not assumed:**
1. `delegate_to_agent`'s `task` field (`request-receivable.js`'s `DELEGATE_TO_AGENT_TOOL`) is a plain `string` — generic across every capability's delegation, by design. The delegating agent (Priya) must paraphrase her own structured input (`supports`/`complicates`/`consider`, with real citation UUIDs) into free text for that one field.
2. `execute.js`'s `delegate_to_agent` branch (`runLoop()`, line ~304-313) builds the delegate's entire `task_context` from `task` alone — `task_context: task`. The delegator's own real, structured `task_context` (the thing that was passed into *this* `runCapability()`/`runLoop()` call in the first place) is available in the enclosing scope today only up through `runCapability()` — it is **not currently threaded into `runLoop()`** at all (confirmed: `runLoop()`'s destructured params, line 170-176, do not include `task_context`; `runCapability()`'s call to `runLoop()`, line 423-429, does not pass it).
3. `intelligence-review-format`'s own method requires every field — especially `key_data_points`' citations — to trace back to real given content. Fed only Priya's lossy paraphrase (no real citation IDs), Alex's turn cannot produce a valid, fully-populated response.
4. `execute.js`'s `is_final === true` branch (line 339-346) spreads `...delegateResult.content` into the final result with no check that it's non-empty. Whatever went wrong inside Alex's own call (exact sub-mode unconfirmed — Supabase's `ai_activity_log` stores no response bodies, so this design session could not inspect it further without adding temporary instrumentation, left to this session's Task 1 diagnostic step below) is silently absorbed into an empty card instead of surfacing as an error.

**Proof the mechanism itself is sound, not broken:** a direct call to `screen-controls`/`intelligence-review-format` with a hand-built, fully-structured `task_context` (real `supports`/`complicates`/`consider`, real citation UUIDs) returned a complete 8-field card **and** a correctly-populated `visualization` (`bar_pair`, Nordholm co-op utilization 55% vs 90% target). This session's fix is entirely about what data reaches Alex, never about the `ChartRenderer`/schema mechanism, which is untouched.

**The fix, two parts:**
- **Task 1 (the real fix):** thread the delegator's own `task_context` through `runLoop()` and merge it into the delegate's `task_context` at the `delegate_to_agent` branch, instead of relying solely on the delegator's free-text `task` string. Harness-generic — applies to every `delegate_to_agent`+`is_final` hand-off (Marcus→Alex on the Q&A path too), not a Priya/Alex-specific patch. No agent_id/capability_slug is hardcoded anywhere by this change — routing/selection stays exactly as agent-reasoned as it is today (`ARCHITECTURE.md` §19d sniff test: confirmed with John before this kickoff was written).
- **Task 2 (the safety net):** when a `delegate_to_agent` call with `is_final: true` returns empty content, throw a clear error naming the delegate agent/capability instead of silently returning a hollow card — same "fail safe, never fake" principle already applied by `AA-108`'s `assemblePrompt()` guard.

**Why this blocks `S-MARKET-INTEL-03`:** the "has charts" deliverable was previously logged as "roadmap, not a bug." That framing is now known to be wrong — no seed question, however clean the underlying metric, can produce a visible chart today, because the card is empty before the chart-worthiness question is even reached. This session unblocks it.

## 6. SCOPE RULES — what NOT to touch

- Do not change `delegate_to_agent`/`request_help`'s routing or candidate-selection logic — this session only changes what data accompanies a delegation the model has already decided to make (target agent/capability/intent stay 100% the model's own tool-call arguments, exactly as today).
- Do not touch `intelligence-review-format`'s Supabase schema/method text — its citation-grounding rule is correct as-is; the bug is that it wasn't being given real citations to ground against, not that its own rule is wrong.
- Do not touch `ChartRenderer`/`CHART_RENDERERS`/`EvidenceColumn` (`SharedUI.jsx`/`MarketIntelligenceScreen.jsx`) — confirmed working correctly by this design session's direct-call test; out of scope.
- Do not add a `.goal`-shaped merge special-case: none of today's 3 real `delegate_to_agent`(+`is_final`) callers (Marcus's `ci-answer-display-intent`, Priya's `hyp-hypothesis-test-display-intent`, Owen's non-final `qg-review-intent` retry) have a `.goal` key in their own `task_context`, so the merge in Task 1d cannot collide with `db-assembly.js`'s CURRENT TASK/`.goal` path today. If a future capability's `task_context` does include `.goal`, its delegate would see the delegator's original goal folded into TASK DETAILS alongside `delegation_task` — worth a comment for whoever adds that capability, not a defensive branch here for a case that doesn't exist yet.
- Do not attempt to distinguish *why* a delegate returned empty content (guardrail block vs. decline vs. something else) in code — Task 2's guard is deliberately failure-mode-agnostic. The Node test's live re-run (Task 7) will report whichever it actually is via `delegateResult.violations`/logs, informative for the record, not a reason to branch behavior on it.
- Do not touch `resumeCapability()`'s `durable_hops` schema (no new persisted column for `task_context`) — the accepted gap in Task 1c matches `AA-139`'s existing precedent for other non-persisted fields; a real need to persist it can be its own future session if it ever actually matters in practice.
