## 2. CONTEXT

`identityForRow()` (`src/hooks/useAIActivity.js:780`) resolves one log row to one caller identity
through four tiers. Its **final fallback** (line 810-812) keys an unlabelled row by its masked
address alone:

```js
return vid
  ? { key: `visitor:${vid}`, name, label: name, ip, org, city }
  : { key: `ip:${ip}`, name, label: org || ip, ip, org, city };
```

There is no `call_source` check on that path, and neither earlier tier can divert these rows:
Tier 1/2 needs a `known_callers` match (the live table holds **4 rows, all `match_type='visitor_id'`**
— no IP-type entries at all), and Tier 3 (line 792) is explicitly `call_source === 'ui'` only, so
automated traffic never folds. Every cookie-less row at one address therefore collapses into a
single `ip:` bucket regardless of what produced it.

**Measured live this cycle** (`ai_activity_log`, no-`visitor_id` rows grouped by masked address ×
`call_source`):

| Masked address | Contents of the single `ip:` bucket |
|---|---|
| `xxx.xx.43.148` | **845 regression** + 8 ui |
| `xxx.xx.33.12` | 210 regression + 2 script + 616 ui |
| `xxx.xx.22.58` | 9 script + 4 session-test + 62 ui + 96 NULL |

`xxx.xx.22.58` and `xxx.xx.33.12` both resolve in `ip_org_cache` to **"AS16591 Google Fiber Inc."** —
the ticket's exact example. So a row labelled with a real org name is, today, part regression driver
and part unattributable browser traffic, with nothing on screen saying so.

This is a **labelling** defect on a non-beta surface, not a correctness one: no number is wrong, the
rows are simply merged under one name.

## 8. NODE.JS TEST

imports the repo's own `buildByCaller` and runs it against a fixture, rather than driving the live
screen). Fixture: no-`visitor_id` rows sharing one masked address — one `call_source:'regression'`,

- **Flag OFF** (`buildByCaller(rows, [], [])`, no opts): exactly **one** group for the address,
  holding all three rows. Proves default-off preserves today's behaviour exactly.
- **Flag ON** (`{ splitAutomated: true }`): exactly **two** groups — the automated bucket holds only
  the regression row; the `ui` and NULL rows stay in the original `ip:` bucket.
- **Conservation:** summed `calls` and `cost` across both ON groups equal the OFF group's totals.

**Would it still pass if the change did nothing?** **No.** With no change `buildByCaller` ignores a
fourth argument and both assertions on the ON side fail — one group is returned where two are
required. The OFF-side assertion alone would pass vacuously, which is exactly why the ON-side
two-group assertion is the discriminating half.
