## 2. CONTEXT

`SES-31` (v6.3.202) removed every `[object Object]` path the S-SES-29 root-cause investigation had found — but one of the same class survived, discovered by that session's own coding agent while verifying, and confirmed independently by this design session against live Supabase and the screen source. Two defects, one site each, both on the "Owen Marsh (Proofreader) regenerated the answer" branch:

1. **Object-as-string.** `qg-review-intent`'s `final_answer` is an OBJECT — `{answer, citations, confidence_tier}` — or null (verified live: `skill_profiles.traits->schema->properties->final_answer`, `"type": ["object","null"]`, described as "the regenerated answer that ultimately passed"). The driver treats it as a string in two places: `runDirectCaseJourney`'s `const finalAnswer = gate.final_answer || qa.answer;` and `runRejectionProbe`'s judge input `gate.final_answer || qa.answer`. Because a non-null object is truthy, whenever Owen retried, the raw object goes into `ci-answer-display-intent`'s `task_context.answer` and into the judge's `artifact_content` — the exact `[object Object]` class `SES-31` just eliminated everywhere else.

2. **Wrong provenance on the other two fields.** The screen swaps the whole triple: `const finalAnswer = retried ? gate.final_answer : qa;` then passes `finalAnswer.answer`, `finalAnswer.citations`, `finalAnswer.confidence_tier` (screen lines 1519 and 1553). The driver always passes `qa.citations` / `qa.confidence_tier` — the ORIGINAL answer's — even when Owen's regenerated answer replaced the text. So a retried case is displayed and judged with mismatched answer-vs-citations provenance.

This fires on exactly the cases the regression cares most about: any case whose answer got blocked and regenerated (case 13 `meridian-electronics` did so repeatedly in the first run's five-try probe). Leaving it would put a known poisoned path into the rerun.

## 5. TASKS (2)

## Task 1 — One exported helper, screen-parity semantics

Add near the other flatten/parity helpers:

```js
// Owen Marsh (Proofreader) returns final_answer as {answer, citations, confidence_tier} (or null)
// when he regenerated a blocked answer. Screen parity: MarketIntelligenceScreen.jsx:1519 swaps the
// WHOLE object, then reads .answer/.citations/.confidence_tier off whichever won.
export function resolveGatedAnswer(gate, qa) { ... }
```

Returns `{ answer, citations, confidence_tier, retried }`:
- `retried` = `!!gate?.final_answer` (screen line 1492's own test).
- When retried: take all three fields from `gate.final_answer`, falling back **per field** to `qa`'s value when the regenerated object omits that field (only `answer` is load-bearing; `citations`/`confidence_tier` are optional in the schema).
- When not retried: all three from `qa`.
- Defensive: if `gate.final_answer` is a plain STRING (contract drift), treat it as the answer text and keep `qa`'s citations/confidence_tier — never let a string be dereferenced into `undefined` fields.

Use it at both sites: `runDirectCaseJourney` (feeding `ci-answer-display-intent`'s `task_context.answer`/`citations`/`confidence_tier`) and `runRejectionProbe`'s judge `artifact_content` (which must receive the `.answer` STRING).

Add a cheap runtime assertion (throw with a clear message naming the field and the received type) rather than silently coercing — a shape change upstream is a finding, consistent with Task 1's parent-session `pickHypothesisText` precedent.
