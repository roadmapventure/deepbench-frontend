## CONTEXT

The AI Audit screen's "By Pattern" section (`AIActivityPanel.jsx`) has two integrity bugs, both confirmed live against Supabase, not assumed:

1. **Silent data loss (`LOG-31`/`LOG-32`).** `useAIActivity.js`'s `computeByPattern()` already has a correct self-maintaining fallback (`LOG-14`): any real, logged pattern slug not in `PATTERN_CATALOG` gets its own auto-labeled entry with `patternType: 'unknown'` instead of being silently dropped. But `AIActivityPanel.jsx`'s render logic sorts patterns into exactly three buckets — `structural`, `reasoning`, `inactive` — none of which match `patternType: 'unknown'` combined with `active: true`. The fallback entry the read layer correctly produces has nowhere to render. Confirmed live: 18 real rows carrying the historical slug `reflection` are invisible on the screen today. **Important scope correction found during this session's Architect Review:** the write-site bug `LOG-32` originally described (the wrong slug being logged) is **already fixed** — `api/prompt/ai-enrichment.js` (lines 274-289, comment tagged `AA-190c`) confirms every current call already logs the correct `reflect` slug. The 18 `reflection` rows are permanent historical residue from before that fix, not a live bug. Per `ARCHITECTURE.md §19i`'s own rule ("historical data cannot be retroactively corrected... pre-cutoff rows stay honestly labeled, not silently assumed either way, forever"), these rows are not renamed or merged — they simply need a place to display, which this session's `LOG-31` fix provides.
2. **Dishonest header stat (`LOG-30`/`LOG-34`).** `shared/ai-patterns.js`'s `PATTERN_CATALOG` flags `react` as `active: true`, despite zero real logged rows ever (confirmed live: `SELECT count(*) FROM ai_activity_log WHERE patterns_used::text ILIKE '%react%'` → `0`). `ARCHITECTURE.md §19i`'s own status table already lists `react` as "Roadmap/inactive" — the catalog and the locked architecture doc currently disagree. `useAIActivity.js`'s `patternsActiveCount` (the AI Audit header's "Patterns Active X/Y" stat) is a direct `PATTERN_CATALOG.filter(p => p.active).length` — a static count of declared flags, not derived from real usage — so correcting the flag directly corrects the header number too. No separate stat-computation change is needed for `LOG-34`; it collapses into the same one-line fix as `LOG-30`.

**Why this matters:** these are the only two currently-open findings in the AI Audit "By Pattern" investigation that produce a live, visibly-wrong result — real data invisible, or a header number that doesn't match reality. Everything else in that investigation (`LOG-17`, `LOG-23` through `LOG-27`, `AI-35`, `AI-46`/`LOG-22`) is either a deeper detection-architecture question awaiting John's input, or lives in different files entirely — deliberately out of scope here, see SCOPE RULES.

// test-log30-pattern-display.mjs -- verifies LOG-30/31/32/34 in isolation from React rendering:
// (1) react is now active:false and excluded from the header's active count, (2) computeByPattern's
// existing LOG-14 fallback for an uncatalogued slug produces an entry that falls through all 3
// original buckets (reproducing the bug pre-fix) and is caught by the new 4th bucket condition
// (proving the fix). Run with: node test-log30-pattern-display.mjs
import assert from 'node:assert';
import { computeByPattern } from './src/hooks/useAIActivity.js';
import { PATTERN_CATALOG } from './shared/ai-patterns.js';

let pass = 0;
function check(label, fn) { fn(); pass++; console.log(`PASS: ${label}`); }

check('react entry still exists in the catalog', () => {
  const reactEntry = PATTERN_CATALOG.find(p => p.slug === 'react');
  assert.ok(reactEntry, 'react must not be removed from the catalog, only deactivated');
});

check('react is active:false (LOG-30) -- matches ARCHITECTURE.md §19i, zero real usage confirmed live', () => {
  const reactEntry = PATTERN_CATALOG.find(p => p.slug === 'react');
  assert.strictEqual(reactEntry.active, false);
});

check('patternsActiveCount no longer counts react (LOG-34)', () => {
  const activeSlugs = PATTERN_CATALOG.filter(p => p.active).map(p => p.slug);
  assert.ok(!activeSlugs.includes('react'));
});

check('computeByPattern still produces a fallback entry for an uncatalogued slug (LOG-14, unchanged)', () => {
  const fakeLog = [{ patternsUsed: ['totally-uncatalogued-test-slug'], ts: new Date().toISOString(), type: 'agent-turn', cost: 3 }];
  const byPattern = computeByPattern(fakeLog);
  const entry = byPattern['totally-uncatalogued-test-slug'];
  assert.ok(entry, 'LOG-14 fallback must still fire for a slug not in PATTERN_CATALOG');
  assert.strictEqual(entry.patternType, 'unknown');
  assert.strictEqual(entry.active, true);
  assert.strictEqual(entry.total, 1);
});

check('pre-fix: that entry falls through all 3 original buckets (reproduces LOG-31 before the fix)', () => {
  const entry = { active: true, patternType: 'unknown', partial: undefined, hitlSpecial: undefined };
  const isStructural = (entry.active || entry.partial) && entry.patternType === 'structural';
  const isReasoning  = (entry.active || entry.hitlSpecial || entry.partial) && entry.patternType === 'reasoning';
  const isInactive   = !entry.active && !entry.hitlSpecial && !entry.partial;
  assert.ok(!isStructural && !isReasoning && !isInactive, 'entry must match none of the 3 original buckets -- this is the bug');
});

check('post-fix: the new 4th bucket condition catches exactly that entry (proves LOG-31/32 fix)', () => {
  const entry = { active: true, patternType: 'unknown', partial: undefined, hitlSpecial: undefined };
  const structural = [].filter(p => (p.active || p.partial) && p.patternType === 'structural');
  const reasoning  = [].filter(p => (p.active || p.hitlSpecial || p.partial) && p.patternType === 'reasoning');
  const inactive   = [].filter(p => !p.active && !p.hitlSpecial && !p.partial);
  const uncatalogued = [entry].filter(p => !structural.includes(p) && !reasoning.includes(p) && !inactive.includes(p));
  assert.strictEqual(uncatalogued.length, 1, 'the uncatalogued entry must be caught by the new 4th bucket');
});

console.log(`${pass}/6 PASS`);
