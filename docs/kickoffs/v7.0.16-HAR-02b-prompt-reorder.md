## 2. CONTEXT
Anthropic prompt caching is a byte-prefix match: only an *unchanged leading portion* of the prompt can be cached. Today the assembled prompt interleaves per-call content (prior conversation at order 2.4, current task at 2.5, reflect at 4.5, RAG at 5) into the middle of the stable agent content (identity 3, behavior 4, guardrails 6), so the cacheable prefix is only Format+Intent — almost nothing. This session reorders assembly so **everything stable renders first, everything per-call renders last**, and threads the stable/volatile boundary through the render so S-HAR-02c can place `cache_control` breakpoints on it. VOICE (`AA-127`) stays the absolute last section — that decision is preserved.

**This session changes the order the model reads its sections in, on every capability, platform-wide.** That is deliberate and approved (John, this design session), gated on the Manual QA regression A/B below. This session does NOT add any `cache_control` — the reorder ships alone so the A/B isolates the behavior change from the billing change.

> **Patch note (S-HAR-02b-patch3, 2026-07-31, John-approved):** the table above is the CORRECTED layout. ## 8. NODE.JS TEST (full code — save as `test-har-02b.mjs`, delete before committing)
```js
// test-har-02b.mjs — S-HAR-02b (v7.0.16). Categories A, B.
import assert from 'node:assert';
import { buildSections } from './api/prompt/db-assembly.js';

const mkSp = (type, slug, extra = {}) => ({ skill_type_slug: type, slug, name: slug, traits: {}, ...extra });
const profiles = [
  mkSp('format', 'fmt-1', { traits: { output_type: 'json', schema: { type: 'object' } } }),
  mkSp('intent', 'int-1', { objective: 'obj', method: 'meth' }),
  mkSp('identity', 'id-1', { objective: 'who' }),
  mkSp('behavior', 'beh-1'),
  mkSp('knowledge', 'kn-1'),
  mkSp('guardrails', 'gr-1', { guardrails: ['never lie'] }),
];
const { sections } = buildSections(profiles, 'agent-x', [], { name: 'A', role: 'R', specialty: 'S' }, 'int-1', null);

// 1) every section carries prompt_phase
for (const s of sections) assert.ok(s.prompt_phase === 'stable' || s.prompt_phase === 'volatile', `missing prompt_phase on ${s.slug}`);
// 2) all stable orders < all volatile orders
const maxStable = Math.max(...sections.filter(s => s.prompt_phase === 'stable').map(s => s.order));
const minVolatile = Math.min(...sections.filter(s => s.prompt_phase === 'volatile').map(s => s.order));
assert.ok(maxStable < minVolatile, `stable/volatile interleaved: ${maxStable} >= ${minVolatile}`);
// 3) phase membership
const phase = Object.fromEntries(sections.map(s => [s.slug, s.prompt_phase]));
for (const slug of ['format', 'intent', 'identity', 'behavior', 'guardrails']) assert.equal(phase[slug], 'stable', slug);
assert.equal(phase['knowledge-kn-1'], 'volatile');
// 4) sort order: stable run exactly format,identity,behavior,guardrails,intent (patch3 layout)
const stableSlugs = sections.filter(s => s.prompt_phase === 'stable').map(s => s.slug);
assert.deepEqual(stableSlugs, ['format', 'identity', 'behavior', 'guardrails', 'intent']);

// 5) reflect + task sections are volatile and after the stable run (needs a reflect-declaring profile)
const profiles2 = [...profiles, mkSp('behavior', 'beh-2', { technical_services: ['reflect'] })];
const r2 = buildSections(profiles2, 'agent-x', [], null, 'int-1', null);
const reflect = r2.sections.find(s => s.slug === 'reflect');
assert.equal(reflect.prompt_phase, 'volatile');
assert.ok(reflect.order > Math.max(...r2.sections.filter(s => s.prompt_phase === 'stable').map(s => s.order)));

console.log('ALL TESTS PASS');
```
