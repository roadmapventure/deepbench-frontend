## CONTEXT

Three independent CHI (Channel Intelligence) live-status/waiting-state UX cleanups John reported off a live dev-preview screenshot (forecast flow: "How do smartphone upgrade cycles vary by country…"). All three land in **single shared components** that render on both desktop (`EvidenceColumn` at L3797, `AgentWorkingIndicator` in `InteractColumn` at L2776) and mobile (`MobileBody`'s `EvidenceColumn` at L2974, `AgentWorkingIndicator` at L2981) — so one fix each covers both surfaces; no separate `MOB` row. No `api/`, schema, or delegation touched — pure Layer-2 UI.

**Governing principle (unchanged from `CHI-58`):** Column 2 (Evidence) shows *content*; live status *narration* belongs in Column 1's `AgentWorkingIndicator` strip. Task 3 honors this by using motion-as-a-skeleton (a shimmering placeholder shaped like the content about to land), **not** motion-as-words — it removes the leftover "Generating candidate theories…" narration text rather than animating it.

**Task 1 — chat ack no longer points at a choice that doesn't exist yet.** The `hyp_entry` ack ([L3396](src/screens/MarketIntelligenceScreen.jsx:3396)) is a hardcoded template string (confirmed: the model never authors it). Its tail — "Pick or refine a hypothesis on the right." — tells the user to pick a hypothesis while Priya is still *generating* them, so there's nothing to pick. Replace with an intent-branched tail that describes what's actually happening.

**Task 2 — every live status shows an expected time, via a centralized fallback.** The live `AgentWorkingIndicator` only renders an estimate when `workingStatus.expectation` is set ([L644](src/screens/MarketIntelligenceScreen.jsx:644)). Only the qa flow passes one (`"expected < 2m"`, hardcoded at that one call site, L3326/L3338); the hypothesis-generation and hypothesis-test statuses pass `formatExpectation(est)` **or `null`** (null whenever `estimateChainMs` has no historical p90 data for that chain — exactly the screenshot: "Priya is generating hypotheses…" with no estimate), and 5 other statuses (`Owen is reviewing…`, `Marcus is preparing…`, `Elena is consolidating…`, `Nadia is drafting…`, `Nadia is processing…`, plus delegation micro-hops) pass nothing at all. `elapsed` is universal only because it's computed inside the component; the fallback was never centralized the same way. Fix: move the ceiling fallback into the component so *every* status — the 7 that pass null today and any added later — inherits it; grounded `expect > Xs` still wins when present. Retire the qa call site's live literal so there's one source of the ceiling string.

**Task 3 — Column-2 waiting drawers show motion, not a frozen box.** Two waiting states have no motion today: the Candidates drawer's `stage === "generating"` renders static italic "Generating candidate theories…" ([L2034](src/screens/MarketIntelligenceScreen.jsx:2034)), and the Result drawer's `stage === "testing"` renders an **open, entirely empty** box (its only body block is gated on `st && hypFlow.stage === "result"`, both false during testing). The News drawer already animates (3× `NewsCardSkeleton` + `ShimmerSweep`). Give the other two the same motion language: shimmering skeleton rows shaped like the content about to appear.

// test-chi-73.mjs — pure Node, no app imports.

let pass = 0, fail = 0;
function assert(cond, label) {
  if (cond) { pass++; console.log(`PASS: ${label}`); }
  else { fail++; console.log(`FAIL: ${label}`); }
}

// --- Mirror of Task 1: the hyp_entry ack tail map + message assembly ---
const INTENT_LABEL = { theory: "Theory", forecast: "Forecast", correct: "Correct" };
const HYP_ENTRY_TAIL = { forecast: "Building theories now...", theory: "Building theories now...", correct: "Reviewing that correction now..." };
function ackText(intent) {
  return `Got it — treating that as a ${INTENT_LABEL[intent] || intent}. ${HYP_ENTRY_TAIL[intent] || "Building theories now..."}`;
}
{
  assert(ackText("forecast") === 'Got it — treating that as a Forecast. Building theories now...', "forecast: Forecast label + Building theories tail");
  assert(ackText("theory") === 'Got it — treating that as a Theory. Building theories now...', "theory: Theory label + Building theories tail");
  assert(ackText("correct") === 'Got it — treating that as a Correct. Reviewing that correction now...', "correct: correction-worded tail, not theories");
  assert(!ackText("forecast").includes("Pick or refine"), "old 'Pick or refine' phrasing gone");
  assert(ackText("mystery").includes("Building theories now..."), "unknown intent: falls back to theory phrasing, no undefined");
}

// --- Mirror of Task 2: the centralized live expected-time fallback ---
const LIVE_EXPECT_FALLBACK = "expect < 2m";
function liveExpectation(expectation) {
  return expectation || LIVE_EXPECT_FALLBACK;
}
{
  assert(liveExpectation("expect > 45s") === "expect > 45s", "grounded estimate still wins when present");
  assert(liveExpectation(null) === "expect < 2m", "null (Priya hyp-gen, no p90): shows centralized ceiling");

  assert(liveExpectation("") === "expect < 2m", "empty string: shows ceiling, never a blank estimate");
  assert(LIVE_EXPECT_FALLBACK === "expect < 2m", "fallback is present-tense (live), not past-tense 'expected'");
}

// --- Mirror of Task 3: which Column-2 waiting states now render motion (stage gating) ---
function candidatesShowsSkeleton(stage) { return stage === "generating"; }
function resultShowsSkeleton(stage) { return stage === "testing"; }
