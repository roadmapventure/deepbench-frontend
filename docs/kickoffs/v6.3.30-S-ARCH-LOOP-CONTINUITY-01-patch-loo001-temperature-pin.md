## 1. CONTEXT

**Patch to `S-ARCH-LOOP-CONTINUITY-01` (v6.3.28), same-day QA failure, root-caused before this doc was written.** That session shipped three fixes (`LOO-001`/`LOO-002`/`LOO-004`) to `agent-selection-intent`. Its own live verification (6 runs of the self-only-match scenario: Marcus, `requesting_agent_id: "marcus"`, skill need matching only his own `channel-intelligence` capability) found **only 1 of 6 correctly returned `no_match: true` — the other 5 recommended Marcus back to himself**, even though the model's own `reasoning` field explicitly acknowledged the self-referral conflict in the same response before overriding it. `LOO-002` (no-match schema) and `LOO-004` (`is_active` gate) both passed their own live verification cleanly and are not touched by this patch.

**Root cause, verified live this design session (not assumed from the coding report):** queried `skill_profiles` directly — `agent-selection-intent.temperature` is `null`, while `ci-answer-intent`/`qg-review-intent` are both pinned to `temperature: "0"` under `AA-154`, an existing fix for this exact failure class (reasoning-text-vs-output-field inconsistency under Anthropic's default temperature). `agent-selection-intent` was never brought under that precedent. This is a plausible, evidence-backed root cause — not a guess — but it is a real behavioral change outside `v6.3.28`'s original scope (touches determinism of every `agent-selection-intent` call platform-wide, not just the self-referral path), so it was deliberately not applied unilaterally by the prior coding session and is confirmed with John before this patch, per the Design Session Walkthrough Required rule.

**Explicitly not in scope:** no code-level filtering added anywhere (the `LOO-001` design principle — reasoning, not filtering — stands unchanged). If temperature pinning alone does not close the gap after this patch's expanded live re-test, that is a new finding requiring its own follow-up design decision, not something this patch session should improvise around.
