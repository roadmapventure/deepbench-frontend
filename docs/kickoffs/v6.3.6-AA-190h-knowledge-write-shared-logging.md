## 1. CONTEXT

Eighth site, and shaped differently from the other 7: `lib/knowledge-write.js`'s `embedAndUpsertEntry()` (called by `api/load-entries.js`'s POST handler, hit by both `PersonnelScreen.jsx`'s "Training tab — Add Courses" save and `TeachScreen.jsx`'s "Teach Agent" save) has **no `ai_activity_log` write at all today** — not a hand-rolled `fetch()` to migrate, a write that's simply missing. Two separate real bugs, both closed by the same fix:

**Bug 1 — duplicated OpenAI embedding implementation.** This file makes its own independent `fetch('https://api.openai.com/v1/embeddings', ...)` call (lines 39-43) instead of reusing `lib/vector-search.js`'s already-exported `embedContent()` — the same shared primitive `lib/librarian.js` already uses. Confirmed: `AA-190` site 1 (`lib/librarian.js`) already fixed `vector-search.js`'s `embedText()` to capture and return real OpenAI `usage` — this file's separate reimplementation never got that fix, and has no way to.

**Bug 2 — one of the two real callers has zero logging of any kind.** `PersonnelScreen.jsx` (line 676) calls a client-side `logAICall({type:"reinforcement", model:"text-embedding-3-small", ...})` immediately after its save request succeeds — but with no `tokens` param (defaults to `0`, one of `AA-190`'s originally-flagged lower-priority client-side gaps). `TeachScreen.jsx`'s save flow (confirmed reading it, lines 158-179) hits the exact same `/api/load-entries` POST → `embedAndUpsertEntry()` path but has **no logging call of any kind** — every real embedding from this specific save path is completely invisible, not even a zero-cost row.

**Fix, both bugs at once:** move the real OpenAI embedding call in this file onto `embedContent()` (gets the real `usage` for free, eliminates the duplicate implementation), and add a real server-side `logActivity()` call inside `embedAndUpsertEntry()` itself — the shared primitive both screens call through. This automatically covers `TeachScreen.jsx`'s previously-100%-invisible path with zero changes to that file, and is a strictly better fix than patching `PersonnelScreen.jsx`'s client-side gap alone (site-specific client patches don't reach `TeachScreen.jsx`; a shared-primitive fix reaches every current and future caller). `PersonnelScreen.jsx`'s now-redundant client-side `logAICall()` call must be removed in the same session — leaving it in place would double-log every `PersonnelScreen` save (one real row from the new server-side `logActivity()`, one stale zero-token row from the client) once the server-side fix lands.

**Found this session, deliberately NOT fixed — a second addendum to `AI-53`'s naming-collision pattern:** `SERVICE_CATALOG`'s `knowledge-reinforcement` entry lists `patterns: ['Embeddings','Structured Output']` — but `embedAndUpsertEntry()` performs pure embedding + a raw Supabase upsert, no LLM generation call of any kind, so `'Structured Output'` is a stale/incorrect tag here too. Not fixed in this session for the same reason as `AI-53`: it's a `SERVICE_CATALOG` naming decision in a different file (`src/hooks/useAIActivity.js`), out of this session's file-count budget, and not urgent enough to justify expanding scope under time pressure. Logged as a follow-up to `AI-53` in this design session's close-out.
