## 2. CONTEXT

John reviewed the live MI screen and flagged the "agent is working" status dot in the app header (shared globally with Work Dashboard / AI Review tab) as being in the wrong place — he expects it in the chat column instead, plus a live `m:ss` timer like Claude Code's own "thinking" indicator, so the elapsed time is visible while an agent is working, not just after the fact in the Pipeline Log's static `X.Xs`.

Design session found the real scope was bigger than "move a dot":

- **Only one agent runs at a time, confirmed by code** (no `Promise.all`/concurrent dispatch anywhere in this file or the `execute.js` harness loop — it's a single turn-based loop by construction, §19d). So this is one status line that swaps message + resets its timer each time control passes to a new agent — never multiple concurrent lines. Real concurrent-agent display is a future architecture item, not this session (`docs/FEATURES.md` notes this under `MI-23`'s row).
- Of the 6 real "agent working" turns on this screen, only 3 show *any* status today (Marcus Q&A — text only, no timer; Priya hypothesis test and Elena+Nadia commit — header dot only). The other moments (Priya generating hypotheses; Nadia resolving a confirmation) show nothing at all today, anywhere, including the Pipeline Log — confirmed these are real, unlogged `runCapability()` calls, not missing routing (every capability call is unconditionally audited server-side via `execute.js`'s `logAgentTurn()`, regardless of what this screen's own local Pipeline Log widget does — so this gap is a page-local display completeness issue, not an AI Audit visibility issue).
- John's direction: track and show **every** agent-working turn the same way, "agent> is thinking m:ss," timer resetting per turn.
- The Theory Evidence (middle) panel has its own static duplicate text for 3 of these same stages ("Priya is generating hypotheses…", "Priya is running a hypothesis test…", "Elena and Nadia are reviewing this commit…"). John confirmed removing the hypothesis-test one now that chat covers it; this kickoff extends the same reasoning to the other two duplicate lines (same panel, same "don't show the same status twice on screen" logic) — flagged explicitly to John before this kickoff was issued, not assumed silently.

```jsx
function formatElapsed(ms) {
  const totalSec = Math.max(0, Math.floor(ms / 1000));
  const m = Math.floor(totalSec / 60);
  const s = totalSec % 60;
  return `${m}:${String(s).padStart(2, "0")}`;
}

// FEATURE: MI-23 — replaces the header's global AI status dot for this screen; one line, swaps
// message + resets its timer each time control passes to a new agent (only one agent ever runs
// at a time on this platform today, confirmed no concurrent dispatch anywhere in this file or the
// execute.js harness loop — see kickoff CONTEXT). Keyed by startedAt at the call site (not here)
// so React fully remounts this component on every new turn instead of trying to reset internal
// tick state — the simplest correct way to guarantee the timer starts at 0:00 every time.
function AgentWorkingIndicator({ message, startedAt }) {
  const [now, setNow] = useState(() => Date.now());
  useEffect(() => {
    const id = setInterval(() => setNow(Date.now()), 1000);
    return () => clearInterval(id);
  }, []);
  return (
    <div style={{display:"flex",alignItems:"center",gap:8,marginBottom:12}}>
      <AIDiamond size="7px" color={T.brass}/>
      <span style={{fontFamily:mono,fontSize:11,color:T.muted,fontStyle:"italic"}}>{message}</span>
      <span style={{fontFamily:mono,fontSize:10,color:T.brassDeep}}>{formatElapsed(now - startedAt)}</span>
    </div>
  );
}
```

```js
let pass = 0, fail = 0;
function check(name, cond) {
  if (cond) { pass++; console.log(`PASS: ${name}`); }
  else { fail++; console.log(`FAIL: ${name}`); }
}

// ── formatElapsed(ms) — Category B ──────────────────────────────────────────
function formatElapsed(ms) {
  const totalSec = Math.max(0, Math.floor(ms / 1000));
  const m = Math.floor(totalSec / 60);
  const s = totalSec % 60;
  return `${m}:${String(s).padStart(2, "0")}`;
}

check("0ms -> 0:00", formatElapsed(0) === "0:00");
check("7000ms -> 0:07", formatElapsed(7000) === "0:07");
check("64000ms -> 1:04", formatElapsed(64000) === "1:04");
check("599000ms -> 9:59", formatElapsed(599000) === "9:59");
check("600000ms -> 10:00", formatElapsed(600000) === "10:00");

// ── Remount-per-turn semantics — Category D ─────────────────────────────────
// Simulates AgentWorkingIndicator's key={startedAt} behavior: a new turn must produce a
// startedAt strictly greater than the previous one, so React's key changes and the interval
// timer restarts at 0:00 rather than continuing to count from the old turn.
function simulateTurns(turnStartTimes) {
  const keys = turnStartTimes.map(t => t); // key === startedAt, per the spec
  const allUnique = new Set(keys).size === keys.length;
  const strictlyIncreasing = keys.every((k, i) => i === 0 || k > keys[i - 1]);
  return { allUnique, strictlyIncreasing };
}

const sixTurnTimeline = [1000, 1500, 3000, 5000, 5001, 8000]; // simulated t0s across a full flow
const sim = simulateTurns(sixTurnTimeline);
check("every turn's startedAt is unique (forces remount)", sim.allUnique);
check("turn timestamps strictly increase across a flow", sim.strictlyIncreasing);

// Same t0 must never be reused across two different messages (would fail to remount/reset)
check("commit step 1 and step 2 use different t0s (onCommit's two sequential calls)",
```
