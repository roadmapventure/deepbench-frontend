## The build — additive, never surgical

The design constraint is the one part (a) named: **do not extract facts out of the judgment
paragraph.** So this ship does not touch that paragraph at all. It adds a **renderer-owned block**
above it, and makes everything outside the block un-writable by the renderer.

1. **`scripts/render-standing-brief.js`** (new) — renders the live board census, `status` and
   `design_status` censuses, John's scheduler/automation settings and the standing drain's state into
   a marked block. Exit 0 rendered / no drift, exit 1 `--check` drift, exit 2 could not run.
2. **`docs/runbooks/standing-brief.md`** — gains the two markers and the first rendered block. **The
   hand-maintained paragraph is not edited.**
3. **`tests/regression/SES-177b-standing-brief-block.js`** (new) — guards it, importing the real
   predicates rather than copying them.

### The three properties that make this safe

- **ONLY THE REGION BETWEEN THE MARKERS MAY CHANGE, and it is asserted rather than intended.** The
  renderer splices, then compares the head (before `BEGIN`) and tail (after `END`) byte-for-byte
  against what it read. A single byte's difference outside the markers and it exits 2 writing
  nothing. This is what makes an additive block structurally incapable of becoming the v7.0.197
  briefing wipe: the destroy-what-you-cannot-see risk is not mitigated by care, it is unreachable.
- **Fail closed on a missing hand paragraph.** If the `**Next session:**` sentinel is gone — the
  judgment prose part (a) moved verbatim — the renderer refuses (exit 2) before any network call,
  exactly as `render-claude-state.js` refuses without the standing brief. The block must never be
  the only thing left in a file whose reason for existing is the prose beside it.
- **John's `as of` stamp on every generated group — and `--check` compares facts, not the clock.**
  His Accept on gated card `8c0f2bf9` (23:08:29Z, eight minutes before this cycle opened) is the
  operative build spec: *"board census from `backlog_items`, drain state from
  `runner_directives`/`runner_drain_scope`, scheduler line from `runner_settings`, all generated at
  build time; judgment prose … stays byte-for-byte untouched; **every generated line carries an
  'as of \<timestamp\>'**."* **This ship's first build omitted the stamp**, borrowing
  `export-backlog-snapshot.js`'s determinism convention so `--check` stayed meaningful. That
  reasoning was sound and it was not the decision — his word outranks a cycle's preference, so the
  stamp ships. What keeps `--check` meaningful anyway: it compares the embedded payload `sha256`,
  never the stamp, so a refreshed stamp over identical facts is reported as exactly that and is not
  drift. `renderBlock()` takes the clock as an **argument**, so it stays assertable.

## QA — discriminating, stated as the runbook requires

Would each test still pass if the change did nothing? No:

- **Outside-the-markers guard, end-to-end:** a fixture whose tail is altered by one byte between read
  and write makes the real script exit 2 and leave the file byte-identical. The negative control is
  the same fixture untouched, which renders.
- **Fail-closed guard, end-to-end:** the `**Next session:**` sentinel removed → exit 2, file
  byte-identical, restored in a `finally`. Runs without credentials, because that branch sits above
  the env check.
- **Drift detection is proven against the REAL stale text:** `renderBlock()` over this cycle's live
  census does not equal the paragraph's stored numbers — the assertion is that the shipped block
  disagrees with the hand-maintained sentence on `interval_hours`, which is the live defect.
- **John's stamp, asserted rather than intended:** each of the five generated groups carries an
  `as of`, and two different clocks over identical facts render different text (a frozen stamp is the
  stale-number defect again). An unparseable clock throws rather than rendering `Invalid Date`.
- **Drift is a facts question:** identical facts under two clocks carry the **same** `sha`, so a
  stamp refresh is not drift; one added board row changes it, so `--check` still fires when it should.
- **Found while building it, and fixed rather than shipped past:** the fail-closed predicate's first
  form was `text.includes("**Next session:**")` — and the script's own header comment *quotes* that
  sentinel while explaining the rule, so the check was satisfied by its own documentation and would
  have passed on a brief whose judgment paragraph had been deleted outright. It is now line-anchored,
  with a control asserting a mention-in-a-comment does **not** satisfy it. This is the `SES-180`
  self-flagging class in a second costume.
