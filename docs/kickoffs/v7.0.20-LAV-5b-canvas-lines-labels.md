### Task 2 — Model tag shows the family name
Add (exported, beside the other pure derivations):
```js
// "claude-haiku-4-5-20251001" -> "Haiku". Parsed from the real id, never a lookup table of
// models; an id that doesn't match the claude-<family> shape renders verbatim (honest fallback,
// never invented). Title attr keeps the full id either way.
export function modelFamily(modelId) {
  if (typeof modelId !== "string") return null;
  const m = modelId.match(/^claude-([a-z]+)/);
  if (!m) return modelId;
  return m[1].charAt(0).toUpperCase() + m[1].slice(1);
}
```
`.lav-model` renders `modelFamily(modelTag)` with `title={modelTag}` (full id on hover) — the overflow/ellipsis styles stay as a safety net.

### Task 3 — A finished agent keeps its last pattern pill (root-cause required)
Requirement (John, item 9): once a run completes, every agent that worked keeps **the last pattern it used** visible in its card slot, until the next run's `question_boundary` resets the canvas.

Reading the current code, `spanByAgent` (from `runHops`) and the `spanPatterns` fetch both persist after terminal — yet John observes empty slots on finished agents. **Diagnose the actual clearing mechanism live before changing anything** (`CLAUDE.md` root-cause rule). Candidate causes to check, in order: (a) the span's rows land *after* the last `fetchTracePatterns` attempt, and `needsSpanRefetch`'s bounded budget already expired — so late-classified spans never re-fetch once the run ends; (b) the run's last credited span for an agent is one whose rows match no gold pattern, while an *earlier* span of the same agent did match — "last credited span" ≠ "last classified span"; (c) benched scaling makes an existing pill illegible rather than absent.
Fix accordingly, within these bounds: keep the pill on the **latest classified** span per agent (fall back from the latest credited span to that agent's most recent span that has classifications); after the run goes terminal, allow ONE final `fetchTracePatterns` re-fetch (triggered by `running` flipping false — bounded, not a poller); never render a pill for a span with no classification (no fallback label, §19l). The pill must be legible in the benched state (if (c) is the cause, un-hide/scale the slot for benched nodes — smallest change that makes it readable).

### Task 4 — Lit routing lines + on-line labels (John-approved behavior)
Single source for the label vocabulary, beside the existing color constants:
```js
// Legend words, keyed by the pulse/edge meaning colors already defined above. The lit-line label
// and the legend render from this one map — they can never disagree.
export const EDGE_MEANING_LABEL = new Map([
  [DISPATCH_COLOR,   "Delegate"],
  [REPORT_COLOR,     "Report back"],
  [REDISPATCH_COLOR, "Re-dispatch"],
  [HANDOFF_COLOR,    "Hand-off"],
]);
```
Behavior:
- New state: `litEdge` = `{ key, color }` of the most recent pulse's pair (set where pulses are created in the `runHops` effect — the LAST pulse of each new batch wins). It persists until the **next** pulse fires (any pair), a `question_boundary` resets the run, or the ledger clears. Exactly one lit line exists at a time.
- Render: the edge whose `key` matches `litEdge` draws with `stroke={litEdge.color}`, solid (no dash), `strokeWidth 2.2`, full opacity — the resting dashed gray look returns when it un-lights. Terminal hand-off edges (brass, existing `sessionEdges` behavior) keep their brass color and ALSO carry their label while brass.
- Label: an SVG `<text>` at the edge path's midpoint, rotated to the path's direction so it runs parallel along the top of the line: `fontFamily:body`, `fontSize:9.5`, `fill:T.muted` — the legend's own font size and color (John's explicit spec). Compute angle via `Math.atan2(dy,dx)`; if the angle would render upside-down (|angle| > 90°), add 180° so the text always reads left-to-right. Offset a few px above the path (`dy:-5`). Text = `EDGE_MEANING_LABEL.get(color)`; a color not in the map renders NO label (never invented copy). Labels render for the lit edge and for brass hand-off edges.
- The legend at bottom-left is unchanged (it stays as the reference key); the moving `Pulse` animation itself is unchanged.
- Assembly hops produce no pulses today and therefore can never light an edge — add nothing that changes that.
