## CONTEXT

Found live 2026-07-20 during the design session's own Manual QA of `S-LOO-010`, re-checking the Jordan → Alex news-fetch flow. The drawer now shows "1 hop" — only Alex — with zero trace of Jordan — Web Search Expert's own turn, even though he does real work (an actual web search, `HAR-05`'s `enableWebSearch`) before deciding to hand off to Alex for formatting.

**Root cause, precise:** in `dispatchDelegation()`'s plain `delegate_to_agent` branch (as opposed to the `request_help`→broker branch `S-LOO-009d` already fixed), a `delegation` event announces the hand-off, creating a pending placeholder attributed to the *originating* agent (`agentId: agent_id`). When the hand-off resolves final, `S-LOO-009`'s `delegation_complete` event claims that exact placeholder and overwrites it with the *target* agent's identity — correct for crediting the target, but it means the originating agent's own row never survives; it becomes the target's row, not two separate rows.

**Why this wasn't caught earlier:** it was masked by a different, now-fixed bug. Before `S-LOO-009`, Jordan's placeholder never resolved at all — it stayed permanently stuck on "routing to Alex…" forever, occupying its own slot by accident, which looked like Jordan had his own hop even though it was really the exact class of bug this session has been fixing all along. Making placeholders resolve correctly (necessary and correct) is what exposed that nothing was built to *also* preserve the originator's own credit once resolution actually happens.

**Why `S-LOO-009d`'s fix doesn't already cover this:** Michelle's broker leg (`request_help`→`delegationRequired` auto-resolve) is a genuinely different shape — her own turn and the final target's turn are two separate nested capability calls, so crediting both was a matter of firing two separate events already present at two separate points in that branch. Jordan's shape has no broker step: one agent, one turn, one direct final hand-off. And `S-LOO-010`'s own automatic Shape-1 crediting (`display_agent_id == null`) correctly does *not* fire here either — a delegation genuinely did resolve this call, so by design that check stays silent, exactly as it should for the *returning* case (e.g. Owen's own retry-via-Marcus, already fully credited via `S-LOO-010`'s mechanism once his own call resolves directly).

**Confirmed generic, not agent-specific, and confirmed not a duplicate risk:** the fix fires unconditionally inside the `if (delegationRequired || tool_input.is_final === true)` block — i.e. only on the *final* path. The *returning* path (Owen/Marcus's shape) never reaches this branch's final block at all, so there's no double-credit risk with `S-LOO-010`'s own Shape-1 detection. Per the platform's own absolute rule (confirmed live with John, `S-LOO-009`/`S-LOO-009b`'s design session) — every real agent call is its own hop, no exclusion, ever — this fires for *every* agent that ever takes this exact dispatch path, not conditionally on whether their own turn "did enough" to deserve it.
