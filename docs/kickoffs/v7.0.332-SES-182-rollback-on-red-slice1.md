## The two decisions this build owed, and a collision the design did not settle

**1. The `reverted` outcome — the constraint is NOT widened.** `runner_cycles_outcome_check` admits
exactly `shipped` / `gated_before_build` / `reverted` / `did_not_run` / `failed` (read from
`pg_get_constraintdef`). The design named this a build-cycle decision. A sweep rollback records
`outcome='reverted'` **qualified in `notes`**. A sixth value would give one fact a second home for a
distinction nothing yet queries, and the design's own §4 asks for *"reusing the runbook's existing
`outcome='reverted'` path rather than paralleling it"*.

**2. Migration-in-range is detected by the WATERMARK, not by reading the diff.** This is the
decision the whole slice turns on. Migrations in this platform *exist only in the database — the
repo has no `.sql` files*, so a file-based test reports **every** range code-only, which is the one
direction that must never be wrong: it would auto-revert a schema change believing it was text. A
commit-message scan is no better — it trusts prose a cycle wrote about itself. So the green pointer
stores `migration_watermark` and the test is whether it **moved**; unknown on either side is treated
exactly as moved. This needs no down-capture ledger, which is why slice 1 can ship without slice 2.

**3. THE COLLISION: which `kind` an incident card wears.** `runner_items_kind_check` admits exactly
`ship` and `gated_before_build`, and `build-briefing.mjs:449-450` renders §5 from `ship`/`test` and
§6 from `gated_before_build` **and nothing else**. So a new `incident` kind would file a card that
renders on **no surface John reads** — the one outcome an incident card must never have — and
fixing that means editing the briefing builder, a fourth file and a riskier one.

The card is therefore filed as `gated_before_build`, and that is a decision rather than a fudge: §6
already asks the two questions this card asks — Accept means *the rollback was right*, Reverse means
*put it back* — and it renders today with no renderer change. **The consequence is named rather than
hidden:** a gated card touches neither rung nor streak (B34, enforced in `apply_ladder_decision`),
so the rollback does **not** move the ladder, which the design's §5 wanted. The ladder-correct path
survives anyway — the *original ship card* for the reverted work is still on John's page and
Reversing **that** is what moves the ladder. Whether an incident deserves its own kind and its own
renderer row is a real question and it is **on this cycle's ship card for John**, not decided here.

Also noted, not fixed: `build-briefing.mjs:449` filters on `kind === 'test'`, a value the CHECK
constraint has never admitted. Pre-existing dead branch, someone else's ticket.
