# THE DISTINCTION THE NEXT EDITOR WILL BE TEMPTED TO COLLAPSE

**A frame with a real `fromAgentId` whose account is missing is still a REAL defect and must still
fail gate 6.** Sites 929/963/1015/1372 *harvest* their account (`?.content?.account ?? null`) — when
that harvest comes up null, a delegate genuinely completed work and told nobody what it did, which is
exactly the failure gate 6 exists to catch. The exemption is only for the two sites where the
platform itself declares the account structurally absent, and their signature is the hardcoded
identity triple, not the null account.

**A predicate that merely tests `account == null` is vacuous** — gate 6 only ever examines frames
whose account is absent, so that predicate exempts every failure the gate polices and the gate can
never fire on a completion again. The predicate MUST test the identity triple and MUST NOT be
loosened to any single field: a frame missing only `fromAgentId` (or only `from_span_id`) does not
match the emit sites and is a §19p identity defect wearing a costume, not an early credit. Equally
forbidden: a slug allowlist (the per-intent enforcement home §19s removed) or a hardcoded count of
expected early-credit frames (their number varies per run by construction).

# TASKS — one file: `tests/regression/lav-28-receipt-gates.js`

**Task 1 — the predicate, exported and documented: `isEarlyCreditFrame(frame)`.**

```js
// LAV-30 (§19s): the LOO-011/LOO-014 early-credit frames — execute.js's two originator-credit
// emits — fire BEFORE their nested dispatch resolves, so the platform hardcodes account: null as
// DELIBERATE (the emit sites' own comments). Their STRUCTURAL signature, matched verbatim and in
// full: a delegation_complete whose entire from-identity is null. Never a slug allowlist, never a
// count, and NEVER `account == null` alone — that would exempt every failure gate 6 exists to
// catch. A completion with a real fromAgentId and no account is a delegate that finished work and
// told nobody: still a defect, still an offender.
export function isEarlyCreditFrame(f) {
  return !!f && f.type === "delegation_complete"
    && f.fromAgentId == null && f.fromCapabilitySlug == null && f.from_span_id == null;
}
```

`to_span_id` deliberately stays out of the predicate: the emit sites always carry it (§19p — the
frame credits that span), but its absence is a different defect gate 6 does not police, and requiring
it here would silently convert an identity bug into a presence failure with a misleading name.

**Task 2 — `gatePresence()` honors the predicate, and ONLY there.** In the accounts loop, an absent
account on a frame matching `isEarlyCreditFrame` is skipped: no offender pushed, and — the half an
editor will be tempted to drop as redundant — **its intent never joins `missingIntents`**, so it
cannot consume the `SCHEMA_LESS_INTENT_COUNT` coverage budget. Both halves are load-bearing: skipping
only the offender push would leave the requester's own intent inflating `missingIntents.size`, so a
run with early credits would trip the "coverage regressed" line at 7 genuine schema-less intents —
a false regression alarm — while a real 8th missing intent must still trip it. `receiptsOf()`,
`hopSpanOf()`, `declaredWorkBySpan()` and gates 1–5 are **byte-identical** — gates 1–5 already skip
text-less accounts, so the exemption lives in exactly one place. Update only the file header's
version line and gate 6's comment; extend the MUTATION note (see QA).
