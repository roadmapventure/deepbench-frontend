# v7.0.216 — SES-188: the briefing harvest is truncation-dependent, not blind

**Ticket:** `SES-188` — *The briefing harvest is blind: reading the page returns only its first
bytes, so John's taps cannot be picked up* (`P9 - Bug Fixes`, tier `now`, queue 7).
**Session:** runner cycle `50592275-20ac-431b-b161-517f8dc35add`, Automated, `claude-opus-5`.
**Model discipline:** no subagent delegation — the judgment-dense half of this ticket was a
measurement this cycle had already taken as a side effect of its own step-2 harvest, so
delegating it would have re-run a completed observation, not bought a second opinion.

## The premise, and what revalidation found

`SES-188` was filed at `02:5xZ` on 2026-08-24 by cycle `e42f8d4e` and states that **both**
documented read paths — the `Artifact` tool's `read` action and `WebFetch` — return only the
artifact's head wrapper and **never** the `briefing-state` block, with the consequence that
"John's taps cannot be picked up" and a cycle must decline to republish.

**Half of that is confirmed and half of it is disproven, both by direct measurement this cycle
(03:22–03:23Z), against the live page, not a fixture:**

| Read path | What came back | Reached `briefing-state`? |
|---|---|---|
| `Artifact` action `read` | the artifact-reader wrapper + head, cut off inside the frame-runtime script | **No** |
| `WebFetch` on the same URL | the *same* wrapper, but a **longer** head — through the head, `</style></head><body>`, the complete `briefing-state` block, and on into `<script id="code">` | **Yes** |

So the two paths are **not** two independent readers that both fail. They are the **same**
artifact-reader interception — `WebFetch` on a `claude.ai/code/artifact/…` URL returns the
identical `[Artifact … full HTML saved to /root/.claude/…]` wrapper — differing only in **how
much head each one returns**. The block is not unreachable; it sits immediately after
`<body><div id="page"></div>`, which is early enough that the longer read clears it.

**The consequential claim is false, and this cycle disproved it by doing the thing it says is
impossible.** The harvest returned John's live state including a **night meter reading he typed
at `03:19Z`, three minutes before this cycle opened** (`all_models 60`, `fable 67`, `h5 0`) —
a tap that by the ticket's account could not have been picked up.

## Why this is worth a ship rather than a shrug

The false half is **expensive and live**. Two cycles (`598a9b81` at 01:41Z, `e42f8d4e` at
02:5xZ) correctly declined to republish rather than destroy un-harvested taps — the right call
on their evidence — and the page has therefore gone stale with **18 undecided cards** behind it
and John's last harvested decision at `2026-08-23T22:10Z`. Every further cycle that reaches for
the short read will re-derive the same wrong conclusion and decline again. That is the same
shape of waste `SES-114` measured (three re-derivations of one answer in a day), and the same
shape of error the runbook keeps paying for: **a single tool's silence read as a finding**
(`v7.0.117`, "a subagent that has not returned is not a result").

## What is NOT claimed, and must not be shipped as doctrine

**One successful read is not a reliability guarantee.** This cycle has exactly one successful
observation of `WebFetch` reaching the block, against `e42f8d4e`'s report of it failing. Both
can be true: the cut-off is a **size budget**, the served page is **198.3 KB and grows every
rebuild**, and nothing here establishes where the threshold sits or that it is stable. The
ticket's own "WHAT IS OBSERVED vs. WHAT IS NOT" section is right and stays right.

Therefore this ship deliberately does **not** write *"use WebFetch, it works"* into the
procedure. Doing so would replace one unverified belief with another, and the next page growth
would make it false silently — which is worse than the bug, because a cycle would then rebuild
from a truncated read it believed was complete and **destroy John's taps**, the exact failure
`v7.0.197`'s seed sentinel exists to prevent.

## The change

**A cycle must TEST whether its harvest reached the block, and branch on the test — never
conclude from which tool it used.** Two files, doc-only:

1. `docs/runbooks/briefing-page.md` — the decision read-back contract gains the measured
   truncation finding, the explicit test (`briefing-state` present *and* parseable, with a
   named recent value to confirm it is the live block and not a stale seed), and the two
   branches: verified harvest → proceed to rebuild; unverified → **decline the republish**, the
   behaviour that is already correct and stays mandatory.
2. `docs/runbooks/runner-cycle.md` — step 2's harvest instruction points at that contract in
   one sentence. Cited, not restated, so the two files cannot drift the way step 5 and step 7
   did before `v7.0.114`.

**The durable fix stays open and is named rather than quietly dropped.** The ticket's three
candidates — a size-bounded read that returns a named block, a Supabase-side buffer the page
writes taps into directly (which would retire the page-as-buffer design entirely), and a
sanctioned exception to the `~/.claude/` rule for this one read — are architectural choices,
and the third would need a §19v rule change. None is chosen here. This ship removes the
operational failure (cycles declining to republish on a wrong premise) without pre-empting
that decision, and `SES-188` stays open carrying it.

## Scope

Files (2, under the ≤3 cap): `docs/runbooks/briefing-page.md`,
`docs/runbooks/runner-cycle.md`. Plus standard close-out: `CLAUDE-STATE.md`,
`docs/SESSIONS.md`, `docs/backlog/BACKLOG-SNAPSHOT.md`.

No `src/`, `api/` or `lib/` change; no schema change; no site change. Exposure rule does not
engage — nothing an approved surface renders changes.

## QA — discriminating, stated as a test

- **The measurement itself is the discriminating test**, and it fails if the change did
  nothing: run both read paths against the live URL and compare where each one stops. A build
  that merely asserted "harvest works" would pass a completeness check and fail this one,
  because the `Artifact`-read arm **does** truncate and the doc must say so.
- **Negative control on the seed:** the harvested block must carry a value newer than the last
  stored `runner_usage_readings` row — here John's `03:19Z` night reading against a stored
  latest of `2026-08-23T13:51Z`. A truncated-but-valid-looking empty block cannot produce that,
  which is precisely what distinguishes a real harvest from the `v7.0.197` empty-skeleton
  failure.
- Docs-only change, so `npm run build` and the regression suite are run as regression guards
  (nothing should move), not as proof of the change.
