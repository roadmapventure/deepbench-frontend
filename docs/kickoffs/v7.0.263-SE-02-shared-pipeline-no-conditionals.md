## 3. THE PROPERTY THIS SHIP TURNS ON

**A presence check is not a conditional on identity, and this check is worse than useless if it
cannot tell them apart.** SE-01's lesson, and it is sharper here.

The naive grep — *"an `if` mentioning `agent_id` in a governed file"* — returns **14 hits on today's
clean tree, and every single one is legitimate**:

```
db-assembly.js:525   if (!capability_slug && !agent_id) {      ← "was an id supplied at all?"
db-assembly.js:559   if (agent_id) { … }                       ← branch on PRESENCE, not identity
execute.js:1704      if (!capability_slug) throw new Error(…)  ← an argument guard
execute.js:497       if (!res.ok) throw new Error(`…"${capability_slug}"`)   ← id only in a message
```

The pipeline **must** branch on whether an id was supplied — that is not intelligence about a
particular agent, it is argument handling. What the Founding Principle forbids is branching on
**which** agent or capability it is. So the matcher keys on **comparison against a literal**
(`=== 'alex'`, `!== "pdf"`, `switch (agentId)`, membership in a literal id array), never on the
identifier appearing near an `if`.

**Measured, whole-platform:** across `api/`, `lib/` and `shared/` there is exactly **one** literal-id
conditional — `api/brief.js:90`, `if (agent_id === "pat")`.

## 4. THE SCOPE CALL, MADE EXPLICITLY

`api/brief.js` is **not** in scope and the check must not fail on it. §19 names three files, §19b
names one, §19d names two primitives; `brief.js` is a capability route and none of them. Its
conditional is a deliberate, commented control-case bypass (*"Pat … cold every time, no configs, no
RAG, no reflect"*).

Widening a LOCKED rule to cover a file it does not name would be the runner granting itself scope —
the same boundary `SES-196` kept when it left `removal proposed` out of the picker. **But silently
dropping the finding would be worse**, so it is REPORTED on every run as an adjacent observation,
explicitly labelled as outside the rule's named scope, in the shape `check-library-access.js` prints
its declared exceptions. Visible, and not pretending to authority it does not have.
