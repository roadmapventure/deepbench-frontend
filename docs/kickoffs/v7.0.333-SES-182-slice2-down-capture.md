## What this slice builds

### 1. Capture is a FUNCTION, not a step each cycle must remember

`public.capture_migration_down(p_cycle_id, p_up_name, p_objects)` is called **immediately before**
`apply_migration`, and it derives the down from the database's own current state rather than from
prose a cycle wrote about its own migration. This file records eight times over that *a rule each
cycle must remember is a rule that gets silently forgotten* (`record_skip`'s precedent), and the
same argument applies with extra force here: a hand-authored down is exactly the *"authored from
memory"* the design forbids (`v7.0.324` §2(a)).

`p_objects` is the list of objects the up touches — `{"kind": …, "identity": …}` — and it is the
**one** thing the caller supplies, because it is the one thing the database cannot know before the
up runs. Everything else (prior definitions, prior overload set, existence) is read live.

**Derivation, per object, and the whole rule is in the two branches:**

| Prior state | Down the function derives |
|---|---|
| the object does **not** exist yet | `DROP <kind> IF EXISTS <identity>` — drop by identity |
| a `function` **does** exist | re-apply every captured `pg_get_functiondef`, **then** drop every overload of that name absent from the captured identity set, **then** assert the overload count is exactly the captured one |
| a `view` **does** exist | `CREATE OR REPLACE VIEW … AS <captured pg_get_viewdef>` |
| anything else already exists | **refused** — the row is `classification='refused'` with the reason stored, and no down is offered |

**The overload drop and the count assertion are not decoration** — they are
`.claude/rules/supabase-function-signature.md` executed. A down that recreates the old signature
*beside* the new one is the `DAT-12` outage (90 seconds of 0-chunk retrieval on every live CHI
answer) rebuilt in reverse, and the kickoff names it forbidden edit #4.

**Refusals name the object, and a refused capture is not a failure.** It is `v7.0.324` §2(b) —
*"a migration whose lossless down cannot be stated is refused the unattended lane"* — reaching the
ledger instead of a cycle's judgment. Grants/ACL changes are refused **deliberately** and that is
this slice's declared remainder: re-applying an exploded ACL correctly is
`.claude/rules/supabase-column-grants.md`'s whole subject matter, and a wrong one is a live
exposure. Refused-and-loud is the recoverable direction; guessed-and-applied is not.

### 2. The range is READ BY THE CYCLE and PASSED IN — the engine still fetches nothing

`public.migrations_in_range(p_from, p_to)` gives the exclusive-from / inclusive-to predicate **one
executable home** so no cycle re-derives it, and the cycle hands the result to the engine as
`--migrations`. That is the identical boundary slice 1 keeps for the CI conclusion, and for the
identical reason: `runner_secrets` holds no credential for `supabase_migrations`, PostgREST does not
expose that schema, and a script that invented a path to it would be the only thing in the platform
holding one.

### 3. `schemaPlanFor()` — pure, and it decides by MISSING members, never by counting

The engine's moved-watermark branch now consults the ledger. **Every** migration in the red range
must carry a stored `auto-downable` down; the plan is ordered **newest-first** (an ordering the
guard pins, because applying downs oldest-first re-creates what a later down expected gone).

**One missing or refused member ⇒ the whole range is card-only, and the card NAMES the member.**
Not a partial rollback: a schema half-undone is a state no green anchor describes, and the design's
fail-direction sentence is explicit — *"a red range containing any migration the actuator cannot
match to a stored, classified down → no automatic schema action at all"*.

**An empty or absent `--migrations` list is NOT innocent.** It resolves to *not reversible* with
that reason named, which is what keeps slice 1's behaviour byte-identical for every caller that
does not pass one — including `tests/regression/SES-182-rollback-on-red.js`, whose moved-watermark
clause still expects `card-only` and still finds it.

### 4. The authority boundary is unchanged, and that is the point

The engine emits a `schema_plan`; it **does not apply DDL**, exactly as it does not push. The claim
re-assertion (step 0), the issued-version proof (`SES-153`) and the fetch/rebase ladder (B42) live
in the cycle, and a script that reached past them would be the `SES-019` shape. Slice 1's header
already says this about `git`; this slice extends the same sentence to `apply_migration` rather
than carving an exception into it.

## The edits this ship forbids

1. **Partial schema rollback** — downing the members that have downs and carding the rest. Named
   above; pinned by `aRangeWithOneMissingDownIsNeverPartiallyRolledBack()`.
2. **Applying downs oldest-first.** Pinned by `theDownPlanIsNewestFirst()`.
3. **Giving the engine DDL authority** (an `apply_migration` call, a `pg` client). Pinned by
   `theEngineNeverAppliesDdlAndNeverPushes()`, which extends slice 1's shell-out assertion.
4. **A function down without the overload drop and the count assertion** —
   `.claude/rules/supabase-function-signature.md`; pinned by
   `aFunctionDownDropsStaleOverloadsAndAssertsTheCount()` with the retired bare
   `CREATE OR REPLACE`-only form applied to the same fixture and asserted to lose.
5. **Treating an absent `--migrations` list as an empty range** (i.e. as "no migrations, therefore
   reversible"). Pinned by `anUnsuppliedRangeFailsClosed()`.
