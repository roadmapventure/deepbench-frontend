## The fix, and why the ticket's proposed one-liner is wrong

The ticket proposes speccing `node --env-file=.env.local tests/regression/run-all.js`.
**That breaks every cloud runner cycle**, verified on Node 22.22 rather than assumed:

```
node --env-file=.does-not-exist            -> node: .does-not-exist: not found      (exit != 0)
node --env-file-if-exists=.does-not-exist  -> not found. Continuing without it.     (exit 0)
node --env-file-if-exists=<present file>   -> variables load
```

`.env.local` is git-ignored, so it is absent in **every** fresh clone — which is the environment
that runs this suite most often. Shipped form:

```
node --env-file-if-exists=.env.local tests/regression/run-all.js
```

Rule 5 now also carries three things a later editor would otherwise strip:

- **the measurement** (68/68 vs 67/68, naming `SES-177`), so the rule is evidence, not taste;
- **`SES-180` (b)'s `NOT A FULL RUN:` line is deliberately *not* a failure** — gating on it would
  paint CI permanently red wherever credentials are absent, the outcome `SES-180` shipped around.
  Without this stated, the next reader "finishes the job" and reverses a deliberate decision;
- **credentials are not spend** — `DAT-12`'s `DAT12_LIVE_CHI` (two ~60 s LLM journeys) stays on its
  own opt-in flag. A couple of REST reads should always run; a paid journey should not start because
  someone passed a credentials flag.
