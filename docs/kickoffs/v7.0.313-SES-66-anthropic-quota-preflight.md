## What shipped

**`scripts/check-anthropic-quota.js`** — the pre-flight, with the same deliberate three-way exit
contract `check-deploy-current.js` established: **0** clear, **1** capped, **2** cannot run. Exit 2 is
distinct from exit 1 on purpose — an unrunnable check must never be reported as a pass, and must
never be confused with a real cap either.

Two design decisions carry the whole ticket, and both are stated in the file's own header so the
next reader decides by the rule rather than by shortening the code:

1. **The probe is an inference call, not `GET /v1/models`.** The obvious cheaper move is the wrong
   one: a spend cap gates *inference*, not metadata, so `/v1/models` returns 200 for a fully-capped
   account and the check would report "clear" on exactly the state it exists to catch. A pre-flight
   that cannot fail is worse than none, because a session then trusts it. The probe is therefore the
   smallest real call available — `MODELS.HAIKU` from `shared/models.js`, `max_tokens: 1`, a
   one-character prompt.
2. **The classification keys on the MESSAGE, never on the status alone.** The incident's entire
   symptom was the string `Anthropic call failed: 400`, and 400 is equally the API's status for a
   malformed request or a bad model id. `status === 400 -> capped` therefore passes the incident's
   own fixture *and is still wrong*: it reports every ordinary request bug as an account cap and
   sends a cycle to wait out a limit it is not under. A 400 is a cap only when the body says so.

**The ticket's second ask is satisfied rather than deferred.** SES-66 asks, *"at minimum record the
cap's reset behavior … once observed again"*. `parseResetsAt()` extracts the instant the live message
carries (*"You will regain access on 2026-08-01 at 00:00 UTC"* → `2026-08-01T00:00:00Z`), so the
reset is recorded by the check rather than by a human noticing and writing it down. **What it does
not do, named rather than left to be found:** it does not settle the rolling-vs-fixed-window question
the ticket flags as unconfirmed. An absent reset is `null`, never an invented date.

**`docs/runbooks/runner-cycle.md`** — step 3 gains the bullet next to Deploy quota, including the
one thing a runbook must say and a script cannot: **this is a pre-flight, not a wall.** A cap yields
to work that needs no live call, exactly as the deploy-quota bullet yields; it is never a
`did_not_run`. It is also scoped — a doc-or-SQL cycle needs no key and skips it silently, so this
adds no per-cycle cost to the common case.

## QA — what was run, and what each arm proves

- **`npm install && npm run build`** green.
- **Full regression suite** green (`tests/regression/run-all.js`).
- **LIVE END-TO-END, not a seam proof:** the shipped `probe()` made a real call to
  `api.anthropic.com/v1/messages` with the key read from `runner_secrets` in-process, and returned
  `{"verdict":"clear","exitCode":0}`. This is the half a stub can never prove — that the auth header,
  the `anthropic-version` header, the canonical model id and the body shape are all accepted by the
  real API. The key was held in memory only: never printed, never in argv, never written to a file.
- **CLI fail-closed arm, run live:** `env -u ANTHROPIC_API_KEY node scripts/check-anthropic-quota.js`
  → exit **2**, not 0.
- **The discriminating arm** — would it still pass if the change did nothing? No, and this is proven
  as a **difference** rather than a property both implementations share (the `SES-213` lesson): the
  retired `status === 400 -> capped` form is kept in the guard as `retiredStatusOnlyClassify`, run
  against the **same** ordinary-400 fixture, and asserted to **lose** — it calls it a cap where the
  shipped classifier says `unknown`. Arm 7 additionally asserts the two forms **agree** on the real
  cap fixture, which is what makes the control fair rather than rigged: the difference is the
  ordinary 400, not the cap.
- **FILE-LEVEL NEGATIVE CONTROL, executed rather than described:** the shipped classifier's
  message-keyed branch was mutated in place to `if (status === 400)` and the guard was re-run — it
  **FAILED** (`an ordinary 400 must be 'unknown' … + 'capped' - 'unknown'`, exit 1). The tree was then
  restored and the guard passes again.
- **Opposite-direction pair:** arm 4 pins 429 as a cap with no message needed; arm 5 pins 401 as
  **not** a cap, because reporting a bad key as a cap tells a session to wait for a reset that will
  never come. A "simplification" collapsing the two fails one of them.
- **`SES-158` vacuity meta-check** over all five source clauses: each must fail against its own
  `breaks()` mutation, so no clause passes by asserting nothing.
