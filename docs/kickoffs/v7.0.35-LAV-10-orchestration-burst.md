## 2. CONTEXT

Split out of `LAV-9`'s design session (2026-08-01): when an agent starts orchestrating (dispatches to sub-agents and is waiting on them), today it just gets a different node border/ring (`is-orch`) — same weight as every other card, no announcement. John wants that moment to visibly declare itself: a one-time flash across the canvas the instant orchestration starts, followed by each actual contributor (the orchestrator, then its currently-engaged delegates) getting its own individual flash in sequence — "so the user sees 1 agent's loop requires all N amount of agents talking at once," his own framing carried over from `LAV-9a`'s "all active edges at once" mechanism, applied here to nodes instead of edges. Confirmed in the design session: cards stay exactly where they already sit (no new spatial cluster/offshoot) — only light and motion change, and it's a one-shot event, not a persistent effect.

**Trigger:** a rising edge on `deriveNetwork()`'s existing `orchestrators` set (`AgentNetwork.jsx` line ~268) — an agent that's newly holding an open delegation, not one that's simply still holding one. No new event type, no invented state.

**Color:** reuses `ACTION_TEXT_COLORS_FETCH.CLICK` — the exact token `is-orch`'s existing spin-ring already uses (line ~596-597) — so the burst reads as *more of what orchestration already means*, not a disconnected new signal.

**Sequence, confirmed with John:** canvas-wide flash fires immediately; ~150ms later (while the flash is still fading) the cascade starts — the orchestrator's own card flashes, then each of its currently-engaged delegates in the order they joined, staggered ~100ms apart, each with a single bright one-shot ripple.

Pure Node, no app imports — the rising-edge/contributor-list logic and the total-duration formula, reimplemented inline against the same contract as Task 1. Run: `node test-lav-10.mjs`, delete before committing.

```js
// test-lav-10.mjs -- LAV-10 Category B logic tests (pure, no app imports)
let pass = 0, fail = 0;
function assertEq(actual, expected, msg) {
  const ok = JSON.stringify(actual) === JSON.stringify(expected);
  if (ok) { pass++; } else { fail++; console.error(`FAIL: ${msg} -- got ${JSON.stringify(actual)}, expected ${JSON.stringify(expected)}`); }
}

// Mirrors the detection effect's per-render logic: given the CURRENT orchestrators set, the
// already-known set, and the current engaged list, compute (a) the fresh ids this render and
// (b) that render's contributors list, exactly as the effect body does.
function detectBurst(orchestratorsNow, known, engaged) {
  const fresh = [...orchestratorsNow].filter(id => !known.has(id));
  orchestratorsNow.forEach(id => known.add(id));
  if (!fresh.length) return null;
  const orchestratorId = fresh[fresh.length - 1];
  const kids = engaged.filter(id => id !== orchestratorId);
  return { orchestratorId, contributors: [orchestratorId, ...kids] };
}

// A: first render, one new orchestrator with two engaged kids -- fires, contributors in order
let known = new Set();
let r = detectBurst(new Set(["michelle"]), known, ["michelle", "marcus", "priya"]);
assertEq(r?.contributors, ["michelle", "marcus", "priya"], "A: fires on first orchestrator, orchestrator first then kids");

// B: same orchestrator still open next render -- does NOT re-fire (known now has "michelle")
r = detectBurst(new Set(["michelle"]), known, ["michelle", "marcus", "priya"]);
assertEq(r, null, "B: no re-fire while the same orchestrator continues");

// C: a second, different orchestrator starts later -- fires again, fresh contributors
r = detectBurst(new Set(["michelle", "owen"]), known, ["michelle", "marcus", "priya", "owen", "nadia"]);
assertEq(r?.orchestratorId, "owen", "C: fires for the newly-added orchestrator only");
assertEq(r?.contributors, ["owen", "michelle", "marcus", "priya", "nadia"], "C: contributors = orchestrator then every OTHER engaged id");

// D: question-boundary reset (runHops.length shrank) clears `known` -- same orchestrator can re-fire
known = new Set(); // what the effect does when runHops.length < burstLenRef.current
r = detectBurst(new Set(["michelle"]), known, ["michelle"]);
assertEq(r?.contributors, ["michelle"], "D: fires again after a reset even for a previously-seen id");

// E: total on-screen duration formula matches the effect's own setTimeout math
function totalMs(contributorCount, cascadeGap, stagger, ripple) {
  return cascadeGap + contributorCount * stagger + ripple;
}
assertEq(totalMs(3, 150, 100, 500), 950, "E: 3 contributors -- 150 + 300 + 500");
assertEq(totalMs(1, 150, 100, 500), 750, "E2: single orchestrator, no kids -- 150 + 100 + 500");

console.log(fail === 0 ? "ALL TESTS PASS" : `${fail} FAILED, ${pass} PASSED`);
if (fail > 0) process.exit(1);
```
