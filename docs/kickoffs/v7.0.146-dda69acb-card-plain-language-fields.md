## 2. CONTEXT

`v7.0.145` shipped tonight, 14 minutes before this cycle opened, and John **Accepted** it at
21:32Z. It gave every card a **More info** panel with three required fields — *what you can't do
today* / *what you could do after* / *why that's worth something* — which is, close to verbatim,
the specification inside directive `6b6cdd71`.

**It made those fields required at render, and only at render.** The rebuild passes them as a
per-card JavaScript object literal:

```js
card('item-1f6de346','ship','Ship', …,
  { cant: '…', after: '…', worth: '…' })   // <- hand-written by whichever cycle is rebuilding
```

So the text has nowhere to live between rebuilds. Register **B18** — *"build the briefing cards
FROM the database's undecided `runner_items` set, never from this cycle's memory of what it
filed"* — cannot be honoured for this part of a card, because the database has no place to put
it. The next cycle to rebuild the page must re-invent the wording from scratch, from memory, for
a card it did not write. That is exactly the silent drift B18 exists to prevent, and it is the
mechanism most likely to reproduce the confusion John Reworked twice in three minutes tonight.

**Premise revalidated live this cycle, not assumed** (`SES-87`, register B7): `runner_items`'
columns were read from `information_schema` before any work — `id, created_at, cycle_id,
backlog_id, kind, title, value_case, before_after, qa_evidence, dev_link, flag_slug, cost_usd,
model, decision, decision_reason, decided_at`. No field for any of the three. Gap confirmed open.

This is the same move `SES-86` phase 3 made when John's automation queue stopped being a doc
section and became `backlog_items.automation_rank`: **a rule every cycle has to remember is turned
into a field it cannot forget.** The runbook's own note on that change — *"As a doc section,
layer 2 was something each cycle had to remember to consult, and the forgetting was silent"* — is
the argument here too.

## 6. DESIGN RULES

- **Additive only.** `ADD COLUMN IF NOT EXISTS`, nullable, no default. Not a
  schema-destructive migration, so it is outside §19v's gated lane; `runner_items` is the
  runner's own ledger, not platform or agent data.
- **`NULL` is the defect line, and stays that way.** No sentinel string, no empty-string default.
- **Plain language means John's words, not the system's.** The fields are prose written to a
  person, in his register. "You can't X today" — never "the affordance is absent".

  defend the original wording.
