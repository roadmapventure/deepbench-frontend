A flag the browser could flip is not a flag.

**Task 2 — the reader (1 new file, `src/lib/featureFlags.js`).**
One shared module, three layers, fail-closed at every one:
- `parseFlagOverrides(search)` — `?ff=slug-a,!slug-b` → `{slug-a: true, slug-b: false}`. `!` prefix forces off.
- `resolveFlag(slug, rows, overrides)` — resolution order **override → data row → false**. Unknown slug, absent row, failed fetch, malformed param: **false**.
- `fetchFeatureFlags()` / `useFeatureFlag(slug)` — one in-flight fetch shared by every caller (module-level promise), starting value `false` so a flagged surface can never flash on while the row loads.
The Supabase client is imported **dynamically inside the fetch**, not at module top level — the pure resolution logic must be importable (by tests, by a Node seam proof) without constructing a client from env vars that do not exist outside Vite.

**Task 3 — the regression test (1 new file, `tests/regression/HAR-41-feature-flags.js`).**
Guards the properties that decide whether an unattended flag is safe: default-off, override-wins, `!`-forces-off, and the red controls (a flag that is always on passes nothing here).
