## The measurement that decided the (c) design

The retired caps could not fire. `FEATURES-LATER.md` would have had to grow **125×** its live size
to trip a 150 KB cap, and `FEATURES-NEXT.md` had no cap at all. A cap that cannot fire is not a
guard, it is a comment — and check 3's whole job is to notice a v7.0.113 stub regrowing ticket rows.

New baselines are each file's live size plus deliberate slack, so an edit to the legend/taxonomy
prose these stubs legitimately carry stays quiet while a returning ticket table does not:

```
FEATURES.md       20 KB   (14.2 KB live — carries the Priority Class legend + Type taxonomy)
FEATURES-NEXT.md   4 KB   ( 1.2 KB live — legend-only stub, previously uncapped)
FEATURES-LATER.md  4 KB   ( 1.2 KB live — legend-only stub)
```

Stated as a **ratchet**, same discipline as `ROW_LENGTH_CAP`: tighten toward the measured size as
the stubs settle, never loosen to silence a real finding.
