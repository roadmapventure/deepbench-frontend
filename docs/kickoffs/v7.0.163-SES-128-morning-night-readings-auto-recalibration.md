## 2. CONTEXT

**Pick-time premise revalidation (`SES-87`, register B7) — the premise HOLDS, verified live this
cycle on four independent checks, none recalled:**

1. `information_schema.columns` for `public.runner_usage_readings` returns
   `id, taken_at, fable_pct, all_models_pct, session_5h_pct, source, est_tokens_since_prev,
   tokens_per_pct, note` — **there is no slot column.** Nothing in the schema can distinguish a
   night reading from a morning one.
2. All **eight** stored readings carry `tokens_per_pct = NULL`. **The platform has never once derived
   a calibration**, so every allowance it has ever computed fell back to the uncalibrated 10M cap
   or the 3M stale floor.
3. The live page's reading card (`briefing-template.html:629-638`) renders **one** row of three
   inputs and one Save button; `briefing-state`'s `reading` key is a single flat object
   (`{"fable":"20","all":"18","h5":"5","at":"2026-08-22T13:50Z"}`, read from the live artifact
   this cycle). No morning/night distinction exists on the page either.
4. `runner-cycle.md` step 3 carries the calibration *arithmetic* in prose but has **no derivation
   step** — no cycle is told to find the bracketing pair, compute from it, or set the day's max.

**One half of spec §4 is already done and this ticket must not redo it.** §4 also says the
"✓ Your latest reading was recorded" line moves from the tokens card to the reading card.
`SES-124` already moved it (`briefing-template.html:626-633`, comment names SES-128 as the owner
of the remaining Morning/Night rows). Verified by reading the template, not assumed.

**Why the night→morning pair is the mechanism.** John's meter is consumed by *both* his own manual
sessions and the runner. A window bracketed by his last reading at night and his first in the
morning is one in which **only the runner spent** — so tokens-per-percent measured across it is
uncontaminated. Any other window mixes the two and yields a calibration that is confidently wrong.

## 6. DESIGN RULES

- **Tokens:** no new colour, font or spacing value. The Morning/Night rows reuse the existing
  `.readgrid` / `.savebtn` / `.recorded` classes verbatim — `src/tokens.js` is untouched.
- **Fail closed, in both directions.** A derivation that cannot be trusted returns NULL and the
  caller falls back to today's existing guardrails; it never returns a guess. The four guards:
  no bracketing pair → NULL; `all_models_pct` delta ≤ 0 (a meter reset or a rolled-over week) →
  NULL; zero estimated tokens inside the window → NULL; window wider than 24h → NULL.
- **John's word outranks the derivation.** An unexpired `budget_override` with `max_tokens` is the
  ceiling, full stop — this matches register B32 and is stated in step 3 rather than left to a
  cycle to infer.
- **Rule as code, not as prose.** The derivation is a Postgres function because this platform has
  now paid four times for the alternative (`SES-86` phase 3, `v7.0.146`, `SES-101`, `SES-111`,
  `SES-127`): a rule each cycle re-derives from a paragraph is a rule that gets re-derived

  `SES-127` each required for theirs — the first tap on a page published before this shipped must
  not throw on an undefined.
