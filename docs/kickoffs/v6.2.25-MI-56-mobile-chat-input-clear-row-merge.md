## 2. CONTEXT

`S-MI-51` (earlier today) built the current mobile shell: a permanent Chat/Evidence tab bar, a permanent elapsed/expect status strip, and a permanent "Question box, Send, and a Clear link... reachable regardless of active tab" (its own words, `STYLE-GUIDE.md` §21). As implemented, that permanent strip is actually **two separate flex rows**:

1. Input + Send, in one row, `padding:"9px 14px 0"` (no bottom padding).
2. A second, separate full-width row directly below it, `padding:"4px 14px 7px"`, `justifyContent:"flex-end"`, containing only the "Clear" text link.

John's screenshot shows this clearly: the input+Send row looks correct, but the Clear row beneath it reads as a large, mostly-empty horizontal bar with a small "CLEAR" label floating in the far corner — visually disconnected from the input above it, like a stray leftover element rather than part of the same control group.

**Fix:** merge both rows into one. Input (`flex:1`) — Send button — a thin `1px` vertical divider (`background: T.lineSoft`) — Clear link, left to right, single row.

**Why the divider, not just closer spacing:** Clear has **no confirm dialog** — it resets the entire conversation and any active theory flow immediately on tap, a deliberate `S-MI-51` decision this session does not revisit. Putting Clear directly adjacent to Send without any visual separation increases the real risk of a mis-tap right after sending a message. The divider (plus its own small flanking gaps) gives Clear a distinct visual zone within the row — a lightweight mitigation that doesn't require reopening the confirm-dialog question, which is out of scope here.

`STYLE-GUIDE.md` §21's newest amendment (already locked by this design session, appended after `S-MI-51-design`'s rewrite and `MI-50`'s prior amendment — not a conflict, not a rewrite of either) is the source of truth for the rule above.

## 6. DESIGN RULES

- Single row, `alignItems:"center"`, `gap:8` between each element (input↔Send, Send↔divider, divider↔Clear)
- Divider: `width:1px`, `alignSelf:"stretch"` (matches the row's own height), `background:T.lineSoft`
- Clear stays visually de-emphasized relative to Send — muted-gray small mono uppercase text, no button chrome — exactly as it already was, just relocated
- Bottom padding on the merged row: `8px` (splits the difference between the old two rows' combined `0` + `7px`, closes the strip off cleanly before the Agent Routing panel below)
- Do not add a confirm dialog to Clear — that's a separate, already-made `S-MI-51` decision, out of scope
- Full detail: `STYLE-GUIDE.md` §21's newest amendment (already locked)
