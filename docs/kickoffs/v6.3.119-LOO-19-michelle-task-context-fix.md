## CONTEXT

Users are seeing "Something went wrong reaching Marcus — try again." on the Channel Sales Intelligence screen at an elevated rate. Root-caused (design/investigation session `investigate-marcus-error-0721`, 2026-07-21/22) via real `durable_hops` Supabase data: platform-wide schema-tool parse-failure rate jumped from a 0–17% baseline (07-13 through 07-18) to 22–56% every day from 2026-07-20 onward — a real regression, not baseline flakiness.

**Root cause:** commit `6a052d3` (`HAR-06`, 2026-07-18) added a generic task_context pass-through to `api/prompt/db-assembly.js`'s `assemblePrompt()`: when `task_context.goal` is present, it now also does `Object.entries(task_context)` to append every other field into the prompt's CURRENT TASK section. This assumed `task_context` is always a plain object.

`api/capabilities/execute.js`'s `dispatchDelegation()` (line ~485) is the **one exception platform-wide** — confirmed by an exhaustive grep of every `task_context:` assignment in `src/` and `api/` (every other caller passes a plain object literal or an already-object variable). The `request_help` → Michelle (`project-manager`/`agent-selection-intent`) dispatch builds her `task_context` via `JSON.stringify({ ...tool_input, requesting_agent_id: agent_id })` — a string, not an object. This dates to `AA-87` (2026-07-02), written one day *before* `AI-44` (2026-07-03) added the proper generic object-fallback mechanism that would have handled this shape correctly; nobody went back to switch Michelle's call over once the better mechanism existed, since it wasn't broken yet.

`Object.entries()` on a string iterates its individual characters. Confirmed directly against a real failed row (`durable_hops` id `9db8948e-71a8-4ec5-998c-b621c6d83a40`): Michelle's stored `system_prompt` was 48,384 characters, containing literally `0: {\n1: "\n2: s\n3: k\n4: i\n...` for thousands of lines right after the Goal text — her real instructions buried in noise. Since every agent's `request_help` call routes through her, this explains schema-tool failures cascading across otherwise-unrelated intents (her own `agent-selection-intent` missing `reasoning`, and downstream `qg-review-intent` escalations that request her help).

**Explicitly out of scope:** `HAR-9` (Eleanor's separate, pre-existing `library-catalog-intent` citations-field flake) is a distinct, already-tracked issue — confirmed unrelated (her prompt is built from a real object, not a string) and not touched by this fix.

## TASKS (1 of 1)

### Task 1 — Pass `task_context` as a plain object at the `request_help` dispatch site

**File:** `api/capabilities/execute.js`

Find (inside `dispatchDelegation()`, the `via_tool === 'request_help'` branch, ~line 483-487):

```js
    delegateResult = await runCapability({
      capability_slug: 'project-manager', intent_slug: 'agent-selection-intent', agent_id: pmAgentId,
      task_context: JSON.stringify({ ...tool_input, requesting_agent_id: agent_id }), tenant_id, _hop_counter: hopCounter, _deadline: deadline, _onEvent: onEvent,
      _trace_id: trace_id,
    });
```

Replace with:

```js
    delegateResult = await runCapability({
      capability_slug: 'project-manager', intent_slug: 'agent-selection-intent', agent_id: pmAgentId,
      task_context: { ...tool_input, requesting_agent_id: agent_id }, tenant_id, _hop_counter: hopCounter, _deadline: deadline, _onEvent: onEvent,
      _trace_id: trace_id,
    });
```

That's it — remove `JSON.stringify(...)`, pass the object directly. `tool_input`'s real fields (`skill_needed`, `task_description`, `context`, `reasoning`) plus `requesting_agent_id` will now flow through `db-assembly.js`'s existing `AI-44` generic "TASK DETAILS" fallback (they have no `.goal` key, so `assemblePrompt()` correctly routes them there, not into the buggy `CURRENT TASK`/Goal branch) — the same safe, already-proven mechanism Nadia's and Sam's capabilities already use. No change to `db-assembly.js` itself.

**Add a version-header comment update** to `api/capabilities/execute.js`'s top-of-file header line (per `STANDARDS.md` Section 1) noting `v6.3.119 | LOO-19 -- Michelle's request_help dispatch passes task_context as a real object, not a stringified blob; JS's Object.entries() on a string iterates characters, which combined with HAR-06's new generic pass-through corrupted her prompt on every request_help call since 2026-07-18`.

## NODE.JS TEST

Live test (Category L — required, this session modifies code that calls an `api/` endpoint's internal dispatch). Save as `test-loo-19-api.mjs` in the worktree root, run via `node --env-file=.env.local test-loo-19-api.mjs`, **delete before commit**.

```js
// test-loo-19-api.mjs -- LOO-19 live verification: Michelle's request_help dispatch no longer
// corrupts her prompt when task_context is passed as a real object instead of a JSON string.
import { assemblePrompt } from './api/prompt/db-assembly.js';
import { runCapability } from './api/capabilities/execute.js';

const task_context = {
  skill_needed: 'Verification of specific Data Room record IDs against their data_type classification',
  task_description: 'Confirm whether the cited record IDs are genuinely sourced-tier before an answer citing them can be cleared.',
  context: 'Raised by a quality-gate review of a channel-intelligence answer that cites several Data Room records.',
  reasoning: 'The synthesized_as_fact guardrail requires this verification before the answer can pass.',
  requesting_agent_id: 'owen',
};

let failures = 0;
function check(cond, label) {
  if (cond) { console.log(`PASS: ${label}`); }
  else { console.error(`FAIL: ${label}`); failures++; }
}

// 1. Prompt-shape check -- the actual bug: character-by-character garble from Object.entries()
//    on a string. Confirms the fix at the source (assemblePrompt sees a real object now).
const promptRequest = await assemblePrompt({
  capability_slug: 'project-manager', agent_id: 'michelle', tenant_id: 'global',
  task_context, intent_slug: 'agent-selection-intent',
});
const taskSection = promptRequest.sections.find(s => s.slug === 'current-task' || s.slug === 'task-details');
check(!!taskSection, 'a CURRENT TASK or TASK DETAILS section was built');
check(taskSection && !/\n\d+: /.test(taskSection.content), 'no character-index garble (e.g. "0: {") in the prompt');
check(taskSection && taskSection.content.includes('skill_needed:'), 'skill_needed field present as clean text');
check(taskSection && taskSection.content.includes('requesting_agent_id: owen'), 'requesting_agent_id present (parity check -- her self-referral guard depends on this field reaching her)');
check(taskSection && taskSection.content.length < 2000, `prompt section is a reasonable size (${taskSection?.content.length} chars, vs. 48,384 for the real pre-fix failing case)`);

// 2. Live call -- the bug's real-world symptom was "Parse failed and retry also failed" on this
//    exact call. A clean live round trip proves the mechanism, not just the prompt shape.
const result = await runCapability({
  capability_slug: 'project-manager', intent_slug: 'agent-selection-intent', agent_id: 'michelle',
  task_context, tenant_id: 'global',
});
const content = result.content || result;
check('candidates' in content, 'live response includes candidates field');
check('reasoning' in content, 'live response includes reasoning field (this exact field was the one confirmed missing in production failures)');
check(!!content.recommended_agent_id || content.no_match === true, 'live response has either a real recommendation or a legitimate no_match verdict');

if (failures > 0) { console.error(`\n${failures} check(s) failed.`); process.exit(1); }
console.log('\nAll checks passed.');
```
