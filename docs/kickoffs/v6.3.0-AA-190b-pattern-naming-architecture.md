## 1. CONTEXT

Two related findings from this design session's ongoing `AA-190` investigation:

**Finding 1 — three pattern names in `PATTERN_CATALOG` use invented or misapplied terminology instead of the real published term (John's explicit directive: standard AI terms only, from here on out, verified against the literature, not guessed):**
- `agent-delegation`'s own `desc` field already cites the correct term and just doesn't use it as the label: *"Orchestrator-workers pattern (Anthropic, 'Building Effective Agents')"* — the `name` field says "Agent Delegation" instead of **Orchestrator-Workers**.
- `intelligent-synthesis` describes a full-prompt rewrite pass to fit a token budget — the established term for this is **Prompt Compression** (LLMLingua/LongLLMLingua, Microsoft Research).
- `transfer-learning` is not just non-standard, it's **wrong** — real Transfer Learning is weight-level model adaptation, unrelated to what this pattern does (generalizing one confirmed correction into a reusable rule for future similar questions). That's the **Retain** phase of the classic Case-Based Reasoning cycle (Aamodt & Plaza 1994: Retrieve→Reuse→Revise→Retain) — the correct term was already sitting in this same catalog, since `case-based-reasoning` is a correctly-named sibling pattern. Renaming to **Case Retention** pairs it correctly with its sibling.

**These are display-name-only changes — no `slug` changes.** Confirmed this design session: `agent-delegation` and `transfer-learning` slugs are still actively written by not-yet-migrated sites (`execute.js`'s `logAgentTurn()`, `request-receivable.js`'s `buildPatternsUsed()`) — renaming the slug itself would silently orphan every existing and future row from those sites until they're migrated (sites 4+ in this sequence, not yet done). Only the `name` field (and every string in `SERVICE_CATALOG[*].patterns` that duplicates it) changes.

**Finding 2 — no structural mechanism prevents this drift from recurring.** `PATTERN_CATALOG` lives in `src/hooks/useAIActivity.js`, a frontend-only file — confirmed this session, zero existing precedent anywhere in the repo of `lib/`/`api/` importing from `src/`. That's *why* 9 server-side write sites hardcode their own `patterns_used` string literals instead of referencing the catalog, and why `AI-50c`'s `reflection`→`reflect` rename (found in `AA-190` site 1's investigation) silently didn't reach `ai-enrichment.js`. Fix: extract `PATTERN_CATALOG` into a new framework-free file both runtimes can import, and have `logActivity()` validate every `patternsUsed` array against it at write time — a typo or stale slug logs a loud warning immediately, not silent invisibility discovered a day (or never) later.

**Also fixed, found while reading `SERVICE_CATALOG` for cross-references:** the `ai-enrichment` service entry (line 28) never listed `Intelligent Synthesis`/Prompt Compression in its `patterns` array at all, despite the code performing it (`ai-enrichment.js`'s Step 4 — not migrated yet, that's `AA-190` site 3, but the catalog tag itself belongs here since we're already fixing this entry's other pattern names).

```js
import { PATTERN_CATALOG } from './shared/ai-patterns.js';
import { SERVICE_CATALOG } from './src/hooks/useAIActivity.js';
import { logActivity } from './lib/activity-log.js';

let failures = 0;
function assert(cond, label) {
  if (!cond) { failures++; console.error(`FAIL: ${label}`); }
  else { console.log(`PASS: ${label}`); }
}

// Category M: every pattern name in every SERVICE_CATALOG[*].patterns array must exist
// (by name) in PATTERN_CATALOG, and be active:true -- the exact check class that would have
// caught this session's own bug before it shipped, and will catch the next one.
const catalogNames = new Set(PATTERN_CATALOG.filter(p => p.active).map(p => p.name));
let allServicePatternsValid = true;
for (const svc of SERVICE_CATALOG) {
  for (const patName of svc.patterns) {
    if (!catalogNames.has(patName)) {
      allServicePatternsValid = false;
      console.error(`  -> "${patName}" (service: ${svc.slug}) not found as an active PATTERN_CATALOG name`);
    }
  }
}
assert(allServicePatternsValid, 'Category M: every SERVICE_CATALOG pattern name matches an active PATTERN_CATALOG name');

// Regression tests: the 3 renames landed, slugs unchanged
const bySlug = Object.fromEntries(PATTERN_CATALOG.map(p => [p.slug, p]));
assert(bySlug['agent-delegation']?.name === 'Orchestrator-Workers', 'agent-delegation renamed to Orchestrator-Workers, slug unchanged');
assert(bySlug['intelligent-synthesis']?.name === 'Prompt Compression', 'intelligent-synthesis renamed to Prompt Compression, slug unchanged');
assert(bySlug['transfer-learning']?.name === 'Case Retention', 'transfer-learning renamed to Case Retention, slug unchanged');

// Regression test: ai-enrichment service now tags Prompt Compression
const aiEnrichment = SERVICE_CATALOG.find(s => s.slug === 'ai-enrichment');
assert(aiEnrichment?.patterns.includes('Prompt Compression'), 'ai-enrichment SERVICE_CATALOG entry now includes Prompt Compression');

// logActivity() write-time validation: capture console.warn instead of hitting real network
let warned = null;
const realWarn = console.warn;
console.warn = (msg) => { warned = msg; };
let capturedBody = null;
const realFetch = global.fetch;
global.fetch = async (url, opts) => { capturedBody = JSON.parse(opts.body); return { ok: true, json: async () => ({}) }; };
process.env.SUPABASE_URL = 'https://test.supabase.co';
process.env.SUPABASE_SERVICE_KEY = 'test-key';

logActivity({ agentId: 'dan', aiType: 'reflect', feature: 'ai-enrichment', patternsUsed: ['reflect'] });
await new Promise(r => setTimeout(r, 10));
assert(warned === null, 'logActivity: valid slug produces no warning');
assert(JSON.stringify(capturedBody.patterns_used) === JSON.stringify(['reflect']), 'logActivity: valid patternsUsed still written as given');

warned = null;
logActivity({ agentId: 'dan', aiType: 'reflect', feature: 'ai-enrichment', patternsUsed: ['reflection'] });
await new Promise(r => setTimeout(r, 10));
assert(warned !== null && warned.includes('reflection'), 'logActivity: stale/unrecognized slug ("reflection") triggers a warning naming it');
assert(JSON.stringify(capturedBody.patterns_used) === JSON.stringify(['reflection']), 'logActivity: unrecognized patternsUsed still written as given, not silently dropped');

console.warn = realWarn;
global.fetch = realFetch;

if (failures > 0) {
  console.error(`\n${failures} test(s) FAILED`);
  process.exit(1);
} else {
  console.log('\nALL TESTS PASS');
```
