## CONTEXT

**Root-caused via direct Supabase `deliverables` query, not guesswork — worse than the originally-described symptom.** `AA-135`'s residual "Riley-shape" case isn't just a cosmetic `confidence_tier: undefined` in the Pipeline Log — it's a genuinely blank chat card, because of a harness bug one level deeper than previously documented.

`html-display-format` (Riley) has `traits.schema: null`, `output_type: 'html'` — she has no schema tool, so her call terminates via a plain-text model response. Her real output (confirmed live via Supabase) is a raw HTML **string**, e.g. `content: "<div>...</div>"` — not an object.

When Marcus's `delegate_to_agent(is_final:true)` picks Riley, `buildFinalDelegationResult()` (`execute.js`, fixed for shape by `AA-144`) does `...content` to flat-spread the delegate's content onto the final result. **`...` on a string spreads its characters as numeric-indexed properties** (`{0:'<', 1:'d', 2:'i', ...}`) — not an error, just useless junk. None of `headline`/`body`/`confidence_tier` ever get set. The frontend's `runQaWithQualityGate()` then reads `display.headline`/`display.body` — both `undefined` — producing a fully blank card, not just a missing badge.

This is a **generalizable harness bug**, not Riley-specific: any future capability with a non-JSON `output_type` used as an `is_final` delegate target would hit the identical failure. `AA-129`'s existing fix (giving Michelle visibility into candidates' output shape) reduces *how often* this fires but is explicitly "observed improvement, not a guarantee" per its own architecture (agent selection is reasoned, never hardcoded) — this session makes the outcome safe *when* it does fire, rather than trying to prevent selection deterministically.

## TASKS (3)

**Task 1 — `api/capabilities/execute.js`: stop spreading non-object content.** In `buildFinalDelegationResult()`, only flat-spread `content` when it's a genuine plain object — never a string (or other primitive). `content` itself (the mirrored key added by `AA-144`) still always carries the real value unchanged.
```js
export function buildFinalDelegationResult({ delegateResult, targetAgentId, targetCapabilitySlug, targetIntentSlug, finalPatterns, displayAgentCard, lastHelpSelection }) {
  const content = delegateResult.content;
  if (!content || (typeof content === 'object' && Object.keys(content).length === 0)) {
    throw new Error(`delegate_to_agent: ${targetAgentId}/${targetCapabilitySlug}${targetIntentSlug ? '/' + targetIntentSlug : ''} returned no content for a final delegation (violations: ${JSON.stringify(delegateResult.violations || [])})`);
  }
  const isPlainObject = typeof content === 'object' && content !== null;
  return {
    status: 'final_delegation',
    content,
    ...(isPlainObject ? content : {}),
    patterns_used: finalPatterns,
    display_agent_card: displayAgentCard,
    display_agent_id: targetAgentId,
    selection: lastHelpSelection,
  };
}
```
Note: the empty-content guard is unchanged in effect — `Object.keys("")` is `[]` (still throws on a genuinely empty string), `Object.keys("<div>...")` is non-empty (still passes) — only the `typeof content === 'object'` check is new, and it only gates the spread, not the guard.
