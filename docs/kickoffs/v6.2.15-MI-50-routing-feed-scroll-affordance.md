## 2. CONTEXT

`S-MI-45` built the mobile "Agent Routing · Live" feed — a `flex:1` pane pinned below chat (`MarketIntelligenceScreen.jsx`, `MobileBody`, ~line 1429-1439) with plain `overflowY:"auto"`. John's live report: there's no visual signal that panel is scrollable, easy to miss since mobile browsers show thin/auto-hiding native scrollbars.

**Direct precedent already shipped, read it before writing anything:** `SH-21`'s follow-up session (`AboutPanel.jsx`, ~lines 514-543) added the same kind of hint to a horizontal-scrolling tab bar — a `linear-gradient` fade from transparent to the panel's own background color, plus a small brass chevron, `pointerEvents:"none"` so it never blocks taps. That one is **static** (always shown on mobile, not scroll-position-aware) because tab bars always overflow by design on mobile there.

**This session's fix is dynamic, and that's a deliberate, justified departure from the static precedent — not an inconsistency:** the routing feed's content is variable (0 events at first load, 1-2 events that fit fine, or many events that genuinely overflow). A static always-on hint would be visibly wrong — shown even when there's nothing below to scroll to. So this fix computes actual remaining scroll distance (`scrollHeight - scrollTop - clientHeight`) and only renders the hint when there's real content below the fold, re-checked on scroll and whenever the event list grows (new events streaming in).

**Second deliberate departure:** the chevron animates (reuses the already-existing `dbounce` keyframe from `tokens.js`'s `GLOBAL_CSS` — do not add a new keyframe) where `SH-21`'s tab hint is static. Justified: this panel is specifically about live, moving content ("Agent Routing · Live," matching the platform's established "movement is king" mobile emphasion from `S-MI-45`), so a little motion on the affordance itself reinforces that the panel is alive, not just decorative chrome.

`STYLE-GUIDE.md` §21's 2026-07-14 amendment is already locked and is the source of truth for the rule above.

## 6. DESIGN RULES

- Fade gradient: `linear-gradient(to bottom, transparent, T.cardAlt 70%)`, `height: 26px` — matches `SH-21`'s gradient shape/stop, adapted to vertical
- Chevron: `mono`, `fontSize: 10`, `color: T.brass`, `"⌄"` — matches `SH-21`'s chevron styling exactly (font/size/color), different glyph (down vs. right) and animated (`dbounce`, unlike `SH-21`'s static one) — both departures justified in Section 2, do not remove the animation to "match" `SH-21` more closely
- `pointerEvents: "none"` on the overlay — mandatory, must never intercept a tap meant for the feed underneath
- Threshold: `> 4px` remaining scroll distance (not `> 0`) — avoids flicker from sub-pixel rounding when genuinely at the bottom
- Re-check triggers: on `scroll` (user-initiated) and on `ordered.length` change (new events arriving) — both required, a feed that grows while the user isn't actively scrolling must still get the hint if it now overflows
- Full detail: `STYLE-GUIDE.md` §21's 2026-07-14 amendment (already locked)

## 8. NODE.JS TEST

```js
// test-MI-50.mjs
// Pure logic tests — no app imports. Mirrors the scroll-distance calculation (Category B)
// and confirms the threshold avoids false positives at exact/near-exact bottom (Category C-adjacent).

let pass = 0, fail = 0;
function assert(desc, cond) {
  if (cond) { console.log(`  ✓ ${desc}`); pass++; }
  else       { console.error(`  ✗ ${desc}`); fail++; }
}

function canScrollMore(scrollHeight, scrollTop, clientHeight) {
  return scrollHeight - scrollTop - clientHeight > 4;
}

// T1: content taller than viewport, scrolled to top — more below
assert("T1: scrolled to top with overflow shows the hint", canScrollMore(400, 0, 150) === true);

// T2: content taller than viewport, scrolled to true bottom — no hint
assert("T2: scrolled to exact bottom hides the hint", canScrollMore(400, 250, 150) === false);

// T3: content exactly fits, no overflow at all — no hint
assert("T3: content exactly fills the pane, no hint", canScrollMore(150, 0, 150) === false);

// T4: content shorter than viewport (few events) — no hint
assert("T4: short content (0-2 events) never shows the hint", canScrollMore(80, 0, 150) === false);

// T5: sub-pixel rounding near the bottom (e.g. 2px remaining) — no false positive
assert("T5: 2px remaining (sub-threshold) does not show the hint", canScrollMore(400, 248, 150) === false);

// T6: 10px remaining — real remaining content, shows the hint
assert("T6: 10px remaining shows the hint", canScrollMore(400, 240, 150) === true);

console.log(`\n${pass + fail} tests — ${pass} passed, ${fail} failed`);
if (fail > 0) process.exit(1);
else console.log("ALL TESTS PASS");
```
