## 4. STUB DEFINITIONS

Three calls, made here, reversible:

- **D1 — the unit is the added line, not the changed file.** Scope = the `+` lines of `git diff --unified=0 <base> HEAD`. Editing line 10 of a kickoff that carries the literal on line 155 stays green; only a line this change *adds* can go red.
- **D2 — a step inside the existing `checks` job, not a new job** (pattern:17). `checks` is already blocking and already covered by the anchor, so there is no `needs`/payload churn and no SES-255 breakage.
- **D3 — fail closed on an unresolvable base: exit 2.** Matches the script's own convention ("exit 2 = could not run, never a pass"). Safe because `on: push` fires only on `dev` and `main`, so `github.event.before` is always a real sha.

New in `scripts/audit-private-scan.js` — additive; `scanTree`, `scanText`, `trackedFiles`, `DETECTORS`, `ALLOWLIST` and `aggregate` are unchanged:

- `export function addedLines(baseRev, rootAbs = ROOT)` → `[{rel, line, text}]`, parsing `git diff --unified=0 --no-color <baseRev> HEAD` and reading new-file line numbers off the hunk headers (`@@ -a,b +c,d @@`). Throws when `baseRev` will not resolve.
- `export function scanChange(baseRev, rootAbs = ROOT)` → hits, calling `scanText(rel, line)` per added line and remapping the returned `line: 1` to the real new-file number.
- `main()` gains `--base=<rev>`: with it, run `scanChange`, print `private-scan (change-scoped) N hits vs <rev>`, and **exit 1 when N > 0**, 0 when clean, 2 when the base will not resolve. Without it, today's whole-tree behaviour and exit 0 are untouched.
