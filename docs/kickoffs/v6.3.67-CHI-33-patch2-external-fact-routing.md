## CONTEXT

**Root cause, fully traced across two live-QA passes:**

1. Marcus's `ci-routing-intent` classifier only distinguishes two shapes: an already-established Data Room fact being explained (**qa**) vs. the user's own unverified causal claim being proposed for testing (**theory**). A real, externally-sourced fact (a news headline) presented as *given*, asking how it relates to Data Room content, is a third shape his method text never names — so it falls into whichever existing bucket sounds closest, inconsistently (first attempt: `escalate`; reworded attempt: `theory`).
2. Underneath that: even a correct `qa` classification wouldn't have used the fetched article properly. `ci-answer-intent`'s own method text scopes him to "only what your own retrieved context... provides from the CSO Data Room" — there is no instruction anywhere telling him to read and incorporate supplementary `task_context` fields like the article content `CHI-33` already passes in.

**The fix — Skill Profile content only, additive, capability-wide (verified: this is the exact same `ci-routing-intent`/`ci-answer-intent` pair every one of the 20 example questions and every free-typed question already calls — a content improvement here helps all of them, not just card clicks):**

1. `ci-routing-intent.method` gains one more explicit, additive rule: an externally-sourced fact presented as given (not the user's own theory) asking for its relevance against Data Room content classifies as **qa**.
2. `ci-answer-intent.method` gains an instruction to read and ground answers in any supplied background material (`task_context`'s extra fields), alongside normal Data Room retrieval — cited per his existing rules for Data Room content, referenced directly (no `data_type` tier of its own) for the external material.
3. The card-click question is reworded once more, now correctly shaped to match rule #1 — presents the headline as delivered news, not a causal test.
