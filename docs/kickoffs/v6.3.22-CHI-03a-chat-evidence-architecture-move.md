## 2. CONTEXT

Design session with John (2026-07-16, `S-CHI-03-design`) walked through John's live screenshot complaint (item #1 of 5 from the same session that produced `CHI-01`/`CHI-02`) and a full interactive mock before scoping: **any document, written analysis, or narrative Marcus (or any agent) produces is evidence and belongs in Column 2, never Column 1.** Chat should be pure agent-to-user conversation; when Marcus has findings, he *says* so in chat rather than the full analysis rendering as a chat bubble.

**Current architecture (confirmed by reading the code, not assumed):** `EvidenceColumn` only ever renders `hypFlow` state today (generating/choosing/ready/testing/result/confirmation). `MessageBubble`'s `qa` case (Marcus's full Q&A card: headline, body sections, Actual/Theorized data tables, review-choice buttons) and its `hyp_submitted`/`hypothesis_test` cases all render their full content **directly in chat** — `EvidenceColumn` never sees any of it. Critically: a user who asks a question and clicks "Good, thanks" (never starting a hypothesis flow) leaves that answer sitting in chat forever with `EvidenceColumn` staying in its empty state permanently — Evidence and the Q&A answer are only accidentally connected today via the fact that a hypothesis flow, when started, happens to reference the same answer.

**What this session actually builds (John's confirmed design, mock-approved):**
- Chat keeps: the flag/review-reason text, the "→ Sent to Priya" routing note, and elapsed-time captions — these are Marcus's own conversational commentary about his work, not the work itself, and stay exactly as they render today (John's explicit correction mid-session: not everything agent-authored is "evidence" — status/commentary about the deliverable is conversation, the deliverable itself is evidence).
- Chat's `qa` card shrinks to a pointer sentence: *"I've pulled together an answer — the full breakdown is in Evidence. Take a look and let me know if you have questions."*
- The qa answer's full card (headline/body/tables/byline) and its review-choice buttons ("Good, thanks" / "Have Priya generate theories") move into `EvidenceColumn`, which must now render independently of `hypFlow` — a brand-new `qaEvidence` state slot, separate from `hypFlow`, holds "the most recent Q&A answer," always shown in Evidence the moment Marcus answers, whether or not a hypothesis flow is ever started.
- The submitted-theory text (`hyp_submitted`, today a themed chat card) moves into `EvidenceColumn` too — no new state needed, it's already carried on `hypFlow.chosenText`, just needs to render there instead of as a chat message.
- Columns rename: "Interact" → **"Chat"**, "Evidence" → **"Evidence & Interaction"** (since the review/resolve actions move there too, not just read-only content).
- **Interim placeholder, not the final UX:** this session removes the old `hypothesis_test` chat-card push at `onDiscard()`/`onResolveConfirmation()` and replaces it with a short static placeholder line (not live-authored) — `CHI-03b` (separate session, already scoped) replaces that placeholder with a real Marcus-authored live acknowledgment. Shipping a static placeholder for one deploy cycle between `a` and `b` is a deliberate, accepted interim state, same precedent as `MI-01a`→`01d`'s incremental sub-sessions.

**Explicitly NOT in this session:** the two new live acknowledgment capabilities (`CHI-03b`), the turn→hop rename and cross-reference badges (`CHI-03c`), and `AA-197` (prompt caching — deliberately kept separate, harness-level, not folded in per John's explicit call).

## 8. NODE.JS TEST

Category B (Logic Tests) — pure state-shape/rendering-order logic, no DB/API/live call involved.

```js
// test-CHI-03a.mjs — pure Node.js, no app imports
let pass = 0, fail = 0;
function assert(desc, cond) {
  if (cond) { console.log(`  ✓ ${desc}`); pass++; }
  else       { console.error(`  ✗ ${desc}`); fail++; }
}

// Mirrors EvidenceColumn's new render-order decision (MarketIntelligenceScreen.jsx, Task 3).
function decideEvidenceRender(qaEvidence, hypFlow) {
  const blocks = [];
  if (qaEvidence) blocks.push("qa_card");
  if (hypFlow && hypFlow.chosenText && (hypFlow.stage === "testing" || hypFlow.stage === "result" || hypFlow.confirmation)) {
    blocks.push("submitted_theory");
  }
  if (hypFlow) blocks.push(`hypflow_${hypFlow.stage}`);
  if (blocks.length === 0) blocks.push("empty_state");
  return blocks;
}

// T1: plain Q&A, never escalated — qa card shows, nothing else
assert("plain qa with no hypFlow shows only the qa card",
  JSON.stringify(decideEvidenceRender({ headline: "x" }, null)) === JSON.stringify(["qa_card"]));

// T2: nothing asked yet — true empty state
assert("no qaEvidence and no hypFlow shows the empty state",
  JSON.stringify(decideEvidenceRender(null, null)) === JSON.stringify(["empty_state"]));

// T3: hypFlow started directly (own-theory path, MI-71), no prior Q&A — no qa card, no submitted-theory yet (choosing stage)
assert("hypFlow choosing stage with no qaEvidence shows only the hypflow block",
  JSON.stringify(decideEvidenceRender(null, { stage: "choosing" })) === JSON.stringify(["hypflow_choosing"]));

// T4: qa answered, then escalated to hypothesis flow now testing — both qa card AND submitted theory show
assert("qa + hypFlow testing shows qa card, submitted theory, and the hypflow block, in that order",
  JSON.stringify(decideEvidenceRender({ headline: "x" }, { stage: "testing", chosenText: "my theory" })) ===
  JSON.stringify(["qa_card", "submitted_theory", "hypflow_testing"]));

// T5: ready stage (theory chosen, not yet started) — chosenText exists but stage doesn't qualify yet, no submitted-theory block
assert("hypFlow ready stage does not yet show the submitted-theory block",
  JSON.stringify(decideEvidenceRender(null, { stage: "ready", chosenText: "my theory" })) === JSON.stringify(["hypflow_ready"]));

// T6: confirmation stage (Nadia's ConfirmationCard) — submitted theory still shows even though stage moved past "result"
assert("confirmation stage still shows the submitted theory",
  JSON.stringify(decideEvidenceRender(null, { stage: "result", confirmation: { confirmation_id: "c1" }, chosenText: "my theory" })) ===
  JSON.stringify(["submitted_theory", "hypflow_result"]));

console.log(`\n${pass + fail} tests — ${pass} passed, ${fail} failed`);
if (fail > 0) process.exit(1);
else console.log("ALL TESTS PASS");
```
