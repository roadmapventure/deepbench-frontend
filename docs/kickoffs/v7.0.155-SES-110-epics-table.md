## 6. DESIGN RULES

- **The epic is a grouping lens, never a sort key.** `recompute_backlog_queue()` is not touched
  and `epic_id` appears in no `ORDER BY`. Queue order must be byte-identical after this ship —
  asserted as a negative control, not assumed.
- **Grants: `epics` gets ZERO `anon`/`authenticated` privileges**, mirroring `backlog_items`
  exactly (measured this session: `relacl = {postgres=arwdDxtm/postgres,
  service_role=arwdDxtm/postgres}`, RLS off). The decision is *explicit*, per the ticket: nothing
  in the browser reads epics — the briefing page is static HTML rebuilt server-side by the cycle,
  and the dev site never queries the board — so the anon key needs nothing here.
- **The SES-78a new-table trap is LIVE and was measured, not assumed.** `pg_default_acl` for role
  `postgres` in schema `public` is
  `{postgres=arwdDxtm/postgres, anon=rm/postgres, authenticated=rm/postgres, service_role=arwdDxtm/postgres}`
  — a new table auto-grants `anon`/`authenticated` **SELECT + MAINTAIN**. Creating `epics` without
  an explicit `REVOKE` would publish it to the key that ships in the browser bundle. The migration
  therefore revokes explicitly, and QA asserts **both directions** per
  `.claude/rules/supabase-column-grants.md` — the denied role denied *and* the permitted role still
  permitted. A one-directional check passes on a table nobody can read at all.
- **`MAINTAIN` is checked via `pg_class.relacl`, not `information_schema`** (`DAT-20`: the
  information_schema views do not report PG17 `MAINTAIN`, so a `m` residue is invisible there).
- **Snapshot losslessness is the file's whole point.** The new column is appended LAST so every
  existing cell index is unchanged, and `ROW_FIELDS`/`COLUMNS`/the rendered header move together.
  `parseDocument()`'s strict `cells.length !== ROW_FIELDS.length` throw is the guard that a writer
  change without a reader change cannot pass QA.
- **The snapshot stores the epic NAME, not the uuid** — `epics.name` is UNIQUE and human-readable,
  so the backup restores membership without depending on a surrogate key surviving.
