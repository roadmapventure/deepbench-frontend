**Design decision this session encodes (2026-07-02, John — the "sniff test"):** every decision point in this mechanism was tested against *"does this show AI intelligence, judgment, and reasoning that is traceable and logged, or have we just hardcoded data/routing dressed up as intelligence?"* (now locked in `ARCHITECTURE.md` §19d's "Design intent" note). Three things follow directly from that test, and are the core of this session's design — do not deviate from them without a new design session:
1. **No fast path.** There is no way for a Skill Profile to pre-declare a fixed destination capability for "who handles my next step." Every single `request_help` call — even for a business step that will predictably resolve the same way every time (e.g. Stress Test output → triage) — routes through whoever holds `project-manager` and gets resolved by *their* live reasoning over the current roster. A stable outcome is fine; a hardcoded route to get there is not.
2. **The decision to ask for help is the requesting agent's own per-call inference**, never a static "always asks for backup" trait (fails the sniff test even as pure data) and never this session's job to auto-detect (that's Owen Marsh's deferred critique/governance role, `AA-81` — explicitly out of scope here, do not build any part of it).
3. **`delegate_to_agent`'s `agent_id` is only ever the model's own tool-call argument**, chosen from real candidates it was just handed — never a static field, never a harness-side lookup that picks for it.

## 2. CONTEXT

The Agent Loop (`ARCHITECTURE.md` §19d) lets a capability's model call a delegate tool mid-task instead of running strictly single-shot. The harness (`AA-80`) shipped correctly as a generic multi-turn loop, but its `available_delegates` data shape had two fields — `executing_agent_id` and `critique_agent` — that named a specific colleague directly inside another agent's Skill Profile data. That's the exact anti-pattern `§19e`'s Rule #1 bans: *no agent's data ever names another agent, ever — not even via a "generic" harness-level lookup.* No real agent's Skill Profile ever actually got this data populated (`AA-81`, which would do that, has been blocked on this session), so this is a pre-launch correction, not a live bug fix.

This session replaces that entire mechanism with one always-brokered path: a generic `request_help` tool (no `capability_slug`, no `agent_id` — just a plain-language description of the skill needed) that the harness routes, every time, to whoever currently holds the `project-manager` capability (Michelle Manning, resolved live — never the literal string `"michelle"`). Michelle's own `agent-selection-intent` (`AA-86`, already built) reasons over the live roster and returns ranked candidates — she never picks for the requester. The requester's model then calls a second generic tool, `delegate_to_agent`, naming the specific `agent_id`/`capability_slug` it chose from those candidates. The consequential-action gate (`requires_human_confirmation`) is also patched the same way: it moves off the deleted delegate-object shape onto the calling capability's own Intent Skill Profile, and its critique dispatch resolves live via the same mechanism, never a named `critique_agent`.

`AA-83` is folded in because it touches the identical code: `execute.js`'s HTTP `handler()` currently spreads `req.body` raw into `runCapability()`, which doesn't exclude the internal-only `_hop_counter` param from external input. A crafted request could seed a corrupted counter and undermine `§19d`'s "not data-overridable" hard ceiling on total delegate hops. Fixed by explicit-destructuring the public param list.

async function resolveCapabilityHolder(capability_slug) {
  const supabaseUrl = process.env.SUPABASE_URL;
  const supabaseKey = process.env.SUPABASE_SERVICE_KEY;
  if (!supabaseUrl || !supabaseKey) throw new Error('Supabase not configured');
  const headers = getSupabaseHeaders(supabaseKey);
  const res = await fetch(
    `${supabaseUrl}/rest/v1/agent_capability_assignments?capability_slug=eq.${encodeURIComponent(capability_slug)}&select=agent_id&limit=1`,
    { headers }
  );
  if (!res.ok) throw new Error(`Failed to resolve holder of capability "${capability_slug}"`);
  const rows = await res.json();
  if (!rows.length) throw new Error(`No agent currently holds capability "${capability_slug}"`);

export async function callModel({ systemPrompt, model, max_tokens, format_contract, canRequestHelp = false, conversation_history = [] }) {
  const anthropicKey = process.env.ANTHROPIC_API_KEY;
  if (!anthropicKey) throw new Error('ANTHROPIC_API_KEY not configured');
  const anthropicHeaders = { 'Content-Type': 'application/json', 'x-api-key': anthropicKey, 'anthropic-version': '2023-06-01' };

  const isJson = format_contract.output_type === 'json';
  const schemaTool = (isJson && format_contract.schema)
    ? { name: format_contract.skill_profile_slug, description: 'Return structured output', input_schema: format_contract.schema }
    : null;
  const harnessTools = canRequestHelp ? [REQUEST_HELP_TOOL, DELEGATE_TO_AGENT_TOOL] : [];

  const callBody = buildCallBody({ format_contract, systemPrompt, model, max_tokens, canRequestHelp, conversation_history });

  const llmRes = await fetch('https://api.anthropic.com/v1/messages', {
    method: 'POST', headers: anthropicHeaders, body: JSON.stringify(callBody), signal: AbortSignal.timeout(55000),
  });
  if (!llmRes.ok) {
    const text = await llmRes.text();
    throw Object.assign(new Error(`Anthropic call failed: ${llmRes.status}`), { status: 502, detail: text });
  }
  let llmData = await llmRes.json();
  let usage = llmData.usage || { input_tokens: 0, output_tokens: 0 };
  let retryCount = 0;
  let turn;

  try {
    turn = parseModelTurn(llmData, tools);
  } catch (parseErr) {
    if (tools.length > 0) {
      retryCount = 1;
      const retryBody = {
        ...callBody,
        messages: [...callBody.messages, { role: 'assistant', content: llmData.content }, { role: 'user', content: 'Your response did not conform to the required schema. Please try again and return the structured output exactly as specified.' }],
      };
      const retryRes = await fetch('https://api.anthropic.com/v1/messages', { method: 'POST', headers: anthropicHeaders, body: JSON.stringify(retryBody), signal: AbortSignal.timeout(55000) });
      if (!retryRes.ok) throw Object.assign(new Error('Parse failed and retry also failed'), { status: 422, detail: parseErr.message });
      llmData = await retryRes.json();
      usage = { input_tokens: usage.input_tokens + (llmData.usage?.input_tokens || 0), output_tokens: usage.output_tokens + (llmData.usage?.output_tokens || 0) };
      turn = parseModelTurn(llmData, tools);
    } else {
      throw Object.assign(new Error('Parse failed'), { status: 422, detail: parseErr.message });
    }
  }

  return { ...turn, raw_content: llmData.content, usage, retryCount };
}
