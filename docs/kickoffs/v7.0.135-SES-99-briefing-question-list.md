## The problem, in the shape John met it

The briefing has carried a section called **"Help me — the questions"** since register B29. It is
a *paragraph*. Today's copy asked him three things inside one block of prose — the parallelism
call, the routine cadence, and the `.claude/` pre-approval — and the only way to answer any of
them was to scroll to the directive box at the bottom of the page and **type an answer in
sentences**, on a phone.

So the cost of answering was set by the hardest question in the paragraph, and answering *one*
of three meant writing a sentence that named which one. Measured against his actual behaviour:
the section is a `<p>` with no controls in it, so **not one of its questions could ever be
answered through it** — every answer John has given (`fb643367` "1.no 2. Updates every
5 hours 3.I don't know how to answer", `1d01ea85` "1.leave it 2. Midnight cst 3.need to know why
it died") arrived as hand-numbered replies typed into the directive box, which then had to be
parsed back onto the questions by the next cycle. That parse is a guess, and one of those
answers — *"3. I don't know how to answer"* — is what a question costs when it is asked in
prose.

The cards already prove the cheap shape works: **37 of 37 cards decided, none left open**
(counted from `runner_items` this cycle), all by tap. Questions are the only thing on the page
still asking for prose.

## What ships

**A first-class question list, tappable, with a real home in the ledger.**

1. **New table `public.runner_questions`** (additive migration `ses99_runner_questions`, no
   existing object altered). One row per open question: a stable `qid` slug (the DOM id), the
   yes/no `question` sentence, one clause of `context`, the `asked_cycle`, and the answer
   columns (`answer` constrained to `yes`/`no`, `answered_at`, an optional typed `answer_note`,
   `status` in `open|answered|withdrawn`, `acted_cycle`). Public roles get **zero** privileges,
   asserted after the migration rather than assumed — `SES-78a`'s live catch was new tables
   coming up publicly readable, and `.claude/rules/supabase-column-grants.md` says read
   `role_table_grants` for **all** privilege types, not just SELECT.
2. **The page renders the open questions as rows with two buttons — Yes and No.** A tap records
   and self-publishes through the same `claude.use('artifact').publish(doc)` path every card
   already uses; the answer lands in the `briefing-state` block under a new `answers` key
   (`{"<qid>": {"a":"yes|no","at":"<iso>Z","note":""}}`). An optional one-line note input appears
   after a tap for when he wants to say more — **never required**, which is the whole point.
3. **The harvest reads it.** `runner-cycle.md` step 2 gains `answers`: each answered `qid` is
   written to `runner_questions` (before-image first), `status='answered'`. An answered question
   leaves the list on the next rebuild; an unanswered one carries forward, exactly like an
   un-decided card. **Silence is never an answer** — the same rule the cards already have.
4. **Step 9's "Help me" section becomes that list**, and the rule that a question must be
   *askable as yes/no* becomes part of the contract: a question that cannot be phrased that way
   is not ready to be asked, and belongs on a gated card with a proposal instead.

## Why a table rather than reusing `runner_items`

Checked, not assumed: `runner_items_kind_check` admits exactly `ship` and
`gated_before_build`, and `runner_items_decision_check` exactly `accept|reverse|rework`. Bending
a question into a card would have meant answering "is the routine hourly?" with **Reverse**, and
would have put questions into the same set the trust ladder and the exposure-rate line count.
A question is not work awaiting a rating; it is a question. It gets its own table.
