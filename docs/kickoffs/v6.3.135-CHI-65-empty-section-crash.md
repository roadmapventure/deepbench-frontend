## CONTEXT

Selecting a candidate theory on Channel Intelligence crashes the **entire page** with React error #31 ("Objects are not valid as a React child (found: object with keys `{text, citations}`)"). Found live 2026-07-22 during `CHI-59`'s QA; root-caused 2026-07-23.

Priya Nair — Forecast/Theory/Performance Expert — returns a hypothesis test as three sections (`supports`, `complicates`, `consider`), each shaped `{text, citations}`. Alex Reeves — Screen Controls Editor — renders them into the Column 2 Result drawer via `intelligence-review-format`. The screen unwraps each with `st.supports.text || st.supports` — a fallback written for a string-vs-object ambiguity. When `text` is present but **falsy**, that `||` falls through to the object itself, React refuses it, and the page dies.

`complicates.text` is typed `["string","null"]` in both Skills' schemas, and `intelligence-review-format`'s guardrail explicitly blesses null. **So an empty Complicates is sanctioned by the contract — the page crashes precisely when a theory is clean.**

**The deeper finding (§19j):** a deliberate "I checked and found nothing" and an accidentally-dropped field arrive as the identical value. Nothing can tell them apart. The fix makes the deliberate case say so out loud, which makes an empty section unambiguously a failure.

**`HAR-9` is ruled out** — that was `max_tokens` truncation; this fires on well-formed, schema-valid output. Different mechanism. Do not conflate them.

**Explicitly NOT this session** — all four have their own rows: `CHI-66` (no React error boundary exists anywhere in `src/`), `HAR-14` (`parseModelTurn()` checks top-level key presence only), `LOG-54` (nothing records that a section came back empty), `AGT-31` (`intelligence-review-format` omitting required fields on ~40–60% of display calls — the *other* error in this bug's original report).

SET method = method || E'\n\nNEVER LEAVE A SECTION EMPTY: supports, complicates, and consider must each contain real text on every response. ### Task 3 — `MarketIntelligenceScreen.jsx`: never hand React an object

**3a — add the helper** at module scope, immediately after `shapeForLog()` (~line 470). `shapeForLog()` is deliberately *not* reused: it truncates to 140 chars and would silently cut real analysis text.

```js
// FEATURE: CHI-65 — the Result drawer's three sections arrive as {text, citations} (both
// hyp-hypothesis-test-intent's and intelligence-review-format's schemas), except on the
// AA-135/AA-137 string-content paths where the whole value is a plain string. The previous
// `v.text || v` unwrap handled both, but fell through to the OBJECT whenever text was present-
// but-falsy — a state complicates.text's own ["string","null"] type explicitly permits — handing
// React an object and taking the entire page down (error #31). Returns usable text or "", never
// an object. Deliberately does NOT substitute placeholder copy for an empty section: the screen
// holds no content policy, that guarantee lives at the agent level (ARCHITECTURE.md §19j).
function sectionText(v) {
  if (typeof v === "string") return v.trim();
  if (v && typeof v.text === "string") return v.text.trim();
  return "";
}
```

**3b — compute once** in `EvidenceColumn`, immediately after the existing `groupKeyDataPoints` line (~1876):

```js
const stSupports = sectionText(st?.supports);
const stComplicates = sectionText(st?.complicates);
const stConsider = sectionText(st?.consider);
```

**3c — replace the three render sites** (currently lines 2106–2108). Each becomes gated on the computed text, with the text rendered directly. **Every style object, label, colour token and element structure stays byte-identical** — only the condition and the interpolated value change:

- L2106: `{st.supports && (…{st.supports.text || st.supports}…)}` → `{stSupports && (…{stSupports}…)}`
- L2107: `{st.complicates && (…{st.complicates.text || st.complicates}…)}` → `{stComplicates && (…{stComplicates}…)}`
- L2108: `{st.consider && (…{st.consider.text || st.consider}…)}` → `{stConsider && (…{stConsider}…)}`

A section with no usable text renders **nothing** — no heading, no placeholder line, no fallback copy.

// test-chi-65.mjs — CHI-65 empty-section crash guard
import { readFileSync } from "node:fs";

let pass = 0, fail = 0;
const eq = (label, got, want) => {
  const ok = got === want;
  ok ? pass++ : fail++;
  console.log(`${ok ? "PASS" : "FAIL"}  ${label}${ok ? "" : `\n        got=${JSON.stringify(got)} want=${JSON.stringify(want)}`}`);

// --- Category C: every shape that can reach this helper ---
eq("null text (the CHI-65 crash case) -> ''", sectionText({ text: null, citations: [] }), "");
eq("empty-string text -> ''",                 sectionText({ text: "", citations: [] }), "");
