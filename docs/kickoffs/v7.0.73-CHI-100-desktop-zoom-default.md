# CONTEXT

John's report, measured live by the design session (2026-08-07, dev preview): at an effective viewport of 1242×575 (a 1366-class laptop at ~110% browser zoom), the Channel Intelligence screen lays out 593px of content in a 575px viewport — the page overflows by 18px with no scroll, and what falls off the bottom is the chat input ("Ask about channel performance…") and its Send button. The beta surface's primary controls are invisible until the user manually zooms the browser to ~80%.

John's approved fix (this conversation, explicit yes): the app defaults to rendering at 80% on desktop. Verified live on the deployed page by the design session: setting `zoom: 0.8` on `#root` makes the chat controls visible — and exposes the one required compensation: everything `100vh`-based lays out at 100 viewport-CSS-px and then renders at 0.8 scale, leaving a 115px blank band below the app. Exactly two `100vh` sites exist in `src/` (verified by grep): `GLOBAL_CSS`'s `html, body, #root` rule and `AppShell`'s wrapper div. Hence the two-part spec below: zoom + height compensation, nothing else.

Mobile is untouched: the zoom applies only at `min-width: 769px`, the exact complement of `useIsMobile`'s `max-width: 768px`, so no mobile layout (all QA'd at true size this week) changes by even a pixel. Media queries and `matchMedia` evaluate against the real viewport and are unaffected by CSS zoom, so the mobile/desktop branch decision itself does not move.

The underlying CHI overflow (the column that refuses to shrink those last 18px) is deliberately NOT fixed here — filed as CHI-101 (UI, Post-beta): after this ships it reproduces only below ~460px of real viewport height.

# TASKS (2 tasks, 2 files)

## Task 1 — `src/tokens.js`: desktop zoom block in `GLOBAL_CSS`

Append to the `GLOBAL_CSS` template string, after the `input[type=range]` line (end of the current sheet):

```css
@media (min-width: 769px){
  #root { zoom: 0.8; min-height: calc(100vh / 0.8); --shell-h: calc(100vh / 0.8); }
}
```

With a comment line above it inside the CSS (CSS comment syntax) or as a JS comment on the export — match the file's existing style:

```
/* FEATURE: CHI-100 -- desktop renders at 80% (John's call): controls must fit at 100% browser
   zoom. 769px is MOBILE_BREAKPOINT+1 (useIsMobile.js) -- mobile stays true-size. Every
   100vh inside the zoomed root lays out at 80% of the viewport, so the two vh sites
   (this #root rule, AppShell's wrapper via --shell-h) compensate with calc(100vh / 0.8). */
```

Rules that are the point:
- `zoom` appears exactly once in `src/` — this block. No per-screen zoom anywhere.
- `769` is not arbitrary: it is `MOBILE_BREAKPOINT + 1`. Do not use a different number.
- The base `html, body, #root { … min-height:100vh … }` rule stays byte-identical — the media block overrides `#root` only, on desktop only.

## Task 2 — `src/AppShell.jsx`: shell height consumes the compensation variable

At the `AppShell` wrapper (~L367), change exactly:

```jsx
<div style={{height:"100vh",background:T.paperDeep,fontFamily:body,color:T.ink,display:"flex",flexDirection:"column"}}>
```

to:

```jsx
<div style={{height:"var(--shell-h, 100vh)",background:T.paperDeep,fontFamily:body,color:T.ink,display:"flex",flexDirection:"column"}}>
```

Mobile: `--shell-h` is unset (the media query doesn't match), the fallback keeps `100vh` — byte-identical behavior. Desktop: `calc(100vh / 0.8)` lays out, renders at 0.8 = exactly full viewport.

Also add the standard v7.0.73/CHI-100 version-header comment line at the top of both touched files.
