## The design question the ticket owns — PLACEMENT, answered by measurement

§7 says verbatim and the body is ~7.6 KB and grows with every amendment; the page is under the
`SES-188` read budget. The ticket left **placement** open ("below the state block, where growth is
harmless, or a fold"). Measured rather than argued, on the template as it stands:

| Anchor | Byte offset | % of file |
|---|---|---|
| `id="briefing-state"` | **2,624** | 1.6% |
| `secnum">15` | 136,064 | 83.0% |
| `secnum">16` | 143,010 | 87.2% |

The state block sits at **1.6%** of the document, and `doc()` (the renderer that produces the page
John's own taps publish) emits it **first in the body**, before `#f`/`#s` — that ordering is
`SES-188`'s own fix. Every section renders into `#page`, which is **after** the block on both paths.
So §17's growth is **provably below the block** and costs the harvest read nothing.

**That is asserted, not assumed:** the guard measures `briefing-state`'s byte offset in the built
page and requires it to be **byte-identical** before and after this change. No fold is needed, and a
fold was rejected for a second reason — a folded section is one John can leave closed, and §7's point
is that the directive is standing law he reads.

## The boundary that decides the §7b build

*"The pick list must be DERIVED from the same predicates the picker uses — never a second
hand-maintained copy"* (`SES-45`: "a second implementation agreeing with itself"). The live picker's
§2(c) predicate already exists in SQL — `drain_chain_gate`'s §2e branch, shipped by
`ses238_prime_directive_chain_gate` (attended, verified). Writing it a third time in JavaScript is
the defect this ticket names.

So: **one SQL home.** Migration `ses236_prime_directive_queue` creates
`public.prime_directive_queue()` and **refactors `drain_chain_gate` to call it**, so the page and the
gate cannot drift. `SES-238`'s own description asked for exactly this ("it should be one SQL home
both the picker and the gate call").

**The refactor is an extraction, never a widening**, and that is proven rather than claimed: the
gate's verdict on real cycle rows is captured **before** the migration and asserted identical
**after**. `drain_epic_next` is deliberately **not** touched — that is a bigger change with its own
risk, and the drain lane mirroring its pick side is disclosed below as this ticket's remainder.

## Named deviations, disclosed rather than buried (the `SES-196` convention)

1. **Ordering.** §2(c)'s words are *"oldest first"*; the **shipped picker** orders by `b.queue`
   (`drain_chain_gate`, and step 5's board read). The page must match the **live picker**, not the
   prose, so the Selfbuild lane orders by `queue` — and §17's note says so in John's register rather
   than quietly choosing one. Filed as question `q-pd-oldest-first`.
2. **Mission vs standing directives is a cycle's judgment, not a stored column.** §2(a) says
   *"mission directives"*; `runner_directives` has no column separating a build order from a standing
   authorization, and seven rows are queued right now of which one is a mission. The lane therefore
   renders **every** open queued directive, oldest first — which is what a cycle actually reads —
   with its opening words, and the note names this as the one figure on the panel that is not
   mechanically derived. Inventing the distinction in a `LIKE` heuristic would be a fact with a
   second home. Filed as question `q-pd-mission-flag`.
3. **The drain lane re-expresses `drain_epic_next`'s pick side.** `drain_epic_next()` **writes** (it
   retires a completed drain), so it cannot be called for display, and the runbook forbids adding a
   dry-run form to dodge that write. The drain lane therefore applies this function's own `buildable`
   CTE to `runner_drain_scope`'s named members. Consolidating that with `drain_epic_next` is this
   ticket's declared remainder, not silently absorbed.
4. **The Selfbuild lane does NOT exclude drain members**, though the page shows each ticket once.
   Excluding them in SQL would change what the gate's §2e branch selects and break the equivalence
   proof above; the de-duplication is therefore done at **render** time. The predicate stays
   byte-equivalent to what shipped.
