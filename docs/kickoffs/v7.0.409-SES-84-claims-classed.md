**Decided (M7 gate, ruling ii):** `SES-84` is done when (1) every live claim carries a `judgment_class` (P1–P4) **or an explicit class-neutral mark**, classified under the §19v delegation with a one-line reason; and (2) the standing brief renders, per class, the ratified / proposed / rejected counts and the newest proposed root claim. `SES-159` (the class-understanding loop) reads the same census, so the census is a **view**, not renderer-private arithmetic.

**What "class-neutral" means, decided here:** a claim that grounds no pull test — a mechanics fact (*"the ship gate is `check-decision-pattern-quotes.js`"*), a rejected path about process, a provenance note. It is a decision, not an absence, so it gets its own mark and reason. `NULL` in `judgment_class` alone stays ambiguous and is exactly what this ticket removes.

## 6. DESIGN RULES

- **Classing is not ratifying.** `status`, `confidence`, `provenance`, `decided_at` are John's columns (ratified/rejected) or the drafter's (confidence); this ticket never writes them.
- **One decision, one Reverse.** The whole pass is undone by `reverse_decision(<id>, 'John', '<why>')`; that is why every row gets a before-image under the decision.
- **The view is the one home for the census.** The renderer reads it; `SES-159` will read it; nobody re-derives the counts.
- **Neutral is a decision with a reason**, never a default.
