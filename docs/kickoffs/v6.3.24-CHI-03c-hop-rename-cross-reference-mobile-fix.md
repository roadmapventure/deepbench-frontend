## 2. CONTEXT

From the same design-session walkthrough: John asked for a more standard AI-industry term than "turn" for the Agent Routing log's numbering, since "turn" already means something different in AI/chat systems (a conversation turn — one user+assistant exchange) than what this codebase counts (one internal agent-to-agent delegation). Verified live in `ARCHITECTURE.md`/`docs/kickoffs/v6.3.19-AA-196-*` that **"hop" is already the established term in this exact codebase** — "platform-level hard ceiling on total delegate hops," the `durable_hops` table, the in-flight "hop budget" work — not a new term being introduced, a correction of an existing inconsistency.

**Also from the same walkthrough:** cross-reference badges connecting Chat/Evidence artifacts to the specific hop range that produced them (mock-approved, "option a" — range badges, not the heavier "Exchange N" grouping alternative). Since a single Chat/Evidence artifact (e.g. a `qa` answer) can span multiple hops (`AA-159`: one live run took 6 hand-offs for a single answer), the badge shows a range (`Hops 1–4`), not a single number.

**Real gap found while reading the mobile flash logic for this session (not previously scoped, but squarely part of "the mobile fix"):** `evidenceUnseen` (~L2026) only watches `hypFlow.stage` changing, and `hasActiveFlow` (~L2015: `!!hypFlow`) gates whether the Evidence tab is even clickable (~L2046) and whether it auto-opens (~L2038). Both predate `CHI-03a`'s `qaEvidence` addition — a plain Q&A that never starts a hypothesis flow now has real content in Evidence Column that the mobile tab-bar logic is completely blind to: the Evidence tab stays disabled and never flashes, even though `qaEvidence` has real content sitting there. This is a direct, mechanical consequence of `CHI-03a`'s own change, correctly scoped to this session (the mobile-fix session) rather than `CHI-03a` itself, per the split John already confirmed.

### Task 2 — Hop-range snapshot + cross-reference badges

Add a helper near `groupEventsIntoHops()`:
```jsx
// FEATURE: CHI-03c — snapshot the current hop count so a caller can compute the range of hops
// its own operation produced, once that operation's onEvent/logEvent calls are done. Read the
// live `ordered` (or its underlying source array/ref) as it stands at the moment of each call —
// confirm the exact current declaration before wiring this in, since CHI-03a/CHI-03b's edits may
// have shifted its exact form since this doc was written.
function currentHopCount(ordered) {
  return groupEventsIntoHops(ordered).length;
}
```

At each traced operation's boundaries, capture `{ hopStart: currentHopCount(ordered) + 1, ... }` immediately before its first `onEvent`/`logEvent` call, and `{ hopEnd: currentHopCount(ordered), ... }` immediately after its last one, attaching both onto the resulting object:
- `runQaWithQualityGate()` (~L820+) → attach to the `qa` result object that becomes `qaEvidence` (`CHI-03a`).
- `onSelectHypothesis()`'s `runHypothesisTest()` call (~L2350+) → attach to the `st` object that becomes `hypFlow.hypothesisTest`.
- `CHI-03b`'s two ack calls (`ci-submission-ack-intent`/`ci-resolution-ack-intent`) → attach to the resulting chat message (`hopStart`/`hopEnd`, typically equal to each other — a single hop — since neither ack can request help, `can_request_help: false`).

Render a small badge wherever these attach — `Hops {hopStart}` when `hopStart === hopEnd`, else `Hops {hopStart}–{hopEnd}` — on: `QaEvidenceCard` (`CHI-03a`, header row), the `hypFlow.hypothesisTest` render block (`EvidenceColumn`, near its header), the chat pointer sentence (`qa`'s new short bubble), and both `CHI-03b` ack messages. Badge style: small mono-font chip, border color matching the card's existing `borderLeft` accent color (no new color introduced — reuse whatever accent each card already uses).

**Known accepted approximation, do not attempt to fully solve:** if an operation's very first hop happens to share `agentId` with the immediately preceding operation's very last hop, `groupEventsIntoHops()` would merge them into one hop card — the boundary capture above attributes that shared hop to whichever operation's range captures it second. This is the same "hop" granularity limitation already accepted for the Agent Routing log itself; do not add cross-operation hop-splitting logic to work around it.

## 8. NODE.JS TEST

Category B (Logic Tests).

```js
// test-CHI-03c.mjs — pure Node.js, no app imports
let pass = 0, fail = 0;
function assert(desc, cond) {
  if (cond) { console.log(`  ✓ ${desc}`); pass++; }
  else       { console.error(`  ✗ ${desc}`); fail++; }
}

// Mirrors groupEventsIntoHops() post-rename (MarketIntelligenceScreen.jsx) — logic unchanged from
// the pre-rename groupEventsIntoTurns(), only field names differ.
function groupEventsIntoHops(ordered) {
  const hops = [];
  for (const evt of ordered) {
    const last = hops[hops.length - 1];
    if (last && last.agentId === evt.agentId) last.events.push(evt);
    else hops.push({ agentId: evt.agentId, events: [evt] });
  }
  const total = hops.length;
  return hops.map((h, i) => ({ ...h, hopNumber: total - i }));
}

// Mirrors Task 2's hop-range badge text logic.
function hopBadgeText(hopStart, hopEnd) {
  return hopStart === hopEnd ? `Hop ${hopStart}` : `Hops ${hopStart}–${hopEnd}`;
}

// T1: rename preserves exact prior grouping semantics
const seq = [{ agentId: "marcus" }, { agentId: "owen" }, { agentId: "owen" }, { agentId: "michelle" }];
const hops = groupEventsIntoHops(seq);
assert("3 real hand-offs collapse consecutive same-agent events into 3 hops", hops.length === 3);
assert("oldest hop is numbered 1", hops[hops.length - 1].hopNumber === 1);
assert("newest hop has the highest number", hops[0].hopNumber === hops.length);

// T2: badge text — single hop vs range
assert("single-hop badge reads 'Hop N'", hopBadgeText(5, 5) === "Hop 5");
assert("multi-hop badge reads 'Hops N–M'", hopBadgeText(1, 4) === "Hops 1–4");

// T3: mobile evidenceUnseen trigger — fires on qaEvidence change alone (the CHI-03c fix), not just hypFlow.stage
function shouldFlagEvidenceUnseen(qaEvidence, prevQaEvidence, stage, prevStage, mobileTab) {
  return (qaEvidence !== prevQaEvidence || stage !== prevStage) && mobileTab !== "evidence";
}
assert("qaEvidence-only change while on chat tab flags evidence unseen", shouldFlagEvidenceUnseen({ headline: "x" }, null, undefined, undefined, "chat") === true);
assert("no change does not flag evidence unseen", shouldFlagEvidenceUnseen(null, null, undefined, undefined, "chat") === false);
assert("change while already on evidence tab does not flag (already seen)", shouldFlagEvidenceUnseen({ headline: "x" }, null, undefined, undefined, "evidence") === false);

console.log(`\n${pass + fail} tests — ${pass} passed, ${fail} failed`);
if (fail > 0) process.exit(1);
else console.log("ALL TESTS PASS");
```
