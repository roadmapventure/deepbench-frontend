## 2. CONTEXT

The rule was written **reactively**: Victoria Chen shipped without standard fields and crashed

## 3. THE PROPERTY THIS SHIP TURNS ON

**The required-field list must not become a second copy.** The obvious implementation hardcodes the
23 names in the test. That creates two homes for one fact, and the moment §11 gains a field the test
keeps passing while the standard says otherwise — the exact drift this codebase has paid for
repeatedly (`SES-86` phase 3, `SES-101`, `SES-111`, `SES-127`…).

So the test **parses §11's own table out of `docs/STANDARDS.md`** and asserts `AGENTS` against it.
The document stays the single source of truth; adding a row to §11 immediately binds every agent.

**That move introduces its own failure mode, and it is guarded rather than assumed:** a parser that
finds nothing would assert nothing and pass. So the parse is asserted to yield **exactly 23 fields**
with the expected names before any agent is checked — if §11 moves or is reformatted, the test fails
**loudly** instead of going quietly vacuous.

**TYPES, NOT JUST PRESENCE — because presence would not have caught the original crash.** §11 gives a
type for every field. `trainableBy` present but numeric still dies on `.toUpperCase()`. The test
asserts the declared type per field, with `token` meaning one of the four `T` palette values the
table names.

  conditionally-skipped, which `SES-180`/`SES-61` have already shown reads as a pass. Named here as
  the remainder rather than half-built.
- It does not lint the *values* (a salary of 1 passes). It enforces the contract §11 states —
  presence, type, and palette membership — not editorial judgment about the numbers.
