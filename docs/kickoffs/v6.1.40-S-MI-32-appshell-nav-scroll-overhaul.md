## 1. CONTEXT

Three related UI bugs/changes found in a 2026-07-09 design session, all isolated to `AppShell.jsx`:

**MI-32 — root cause of the chat scrolling past the fold.** `AppShell.jsx`'s outer wrapper (`~line 236`) sets `minHeight:"100vh"` instead of `height:"100vh"`. Every screen in this app (all 11 `AppShell` consumers, confirmed by grep) already codes its own content region as `flex:1, overflowY:"auto"`, expecting the ancestor chain to hand it a definite, viewport-bounded height so it caps and scrolls internally. `minHeight` (vs `height`) breaks that: the root's height becomes content-driven instead of viewport-bounded, so the flex chain never gets a real size to divide up — every panel renders at natural content height and the whole document scrolls instead. On the Market Intelligence screen specifically, this drags the chat input box out of view once the message list grows. One-line fix.

**MI-33 — top nav should stay pinned (static) while content scrolls.** Very likely a side effect of MI-32, not a separate bug: the header (`AppHeader`, `height:60, flexShrink:0`) is already the first flex child ahead of the scrolling content region — it only scrolls away today because the whole document scrolls per MI-32. Verify live after the MI-32 fix; do not write a separate fix unless live testing shows it's still broken.

**MI-36 — nav restructure.** Collapse the current 3-tab nav (Market Intelligence / Work / Bench) back to 2 top-level tabs: **Work** and **Bench**. Clicking "Work" opens a dropdown, top to bottom: **Market Intelligence** (→ `/`, unchanged default-landing route — splash still lands here first, only the nav entry point moves), **Project Management** (→ `/work`, today's `DashboardScreen`, unchanged), **Spend Analysis** (→ `/work/1/analyze`, an existing, already-built page — `AnalyzerScreen.jsx`'s CSV-upload/column-mapping stage, deep-linked to task id `1` specifically — not a new build, just a new nav entry point to it). John's framing: "Work" becomes the parent container for multiple dashboards as the platform grows; these 3 are the first, more will follow later (not this session's scope). **"Work" tab shows active/highlighted whenever the user is on any of its 3 dashboard routes, including `/` (MI)** — MI is conceptually one of Work's dashboards now, John confirmed explicitly.
