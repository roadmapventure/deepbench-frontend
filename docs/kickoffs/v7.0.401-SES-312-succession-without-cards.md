## 2. CONTEXT

**The handoff still waits on a tap that no longer exists.** `gate-review.md` files the review as a `gated_before_build` card *"for John's Accept"*; prohibition 1 says the review *"writes no `backlog_items` row"* because *"his Accept on the card is what files them"*; directive `0970abad` declares the next drain only after the review is **accepted** (*"an undecided review card is not a naming"*). `SES-285` retired the card/tap surface, so no review can be accepted, no successor can be filed, no drain can be declared. The M5 review ran attended on 2026-09-02 and left no `runner_items` row at all; the M6 gate wrote one by hand (`18500000-…-a5`) so step 8d would not re-run it — a hand-written row is not a mechanism.

**Decided at the M6 gate (M6-01, reversible):** the review still files its `runner_items` row (the sweep's idempotence key — `ck_runner_items_epic_id_review_only` admits `epic_id` only on that shape), but under `M6-06` it **decides**: `decision = 'accept'` written by the review itself, `decision_reason` = the two lenses' verdicts, and the whole thing registered through `record_decision()` so it carries a 72-hour reversal handle. The successor members it names are filed **in the same transaction** (`M6-05`; charter closure item 3 — *"batched and visible to John"* — is met by the decision row and the standing brief's *Open decisions* block, `SES-286c`). The drain for the next milestone is declared in that same cycle under `0970abad`, whose body is amended so *"accepted"* reads *"decided and not reversed"*. A review with **disagreeing lenses** still decides — it records both positions verbatim and rules the narrower scope (the members both lenses named), because a split that parks the platform is the `B23` failure `M6-02` inverted.

**Anti-widening survives.** A review may file only members named in its own text; the decision row's before-images (`row_data NULL` for each filed ticket) are the reversal handle, so a review that over-files is one `reverse_decision()` from undone. `drain_epic_next()` property 5 (nothing creates a drain row but John) keeps its one pre-authorised exception, `0970abad`, unchanged in scope.
