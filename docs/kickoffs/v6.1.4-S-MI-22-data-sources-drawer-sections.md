## 5. TASKS

**Task 1 — `groupDataSources(rows)` pure helper (`MarketIntelligenceScreen.jsx`, near `describeDataType`)**
Input: the raw `dataSources` array (`useDataSources()`'s rows, unchanged shape). Output:
```js
{
  sourced: [...rows],                          // label === "Sourced"
  simulationByCategory: {                       // label === "Source Simulation", grouped by row.category
    [category]: [...rows]                       // insertion order = first-seen category order; rows within a
  },                                             // category preserve the hook's existing title-sort order
  analysis: [...rows]                           // label === "Analysis"
}
```
Group membership determined by calling `describeDataType(row.data_type, { isBaseline: row.is_baseline, source: row.source })` per row (same call already used for badges — do not duplicate the label logic). A category with zero rows is never present as a key (do not pre-seed known categories). Rows within each bucket keep the array order they arrive in (already title-sorted by the hook's `.order('title')` — no re-sort needed here).

**Task 2 — "Data Sources" drawer: Sourced + sub-grouped Simulation sections**
Replace the current flat `dataSources.map(...)` body with:
- `count` prop: `` `${sourced.length + simulationTotal} dataset${... === 1 ? "" : "s"} · ${sourced.length} sourced · ${simulationTotal} simulation` `` (drop the "analysis" count — Analysis is no longer part of this drawer's total).
- If `sourced.length === 0 && simulationTotal === 0`: keep the existing "No Data Room content loaded yet." empty state, unchanged.
- Otherwise render, in order:
  1. A "SOURCED (`n`)" section header (reuse the same mono/9px/uppercase/600-weight/`T.muted` convention `Drawer`'s own title row already uses — do not invent a new header style) followed by each sourced row's existing card markup, only if `sourced.length > 0`.
  2. A "SIMULATION (`n`)" section header (same convention, `n` = total simulation rows across all categories), only if `simulationTotal > 0`, followed by one sub-group per key in `simulationByCategory`, each rendered as a smaller category header (`SIMULATION_CATEGORY_LABELS[category] ?? category`, same header style, one size down or same size — coding session's call, stay consistent with the existing category-badge text style at line ~871) followed by that category's rows. Iterate `simulationByCategory`'s keys sorted alphabetically by the raw `category` string (stable, no hardcoded category list — `geo_briefing` sorts before `partner_scenario` naturally, and any future category slots in without a code change).
- Existing per-row card markup (title, badge, who-tag, category line, metadata line) is unchanged — only the grouping/headers wrapping it changes.
