## 2. CONTEXT

`AIActivityPanel.jsx` ("AI Audit," triggered from `AppShell.jsx`'s header button on desktop and its mobile hamburger-drawer "Platform → AI Audit" item, both already live) is a hardcoded `width: 650` fixed right-side panel with zero mobile treatment. On a real phone, roughly 260px of it — including the × close button and 2 of 5 header stats — sits past the visible viewport edge, reachable only by a horizontal scroll essentially no mobile user will discover. `S-MOBILE-NAV-01` (shipped, `v6.2.0`) already wires "AI Audit" into the mobile menu; tapping it today opens this same unfixed panel.

**Design session process:** three rounds of mocking against real data (not placeholder numbers) — pulled live via Supabase MCP against `ai_activity_log` (`tenant_id='global'`, most recent 500 rows, the exact window `hydrateFromSupabase()` loads) and aggregated with `useAIActivity()`'s own rules (service→pattern rollup via `AI_TYPE_TO_SERVICE`, sort order, active/inactive split). Final mock built two full renders — desktop's real 650px panel and the mobile proposal — from one shared HTML content template, to prove by construction that nothing is dropped or summarized on mobile: same 15 active + 8 inactive patterns, same 10 active + 22 uncalled services, same 2 LLMs, same 8 agents, same 7 MCP surfaces, same 8 checklist rules, all three tabs.

**Locked decisions (confirmed by John, do not re-litigate):**
1. **Layout: `STYLE-GUIDE.md` §26's Side-Panel Overlay pattern** — 82%-width drawer capped at `maxWidth: 340` (reusing `S-MOBILE-NAV-01`'s §24 drawer-width convention exactly, not a new value), **not** a full-screen takeover. John's explicit call after comparing both live in the mock. This is a deliberate departure from `S-MI-45`'s Evidence/Activity full-screen convention — §26 already establishes that side panels triggered from header/menu chrome (lower-stakes, navigational/reference content) get the drawer treatment, content-entry overlays get full-screen. `§26` names `AIActivityPanel.jsx` directly as its next candidate.
2. **Dismiss: backdrop-tap-to-dismiss added, alongside the existing ×.** Matches §26 / `AboutPanel.jsx`'s convention. **Real asymmetry, noted deliberately, not an oversight:** `AIActivityPanel.jsx` has no backdrop element on desktop today (confirmed by reading the source — unlike `AboutPanel.jsx`, which already had one pre-`SH-21`). This session adds the backdrop **only inside the `isMobile` branch** — desktop stays exactly as it is today, × only, no backdrop, zero desktop diff. This matches the same "gated by `useIsMobile()`, desktop unchanged by construction" pattern every other mobile session in this track has used (`S-MI-45`, `S-MOBILE-NAV-01`, `SH-21`) — it is not introducing a new cross-cutting desktop change.
3. **Tab bar: stays `flex:1` per tab, no horizontal scroll.** Per §26's own instruction to judge tab-bar treatment by content density rather than blanket-apply `AboutPanel.jsx`'s 7-tab horizontal-scroll fix: this panel has only 3 tabs ("Activity Log" / "MCP Roadmap" / "Architect Checklist"), which fit comfortably at 340px with `flex:1` — confirmed in the mock at real mobile width, no clipping or ellipsis. Font size drops slightly (9→8) as a safety margin, not because scroll is needed.
4. **Platform Roadmap's 2-column grid (AI Patterns | DeepBench Services) stays 2-column on mobile**, not forced to 1-column. Per §26's own guidance: "a 2-item comparison grid can stay 2-column at mobile width" — this is a 2-item grid (unlike `AboutPanel.jsx`'s 3-way Now/Next/Later roadmap, which does drop to 1-column). Confirmed legible in the mock.
5. **Header stat strip (5 stats) wraps instead of overflowing** — `flexWrap` added on mobile only, no stat dropped or summarized.
6. **All data, sections, defaults, and interaction logic are completely unchanged** — same `useAIActivity()` output, same `PATTERN_CATALOG`/`SERVICE_CATALOG`/`MCP_SURFACES`/`CHECKLIST` constants, same default open/closed section state (`pattern`/`service`/`llm`/`agent` open, `roadmap` closed), same collapse/expand behavior. This is purely a layout/sizing branch, zero content decisions.

`STYLE-GUIDE.md` §26 is already locked (by `SH-21-design`) and is the source of truth for the drawer-width/dismiss/grid rules above; this session does not modify `STYLE-GUIDE.md` — it applies an already-written rule to its already-named next candidate.
