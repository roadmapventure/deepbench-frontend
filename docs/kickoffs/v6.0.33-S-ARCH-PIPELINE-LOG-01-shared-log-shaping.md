## CONTEXT

Found 2026-07-07 during a design session UX review of a live MI screen screenshot: Column 3 Pipeline Log's `agent_selection` case rendered Michelle's PM-broker selection `reasoning` field completely raw — a multi-paragraph delegation analysis instead of a short "why this agent" line. Root cause: `describePipelineEvent()` is a 9-case switch statement, one hand-written template per event type, not a shared service — so whether a case's free text gets shaped depends entirely on that one case remembering to do it. It didn't, and the tool schema's own `maxLength: 300` on `reasoning` (`request-receivable.js:29,48`) is instructional only, not server-enforced by Anthropic — the model exceeded it and nothing caught it before display.

**Audit of all 9 cases found `agent_selection` isn't the only exposed one.** Five of nine cases embed a raw model-authored free-text field with zero shaping:
- `agent_selection` — `evt.data.reasoning` (line 90)
- `proofreader` (revise branch) — `e.critique` (line 73)
- `failure_triage` — `evt.data.suggested_research_request` (line 76)
- `patch_proposed` — `evt.data.proposed_action?.version_note` (line 82)
- `patch_resolved` — `evt.data.result?.content?.confirmation_note` (line 84)

Only `memory_consolidation` (line 80) defends itself today, with an ad hoc inline `.slice(0, 90)` — a one-off, not a shared pattern.

**Design resolved 2026-07-07 (John):** the fix is a shared, deterministic, client-side formatter — same "generic, not capability-specific" precedent as `execute.js`'s `logAgentTurn()` (a single function every capability's turn already passes through, no branching per capability). **Not** routing every agent's reasoning through a live formatting agent (Alex) for consistency — that would (a) violate the no-fixed-relationship delegation rule (`ARCHITECTURE.md` §19d — any real delegation must go through Michelle's broker, chosen by the requesting agent's own reasoning, never hardcoded to one agent), and (b) add a live LLM hop to every single pipeline-log line platform-wide, directly working against the current MI-loop-speed priority (`S-ARCH-LATENCY-FIX-01`/`AI-46`/`AA-124`).

The goal per John: the log should still read as real reasoning ("why the agent was called, what decision they made") — not a stripped-down activity code. So the shaping rule is **first sentence if one exists and fits, otherwise a hard character cap with an ellipsis** — not an arbitrary mid-word chop.

### Task 1 — `src/screens/MarketIntelligenceScreen.jsx`: add shared `shapeForLog()` helper

Add immediately above `describePipelineEvent()` (before line 61):

```js
// FEATURE: AA-125 — shared free-text shaping so every event type that embeds a raw
// model-authored string (reasoning/critique/notes) gets the same "short, readable log
// line" treatment instead of each switch case deciding independently. Prefers the
// first full sentence (reads as real reasoning, not a mid-word chop); falls back to a
// hard character cap only when no sentence boundary exists within range.
function shapeForLog(text, maxLen = 140) {
  const s = (text || "").trim();
  if (!s) return "";
  const firstSentence = s.match(/^[^.!?]*[.!?]/);
  if (firstSentence && firstSentence[0].trim().length <= maxLen) {
    return firstSentence[0].trim();
  }
  if (s.length <= maxLen) return s;
  return `${s.slice(0, maxLen).trim()}…`;
}
```
