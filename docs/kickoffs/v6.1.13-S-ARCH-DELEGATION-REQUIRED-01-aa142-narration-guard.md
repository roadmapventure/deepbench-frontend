## 1. CONTEXT

**Root-caused this design session, then measured live via a 6-run stress test across all 3 Market Intelligence seed questions (John's explicit request) — 4 of 6 runs hit this exact bug.**

`ci-answer-display-intent` (Marcus) and `hyp-hypothesis-test-display-intent` (Priya) both exist for exactly one purpose: hand the already-approved answer to a Display agent for formatting, via `request_help` → `delegate_to_agent`. Their own `method` text already says this ("You never render or show this to the user yourself"). But the harness lets the model's turn end with a plain-text response instead of a tool call whenever there's no schema tool (`hasSchemaTool: false` — true for both these intents), and `tool_choice` is `'auto'` whenever `canRequestHelp: true` (`buildCallBody()`, `request-receivable.js:75`). That combination is deliberate (`AA-97`) for capabilities that can *legitimately* answer in plain text (e.g. Priya's `hyp-stress-test-intent`), but it also lets Marcus/Priya's *always-must-delegate* intents narrate their intended hand-off in prose ("I've routed your answer to Riley...") instead of completing it — and `execute.js:217`'s `if (!turn.is_delegate_call)` branch treats that narration exactly like a real, valid final answer. No error, no distinction, no retry.

**Measured, not guessed:** 11 of 122 real turns (~9%) across these two intents ended in narration instead of delegation (Supabase `ai_activity_log`, `ai_type: 'agent-turn'`, since `AA-120`'s per-turn instrumentation shipped). The live 6-run stress test (2 runs each of the 3 seed questions, against the deployed dev URL) hit it on 4 of 6 attempts, across all 3 questions.

**Passes `ARCHITECTURE.md` §19d's sniff test — confirmed explicitly, not assumed:** this fix does not remove any agent's own reasoning. Marcus and Priya's `method` text for these two intents *already* unconditionally requires delegation — there is no legitimate "should I delegate or not" judgment call at this specific intent; delegating is the entire and only job. Marking the intent `delegation_required` and having the harness verify the required action actually happened is structurally identical to `AA-108`'s "throw a clear error when `intent_slug` doesn't match" and `AA-126` Task 2's "fail loudly on an empty final delegation" — both already-accepted "fail safe, never fake" precedents on this exact harness. It does not touch `request_help`/`delegate_to_agent`'s own candidate-selection reasoning, which stays 100% agent-judged, unchanged.

**Decision made with John, 2026-07-07, after the stress test:** do the harness guard, not a prompt-only fix alone (the measured ~9% real-world rate is too high to trust an advisory-only instruction, which `AA-120`/`AA-131` already documented is not server-enforced on Haiku) — but tighten the `method` text too, since it's free and likely reduces the retry rate. **A second, separate finding from the same stress test — `AA-143` (Owen legitimately blocking Marcus's answers on 2 of the 6 runs for uncited/hallucinated-looking specifics) is explicitly out of scope for this session, deferred to its own future session per John's direct instruction — do not fold it in.**

## 6. SCOPE RULES — what NOT to touch

- Do not change `request_help`/`delegate_to_agent`'s own candidate-selection or routing logic — this session only adds a check for whether the *required* tool call happened at all, never influences which candidate/agent gets chosen.
- Do not set `delegation_required: true` on any other Skill Profile this session — scoped to exactly the two intents this bug was found on (`ci-answer-display-intent`, `hyp-hypothesis-test-display-intent`). Any future intent that needs this same guarantee gets it by setting the same trait, in its own session.
- Do not touch `hyp-stress-test-intent` or any other `can_request_help`-with-no-schema intent that can legitimately answer in text — confirm via Supabase that no other Skill Profile has `delegation_required` set before this session's Task 1, and that Task 1's `UPDATE` only touches the two named rows.
- Do not fold in `AA-143` (Owen's legitimate guardrail blocks on 2 of 6 stress-test runs) — separate, non-bug finding, explicitly deferred to its own future session.
- Do not persist `delegationRequired` on `durable_hops` — accepted gap, matching `AA-126`'s precedent for other non-persisted loop-state fields.
- Do not touch `AA-137`'s string-fallback frontend rendering (`MarketIntelligenceScreen.jsx`) — that fallback stays correct and necessary regardless: it's what renders the `throw` case's surfaced error today would need separate handling, but the *legitimate* single-retry-then-succeed path (the common case after this fix) returns a normal, well-formed final answer that renders through the existing `qa`/`hypothesis_test` card paths, unchanged.
