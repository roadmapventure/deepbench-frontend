## CONTEXT

Found live 2026-07-20, John's own screenshot: the Agent Routing drawer now shows only "Jordan has finished." / "Alex has finished." — no information about what either agent actually did. Confirmed by direct code read: `delegation_complete` (added `LOO-009`, consumed `LOO-009b`–`LOO-011`) was only ever built to answer "who finished," never "what did they do" — its description is a hardcoded, content-free template (`${toName} has finished.`).

**This wasn't a problem in isolation — it became one because it replaced declarations that carried real content:**
- Michelle's hop used to show her real reasoning (`agent_selection`'s old `resolveData`/`evt.data.reasoning`) — removed in `LOO-009b`'s Shape-2 cleanup. **This is the one genuine content loss** — real, agent-authored text, gone.
- `display_format`/`news_fetch` (removed in `LOO-010`) were never actually rich — both were static labels ("Formatting data for display" / "Formatting the news feed for display"), not real extracted content. Their loss is a *label* loss, not a content loss — the fix for these is a real, per-service *label*, not new content extraction.
- Jordan's own credit (`LOO-011`) never had an old equivalent at all — the pre-`LOO-009` system never credited him; his old hop was a permanently-stuck live placeholder, not real content either.

**The fix, precisely — restore what was actually lost, for each of the three cases, all still fully generic (no capability-specific branches, only field-presence checks on already-available data):**
1. Michelle's broker-leg credit: attach her real `reasoning` (already computed at that exact line, just never attached to this event) — exact restoration of the old text.
2. Any final target's credit (Alex, or any future target): attach a real per-service *label*, reusing `SERVICE_CATALOG`'s existing `name` field (already platform-wide, data-driven, the same lookup pattern `PATTERN_NAME` already uses two lines below the import) — not new content extraction, a real label instead of a bare "has finished."
3. The originating agent's own credit (Jordan's case, `LOO-011`): attach the task description that agent itself wrote for its target (`tool_input.task`, already available at that line) — more informative than the old system had, since the old system never credited this agent at all.
