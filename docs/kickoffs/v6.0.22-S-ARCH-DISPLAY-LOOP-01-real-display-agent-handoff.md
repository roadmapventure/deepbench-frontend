## 2. CONTEXT

**The bug that started this:** a live screenshot review (this design session) showed Marcus's Q&A answer rendering as raw, unparsed markdown (`##`, `**bold**`, `|tables|` printed literally as characters). Root cause: `MessageBubble` does plain `{msg.text}` interpolation, and `ci-answer-intent` has no Format Skill constraining Marcus's output shape. By contrast, Priya's Stress Test looks clean only because `intelligence-review-format` (`AA-77`) already constrains her output to plain-prose fields — not because anything renders markdown.

**The architecture question this raised, and its answer (full reasoning in this conversation's transcript):** `MarketIntelligenceScreen.jsx`'s existing Stress Test call hardcodes `display_agent_id: "alex"` as a literal string — a direct violation of `AR-4.3` ("resolved the same way as any other capability, never hardcoded to one name"). The fix is not to make Marcus *decide whether* to seek a formatter (formatting a human-facing answer is never optional — per `AR-4.3` — so making that a live decision would manufacture a fake decision, the same anti-pattern `AA-98` already rejected in the opposite direction for Elena's unconditional invocation). The real decision is *which* Display agent (Alex/Riley/Claire), and per `AR-2.3`'s reasoning (rejecting a `resolveCapabilityHolder()`-style shortcut for exactly this class of multi-holder resource), that must go through a real `request_help` → Michelle (`agent-selection-intent`) → `delegate_to_agent` round trip — this platform's existing Agent Loop mechanism, already built and running elsewhere (Owen's retry, Nadia's Escalate), just never yet used for Display-agent selection. That gap is `AA-101`, open since 2026-07-03.

**Scope decision (John, this design session):** build the mechanism generically once, prove it live via Marcus's Q&A path (since that's the bug we're fixing anyway). Do **not** migrate Stress Test's existing bundled `intelligence-review-format` call in this session — that's `AA-116`, a deliberate fast-follow, logged separately, because its output is already correctly shaped (a legitimacy fix, not a visible bug).

**Mechanism-ordering decision (this design session):** formatting happens **after** the Proofreader gate/retry sequence resolves, not inside Marcus's own `ci-answer-intent` call. This preserves Owen's existing evaluation semantics completely unchanged (he still evaluates Marcus's raw draft text, exactly as today) and avoids re-deriving `gate`'s `candidate_answer` input shape. Concretely: `runQaWithQualityGate()`'s existing `finalAnswer` (already computed today, whichever of `qa` or `gate.final_answer` won) becomes the input to one new, final display-request step.

**The new mechanism, precisely:**
1. A new Marcus intent, `ci-answer-display-intent` (channel-intelligence capability), receives the approved answer as `task_context`. It has **no schema of its own** — its only behavior is to call `request_help` (never render the answer itself), then, once handed a candidate, call `delegate_to_agent` with a new `is_final: true` flag.
2. `request_help` resolves exactly as it already does platform-wide: to whoever holds `project-manager` (Michelle), who runs `agent-selection-intent` over the real roster (already surfacing real capability descriptions + real intent slugs per `AA-108`) and returns ranked Display-agent candidates.
3. Marcus's next turn calls `delegate_to_agent` targeting whichever candidate ranked highest, with `is_final: true` — a new, generic harness-level flag (Task 1) meaning "this delegation completes my task; return the delegate's own output as the final result, attributed to them," as opposed to the existing default behavior (Owen's retry) where the delegate's result feeds back for the delegator to keep working.
4. The dispatched delegate call is a new Alex intent, `qa-answer-format` (screen-controls capability) — a real, standalone capability call (not a bundled schema), producing the structured, screen-ready shape.

This produces a genuine second `ai_activity_log` row for whichever Display agent gets chosen — unlike `AA-77`'s bundled pattern (zero separate row, credited via `display_agent_card` only), this is real agent-to-agent delegation, a real hop against `MAX_LOOP_DEPTH`.
