## 2. CONTEXT

The News drawer on Channel Sales Intelligence renders three cards that all read
`<UNKNOWN>` — every field: headline, snippet, source, url. `published_at` is `null`.

**Root cause, measured live 2026-07-29 (not inferred):**

Jordan Ellsworth — Web Search Expert really does run his web search. His turn pulled
**49,770 input tokens** of search results (`ai_activity_log` id `25575`, trace
`8fdb2a46-3b2e-44a9-ae61-fdadf32520e6`). Alex Reeves — Screen Controls Editor's turn in the
same trace received **1,223** (id `25580`). The stories exist; they never reach him.

Why: `ws-news-search-intent` carries `traits.delegation_required: true`. When Jordan calls
`request_help`, `execute.js`'s `dispatchDelegation()` takes the `delegationRequired` branch
(~L678) and **auto-dispatches straight to the agent Michelle Manning — Project Manager picked**,
building the delegate's envelope at ~L696 as:

```js
{ ...task_context, delegation_task: tool_input.task_description || tool_input.skill_needed }
```

Jordan's `task_context` is `{}` (the screen passes nothing), and `task_description` is his
*description of the job*, not the stories. He never gets a turn to call `delegate_to_agent`
— confirmed by `call_facts.tool_calls` on his row: `["request_help", "web_search"]`, no
`delegate_to_agent`. The line in his own `method` telling him to pass the stories via
`delegate_to_agent` is unreachable on this path.

Alex, given a job description and a schema whose fields are all `required`, fills them with
`<UNKNOWN>`.

**Alex is not the defect.** Proven by isolation: calling `screen-controls`/`news-cards-format`
directly with three real stories in `task_context.delegation_task` returned three flawless
cards — every field correct, 1.5 s, `guardrails_passed: true`. His Skill needs no change.

**Why this is the only capability that breaks.** There are exactly three
`delegation_required` intents platform-wide. The other two — `ci-answer-display-intent` and
`hyp-hypothesis-test-display-intent` — are *display requests*: the screen puts the content in
`task_context` **before the call starts**, so the `{...task_context}` spread carries it to the
delegate for free. (Marcus Webb — GEO CSO Expert's display request is likewise instructed to
call `delegate_to_agent` and likewise never reaches it — it simply doesn't matter for him.)
Jordan is the only one that *produces* what it hands off, inside the same call that hands off.

**The fix is to make his flow look like theirs**: one call that searches and returns stories,
then a second call that requests display with those stories already in the envelope. No
harness change, no new content channel — the mechanism that already works, used as intended.

**Record correction this session owes:** `docs/BETA.md` bucket 1 row 1 states `LOO-013` was
"verified live 5/5 (`jordan → michelle → michelle → alex`, **3 cards**, no errors)" and that
"case 24 specifically is no longer the known-bad one." The routing fix was real, but that QA
counted cards without reading them — all three were `<UNKNOWN>` then as they are now. Case 24
is still a known-bad case until this ships.

## 5. TASKS (4)

### Task 1 — Supabase: make `ws-news-search-intent` search-only

`UPDATE skill_profiles WHERE slug = 'ws-news-search-intent'`:

- **`traits`** — set to exactly:
  ```json
  { "schema": <the Section 4 schema>, "max_results": 3, "allowed_domains": [], "enable_web_search": true }
  ```
  **`delegation_required` and `can_request_help` are removed.** `enable_web_search`,
  `max_results`, `allowed_domains` are preserved at their current values.
  Adding `traits.schema` is sufficient to make this a structured JSON call —
  `db-assembly.js:161` builds the `format_contract` (`output_type: "json"`,
  `handler: traits.handler || "store"`) from the presence of `traits.schema` alone.
  `ci-answer-intent` is the live precedent: schema, no `handler`, no `output_type`.

- **`objective`** — replace with:
  > Find exactly 3 current, distinct news stories relevant to Apple's channel/carrier program or a direct competitor's channel/carrier program, and return them as structured data.

- **`method`** — replace with:
  > Use your web_search tool to find candidate stories. Favor the last 24-72 hours. Return exactly 3 distinct, credible stories. For each one give the headline as reported (not rewritten), a 1-2 sentence plain summary of what happened and why it matters to Apple's channel program or a competitor's, the publication name, the article URL, and the publication date if you know it. Return the stories themselves as structured output -- you are not formatting them for display, and you are not handing them to anyone.

- **`llm_model`** — unchanged (`claude-haiku-4-5-20251001`).

> You have 3 completed news stories ready for the user (provided in task_context: stories, each carrying headline, snippet, source, url, and published_at). You never render or show these to the user yourself -- that is not your job. Call request_help, describing that you need a Display agent to format a set of news stories into structured on-screen news cards. Once given ranked candidates, call delegate_to_agent, targeting whichever candidate best fits structured on-screen cards (not a full HTML document, not a PDF). A Format Skill only restructures presentation -- it never changes the headlines, summaries, sources, urls, or dates you hand it, and never adds or drops a story. Set is_final true if you are confident nothing further is required of you once formatting completes; set it false if you would need to review or act on what comes back before your own task is actually done. Keep every reasoning field to 1-2 concise sentences -- this is a routing decision, not an analysis; do not restate the candidate list or write a multi-paragraph justification. Never end your turn with a text description of what you are going to do or have done -- you must actually call request_help, then delegate_to_agent, to complete this hand-off. A prose summary of your intended hand-off (e.g. "I have routed this to X, they will format it shortly") is not an acceptable substitute for actually calling the tool -- if you do this, the platform will detect it and ask you to try again.

### Task 3 — `MarketIntelligenceScreen.jsx`: `fetchNewsCards()` makes two calls

Replace the single `callCapability` inside the `try` block of `fetchNewsCards()`
(~L3766) with two sequential calls. Everything else in the function — the
`setNewsCardsStartedAt`, `myGeneration`/`isStale` guard, the `CHI-75`
`chatTurnActiveRef` ownership guards, and the whole `catch` block — is unchanged.

```js
      // FEATURE: CHI-92 — Jordan searches first and returns structured stories; a second
      // call is his display request, with those stories already in task_context. This is the
      // same two-step shape ci-answer-display-intent uses (runQaWithQualityGate above): the
      // harness's delegationRequired auto-dispatch spreads task_context into the delegate's
      // envelope, so content reaches Alex the way it already reaches him for a Q&A answer.
      // Before this split, search and hand-off shared one call, so the stories Jordan found
      // existed only in his own turn and the delegate received the help-request text alone.
      const search = await callCapability({
        capability_slug: "web-search-news", intent_slug: "ws-news-search-intent", agent_id: "jordan",
        task_context: {}, onProgress: onDelegationProgress, isStale,
      });
      if (isStale()) return;
      const stories = Array.isArray(search?.stories) ? search.stories : [];
      if (!stories.length) { setNewsCards([]); if (!chatTurnActiveRef.current) setWorkingStatus(null); return; }
      const result = await callCapability({
        capability_slug: "web-search-news", intent_slug: "ws-news-display-intent", agent_id: "jordan",
        task_context: { stories }, onProgress: onDelegationProgress, isStale,
      });
      if (isStale()) return;
      setNewsCards(Array.isArray(result?.cards) ? result.cards : []);
```

Add the version-header comment at the top of the file, above the existing `v6.3.150` line:

```js
// DeepBench v6.3.227 | MarketIntelligenceScreen.jsx | CHI-92 -- fetchNewsCards() splits into Jordan's search call + his display request, so the stories he finds ride task_context to the display agent instead of dying in his own turn
```

**Empty-search guard:** a zero-story search returns early to the existing empty-state
sentence rather than making a display request with nothing to display — same fail-open
behaviour the `catch` block already has, no new UI state.
