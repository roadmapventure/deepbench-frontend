## 2. CONTEXT

Desktop's `InteractColumn` renders `AgentWorkingIndicator` (the only elapsed-timer/working-status signal) *inside* the scrollable message list (`scrollRef`, L1613; indicator embed at L1656). There is no auto-scroll, so once a few messages exist, a new status update or reply lands off-screen at the bottom — no visible sign of work happening unless the user manually scrolls down. Mobile hit the identical "30s dead air" bug and `MI-51` fixed it there by promoting the indicator to a permanent strip *outside* the scroll area (`MobileBody`, L1811-1815). That fix only touched the mobile branch; desktop's `InteractColumn` never got an equivalent.

Desktop's 3-column grid (`Interact`/`Evidence`/`Audit`, L2223) renders all three columns simultaneously — unlike mobile's tabbed layout, which hides whole columns. So Column 1 (chat) is always on-screen; the actual gap is just that it can be scrolled to a stale position, plus (per John's explicit ask, confirmed in this design session's walkthrough) someone watching Column 2 (`EvidenceColumn`) during a hypothesis flow has no progress signal there at all.

Design session walkthrough with John (2026-07-14) confirmed the fix before this kickoff was written — **two tasks, both approved:**
1. Auto-scroll `InteractColumn`'s message list to bottom on new message/`workingStatus` change, reusing the exact `el.scrollTop = el.scrollHeight` + "don't yank the user back down if they've scrolled up to read history" pattern already live in `FetchContext.jsx` for the Agent Fetch feed (not a new mechanism).
2. Thread `workingStatus` into desktop's `EvidenceColumn` call and render the existing `AgentWorkingIndicator` component (same component, unmodified) near the top of both `EvidenceColumn` states, so someone watching Evidence also sees the elapsed-timer without looking at chat.

Because `scrollRef`/the message list JSX is shared between `InteractColumn`'s bare (mobile) and non-bare (desktop) branches, Task 1's fix applies to both by construction — mobile's Chat tab picks up working auto-scroll it doesn't have today as a beneficial side effect, not new scope.

### Task 1 — Auto-scroll `InteractColumn`'s message list

In `InteractColumn` (currently starting L1609), immediately after `const scrollRef = useRef(null);` (L1613), add:

```jsx
  // FEATURE: MI-64 — tracks whether the user has manually scrolled away from the bottom, same
  // pattern as FetchContext.jsx's fetchUserScrolledRef/scrollToLatest (Agent Fetch feed) — auto-scroll
  // below respects this so a user reading earlier history isn't yanked back down.
  const userScrolledRef = useRef(false);

  const handleScroll = () => {
    const el = scrollRef.current;
    if (!el) return;
    const atBottom = el.scrollHeight - el.scrollTop - el.clientHeight < 40;
    userScrolledRef.current = !atBottom;
  };

  useEffect(() => {
    const el = scrollRef.current;
    if (!el || userScrolledRef.current) return;
    el.scrollTop = el.scrollHeight;
  }, [messages, workingStatus]);
```

`useRef`/`useEffect` are already imported (L151) — no new imports needed.
