## 2. CONTEXT

### What's wrong today

`logAgentTurn()` (`execute.js:206`) receives **three booleans and a declared list**, and turns them straight into frozen pattern names at `:216-220`:

```js
patternsUsed: Array.from(new Set([
  ...(is_delegate_call ? ['agent-delegation'] : []),
  ...(usedWebSearch ? ['tool-use'] : []),
  ...intent_technical_services,
])),
```

Three separate defects in five lines:

1. **`is_delegate_call` → `'agent-delegation'`** — the boolean is true for the harness-generic delegation tools, but *which* tool fired is discarded. `LOG-44` is open precisely because nobody can tell from the log whether these 2,796 calls were handoff, routing, or orchestration. **The answer was in scope at the call site and thrown away.**
2. **`usedWebSearch` → `'tool-use'`** — same string `request-receivable.js` writes for a JSON schema call. This is `LOG-46`'s conflation, reproduced at a second write site.
3. **`...intent_technical_services`** — a **declared** list spread from a Skill Profile onto every call of that intent, with no runtime check the call did any of it. This is the exact untrustworthy-declaration mechanism §19i's archived Four-Source Trust Model was written to kill, still live at this call site. **Do not remove it in this session** (that's a behavior change to `patterns_used`, out of scope) — but capture the real facts alongside it so Layer B can eventually ignore it.

### What's already in scope at the call site — verified this session

`logAgentTurn()` has **exactly one caller**, `execute.js:659`. At that point `turn.tool_name` is live and real — the same field the code already reads directly at `:781`, `:782`, `:788`, and `:794` to decide delegation routing. **The real tool name is sitting one property away from a log write that records a boolean instead.**

`depth` is also already a parameter (`:211` builds it into `feature`). It is the natural seed for `sub_calls_chained[]` — **but that fact belongs to `LOG-49`, not here.** Do not add it.

## 5. TASKS

### Task 1 — `logAgentTurn()` accepts real tool names

Add a `tool_calls = []` parameter to `logAgentTurn()`'s destructured signature (`execute.js:206`). Build and pass `callFacts` to the existing `logActivity()` call:

```js

```

**Leave `patternsUsed` at `:216-220` byte-identical.** `is_delegate_call`, `usedWebSearch`, and `intent_technical_services` all keep working exactly as today. This task is purely additive — a row gains `call_facts`, it does not lose or change `patterns_used`.

### Task 2 — Pass the real tool name from the call site

At `execute.js:659`, pass the real tool name alongside the existing booleans:

```js
tool_calls: turn.tool_name ? [turn.tool_name] : [],
```

Do **not** derive, translate, or normalize the name — write what the harness actually called. `'delegate_to_agent'` and `'request_help'` are different facts and must stay distinguishable; collapsing them is the bug `LOG-44` exists to fix.

If `usedWebSearch` is true, append `'web_search'` to the same array so a web-search turn is distinguishable from a schema turn (`LOG-46`'s conflation, closed at this site).
