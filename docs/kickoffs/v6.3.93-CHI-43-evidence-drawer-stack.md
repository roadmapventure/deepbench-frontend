## CONTEXT

Second of the `CHI-42`–`CHI-46` cluster (`design-evidence-drawers-0721`, John, 2026-07-21) — the root mechanism `CHI-44`/`45`/`46` all build on. `CHI-42` (chat narrates user actions) already shipped independently, v6.3.90.

**The problem:** `EvidenceColumn`'s populated state renders `qaEvidence` (the `QaEvidenceCard`) and `hypFlow` (the submitted-theory block + stage-driven content) as one continuous flat scroll (L1785–1936 today) — everything stacks, nothing collapses, so a new arrival (a theory result landing, for instance) lands below whatever's already there with no signal to look down.

**The fix, confirmed live with John — restyle only, not a data-model change:** Evidence becomes exactly 2 `Drawer` cards (the existing shared component, `SharedUI.jsx`, already used 5 other places on this screen) — one for `qaEvidence`, one for `hypFlow`. Whichever is "currently in play" auto-opens and the column auto-scrolls to it; the other auto-collapses to its titled header, still one click to reopen. **Explicitly NOT in scope:** the deeper fix where a 2nd question/theory currently overwrites the 1st in Evidence entirely (`setQaEvidence`/`setHypFlow` are single-slot overwrites) — that's `CHI-47`, a separate future kickoff, John's explicit call to split it out. This session's 2 drawers still only ever represent "the current answer" and "the current theory flow," same as today — just presented better while they're active.

**Confirmed live with John, walked through on his own Apple-financing example:**
1. Ask a question → Analysis drawer opens (only thing there).
2. Click "deeper theories" → Analysis drawer collapses to its header; Theory drawer opens, column scrolls to it.
3. Select a theory, test it, get a result — same Theory drawer, stays open throughout (one continuous piece of work, not separate arrivals) — but the column re-scrolls to bottom on each of these stage transitions (generating→choosing→ready→testing→result) since new content lands each time.
4. Resolve it (Info Only / Store as Forecast) → Theory drawer disappears (`hypFlow` → `null`, unchanged from today); Analysis drawer — still holding the original answer — reopens automatically since it's the only thing left.

**Mechanical note on why `Drawer` can't just wrap `QaEvidenceCard` as-is:** `Drawer` always renders its own header row (title + optional count + chevron), regardless of open/closed state. `QaEvidenceCard` already has its own rich header ("Analysis & Narrative — based on your question..." + a `HopBadge`, L1530–1535). Wrapping the card whole would produce two stacked headers. Task 3 below removes `QaEvidenceCard`'s own header row — its title text becomes `Drawer`'s `title`, and its `HopBadge` moves to the top of the card's own (now-headerless) body, same visual weight, one level lower. This is a structural necessity of avoiding the duplicate header, **not** `CHI-45`'s later "hop badge into collapsed metadata" relocation — that's still a separate, not-yet-built future session; this session's `HopBadge` stays visible whenever the drawer is open, same as today, just repositioned.

Change to:
```jsx
export const Drawer = ({ title, count, children, defaultOpen = false, maxHeight, resizable = false, onOpen = undefined, open: controlledOpen = undefined, onToggle = undefined }) => {
  const [internalOpen, setInternalOpen] = useState(defaultOpen);
  const isControlled = controlledOpen !== undefined;
  const open = isControlled ? controlledOpen : internalOpen;
  const [dragHeight, setDragHeight] = useState(null);
  const contentRef = useRef(null);

  const toggle = () => {
    const willOpen = !open;
    if (willOpen && onOpen) onOpen();
    if (isControlled) { if (onToggle) onToggle(willOpen); }
    else { setInternalOpen(willOpen); }
  };
```

Every other reference to `open`/`setOpen` in the rest of the component (the render's `{open && (...)}`, the drag handler's `effectiveHeight` calc) is unchanged — `open` is still the same name, now just computed instead of raw state. `isControlled`/`internalOpen` are new local names only; no existing call site (6 uncontrolled `<Drawer>` usages elsewhere in the codebase) passes `open`/`onToggle`, so `controlledOpen === undefined` for all of them and behavior is byte-identical to before.

// --- Category A/B: computeAutoCurrent across all 3 real states ---
{
  assert(computeAutoCurrent(null, null) === null, "neither qaEvidence nor hypFlow: autoCurrent is null (true empty state)");
