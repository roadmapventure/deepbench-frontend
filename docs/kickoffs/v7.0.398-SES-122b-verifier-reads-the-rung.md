## 2. CONTEXT

**Two hardcoded facts and one environment defect, all measured.**

1. `autoDoneEligibility()` grants the bar only to `Selfbuild` epics and, unless the Prime Directive widens it, only to `P10 - Tooling`. The M6 gate ruled the bar ladder-driven: *any class whose rung ≥ `runner_settings.auto_done_rung`* — read from `class_autonomy()`, never from argv. The epic-family restriction is charter decision 2's; the gate's ruling replaces it for classes that have earned the rung (`tooling` sits at rung 13; `bug_fix` at 1), so a `P9 - Bug Fixes` ship on a non-Selfbuild epic stays `delivered` until that class earns rung 3, and a `P10` ship anywhere auto-dones. Fail-closed defaults stay: no class row, no rung read, no credentials → not eligible.
2. `runGate()` spawns with `shell: true` on Windows and passes `process.execPath` unquoted. On John's machine that is `C:\Program Files\nodejs\node.exe`, so the regression and hygiene gates exit 1 with `'C:\Program' is not recognized` and every attended verifier run is a false `block` — measured on `SES-301`'s verdict `253aca14` (build green, the two node-spawned gates red on that message). The cloud runner (Linux) never saw it, which is why it survived. `SES-311`'s attended verifier step cannot exist until this is fixed.
3. `SELF_CERTIFYING_PATHS` will refuse this ship its own bar — correct, and expected; the design session writes `done` after its own QA.
