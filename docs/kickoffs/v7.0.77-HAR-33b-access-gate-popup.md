## 1. CONTEXT

Part a refuses gated API calls with HTTP 403 and body `{ deepbench_gate: true, reason, ip, stats? }`. Today that surfaces as whatever each screen does with a failed fetch. This session gives it one global, John-approved face: a modal in the Treasury design system. Rules from the design session (John, verbatim decisions 2026-08-08):

- Blocked visitors can keep browsing; the popup appears on every refused model call and is freely dismissible (✕ and a "Keep browsing" text affordance). No other session state changes.
- **No email button and no email address anywhere** — true users know how to reach John (his explicit call; do not "improve" this).
- Positive, light tone. Two variants by `reason`:
  - `spend_cap` — heading **"Thank you for testing DeepBench while in private beta."**, badge "Superuser" (brass), body line **"You are a superuser! Here is what you have put the agents through:"**, then three stat tiles — "LLM calls" `stats.llm_calls`, "Tokens" `stats.total_tokens` (toLocaleString), "Usage" `$` + `stats.cost_usd.toFixed(2)` — then **"If you need more access, email John with your IP address:"** followed by the IP in a mono chip. Per HAR-33a PATCH-1, every `spend_cap` refusal carries `stats`; the one documented edge (the gate's stats RPC failed mid-refusal) omits it — in that rare case render the variant without the tiles row, everything else unchanged. Never render `0`/`NaN` tiles from a missing `stats`.
  - `geo` and `manual` — badge "Private beta" (moss), heading **"DeepBench is in private beta."**, body **"Contact John and let him know your IP address:"** + IP chip + **"for access."**
- John approved a rendered mock of both variants this session; match it: card `T.card` on `rgba(11,25,41,0.45)` overlay, `T.line` border, radius 10, Fraunces heading in `T.navy` 21px/600, Inter body `T.ink` 14px, stat tiles `T.cardAlt` with `T.muted` 11px labels and Fraunces 20px values (`T.navy`; Usage value `T.brassDeep`), badges as bordered pills (brass wash `rgba(182,135,58,0.14)`/`T.brass` border/`T.brassDeep` text; moss `rgba(90,117,56,0.12)`/`T.moss`). Import every value from `src/tokens.js` — zero literal hex in the component (`.claude/rules/design-tokens.md`).

## 4. TASKS (3)

### Task 1 — `src/lib/gate-intercept.js` (NEW)

A module that (a) wraps `window.fetch` once at import time: for responses with `status === 403` whose URL contains `/api/`, it clones and parses the body; if `deepbench_gate === true` it forwards `{ reason, ip, stats }` to registered listeners, then returns the original response unchanged (screens keep their existing error handling — do not swallow or alter the response); (b) exports `subscribeGate(fn)` returning an unsubscribe. Parse failures and non-JSON bodies are silently ignored (never throw inside the wrapper). Guard against double-wrapping (idempotent import).

### Task 2 — `src/components/AccessGateModal.jsx` (NEW)

Renders the two variants per CONTEXT from the event payload; uses `hModalFadeIn`/`hModalPopIn` keyframes already in `GLOBAL_CSS` (no new keyframes); ✕ top-right and "Keep browsing" (muted text button) both close it; Escape closes; re-fires on each new gate event. No portal library — plain fixed-position JSX like `PromptEvolutionModal.jsx` (read it for the established modal idiom and match it).

### Task 3 — Mount

In `src/AppShell.jsx`: import `gate-intercept` (side effect) and render `<AccessGateModal />` once at shell level, subscribing via `subscribeGate`. Nothing per-screen.
