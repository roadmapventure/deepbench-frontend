## 2. CONTEXT

**What this is, plainly.** The gold table `pattern_vocabulary` holds Susan Smith — Trainer's approved, industry-recognized AI patterns (name + definition + citation). 23 rows. The Displayer view (Session B, `LOG-38`) will name each log row by matching the row's captured **signature** against each gold pattern's **`criteria`**. Today only **1 of 23** rows (`self-consistency`) has `criteria` — the other 22 were promoted before the `criteria` mechanism existed (`LOG-66`). This session authors the missing `criteria` so the Displayer has something to match. Without it, Session B's view returns "unclassified" for every row.

**The model (locked this session, live with John — do not deviate):**

> **industry definition → criteria → (match) → logs.** One-way.

- `criteria` is authored **from the pattern's cited industry definition**, encoded into the signature-field vocabulary. It is **never** reverse-engineered from what log rows happen to contain — that would be the deterministic `buildPatternsUsed`/`PATTERN_CATALOG` labeling this whole model exists to kill. If the log shapes the criteria, the log is choosing the name. Forbidden.
- The **only** actor who authors `criteria` is **Susan (the Pattern Definer)** — the semantic act happens once, at definition. No `criteria` value is ever hand-written by a human or hardcoded in any file.
- Susan is grounded in exactly two things: **(a)** the industry definition + a real web-searched citation, and **(b)** the defined signature-field value vocabulary (§19k, task 3 below). **She is not shown log rows.**
- Logs are touched only at **read time** (the Displayer) and by us for **QA verification** ("does this definition-derived criterion in fact match the right real rows?") — never as a source for authoring.

**Why `criteria` is not the `description` field.** They are two independent expressions of the same pattern: `description` is prose for humans ("RAG: retrieve relevant content, then generate grounded on it"); `criteria` is a machine fingerprint in the signature vocabulary (`{ "retrieval_method": { "in": ["similarity-search","mixed"] } }`). There is no text-to-criteria translation — producing `criteria` means mapping the definition's *defining behavior* onto the signature fields that express it.

**Scope of the authoring = expressibility, not occurrence** (settled live with John, verified against Supabase project `rallojeqnkgtxgsdsnqm` this session):
- Author `criteria` for **every** pattern whose defining behavior maps to one of the 15 signature fields — whether or not any current log row exhibits it.
- This **includes dormant patterns** whose defining fact is one of the three `LOG-49` facts not yet captured (`sub_calls_chained` → Prompt Chaining / ReAct; `input_references_other_deliverable` → Reflection / Multi-Agent Debate / Case-Based Reasoning; `self_reported_claims` → Self-Verification via Claim Questions). Verified live: these three fields are populated on **0 of 530** captured rows today. Their criteria are valid now, match 0 rows now, and **auto-activate with zero rework** when the concurrent `LOG-49` session lands. `SIGNATURE_FIELDS` already includes all three, so they pass `validateCriteria()`.
- Susan **discards or defers** only patterns with **no signature field at all** (e.g. Token Streaming, Few-Shot Prompting — not in the 15-field model). Her call, per definition — not a pre-decided list. Those honestly remain unclassified (the future "requiring re-classification" bucket).

## 4. STUB DEFINITIONS

**The `amend` decision** (new, 4th branch of `reviewCandidate()`), semantics: *write validated `criteria` (and its grounding citation) onto an already-promoted gold row, identified by `matched_existing_slug`.*

Required inputs when `decision === 'amend'`:
- `matched_existing_slug` (string) — the `pattern_vocabulary.pattern_slug` to amend.
- `criteria` (object) — passes `validateCriteria()` (same allowlist + 3-operator grammar as promote).
- `citation` (string) — the source grounding the definition this criteria encodes. **Required**, mirroring the promote citation gate: every `criteria` write must be traceable to a cited definition. The `amend` writes `criteria` **and** `citation` onto the row (they stay coupled — the citation reflects the source that grounds the current criteria).

Effect:
- `PATCH pattern_vocabulary?pattern_slug=eq.<matched_existing_slug>` setting `{ criteria, citation }`, `Prefer: return=representation`. Throw if 0 rows returned (no such slug to amend).
- `PATCH pattern_candidates?id=eq.<candidate_id>` setting `status='amended'`, `reviewed_by='susan'`, `resolved_at=now()`, `resolution` (the full decision payload, same shape as the other branches).
- Return `{ success: true, decision:'amend', vocabulary_entry, candidate }`.

Deliberately **not** built: rename / retire / `superseded_by` (that is `LOG-51`, a different decision with different governance). `amend` only writes `criteria` + `citation` onto an entry that keeps its identity.
