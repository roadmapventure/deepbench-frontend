## Premise, revalidated live this cycle (not recalled)

`SES-180`'s own ship notes (`v7.0.219`) list three things still owed, and name the first as the
runner's:

> (1) The skip-vs-fail distinction … a test declares "I cannot run here" and the harness counts it
> as skipped, never as passed and never as failed. It must be DECLARED by the test, never guessed
> by the harness — a harness that infers skips will swallow real failures.

Read live 2026-08-24, this cycle, in this clone:

- `tests/regression/run-all.js` has **no skip concept at all**. Its loop has exactly two outcomes:
  the module's default export resolves → `[PASS]`, or it throws → `[FAIL]`. There is no third.
- **Five** tests already detect the environment gap and print a `SKIPPED` line before returning —
  `AGT-44`, `CHI-31`, `DAT-003`, `DAT-11`, `DAT-12`. Their declaration is a `console.log` the
  harness cannot see, so all five are counted **PASS**.
- `SES-92` (`v7.0.221`) moved `CHI-31` from the FAIL side to that same silent-PASS side. That was
  the right direction — a gap is not a regression — but it landed the suite on the *other* error.

So the live state is worse than "no distinction": without credentials the suite prints
**`50/50 passed`** and exits 0 while five of those fifty ran only part of themselves. CI has run
five times (runs 1–5, all `success`); every one of them reported 50/50 on a partial run. That
number is what `SES-180` says it cannot yet gate on, and it is why the regression job ships
`continue-on-error`.

**Premise holds.** Nothing between filing and now has closed it.

## The correction, and the one thing an editor will be tempted to change

The obvious build is a boolean: `skip()` marks the *test* skipped, `[SKIP]`, `48/50 passed,
2 skipped`. **That is wrong on this suite and would ship a second lie.** Measured: all five of
these tests skip a **half**, not themselves — `CHI-31`'s comment says so in as many words ("THE
SKIP MUST STAY EXACTLY HERE — below every source-parsed assertion and above the first credentialed
one"), and its `describeDataType()` assertions really do run and really do pass. Calling the whole
test "skipped" would discard a genuine pass; calling it "passed" discards the gap. The honest unit
is therefore **the part, not the test**:

```
[PASS] CHI-31-source-simulation-consistency.js
       [NOT RUN] Skill Profile half — no SUPABASE_URL / SUPABASE_SERVICE_KEY in env
```

and a summary that cannot be misread as a full run.

**Declared, never inferred.** `notRun()` is a call the test makes. The harness never parses output,
never sniffs `process.env`, and never decides on a test's behalf — that is the property `SES-180`'s
header asks for, and the reason a string-matching harness (which could have shipped without
touching a single test file) is rejected here.

**Exit code is deliberately unchanged.** `exit 1` iff something FAILED. A not-run part is
information, not a failure — making it red would paint CI permanently red without credentials,
which is the exact failure `SES-180` shipped `continue-on-error` to avoid. What changes is that
the log now *says* the run was partial, which is what a later cycle needs before it can honestly
promote that job to blocking.

## QA — discriminating, one variable

The test is: *would it still pass if the change did nothing?*

- **Control:** the suite on this clone with no credentials **before** the change prints
  `50/50 passed` and nothing else. After the change it must print `50/50 passed` **and** name
  `CHI-31`'s not-run half. Same pass count, different truth — a build that only renamed things
  cannot produce that difference.
- **Fixture arm (`--dir`):** three throwaway modules — one that declares a not-run part and
  passes, one that passes clean, one that throws — must render `[PASS] + [NOT RUN]`, `[PASS]`,
  `[FAIL]`, exit **1**, and the not-run count must be **1**, not 2 (proving the drain does not
  leak the declaration into the next module).
- **Leak arm:** a module that declares a part and then *throws* must be `[FAIL]` with its
  declaration still attributed to it and **not** to the module after it.
- **Credentialed arm:** with real credentials, `CHI-31` must run its Skill Profile half and
  declare nothing — a not-run line that appears when the environment is complete is a bug.

Fixtures live in the scratchpad, never in the repo, and are deleted after.
