use: a `console.log` naming **what went unverified** and **how to include it**, then `return`. The

**Deliberately NOT in scope, though the sibling does it:** `DAT-11` also accepts
`VITE_SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` as fallbacks. Adding those here is a second,
unrelated behaviour change to a test this ticket asks only to make honest. `FAIL` stays reserved for
an actual content mismatch — a real missing CHI-31 clause in either Skill Profile's method text —
which is the whole point of the fix.

## QA plan — the negative control is the point

A skip that swallows real failures is strictly worse than the bug. So:

1. **Without credentials:** the suite must report **50/50** with `CHI-31` printing its skip line —
   where before the change it reported 49/50 with `CHI-31` the sole `FAIL`. Both halves measured in
   the same clone, minutes apart.
2. **With credentials:** the suite must still report **50/50** and `CHI-31` must genuinely run its
   Skill Profile assertions — not skip past them because the fix leaked into the credentialed path.
3. **The discriminating control — would it still pass if the change did nothing?** With credentials
   present, break one asserted clause and confirm the test **still FAILS**. A skip written one line
   too high converts every real mismatch into a silent pass, which is the exact failure mode
   `SES-180`'s note warns about, and nothing else in this QA would catch it.
4. `npm run build` green.
