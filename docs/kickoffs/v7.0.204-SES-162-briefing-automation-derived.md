## The three decisions worth knowing

**`nextFireChicago` walks a wall clock; it does not do offset arithmetic.** Since `SES-151`
(`v7.0.196`) the grid is an America/Chicago **hour divisible by `interval_hours`** — 12/3/6/9 on
John's clock, DST-proof by construction. The obvious implementation takes the next **UTC** hour
divisible by the interval, and that is **right for exactly half the year**: at the CST offset of 6
it agrees, and at the CDT offset of 5 it lands an hour off the grid. That is the drift `SES-151`
killed at the gate, and it must not come back in the render. Both halves are asserted (below), so
a future "simplification" back to UTC fails in the test rather than on his page.

**`runner_directives` has no `updated_at`**, found by a `42703` from PostgREST and then read from
`information_schema` rather than guessed. `created_at` is when **John declared** a drain, never when
it finished, so using it would print a completion time off by the whole life of the drain. The
finish time is the closing cycle's `ended_at`; when `acted_cycle` is `NULL` there is no honest time
on file and the history line simply **carries none rather than inventing one**.

**`daily_max_effective` comes from `resolve_day_token_cap()`, never from the box multiplied out.**
That is `SES-147`'s own stated boundary, restated here because this is the code that would have
been tempted: the box is one of five rungs, so `box × 1,000,000` is wrong on exactly the days a
higher rung fires.
