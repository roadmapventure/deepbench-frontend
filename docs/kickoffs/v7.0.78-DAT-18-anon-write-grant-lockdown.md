## 2. CONTEXT

The public anon key ships in every visitor's browser bundle. As of `v7.0.77` it still holds
table-level `INSERT/UPDATE/DELETE/TRUNCATE/REFERENCES/TRIGGER` on 29 of the 32 public tables,
RLS disabled — anyone with devtools can rewrite or wipe `skill_profiles`, `agents`,
`the_library`, both counters, etc. `S-HAR-33-design` locked down the two gate-critical tables
(`ip_org_cache`: no public writes at all; `ai_activity_log`: table-level INSERT only +
column-scoped SELECT that hides `caller_ip`); `model_pricing` was created with no public grants.
This session closes the remaining hole.

**The design session's survey (verified live 2026-08-08, both in code and `information_schema`)
found exactly three legitimate public-key write paths in the entire codebase:**

1. `tasks` — browser INSERT (`src/screens/CreateWorkOrderScreen.jsx` ~L533) and UPDATE
   (`src/contexts/AnalyzerContext.jsx` ~L302, `src/screens/TaskInstructionsScreen.jsx` ~L404/480/717).
   Keeps INSERT + UPDATE. Never DELETE/TRUNCATE (no browser code deletes tasks).
2. `ai_activity_log` — browser INSERT (`src/hooks/useAIActivity.js` ~L1064). Already correctly
   locked; **this session does not touch it.**
3. `platform_stats` — written NOT by the browser but by `scripts/platform-stats.js`, which runs
   from `package.json`'s `prebuild` on every Vercel build **using the anon key**. Task 2 switches
   it to the service key, then the revoke includes `platform_stats`. (Verified live: the prebuild
   write works on Vercel today — row `id=1` `updated_at` 2026-08-08 18:00 UTC — and
   `SUPABASE_SERVICE_KEY` has the same Vercel env type/targets as the anon key it replaces, so
   build-time availability is proven equivalent.)

All 12 `api/` routes + `middleware.js` use `SUPABASE_SERVICE_KEY` (verified by grep — no
`createClient`/anon usage anywhere in `api/`) — unaffected. Version/ID counters are written via
the Supabase MCP (`postgres` role) — unaffected. Reads are untouched: table-level SELECT stays
granted everywhere it is today, so `select=*` keeps working (the LOG-124 column-list breakage
class does not apply to write revokes).

### Task 3 — The revoke migration (Supabase MCP `apply_migration`, name `dat18_anon_write_revoke`)

```sql
-- DAT-18: the anon key keeps write access ONLY where the app legitimately writes.
-- Kept: tasks INSERT+UPDATE (browser), ai_activity_log INSERT (browser, untouched here).
revoke insert, update, delete, truncate, references, trigger
on table
  public.agent_capability_assignments, public.agent_configs, public.agent_pricing_history,
  public.agent_revenue_splits, public.agent_run_log, public.agent_training_sessions,
  public.agents, public.briefings, public.capabilities, public.capability_skill_profiles,
  public.conversations, public.customer_agents, public.data_rooms, public.deliverables,
  public.dev_version_counter, public.durable_hops, public.feature_id_counter,
  public.knowledge_entries, public.known_callers, public.pattern_candidates,
  public.pattern_vocabulary, public.pending_confirmations, public.platform_services,
  public.platform_stats, public.skill_profiles, public.skill_types, public.the_library,
  public.the_reasoning
from anon, authenticated;

revoke delete, truncate, references, trigger on table public.tasks from anon, authenticated;

-- Close the upstream gap: future tables no longer auto-grant writes to the public roles.
-- (All public tables are owned by postgres — verified 2026-08-08.)
alter default privileges for role postgres in schema public
  revoke insert, update, delete, truncate, references, trigger on tables from anon, authenticated;
```

These are table-level revokes against table-level grants — they genuinely remove them (the
column-REVOKE no-op trap in `.claude/rules/supabase-column-grants.md` applies to column-scoped
subtraction, not this).

### Task 4 — Post-migration grant-matrix assertion (Supabase MCP `execute_sql`)
Run the survey query and diff against the expected matrix — every row must match exactly:

```sql
select t.tablename,
       coalesce(string_agg(distinct g.privilege_type, ',' order by g.privilege_type)
                filter (where g.grantee = 'anon'), '') as anon_privs
from pg_tables t
left join information_schema.role_table_grants g
       on g.table_schema='public' and g.table_name=t.tablename and g.grantee='anon'
where t.schemaname='public'
group by t.tablename order by t.tablename;
```

Expected: the 28 revoked tables → exactly `SELECT`; `tasks` → exactly `INSERT,SELECT,UPDATE`;
`ai_activity_log` → exactly `INSERT` (its SELECT is column-scoped and correctly absent from
table-level grants); `ip_org_cache` and `model_pricing` → `''` (empty). Repeat with
`grantee='authenticated'` — same expectations. Also assert the default-privilege change landed:

```sql
select pg_get_userbyid(defaclrole) as owner, defaclobjtype,
       array_to_string(defaclacl::text[], ';') as acl
from pg_default_acl d join pg_namespace n on n.oid=d.defaclnamespace
where n.nspname='public';
```

`anon`/`authenticated` entries must show at most `r` (SELECT) for object type `r` (tables). Any
mismatch anywhere = the migration is wrong — stop and fix before committing anything.

```js
// test-S-DAT-18.mjs — grant lockdown, both directions (rule: supabase-column-grants.md)
const URL = process.env.SUPABASE_URL || process.env.VITE_SUPABASE_URL;
const ANON = process.env.VITE_SUPABASE_ANON_KEY;
const SERVICE = process.env.SUPABASE_SERVICE_KEY;
if (!URL || !ANON || !SERVICE) { console.error("missing env"); process.exit(1); }

const NOROW = "00000000-0000-0000-0000-000000000000"; // filter that matches nothing, by design
const hdr = (k, extra = {}) => ({ apikey: k, Authorization: `Bearer ${k}`, "Content-Type": "application/json", ...extra });
let pass = 0, fail = 0;
const ok = (name, cond, detail = "") => { cond ? pass++ : fail++; console.log(`${cond ? "PASS" : "FAIL"}: ${name}${cond ? "" : " -- " + detail}`); };

// PostgREST surfaces a revoked grant as HTTP 401/403 (code 42501). 2xx means the write went through.
const denied = (r) => r.status === 401 || r.status === 403;

async function probe(name, method, path, body, key, expectDenied) {
  const r = await fetch(`${URL}/rest/v1/${path}`, { method, headers: hdr(key, { Prefer: "return=representation" }), body: body ? JSON.stringify(body) : undefined });
  const txt = await r.text();
  ok(name, expectDenied ? denied(r) : r.ok, `HTTP ${r.status}: ${txt.slice(0, 140)}`);
  return { status: r.status, txt };
}

// --- Denied direction (the discriminating half: every probe here succeeded pre-migration) ---
await probe("skill_profiles INSERT denied", "POST", "skill_profiles", { slug: "dat18-probe", name: "probe" }, ANON, true);
await probe("agents UPDATE denied", "PATCH", `agents?id=eq.${NOROW}`, { name: "x" }, ANON, true);
await probe("the_library DELETE denied", "DELETE", `the_library?id=eq.${NOROW}`, null, ANON, true);
await probe("platform_stats UPDATE denied", "PATCH", "platform_stats?id=eq.999", { commits_dev: 0 }, ANON, true);
await probe("feature_id_counter UPDATE denied", "PATCH", "feature_id_counter?prefix=eq.ZZZ", { last_issued_number: 0 }, ANON, true);
await probe("tasks DELETE denied", "DELETE", `tasks?id=eq.${NOROW}`, null, ANON, true);

// --- Allowed direction (the app's real write paths must still work) ---
const ins = await fetch(`${URL}/rest/v1/tasks`, {
  method: "POST", headers: hdr(ANON, { Prefer: "return=representation" }),
  body: JSON.stringify({ tenant_id: "global", title: "S-DAT-18 grant probe", agent_id: "nadia", type: "Work Order", status: "pending" }),
});
const insBody = await ins.json().catch(() => []);
const newId = Array.isArray(insBody) && insBody[0]?.id;
ok("tasks INSERT allowed (Create Work Order path)", ins.status === 201 && !!newId, `HTTP ${ins.status}`);
if (newId) {
  await probe("tasks UPDATE allowed (Task Instructions path)", "PATCH", `tasks?id=eq.${newId}&tenant_id=eq.global`, { title: "S-DAT-18 probe (updated)" }, ANON, false);
  const del = await fetch(`${URL}/rest/v1/tasks?id=eq.${newId}`, { method: "DELETE", headers: hdr(SERVICE) });
  ok("probe task cleaned up via service key (service key unaffected)", del.ok, `HTTP ${del.status}`);
}

// --- SELECT untouched (one representative read per posture class) ---
const sel = await fetch(`${URL}/rest/v1/skill_profiles?select=*&limit=1`, { headers: hdr(ANON) });
ok("skill_profiles SELECT * still works", sel.ok, `HTTP ${sel.status}`);
const audit = await fetch(`${URL}/rest/v1/ai_activity_log?select=id,ai_type&limit=1`, { headers: hdr(ANON) });
ok("ai_activity_log column-list SELECT still works", audit.ok, `HTTP ${audit.status}`);

// --- platform-stats.js runs strict on the service key ---
const { execSync } = await import("node:child_process");
try { execSync("node --env-file=.env.local scripts/platform-stats.js", { stdio: "pipe" }); ok("platform-stats.js strict run (service key)", true); }
catch (e) { ok("platform-stats.js strict run (service key)", false, String(e.stdout || e.message).slice(0, 200)); }

console.log(fail === 0 ? `ALL TESTS PASS (${pass})` : `${fail} FAILURES`);
process.exit(fail === 0 ? 0 : 1);
```

Run order: Tasks 1–2 → this test **must show the denial probes FAILING pre-migration is not
required** — run it once after Task 3/4; every denial probe passing is only meaningful
post-migration (pre-migration they would succeed as writes, which is exactly the hole).
