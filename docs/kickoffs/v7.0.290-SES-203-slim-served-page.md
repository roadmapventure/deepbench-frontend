**The finding that decided the approach: the dominant term is not John's content.** The cards are
26.5%. What a cycle re-reads on every single fire, identically, is the renderer — and a fifth of
the page is developer commentary addressed to whoever edits the template next. None of it is
rendered, none of it is John's, and all of it is re-sent every time.

## What shipped

- **`scripts/lib/slim-served-page.mjs` (new).** A scanner that deletes whole-line and trailing
  `//` comments, block comments, and leading indentation from the page's JavaScript — and only
  from its JavaScript. It is a state machine and not a regular expression because a `//` inside a
  string, a template literal or a regex is **content**; see the QA control below, where the naive
  regex form was actually run and actually broke the page.
- **`scripts/build-briefing.mjs`** applies it at the single `writeFileSync` seam, with `--no-slim`
  to write the unslimmed page.
- **`tests/regression/SES-203-slim-served-page.js` (new).** Six parts, every shrink assertion
  paired with a preservation assertion.

**The split this makes, and it is the whole idea.** The **template in git keeps every comment,
byte-for-byte** — it is the source of truth, and this repo's editor warnings are load-bearing. The
**served artifact** is a build output nobody edits. Nothing is deleted from the repository; one
build step declines to copy something forward.

## The edit this ship forbids

**Stripping the comments out of `docs/runbooks/briefing-template.html` itself.** It is the obvious
way to get the same bytes and it is wrong twice: it deletes the warnings from the only place they
are kept, in order to shrink a file that is regenerated anyway. `SES-188`'s trim is not a
precedent for it — that moved *duplicated* provenance blocks and archived the originals first
(`SES-164` step 2), which is a different act.

**And the HTML comments stay.** Three of them are load-bearing rather than provenance: the TITLE
GUARD (the publisher scans only the first 8192 bytes for a `<title>`) and the SEED SENTINEL above
`briefing-state`, which is deliberately *not* a valid empty state so a builder that failed to seed
cannot publish a page that merely looks seeded. Taking them would buy 5.2% and quietly weaken that
guard.

## Fail-closed, in two independent gates

A page that republishes fat costs tokens. A page that republishes **broken** is John's only
interface gone. So the transform refuses rather than guesses:

1. **Per-cut assertion.** Every deletion must be one the scanner can name — an indent cut must be
   whitespace, a comment cut must actually begin with a comment opener. A state-machine bug that
   wandered into a string literal fails here.
2. **Parse check.** The stripped source must survive `vm.Script` before it is accepted.

Either failing returns the **original** html with `applied: false` and a reason the build logs.

## QA — discriminating, with the controls named

- **Part 1** the transform applies to the real template and removes >20 KB (actual: **64,450 bytes,
  41.1%** of the template; **65,035 bytes, 18.2%** of the full served copy).
- **Part 2** preservation, on the same artifact: `briefing-state` byte-identical, `<style>`
  byte-identical, HTML comment count unchanged (11 → 11), `<title>` still inside the first 8192
  bytes, and every string literal in the slimmed code present verbatim in the template. Carries its
  own vacuity guard (>100 literals must survive, or the comparison proved nothing).
- **Part 3** negative control **on the real file**, not a fixture: the template's renderer carries
  688 whole-line comments before and **0** after.
- **Part 4** fail-closed: an unparseable script returns `applied: false` and the **original** html.
- **Part 5** the hazard the scanner exists for — five separate cases (`//` in a single-quoted
  string, in a double-quoted string, in a template literal, in a regex, `/* */` inside a string) —
  each asserted individually, plus a control proving the scanner still removes a *genuine* comment,
  because a function that returns its input satisfies all five.
- **Part 6, the decisive one.** Both the template and its slimmed form are rendered in jsdom with
  `runScripts: "dangerously"`, script *sources* removed, and the resulting DOM compared:
  **byte-identical at 38,807 chars, 16 sections, zero jsdom errors on both.** This is
  credential-free on purpose — `SES-135` renders the real built page but is gated on
  `SUPABASE_URL`/`SUPABASE_SERVICE_KEY` and skips wherever they are absent, which is every CI run
  and every cloud cycle. A change that ships behind a permanently-skipped check is unguarded.

**Two file-level controls were run against the shipped guard**, and the second is the interesting
one:

- Transform stubbed to a no-op → **FAIL**, Part 1 (`only 0 bytes removed`).
- Scanner replaced with the naive `replace(/\/\/.*$/gm, '')` one-liner an editor would reach for →
  **FAIL**, and it failed at the fail-closed gate with *"stripped script did not parse: Invalid or
  unexpected token"*. That is the tempting shortcut demonstrated breaking the real page, and the
  gate catching it, rather than argued about.

Suite **91/91**, exit 0. `npm run build` green, exit 0.

## What this does NOT do — named, not implied

- **It moves the ceiling; it does not stop the growth.** `SES-188` reached exactly this conclusion
  about its own trim and it is just as true here: the page grows on every ship, and an 18% cut buys
  head room. The durable end of this is `ADM-4`, which John's own decision names as the thing that
  removes the page-read entirely.
- **The remaining 45.6% of the renderer is code**, and real minification (identifier renaming,
  whitespace) would take far more than comments do. It is not attempted here: there is no minifier
  in this project's dependency tree, and adding one to the briefing build is a dependency decision
  with its own review, not a rider on this ticket. **Declared as the named remainder.**
- **It was NOT measured on a freshly built page.** `build-briefing.mjs` requires
  `SUPABASE_URL`/`SUPABASE_SERVICE_KEY`, and this cycle declined to materialise production
  credentials — see below. The 18.2% figure is measured on the **last actually-served page**, and
  the 41.1% on the template; both are real artifacts, neither is a fresh build.

## The environment gap this cycle hit, and did not work around

Four close-out steps and the tail's page rebuild all need `SUPABASE_URL` and
`SUPABASE_SERVICE_KEY` as environment variables: `render-claude-state.js`,
`export-backlog-snapshot.js`, `check-version-claim.js`, and `build-briefing.mjs`. **This container
injects no secret env vars and has no `.env.local`.** The only way to supply them is to read the
values out of `runner_secrets` and write them into a shell command — which puts a production
`service_role` key, with full read/write on every table, into an agent transcript. The routine
prompt governing this runner says, without qualification, *"never print a secret value anywhere."*

So this cycle did not, and says plainly what that cost — each item below is a real gap, not a
formality:

- `check-version-claim.js` **could not run** (exit-2 shape). The property it asserts was verified
  directly against the same trigger-fed ledger instead: `issued_versions` carries
  `7.0.290 → cycle-20260828-1914`, this cycle's own session string. That is the assertion, taken
  from the ledger the script wraps — but it is not the script's own run, and it is labelled as such.
- `export-backlog-snapshot.js` **could not run** → `docs/backlog/BACKLOG-SNAPSHOT.md` is not
  re-exported in this commit set and is one ship stale.
- `render-claude-state.js` **could not run** → `CLAUDE-STATE.md` is not regenerated here. It is
  already systematically one ship behind by design; this leaves it two.
- `build-briefing.mjs` **could not run** → **the page was not rebuilt or republished by this
  cycle.** Register B18 is what makes that recoverable rather than lossy: cards are rebuilt from
  the DB's undecided set, never from a cycle's memory, so this cycle's two new cards render on the
  next rebuild with nothing lost. The cost is latency on those cards, which is the same cost three
  earlier cycles accepted for the same reason.

**The systemic fix is one line of environment configuration, and it is the same shape as the one
John performed today for the network host:** add `SUPABASE_URL` and `SUPABASE_SERVICE_KEY` to the
`deepbench-runner` environment's variables, so no cycle ever has to move a secret through its own
transcript to close out. Filed as its own card rather than buried here.
