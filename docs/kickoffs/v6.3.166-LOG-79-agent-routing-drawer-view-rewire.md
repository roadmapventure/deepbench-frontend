## 1. Use case (the problem, plain)

**Problem.** The Agent Routing drawer's per-hop "AI patterns used:" line still reads the frozen legacy `patterns_used` field threaded through the API response — write-time stamped names the platform has already replaced with read-time classification (`§19k`). So a hop can claim `rag` that never retrieved, and the governed criteria corrections Susan Smith — Trainer makes never reach this surface. `LOG-36` already fixed the display *name* (governed vocabulary); the *set* of patterns per hop is still legacy — this closes that half.

**Fix.** Each completed hop's pattern names come from the `ai_call_patterns` view (the Log Displayer) — the real signature match for that hop's own logged rows, joined via `trace_id`/`span_id`. Legacy `patterns_used` display is retired on this surface.

**Expected after.** A completed hop shows the governed names the view derives for its rows (e.g. "AI patterns used: Retrieval-Augmented Generation, Agent Handoff"). A hop whose rows match no gold pattern shows **no pattern line at all** — the honest unclassified state, expressed structurally, with **no user-facing boundary/date copy anywhere** (John's explicit call at this session's UI gate, recorded in `§19l`'s amended third seal condition — the AI Audit surface is NOT touched this session for the same reason). A live in-flight hop shows no pattern line until its rows are written — by design, not a bug.

**Example.** Today Marcus's Q&A hop shows whatever `request-receivable.js` stamped at write time (e.g. `Structured Output, Tool Use, Rag`). After: the same hop shows exactly what the Displayer derives from its logged facts — if its rows match RAG's criteria (`retrieval_method in [similarity-search, mixed]`, real chunk ids), "Retrieval-Augmented Generation"; if they match nothing, no line.

## 2. Root cause / mechanism (brief)

- `RoutingActivityLine` (`MarketIntelligenceScreen.jsx` ~line 2445) reads `evt.data.patterns_used` and labels via `patternLabelFor(vocab, slug)`.
- The response payload has no trace identity: `runLoop()`'s `finalResult` (`execute.js` ~line 854) omits `trace_id`/`span_id` even though both are threaded through the whole loop (`LOG-49`). Without them the client cannot join to the view.
- The view (verified live this session) exposes `ai_activity_log_id, created_at, cost_usd, pattern_slug, pattern_name, pattern_description` — no trace/span columns — so the join is: trace → `ai_activity_log` ids/spans → `ai_call_patterns` by id.
- **Locked invariant (`LOG-49`): the hops model is untouched.** Hops still come from client events; only the pattern-name *source* changes. No re-count, no event restructuring.

## 4. Tasks

**Task 1 — response carries trace identity (`execute.js`, ~line 854).**
`const finalResult = { ...result, display_agent_card, display_agent_id: display_agent_id || null, last_help_selection: lastHelpSelection, trace_id, span_id };`
Both are in scope at that line. Generic, applies to every capability identically. Do not add them to error/`pending_confirmation`/`depth_exceeded` returns — those never display pattern lines.

**Task 2 — `src/lib/tracePatterns.js` (new).**
Two exports:
- `buildSpanPatternMap(activityRows, patternRows)` — **pure.** Inputs: `[{id, span_id}]` and `[{ai_activity_log_id, pattern_name}]`. Returns `{ [span_id]: [unique pattern_name, …] }`. Rows with null `span_id` are skipped; names deduped, insertion-ordered.
- `fetchTracePatterns(traceId)` — `import { supabase } from './supabase.js'`. Query 1: `ai_activity_log` select `id, span_id` where `trace_id = traceId`. Query 2: `ai_call_patterns` select `ai_activity_log_id, pattern_name` where `ai_activity_log_id` in (query 1 ids); skip query 2 when query 1 is empty. Return `buildSpanPatternMap(...)`. On any error: `console.warn` + return `{}` (the `LOG-38` fetch posture — the drawer just shows no lines). If query 1 returns 0 rows, one delayed retry (~1500ms) then give up — rows are written before the response returns, so this is belt-and-braces only.
No pattern names, slugs, or per-pattern branches anywhere in this file (`.claude/rules/ai-pattern-signature.md`).

**Task 3 — drawer rewire (`MarketIntelligenceScreen.jsx`).**
- New `useTracePatterns(traceId)` hook, module-level cache keyed by trace id (mirror `usePatternVocabulary`'s cache shape): first mount with a given trace triggers `fetchTracePatterns` once; all lines for that trace share the result; state updates when the fetch resolves.
- `RoutingActivityLine`: replace the `evt.data.patterns_used` read with `useTracePatterns(evt.data?.trace_id)` + lookup of `evt.data?.span_id`. Names render exactly as today (`AI patterns used: {names.join(', ')}`), same style, no visual change. The view's `pattern_name` IS the governed vocabulary name, so `patternLabelFor`/`usePatternVocabulary` drop out of this component — remove them here only if now unused in this component; leave other usages in the file alone.
- Thread ids at the event sites that currently thread `patterns_used` off a `callCapability` result: `failure_triage` (~1357: pass `trace_id: gate.trace_id, span_id: gate.span_id`), `generateHypotheses`/`hypothesis_generation` (~1468/3365: return + pass the ids), `runHypothesisTest` display/analysis (~1523-1526: carry `analysis.trace_id`/`analysis.span_id`), `patch_resolved` (~3814/3823: pass ids off `result` if present). Sites whose `data` is the `finalResult` itself (e.g. ~1264) inherit the ids with zero change.
- Retire the now display-dead `patterns_used` threading at those same sites (the response field itself stays — `LOG-40` owns retiring the write). Do NOT touch `AboutPanel.jsx`, `aiPatterns.js`, `useAgents.js`, `useAIActivity.js`, or `AIActivityPanel.jsx` (`LOG-70`'s remaining consumers stay legacy until `LOG-40`; the AI Audit surface needs no change this session).

**Task 4 — Node test (`tests/regression/LOG-79-trace-pattern-map.js`).**
Import `buildSpanPatternMap` from `src/lib/tracePatterns.js`. Assert:
1. Two rows sharing a span with two view matches → one key, both names, deduped.
2. A row with `span_id: null` contributes nothing.
3. A log row with no view match → its span absent from the map (no empty-array fabrication).
4. Empty inputs → `{}`.
Register in `tests/regression/run-all.js`.
