## 2. CONTEXT

**The premise, revalidated live 2026-09-11 (every number below is a query this session ran, not the ticket's text):**

- `select … from runner_green_states order by observed_at desc limit 1` → `0125a062`, `ci_run_id 33645601940`, watermark `20260902145738`, `observed_at 2026-09-02 15:08:17Z`. 15 anchors total.
- `ci_run_conclusions`: 189 rows, **91 all-success** (both blocking jobs `success`). Newest green: `af981b16`, run `34433050927`, `concluded_at 2026-09-10 03:24:59Z`. **81 greens have no anchor**; 63 of them concluded after the newest anchor.
- Head of `dev` (`bcbc6cf`) is **red** — `Tripwire + regression (blocking) = failure` — and so are all 17 runs of 2026-09-11 (0 green). That red is pre-existing and is not this ticket's.
- Current migration watermark: `20260911173333`.
- **Correction to the ticket's wording:** the routine is *not* off. `runner_cycles where trigger = 'scheduled'`: 1 cycle on 09-02, 5 on 09-09 (21:10–21:17Z, no version, no push — they never reached step 4a), 6 on 09-11. The gap is not "the routine is off"; it is that step 4a records a green **only when a cycle is up and dev's head is green at that minute**. 09-09 had 16 greens and five cycles and recorded none; 09-11's cycles ran step 4a on a red head. The ticket's mechanism is right (derive the anchor from `ci_run_conclusions`), its diagnosis is narrower than the defect.
- **Premise: alive.** A red on `dev` today is measured against a commit 9 days and 63 greens old.

**Why the anchor must be written at conclusion time, not read later.** `rollback-on-red.js` `rangeIsCodeOnly()` (line 152) compares the anchor's `migration_watermark` with the current one; equal ⇒ code-only ⇒ revert-forward is automatic. A function that *derives* the anchor from `ci_run_conclusions` at read time would have to stamp today's watermark on a week-old green, making every range look code-only — the one direction the engine's header says must never be wrong (line 75–77). So the ticket's first variant (`latest_green_state()`) is rejected; the second (a trigger that inserts the row at the moment the conclusion lands, reading the watermark then) is the design. **Measured, not assumed:** `max(version) where version <= to_char(concluded_at, 'YYYYMMDDHH24MISS')` reproduces the recorded watermark on **9 of 9** anchors that carry one (versions are apply-time UTC stamps), and fills the one anchor (`77cca03a`) that was recorded with `NULL`.

**Why nothing calls anything.** The ticket offers "have the attended ship path (`scripts/verifier.js` or `record_ship_decision`) call it." Neither may: `verifier.js` is verdict-only and *writes exactly one row* by its founding property (header lines 252–257); `record_ship_decision()` runs at step 7's close-out, **before CI has concluded** on the push it records, so it cannot know green. A trigger on the row CI itself writes needs no caller, attended or unattended, and that is exactly the claim in the ticket's title.

**The branch guard, a hazard the ticket did not see.** `ci.yml` runs on pushes to `dev` **and `main`**, and `git merge-base --is-ancestor origin/main origin/dev` → **no** (16 merge commits on `main`, last `74611da` at v7.0.90). A green published for a `main` merge commit would become the newest anchor, and `revertPlanFor()` would emit `git revert <main-sha>..<dev-head>` — a non-ancestor base reverts far past the red range. Today every one of the 189 rows is a `dev` ancestor (checked with git, 189/189 — `main` has not been merged since before `ci_run_conclusions` existed), so the backfill is safe; the future is guarded by publishing `ref` (`github.ref_name`) from the reporter and anchoring `ref = 'dev'` only. A `NULL` ref — a run still on the pre-ship workflow — anchors nothing.

**What this does not do, named:** it does not touch `scripts/rollback-on-red.js` (`TRIGGER_SOURCES`, `decide()`, attribution are untouched; John's Q1 ruling stands); it adds no trigger source; it does not make attended reds actionable (an unattributed sha still yields `none`, by design). `SES-182`'s standing hold (directive `58db64ae` item 6) was on *picking SES-182 until SES-191's drill* — both are `done`; this ticket is `SES-352`, and it changes the anchor's *source*, not the engine's *power*.

```sql
-- SES-352 (v7.0.452): the green anchor is written by CI's own conclusion.
-- Rationale and measurements: docs/kickoffs/v7.0.452-SES-352-green-anchor-from-ci.md

-- (1) the branch CI ran on. NULL = published before this ship, or by a run still on the old
--     workflow; only 'dev' rows ever anchor (origin/main is not an ancestor of origin/dev).
alter table public.ci_run_conclusions add column if not exists ref text;
comment on column public.ci_run_conclusions.ref is
  'SES-352: github.ref_name of the run, published by ci.yml report-conclusion. Only ''dev'' rows anchor; NULL anchors nothing.';

-- (2) the watermark as it stood at an instant. Versions are apply-time UTC stamps, so the
--     comparison is textual; reproduces 9/9 recorded anchor watermarks (measured 2026-09-11).
create or replace function public.migration_watermark_at(p_at timestamptz)
returns text
language sql stable security definer
set search_path = public, pg_catalog
as $$
  select max(m.version)::text
    from supabase_migrations.schema_migrations m
   where m.version <= to_char(p_at at time zone 'UTC', 'YYYYMMDDHH24MISS')
$$;

-- (3) the SQL twin of scripts/rollback-on-red.js isRunGreen(): a non-empty array whose every
--     job concluded 'success'. Empty, non-array, NULL, cancelled, skipped, failure -> false.
--     tests/regression/SES-352-green-anchor-from-ci.js asserts the two agree on every fixture.
create or replace function public.ci_conclusion_is_green(p_jobs jsonb)
returns boolean
language sql immutable
as $$
  select case
    when jsonb_typeof(p_jobs) = 'array' and jsonb_array_length(p_jobs) > 0
      then not exists (select 1 from jsonb_array_elements(p_jobs) j
                        where j->>'conclusion' is distinct from 'success')
    else false end
$$;

-- (4) the anchor writer. observed_at and the watermark are taken at concluded_at -- the moment
--     CI first published this sha (a merge-duplicates re-run keeps the original concluded_at).
--     ON CONFLICT never overwrites a watermark a cycle recorded; it only fills a NULL one.
create or replace function public.anchor_green_from_ci()
returns trigger
language plpgsql security definer
set search_path = public, pg_catalog
as $$
begin
  if new.ref = 'dev' and public.ci_conclusion_is_green(new.jobs) then
    insert into public.runner_green_states
      (commit_sha, ci_run_id, migration_watermark, observed_at, version, observed_by_cycle)
    values
      (new.commit_sha, new.run_id::text, public.migration_watermark_at(new.concluded_at),
       new.concluded_at, null, null)
    on conflict (commit_sha) do update
      set migration_watermark = coalesce(public.runner_green_states.migration_watermark,
                                         excluded.migration_watermark);
  end if;
  return null;
end $$;

drop trigger if exists trg_anchor_green_from_ci on public.ci_run_conclusions;
create trigger trg_anchor_green_from_ci
  after insert or update of jobs, ref on public.ci_run_conclusions
  for each row execute function public.anchor_green_from_ci();

-- (5) grants: the platform convention is postgres + service_role only (read live from
--     migrations_in_range / class_autonomy / plan_data_restore proacl). Default ACL hands
--     anon/authenticated EXECUTE, so revoke explicitly. The column inherits the table's
--     grants (service_role only; anon/authenticated hold nothing on ci_run_conclusions).
revoke execute on function public.migration_watermark_at(timestamptz) from public, anon, authenticated;
grant  execute on function public.migration_watermark_at(timestamptz) to service_role;
revoke execute on function public.ci_conclusion_is_green(jsonb) from public, anon, authenticated;
grant  execute on function public.ci_conclusion_is_green(jsonb) to service_role;
revoke execute on function public.anchor_green_from_ci() from public, anon, authenticated;
grant  execute on function public.anchor_green_from_ci() to service_role;

-- (6) backfill, §19v-first. Every one of the 189 legacy rows was verified a dev ancestor with
--     git merge-base --is-ancestor (189/189, 2026-09-11; main last merged at v7.0.90, before
--     this table existed). Stamping ref = 'dev' fires the trigger per row, which writes the
--     81 missing anchors with their conclusion-time watermarks and fills 77cca03a's NULL.
insert into public.runner_before_images (cycle_id, table_name, pk_value, row_data)
  select '<cycle>', 'ci_run_conclusions', c.commit_sha, to_jsonb(c)
    from public.ci_run_conclusions c where c.ref is null;
insert into public.runner_before_images (cycle_id, table_name, pk_value, row_data)
  select '<cycle>', 'runner_green_states', c.commit_sha, null
    from public.ci_run_conclusions c
   where c.ref is null and public.ci_conclusion_is_green(c.jobs)
     and not exists (select 1 from public.runner_green_states g where g.commit_sha = c.commit_sha);
insert into public.runner_before_images (cycle_id, table_name, pk_value, row_data)
  select '<cycle>', 'runner_green_states', g.commit_sha, to_jsonb(g)
    from public.runner_green_states g
   where g.migration_watermark is null
     and exists (select 1 from public.ci_run_conclusions c
                  where c.commit_sha = g.commit_sha and c.ref is null and public.ci_conclusion_is_green(c.jobs));
update public.ci_run_conclusions set ref = 'dev' where ref is null;
```

```js
async function rpc(base, key, fn, body) {
  const res = await fetch(`${base}/rest/v1/rpc/${fn}`, {
    method: "POST",
    headers: { apikey: key, Authorization: `Bearer ${key}`, "Content-Type": "application/json" },
    body: JSON.stringify(body),

  return { status: res.status, body: await res.text() };
}

}
```
