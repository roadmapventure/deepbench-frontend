### The facts are already in hand — verified this session

`embedAndSearch()` (`lib/vector-search.js:39`) already returns `chunks` — real ids — and `usage`. `lib/librarian.js` logs at `:206-212` and `:219-225` with that `result` **already destructured in scope**. The evidence is one property away from a log write that records only a frozen label. Same shape as `LOG-37b`'s finding at `execute.js:659`.

### The counter-example that decides the gating — found this session, do not skip

`embedAndSearch()` **early-returns at `:40` without embedding anything** when `queryText` or `scopeValue` is missing, returning `usage: null`. Its callers log `model: 'text-embedding-3-small'` regardless. So some existing rows already claim an embedding call that never ran.

Therefore the fact must be gated on what actually executed, not on the caller's intent — the exact lesson `LOG-37a-patch` learned when `getRosterCandidates()` returned roster rows in a field named `chunks`:

- **`usage !== null` ⇒ an embedding really ran** ⇒ `retrieval_method: 'similarity-search'` is provable.
- `usage === null` ⇒ no embed happened ⇒ **omit every fact**, write `call_facts: null`.
- `chunks.length > 0` ⇒ `retrieved_chunk_ids`. Zero chunks with `usage` present is **"searched, found nothing"** — honest, and it must stay distinguishable from "did not search." That distinction is the whole point of `retrieval_method` per §19i.

## 5. TASKS

### Task 1 — `embedAndSearch()` returns the facts (`lib/vector-search.js`)

Add a `callFacts` key to the object `embedAndSearch()` returns, built from what it already has. Build it in one place so no caller hand-rolls a fact shape:

- early return at `:40` (nothing embedded) → `callFacts: null`
- every return where `usage` is present → `retrieval_method: 'similarity-search'`
- returns carrying matches → also `retrieved_chunk_ids: matches.map(m => m.id).slice(0, 50)`

**All four existing return sites (`:40`, `:50`, `:52`, `:57`) must carry the key** so no caller has to distinguish them. Do not change any existing key on the returned object — `context`, `chunks`, `matchCount`, `usage` keep their current names, types, and values.

`embedContent()` is **not** touched — see §7.

### Task 2 — `lib/librarian.js` passes the facts at its two retrieval log sites

At `:206-212` and `:219-225`, add one line to the existing `logActivity()` call:

```js
callFacts: result.callFacts,
```

`result` is already in scope at both sites. **Change nothing else** — `agentId`, `aiType`, `feature`, `model`, `inputTokens`, `latencyMs`, and especially `patternsUsed: ['rag','embeddings']` stay byte-identical. The denied/no-access log calls at `:230` and `:234` are **not** touched (no embed ran on those paths).

### Task 3 — `lib/rag.js` records the retrieval method

`queryRAG()`'s `logActivity()` call at `:32-41` fires **after the embed and before the vector search**, so chunk ids do not exist yet at that point. Add only the fact that is provable there:

```js
callFacts: { retrieval_method: 'similarity-search' },
```

**Do not move the `logActivity()` call below the RPC to reach the chunk ids.** The RPC has two early-return failure paths (`:64`, `:66`); moving the log past them would silently stop logging those calls entirely, which `.claude/rules/capability-logging.md` forbids outright. Capturing `retrieved_chunk_ids` here needs its own restructure — **`LOG-113`**.

This is not a consolation prize: §19i states the Layer B rule *"must key on the retrieval method, not on chunk presence."* This fact is exactly what makes `queryRAG()`'s 1,003 `rag`-labelled calls checkable.

**`AA-105` (Tech Debt) stays deferred.** This session does **not** port `queryRAG()` onto `embedAndSearch()`. It adds one argument to a log call that already exists.

## 6. DESIGN RULES

- **Facts, never names.** `retrieval_method` and `retrieved_chunk_ids` are structural properties. If a value looks like a pattern slug, it is wrong.
- **Provable, never inferred.** Every fact must follow from code that demonstrably executed. Never synthesize a chunk id; never assume an embed ran.
- **Additive only.** No existing field changes meaning, type, or nullability. `patterns_used` is untouched everywhere.
- **Never remove or weaken an existing `logActivity()` call** (`.claude/rules/capability-logging.md`) — this is what forbids relocating `rag.js`'s log call.
- **No conditionals keyed to agent id or capability slug** (`.claude/rules/capabilities-are-data.md`). `librarian.js`'s existing hardcoded `agentId: 'eleanor'` is pre-existing and out of scope — do not extend that pattern into the new code, and do not "fix" it here either.
- **`the_library`'s single-path rule holds** (`.claude/rules/library-access.md`). This session adds no new store access and no new code path.
- **Do not touch retrieval or access-control control flow.** `getCredentials()`, the `uber_access` branch, `match_threshold`, and scope resolution are read-only context here.
