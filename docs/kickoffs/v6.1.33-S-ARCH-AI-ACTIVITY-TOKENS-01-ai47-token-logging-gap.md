## CONTEXT

Found 2026-07-08 (design session `aa151-agent-selection-budget-0708`) while trying to root-cause why `AA-151`'s `agent-selection-intent` `max_tokens` bump (1200→2200) didn't reduce the bug's failure rate — the design session needed real `output_tokens` data to check whether budget was ever actually the constraint, and discovered `ai_activity_log.output_tokens`/`.input_tokens` are `null` on every single row platform-wide (checked all `ai_type`s, last 2 hours). Direct code read (not guesswork — confirmed by reading the actual write sites) found **two distinct, separate bugs**, both in shared harness code, both real:

**Bug 1 — `execute.js`'s `logAgentTurn()` never captures usage at all.** Its own function signature (`{ capability_slug, intent_slug, agent_id, tenant_id, model, depth, latency_ms, is_delegate_call, api_retry_count }`) has no token parameter, and its POST body to `ai_activity_log` never includes `input_tokens`/`output_tokens` keys. At its one call site (`execute.js` ~line 314, inside `runLoop()`), `turn.usage` (returned by `callModel()`) is sitting right there and is simply never passed through. This is the write path for every turn inside the delegation loop, `ai_type: 'agent-turn'` — confirmed live: 438 rows in the last 2 hours, zero token data. **This is the write path that logs Michelle's `agent-selection-intent` turns** (`feature: 'project-manager:agent-selection-intent:depth1'`), so it's what's blocking `AA-151`'s real diagnosis specifically.

**Bug 2 — `request-receivable.js`'s `sendRequest()` STEP 4 write is real but mislabeled/incomplete.** Line 447: `input_tokens: (usage.input_tokens + usage.output_tokens) || null` — this writes the *combined* input+output total into the `input_tokens` column, and never writes `output_tokens` at all. Confirmed live: 9 different `ai_type`s (`channel-intelligence`, `screen-controls`, `data-room-custody`, `quality-gate`, `guardrails-check`, `html-display`, `project-manager`, `hypothesis-evaluation`, `pipeline-triage`) all show a real non-null but mislabeled `input_tokens` value (up to 17,689), `output_tokens` always null. This is `sendRequest()`'s own top-level call path (not the loop), used by capabilities/turns that don't go through `execute.js`'s `runLoop()`.

Both bugs are shared harness code (`api/capabilities/execute.js`, `api/prompt/request-receivable.js` — 2 of DeepBench's 4 harness files, see `feedback-harness-vs-service-discipline`) — fixing them is inherently generic, not capability-specific, and directly enables `AA-161`-style budget diagnosis from live production data going forward instead of requiring an ad-hoc out-of-band script every time.
