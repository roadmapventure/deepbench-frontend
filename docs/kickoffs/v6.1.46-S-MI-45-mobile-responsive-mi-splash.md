## 2. CONTEXT

John asked for a risk assessment on making the front end mobile-responsive. That widened into a full design pass on `MarketIntelligenceScreen.jsx` specifically (John's framing: "MI" = the Market Intelligence screen, confirmed as the actual landing route `/` on `dev` — not `AnalyzerScreen.jsx`, which an earlier pass in this same conversation incorrectly targeted before the branch mismatch was found and corrected: the working branch had been cut from stale `main` (v5.2.41) instead of `dev` (v6.1.45+), reset via `git checkout -B ... origin/dev`, no history lost).

The design was iterated live against an interactive HTML mock (built from the real component's actual copy — Marcus Webb, the three `EXAMPLE_QUESTIONS`, the Sourced/Analysis/Source Simulation/Learned tags, the five Audit drawer titles — and the real Treasury tokens, not a generic mockup) across two full rounds before lock:

- **Round 1** proposed a simple single-column stack (Interact → Evidence → Audit, page-scrolling). John rejected this in favor of something more deliberate.
- **Round 2**, per John's direction: mobile should have a **not-to-exceed-viewport fit** (no page scroll), **chat as the clear primary surface**, a **persistent sliver showing live Agent Routing activity** so the "agents talking to each other" showcase moment survives without the user having to leave chat, and **Evidence + the rest of Audit as user-selected full-screen views** rather than simultaneously visible. Four follow-up questions were asked and answered one at a time; all four locked as shown below. John then asked for the splash screen (`WelcomeSplash.jsx`) to get the same treatment — same overlay mechanic as desktop, sized to ~75% of the mobile screen, MI visible (blurred) behind it, exactly as it already behaves on desktop today.

**Locked decisions (all confirmed by John, do not re-litigate):**
1. Mobile split: chat (`InteractColumn`) at `flex:3`, a pinned condensed Agent Routing feed at `flex:1` directly below it (~75/25). No page-level scroll — only these two panes scroll internally.
2. Evidence button shows a small live badge dot when `hypFlow` is active (non-null) — otherwise Evidence is just an empty-state legend and is easy to miss behind a tap exactly when it matters.
3. Evidence/Activity overlays dismiss via an explicit "← Back to Chat" control only — no tap-outside-to-close (deliberate, avoids accidental dismissal while scrolling overlay content).
4. The pinned Agent Routing feed shows the exact same full, unfiltered event data as desktop's Agent Routing drawer — condensed shell only, never a trimmed subset.
5. `WelcomeSplash.jsx` mobile: same component, same copy, same dismiss mechanic — only the panel resizes to `75vw × 75vh` (vs. desktop's `80vw / max 960px / 88vh`).
6. Desktop must be **completely unchanged** — this is a new runtime-gated composition (`useIsMobile()`), not a CSS reflow of the existing 3-column grid. The desktop code path is untouched by construction.
7. `AppShell.jsx`'s Work-dropdown nav mobile treatment is explicitly **out of scope** — flagged in the mock itself, tracked as a separate future session.

`STYLE-GUIDE.md` §21 (Mobile Composition), §22 (`useIsMobile()`), §23 (Splash Mobile Sizing) are already locked by this design session — they are the source of truth for every rule above; this Section 2 is context, §21-23 is the spec.

### Task 1 — `src/hooks/useIsMobile.js` (NEW FILE)

```js
// DeepBench v6.1.46 | useIsMobile.js | S-MI-45 — platform's single responsive breakpoint source
// FEATURE: MI-45 — see STYLE-GUIDE.md §22
import { useState, useEffect } from "react";

export const MOBILE_BREAKPOINT = 768;

export function useIsMobile() {
  const query = `(max-width: ${MOBILE_BREAKPOINT}px)`;
  const [isMobile, setIsMobile] = useState(
    () => typeof window !== "undefined" && window.matchMedia(query).matches
  );

  useEffect(() => {
    const mql = window.matchMedia(query);
    const onChange = () => setIsMobile(mql.matches);
    onChange();
    mql.addEventListener("change", onChange);
    return () => mql.removeEventListener("change", onChange);
  }, [query]);

  return isMobile;
}
```

- `matchMedia`'s `change` event, not a `resize` listener — fires only when the boolean actually flips.
- Cleanup via `removeEventListener` on unmount — Category D (Component Lifecycle) compliance.
- This is the **only** place `MOBILE_BREAKPOINT` or a `matchMedia`/`window.innerWidth` check may be defined. Both Task 2 and Task 3 import this hook — do not re-derive the breakpoint inline in either file (Category M).
