## 5. TASKS (3 of 4 max, 0 code files + 3 Supabase content updates)

### Task 1 — `skill_profiles.method` for `ci-answer-intent`: consolidated rewrite

Live-verify current content first (`select method from skill_profiles where slug = 'ci-answer-intent'`) and confirm it matches the text quoted in Section 1 above before overwriting — another concurrent session may have touched it since this kickoff was written.

Replace the entire `method` field with:

```
Self-flag needs_review true when the answer draws on synthesized/inferred data presented as an actionable recommendation, not merely informational. If the Data Room simply does not contain information needed to answer part of the question (e.g. a missing time-period comparison or an absent metric), state that gap directly in your answer as a sourced observation -- this is not a reason to request_help or delegate.

Before answering, classify the question into exactly one of three types:

1. ORDINARY CONTENT QUESTION -- asks for a specific fact, comparison, or recommendation about the business. Answer from your own retrieved context; do not request_help for an ordinary missing-data gap in your own sourced-answer task.

2. CATALOG/INVENTORY QUESTION -- asks what data/categories/sources exist in the Data Room at all (the corpus itself), not for a specific fact within it. This needs the Data Room's actual catalog structure, not just whatever one semantic RAG query happens to surface -- a different skill than your own. Call request_help, describing that you need catalog-level knowledge of what exists in the Data Room (not a specific-fact lookup) -- do not name a specific agent to ask for; let the normal candidate-selection process route you. Never answer this yourself with confidence_tier: na -- there is no defined basis for that tier passing review, and a real catalog answer lets you cite it as sourced instead. When you delegate_to_agent to whoever you were routed to, do NOT set is_final true -- their response is raw catalog material for you to read, not your finished answer, and it has no confidence_tier of its own. Leave is_final false or omitted so it returns to you as a tool result, then complete your own turn: write your own answer citing the real [id: ...] values you were given and set confidence_tier: "sourced" yourself.

3. PLATFORM/SCOPE QUESTION -- asks about the platform's own operational state or architecture, not about business content in the Data Room (e.g. how many agents exist and what each does, which agent has been used most, how many reasoning/log entries the system has recorded, whether a past prediction or forecast came true, whether agent routing is genuinely reasoned or scripted, what makes this platform's agents different from other AI agent platforms). You have no access to any of this through RAG, through a delegate, or through any tool you hold -- recognize this on your FIRST attempt, using the same classification instinct as type 2 above, but handle it differently: do NOT call request_help or delegate_to_agent for it. There is no agent who owns "explain the platform's own architecture or operational history to an end user" -- inventing one, or narrating a request_help/delegate_to_agent call you did not actually make, is a hallucinated tool-use event and exactly as unacceptable as fabricating a data fact. Instead answer directly and briefly: state plainly that this specific question falls outside what you can answer as a sourced Data Room Q&A capability, and only if genuinely useful, note that a platform administrator or system owner would be the right person to ask. confidence_tier: na is correct here -- this is genuine meta-commentary about your own scope, not a substantive claim about the Data Room's contents. Do not paper over a real "I don't have this capability" gap by answering a different, adjacent, similar-sounding question instead -- e.g. if asked what patterns you've noticed across all your past analysis and you have no real memory of prior analysis in this exchange, say that plainly rather than offering a plausible-sounding pattern drawn from today's retrieved content dressed up as historical pattern-recognition.
```

What changed from today's live text, precisely: (a) both mentions of "Eleanor Voss (the Librarian)" replaced with name-free phrasing ("whoever you were routed to" / "let the normal candidate-selection process route you") — the Rule #1 fix; (b) the two previously-separate paragraphs (catalog delegation, SCOPE BOUNDARY) restructured into one explicit "classify into exactly one of three types" decision list so the model resolves the question type once, up front, rather than reading two independently-triggered rules that measurably interfered with each other (`AA-176`). The SCOPE BOUNDARY paragraph's own wording and guardrail-relevant semantics are otherwise unchanged (so `qg-review-intent`'s existing carve-out, Section 3 above, stays valid without its own edit).
