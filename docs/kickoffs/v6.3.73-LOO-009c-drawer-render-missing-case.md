## CONTEXT

Found live 2026-07-20 during the design session's own Manual QA of `S-LOO-009b` (not accepted from the coding report alone — a live reproduction of the exact original bug scenario, run through to its final display hand-off). A final delegation resolved correctly (`delegation_complete.toAgentId` matched the real completing agent, confirmed via DOM inspection) but its hop card rendered **completely blank** — no text at all.

Root cause: there are two separate functions that turn a stored event into display text. `describeDelegationEvent` (the transient chat status line, e.g. "Marcus is thinking…") was updated in `S-LOO-009b` Task 3 to handle `delegation_complete`. `describePipelineEvent` — a *separate* function, used by `RoutingActivityLine` to render the **persistent** Agent Routing drawer row — was not. Its switch statement has explicit cases for `delegation`/`delegation_return` but falls through to a blank default (`{ summary: "", color: T.muted }`) for any unrecognized type, including the new `delegation_complete`. This is a gap in `S-LOO-009b`'s own Task 3 spec, not a regression — `delegation_complete` is a brand-new event type; nothing rendered it before because nothing existed to render.
