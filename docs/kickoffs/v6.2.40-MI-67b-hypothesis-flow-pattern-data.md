## 2. CONTEXT

`MI-67` (v6.2.37, merged) fixed `callCapability()` to stop discarding real `patterns_used`. Running this design session's own live Manual QA against the real dev deployment (per `CLAUDE-DESIGN.md` Step 5b — verify directly, not indirect) surfaced a **second, narrower version of the same bug**, one layer above `callCapability()`, in the two Priya hypothesis-flow wrapper functions that don't just forward `callCapability()`'s return — they reconstruct a new object from part of it:

**Confirmed live (real dev URL, real question, real hypothesis flow), not theorized:**
1. **`generateHypotheses()` (L777, unchanged by `MI-67`):** `return gen.hypotheses || [];` — returns a bare array, discarding `gen.patterns_used` entirely. Its caller (`enterHypothesisFlow`, L2029) does `data: { candidates }` — so the "Generated N hypothesis candidates" row shows **no pattern line at all**, live-confirmed (real row: `Priya / Hypothesis Evaluation / Generated 4 hypothesis candidates · 26.8s` — capability name only, no patterns, despite `hyp-generation-intent` genuinely using `rag`+`structured-output`).
2. **`runHypothesisTest()` (L821-825, unchanged by `MI-67`):** its final return is either a hand-built object (string-content branches, no `patterns_used` field at all) or `display` verbatim (object branch) — `display` being the **display/hand-off step's** result (`hyp-hypothesis-test-display-intent`, real patterns `tool-use`/`agent-delegation`/etc.), not the **analysis step's** (`hyp-hypothesis-test-intent`, real patterns `rag`+`structured-output` — the actual stress-test Priya performed). The caller logs this return value directly as the "hypothesis_test" event's `data` (`logEvent({ type: "hypothesis_test", ..., data: st, ... })`). Live-confirmed: the "Hypothesis test complete" row showed `Structured Output, Tool Use, Prompt Chaining, Guardrails / Output Filtering, Agent Delegation` — the **display** step's patterns, misattributed to the row representing Priya's **analysis**. This is worse than showing nothing: it's real data, attached to the wrong step.

Both gaps are the same causal family as `MI-67`'s root cause (a wrapper function between `callCapability()` and `onEvent()` drops or misroutes `patterns_used` when it reconstructs its return value) — `MI-67`'s fix only reached the one choke point (`callCapability()` itself); these two functions sit one layer above it and weren't in that kickoff's scope because the gap wasn't yet known. Per `CLAUDE-DESIGN.md` Step 5c ("Any FAIL → full root cause analysis... a bug that fails QA once must not fail QA twice") and the project's standing "No Blind Fixes" rule, this is that root-cause pass, done before writing this patch — not a guess.

**Duplicate-functionality / layer check:** no new function needed — both existing wrapper functions already have exactly the data (`gen`/`analysis`) this patch needs; the fix is purely preserving/redirecting a field already in scope at each return statement.

**Cross-reference integrity:** `RoutingEventRow`/`AI-50c`'s real-data-preferred logic (`MI-67`) is unchanged and correct — it already does the right thing with whatever `evt.data.patterns_used` it's handed. This patch's job is only to hand it the right value.

## 5. TASKS

### Task 1 — `src/screens/MarketIntelligenceScreen.jsx`: preserve/redirect `patterns_used` through both hypothesis-flow wrappers

**1a. `generateHypotheses()` (~L768-778)** — return `patterns_used` alongside the existing hypotheses array, don't just return the bare array:

```jsx
async function generateHypotheses({ flaggedQuestion, flaggedAnswer, reviewReason }) {
  const gen = await callCapability({
    capability_slug: "hypothesis-evaluation", intent_slug: "hyp-generation-intent", agent_id: "priya",
    task_context: {
      flagged_question: flaggedQuestion,
      flagged_answer: flaggedAnswer || "",
      review_reason: reviewReason || "user-initiated, no explicit claim extracted",
    },
  });
  // FEATURE: MI-67b — patterns_used was being discarded here, one layer above callCapability()'s
  // own MI-67 fix; the caller needs both the hypotheses array (unchanged shape/contract) and the
  // real patterns for its Agent Routing log event.
  return { hypotheses: gen.hypotheses || [], patterns_used: gen.patterns_used || [] };
}
```

**Caller** (`enterHypothesisFlow`, ~L2027-2029) — destructure both, keep `candidates`' existing contract (still a bare array everywhere else it's used: `hypFlow.candidates`, `EvidenceColumn`'s `.map()`, etc.) unchanged:

```jsx
const { hypotheses: candidates, patterns_used } = await generateHypotheses({ flaggedQuestion, flaggedAnswer, reviewReason });
logEvent({ type: "hypothesis_generation", agentId: "priya", data: { candidates, patterns_used }, durationMs: Date.now() - t0 });
setHypFlow(prev => prev && ({ ...prev, stage:"choosing", candidates }));
```

**1b. `runHypothesisTest()` (~L821-825)** — override `patterns_used` on every returned shape to `analysis.patterns_used` (the real stress-test call's patterns), not `display`'s (the separate hand-off step, already correctly shown on its own `display_format` event, L811 — unaffected by this change):

```jsx
  // FEATURE: MI-67b — this function's return value (`st`) becomes the "hypothesis_test" event's
  // data — it must carry the ANALYSIS step's real patterns (this function's own hyp-hypothesis-
  // test-intent call), not the DISPLAY step's (hyp-hypothesis-test-display-intent, already
  // correctly attributed to the separate display_format event two lines above). Every branch below
  // explicitly sets patterns_used from `analysis`, overriding whatever `display` itself carries.
  return typeof display === "string"
    ? { headline: display, supports: null, complicates: null, consider: null, confidence: null, display_agent_card: null, display_agent_id: null, selection: null, patterns_used: analysis.patterns_used || [] }
    : typeof display.content === "string"
    ? { headline: display.content, supports: null, complicates: null, consider: null, confidence: null, display_agent_card: display.display_agent_card, display_agent_id: display.display_agent_id, selection: display.selection, patterns_used: analysis.patterns_used || [] }
    : { ...display, patterns_used: analysis.patterns_used || [] }; // final_delegation shape: every intelligence-review-format field + display_agent_card/id/selection, patterns_used overridden to the real analytical call's
}
```

Nothing else in either function changes. Update the version header comment on line 1.

## 8. NODE.JS TEST

```js
// test-MI-67b.mjs
// Pure logic tests — no app imports. Mirrors generateHypotheses()'s new return shape (Task 1a)
// and runHypothesisTest()'s patterns_used override (Task 1b). Category M.

let pass = 0, fail = 0;
function assert(desc, cond) {
  if (cond) { console.log(`  ✓ ${desc}`); pass++; }
  else       { console.error(`  ✗ ${desc}`); fail++; }
}

// T1: generateHypotheses()'s return — mirrors the fixed shape
function generateHypothesesResult(gen) {
  return { hypotheses: gen.hypotheses || [], patterns_used: gen.patterns_used || [] };
}
assert("T1a: hypotheses array preserved unchanged",
  JSON.stringify(generateHypothesesResult({ hypotheses: [{id:"H1",text:"x"}], patterns_used: ["rag","structured-output"] }).hypotheses)
  === JSON.stringify([{id:"H1",text:"x"}]));
assert("T1b: patterns_used now carried alongside hypotheses",
  JSON.stringify(generateHypothesesResult({ hypotheses: [], patterns_used: ["rag","structured-output"] }).patterns_used)
  === JSON.stringify(["rag","structured-output"]));
assert("T1c: missing patterns_used defaults to empty array",
  Array.isArray(generateHypothesesResult({ hypotheses: [] }).patterns_used));

// T2: runHypothesisTest()'s patterns_used override — mirrors the fixed return, all 3 branches
function hypothesisTestResult(display, analysisPatterns) {
  return typeof display === "string"
    ? { headline: display, patterns_used: analysisPatterns || [] }
    : typeof display.content === "string"
    ? { headline: display.content, patterns_used: analysisPatterns || [] }
    : { ...display, patterns_used: analysisPatterns || [] };
}
assert("T2a: object-shape display gets analysis's patterns, not its own",
  JSON.stringify(hypothesisTestResult({ supports: {}, patterns_used: ["tool-use","agent-delegation"] }, ["rag","structured-output"]).patterns_used)
  === JSON.stringify(["rag","structured-output"]));
assert("T2b: string-decline display still carries analysis's real patterns, not an empty array",
  JSON.stringify(hypothesisTestResult("Declined.", ["rag","structured-output"]).patterns_used)
  === JSON.stringify(["rag","structured-output"]));
assert("T2c: string-content display (Riley shape) also carries analysis's patterns",
  JSON.stringify(hypothesisTestResult({ content: "raw html" }, ["rag","structured-output"]).patterns_used)
  === JSON.stringify(["rag","structured-output"]));
assert("T2d: display's own fields (e.g. supports) survive the override untouched",
  hypothesisTestResult({ supports: { text: "x" }, patterns_used: ["tool-use"] }, ["rag"]).supports.text === "x");

console.log(`\n${pass + fail} tests — ${pass} passed, ${fail} failed`);
if (fail > 0) process.exit(1);
else console.log("ALL TESTS PASS");
```
