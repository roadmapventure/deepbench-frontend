## CONTEXT

Found live 2026-07-20 during the design session's own Manual QA of `S-LOO-009b`/`S-LOO-009c`. In a `request_help` → `delegationRequired` auto-resolve chain (e.g. Marcus asks who should format the answer → Michelle picks Alex), there are genuinely **two** hand-offs: requester→broker (Marcus→Michelle), then broker→final target (Michelle→Alex). `S-LOO-009` added `delegation_complete` for the *second* leg only (the final target) — the broker's own leg never gets any completion signal from either mechanism. Confirmed not agent-specific: the harness resolves the broker generically via `resolveCapabilityHolder('project-manager')`, never a hardcoded agent id — whoever holds that capability today would hit the identical gap.

Why this specific path is missing it: the *ordinary* (non-`delegationRequired`) `request_help` path already fires `delegation_return` correctly for the broker's leg, via the `returningFromAgentId`/tail-of-function block. But the `delegationRequired` auto-resolve path takes an early `return { outcome: 'final', ... }` that never reaches that block — so its broker leg is structurally invisible. Confirmed this used to *appear* to work before `S-LOO-009b`: `display`'s old `agent_selection` `hopEvents` declaration (removed in `S-LOO-009b` Task 4) happened to resolve the broker's placeholder by coincidence of a matching agent id, not because the mechanism understood the hand-off — removing it exposed the gap rather than causing a new one.
