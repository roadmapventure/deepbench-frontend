## 2. CONTEXT

**The gap, plainly.** The audit log can say *what* the platform did but not *which screen it was launched from*. Every screen funnels through `/api/capabilities/execute` (§19b); `feature` records `<capability>:<intent>:<depth>` (what ran), and `call_source` records `ui`/`script`/`regression`/`session-test` (how). So a Channel Sales Intelligence run and a Live Agent Console run log identically. Found live 2026-08-10 answering "which dashboard screens were run in the past 2 days" — the capability content was answerable, the screen origin was not.

**Mechanism, decided in the design conversation before this kickoff: derive it from the address the browser already sends.** The row's original fix direction proposed a new `x-db-screen-origin` header set by the frontend. That was rejected in favour of reading `Referer`, for one measured reason: the frontend sets **no** custom headers anywhere today, so the header route needs new plumbing at ~10 call sites across 8 files to reach every screen — well past this session's file budget, which would leave Teach, Bench, Personnel File, Project Management and Spend Analysis permanently unattributed (there is no backfill — §19i). Reading the address covers every screen at once with zero frontend edits, in the same single choke point `LOG-121` already established.

**Both halves of that mechanism were proven live on dev before this kickoff was written, with controls:**

1. *The header survives the trip into our code.* Two identical POSTs to `/api/rag-query` on the live dev deployment, four seconds apart, differing by nothing but a `Referer` header: the one without logged `call_source: 'script'`, the one with logged `call_source: 'ui'`. That flip is only possible if the header reached `lib/request-context.js` intact through Vercel's edge, the `HAR-33` gate, and the function boundary. The control matters — if the header were being stripped, both rows would read `script`.
2. *The browser sends the full path, not just the origin.* Navigating from `/channel-intelligence` to `/bench`, the destination page reported its referrer as `https://<host>/channel-intelligence` — the whole path. This deployment serves no `Referrer-Policy` header (measured on the document response) and `index.html` carries no meta referrer, so the browser default applies.

**Why nested and delegated calls come along for free.** `lib/activity-log.js` reads its context from `AsyncLocalStorage`, so every row written during a request inherits it — including the depth-1+ agent turns that happen server-side and never touch a browser. That is already true of `call_source`; this rides the same store and needs no extra work.

**The recorded value is the screen's NAME, never the address.** Two load-bearing reasons: `/bench/<agent>` and `/work/<task>` carry identifiers, and this column is read from the browser with the anon key (the `LOG-124` lesson) — so the raw path is read and discarded. And the address deliberately disagrees with the name in two places, because the nav label is canonical and the route is not (`docs/SCREEN-INVENTORY.md`, both entries corrected this session against the shipped literals after John's live correction):

| Address the browser sends | Recorded as |
|---|---|
| `/` and `/live-agent-view` | `live-agent-console` |
| `/channel-intelligence` | `channel-sales-intelligence` |
| `/work` | `project-management` |
| `/work/new` | `create-work-order` |
| `/work/<task>` | `task-instructions` |
| `/work/<task>/analyze` | `spend-analysis` |
| `/work/<task>/fetch` | `fetch` |
| `/bench` | `agent-roster` |
| `/bench/new` | `add-agent` |
| `/bench/test` | `test-my-team` |
| `/bench/<agent>` | `personnel-file` |
| `/bench/<agent>/teach` | `teach` |

**The migration is already applied — do not write one.** The parent design session applied `screen_origin` (nullable `text`) plus its `anon`/`authenticated` SELECT grant before writing this kickoff, deliberately: `logActivity()` POSTs a JSON body to PostgREST with a swallowed `.catch(() => {})`, so if this code deployed before the column existed, PostgREST would reject every insert and **every audit row would be silently lost**. Column first removes that race entirely. Verified live after applying: the column exists, `anon` can SELECT it, and `caller_ip` is still withheld (`LOG-124`'s lockdown intact).

**Accepted limits, unchanged from `call_source`.** A non-browser caller can forge a `Referer`, exactly as it can forge `x-db-call-source`. This is self-declared attribution for separating traffic John controls, not a security boundary (`docs/harvests/LOG-121.md`). Worth noting it is *stronger* than `call_source` for real browser traffic: page script cannot set `Referer` — it is a forbidden header name, written by the browser itself.

**Task 1 — `lib/request-context.js`: the route→screen map and its matcher.**

Add near `deriveCallerIp`/`deriveDeviceType` (same style — pure, header-only, cannot throw):

```js
// FEATURE: LOG-138 -- which screen launched the run. The browser already sends the page address on
// every same-origin request; nothing in the frontend changes. Proven live 2026-08-10 both
// directions: a request carrying only a Referer logged 'ui' where the identical request without one
// logged 'script' (so the header survives Vercel's edge, the HAR-33 gate and the function boundary
// intact), and a real browser navigation reported the FULL path, not the bare origin -- this
// deployment serves no Referrer-Policy and index.html has no meta referrer, so the browser default
// applies. Forgeable by a non-browser caller exactly as x-db-call-source is: self-declared
// attribution, not a security boundary (docs/harvests/LOG-121.md). Stronger than call_source for
// real browsers, though -- page script cannot set Referer, it is a forbidden header name.
//
// THE VALUE IS THE SCREEN'S NAME, NEVER THE ADDRESS. /bench/<agent> and /work/<task> carry
// identifiers and this column is read from the browser with the anon key (the LOG-124 lesson), so
// the path is read and discarded. The address deliberately disagrees with the name in two places
// (/live-agent-view -> live-agent-console, /channel-intelligence -> channel-sales-intelligence)
// because the nav label is canonical and the route is not (docs/SCREEN-INVENTORY.md). Do NOT
// "fix" either to match the other.
//
// ORDER IS SIGNIFICANT -- the literal /bench/test, /bench/new and /work/new must be tested BEFORE
// the /bench/<agent> and /work/<task> patterns, or "test"/"new" are read as ids. Same specificity
// ordering react-router applies in src/main.jsx; keep this list in sync with that file's <Route>s.
// An unmatched path returns null (unattributed), never a guess -- same posture as
// ALLOWED_CALL_SOURCES. A route added later without an entry here shows blank, which is visible
// and honest; the one edit that MUST be paired is re-pointing "/" (see docs/SCREEN-INVENTORY.md's
// LA-01 precondition), because "/" currently serves the Live Agent Console.
const SCREEN_ROUTES = [
  [/^\/$/,                        'live-agent-console'],
  [/^\/live-agent-view\/?$/,      'live-agent-console'],
  [/^\/channel-intelligence\/?$/, 'channel-sales-intelligence'],
  [/^\/work\/?$/,                 'project-management'],
  [/^\/work\/new\/?$/,            'create-work-order'],
  [/^\/work\/[^/]+\/analyze\/?$/, 'spend-analysis'],
  [/^\/work\/[^/]+\/fetch\/?$/,   'fetch'],
  [/^\/work\/[^/]+\/?$/,          'task-instructions'],
  [/^\/bench\/?$/,                'agent-roster'],
  [/^\/bench\/new\/?$/,           'add-agent'],
  [/^\/bench\/test\/?$/,          'test-my-team'],
  [/^\/bench\/[^/]+\/teach\/?$/,  'teach'],
  [/^\/bench\/[^/]+\/?$/,         'personnel-file'],
];

function deriveScreenOrigin(headers) {
  const raw = headers.referer;
  if (!raw) return null;
  let url;
  try {
    url = new URL(String(raw));
  } catch {
    return null; // not a parseable absolute URL -- unattributed, never an exception
  }
  // Only OUR OWN pages may name a screen. A foreign referer is somebody else's site and says
  // nothing about our UI -- the same same-host test hasBrowserSignal() already applies.
  const host = headers.host ? String(headers.host) : null;
  if (!host || url.host !== host) return null;
  for (const [pattern, slug] of SCREEN_ROUTES) if (pattern.test(url.pathname)) return slug;
  return null;
}
```

## 7. SCOPE RULES
- Do **not** touch any file under `src/`. If you find yourself wanting to set a header in a screen, stop — that is the approach this design measured and rejected.
- Do **not** write a migration or alter any table. The column and its grant already exist (Section 2).
- Do **not** put `screen_origin` into `call_facts`, `log_row_signature()`, any view body, or any criteria. Plumbing column only (Section 3).
- Do **not** store the raw path, the query string, or the full referer URL — only a slug from `SCREEN_ROUTES`, or `null`.
- Do **not** coerce an unrecognized path to a default, a "other"/"unknown" bucket, or the nearest match. Unmatched is `null`.
- Do **not** let anything in this change throw, reject, or block a request — `lib/request-context.js`'s standing rule, stated in its own header.
- Do **not** consult `Origin` as a fallback when `Referer` is absent: `Origin` carries no path, so it can only ever produce a wrong screen or a redundant null.
- Do **not** rename the routes or the component filenames to match the slugs (Section 2's table is intentional).

## 8. NODE.JS TEST (full code — save as `test-log-138.mjs`, delete before committing)

```js
// test-log-138.mjs — S-LOG-138 (v7.0.90). Category B.
import assert from 'node:assert';
import { withRequestContext, getRequestContext } from './lib/request-context.js';

const HOST = 'deepbench.example';
async function contextFor(headers) {
  let seen;
  await withRequestContext(async () => { seen = getRequestContext(); })(
    { headers }, { setHeader() {}, headersSent: false });
  return seen;
}
const originFor = async (path) =>
  (await contextFor({ host: HOST, referer: `https://${HOST}${path}` })).screenOrigin;

// --- every route in src/main.jsx maps to its screen's NAME, not its address
assert.equal(await originFor('/'),                       'live-agent-console');
assert.equal(await originFor('/live-agent-view'),        'live-agent-console');
assert.equal(await originFor('/channel-intelligence'),   'channel-sales-intelligence');
assert.equal(await originFor('/work'),                   'project-management');
assert.equal(await originFor('/work/new'),               'create-work-order');
assert.equal(await originFor('/work/8214'),              'task-instructions');
assert.equal(await originFor('/work/8214/analyze'),      'spend-analysis');
assert.equal(await originFor('/work/8214/fetch'),        'fetch');
assert.equal(await originFor('/bench'),                  'agent-roster');
assert.equal(await originFor('/bench/new'),              'add-agent');
assert.equal(await originFor('/bench/test'),             'test-my-team');
assert.equal(await originFor('/bench/nadia'),            'personnel-file');
assert.equal(await originFor('/bench/nadia/teach'),      'teach');

// --- ORDERING: the literals must beat the id patterns. These are the assertions that fail if the
//     map is ever reordered -- "new"/"test" must never be read as a task or agent id.
assert.notEqual(await originFor('/bench/test'), 'personnel-file', 'ordering regression: /bench/test read as an agent id');
assert.notEqual(await originFor('/bench/new'),  'personnel-file', 'ordering regression: /bench/new read as an agent id');
assert.notEqual(await originFor('/work/new'),   'task-instructions', 'ordering regression: /work/new read as a task id');

// --- a trailing slash and a query string must not defeat the match
assert.equal(await originFor('/channel-intelligence/'), 'channel-sales-intelligence');
assert.equal(await originFor('/bench?tab=all'),          'agent-roster');

// --- UNRECOGNIZED PATH -> null. Never a guess, never a nearest match, never a bucket.
assert.equal(await originFor('/some-future-screen'), null);
assert.equal(await originFor('/work/8214/unknown-child'), null);
assert.equal(await originFor('/bench/nadia/teach/extra'), null);

// --- A FOREIGN referer must never name one of our screens, even on a path shaped like ours.
let ctx = await contextFor({ host: HOST, referer: `https://evil.example/channel-intelligence` });
assert.equal(ctx.screenOrigin, null, 'a foreign referer must never name a DeepBench screen');

// --- absent/malformed referer degrades to null and never throws (this file's standing rule)
assert.equal((await contextFor({ host: HOST })).screenOrigin, null);
assert.equal((await contextFor({ host: HOST, referer: 'not-a-url' })).screenOrigin, null);
assert.equal((await contextFor({ referer: `https://${HOST}/bench` })).screenOrigin, null, 'no host header -> cannot prove same-origin -> null');
assert.equal((await contextFor({})).screenOrigin, null);

// --- THE RAW PATH MUST NEVER SURVIVE. Identifiers in the address must not reach the context.
ctx = await contextFor({ host: HOST, referer: `https://${HOST}/bench/nadia` });
assert.equal(ctx.screenOrigin, 'personnel-file');
assert.equal(JSON.stringify(ctx).includes('nadia'), false, 'an agent id from the address must never reach the logged context');
ctx = await contextFor({ host: HOST, referer: `https://${HOST}/work/8214/analyze?secret=x` });
assert.equal(JSON.stringify(ctx).includes('8214'), false, 'a task id from the address must never reach the logged context');
assert.equal(JSON.stringify(ctx).includes('secret'), false, 'a query string must never reach the logged context');

// --- purely additive: the five LOG-121/LOG-130 fields are unchanged by this feature
ctx = await contextFor({ host: HOST, referer: `https://${HOST}/channel-intelligence`, 'x-db-call-source': 'regression' });
assert.equal(ctx.callSource, 'regression', 'screen origin must not influence call_source');
assert.equal(ctx.screenOrigin, 'channel-sales-intelligence', 'a non-ui caller may still carry a screen origin');
ctx = await contextFor({ host: HOST, 'sec-fetch-site': 'same-origin' });
assert.equal(ctx.callSource, 'ui');
assert.equal(ctx.screenOrigin, null, 'a browser with no referer is ui with no screen -- not a guess');

console.log('ALL TESTS PASS');
```
