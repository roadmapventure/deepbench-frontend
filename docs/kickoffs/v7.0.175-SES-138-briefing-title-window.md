## 2. CONTEXT

Cycle `702aa2db` found this live at 02:20Z tonight, on the served artifact rather than by
reasoning: after the `v7.0.173` rebuild the briefing came back named **"briefing-out"** — the
build file's *filename* — instead of **"DeepBench Morning Briefing"**. John finds this page by its
name in his artifact gallery and by its browser tab, so a rebuild that silently renames it is a
real defect.

**Root cause, and it is not a typo.** The Artifact tool scans only the **first 8192 bytes** of a
file for a `<title>`. `briefing-template.html` opens with its provenance comment block — eleven
comments, one per ship — so the `<title>` tag is present, correct, and *never seen*.

**Revalidated live this cycle (`SES-87`, register B7), and the measurement moved while being
taken:**

| | byte offset of first `<title>` | inside the 8192 window |
|---|---|---|
| `SES-138` as filed, 02:20Z | 24,537 | no |
| measured this cycle, 02:34Z | **24,770** | no |

**233 bytes in fourteen minutes.** That is the ratchet the ticket describes, demonstrating itself
inside one cycle: every ship prepends one more comment, so the offset only ever grows. The premise
is not merely alive, it is worsening on the clock.

**The half that decides the fix.** The ticket offers (a) pass `title:` on every publish or
(b) move the tag above the comment block, and recommends (b) with (a) as belt-and-braces. That is
right, and the reason is this platform's most expensive recurring lesson: (a) alone is *a rule
every future cycle must remember*, which is the exact shape `SES-86` phase 3, `v7.0.146`,
`SES-101`, `SES-111`, `SES-127`, `SES-128` and `SES-129` each had to convert from prose into
structure. Seven precedents is enough. **(b) makes the file correct by construction; (a) and the
post-publish assertion are the belt and braces; the regression test is what stops (b) being
quietly undone** by the very habit that caused this — a cycle prepending its provenance comment at
byte 0.

**Measured and deliberately NOT changed: the self-publish path is already correct.** `doc()` at
template line ~1178 emits `<!doctype html><html><head>…<title>` with the tag inside the first ~150
bytes, so John's own taps have never been able to rename the page. Only a *cycle* publishing the
template-derived file hits this. Widening the fix to `doc()` would be changing a path that works.
