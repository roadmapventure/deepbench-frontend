## Check 12 — a rule statement restated outside its canonical home

**ID-anchored with an overlap test, and the first half is inherited rather than invented.** Check
9's own header already establishes that the registry `statement` is a *paraphrase*, so matching it
against prose "ships a check that can never fire." So the rule ID finds the candidate and the
overlap decides whether the passage is a **copy** or a **citation** — this repo is full of
legitimate citations ("register B42", "per B24"), and a check that flagged those would emit ~113
findings and be switched off within a day.

**The threshold was measured, not felt.** Live at this ship: **113** live-rule ID occurrences
outside their canonical homes. Excluding rendered blocks, the overlap distribution is a continuum
with **no natural gap** — so the line is drawn where the words themselves justify it rather than at
a trough that does not exist: **0.9** means the passage reproduces essentially the whole statement,
which is a copy by any reading, where 0.5 only means it discusses the same subject. That yields
**3 findings** (`B34`, `B12`, `B18`), and 0 at 0.95.

**WARN, not FLAG**, on the same reasoning `v7.0.242` used one cycle earlier to draw the gating line:
the canonical text is intact and correct; these are duplications awaiting `SES-201`'s marker
migration, which is that ticket's whole job. Promoting check 12 to FLAG is right *after*
`SES-201` drives the population to zero, not in advance of it — and because checks 12/13 are not in
the gating set, this ship leaves `--gate` clear.

**A rendered `{{rule:ID}}` block is exempt**, because a marked block regenerates from the registry
row and cannot drift — flagging it would tell every cycle to undo `SES-175`.

**Two bugs found while building it, both fixed rather than shipped past:**

1. **An index mismatch.** The first form found occurrences in `stripHtmlComments(raw)` and then
   sliced the block out of `raw`. Stripping shifts every index after the first comment, so the
   window landed on the wrong passage. Occurrences and the block now both come from the raw text,
   and the *block* is stripped for the overlap test — which is what makes both properties hold at
   once (the marker lives in a comment; provenance prose is not a restatement).
2. **The wrong window.** Reusing check 9's `enclosingBlock()` found **1 of the 4** copies, because
   its ±280-character window is sized for a proximity question and governance paragraphs run
   longer. Check 12 asks whether a passage *reproduces* a statement, so it uses the paragraph.
   A checker reporting a quarter of what it can see is the "green while looking at nothing" failure
   in a milder costume.

## Check 13 — one procedure, two live homes

Mechanical, no threshold: identical normalised fenced blocks in two different docs. Comment lines
are stripped before hashing, so the same SQL under two different explanatory headers still reads as
one procedure — which is exactly the case worth catching.

**It reads a wider doc set than checks 9–12, and that is the point.** Those scan the *rules'* docs
(canonical homes plus runbooks). A duplicated procedure can live anywhere a procedure is written
down, and the live case proves it: `docs/GOVERNANCE-MODES.md` is nobody's `canonical_doc`, so the
rule-doc set misses the very instance the ticket cites. The set is **derived** (root `*.md`,
`docs/*.md`, `docs/runbooks/*.md`) rather than hand-listed, minus the **history** files —
`SESSIONS.md` and `FEATURES-ARCHIVE.md` quote procedures as a *record*, which is correct and must
never be flagged as a second home.

Measured: **63 docs, 181 qualifying blocks, exactly 1 duplicate** — the `B40` claim SQL at
`docs/GOVERNANCE-MODES.md:47` and `docs/runbooks/runner-cycle.md:1459`, precisely what the ticket
names. **FLAG**, because two live copies of an *executable* procedure drift silently and then one
of them is wrong.
