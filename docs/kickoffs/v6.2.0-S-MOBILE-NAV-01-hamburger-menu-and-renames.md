## 2. CONTEXT

Follow-on to `S-MI-45` (mobile MI body, shipped `v6.1.46`). John live-verified `S-MI-45` on a real iPhone via screenshot — the chat/routing-feed split worked correctly, but the screenshot also showed the header (`AppShell.jsx`, out of `S-MI-45`'s scope) overlapping badly: the Work/Bench nav, AI Audit button, and About button all collide because none of them account for a narrow viewport (the Work/Bench nav is `position:absolute; left:50%`, independent of flex layout).

Design was iterated live against an interactive HTML mock that first **recreated the actual broken header from John's screenshot exactly** (same overlap, same root cause), then a proposed hamburger-collapse. Five follow-up questions were asked and answered one at a time; all five locked as shown below. John then added four more instructions in the same message, all incorporated:

**Locked decisions (all confirmed by John, do not re-litigate):**
1. **Header collapse:** below `MOBILE_BREAKPOINT` (768px, `useIsMobile()`), the header shows logo + a shrunk (not dropped) "AI Workforce Platform" subtitle + a single hamburger trigger. Desktop's row (Work-dropdown, Bench tab, AI status dot, `rightContent`, `onBack`, AI Audit button, About button) is completely unchanged — gated by `useIsMobile()`, same construction pattern as `S-MI-45`.
2. **Menu shape:** the hamburger opens an **82%-width right-side drawer** with a dimmed (`rgba(18,36,60,.5)`) backdrop over the remaining viewport — **not** a full-screen takeover like `S-MI-45`'s Evidence/Activity overlays. Deliberate departure, John's call.
3. **Menu dismiss:** **both** the explicit × button **and tap-on-backdrop** close it — also a deliberate departure from Evidence/Activity's back-button-only rule (a nav menu is lower-stakes than content someone might be scrolling).
4. **Menu contents:** one unified list, grouped to match the desktop nav's own structure — "Work" (3 items, same destinations as the desktop Work dropdown), "Bench" (1 item), "Platform" (AI Audit, About DeepBench). Current route highlighted, same active-state visual treatment as the existing Left Sidebar Nav Pattern (`STYLE-GUIDE.md` §10 — brass left border, brass-tinted background).
5. **AI status dot:** dropped on mobile entirely, no replacement indicator.
6. **`rightContent`/`onBack`:** John's call — these don't belong in shared header chrome at all, they're a control that belongs in the calling screen's own body. **Not rendered on mobile.** This is a real, tracked gap (`SH-20`) for any screen currently relying on them (first known instance: Analyzer's "← Column Mapping"). **Explicitly deferred to a future session** — John: "let's work that on a future session." Do not attempt to fix it here.
7. **Version:** this is the start of a new mobile-development version line, `v6.2.x`. `S-MI-45` stays `v6.1.46` — not renumbered retroactively.
8. **Rename — "Market Intelligence" → "Channel Sales Intelligence"** everywhere a user reads it (display-text only, same pattern as `S-RENAME-01`): `AppShell.jsx`'s Work dropdown item + new mobile menu item, `MarketIntelligenceScreen.jsx`'s own page title + one line of empty-state copy, `WelcomeSplash.jsx`'s capability strip. **Unchanged:** the component filename, the `/` route, every `MI-*` feature ID, every `S-MI-*` session name, every internal variable/constant.
9. **Rename — "Bench" → "Agent Roster"** wherever it names the *screen* (display-text only): `RosterScreen.jsx`'s own headline ("Your bench." → "Your agent roster.") and the Bench item inside the new mobile menu. **The top-level nav tab stays "Bench"** — both the desktop `NavTab` label and the mobile menu's group label. John's explicit call: the primary nav label and the screen's own name are two different things.
10. **`AboutPanel.jsx` is explicitly out of scope** — it has two "Bench" mentions, one that plausibly should rename ("Bench Dashboard" describing the module) and one that plausibly shouldn't (an instructional step telling the user to click the "Bench" nav tab, which isn't renaming). Genuinely ambiguous, deliberately deferred rather than guessed.

`STYLE-GUIDE.md` §24 (Mobile Header) and §25 (Terminology) are already locked by this design session — they are the source of truth for every rule above; this Section 2 is context, §24-25 is the spec.

// test-S-MOBILE-NAV-01.mjs
// Pure logic tests — no app imports. Mirrors the mobile nav group data shape (Category B)

let pass = 0, fail = 0;
function assert(desc, cond) {
  if (cond) { console.log(`  ✓ ${desc}`); pass++; }
