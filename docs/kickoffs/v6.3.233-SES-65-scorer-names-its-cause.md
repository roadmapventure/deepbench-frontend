## 2. CONTEXT

**This is a reporting fix. It changes what the regression run *says*, never what it *decides*.**

Bucket 1's ship bar is the 24-case CHI regression run. Today that run can print `FAIL` for a question and list zero reasons — `case_pass: false`, `failed_criteria: []`. Measured four separate times on case 9 `vitrine-tech` (three runs in `S-AGT-44-design` QA, recorded on `DAT-16`; a fourth in `design-arch-beta-0729`'s pre-regression round 2).

**Mechanism, `scoreVerdict()` rich-answer branch (`scripts/chi-true-regression.mjs:344`):** `pass` comes from Owen Marsh — The Proofreader's own holistic flag (`:364`), which runbook §5 makes the bar (*"Any `pass: false` = that question FAILs on content"*). `failed_criteria` is built independently from a three-criterion loop (`:360`). When Owen fails an artifact on something none of those three cover, the two disagree and the reason list comes back empty.

**What is NOT wrong, and must not be "fixed" (design ruling, 2026-07-29, John approved):** `asked_metric_present` is absent from that loop **deliberately**. Runbook §5b's table states it outright — *"Rich-answer class (default): not scored"* — locked under `AGT-36b` (v6.3.225) with John's §8 approval. It cannot become a rich-answer gate as written: its own Skill instruction (`skill_profiles.qg-content-context-intent`) says *"If the question does not ask for a quantity at all, this is false"*, so on every non-quantitative question in the suite `false` is the **correct** reading and carries no signal. Gating on it would fail correct answers — precisely the failure `AGT-36b` removed when it replaced `quantitative_content_present`. Case 24 `news-first-card` is the live example: it asks for analysis of a news story, not a figure. **Task 4 writes this ruling into the runbook so it is not refiled as a bug a third time.**

**The reason was never actually lost — this is a summary defect, not data loss.** `judgeArtifact()` already returns the full verdict as `evidence` (`:380`), and Owen's Skill schema carries a `critique` string (≤300 chars, verified live in Supabase this session) plus a quoted `evidence` field on every criterion. `DAT-16` proves a reader can recover the reason from the existing output — that row quotes Owen verbatim on case 9: *"never names Brazil, never states Apple's compliance threshold, and never calculates or states what the actual gap is."* What is broken is that the field which is supposed to summarize *why* comes back empty, so anything reading `failed_criteria` — a human skimming the run, or any tooling built on it — sees a failure with no cause.

**Use the mechanism that already exists.** `finalizeCase()`'s `fail_causes` already carries reason detail inline for its other causes — `infra_death: <error>` and `journey_deviation (expected X, got Y)`. `judge_fail` is the one bare token in that list. Task 2 brings it in line with its siblings rather than introducing a parallel reporting channel.

**One disagreement direction stays open and is deliberately not fixed here.** The mirror case — Owen's flag reads `pass: true` while a scored criterion failed — would be a false green. It has never been observed on a scored criterion (the "false green" recorded on `SES-65`'s row is entirely `asked_metric_present`, i.e. the not-scored criterion above, not a defect). Resolving it would mean sourcing `pass` from `failed_criteria`, which **is** a scoring change and could flip currently-green cases red. Out of scope; Task 3 pins the current behavior so a later session cannot change it by accident, and Task 4 records it as a known, unobserved gap.

## 5. TASKS (4)

### Task 1 — a rich-answer failure can never carry an empty cause list (`scripts/chi-true-regression.mjs`)

In `scoreVerdict()`'s rich-answer branch only (`:360`–`:364`), after the existing criteria loop and the `platform_language_detected` push, add the invariant: if `pass` would be `false` and `failed_criteria` is empty, push the literal `"holistic_verdict"`.

```js
  const pass = verdict?.pass === true;
  if (!pass && failed_criteria.length === 0) failed_criteria.push("holistic_verdict");
  return { pass, failed_criteria };
```

Constraints, all three mandatory:
- **Scoring is untouched.** `pass` is still `verdict?.pass === true`. Nothing that passes today starts failing; nothing that fails today starts passing. The only change is the contents of `failed_criteria` in the one case where it was empty.
- **Do not add `asked_metric_present` to the loop** — see Section 2. The existing test at `AGT-36-honest-gap-scoring.js:104`–`110` pins this and must keep passing unmodified.
- **Do not touch the `honest-gap` branch** (`:349`–`:357`). It already derives `pass` from `failed_criteria`, so the invariant holds there by construction.

`"holistic_verdict"` is an honest name for what happened: Owen judged the artifact as a whole and failed it. It is not a sixth criterion and must not be added to Owen's Skill schema.

### Task 2 — Owen's own words reach the case record and the run's FAIL line (`scripts/chi-true-regression.mjs`)

**2a.** `judgeArtifact()` (`:380`) — add `critique` to the returned record, next to `failed_criteria`, reading it off the verdict:

```js
  return { artifact: artifact_type, outcome_class: ctx?.outcome_class || "rich-answer", pass, failed_criteria, critique: verdict?.critique ?? null, evidence: verdict };
```

`evidence` stays exactly as it is — this surfaces the field, it does not move it.

**2b.** `finalizeCase()` (`:602`) — `judge_fail` gains its detail inline, matching the shape `infra_death` and `journey_deviation` already use on the same list. Build it from the failing verdicts only:

```js
  if (!SKIP_JUDGE && !infraDeath && judgeVerdicts.some(v => v.pass !== true)) {
    const detail = judgeVerdicts.filter(v => v.pass !== true).map(v => {
      const why = v.failed_criteria.join(", ");
      return v.critique ? `${v.artifact}: ${why} -- "${v.critique}"` : `${v.artifact}: ${why}`;
    }).join(" | ");
    fail_causes.push(`judge_fail (${detail})`);
  }
```

The per-case console line at `:676` already prints `causes=` + `fail_causes.join(",")`, so it picks this up with no change there. **Do not edit `:676`.** If the joined line proves unreadably long in the live run, that is a Section 11 observation to report, not a reason to truncate Owen's text — the whole point is that the reason is visible.

### Task 4 — record the ruling and the known gap (`docs/runbooks/CHI-TRUE-REGRESSION.md`)

**4a.** In §5b, immediately under the criterion table (after `:114`, before the *"Why the guidance and jargon bars stay"* paragraph), add a note — do not edit the table itself:

> **Why `asked_metric_present` is *not scored* on the rich-answer path (ruling, 2026-07-29, `SES-65`).** This is deliberate, not an omission, and has now been raised as a bug twice. The criterion asks whether the artifact reports a figure for *the quantity the question asked about*; Owen's Skill instructs him to return `false` when the question asks for no quantity at all. On the rich-answer path most questions do not, so `false` is the correct reading there and carries no quality signal — gating on it would fail correct answers, the exact failure `AGT-36b` removed when it replaced `quantitative_content_present`. Case 24 `news-first-card` is the live example: it asks for analysis of a news story, not a figure. Making it a rich-answer gate is a §8 baseline change and would first require separating *"the answer omitted the asked-for number"* from *"no number was asked for"*, which the single boolean cannot express today. A genuine miss on a question that **does** ask for a figure — case 6 `upgrade-cycles` — is tracked as content, on `AGT-47`, not as a scorer defect.

**4b.** In §7 (Scoring), add:

> **A failure always names a cause (`SES-65`, v6.3.233).** `scoreVerdict()` cannot return `pass: false` with an empty `failed_criteria`: when Owen fails an artifact as a whole without any scored criterion failing, the list carries `holistic_verdict` and the run's own FAIL line carries his critique verbatim. `holistic_verdict` is a reporting marker, not a criterion — it is not in Owen's Skill schema and he is never asked about it.
>
> **Known, unobserved gap.** The mirror direction is not guarded: `pass: true` alongside a failing scored criterion would report a green case with a recorded failure. Never observed on a scored criterion. Closing it means sourcing `pass` from `failed_criteria` instead of Owen's flag — a scoring change under §8, deliberately not taken by `SES-65`.
