## 2. CONTEXT

**What exists.** Every write already leaves a `runner_before_images` row (§19v). A Reverse on a `ship` card replays that cycle's images through `apply_data_restore()`, which classifies each image (`restorable` / `unverifiable` / `refused`) and writes doubtful rows never. The trust ladder is written only by `apply_ladder_decision()`, keyed on John's card taps — an input that no longer arrives since `SES-285`.

**What does not exist, measured 2026-09-02:** no table records *a decision* — what was decided, why, when it becomes final, and how to undo it. `M6-02` promises a 72-hour window; `M6-05` promises decision-and-ticket in one transaction; `M6-06` promises a recorded reversal handle; `M6-07` promises the ladder promotes on an unreversed decision and demotes on a reversal. All four are `status = live`, and the SES-184 and SES-185 gate decisions, the `SES-82` de-scoping, the 33 `needs-john → needs-decision` conversions and the 7 `john-paced` conversions were each "reversible under M6-02" **by the availability of before-images alone** — there is no id John can hand back, no expiry, and no ladder effect. A rule marked `script` that no script runs.

**Design, decided here (M6-01, reversible):**

1. **A decision is a row.** `public.runner_decisions` holds the record; its reversal handle is its `id`. Before-images written under a decision carry `runner_before_images.decision_id`, so *"undo this decision"* is *"replay the images that name it, newest first."*
2. **The window is a column, not a literal.** `runner_settings.reversal_window_hours`, seeded `72` (the `SES-146` correction: every cadence number is a column). `expires_at` is computed at record time so a later change of the setting never moves an existing window.
3. **Silence is assent, mechanically.** `sweep_decision_windows()` finalises every open decision past its `expires_at` and, if the decision names a ladder work class, promotes that class by the `SES-107` rule (streak +1, rung +1 every 5th, streak never reset). One call, idempotent, run from the cycle tail (part b) and from attended close-outs (part b).
4. **A reversal restores and demotes.** `reverse_decision()` replays the decision's images through the same classification the restore engine uses, writes before-images of the reversal itself (so a reversal is reversible), marks the decision `reversed`, and demotes the named class (rung −1 floor 0, streak 0) — whether or not the window had closed. A decision nobody reversed is the only evidence of unattended judgment a tap never was; a decision somebody reversed is the strongest negative signal there is.
5. **One ladder writer for the new inputs.** `ladder_apply_signal(work_class, signal, actor_cycle, actor_session)` is the single function that moves `runner_ladder` on `promote` / `demote`. `apply_ladder_decision()` is left as it is (its gated short-circuit still protects the ledger); `SES-122` routes verifier verdicts through `ladder_apply_signal` and retires the tap path. `ladder_work_class(priority_class)` is extracted as an `IMMUTABLE` helper so the digit→class mapping has one home.
6. **Ledger tables are never replayed.** The restore allowlist for a decision reversal is the set of tables a decision may legitimately have changed: `backlog_items`, `runner_directives`, `runner_drain_scope`, `runner_settings`, `governance_rules`, `epics`. Everything else (`runner_cycles`, `runner_items`, `runner_before_images`, `runner_decisions`, `runner_ladder`, `runner_verdicts`, counters) is refused and reported — the same fail-closed direction `plan_data_restore()`'s `k_ledger` takes. Tables without `updated_at` (`runner_directives`, `runner_drain_scope`) are restored and reported as `restored_unverified`, because a John-initiated reversal is his explicit word, unlike the auto-rollback path where doubtful rows are never written; tables with `updated_at` refuse a row written after the image, exactly as the engine does.

**1b. The decision ledger.**
```sql
CREATE TABLE public.runner_decisions (
  id               uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  decided_at       timestamptz NOT NULL DEFAULT now(),
  cycle_id         uuid REFERENCES public.runner_cycles(id),
  session_name     text,
  kind             text NOT NULL,                 -- free text, e.g. 'ticket-status','ticket-scope','gate','removal','directive','settings','rule','reversal'
  backlog_id       text CHECK (backlog_id IS NULL OR backlog_id ~ '^[A-Z]+-[0-9]+[a-z]?$'),
  summary          text NOT NULL CHECK (length(btrim(summary)) > 0),
  reasoning        text NOT NULL CHECK (length(btrim(reasoning)) > 0),
  ladder_work_class text REFERENCES public.runner_ladder(work_class),
  expires_at       timestamptz NOT NULL,
  status           text NOT NULL DEFAULT 'open' CHECK (status IN ('open','final','reversed')),
  finalized_at     timestamptz,
  ladder_applied_at timestamptz,
  reversed_at      timestamptz,
  reversed_by      text,
  reversal_reason  text,
  reverses         uuid REFERENCES public.runner_decisions(id),   -- set on kind = 'reversal' rows
  CONSTRAINT ck_decision_attribution CHECK ((cycle_id IS NOT NULL) <> (session_name IS NOT NULL)),
  CONSTRAINT ck_decision_reversed_fields CHECK (status <> 'reversed' OR (reversed_at IS NOT NULL AND reversed_by IS NOT NULL))
);
CREATE INDEX ON public.runner_decisions (status, expires_at);
ALTER TABLE public.runner_before_images ADD COLUMN IF NOT EXISTS decision_id uuid REFERENCES public.runner_decisions(id);
CREATE INDEX ON public.runner_before_images (decision_id) WHERE decision_id IS NOT NULL;
REVOKE ALL ON public.runner_decisions FROM anon, authenticated;   -- service_role only, like every runner_ table
```

**1c. `ladder_work_class(p_priority_class text) RETURNS text IMMUTABLE`** — the digit CASE lifted verbatim from `apply_ladder_decision()` (`'2'→invention`, `'5'→enhancement`, `'7'→agent_creation`, `'8'→determinism_removal`, `'9'→bug_fix`, `'10'→tooling`, else NULL). Do **not** edit `apply_ladder_decision()` — `SES-122` owns that; the duplicate CASE is named in its kickoff as the thing it removes.

**1d. `ladder_apply_signal(p_work_class text, p_signal text, p_actor_cycle uuid, p_actor_session text) RETURNS TABLE(applied boolean, rung_before int, streak_before int, rung_after int, streak_after int, promoted boolean, reason text)`** — `VOLATILE`. `p_signal` ∈ `('promote','demote')`, else raise. Exactly one of the actor args non-null (mirror `ck_before_image_attribution`). Reads the class row (`FOR UPDATE`); `promote`: `streak+1`, `promoted := (streak % 5 = 0)`, `rung + 1` if promoted, streak **not** reset (`SES-107`, John's "no reset"); `demote`: `streak 0`, `rung greatest(rung-1,0)`. Writes the `runner_ladder` before-image (attributed to the actor) **before** the update. No `runner_items` involvement.

**1e. `record_decision(p_cycle_id uuid, p_session_name text, p_kind text, p_backlog_id text, p_summary text, p_reasoning text, p_ladder_work_class text DEFAULT NULL) RETURNS uuid`** — `VOLATILE`. Inserts the row with `expires_at = now() + (SELECT reversal_window_hours FROM runner_settings WHERE id = 1) * INTERVAL '1 hour'`, returns the id. The caller writes its before-images with `decision_id = <that id>` **in the same transaction** (`M6-05`); the function itself writes nothing else. A convenience `attach_before_images(p_decision uuid, p_image_ids uuid[]) RETURNS integer` sets `decision_id` on already-written images that carry none (never re-points an image that already names a decision).

**1f. `sweep_decision_windows(p_actor_cycle uuid, p_actor_session text) RETURNS TABLE(finalized integer, promoted integer)`** — `VOLATILE`, idempotent. For every `status = 'open'` row with `expires_at <= now()` (`FOR UPDATE SKIP LOCKED`): set `status = 'final'`, `finalized_at = now()`; if `ladder_work_class IS NOT NULL AND ladder_applied_at IS NULL`, call `ladder_apply_signal(class, 'promote', …)` and stamp `ladder_applied_at`. Before-image of each decision row first.

**1g. `reverse_decision(p_decision uuid, p_actor text, p_reason text, p_actor_cycle uuid DEFAULT NULL) RETURNS TABLE(outcome text, restored integer, restored_unverified integer, refused integer, demoted boolean, reversal_id uuid, reason text)`** — `VOLATILE`. Refuses (`outcome = 'refused'`) when the decision does not exist, is already `reversed`, or is itself a `kind = 'reversal'` row. Otherwise, in one transaction: insert the reversal decision row (`kind = 'reversal'`, `reverses = p_decision`, `session_name = p_actor` unless `p_actor_cycle` given, `summary`/`reasoning` from args, `expires_at = now()` — a reversal is final immediately); then for each image with `decision_id = p_decision` **newest first**, grouped `DISTINCT ON (table_name, pk_value)` taking the **oldest** image per row (the state before the decision touched it): skip and count `refused` when the table is outside the allowlist in Context item 6 or has no single-column pk (reuse the engine's pk lookup); when the table has `updated_at` and the live row's `updated_at` is later than the image, count `refused`; else write the live row's before-image (`decision_id = reversal_id`, attributed to the actor), then `DELETE` (image `row_data IS NULL`) or delete-and-reinsert from `jsonb_populate_record` with generated columns dropped (`attgenerated = ''`, the `SES-220` lesson), counting `restored` (table has `updated_at`) or `restored_unverified` (it does not). Then set the original row `status = 'reversed'`, `reversed_at`, `reversed_by`, `reversal_reason`; if it names a class, `ladder_apply_signal(class, 'demote', …)` and `demoted := true`. Runs `recompute_backlog_queue()` at the end when any `backlog_items` row was written.
