## 1. CONTEXT

John asked "what's the highest priority for the AI audit log," which led to live-testing a real question through the deployed Channel Intelligence (MI) screen and comparing the real `ai_activity_log` rows it produced against both the platform-wide AI Audit screen and the MI screen's own "Agents" drawer. Three real, verified bugs came out of that one live test (ids `11053`–`11071`, real Anthropic calls, `2026-07-16`), all sharing one root cause: **the platform has two separately hand-maintained lists trying to classify `ai_activity_log` rows back to their real capability, and both have drifted.**

**`LOG-12` — AI Audit's `byService` misattributes delegation-loop turns.** `logAgentTurn()` (`execute.js`) writes an `ai_type: 'agent-turn'` row for **every** turn in a multi-turn capability; `sendRequest()` additionally writes a second, capability-named row (e.g. `ai_type: 'quality-gate'`) only for the **terminal** (non-delegating) turn. `byService`'s grouping key is `AI_TYPE_TO_SERVICE[e.type] || e.type` — for every non-terminal turn, `e.type` is literally `'agent-turn'`, which resolves to the generic "Agent Turn (Delegation Loop Reasoning)" bucket instead of the real capability, even though the real capability is sitting right there as the first `:`-delimited segment of the row's own `feature` field. **Measured live:** Owen's Quality Gate review of one real answer made 5 real Anthropic calls (`ids 11058, 11062, 11067, 11070, 11071`); only the last is attributed to "Quality Gate" in AI Audit's By-Service view — the other 4 (real tokens, real cost) land in "Agent Turn," indistinguishable from any other capability's own intermediate turns.

**`LOG-13` — MI screen's Agents drawer drops real activity for 3 agents.** `MarketIntelligenceScreen.jsx`'s `MI_LOOP_SCOPE` constant has two parallel lists: `aiTypes` (bare capability names, matched against terminal rows) and `featurePrefixes` (`"<slug>:"` prefixes, matched against `agent-turn` rows' `feature` field, since those never carry a bare matching `ai_type`). `data-analysis`, `memory-consolidation`, and `data-room-custody` are present in `aiTypes` but **missing from `featurePrefixes`** — so Nadia's (Data Analysis), Elena's (Memory Consolidation), and Eleanor's (Data Room Custody, distinct from her Librarian capability) own intermediate `agent-turn` rows fail `useAgentActivitySummary()`'s `inScope()` check and are dropped **entirely** — not miscategorized like `LOG-12`, invisible: zero call count, zero cost, zero latency contribution. Confirmed live: Nadia's `data-analysis:none:depth2` turn (`id 11046`, real Sonnet call, `1405`/`1526` tokens) from this same session would not appear anywhere in the drawer. (`project-manager:agent-selection-intent:` and the two `screen-controls:` entries are deliberately *narrower* than their bare `aiTypes` counterpart — Michelle and Alex have non-MI intents on other screens that must stay excluded — so this fix adds only the 3 confirmed-missing entries, it does not collapse the two lists into one.)

**`LOG-14` — `SERVICE_CATALOG`/`PATTERN_CATALOG` are static and not self-maintaining.** Per John's explicit direction this session: these catalogs should update when a new real service or pattern is identified, not require a manual catalog edit before that data is visible. The concrete instance found: `guardrails-check` (Alex's and Michelle's real guardrail-check calls, confirmed live: `ids 11044, 11065`, both `patterns_used: ["guardrails","prompt-chaining"]`) has **zero `SERVICE_CATALOG` entry and zero `AI_TYPE_TO_SERVICE` mapping** — `byService`'s `for (const svc of SERVICE_CATALOG)` loop never produces a bucket for it, so these real calls don't just miscategorize, they vanish from By-Service entirely. This is the same class of gap `LOG-11` already documented for other services (`document-extraction`, `prompt-assembly`) — this session closes the `guardrails-check` instance specifically *and* builds the general safety net so the next uncatalogued service/pattern doesn't require its own future session to notice.

**Both the AI Audit screen and the Agents drawer read live from Supabase on every mount/refresh** (`hydrateFromSupabase()`, `useAgentActivitySummary()`'s `fetchAll()`) — no caching layer to invalidate. Fixing the shared computation is sufficient; both screens reflect it on next refresh with no separate wiring.

### Task 1 — `src/hooks/useAIActivity.js`: generic capability-slug resolver, fix `byService`'s bucket-dumping (`LOG-12`)

Add a new exported helper directly below `AI_TYPE_TO_SERVICE`'s closing `};` (currently ends at the `'project-manager': 'task-planning',` line):

```js
// FEATURE: LOG-12 -- agent-turn rows always carry their real capability as the first ':'-delimited
// segment of `feature` (logAgentTurn()'s own format, execute.js) -- reading it directly is generic
// and never goes stale, unlike a maintained list. Fixes byService dumping every non-terminal
// delegation-loop turn into the generic 'agent-turn' bucket instead of its real capability
// (found live 2026-07-16: 4 of Owen's 5 real quality-gate review calls were invisible under
// "Quality Gate," landing in "Agent Turn" instead).
export function capabilitySlugForRow({ ai_type, feature }) {
  const rawSlug = (ai_type === 'agent-turn' && feature) ? feature.split(':')[0] : ai_type;
  return AI_TYPE_TO_SERVICE[rawSlug] || rawSlug;
}

// FEATURE: LOG-14 -- title-cases a kebab-case slug for an auto-detected catalog fallback label.
// Same one-line shape as MarketIntelligenceScreen.jsx's local formatKindLabel() (not imported --
// that function is screen-local and this is a different call site; duplicating one pure one-line
// formatter is not worth a new shared module for two callers).
function humanizeSlug(slug) {
  return slug.split('-').map(w => w.charAt(0).toUpperCase() + w.slice(1)).join(' ');
}
```

  // capability) instead of the raw ai_type, so non-terminal delegation-loop turns land under the
