## 2. CONTEXT

**Premise revalidated live at pick time, not taken from the ticket:**
`grep -rln briefing-template scripts/` returns **nothing**. The only files referencing the template
are six regression tests that *read* it. Meanwhile `briefing-page.md` and `runner-cycle.md` step 9
have required every cycle since `v7.0.99` to rebuild the page *"structurally from
`briefing-template.html` + the `runner_` tables"*.

So every cycle has done it **by hand** — roughly fourteen SQL queries re-derived into hardcoded
string literals spread through a 1,700-line, ~158 KB template. Two cycles in a row hit that wall,
which is what turned a recurring cost into a ticket.

**This cycle is unusually well placed to fix it:** it is the third cycle of a session that had
already rebuilt and published this page **twice** (`v7.0.197`, `v7.0.199`) using a working script
in scratch. Shipping it is promoting proven code, not writing new code.

## 6. DESIGN RULES

- **Anchored substitution, hard stop on a moved anchor.** The builder edits a template it does not
  own, by string match. A silent no-op would publish a page with a section still reading *"Sample
  value"* — so `must()`/`splice()` `die()` with **exit 2**, the same "could not run" convention
  `export-backlog-snapshot.js` and `heal-engine.js` use.
- **Do not re-derive an owned rule.** The seed and the card set come from
  `briefing_state_seed()` and `briefing_open_cards()`; the builder is not a ninth home for them.
- **Refuse to invent the narrative.** §3's findings, John's directive lines, the questions and the
  vision claims are judgment. `--data` is required and has no default.
- **Fixed DOM ids are data, not code.** `item-chi84-gate` must survive a rebuild because
  `runner_card_asks.target_id` is keyed on it — the map lives in `--data`, and the builder never
  invents one.
