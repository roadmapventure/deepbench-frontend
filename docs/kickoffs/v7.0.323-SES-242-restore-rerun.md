## The decision this ticket left to its build cycle

The ticket names two fix shapes and says outright that *"the choice is the ticket"*.

**(a) shipped — the runbook tells the operator to re-run until the named-miss list stops shrinking.**
**(b) not taken — order each table's rows by self-referential dependency in the loader (or retry the
fallback's own misses once).**

**(b) is the better fix and is carried as the declared remainder.** It removes the operator step
instead of documenting it. It is not taken here for a reason that is disclosed rather than dressed
up as design preference: **`restore-supabase.mjs` is not in this repository.** It lives in
`deepbench-backups-offsite`, where John's standing rule is that a push needs his word **each time**
(directive `c98048a5`, as narrowed by `1c9609de` — drill *dumps* are pre-authorised, *pushes* are
not). An unattended cycle cannot land it, and this session's repository scope does not reach it.

**(a) also stands on its own merit**, which is why it is worth shipping rather than parking the
whole ticket: since `SES-230` the loader already **names every missed row** with primary key,
SQLSTATE and the server's own message, so "re-run while that list shrinks" consumes information the
tool already prints. The ticket's own words for (a): *"cheap, honest, no code, and it keeps the
loader's 'nothing is dropped silently' property doing the work."*

### The clause that carries the ticket

The termination test is **"stop when the named-miss list stops shrinking"**, explicitly *not* a pass
count. Two independent reasons, both in the shipped text:

1. A literal *"run it twice"* stops early on a dependency chain three deep.
2. More dangerously, it teaches an operator mid-outage to expect movement that cannot come: a
   `TABLE-WIDE` report (the jsonb scalar `null`, `SES-230`; the generated-column `428C9`,
   `SES-220`) **never** shrinks on a re-run. The shipped text says so in its own paragraph, so
   step 3 cannot send someone into an unbounded loop on `ai_activity_log`.
