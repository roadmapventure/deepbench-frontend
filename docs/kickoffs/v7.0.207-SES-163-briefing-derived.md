## The decision the whole ticket turns on

`runner_card_asks.target_id` is keyed on a card's **DOM id**. The retired builder read the map from
`data.fixed_dom_ids || {}` — **a silent empty default** — so a cycle that omitted it re-keyed the
card and orphaned John's recorded thread. The failure was invisible by construction, because
`SES-132`'s §9.1 orphan renderer still shows the text; the thread simply leaves the card it belongs
to. Live proof it was not hypothetical: card `c4f8b217` (`CHI-84`, **still undecided**) is keyed
`item-chi84-gate` while its derived id is `item-c4f8b217`.

So the map is now `public.briefing_dom_ids`, and an ask target naming a card no row claims is
**exit 2, never a warning**. The boundary that keeps that from wedging every future rebuild is
stated as a property: a target whose card is simply *not rendered* (decided, or self-retired) is
**not** an error — that is the orphan renderer doing its ordinary job.

### Two defects this ticket's own QA caught before they shipped

Both were found by **calling** the new code, not by reasoning about it — and both would have shipped
looking fine:

1. **The §14 "first clause" rule, twice wrong.** Splitting on the comma alone left
   `'Private Relay egress — Suchi's Tue 8/18 visit came via this IP (cookie a7a960c6); shared range'`
   **uncut** — a 95-character provenance paragraph in the Name column, which is precisely the defect
   `briefing-page.md` §14's rule exists to prevent, reproduced by the fix for it — and mangled
   `'David (Austin, TX)'` into `'David (Austin'`. Correcting it to split on a strong separator then
   revealed a second shape: stripping at a separator *inside* a parenthetical leaves an unbalanced
   fragment (`'Mom (Adrian, Missouri'`). Final live output: `Private Relay egress`, `Matt Chester`,
   `David`, `John`, `Mom`.
2. **The masthead version must NOT come from `dev_version_counter`.** Deriving it looks obviously
   right and is wrong under parallel cycles (register B42): the counter is a **claim register**
   shared by every concurrent session, not "the current version". This cycle claimed **v7.0.207**
   and the counter already read **209** when the page was built — so the first live build stamped a
   version the page was not. It is a `--version` argument now, with **no default**: a guessed
   version on the masthead is unfalsifiable from the page.

Grants asserted **both directions** per `SES-101`/`DAT-18` (`anon`/`authenticated` false,
`service_role` true, revoked from `PUBLIC`); `briefing_use_rows` asserted at **1 overload** per
`.claude/rules/supabase-function-signature.md`.
