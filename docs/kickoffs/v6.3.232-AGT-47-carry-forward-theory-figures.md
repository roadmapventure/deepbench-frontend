### Correction to the design session's own finding — the field, verified live this session

The design harvest named the fix's target as `skill_profiles.data-patch-intent.method`. **That is
the wrong field**, caught by re-verifying live rather than trusting the harvest's prose:

```sql
select slug, method, traits->>'analysis_instructions' as analysis_instructions
from skill_profiles where slug in ('data-patch-intent','data-patch-execute-intent');
-- both rows: method IS NULL. The full instructional text for data-patch-intent lives in
-- traits.analysis_instructions instead.
```

`api/prompt/db-assembly.js`'s `intent` branch (`buildSections()`, ~line 135) concatenates, in
order: `objective`, then `method` (if set), then `traits.analysis_instructions` (if set). For **this
specific profile** `method` is null and `analysis_instructions` already carries the entire live
instruction — the decision rules, the `chunk_id`-copy rule, the `request_help`/`delegate_to_agent`
cleanup flow. Writing the new instruction into the empty `method` field would technically still
reach the prompt (the intent branch does not drop it, unlike the guardrails branch `AGT-44` dealt
with) — but it would render as a disconnected fragment *before* the coherent
`analysis_instructions` narrative it needs to modify, not inside it. The correct edit is inline,
inside `traits.analysis_instructions`, at the point that narrative already talks about composing
`content`.

### The fix

One inserted paragraph in `traits.analysis_instructions`, placed immediately after the paragraph
that lists the fields Nadia determines and immediately before the existing `no_action` branch —
telling her to compose `content` directly from `user_reasoning`/`correction` and carry forward
every concrete figure, named entity, and time period rather than generalizing them away. Every
other paragraph — the `chunk_id` copy rule, the `no_action` branch, the `request_help`/
`delegate_to_agent` cleanup flow, its own "preserve every fact" instruction — is untouched.

### Task 1 — insert the carry-forward instruction (`skill_profiles.data-patch-intent.traits`)

Use `jsonb_set` so every other `traits` key (`schema`, `can_request_help`,
`on_accept_intent_slug`, `requires_human_confirmation`) is left byte-identical — do not replace the
whole `traits` object.

```sql
UPDATE skill_profiles
SET traits = jsonb_set(
  traits,
  '{analysis_instructions}',
  to_jsonb($TXT$You are given disputed_chunk_id, correction, and user_reasoning in your task context. Determine your decision: action (opinion/promote/no_action), chunk_id (copy disputed_chunk_id exactly, character for character -- never invent, rename, paraphrase, or summarize it; null if disputed_chunk_id is null), content, confidence, and version_note.

When action is opinion or promote, compose content directly from user_reasoning and correction and carry forward every concrete detail they contain: named countries, regions, partners, or markets, and exact or approximate figures, percentages, and time periods. Do not generalize a specific figure into a vague category -- for example, do not write "the country" when user_reasoning names Japan, Mexico, the US, and the UK with their own separate numbers. content is judged on whether it retains the specifics you were given, not on how smoothly it reads without them.

If action is no_action, content is null -- return your answer directly. Do not request help.

If content is non-null (action is opinion or promote): before finalizing, use request_help to ask for help getting your content field's wording cleaned up for a human-facing confirmation card. Describe the need plainly, e.g. "rewrite this text as clean, readable prose for a confirmation card -- no markdown syntax (no **, #, |), preserve every fact and the original meaning exactly, do not add or remove information." Once you are told who to reach, use delegate_to_agent with exactly the agent_id, capability_slug, and intent_slug you were given to contact them directly, passing your action, chunk_id, content, confidence, and version_note as context. Wait for their response, then use their rewritten text as your content field verbatim -- do not rewrite it yourself, do not paraphrase it further. Return your final answer with action, chunk_id, confidence, and version_note exactly as you originally determined them.$TXT$::text)
)
WHERE slug = 'data-patch-intent'
RETURNING slug, method, traits->>'analysis_instructions' AS analysis_instructions;
```

**Do not touch `data-patch-execute-intent`.** Its own `analysis_instructions` already receives
`content` as a given, already-decided value — nothing for it to generalize away.
