## 2. CONTEXT

The masthead (§1) carries three lines today: the date, the version, and `#waiting` — the
decisions-waiting counter `countWaiting()` fills from `data-awaits`. Read live in
`docs/runbooks/briefing-template.html` line 691 before a line changed:

```
'<div class="date">Aug 19, 2026 CST<br>v7.0.94<br><b id="waiting"></b></div></header>'
```

There is **no timestamp of any kind in the masthead** — not of his last tap, not of the page's
own build. Premise confirmed, not recalled.

**His sentence is two requirements, not one, and shipping only the first would miss the point.**
"A timestamp of the last action" is the first. "I can't tell what time my last action was
**compared to** if the page has refreshed yet" is the second: he is asking whether the run that
should have picked his tap up has happened. One timestamp alone cannot answer that — it needs the
page's own rebuild time next to it, and the comparison stated rather than left for him to do in
his head at midnight.

**The one that would have shipped wrong.** The obvious implementation renders the last-action
time as a string the rebuilding cycle types in. That is exactly the failure `SES-124`'s
`countWaiting()` exists to prevent: the masthead is the half John reads first and it must never be
able to disagree with the state under it. A cycle-typed stamp is also *structurally* incapable of
being right — the page self-publishes on **every** tap (`save()` → `doc()`), so between two cycles
his taps move the state many times and no cycle is running to re-type anything. The stamp is
therefore **derived from `briefing-state` in `wire()`**, on every render, exactly like the counter.

The page's *build* time is the opposite case and is genuinely a cycle-authored constant: nothing
in the state knows it. It goes in the `#code` script, which `doc()` carries through a self-publish
verbatim — so it survives his taps and changes only when a cycle rebuilds. That asymmetry is the
whole design.

## 6. DESIGN RULES

- **Derived, never typed** (`SES-124`): every element of the stamp except `PAGE_BUILT` comes from
  `briefing-state`. `PAGE_BUILT` is the one value the state cannot know.
- **A runner reply in an ask thread is NOT John's action.** `state.asks[t][i]` entries written by a
  cycle carry a `q` beginning `[runner,` (live convention, read from the page's own state this
  cycle). Counting them makes "your last action" report the runner's last action — the same class
  of wrongness as the masthead disagreeing with the cards. They are skipped by that prefix.
- **CST display, UTC storage** (John, 2026-08-20): the stamp renders through
  `toLocaleString('en-US', {timeZone:'America/Chicago'})` and is labeled CST. Nothing about the
  stored `at` shape changes.
- **Absent is not zero.** No actions in state → "No actions recorded yet", never a fabricated time.
  An `at` that will not parse is skipped, not rendered as `Invalid Date`.
- **A fold still never publishes**, and neither does anything here: `stampLastAction()` is render
  only. The one new write is `directive_at`, on the save path that already published.
