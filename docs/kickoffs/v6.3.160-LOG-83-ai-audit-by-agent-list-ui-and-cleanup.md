## 1. Use case (the problem, plain)

**Problem.** The AI Audit screen's **By Agent** list has four issues John raised from a live screenshot:
1. It opens **expanded** by default — it's a long list and should start collapsed.
2. It sits **below By Service**; John wants it **directly under By LLM**.
3. Each agent's second line shows an internal **code/id** (`CI-01`, `PP-01`) — meaningless to a viewer. It should show the agent's **role title** instead.
4. The list contains **junk rows**: one placeholder "all-zero" agent that is really a leftover **negative test**, and several **duplicate** rows for agents that were logged under an old/wrong identifier (e.g. `marcus-webb` separate from the real `Marcus Webb`; two `Michelle Manning` rows).

**Fix.** By Agent (a) defaults collapsed, (b) moves under By LLM, (c) shows each agent's role title on line 2, and (d) the underlying log is cleaned so mislabeled rows merge into the right agent and the test rows are gone.

**Expected after.** Open AI Audit: By Agent is collapsed. Expand it — it sits right under By LLM. Every row's second line is a human role ("GEO CSO Expert", "Project Manager"), not a code. Marcus Webb appears **once** (his 2 stray `marcus-webb` calls folded in), Michelle **once** (not twice), Eleanor's 24 mislabeled calls folded in, and the `00000000-…` test agent is gone. Total / Cost / Avg columns are unchanged in how they're computed.

**Example.** Before: a row `marcus-webb · Total 2` sits far down the list, separate from `Marcus Webb · CI-01 · Total 3,218`. After: no `marcus-webb` row; Marcus Webb reads `Marcus Webb / GEO CSO Expert · Total 3,220`.

## 2. Findings behind this (verified live against `ai_activity_log`, 2026-07-27)

- **The all-zero agent** = `agent_id = '00000000-0000-0000-0000-000000000000'`, 16 rows, all in a 7-minute window on 2026-07-16, every one a call to a capability literally named `nonexistent-capability-xyz`. A negative test, not a real agent → **delete**.
- **The duplicates** are 4 historical mislabel groups (all ≥12 days old; the current write path no longer produces any of them — confirmed by grep, nothing in `src/`/`api/`/`lib/`/`shared/` emits these strings):

  | Logged as | Rows | Real agent id |
  |---|---|---|
  | `marcus-webb` | 2 | `marcus` |
  | `eleanor-voss` | 18 | `eleanor` |
  | `eleanor_voss` | 6 | `eleanor` |
  | `PP-01` (Michelle's code) | 2 | `michelle` |

  The `PP-01` group is why the screenshot shows **two Michelle Manning rows**: `resolveAgent()` already resolves the bare code `PP-01` to her *name* for display, but `byAgent` buckets on the raw `agent_id`, so her totals split into two rows that happen to render with the same label. Merging the data collapses it to one.
- **Cost / Avg are real (item #6 — verified, no code change needed).** Cost is derived per row from real token counts × the published Anthropic/OpenAI rates in `computeCallCost()` (AA-181); only **43 of 21,605** rows carry a stored `cost_usd`, the rest are computed live. Avg is the mean of real `latency_ms` (present on 20,979 rows). Total is a row count. Nothing hardcoded. **Do not "fix" any number** — just confirm reconciliation live (Section 7).
