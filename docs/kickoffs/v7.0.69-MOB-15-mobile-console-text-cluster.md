### T3 — Assembly tracker band (AssemblyView.jsx)

1. Add `export` to the existing `StageSection` (no other change to it).
2. New export:

```jsx
export function AssemblyTrackerBand({ stages, running = false, openKey = null, onToggle }) {
  const sections = stages?.sections ?? [];
  const chips = [...sections].reverse();   // fold is newest-first; band reads chronological L→R
  return (
    <div style={/* one row: mono "Assembly" label + chips; overflowX:auto; no wrap; fixed height */}>
      <span>{ASSEMBLY_TITLE}</span>
      {chips.map(s => {
        const label = s.stage ? STAGE_LABEL[s.stage] : IN_PROGRESS_LABEL;
        const live = s.ghost && running && !stages?.terminal;
        return (
          <button key={s.key} type="button" onClick={() => onToggle?.(s.key)} title={label}>
            {s.filled && s.stage !== "error" && "✓ "}{label}
          </button>
        );
      })}
    </div>
  );
}
```

Chip styling (exact tokens in §6): filled = moss ✓ + navy text; live ghost = brass border + `aiBlink` pulse on a leading dot (reuse the global keyframe — no new keyframes); error stage = `T.flag`; terminal survivors render static. `openKey === s.key` gets the strongest border (selected). **No chips render when `sections` is empty — the label stands alone. Never render placeholder/upcoming stage chips: the band shows the fold's real stages only (§19r — no storyboard, §19j — no invented content).** Chip labels are chrome register 1 (John's canonical `STAGE_LABEL` strings, verbatim). Touch target extended to ≥36px via transparent `::after`/padding, the `.lav-mseg` idiom.
