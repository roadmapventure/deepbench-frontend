## 1. Use case (the problem, plain)

**Problem.** The AI Audit screen's **By LLM** drawer is inaccurate in two ways:
1. Its top row reads **`claude-haiku-4-5` · ~3,785 calls**, but only ~52 of those are real Haiku calls. The other ~3,800 are **not model calls at all** — they're deterministic database operations (Eleanor Voss — The Librarian's Data Room lookups `ai_type='librarian'`, Michelle Manning — Project Manager's `agent-directory` reads, `librarian-write`, `document-parsing`, `csv-upload`). Those rows have **no model** in the database (`model IS NULL`), and the screen hardcodes a fake `'claude-haiku-4-5'` label onto them.
2. The same model appears as **two rows**: `claude-haiku-4-5` (52) vs. `claude-haiku-4-5-20251001` (11k); `claude-sonnet-4-5` (6) vs. `claude-sonnet-4-6` (~1.2k). The `MODELS IN USE` header stat inherits this (shows 5).

**Fix.** By LLM shows **real model names only**, each model **once**. Non-model rows drop out; alias/legacy ids collapse into their canonical model. Also move the By LLM drawer up to sit directly under **By Pattern**.

**Expected after.** By LLM shows exactly **3 rows** — Haiku (`claude-haiku-4-5-20251001`), Sonnet (`claude-sonnet-4-6`), and OpenAI `text-embedding-3-small`. `MODELS IN USE` reads **3**. The **Total / Cost / Avg** columns stay exactly as they are — merged rows simply sum the same per-row numbers already computed. No other drawer or header stat changes.

**Example.** Today: `claude-haiku-4-5 · 3,785 · <$0.01 · 431ms` (fabricated) + a separate `claude-haiku-4-5-20251001 · 11,073` row. After: one `claude-haiku-4-5-20251001` row carrying the real Haiku totals (its ~11k calls + the 52 legacy short-form calls folded in); the 3,800 Librarian/directory lookups no longer appear here at all (they remain visible under By Service / By Agent, unchanged).

## 2. Root cause (mechanism, brief)

- **Fabrication:** `hydrateFromSupabase()` maps `model: row.model || 'claude-haiku-4-5'` (~line 510). The `|| 'claude-haiku-4-5'` invents a model for every model-less row.
- **No dedup:** the By LLM aggregation keys on the raw `e.model` (~line 640) and never applies the existing `MODEL_ID_NORMALIZE` alias map (line 412), so aliases split into separate rows.
- **Verdict (design session, architect-reviewed):** `claude-haiku-4-5` and `claude-sonnet-4-5` are **legacy aliases of the platform's canonical models** — `shared/models.js` declares only `HAIKU: claude-haiku-4-5-20251001` and `SONNET: claude-sonnet-4-6`; `STANDARDS.md` §12 maps both short forms to those. Merge is correct. The 6 `sonnet-4-5` rows are a stale 2-day mislabel (2026-07-16..17) from server code that no longer exists.

## 4. Tasks

**Task 1 — kill the fabrication (`useAIActivity.js`, `hydrateFromSupabase`, ~line 510).**
Change `model: row.model || 'claude-haiku-4-5'` → `model: row.model || null`. (Every consumer of `e.model` is null-safe: byLLM guards `|| "unknown"` then the `startsWith` filter excludes it; `buildActivitySummary` guards `row.model || 'unknown'`; `computeCallCost(null,…)` already returns null. Verified — do not add other guards.)

**Task 2 — extract + normalize the By LLM aggregation (`useAIActivity.js`).**
Extract the inline `byLLM` loop (currently ~lines 637–651 inside `useAIActivity()`) into a new **exported pure function** `computeByLLM(log)`, mirroring the existing `export function computeByPattern(log, vocab)` shape, and call it from the hook (`const byLLM = computeByLLM(log);`). Inside it, normalize the key:
```js
const m = MODEL_ID_NORMALIZE[e.model] || e.model || "unknown";
if (!m.startsWith('claude-') && !m.startsWith('text-embedding-')) continue;
```
Everything else in the loop (calls/cost/tokensIn/latencies + the `avgLatency` finalize) stays byte-identical. Do NOT change cost or avgLatency math. `modelsInUse` (line 763) and the panel render need no change — they read `byLLM` and self-correct to 3.
*(Keep using the existing in-file `MODEL_ID_NORMALIZE` — do NOT refactor to source it from `shared/models.js` this session; that is deferred to LOG-82.)*

**Task 3 — reorder drawers (`AIActivityPanel.jsx`).**
Move the entire **By LLM** section block (`<SectionHeader label="By LLM" …>` through its closing render, currently ~lines 322–344) to sit **directly after the By Pattern block** (after the `sections.pattern` block that ends ~line 275) and **before** the By Service block. Resulting order: By Pattern → By LLM → By Service → By Agent → Platform Roadmap. Pure JSX move; no logic/state change (`sections.llm` key unchanged).

Register it in `tests/regression/run-all.js` (follow `LOG-36-pattern-display-sources.js` as the reference harness).
