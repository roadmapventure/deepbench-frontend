## CONTEXT

John, reviewing a live 2-minute MI screen run (the same run diagnosed in `AA-132`), asked for two additions to Column 3's Pipeline Log so he can call out exactly which step to work on by number, in real time, without cross-referencing Supabase himself:

1. **A sequence number to the left of each entry's avatar**, styled like the existing "role" text to the right of the avatar (same `fontFamily`/`fontSize`/`color`). Numbering starts at **1 at the bottom of the log** and increases going up.
2. **The time each step took, appended to the end of the same summary line** every entry already ends on — visible immediately, no click-through.

**Numbering source, already available with zero new state:** `logEvent = (evt) => setPipelineEvents(prev => [...prev, { ...evt, id: prev.length }])` already assigns each event a chronological, 0-based `id` at push time. `AuditColumn()` renders `ordered = [...events].reverse()` (newest on top, confirmed existing behavior). Since `id: 0` is the oldest event and ends up last in `ordered` (rendered at the bottom), `evt.id + 1` is exactly the number John asked for — no new counter, no new field, just render the existing `id`.

**Duration is not currently captured anywhere.** Every Pipeline Log event is emitted client-side, immediately after its own `await callCapability(...)` (or `await runHypothesisTest(...)` / `await resolveConfirmation(...)`) resolves — a real, measurable per-step elapsed time is available for free at every one of the 10 existing emission sites; it just isn't captured today. This session adds a `Date.now()` capture immediately before each await already on its own line, and a new `durationMs` field on the event object passed to `onEvent`/`logEvent` immediately after. Two emission sites (`display_format`'s pair with `agent_selection`, in both `runQaWithQualityGate` and `runHypothesisTest`) share one underlying `callCapability` call — both get the same `durationMs`, which is correct: they are two log lines describing one real server round trip (that round trip itself internally chains Michelle's agent-selection turn + the Format agent's turn, server-side — the frontend can only time what it awaits).

One exception, deliberate: the `hypothesis_test` event (logged by the screen body after `runHypothesisTest()` returns, wrapping both Priya's analysis leg and the display hand-off leg) is timed as the **total** `runHypothesisTest()` call, not just its last leg — this is the more useful number (mirrors what a user actually experiences as "how long did the theory test take"), and does not conflict with `display_format`'s own separately-timed duration one level in.
