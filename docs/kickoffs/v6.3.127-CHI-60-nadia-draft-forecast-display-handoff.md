## 1. CONTEXT

**The problem.** The Draft Forecast drawer (`MarketIntelligenceScreen.jsx`, `CHI-50`) shows Nadia Farouk's raw `data-patch-intent` decision fields, unformatted — `ACTION: promote`, `CONTENT: **some markdown**`, chunk id, confidence, version note, each dumped as a labeled line by `ConfirmationCardContent` (`SharedUI.jsx:475`, the generic `MI-01d` `pending_confirmation` gate). That generic field-dump rendering is deliberately unchanged this session (John's explicit call) — the actual defect is that `content`'s own text is raw/unformatted, not that the card lists field labels.

**Why this can't be a screen-level fix.** `ARCHITECTURE.md` §19b (locked): content specialists never own Format Skills; display/editor agents (Alex Reeves, `screen-controls`) own the Format Skill for the platform. Wrapping `ConfirmationCardContent` or hardcoding a call to Alex would violate that separation, and would re-hardcode an agent name the platform's Real Agent Loop principle (§19d/§19e) forbids.

**Why this isn't `data-patch-execute-intent`.** That's a *different* intent (fires only after a human clicks Accept, writes to the Data Room) — already has `can_request_help: true` for an unrelated need. `data-patch-intent` (fires *before* the human ever sees the card) currently has no delegation ability at all — confirmed live via Supabase this design session.

**The mechanism, verified live in `execute.js` this session — no code changes needed.** The `request_help` → Michelle (`agent-selection-intent`, resolved live, never hardcoded) → `delegate_to_agent` → response-returns-to-caller round trip is already fully generic harness behavior. `data-patch-intent`'s own sibling, `data-patch-execute-intent`, already proves this exact pattern live today (two `request_help` calls for her `promote` action's Data Room write, then finalizes her own schema). Two structural findings ruled out simpler-looking alternatives:
- `delegation_required: true` (Jordan Ellsworth's `web-search-news` → Alex pattern, `CHI-33`) auto-resolves via a **final** delegation, but `runLoop`'s `requiresHumanConfirmation` gate (`execute.js` ~L700) only fires on `!turn.is_delegate_call` — a `delegationRequired` intent can never produce that turn shape (non-delegate turns are retried then thrown, ~L683-693). `delegation_required` and `requires_human_confirmation` cannot coexist on one intent. Ruled out.
- The `format_skill_profile_slug`/`display_agent_id` "format-last" override (`AA-77`, `api/plan.js`'s Work Order pattern) replaces the *entire* format contract on the calling agent's own turn — would strip `data-patch-intent`'s own schema (and with it, the fields `data-patch-execute-intent` needs on accept) rather than layering on top of it. Ruled out.

**The approach that actually holds:** `data-patch-intent` keeps its schema, `on_accept_intent_slug`, and `requires_human_confirmation` completely unchanged — the confirmation gate and the accept→execute pipeline are untouched. She gains `can_request_help: true` and instructions to run the same ask-then-reach round trip her own sibling intent already proves: ask who's qualified (generic, no name), reach whoever's named, use their answer verbatim, then produce her own final schema tool call (which the confirmation gate captures exactly as it does today). Alex still substantively authors the display prose — the harness mechanics just require the confirmation-gated intent's own tool call to be what the gate observes.

A new, dedicated intent for Alex (`data-patch-display-intent`, under his existing `screen-controls` capability) is added rather than relying on Michelle finding no real match among his 3 existing intents (`qa-answer-format`/`news-cards-format`/`intelligence-review-format` — checked live, none share this schema) and falling back to `intent_slug: null` baseline mode, which was independently found to hit an unrelated, pre-existing ambiguity: `screen-controls`'s two Format-type Skill Profiles (`screen-controls-format`, `execution-plan`) are tied at `display_order: 1`, so baseline mode's format contract would come from whichever the query happens to return last, non-deterministically (verified live via Supabase this session). Logged separately, not fixed this session, since the new dedicated intent sidesteps it entirely for this flow: `CHI-60` does not touch `screen-controls-format`/`execution-plan`'s ordering.

**Scope: Supabase data only.** No `src/`/`api/` files change. `can_request_help`, `request_help`/`delegate_to_agent` dispatch, and generic intent-type Skill Profile assembly are all already-shipped, already-generic mechanisms — this session adds Skill Profile rows, nothing else.

```sql
UPDATE skill_profiles
SET traits = traits || jsonb_build_object(
  'can_request_help', true,
  'analysis_instructions',
  'You are given disputed_chunk_id, correction, and user_reasoning in your task context. Determine your decision: action (opinion/promote/no_action), chunk_id (copy disputed_chunk_id exactly, character for character -- never invent, rename, paraphrase, or summarize it; null if disputed_chunk_id is null), content, confidence, and version_note.

If action is no_action, content is null -- return your answer directly. Do not request help.

If content is non-null (action is opinion or promote): before finalizing, use request_help to ask for help getting your content field''s wording cleaned up for a human-facing confirmation card. Describe the need plainly, e.g. "rewrite this text as clean, readable prose for a confirmation card -- no markdown syntax (no **, #, |), preserve every fact and the original meaning exactly, do not add or remove information." Once you are told who to reach, use delegate_to_agent with exactly the agent_id, capability_slug, and intent_slug you were given to contact them directly, passing your action, chunk_id, content, confidence, and version_note as context. Wait for their response, then use their rewritten text as your content field verbatim -- do not rewrite it yourself, do not paraphrase it further. Return your final answer with action, chunk_id, confidence, and version_note exactly as you originally determined them.'
)
WHERE slug = 'data-patch-intent';
```

### Task 2 — New intent for Alex: `data-patch-display-intent` (same project)

```sql
INSERT INTO skill_profiles (slug, skill_type_slug, traits)
VALUES (
  'data-patch-display-intent',
  'intent',
  jsonb_build_object(
    'schema', jsonb_build_object(
      'type', 'object',
      'required', jsonb_build_array('action','chunk_id','content','confidence','version_note'),
      'properties', jsonb_build_object(
        'action', jsonb_build_object('type','string','enum', jsonb_build_array('opinion','promote','no_action')),
        'chunk_id', jsonb_build_object('type', jsonb_build_array('string','null')),
        'content', jsonb_build_object('type', jsonb_build_array('string','null'), 'description', 'Clean, natural prose -- no markdown syntax, no field-marker language.'),
        'confidence', jsonb_build_object('type', jsonb_build_array('string','null'), 'enum', jsonb_build_array('high','medium','low', null)),
        'version_note', jsonb_build_object('type','string')
      )
    ),
    'handler', 'store',
    'output_type', 'json',
    'analysis_instructions',
    'You are given a Data Integrity decision awaiting display: action, chunk_id, content, confidence, version_note. Your only job is to rewrite content into clean, natural, human-readable prose suitable for a confirmation card -- remove markdown syntax (no **, #, |), remove any field-marker-style language, preserve every fact and the original meaning exactly, do not add or remove information. If content is null, leave it null. Return action, chunk_id, confidence, and version_note exactly as given, unchanged.'
  )
)
ON CONFLICT (slug) DO NOTHING;
```

## 7. NODE.JS TEST

Save as `test-chi-60-draft-forecast-display.mjs` at repo root. Run with `node --env-file=.env.local test-chi-60-draft-forecast-display.mjs`. Requires `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `ANTHROPIC_API_KEY` in `.env.local`. **Delete before committing.** Run only after Tasks 1-3 are applied.

```js
// test-chi-60-draft-forecast-display.mjs — Category F/L test for CHI-60
// Run: node --env-file=.env.local test-chi-60-draft-forecast-display.mjs
// DELETE THIS FILE BEFORE COMMIT.

import { runCapability } from './api/capabilities/execute.js';

const SUPABASE_URL = process.env.SUPABASE_URL;
const SUPABASE_KEY = process.env.SUPABASE_SERVICE_KEY;
const HEADERS = { 'Content-Type': 'application/json', apikey: SUPABASE_KEY, Authorization: `Bearer ${SUPABASE_KEY}` };

let pass = 0, fail = 0;
function check(label, cond) {
  if (cond) { console.log(`PASS: ${label}`); pass++; }
  else { console.log(`FAIL: ${label}`); fail++; }
}

async function fetchRow(table, filter) {
  const res = await fetch(`${SUPABASE_URL}/rest/v1/${table}?${filter}`, { headers: HEADERS });
  if (!res.ok) throw new Error(`Fetch failed for ${table}?${filter}: ${res.status}`);
  return res.json();
}

async function testCategoryF() {
  console.log('\n--- Category F: environment + schema ---');
  check('SUPABASE_URL set', !!SUPABASE_URL);
  check('ANTHROPIC_API_KEY set', !!process.env.ANTHROPIC_API_KEY);

  const decide = await fetchRow('skill_profiles', 'slug=eq.data-patch-intent&select=traits');
  check('data-patch-intent exists', decide.length === 1);
  check('data-patch-intent can_request_help true', decide[0]?.traits?.can_request_help === true);
  check('data-patch-intent still requires_human_confirmation', decide[0]?.traits?.requires_human_confirmation === true);
  check('data-patch-intent still on_accept_intent_slug data-patch-execute-intent', decide[0]?.traits?.on_accept_intent_slug === 'data-patch-execute-intent');
  check('data-patch-intent has no delegation_required', decide[0]?.traits?.delegation_required !== true);

  const display = await fetchRow('skill_profiles', 'slug=eq.data-patch-display-intent&select=traits');
  check('data-patch-display-intent exists', display.length === 1);
  check('data-patch-display-intent schema requires same 5 fields as data-patch-intent', JSON.stringify(display[0]?.traits?.schema?.required?.slice().sort()) === JSON.stringify(['action','chunk_id','confidence','content','version_note']));

  const link = await fetchRow('capability_skill_profiles', 'capability_slug=eq.screen-controls&skill_profile_slug=eq.data-patch-display-intent&select=*');
  check('data-patch-display-intent linked to screen-controls', link.length === 1);
}

async function testCategoryL() {
  console.log('\n--- Category L: live end-to-end delegation ---');
  // Deliberately markdown-laden correction text -- the exact defect CHI-60 fixes.
  const result = await runCapability({
    capability_slug: 'data-analysis',
    intent_slug: 'data-patch-intent',
    agent_id: 'nadia',
    task_context: {
      disputed_chunk_id: 'test-chunk-chi-60',
      correction: '**Co-op utilization** rose to 55% in Q3 -- see [source]. This *supersedes* the prior 42% figure.',
      user_reasoning: 'The hypothesis test confirmed the higher figure against two independent sources.',
    },
    tenant_id: 'global',
  });

  check('result has status pending_confirmation', result.status === 'pending_confirmation');
  const pa = result.proposed_action;
  check('proposed_action has action field', ['opinion', 'promote', 'no_action'].includes(pa?.action));
  check('proposed_action has version_note', typeof pa?.version_note === 'string' && pa.version_note.length > 0);

  if (pa?.content) {
    check('content has no markdown bold syntax', !pa.content.includes('**'));
    check('content has no markdown italic asterisks left dangling', !/\*[^*]+\*/.test(pa.content));
    check('content is non-trivial prose', pa.content.length > 10);
  } else {
    console.log('  (action resolved to no_action or content null -- delegation correctly skipped per instructions)');
  }

  // Confirm the real delegation chain actually ran (Nadia -> Michelle -> Alex), not a lucky direct answer.
  const activity = await fetchRow(
    'ai_activity_log',
    `select=capability_slug,intent_slug,agent_id&order=created_at.desc&limit=10`
  );
  const sawMichelle = activity.some(r => r.capability_slug === 'project-manager' && r.intent_slug === 'agent-selection-intent');
  const sawAlex = activity.some(r => r.agent_id === 'alex' && r.intent_slug === 'data-patch-display-intent');
  check('Michelle (agent-selection-intent) ran in this chain', sawMichelle);
  check('Alex (data-patch-display-intent) ran in this chain', sawAlex);
}

(async () => {
  await testCategoryF();
  await testCategoryL();
  console.log(`\n${pass} passed, ${fail} failed`);
  process.exit(fail > 0 ? 1 : 0);
})();
```
