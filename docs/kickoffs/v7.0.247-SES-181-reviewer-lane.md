## What was built

**1. `scripts/verifier.js` — the verdict.** Runs the charter's three gates in order, each producing
`green` / `red` / **`skipped`**, then `verdictFor()` returns `approve` iff all three are green.

| Gate | Command |
|---|---|
| build | `npm run build` |
| regression | `node tests/regression/run-all.js` |
| hygiene tripwire | `node scripts/check-session-docs.js --gate` |

The hygiene gate uses `--gate` — `SES-199`'s flag — deliberately: the bare form exits 0 on every
path, so without it this gate could never be red and the verifier would rubber-stamp by
construction. That is the same defect `SES-199` was filed for, one level up.

**2. `ses181_runner_verdicts` — the ledger.** One row per verdict, service-role only. The
fail-closed rule lives here **as well as** in the script (`ck_runner_verdicts_fail_closed`:
`approve` ⇔ all three gates green), because this script will not stay the only thing that can
insert a row. `ck_runner_verdicts_backlog_id_bare` repeats `SES-116`'s key-column boundary;
`ck_runner_verdicts_reasoning` refuses a verdict with no reason, which is the charter's grounding
rule as a constraint rather than a habit.

**3. Step 7a in `runner-cycle.md` — the wiring.** The verifier runs after the QA bar and before the
close-out status write. On `approve` **and** eligible, the close-out writes `done` instead of
`delivered`; anything else writes `delivered`, unchanged.

## The three boundaries this build refused to blur

- **`skipped` is not `green`, and the natural implementation gets it wrong.** Writing the status
  test as `exitCode !== 1`, or defaulting an absent gate to pass, approves a change whose build
  never ran. The regression test drives the whole 3³ input space and asserts exactly one of the 27
  combinations may approve.
- **The auto-done scope is read off the board, never off argv.** Charter decision 2 supersedes
  `SES-154`'s John-only-writer rule *"for this epic family only"*, so `epic` and `priority_class`
  come from `backlog_items` via the ticket id. A cycle passing its own `--epic` would be
  self-certifying its own scope. Unknown epic, absent ticket, or a failed lookup → **not eligible**,
  with the reason stored rather than a silent `false`.
- **This ship did not take the bar it shipped.** `SES-181` is a `Selfbuild` `P10 - Tooling` ticket
  and would qualify on paper. Charter premise 3 is *"no change certifies itself; a fresh-context
  verifier must pass it"* — and a delivery whose diff **is** the verifier is graded by the code it
  changed. The rule is written into step 7a and obeyed here: status `partial`, card filed, John
  decides.
