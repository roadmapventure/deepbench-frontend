## 2. CONTEXT

A kickoff doc's Section 8 Node test routinely asserts against **text slices** of the current source
(`src.slice(start, end)` anchored on a marker string). Those anchors are **guesses until executed**.
When an anchor's first occurrence is not the intended one, `slice(start, end)` with `start > end`
returns `""` and every assertion over that slice becomes vacuous — it can neither pass nor fail
honestly, and the coding session inherits a test that was never capable of measuring anything.

**Found live in `S-MOB-15`** (`docs/SESSIONS.md`): the kickoff's T1 slice anchored on `.lav-medges`,
whose first occurrence is a prose mention in a CSS comment **above** the target rule. The slice came
back empty; both assertions could never pass. The coding session caught it and re-anchored.

**The practice already works and is already measured — it just has no home.** Three later sessions
ran it and recorded the payoff in `docs/SESSIONS.md`:

- v7.0.74 `LAV-36`: *"8/10 assertions correctly FAILED pre-change, and the run exposed that the
  muted-italic occurrence count was 3, not the guessed 2 … fixed pre-commit instead of burning a
  coding-session round."*
- `LAV-38`/`MOB-21`: *"caught a broken test assertion pre-commit for the second session running
  (check 7's regex died on the `}` inside `${T.brass}`)."*
- `LAV-39`/`LOG-133`: *"caught a broken assertion pre-commit for the third session running (a
  comment-line filter JSX block comments defeat → exact-count form)."*

So the gap this session closes is **not** "does the rule work" — it is that a rule with three
measured saves lives only in session-history prose. That is the same *rule-text-with-no-canonical-home*
shape `SES-200`'s check 12 exists to detect, one level up: nothing points a future design session at it,
and `docs/STANDARDS.md` §4 / `CLAUDE-DESIGN.md` Step 4 — the two places a session actually reads — are
silent. Verified silent this session: `grep -niE "dry.?run"` over both files on a fresh `origin/dev`
returns nothing.

## 8. NODE.JS TEST

`tests/regression/SES-76-kickoff-dryrun-rule.js`, full code, persisted (not deleted — it is a
regression guard, §4's persistence rule). Six clauses, each with its own negative control:

1. `states-the-bar` — the block requires the kickoff's own test to be RUN against unchanged source
   before the kickoff commits.
2. `requires-failure-on-unchanged-source` — it demands every content assertion FAIL pre-change, not
   merely that the test executes.
3. `names-the-empty-slice` — it names the empty-slice shape (`start > end` → `""`) as the specific
   defect, so a reader meets the mechanism and not just the ceremony.
4. `carries-the-evidence` — it cites `S-MOB-15` as found-live rather than asserting the rule bare.
5. `checklist-has-the-box` — §3's issuing checklist carries a dry-run line.
6. `claude-design-points-not-restates` — `CLAUDE-DESIGN.md` Step 4 has the step AND cites
   `STANDARDS.md` §4, AND does not carry a second full copy of the bar.

**Discrimination:** each clause's `breaks` transform mutates the shipped text in the one way that
should matter and asserts the clause then fails. Plus a file-level negative control run against
`origin/dev`'s pre-change copies of both docs — all doc clauses must fail there.
