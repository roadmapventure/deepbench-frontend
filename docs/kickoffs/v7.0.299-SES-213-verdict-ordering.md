## The mechanism, proven rather than argued

The chain, read out of the code this cycle:

- `scripts/verifier.js:242-248` — the gates are spawned with **no `env` option**, so they inherit
  the `SUPABASE_URL` / `SUPABASE_SERVICE_KEY` that step 7a's own command line exports. The
  *credentialed* half of the regression suite therefore runs inside the verifier.
- `tests/regression/SES-177-claude-state-renderer.js:140-153` — that credentialed half spawns
  `render-claude-state.js --check` and asserts exit 0.
- `scripts/render-claude-state.js:180-190` — `--check` compares the rendered body **byte-for-byte**
  against the committed `CLAUDE-STATE.md`, exit 1 on drift.
- `scripts/render-claude-state.js:162` — the render reads `runner_cycles` with
  `outcome=eq.shipped`; `:121` takes the last three. **The render is a pure function of the shipped
  set.**
- Runbook `runner-cycle.md:1770-1776` — a cycle's own row is not `shipped` until the step-9 tail,
  *after* its close-out render and its push.

So cycle N−1 renders while its own row is still open, pushes, then closes `shipped`. Cycle N
branches from that push: the ledger's shipped set now contains N−1 and the committed file does not
→ drift → `[FAIL]` → `gate_regression=red` → **block**. A cycle whose predecessor closed
`gated_before_build` / `did_not_run` never entered the shipped set, so the file still matches →
**approve**. That is exactly the 26/30 split, and it predicts the invariant triple.

## The design choice this cycle owned

The ticket named two orderings and left the choice to the build cycle. They **converge**: option A
as literally stated ("7a after the close-out render") is impossible, because the close-out render
sits *after* the ticket status write, and 7a's auto-done bar decides whether that status write is
`done` or `delivered` — so the verdict must precede it. Repaired A *is* B. The only live question
is **where the render invocation lives**, and that is decided against putting it inside
`verifier.js`:

- **The verdict-only invariant is decisive.** `scripts/verifier.js:9-14` — *"this script CANNOT
  EDIT… touches no file in the tree"* — is charter Multi-agent verification item 1, and the
  script's own header calls it *"the property most likely to be eroded."* Having the verifier spawn
  a file-writer is that invariant laundered, not preserved, and it would have the verifier grade a
  file it had just authored.
- **The fail directions are asymmetric, and that settles axis 5.** This repo's recorded lesson is
  that a rule each cycle must remember gets silently forgotten (`record_skip`'s precedent, cited
  eight times), which argues for code over a runbook sentence. It loses here because *forgetting
  the render reproduces exactly today's behaviour*: a spurious block, ship `delivered`, card John —
  loud, fail-closed, visible on the scoreboard, never a false approve. The in-verifier variant's
  failure mode is an invariant nobody sees erode.

**Decision: the render becomes an explicit sub-step opening 7a, in the runbook, not in the
verifier.**

## Task 2 — the second defect in the same ticket

`runner_verdicts.reasoning` records only the tail of the gate output, so all 26 rows carry an
unrelated `WARN: GATE_BYPASS_SECRET not found` and never the failing test. The site is
`scripts/verifier.js:256`:

```js
const tail = String(res.stderr || res.stdout || "").trim().split("\n").slice(-3).join(" | ");
```

`res.stderr || res.stdout` prefers stderr **wholesale**. Verified against the real output shape:
`tests/regression/run-all.js:77` prints `[FAIL] <file> -- <message>` via `console.log` (**stdout**),
while the warning is a `console.warn` (**stderr**). So the ledger keeps the noise and discards the
finding — which is why this ticket needed a live reproduction instead of a query.

The replacement selects the `[FAIL]` lines and the suite summary from **combined** output, falling
back to the last three lines for gates with no `[FAIL]` vocabulary (build, hygiene). It is
extracted as a **pure exported function** so the guard can test it directly rather than by spawning
a suite.
