## 6. DESIGN RULES

- **The count never disappears.** The sentence keeps `Fetched N records`, because the count is the
  measured fact and the titles are the sample; a build that replaced the number would make a short
  list look like the whole result set.
- **Cap at three, and say how many were held back.** `matchCount` is routinely 74 on
  `the_library_catalog`; an uncapped join would put a paragraph on a card whose sibling lines are one
  short sentence. `and N more` is the only honest way to shorten a list.
- **Absent titles fall through, they never render empty.** A path that returns no usable title
  (`roster`, `queryRAG`, a direct catalog read, any pre-`v7.0.212` frame) produces exactly today's
  sentence. Same rule as `LOG-37a-patch`'s ids: a fact with no honest source is omitted, never
  invented — and it is what keeps this ship backward-compatible with a stream replayed from a stored
  trace.
- **Titles are display, not identity.** They are not written to `call_facts`, not joined on, and not
  used to key anything; `_rag_chunk_ids` remains the id carrier. (`SES-116`'s rule one level out: a
  display string never reaches a key column.)
- **`§19s` four-surface standard, honoured as it stands.** This changes the *content* of a line the
  drawer already renders; it does not re-introduce any line `LAV-32a` removed. The `detail: true`
  sub-entries stay unrendered.

## 8. NODE.JS TEST

`tests/regression/LAV-17-evidence-record-titles.js`, run standalone and under
`tests/regression/run-all.js`. It compiles `src/components/RunTasks.jsx` with esbuild and imports the
**real** `deriveDid` (the `LAV-25-assembly-contract.js` pattern, same supabase stub), then asserts:

1. a fetch frame carrying `titles` renders the record names and the count;
2. a fetch frame with no `titles` renders **today's exact sentence**, character for character;
3. a frame with more titles than the cap renders three names plus `and N more`;
4. blank/null titles are filtered rather than rendered as empty quotes.

**Negative control (the discriminating half):** assertion 1 is written so it fails against the
pre-change `deriveDid` — the pre-change function returns `Fetched 3 chunks from the_library.` for the
same frame, which assertion 1 rejects. Assertion 2 is written so it fails against a build that
*always* switches to the new sentence. Neither assertion can pass on a no-op change.
