## 1. CONTEXT

Found this design session investigating John's report that the AI Audit screen has multiple data-integrity problems ahead of an Apple review, including "made up platform names" and patterns/data that don't match what the LLM actually did.

**AI-54:** `AboutPanel.jsx`'s `AIStackDiagram()` (an SVG under the About panel's Architecture tab, its Governance Layer literally labeled "◀ DeepBench AI Audit") states the Foundation Layer runs `Models (Claude · GPT-4)`. Grepped every `logAICall()`/`logActivity()` call site in the codebase — DeepBench has never called GPT-4 anywhere; the only real models are Claude (generation) and OpenAI `text-embedding-3-small` (embeddings only). This same file's own "By the Numbers" section (~160 lines later) already states the accurate model list correctly — the stack diagram is simply wrong, a static hand-written string with no data behind it.

**AI-55:** `CreateWorkOrderScreen.jsx`'s Goal Suggestion feature (streaming Haiku call via `api/plan.js`'s `suggest-goal` action) logs its AI Audit row client-side with `tokens: 0` hardcoded (lines 363, 373) — every real call shows `$0.00` cost forever, regardless of actual usage. Traced the real fix: `api/plan.js` already receives Anthropic's real `input_tokens`/`output_tokens` inside the SSE stream it relays to the client (`message_start`/`message_delta` events) — it currently forwards only the text deltas and throws the usage numbers away. The correct fix is server-side: capture the real usage, log it once via the platform's existing shared `logActivity()` (`lib/activity-log.js` — the same function every other server route already uses for this), and delete the client-side calls entirely, since they'd otherwise double-log the same call (once real, once fake). This exact pattern — remove a client-side `logAICall()` once the real log fires server-side — was already done once in this same file for the 'planning' type (see the `BUG-14` comments at lines 77/81); this session applies the identical precedent to 'goal_suggestion'.

No new `SERVICE_CATALOG`/`AI_TYPE_TO_SERVICE` entries are needed for AI-55 — `useAIActivity.js` already declares `goal-suggestion` (`patterns: ['Streaming','RAG']`) and already maps `goal_suggestion → goal-suggestion`. This session only makes the real per-call data match what's already declared — it does not claim RAG ran on calls where retrieval found nothing (same fabrication concern as AI-54, smaller scale): `patternsUsed` includes `'rag'` only when `ragContext` was actually non-empty for that call.

**Out of scope, John's explicit call this session:** the broader pattern-registry unification (`AI-35`), the global AI Audit screen's By-Agent taxonomy (`AI-38`), and the `SERVICE_CATALOG`/`PATTERN_CATALOG` hardcoded-vs-DB-backed architecture gap (`AI-25`/`AI-26`) are all separate, larger design sessions — not touched here. This session is scoped to the two cheapest, most visibly embarrassing fabrications only.

**2b.** Inside the `suggest-goal` action's streaming block, replace the reader loop (currently the block from `const reader = anthropicRes.body.getReader();` through the `res.write('data: [DONE]\n\n'); return res.end();` that follows it) with:
```js
      let inputTokens = null;
      let outputTokens = null;
      const streamStart = Date.now();

      const reader = anthropicRes.body.getReader();
      const decoder = new TextDecoder();

      while (true) {
        const { done, value } = await reader.read();
        if (done) break;
        const chunk = decoder.decode(value);
        const lines = chunk.split('\n').filter(l => l.trim());
        for (const line of lines) {
          if (line.startsWith('data: ')) {
            const data = line.slice(6);
            if (data === '[DONE]') continue;
            try {
              const parsed = JSON.parse(data);
              if (parsed.type === 'content_block_delta' && parsed.delta?.text) {
                res.write(`data: ${JSON.stringify({ text: parsed.delta.text })}\n\n`);
              } else if (parsed.type === 'message_start') {
                inputTokens = parsed.message?.usage?.input_tokens ?? null;
              } else if (parsed.type === 'message_delta') {
                outputTokens = parsed.usage?.output_tokens ?? outputTokens;
              }
            } catch {}
          }
        }
      }

      logActivity({
        tenantId: tenant_id, agentId: agent_id || 'michelle',
        aiType: 'goal_suggestion', feature: 'goal-suggestion',
        model: 'claude-haiku-4-5-20251001',
        inputTokens, outputTokens,
        latencyMs: Date.now() - streamStart,
        patternsUsed: ragContext ? ['streaming', 'rag'] : ['streaming'],
      });

      res.write('data: [DONE]\n\n');
      return res.end();
```
The `!anthropicRes.ok` early-return branch above this (no real call completed) is untouched — do not log on that path, same convention every other real-usage-dependent `logActivity()` call site in this codebase already follows.
