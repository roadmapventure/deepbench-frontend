## 2. CONTEXT

A session pushes a change, then checks the deployed dev preview to confirm it works. **Vercel does not reliably build every push to `dev`**, so the session is frequently looking at an older build without knowing it — and a stale-preview run is indistinguishable from a real result in either direction.

**This is measured, not assumed.** Across the 156 commits on `origin/dev` since 2026-07-28 12:00 CST, compared against every `dev` deployment Vercel actually produced (Vercel API, `meta.githubCommitRef === "dev"`):

| Metric | Value |
|---|---|
| Median lag from commit → first build containing it | **37 s** |
| p90 lag | **852 s (14 min)** |
| Max lag | **2,973 s (49.5 min)** |
| Commits waiting > 5 min | **44 / 156 (28%)** |
| Commits waiting > 10 min | **31 / 156 (20%)** |

The design session's own first commit (`bc60735`) sat unbuilt for **46 minutes**. A ~46-minute window that evening produced no `dev` build at all, covering ~8 commits from six different sessions. Commit `8fbfdd4` in that window is another session's ad-hoc workaround — *"chore: poke Vercel dev webhook (no build fired for 5c69eb0/94acad9/c74715a)"*.

**Why this is a beta ship-gate item.** `docs/BETA.md` §2b lists `SES-015` as REQUIRED before the first QA leg because bucket 1 (the 24-case CHI regression) is the ship gate. If that run starts against a preview 46 minutes behind, it reports on the wrong build. A false green there fakes the entire bucket.

**The knowledge already exists — in the wrong file.** `docs/SESSIONS.md` (commit `eece74f`, 2026-07-28) already documents the bundle-grep, the Vercel API check, and that `POST /v13/deployments` returns **402 Payment Required** on this plan so another push is the only remedy. But `SESSIONS.md` is 1.67 MB and `CLAUDE-STATE.md` explicitly instructs every session never to read it by default. So `SES-015` is not "write this down" — it is **move it where sessions read, and make it a gate rather than a note.**

**Two paths, different sufficiency — verified live this session, do not collapse them:**

| QA path | Edge cache? | What is sufficient |
|---|---|---|
| `api/` route (the regression driver's `POST /api/capabilities/execute`) | **No** — measured `X-Vercel-Cache: MISS` on POST | The SHA gate alone |

## 5. TASKS

### Task 1 — `scripts/check-deploy-current.js` (new file)

An ESM guard matching `scripts/check-api-function-count.js`'s house style: `#!/usr/bin/env node`, the `// DeepBench | scripts/<name> | SES-015` header comment, a `FEATURE:` line, a usage line, documented exit codes, and a `--worktree=<path>` argument defaulting to `process.cwd()`.

**Arguments**
- `--worktree=<path>` — repo/worktree to check. Default `process.cwd()`.
- `--sha=<sha>` — commit to test. Default: `git -C <worktree> rev-parse HEAD`.
- `--timeout=<seconds>` — total poll budget. Default `300`.
- `--json` — emit a single JSON object instead of prose (for scripted callers).

**Behavior**

1. Read `process.env.VERCEL_TOKEN`. If absent: print that it is a persistent Windows env var per `docs/ENV-VARS.md`, that a process started before it was set will not see it, and **exit 2** (distinct from a stale-deploy failure — an unrunnable check must never be reported as a pass).
2. `git -C <worktree> fetch origin dev --quiet` so deployed SHAs are resolvable locally.
3. `GET https://api.vercel.com/v6/deployments?app=deepbench-frontend&limit=40` with `Authorization: Bearer ${VERCEL_TOKEN}`. Keep only `meta.githubCommitRef === "dev"`. Sort by `created` descending.
4. `serving` = first with `readyState === "READY"` **and** truthy `aliasAssigned`.
5. **Coverage test — ancestor, never equality.** Pass when the tested SHA is *contained in* what is deployed:
   `git -C <worktree> merge-base --is-ancestor <sha> <serving.meta.githubCommitSha>` (exit 0 = covered).
   **This is the single most important line in the file.** With 5–7 concurrent sessions the deployed tip is usually *ahead* of yours; strict equality would fail almost always and the gate would be ignored within a day. Verified live: `bc60735` correctly PASSED while the preview served a later commit.
   If the serving SHA is not resolvable locally after the fetch (`git cat-file -e <sha>^{commit}` fails), treat as not covered and say why — never assume coverage.
6. If covered → print the serving SHA and **exit 0**.
7. If not covered, branch on whether Vercel has any work in flight (`readyState` in `QUEUED` / `BUILDING` / `INITIALIZING`):
   - **Pending build exists** → poll every 15 s until covered or `--timeout` expires. Measured build duration is ~25 s, so this normally resolves in one or two polls.
   - **No pending build** → wait a single 90 s webhook grace period (re-query once), because a just-pushed commit can take a few seconds to register. If there is still no pending build and still no coverage, stop — **do not burn the remaining timeout.** This is the proven-futile case: `SESSIONS.md` records 12 minutes of waiting with nothing queued, and this session measured a 46-minute dead window. Print the `no-build-fired` remedy (below) and **exit 1**.
8. On timeout while a build was genuinely pending → **exit 1**, stating what was pending.

**Failure output must name the remedy, not just the problem.** On `no-build-fired`, print exactly this guidance:

> No Vercel build was ever triggered for this commit. Waiting will not help — this has been observed to persist for 46 minutes.
> A manual API trigger is not available on this plan (`POST /v13/deployments` returns 402 Payment Required).
> The working remedy is to push another commit, which triggers a build that includes this one:
>   `git -C <worktree> commit --allow-empty -m "chore: poke Vercel dev webhook (no build fired for <sha7>)"`
>   `git -C <worktree> push origin HEAD:dev`

**Exit codes:** `0` covered · `1` not covered (stale / no build / timeout) · `2` cannot run (no token, API error).

Export `pickServing`, `pickPending`, and `decide` for the Node test.

## 8. NODE.JS TEST

Write to `test-ses-015.mjs`, run with `node test-ses-015.mjs`, delete before committing. Pure logic against synthetic fixtures — no network, no git.

```js
import { pickServing, pickPending, decide } from "./scripts/check-deploy-current.js";

let pass = 0, fail = 0;
const t = (name, cond) => {
  if (cond) { pass++; console.log(`  PASS  ${name}`); }
  else { fail++; console.log(`  FAIL  ${name}`); }
};

const dep = (sha, readyState, aliasAssigned, created, ref = "dev") => ({
  meta: { githubCommitSha: sha, githubCommitRef: ref },
  readyState, aliasAssigned, created,
});

console.log("SES-015 — deploy-current gate logic\n");

// --- pickServing -----------------------------------------------------------
t("picks the newest READY+aliased dev deployment",
  pickServing([
    dep("aaa", "READY", 1, 300),
    dep("bbb", "READY", 1, 100),
  ])?.meta.githubCommitSha === "aaa");

t("ignores a READY deployment that never took the alias",
  pickServing([
    dep("aaa", "READY", null, 300),
    dep("bbb", "READY", 1, 100),
  ])?.meta.githubCommitSha === "bbb");

t("ignores BUILDING deployments when choosing what is served",
  pickServing([
    dep("aaa", "BUILDING", null, 300),
    dep("bbb", "READY", 1, 100),
  ])?.meta.githubCommitSha === "bbb");

t("ignores non-dev branches",
  pickServing([dep("aaa", "READY", 1, 300, "main")]) === null);

t("returns null when there is nothing READY",
  pickServing([dep("aaa", "BUILDING", null, 300)]) === null);

// --- pickPending -----------------------------------------------------------
t("counts QUEUED, BUILDING and INITIALIZING as pending",
  pickPending([
    dep("a", "QUEUED", null, 4),
    dep("b", "BUILDING", null, 3),
    dep("c", "INITIALIZING", null, 2),
    dep("d", "READY", 1, 1),
  ]).length === 3);

t("CANCELED and ERROR are not pending",
  pickPending([dep("a", "CANCELED", null, 2), dep("b", "ERROR", null, 1)]).length === 0);

// --- decide ----------------------------------------------------------------
const serving = dep("aaa", "READY", 1, 100);

t("covered -> live, exit 0",
  decide({ covered: true, serving, pending: [] }).exitCode === 0 &&
  decide({ covered: true, serving, pending: [] }).verdict === "live");

t("not covered but a build is pending -> building (keep polling)",
  decide({ covered: false, serving, pending: [dep("b", "BUILDING", null, 2)] }).verdict === "building");

t("not covered and nothing pending -> no-build-fired, exit 1",
  decide({ covered: false, serving, pending: [] }).verdict === "no-build-fired" &&
  decide({ covered: false, serving, pending: [] }).exitCode === 1);

t("no serving deployment at all -> no-deployment, exit 1",
  decide({ covered: false, serving: null, pending: [] }).verdict === "no-deployment" &&
  decide({ covered: false, serving: null, pending: [] }).exitCode === 1);

// --- the regression this gate exists to prevent ----------------------------
t("a covered commit never yields a failing exit code",
  [[], [dep("x", "BUILDING", null, 9)]].every(
    p => decide({ covered: true, serving, pending: p }).exitCode === 0));

console.log(`\n${fail === 0 ? "ALL TESTS PASS" : "TESTS FAILED"} — ${pass} passed, ${fail} failed`);
process.exit(fail === 0 ? 0 : 1);
```
