## 5. TASKS (2)

### T1 — Breadcrumb stage from current-journey content only
At the `currentStage(...)` call site (top-level screen), pass membership-filtered values instead of raw state — the pure function itself does NOT change:
```js
currentStage({
  qaEvidence: getStep("qa") != null ? qaEvidence : null,
  hypFlow: (hypFlow && hypFlow.journeySeq === journeyRef.current.seq) ? hypFlow : null,
})
```
(Reuse the same `hypCurrent` expression the arrival effect already computes — hoist it to a shared `const` if cleaner. `getStep("qa") != null` is the qa-membership test: qa has a step in the current journey iff its content belongs to it.) Net effect verified against QA's repro: stale resolved flow + new Analysis → "Analysis"; right after a news-click reset with a stale unresolved flow → "Question".

### T2 — Gate the three "Needs Your Decision" badges on membership
`EvidenceColumn` gains one new prop, `hypIsCurrent` (boolean, the same `hypCurrent` expression, computed at top level and passed down). Gate each badge:
- Candidates drawer `headerRight`: `hypFlow.stage === "choosing" && hypIsCurrent ? <NeedsDecisionBadge/> : null`
- Result drawer `headerRight`: the existing `hypFlow.stage === "result" && !hypFlow.resolution` condition additionally requires `hypIsCurrent`
- Draft Forecast drawer `headerRight`: `hypIsCurrent ? <NeedsDecisionBadge/> : null` (currently unconditional per `CHI-50`)
Do NOT touch the qa/Analysis drawer's badge (`!qaEvidence.reviewChoice` — the qa slot is overwritten each journey, no stale case). Do NOT touch open/close logic, footers, or `useDrawerStack`.
