## CONTEXT

`QaEvidenceCard` (desktop `EvidenceColumn`, mobile Evidence tab) has no height/overflow control — headline, body, table, byline, elapsed-line, flagged-line, and the "Needs your input" CTA are flat siblings in one div, so the CTA renders however far down the accumulated content pushes it. John had to scroll Column 2 to find it on a real long answer (live screenshot, `CHI-12` row, `docs/FEATURES.md`).

Two fixes:
1. Remove the "Full Agent Routing & Answer Given in Xm Ys" line and the "⚑ Marcus flagged this —" line — both now duplicated in the Chat bubble by `CHI-08` (`v6.3.38`, shipped). The "Formatted by {agent} · {role}" byline is **not** a duplicate — it stays, becoming the last line inside the bounded content box.
2. Wrap the remaining content (headline/body/tables/byline) in a bounded, independently-scrollable box (`maxHeight:320`, `overflowY:"auto"`, top/bottom border) that ends above the footer. The footer (review-choice ack, or the "Needs your input" CTA block) is untouched and renders below that box, unbounded — always fully visible without scrolling.

Mock approved live with John (two iterations — first attempt didn't demonstrate the actual overflow bug, second nailed it): content sits in its own bordered box that ends cleanly at a fixed height with an internal scrollbar; the CTA sits fully visible below it with margin to spare, never crowding the bottom edge.

- `overflowY: "auto"`, `borderTop`/`borderBottom` only, `1px solid T.line` — no side borders (reuses the card's own outer border), no `borderRadius` (squared corners, existing convention throughout this file)
- No new colors or fonts introduced — reuses `T.line`, `body`, `mono` already imported in this file
- Zero change to `onGoodThanks`/`onReview`/`reviewChoice` rendering logic or the CTA block's own styling
