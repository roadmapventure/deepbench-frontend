## 2. CONTEXT

`S-CHI-26c` fixed the fade never appearing at all (the detection logic). Re-verifying live against the real deployed dev preview (Japan example question, a genuinely long answer with 5 prose sections + 2 tables), the fade now **does** appear automatically with no manual scroll needed — but it renders in the wrong place: pinned to the bottom of the entire Evidence & Interaction card (behind/at the same level as the "NEEDS YOUR INPUT" footer with its "Good, thanks"/"Have Priya generate theories" buttons), instead of at the bottom edge of the scrollable analysis content itself.

**Root cause, confirmed via direct DOM measurement (`getBoundingClientRect()` on the fade element and its ancestor chain):** `ScrollFadeHint` is `position:"absolute"`, `bottom:0` — this resolves relative to its **nearest positioned ancestor**, which is `EvidenceColumn`'s outer card div (`position:"relative"`, added in the original `S-CHI-26`/`CHI-29` task). That outer card wraps three siblings: the scroll body, the `ScrollFadeHint`, and the footer (`{footerKind && (...)}`) — all three share the same positioned ancestor. Since the footer is the last flex child, the outer card's own bottom edge coincides with the *footer's* bottom, not the scroll body's. `bottom:0` on the fade therefore glues it to the bottom of the whole card (past the footer), not to the scroll body's own visible cutoff point — measured directly: the scroll body's own rect ended at `y≈525`, but the fade rendered at `y≈745`, matching the outer card's true bottom, not the scroll body's.

This is a design-spec mistake from the original `CHI-29` task (this design session's own error, not a coding-session implementation error — the coding session built exactly what was specified). The mobile Agent Routing feed's own `MI-50`/`CHI-29` instance doesn't have this bug because its `position:"relative"` container wraps *only* the scroll body + fade, with no footer sharing that same positioned ancestor — a structural difference between the two call sites this design session's original task spec failed to account for.

## 5. TASKS (1)

### Task 1 (`CHI-29` third patch) — Give the scroll body + fade their own positioned wrapper, separate from the footer

In `src/screens/MarketIntelligenceScreen.jsx`, `EvidenceColumn`'s populated-state return, current (buggy) shape:
```jsx
<div style={{background:T.cardAlt,border:`1px solid ${T.lineSoft}`,display:"flex",flexDirection:"column",flex:1,minHeight:0,overflow:"hidden",gap:14,position:"relative"}}>
  <div ref={evidenceScrollRef} onScroll={checkEvidenceScroll} style={{padding:"16px 16px 0",display:"flex",flexDirection:"column",gap:14,overflowY:"auto",flex:1,minHeight:0}}>
    {/* ... all the scrollable content ... */}
  </div>
  <ScrollFadeHint show={evidenceCanScrollMore} bg={T.cardAlt}/>
  {footerKind && (
    <div style={{padding:"10px 14px",borderTop:`1px solid ${T.line}`,position:"relative"}}>
      {/* ... footer content, unchanged ... */}
    </div>
  )}
</div>
```

Fixed shape — wrap only the scroll body + `ScrollFadeHint` in a new `position:"relative"` div sized to fill the same space the scroll body used to occupy directly (`flex:1,minHeight:0,display:"flex",flexDirection:"column"`, no padding/margin of its own so it introduces zero visual change to spacing), leaving the footer as a sibling of that new wrapper instead of the scroll body:
```jsx
<div style={{background:T.cardAlt,border:`1px solid ${T.lineSoft}`,display:"flex",flexDirection:"column",flex:1,minHeight:0,overflow:"hidden",gap:14}}>
  {/* FEATURE: CHI-29 — third patch (S-CHI-26d): dedicated position:"relative" wrapper around just
      the scroll body + fade, separate from the footer. The original CHI-29 task put position:
      "relative" on this outer card instead (which also contains the footer as a sibling) -- since
      absolute+bottom:0 resolves against the NEAREST positioned ancestor, the fade was gluing itself
      to the bottom of the whole card (behind the footer) instead of the scroll body's own visible
      edge. This wrapper's bounds exactly match the scroll body's own rendered box (same flex:1/
      minHeight:0 sizing, zero added padding/margin), so the fade now correctly overlays the scroll
      body's own bottom edge, sitting above the footer where it belongs. */}
  <div style={{position:"relative",display:"flex",flexDirection:"column",flex:1,minHeight:0}}>
    <div ref={evidenceScrollRef} onScroll={checkEvidenceScroll} style={{padding:"16px 16px 0",display:"flex",flexDirection:"column",gap:14,overflowY:"auto",flex:1,minHeight:0}}>
      {/* ... all the scrollable content, UNCHANGED ... */}
    </div>
    <ScrollFadeHint show={evidenceCanScrollMore} bg={T.cardAlt}/>
  </div>
  {footerKind && (
    <div style={{padding:"10px 14px",borderTop:`1px solid ${T.line}`,position:"relative"}}>
      {/* ... footer content, unchanged ... */}
    </div>
  )}
</div>
```

Notes:
- The outer card's own `position:"relative"` (no longer needed there since nothing else inside it is absolutely positioned relative to it) can be dropped — but leaving it is harmless (a `position:relative` with no absolutely-positioned direct children is a no-op) if that's simpler to diff; either is acceptable, prefer removing it for clarity since it's dead styling once this patch lands.
- The `gap:14` on the outer card still applies between its (now two, was three) direct children — the new wrapper and the footer — producing the exact same visual gap `CHI-18` locked, since the new wrapper's own rendered height ends exactly where the scroll body used to end (zero added padding/margin on the wrapper itself).
- Do not touch anything inside the scroll body's own content, the footer's own content, `useScrollFadeHint` itself (already fixed correctly in `S-CHI-26c`), or the mobile Agent Routing feed's own instance (`MobileBody`) — that one already has the correct isolated-wrapper structure and is not affected by this bug.

## 8. NODE.JS TEST

Save as `test-chi-29-patch3.mjs`, run with `node test-chi-29-patch3.mjs`, delete before committing.

```js
import { readFileSync } from "fs";

let pass = 0, fail = 0;
function assert(cond, label) {
  if (cond) { pass++; console.log(`PASS: ${label}`); }
  else { fail++; console.error(`FAIL: ${label}`); }
}

const src = readFileSync(new URL("./src/screens/MarketIntelligenceScreen.jsx", import.meta.url), "utf8");

const fnStart = src.indexOf("function EvidenceColumn(");
assert(fnStart !== -1, "EvidenceColumn found");
const nextFnMatch = src.slice(fnStart + 20).match(/\nfunction [A-Za-z]/);
const fnEnd = nextFnMatch ? fnStart + 20 + nextFnMatch.index : src.length;
const fnSrc = src.slice(fnStart, fnEnd);

// The regression this test exists to catch: ScrollFadeHint and the footer conditional
// ({footerKind && ...) must NOT share the same position:"relative" ancestor as each other in a way
// that puts them as direct siblings under one relative div -- i.e. there must be a dedicated
// wrapper between ScrollFadeHint and the outer card. Concretely: the text "position:\"relative\""
// must appear on a div whose very next sibling-in-source (before the footer's own div) is the
// scroll body div with evidenceScrollRef, and ScrollFadeHint must close before the footer's own
// {footerKind && block opens, all inside that SAME wrapper -- while the OUTER card (identified by
// containing both this wrapper and the footer block) must not itself be the element ScrollFadeHint
// resolves against.
const scrollBodyIdx = fnSrc.indexOf("ref={evidenceScrollRef}");
const fadeIdx = fnSrc.indexOf("<ScrollFadeHint");
const footerIdx = fnSrc.indexOf("{footerKind && (");
assert(scrollBodyIdx !== -1, "scroll body (evidenceScrollRef) found");
assert(fadeIdx !== -1, "ScrollFadeHint render found");
assert(footerIdx !== -1, "footer conditional found");
assert(scrollBodyIdx < fadeIdx && fadeIdx < footerIdx, "order is: scroll body, then ScrollFadeHint, then footer");

// Count position:"relative" occurrences between the scroll body's own opening and the footer's
// opening -- there must be at least one wrapping div with position:"relative" that starts AFTER
// the outer card's own div and BEFORE the scroll body div, i.e. a dedicated inner wrapper (not
// just the outer card's own relative, which would be the only one before Task 4's original patch).
const beforeScrollBody = fnSrc.slice(0, scrollBodyIdx);
const lastOuterCardOpenIdx = beforeScrollBody.lastIndexOf('background:T.cardAlt');
const betweenOuterAndScrollBody = fnSrc.slice(lastOuterCardOpenIdx, scrollBodyIdx);
assert(betweenOuterAndScrollBody.includes('position:"relative"'), "CHI-29 patch 3: a dedicated position:relative wrapper div exists between the outer card and the scroll body (not just the outer card's own position:relative)");

// The footer's own div must NOT be inside that same dedicated wrapper -- i.e. between fadeIdx and
// footerIdx, the wrapper div opened above must have already closed (a closing </div> appears)
// before the footer div opens.
const betweenFadeAndFooter = fnSrc.slice(fadeIdx, footerIdx);
assert(betweenFadeAndFooter.includes("</div>"), "CHI-29 patch 3: the dedicated wrapper closes before the footer div opens (footer is a sibling of the wrapper, not inside it)");

console.log(`\n${pass}/${pass + fail} tests passed`);
if (fail > 0) process.exit(1);
```
