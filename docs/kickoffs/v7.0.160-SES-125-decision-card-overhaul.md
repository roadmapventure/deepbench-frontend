## 2. CONTEXT

`SES-124` (`v7.0.159`) shipped the **section frame** — the masthead counter, §2 Daily activity,
§3 Today's findings, the §4 frame, the locked section order, and the collapse framework
(`.item.fold` + `.head[data-toggle]` + `.bodyc`, `h2.clickable` + `.secwrap`, one handler,
`fold()` as the helper). It deliberately did **not** convert a single card: `fold` was made a
CSS *modifier* precisely so the always-open cards could ship untouched until this ticket.

This ticket converts them. Four sections change shape:

- **§5 Shipped** and **§6 Gated before build** — cards default **closed**, numbered `5.1…` /
  `6.1…`, collapsed row carries number + kind chip + **ticket ID** + ticket title + decision
  state. Open card leads with the **plain-language three fields** (`plain_cant` /
  `plain_after` / `plain_worth`) as the **default body**, and the technical record (Value case,
  Before → After, QA evidence, meta, links) moves **under More info**. This is the display
  **reversed** from `v7.0.145`, where the technical record was the body and the plain language
  was hidden behind the button.
- **§9 Questions** — rows default **closed**, numbered `9.1…`, collapsed row shows the question
  text + answer state; consequence lines stay required under both buttons.
- **§12 Vision claims** — a section that has never existed in the template at all. Formatted
  exactly like §9: Yes/No + open text, always 3 rows, default closed, each row led by a
  **class chip** naming the judgment class the claim sets criteria for.

Across all four, the **ask box moves out of the More-info panel and becomes always visible
under the buttons**, with a "✓ Received …" label once a line has been recorded, and the thread
rendered above it.

**Premise revalidated live this cycle (not recalled), by reading
`docs/runbooks/briefing-template.html` at `origin/dev`:** `card()` (line 304) renders an
always-open `.item` with the technical body first and `moreInfo()` holding the plain language;
`question()` (line 337) renders an always-open `.q`; `askBox()` (line 263) is emitted *inside*
the `.more` panel by both; there is no vision-claim renderer and §12 exists only as the HTML
comment `// §12 · Vision claims (formatted exactly like §9): SES-125.` at line 482. The gap is
real and untouched. `revalidated_at` stamped (before-image filed first).

## 6. DESIGN RULES

- **Treasury tokens verbatim** — the mock introduces no new colour; `.clschip` uses `--navy`
  and `--white`, `.got` uses `--moss`. No new CSS variable is added.
- **A fold never publishes and never enters `briefing-state`** (`SES-124`). Converting cards to
  folds must not add a single state key. Only a decision, an answer, an ask or a reading
  publishes.
- **`plain_*` are READ from the row, never re-authored at render time** (`v7.0.146`), and
  **`NULL` must not be coerced to `''`** — the red defect line is the point.
- **Consequence lines are required** on every Yes/No row (`v7.0.145`); a row without them
  renders the defect in red rather than two bare buttons.
- **`data-awaits="1"` on every undecided card, unanswered question and undecided vision row** —
  §1's counter is computed from it (`SES-124`), so §12's rows joining the count is a
  requirement, not a side effect.
- **Buttons on a gated card are never captioned as rating the work** (`briefing-page.md`);
  `buttonMeanings('gate', …)` already encodes that and is preserved.
