## 2. CONTEXT

`S-CHI-26`'s `CHI-29` task added a new hook call (`useRef` + the shared `useScrollFadeHint`, which itself calls `useState`/`useEffect` internally) inside `EvidenceColumn`, **placed after the function's existing early return** (`if (!qaEvidence && !hypFlow) { ... return (...); }`). This violates React's Rules of Hooks: hooks must be called unconditionally, in the same order, on every render of a given component instance. When `EvidenceColumn` is in its empty state, it returns before ever reaching the new hook call (0 extra hooks that render); the instant `qaEvidence`/`hypFlow` becomes truthy (a real answer arrives), the *same mounted component instance* re-renders and now reaches the hook call (1 extra hook) — a hook-count mismatch between consecutive renders of the same instance, which crashes React with "Minified React error #310" (rendered more hooks than during the previous render).

**Live-reproduced during `S-CHI-26-design`'s own Manual QA verification** (not theorized): asked a real question against the deployed dev preview; the moment Marcus's answer arrived and `EvidenceColumn` transitioned from empty to populated state, the app crashed to a blank page with `React error #310` in the console, confirmed via `read_console_messages`.

**Root cause, precisely:** the hook call sits at source lines ~1531-1532, physically after the early-return block at lines ~1502-1523. The fix is purely a move — relocate the hook call above the early return, alongside `EvidenceColumn`'s other unconditional hooks (`useState`/`useAgents`/`useEffect`), so it runs on every render regardless of which branch the function later takes.

**Process note, not part of the code fix:** this was caught by the design session's own live verification exactly as intended (`CLAUDE-DESIGN.md` Step 5b) — the first coding session's Node test and `npm run build` both passed because neither exercises a real state transition from the empty to the populated branch of a mounted component; only a live browser interaction that goes through that transition surfaces a Rules-of-Hooks violation. The Node test below adds a structural check for this exact class of mistake (a hook call appearing after an early `return` in the same function) so a future session touching this function gets a fast, cheap regression signal without needing a live browser check to catch it.

Fixed shape — move the `evidenceScrollRef`/`useScrollFadeHint` call up to sit with the function's other unconditional hooks, before the early return, and leave everything else (including the `st`/`stActualPoints`/`footerKind` computations, which are plain variable assignments, not hooks, and are correctly allowed to stay after the early return) untouched:
```js
function EvidenceColumn({ hypFlow, qaEvidence, onIntentChange, onSelectHypothesis, onDiscard, onCommit, onResolveConfirmation, onGoodThanks, onReview }) {
  const [customText, setCustomText] = useState("");
  const [showOwnTheory, setShowOwnTheory] = useState(false);
  const agents = useAgents();
  const nadia = agents.find(a => a.id === "nadia");
  // FEATURE: CHI-29 — moved above the early return below (patch, S-CHI-26b): this hook must run
  // unconditionally on every render, same as every other hook in this function. The original
  // placement (after the early return) violated React's Rules of Hooks — EvidenceColumn calls a
  // different number of hooks depending on whether qaEvidence/hypFlow are set, which crashes React
  // ("Minified React error #310") the instant the component transitions from its empty state to
  // its populated state, since that's a re-render of the same mounted instance with a different
  // hook count. Found live during S-CHI-26-design's own Manual QA verification.
  const evidenceScrollRef = useRef(null);
  const { canScrollMore: evidenceCanScrollMore, onScroll: checkEvidenceScroll } = useScrollFadeHint(evidenceScrollRef, [qaEvidence, hypFlow]);

  useEffect(() => {
    if (hypFlow && hypFlow.prefillText) { setCustomText(hypFlow.prefillText); setShowOwnTheory(true); }
  }, [hypFlow && hypFlow.prefillText]);

  const showSubmittedTheory = !!(hypFlow && hypFlow.chosenText && (hypFlow.stage === "testing" || hypFlow.stage === "result" || hypFlow.confirmation));

  if (!qaEvidence && !hypFlow) {
    // ... empty-state return, UNCHANGED ...
  }

  const st = hypFlow?.hypothesisTest;
  const { actual: stActualPoints, theorized: stTheorizedPoints } = groupKeyDataPoints(st?.key_data_points);
  const footerKind = selectEvidenceFooterKind(qaEvidence, hypFlow);

  return (
    // ... populated-state return, UNCHANGED except the FEATURE comment above the old hook-call
    // location is removed since the hook itself moved ...
  );
}
```

Do not change anything else in this function — the empty-state JSX, the populated-state JSX, the `evidenceScrollRef`/`checkEvidenceScroll` wiring on the scroll body div, and the `<ScrollFadeHint .../>` render are all already correct and untouched by this patch; only the hook call's *position* moves.

## 8. NODE.JS TEST

Save as `test-chi-29-patch.mjs`, run with `node test-chi-29-patch.mjs`, delete before committing.

```js
import { readFileSync } from "fs";

let pass = 0, fail = 0;
function assert(cond, label) {
  if (cond) { pass++; console.log(`PASS: ${label}`); }
  else { fail++; console.error(`FAIL: ${label}`); }
}

const src = readFileSync(new URL("./src/screens/MarketIntelligenceScreen.jsx", import.meta.url), "utf8");

// Isolate EvidenceColumn's own source (from its function declaration to the next top-level
// function declaration), so this check is scoped to the one function that had the bug.
const startIdx = src.indexOf("function EvidenceColumn(");
assert(startIdx !== -1, "EvidenceColumn function found in source");
const afterStart = src.slice(startIdx);
const nextFnMatch = afterStart.slice(20).match(/\nfunction [A-Za-z]/);
const endIdx = nextFnMatch ? startIdx + 20 + nextFnMatch.index : src.length;
const fnSrc = src.slice(startIdx, endIdx);

// The early-return gate line, and the hook call line, both must exist inside this function.
const earlyReturnIdx = fnSrc.indexOf("if (!qaEvidence && !hypFlow)");
const hookCallIdx = fnSrc.indexOf("useScrollFadeHint(evidenceScrollRef");
assert(earlyReturnIdx !== -1, "CHI-29 patch: EvidenceColumn's early-return gate is present");
assert(hookCallIdx !== -1, "CHI-29 patch: EvidenceColumn calls useScrollFadeHint");

// The regression this test exists to catch: the hook call must appear BEFORE the early return,
// not after it -- Rules of Hooks requires every hook to run unconditionally, every render.
assert(hookCallIdx !== -1 && earlyReturnIdx !== -1 && hookCallIdx < earlyReturnIdx,
  "CHI-29 patch: useScrollFadeHint call appears BEFORE the early return (Rules of Hooks satisfied)");

// General-purpose structural guard, not specific to this one hook: no useRef/useState/useEffect/
// useScrollFadeHint call anywhere in EvidenceColumn should appear after its first early `return`
// statement (a broader net than the single assertion above, in case another hook gets added here
// later by a future session and repeats the same mistake in a different spot).
const firstReturnIdx = fnSrc.indexOf("return (");
const hookPattern = /\b(useState|useRef|useEffect|useScrollFadeHint)\s*\(/g;
let m, hooksAfterFirstReturn = 0;
while ((m = hookPattern.exec(fnSrc)) !== null) {
  if (firstReturnIdx !== -1 && m.index > firstReturnIdx && m.index < earlyReturnIdx) {
    // inside the empty-state JSX block itself (between the early-return's own `return (` and its
    // closing) doesn't count -- these aren't hook calls, just JSX; the regex only matches real
    // call syntax, so a false hit here would mean a real hook call was placed inside the empty-
    // state's JSX return, which would be its own bug worth flagging.
    hooksAfterFirstReturn++;
  }
}
assert(hooksAfterFirstReturn === 0, "CHI-29 patch: no hook call sits between EvidenceColumn's first return and its early-return gate");

console.log(`\n${pass}/${pass + fail} tests passed`);
if (fail > 0) process.exit(1);
```
