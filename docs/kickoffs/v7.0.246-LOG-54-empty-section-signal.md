## What shipped

`ai_activity_log.call_facts.empty_sections` — per call, which **declared-required** properties of a
structured response arrived empty.

**Tri-state, and the middle state is the load-bearing one:**

- key **absent** → the observation does not apply (no declared object schema, no `required`, or a
  text call), or the row predates v7.0.246
- **`[]`** → checked N required properties, all filled — the compliant case
- `["complicates", …]` → these arrived empty, sorted

**The `[]` is a deliberate exception** to `buildCallFacts()`'s omit-when-empty convention. §19j
question 1 asks whether the content specialist complies *reliably*, which needs the denominator
(calls checked) and the numerator (calls with an empty section) from the same column. Omitting `[]`
collapses "checked, all filled" into "never checked", so a silently broken derivation would read as
**perfect compliance** — failing toward "don't build the reviewer", invisibly. Assert both
directions; same lesson as `.claude/rules/supabase-column-grants.md`.

**Generic by construction.** `.claude/rules/capabilities-are-data.md` forbids an
agent/capability/intent conditional in this file, so the **schema** drives the read. No slug appears
anywhere in the derivation, and the guard asserts that.

**Emptiness is whole-value and type-driven:** `null`/absent, whitespace-only strings, empty
arrays/objects, and arrays/objects all of whose members are empty. `0` and `false` are **content**.
Accepted under-report, stated not hidden: `{text: null, citations: ["c1"]}` counts as *filled* —
conservative direction, misses a possible failure rather than inventing one.
