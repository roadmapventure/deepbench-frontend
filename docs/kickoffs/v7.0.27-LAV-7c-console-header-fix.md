## 2. CONTEXT
John's round-2 item 6: the events pane's column-title row shows a gap above it with real data visible in that gap once the pane is scrolled. Root-caused live this session (`design-lav-0801`) via real DOM measurement on the deployed preview, not guessed:

`.lavc-events` (the scroll container) carries `padding:6px 10px`. `.lavc-hdrow` (the sticky field-label row) is pulled flush to the container's edges with `margin:-6px -10px 4px` so it can span full width, and uses `position:sticky; top:0`. **The negative margin and the sticky `top` offset are fighting each other**: the margin repositions the header's *at-rest* position 6px higher (flush with the border edge, inside the padding region), but `position:sticky`'s stuck threshold is computed independently, relative to the scroll container's *padding* edge — which sticky's own `top:0` still measures from the padding edge, 6px below where the margin placed it at rest. The instant the pane scrolls even slightly, sticky snaps the header down 6px to the padding-edge threshold — a visible jump that uncovers 6px of whatever row was scrolled underneath it. Confirmed live: after scrolling, a row that should have been fully clipped above the header rendered at `y=574` while the pane's own border-top sat at `y=584` — 10px of real event text bleeding above the visible boundary.

**Fix:** the sticky threshold has to match the margin, not fight it. Setting `top: -6px` (the negative of the container's own `padding-top`) shifts sticky's threshold to exactly where the negative margin already placed the header at rest — eliminating the jump and, with it, the gap. No other visual change.
