## 2. CONTEXT
The briefing page (claude.ai artifact `4c22b9b1-6b14-4092-b728-1756a59b3173`) is rebuilt every runner cycle from `docs/runbooks/briefing-template.html`. Each Ship (§5) and Gated (§6) card head is a flex row: `.cardnum` · `.kind` chip · `.idchip` · `.ttl` (flex:1) · `.st` · `.chev`. `.idchip` is `flex-shrink:0`, which was fine for short IDs (`SES-133`) but the chip renders `coalesce(backlog_id, display_ref)` (SES-116), and long `display_ref` values — e.g. `directive 603f44ea (Runner · P10 - Tooling)` or `no ticket yet — your Accept files one (follows SES-140 / SES-141)` — refuse to shrink. Result on desktop, seen live by John 2026-08-23: the title (`flex:1`, basis 0) collapses to one word per line (card 5.14), or the row's total minimum width exceeds the card and `.item.fold{overflow:hidden}` clips the title and status column unreadable (card 6.2). Fix approved by John 2026-08-23: let the chip wrap, capped at 45% of the row, so the title always keeps the majority of the width. CSS-only; the fix reaches the live page at the next cycle republish.

## 5. TASKS (1)

### Task 1 — let `.idchip` wrap under a 45% cap
In `docs/runbooks/briefing-template.html`, change exactly one CSS rule. Current (line ~106):

```css
.idchip{font-family:var(--mono);font-size:10px;color:var(--brass-deep);flex-shrink:0}
```

New:

```css
.idchip{font-family:var(--mono);font-size:10px;color:var(--brass-deep);flex:0 1 auto;
        min-width:0;max-width:45%;overflow-wrap:anywhere}
```

Why each property: `flex:0 1 auto` lets the chip shrink; `min-width:0` lets flexbox shrink it below its content width; `max-width:45%` guarantees `.ttl` (flex:1) keeps the majority of the row; `overflow-wrap:anywhere` wraps the long mono strings (they contain `—`, `·`, `/` but also long runs) instead of overflowing. No markup change, no JS change, no other rule touched.

Also update the template's version-header comment block at the top of the file: add a line `<!-- DeepBench v7.0.193 | briefing-template.html | SES-148 — .idchip may shrink and wrap (max-width:45%) so a long display_ref can never crush .ttl or push .st past the card edge -->` in the same style as the existing header comments, **below** the `<title>` line — never above it and never disturbing `<title>DeepBench Morning Briefing</title>` within the first 8192 bytes (SES-138 served-name invariant).
