## The finding

Every one of the 52 tables reported `FILE MISSING`; `Integrity: 52 problem(s).`; exit 1. The
restore path's own guard then refuses with **`Refusing to restore from an altered backup.`**

Nothing is altered. Measured both directions, which is what makes it a finding rather than a
symptom:

| | resolve as stored | resolve after separator normalization |
|---|---|---|
| manifest entries that resolve | **0 of 52** | **52 of 52** |
| sha256 mismatches | — | **0** (50,841 rows) |

`verify-backup.mjs` then returned `PASS — snapshot is complete and internally consistent` over
62 files and 51,718 lines (0 malformed, 0 duplicate PKs, 0 row-count mismatches), and a full
`--all` **dry run** built a complete restore plan for every table. The backup set is byte-perfect.

**Root cause, one writer line-pair.** `dump-supabase.mjs` records each entry's path with
`path.relative(outDir, file)` (lines 159 and 204), which returns the **host's** separator — on
Windows, `data\<table>.ndjson`. Both readers resolve with `path.join(dir, rec.file)`
(`restore-supabase.mjs:68`, `verify-backup.mjs:28`), and on POSIX that string is a single
filename containing a backslash. It went unseen because the only machine that takes dumps is the
only machine on which both separators resolve.

**The expensive part is the message, not the failure.** Mid-outage, "your backup was altered"
sends the person restoring to look for a fresher set or to distrust the one they have, when the
set is intact and the fix is one separator.

- **The tooling fix.** It belongs in `roadmapventure/deepbench-backups-offsite` — a different
  repo, whose default branch is `main`, and which *is the recovery net*. An unattended cycle does

  `C:/Projects/deepbench-backups`; patching one and not the other leaves them divergent. The
  exact two edits are written into §9 so the fix is a transcription, not a re-derivation.

  actually score charter exit criterion 5. It needs a clean Supabase project. Measured, not
  assumed: org `roadmapventure` (`jtcbwfwjuvelhsvhlzzt`) is on the **free** plan; a new project
  is **$0/month**; a branch is **$0.01344/hour** and needs a paid plan; exactly one project

  copy of platform data, and leave behind something the runner's own tools cannot delete

Both are on one `gated_before_build` card. `SES-191` stays `partial`: the drill is genuinely
half-run, and recording it `delivered` would score an exit criterion this cycle did not meet.
