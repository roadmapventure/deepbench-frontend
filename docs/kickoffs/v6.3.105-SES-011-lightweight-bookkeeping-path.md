## 2. CONTEXT

Found 2026-07-21, same session as `SES-010`. Two related frictions bundled under one row:

**Friction 1 — the 8-step worktree ceremony is full price even for a single-line, zero-conflict-risk doc edit.** A session that only needs to log one backlog row or update its own status still runs the full `worktree add` → edit → commit → fetch → rebase → push → `worktree remove` → `branch -D` sequence, including a `.env.local` copy that's irrelevant when no dev server or Node test is involved. The isolation itself is cheap and still worth keeping (a session should never write straight to the shared checkout) — the actual waste is in required steps that only matter for real feature work: the `.env.local` copy, and the *immediate* manual cleanup (steps 7/8) for a worktree that never diverges from `dev` after its one push.

**Friction 2 — `CLAUDE-STATE.md`'s "In flight now" section is a single shared block every concurrent session edits directly**, and that causes real merge conflicts purely from bookkeeping (3 hit in one afternoon, none from actual feature-work collisions) — confirmed distinct from Friction 1: even sessions doing the full ceremony correctly still collide here, because the ceremony isolates each session's *working directory*, not the *shared text block* every session's bullet lives in. `CLAUDE.md` rule 8 already documents a resolution pattern ("keep both sides' bullets, treat as adjacency not a real conflict") — that's a mitigation applied after the fact, not a fix that prevents the conflict from occurring.

**The two frictions share one fix.** Once each session's status lives in its own file (`.claude/inflight/<session-name>.md` — pure per-file writes, structurally can't collide with another session's file), that same "single new file, zero deletions" edit shape becomes exactly the class of edit the lightweight path should cover. Building them together avoids defining "lightweight edit" twice.

**Scope decision (Tier 2, flagged not asked — John delegated this call directly, 2026-07-21 conversation):** this session only decomposes **"In flight now"** into per-session files. `CLAUDE-STATE.md`'s **"Last 3 sessions"** section is edited far less often (once per session, at close-out, sequentially with whatever else is closing at that moment) and hasn't been confirmed as a real contention point the way "In flight now" has — leaving it as a shared block for now, revisit only if it turns out to also collide in practice.

**Design, concretely:**
- **Per-session inflight files:** `.claude/inflight/<session-name>.md`, one line, same content as today's bullet. Written on session start (`CLAUDE.md` rule 6c, unchanged timing), deleted on close-out (`CLAUDE.md` rule 8, same trigger, now a file delete instead of a text removal). `CLAUDE-STATE.md`'s "In flight now" header becomes a two-line pointer instead of the live list.
- **Lightweight Bookkeeping Path** (new `CLAUDE.md` subsection): qualifies when an edit is a pure append — zero deleted/modified lines — confined to either (a) a brand-new `.claude/inflight/<session-name>.md` file, or (b) one new row appended to the end of a backlog table (`FEATURES.md`/`FEATURES-NEXT.md`/`FEATURES-LATER.md`). When it qualifies: reuse the session's existing worktree if one is already open (most cases — a session logging its own status already has one); if none exists, skip the `.env.local` copy (irrelevant, no dev server/Node test involved) and defer worktree removal — a worktree with zero commits ahead of `dev` after its push is exactly what `check-session-docs.js`'s existing check 5/5b already knows how to find and flag for cleanup, no need for the session itself to run steps 7/8 in the moment. Verify with `git diff --stat` before pushing: any deletion means this wasn't actually a qualifying edit — fall back to the full ceremony instead of pushing.
- **`scripts/check-session-docs.js`** stops parsing "In flight now" bullets out of `CLAUDE-STATE.md` text and instead reads `.claude/inflight/*.md` directly (checks 1b, 5, 5c, 5d all retarget to this). "Last 3 sessions" checks (1, 2) are untouched — that section isn't moving.

**Migration of the ~7 currently-listed "In flight now" bullets into their own files is NOT a coding-session task** — it's a bookkeeping-only edit to `CLAUDE-STATE.md` plus new `.claude/inflight/*.md` files, done directly by the design session (`ses-11`) at close-out, after the mechanism above is built and merged. Logged here so it isn't forgotten, not scoped as Task 5.

### Task 3 — `scripts/check-session-docs.js`: read `.claude/inflight/*.md` instead of parsing `CLAUDE-STATE.md` text

Add a directory-listing counterpart to the existing `freshDevText()` helper (same staleness rationale — the freshest cross-session view must come from `origin/dev`, not this session's local worktree copy, which may be hours stale relative to a session that closed out minutes ago):

```js
// Directory counterpart to freshDevText() -- same staleness rationale: another
// session's inflight file may have been added/removed on origin/dev more
// recently than this worktree's own checkout. Lists blob paths via ls-tree
// (works even though .claude/inflight/ may not exist locally in every worktree
// yet), then fetches each file's content the same way freshDevText() already does.
function freshDevDirEntries(relDirPath) {
  let names;
  try {
    const out = execFileSync("git", ["-C", SHARED_CHECKOUT, "ls-tree", "--name-only", "origin/dev", "--", relDirPath], { encoding: "utf8" });
    names = out.split("\n").map(l => l.trim()).filter(Boolean).map(p => path.basename(p));
  } catch {
    return []; // directory doesn't exist yet on origin/dev, or git unavailable
  }
  return names.map(name => ({
    name: name.replace(/\.md$/, ""),
    text: freshDevText(`${relDirPath}/${name}`, null),
  })).filter(e => e.text !== null);
}
```
