## 2. CONTEXT

John reviewed `MI-47`'s shipped one-line layout live (screenshot, annotated) and asked for three refinements — a follow-on polish pass on the same component, not a revert of `MI-47`'s underlying mechanism (the `turnStartedAt`/per-agent-clock/carry-forward-expectation logic all stays exactly as `MI-47` built it; only the rendering and two small copy details change):

**1. Two-line layout instead of one.** Today's single line reads `◆ Marcus is thinking… 7s (7s this Agent) - question > 30s`. New layout, confirmed with John against a concrete mock:
```
elapsed 7s | expect > 30s
◆ Marcus is thinking… 7s
```
Line 1 = total elapsed + estimate, own line, no diamond, format `elapsed {total} | {expectation}` (only the `| {expectation}` half when an estimate exists — falls back to just `elapsed {total}` when `expectation` is null, e.g. the memory-consolidation/data-patch flows that never carry one). Line 2 = the diamond + activity message + per-agent time, format `{message} {perAgentTime}` — drops the `(...this Agent)` parenthetical entirely, just the bare number after the message (John's mock showed no label on this one, unlike line 1's explicit `elapsed`/`expect` labels).

**2. "question" reverts to "expect".** `MI-47` renamed the label from "expect" to "question" because it sat on the same line as, and needed to read distinctly from, the per-agent timer. Now that line 1 sits directly under the user's own question bubble, "expect" is unambiguous again — John's exact words: "we are moving question back to expect — since it will be obvious it belongs to the question now." Reverts `formatExpectation()`'s output and the one hardcoded `"question < 2m"` floor string.

**3. First name only, chat status line only.** `describeDelegationEvent()`'s live handoff messages currently use each agent's full `name` field (e.g. "Marcus Webb is asking Michelle Manning who should help…") — John: "saves room." **Scope confirmed with John: chat status line only** — the pre-existing scripted messages (`"Marcus is thinking…"`, `"Owen is reviewing…"`, etc.) already use first names only, no change needed there; only `describeDelegationEvent()`'s 4 template strings need truncating. The Agent Routing drawer's row headers (avatar + name, e.g. "Michelle Manning") are explicitly **out of scope** — John confirmed those keep full names. Derived at the display layer (`fullName.split(' ')[0]`), not a change to `agents.js`'s `name` field — every other consumer of that field (roster page, agent bios, etc.) is unaffected.

### Task 2 — `MarketIntelligenceScreen.jsx`: first name only in `describeDelegationEvent()`

```js
function describeDelegationEvent(evt, agents) {
  const agentById = (id) => agents.find(a => a.id === id);
  // FEATURE: MI-49 -- first name only (saves room on the chat status line); the Agent Routing
  // drawer's own row headers are explicitly out of scope, still show full names via agentById(...).name.
  const firstName = (id) => (agentById(id)?.name || id).split(" ")[0];
  const fromName = firstName(evt.fromAgentId);
  const toName = firstName(evt.toAgentId);
  if (evt.type === 'delegation_return') {
    return `${fromName} is back — wrapping up…`;
  }
  switch (evt.viaTool) {
    case 'request_help':
      return `${fromName} is asking ${toName} who should help…`;
    case 'critique':
      return `${toName} is reviewing ${fromName}'s proposal…`;
    case 'delegate_to_agent':
    default:
      return `${fromName} is routing this to ${toName}…`;
  }
}
```
Unknown agent IDs (fallback `evt.fromAgentId`/`evt.toAgentId` raw string, e.g. `"ghost-agent"`) still `.split(" ")[0]` safely — a raw id with no space returns itself unchanged, no crash.
