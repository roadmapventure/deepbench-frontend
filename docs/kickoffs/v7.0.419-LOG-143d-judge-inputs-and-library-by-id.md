## 2. CONTEXT

Measured by part (a)'s agent before it wrote a line: `lookupRecordsByIds()` selects `id,data_type` — an existence check, by design (LOO-22). `queryLibrary()` returns content only through a similarity search scoped to one data room. So the judge cannot check *"is each claim traceable to the chunks the run retrieved"* and scores that dimension `unknown`. **Decided:** one new read primitive, `readContentByIds`, in `lib/search-harness.js`, dispatched by the generic `store` field; a thin wrapper in `lib/librarian.js`; `library-lookup.js` gains an `include_content` flag that returns `{ id, exists, data_type, content, citeable, title }` when set. The read runs under Eleanor Voss — The Librarian's capability exactly as the existence check does today; the judge asks for it through the same handler.

**Second gap, measured by part (b) (7b545d44):** the browser cannot supply `assembled_skill_slugs`, `retrieved_chunk_ids` or `self_reported_claims` — all three are written server-side onto `ai_activity_log` rows and never returned to the client — so a card judged from the client's task_context reads `unknown` on `skill_use` and `groundedness` and only partly on `delegation_fit`. **Decided:** the judge's inputs come from the trace's own log rows, server-side. The write handler's sibling, a deterministic **`report-card-trace`** step (`api/_lib/handlers/report-card-trace.js`, registered with one line in the same `HANDLERS` map part (a) used), reads the `ai_activity_log` rows for `task_context.trace_id` under the service role and returns `{ hops:[{agent_id, capability_slug, intent_slug, assembled_skill_slugs}], retrieved_chunk_ids, self_reported_claims }`; the CHI screen calls it first (a second `callCapability()` on a deterministic intent `report-card-trace-intent` held by Owen, `traits.handler = 'report-card-trace'`) and passes its output into the judge call. If a deterministic intent cannot run without a model turn in `request-receivable.js`, STOP and report the exact reason — that is a harness question the parent rules on. **Scope consequence:** this part is now two halves — (d1) the trace-facts step + client wiring, (d2) the Librarian by-id content read — each at most 4 files (handler + registry line + screen + test; harness/librarian/lookup + test); build (d1) first, then (d2) in the same session, two commits, two verifier runs, one report.
