## CONTEXT

Found live 2026-07-16 (John's screenshot): `EvidenceColumn`'s (Column 2, "Evidence & Interaction") action buttons don't line up with `InteractColumn`'s (Column 1, "Chat") "Send" button, even though both columns stretch to equal height in the desktop grid (`gridTemplateColumns` row, `flex:1/minHeight:0`, default `alignItems:stretch`).

Root cause: `InteractColumn`'s card splits a scrolling message list (`flex:1,overflowY:"auto"`) from a **fixed footer row** outside the scroll (`MarketIntelligenceScreen.jsx:2203`, holds the input + navy "Send" button) — so Send always lands at a fixed Y position. `EvidenceColumn`'s card (`:1482-1483`) never got that treatment: it's one continuous `overflowY:"auto"` region, so whatever CTA renders just falls wherever the content stack ends.

The same shape (a decision CTA buried in scroll flow instead of pinned) repeats 3 times inside `EvidenceColumn`:
1. `QaEvidenceCard`'s "Good, thanks" / "Have Priya…" choice (`:1390-1400`) — what John screenshotted
2. The hypothesis-result "Info Only" / "Store as Forecast" buttons (`:1608-1617`)
3. `ConfirmationCard`'s Accept/Reject/Edit (rendered inline at `:1650-1655`, component itself defined in `SharedUI.jsx`)

**John's explicit call (design walkthrough, 2026-07-16): fix the pattern everywhere, not just the QA card.** Mock (before/after wireframe) approved before scoping. This is a pure layout relocation — none of the three CTAs change appearance. `QaEvidenceCard`'s brass gradient card keeps its exact `STYLE-GUIDE.md` §35 styling; `ConfirmationCard` keeps its exact current styling and is not touched in `SharedUI.jsx` at all — only where it's rendered moves.

Logged as `CHI-13` in `docs/FEATURES.md`.
