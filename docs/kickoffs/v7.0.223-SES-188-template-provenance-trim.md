## The three blocks that are NOT provenance and must survive

Getting this wrong is how the trim becomes an outage rather than a fix:

- **The title guard** (offset 42). `<title>` sits at byte 0 and the Artifact publisher scans only
  the **first 8192 bytes** for it. This block explains the ratchet — the tag once sat at byte 24,770,
  present and never seen, and the published artifact was named after the build file. Guarded by
  `tests/regression/SES-138-briefing-title-window.js`. **New comments go BELOW it, never above.**
- **The newest stamp** (`v7.0.201`), per the `SES-164` pattern.
- **The seed sentinel** (immediately above the `briefing-state` line). Deliberately *not* a valid
  empty state; replacing it with a plausible `{"items":{},…}` publishes a page with John's ask
  threads and meter readings missing and nothing saying so.

## The safety step that makes a trim legitimate

`SES-164` step 2: before moving anything, check each retiring comment for an editor warning that
exists **nowhere else**, and relocate that kind into the body next to what it protects — never
delete it. On `runner-cycle.md`, nine of ten spot-checked warnings were already restated in the
body and the tenth appeared **zero** times outside its stamp. That step is run here by a Sonnet 5
subagent sweep over all 17 comments, and its findings are recorded in this session's `SESSIONS.md`
entry rather than asserted as "checked".

## QA plan — discriminating

1. **Byte-identity proof.** `sha256` over the file from the end of the last retiring comment to EOF,
   before and after: baseline **129,202 bytes, `2bd2af4079f8432b7be81d6cba7568d58e27bc987ece279c35ffcd2f2343c69e`**.
   Must be unchanged — a restructure that cannot show this is not content-preserving, whatever the
   diff looks like by eye.
2. **The title window.** `node tests/regression/SES-138-briefing-title-window.js` — the check that
   fails if the title tag leaves the first 8192 bytes. Trimming moves it *toward* byte 0, so this
   should pass more comfortably than before; running it is what turns "should" into "does".
3. **The builder still builds.** `node scripts/build-briefing.mjs` against the trimmed template must
   exit 0 and hit **every anchor** — the builder dies with `ANCHOR MISSING` if the template changed
   under it, which is exactly the failure a careless cut would cause. **This is the discriminating
   one:** a trim that removed a byte of real markup would fail here, and a trim that removed only
   comments cannot.
4. **The measurement the ticket is about.** Rebuilt page size before vs. after the trim, and the new
   offset of `briefing-state`. Report the number, and state the honest bound: this moves the ceiling,
   it does not stop the growth.
5. Full regression suite + `npm run build`.
