## The design choice the ticket delegated, and the two grounds it was made on

The ticket says *"the build cycle owns the design of where this lives (harvest step vs a trigger vs
both)"*. It shipped as a **trigger**, `public.runner_items_accept_clears_flag()` on `runner_items`
(migration `ses219_accept_clears_design_flag`).

1. This runbook records **eight times over** (`SES-86` phase 3, `v7.0.146`, `SES-101`, `SES-111`,
   `SES-127`, `SES-128`, `SES-129`, `SES-143`) that a rule each cycle must remember is a rule that
   gets silently forgotten — `record_skip()`'s own precedent.
2. The requirement names **two writers**: *"a decision harvest (page tap **or** attended-session
   record)"*. An attended session UPDATEs `runner_items` directly and never reads the runner's
   tail, so a rule written into step 2 binds one writer and misses the other — and the attended
   session is precisely the population that caused the bug. The trigger binds both.

### The three boundaries an editor must preserve

Written into the migration header so they travel with the code:

1. **`john-paced` and `designed` are not cleared.** Widening the predicate to *any non-null
   `design_status`* is the edit this forbids. `john-paced` is John's word about his own pace
   (`SES-166`) and the runbook forbids a cycle even *assigning* it — that is the ticket's stated
   scope guard. `designed` is **explicitly not a skip** and is step 6's fast path; clearing it
   discards a kickoff link `SES-112`'s CHECK guarantees exists.
2. **Nothing was backfilled, and that is a safety property.** `SES-182` — one of the four tickets a
   backfill would have touched — is under John's **explicit standing hold** (directive `58db64ae`
   item 6: *"do not flag it, do not pick it"*), so a backfill would hand the picker the one ticket
   he ordered left alone. Forward-only is `B34`/`SES-107`'s boundary applied here.
3. **It loops rather than issuing one `UPDATE`**, because `backlog_id` is not unique — `CHI-48`
   occupies two rows (`SES-97`) — so §19v's one-before-image-per-row holds.

**Named deviation, disclosed rather than buried (`SES-196` convention).** The predicate keys on the
card's `backlog_id` **alone**, not on *"the cycle that set `design_status`"* as the ticket words it.
The narrower reading was checked against the live cases and **misses them**: card `528ab5ba` was
filed by cycle `69064827` while `SES-191`'s flag had been set by an earlier cycle, so a
filing-cycle test would not have cleared the very flag John cleared by hand.
