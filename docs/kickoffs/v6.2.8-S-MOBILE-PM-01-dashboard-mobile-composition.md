## 2. CONTEXT

`DashboardScreen.jsx` (nav label "Project Management", route `/work`) has **zero mobile handling** — no `useIsMobile()` import, no responsive branch anywhere. At a real mobile viewport it breaks in three independent ways, confirmed by reading the shipped code directly (not guessed):
1. **Masthead** (line ~533): headline + subheader on the left, a `+ New Work Order` button on the right in an unconstrained `flex` row — the button crowds the headline with no wrap point.
2. **Stats strip** (line ~553): 5 stat blocks in a fixed-gap `flex` row with `overflow: hidden` — "Agents Working" (the 5th stat) simply clips off the right edge on a narrow viewport, no scroll affordance.
3. **2-column body** (line ~567): `flex: 0 0 50%` task list + a **fixed `width: 340`** chat sidebar, `position: sticky`. On a 390px viewport this doesn't reflow — the fixed 340px column is cut off entirely (195px + 340px + padding exceeds the viewport).

Design was iterated live against an interactive HTML mock recreating the real broken layout first, then the proposed fix, at [claude.ai/code/artifact/5a710f9b-02e6-4c96-83d0-957f8a1193ad](https://claude.ai/code/artifact/5a710f9b-02e6-4c96-83d0-957f8a1193ad) — John reviewed and approved live, all open questions resolved one at a time.

**Locked decisions (all confirmed by John, do not re-litigate):**
1. **Task list stays primary, full-width on mobile.** Unlike `MarketIntelligenceScreen.jsx` (§21, chat-primary — chat *is* that screen's point), this screen's core job is tracking work orders; chat is a secondary tool here. Deliberate departure from §21's chat-primary composition, same category of departure `S-MOBILE-NAV-01` already took from §21's dismiss convention (§24) — different content, different composition, same platform.
2. **Masthead stacks vertically:** headline → italic subheader → `+ New Work Order` button, full width, centered content, below the subheader. No side-by-side crowding.
3. **Stats strip becomes horizontal-scroll**, `overflow-x: auto`, no `overflow: hidden`. Same 5 numbers, same order, no data dropped, no wrap-to-2-rows.
4. **Active/Completed tabs replace the old stacked "Active Work Orders" + "Recently Completed" sections.** Two tabs, labelled exactly "Active" and "Completed", **Active selected by default**. Each tab shows its 3 most recent items with the same "Show more" / "Show fewer" drawer affordance the desktop `Active Work Orders` list already has — **switching tabs resets the drawer to collapsed (3 visible)**.
5. **Chat collapses to a pinned "Chat with Agent" pill** (brass border, small green online dot, sticky to the bottom of the scroll area) that opens a **full-screen overlay** containing the unmodified `ChatPanel` component. Dismiss via an explicit **"← Back to Work Orders" control only** — no tap-outside-to-close. This reuses `MarketIntelligenceScreen.jsx`'s exact Evidence/Activity overlay convention (§21: `position:"absolute", inset:0` inside a `position:"relative"` local wrapper, navy header with brass bottom-border, back-only dismiss) — **not** the nav drawer's tap-outside convention (§24), since this is content, not navigation.
6. **New Work Order button navigates exactly as it does today** — `navigate("/work/new")`, full-screen route change to `CreateWorkOrderScreen.jsx`, unchanged. **That screen is itself un-mobiled** (own locked 2-column layout, `STYLE-GUIDE.md` §15) — found while confirming this button's behavior, explicitly **not fixed this session**, logged as `WO-07` (locked decision #7 below).
7. **`WO-07` gap, logged not fixed:** `CreateWorkOrderScreen.jsx` (`/work/new`) has no mobile handling either. Tracked in `docs/FEATURES-NEXT.md` as ❌ Missing, same treatment `SH-20` got from `S-MOBILE-NAV-01` — a real, tracked gap, not a silent regression. John's explicit call: defer to a future session.
8. **Desktop is completely unchanged.** The mobile branch is additive — gated by `useIsMobile()`, same construction pattern as `AppShell.jsx`'s `AppHeader` and `MarketIntelligenceScreen.jsx`'s `MobileBody`. Not a single desktop pixel moves.

## 6. DESIGN RULES

- Mobile chat overlay: `position:"absolute", inset:0` inside a `position:"relative"` wrapper around the screen's own scrollable content — covers the body only, `AppShell`'s header stays visible above it. Exactly `MarketIntelligenceScreen.jsx`'s `MobileBody` Evidence/Activity pattern (§21), confirmed by reading that file directly, not guessed.
- Chat overlay dismiss: explicit "← Back to Work Orders" control only — no tap-outside-to-close (content overlay convention, §21 — not the nav drawer's tap-outside convention, §24).
- Stats strip: `overflow-x: auto`, `-webkit-overflow-scrolling: touch`, `flex-shrink: 0` on each stat block so none compress.
- Tabs: brass 2px bottom border on the active tab, `T.brassDeep` active text / `T.muted` inactive text — same visual language as other brass-accent active states on this platform (Style Guide's Left Sidebar Nav Pattern, §10, uses the same brass-for-active convention).
- Switching tabs always collapses back to 3 visible items (`setDrawerOpen(false)` on every tab click) — never carries an expanded state across tabs.
- Full detail and rationale: locked decisions #1-8 in Section 2 above.

## 8. NODE.JS TEST

```js
// test-S-MOBILE-PM-01.mjs
// Pure logic tests — no app imports. Mirrors DashboardScreen.jsx's mobile tab/list-selection
// logic (Category B) so the coding session can verify the arithmetic before wiring real JSX.

let pass = 0, fail = 0;
function assert(desc, cond) {
  if (cond) { console.log(`  ✓ ${desc}`); pass++; }
  else       { console.error(`  ✗ ${desc}`); fail++; }
}

// Mirrors the component's mobileList/mobileVisible/mobileHidden computation
function computeMobileView(mobileTab, activeTasks, completedTasks, drawerOpen) {
  const mobileList    = mobileTab === "active" ? activeTasks : completedTasks;
  const mobileVisible = drawerOpen ? mobileList : mobileList.slice(0, 3);
  const mobileHidden  = Math.max(0, mobileList.length - mobileVisible.length);
  return { mobileList, mobileVisible, mobileHidden };
}

const ACTIVE = [1,2,3,4,5,6].map(id => ({ id, title: `Active ${id}` }));
const COMPLETED = [1,2,3,4,5].map(id => ({ id, title: `Completed ${id}` }));

// T1: default Active tab, collapsed — 3 visible, 3 hidden
let v = computeMobileView("active", ACTIVE, COMPLETED, false);
assert("T1a: Active tab collapsed shows 3", v.mobileVisible.length === 3);
assert("T1b: Active tab collapsed hides 3", v.mobileHidden === 3);
assert("T1c: Active tab list is the active array, not completed", v.mobileList === ACTIVE);

// T2: Active tab, expanded — all 6 visible, 0 hidden
v = computeMobileView("active", ACTIVE, COMPLETED, true);
assert("T2a: Active tab expanded shows all 6", v.mobileVisible.length === 6);
assert("T2b: Active tab expanded hides 0", v.mobileHidden === 0);

// T3: Completed tab, collapsed — 3 visible, 2 hidden (only 5 fetched total)
v = computeMobileView("completed", ACTIVE, COMPLETED, false);
assert("T3a: Completed tab collapsed shows 3", v.mobileVisible.length === 3);
assert("T3b: Completed tab collapsed hides 2 (only 5 ever fetched)", v.mobileHidden === 2);
assert("T3c: Completed tab list is the completed array, not active", v.mobileList === COMPLETED);

// T4: empty lists — 0 visible, 0 hidden, no negative hidden count
v = computeMobileView("active", [], [], false);
assert("T4a: empty active list shows 0 visible", v.mobileVisible.length === 0);
assert("T4b: empty active list hides 0, never negative", v.mobileHidden === 0);

// T5: fewer than 3 items — visible count matches list length, hidden is 0
v = computeMobileView("completed", ACTIVE, COMPLETED.slice(0,2), false);
assert("T5a: 2-item completed list shows all 2, not padded to 3", v.mobileVisible.length === 2);
assert("T5b: 2-item completed list hides 0", v.mobileHidden === 0);

// T6: stats strip data shape — 5 entries, correct order (mirrors the render array)
const STATS_ROW = ["Active Work Orders","In Progress","Needs Review","Completed","Agents Working"];
assert("T6a: stats strip has exactly 5 entries", STATS_ROW.length === 5);
assert("T6b: stats strip order is unchanged from desktop", STATS_ROW[0] === "Active Work Orders" && STATS_ROW[4] === "Agents Working");

console.log(`\n${pass + fail} tests — ${pass} passed, ${fail} failed`);
if (fail > 0) process.exit(1);
else console.log("ALL TESTS PASS");
```
