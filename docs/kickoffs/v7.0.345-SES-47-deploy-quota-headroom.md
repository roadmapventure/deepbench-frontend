## 3. The one design decision, and why the obvious form is the wrong one

**THE WINDOW IS A TRAILING 24 HOURS, NOT A CALENDAR DAY — and that is the fail-closed choice rather
than a convenience.** Two calendar days are in play and neither is knowable from here:

- John's spending day is **America/Chicago** (`1d01ea85`, register B35) — but that governs *his
  budget*, and Vercel does not read it.
- Vercel's own quota reset boundary is **not verifiable from this session**. It is not in the API
  response, `runner_secrets` holds no docs, and inventing it is exactly the *"report a number that
  doesn't trace to a row or log"* the standing prohibitions forbid.

A trailing 24-hour count is **≥ any fixed-window count over the same traffic**, by construction. So
it can only alert *earlier* than the true boundary, never later — the same direction as
`check-deploy-serving.js`'s *"unknown is not red"* and the watermark's *"unknown is not innocent"*.
The script says which window it used in its own output, so the number always traces to a stated
window rather than to an assumed reset. **The edit this forbids: "correcting" the window to a
America/Chicago or UTC calendar day.** That is not a tightening, it is a guess about somebody else's
billing clock, and it makes the alarm fire *late* on exactly the burst days it exists to catch.

**THE COUNT IS ACCOUNT-WIDE, NOT PER-PROJECT, and this was measured rather than assumed.** The cap
`SES-33` hit is an account limit. `check-deploy-current.js` queries `?app=deepbench-frontend`, and
reusing that filter would under-count the moment a second project exists. Probed live this cycle at
`16:5xZ`: the unfiltered account query and the `app=`-filtered one both returned **18** over the
trailing 24h, `{"deepbench-frontend":18}` — i.e. they agree **today only because this account
deploys one project**, which is precisely why the agreement must not be baked in. The script drops
the filter and reports the per-project split, so the day a second project appears the number is
still right and the split says where it went.

## 4. What shipped

- **`scripts/check-deploy-quota.js`** (new). Counts account-wide deployments in a trailing 24h
  window through `GET /v6/deployments`, **paginating** (`pagination.next`) because one page caps at
  100 and the ceiling under test *is* 100 — a single-page read reports at most the cap and can never
  observe an overrun. Emits `used` / `remaining` / `pct` against `CAP = 100` and `ALERT_AT = 80`
  (John's number, a named constant, never a literal at the call site). Exit **0** clear, **1** at or
  over the alert threshold, **2** *could not run* — the project's standing three-verdict convention,
  where 2 is never a pass.
- **`tests/regression/SES-47-deploy-quota-headroom.js`** (new). Guards the pure logic against
  fixtures, with a discriminating control — see §5.
- **`docs/runbooks/runner-cycle.md`** — step 4a-ter wires it into the blocker sweep every cycle
  already runs, and states the push rule: **one push per crossing, not one per cycle**, claimed
  atomically the same way the `SES-103` stall tripwire claims its report, so eight cycles a day do
  not send John eight copies of the same alarm.

## 5. QA — what makes it discriminating

The bar is step 7's: *state the test, then ask whether it would still pass if the change did
nothing.*

1. **`verdictFor()` against fixtures at 0, 79, 80, 81, 100 and 137 deployments.** 79 → exit 0,
   80 → exit 1 (**at**, not over — "crosses 80" is inclusive and a `> 80` build lets the 80th
   through), 137 → exit 1 with `remaining` **floored at 0** rather than rendered negative.
2. **THE NEGATIVE CONTROL, which is a difference rather than a property both forms share.** The
   retired single-page form is run against the **same** 137-deployment fixture and asserted to
   report 100 where the shipped form reports 137 — so a rebuild that drops pagination fails on a
   number, not on a promise.
3. **The window is asserted to be trailing-24h**, not a calendar boundary: a fixture whose
   deployments straddle local midnight counts all of them.
4. **Live seam proof, labeled as one:** the real script against the real Vercel API with the real
   token returned HTTP 200 and a count that agrees with the independent probe in §3.
