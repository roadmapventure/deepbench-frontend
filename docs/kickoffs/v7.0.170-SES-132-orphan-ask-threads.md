## 6. DESIGN RULES

- **§9.1 is a SUB-BLOCK under §9, never a fifteenth section.** John approved the fourteen-section
  order and the standing prohibitions forbid touching a LOCKED section. `§4.1` (daily output) and
  `§7.1` (directive follow-through) are the precedent: a numbered sub-block extends the order
  without renumbering it.
- **The orphan set is computed AFTER the whole page is built.** §12's vision claims render *after*
  §9.1's position, so an in-place computation classifies every vision thread as orphaned and
  prints it twice. Hence a marker plus one substitution at the end of `render()`.
- **The substitution passes a function, not a string.** `$&`, `$1` and friends are special in a
  `String.replace` replacement and the text being inserted is John's own prose.
- **`threadedIds` resets per render.** Saving a reading calls `render()` a second time; a set that
  lived across passes would orphan nothing on the second one.
- **No `data-awaits` on §9.1 rows.** A kept thread is information, not a decision owed —
  `SES-127` made the same call for §10, and inflating §1's counter is the
  masthead-disagrees-with-the-page failure `countWaiting()` exists to prevent.
- **§9.1 is where a thread survives a decision, not a second place to hold a live conversation.**
  A cycle still answers an open ask on its live card when there is one.
