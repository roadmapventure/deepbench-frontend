## CONTEXT

**What's broken (live, John's own screenshot, real dev preview):** asking Marcus a Channel Intelligence question (e.g. "Why is our EMEA retail partner's co-op budget utilization so low this quarter?") produces a real 6-hop chain in Column 3's Agent Routing drawer (Marcus → Owen → Michelle → Owen → Michelle → Alex, drawer badge correctly reads "6 hops"). But the chat bubble's own cross-reference badge reads "Hops 2–5" and the wrap-up line reads "Full Agent Routing & Answer in 5 hops total" — both numbers wrong, and disagreeing with the real running count sitting one column over.

**John's correction on the fix approach (this session's actual scope):** Column 3's own hop counter (`groupEventsIntoHops()`/`currentHopCount()`) is correct and complete — treat it as gold, do not modify or second-guess it. The bug is entirely in how the chat label tries to *independently* compute its own hop range mid-flight, using speculative "current count + 1" arithmetic scattered across two inner functions and three ack-bubble call sites. The fix is simpler than that: **the label should just read the real, current total directly from the gold counter** at the two moments that matter — once right before a turn starts (to know where its range begins), and once after every one of that turn's own events (including any logged by the outer caller after the inner function returns) has posted (to know the real end). No speculative math, no threading a `getHopCount` callback several layers deep into functions that shouldn't need to know about hop numbering at all.

**Why the old approach broke (for the record — this is what's being removed, not patched):**
1. `hopEnd` was captured via `getHopCount()` reading `pipelineEventsRef.current` — a ref meant to mirror `pipelineEvents` React state synchronously. The mirror assignment happened *inside* the callback passed to `setPipelineEvents`, which assumes React invokes that callback the instant `setPipelineEvents` is called — not guaranteed (the same defect shape as `STANDARDS.md` Section 8's `BUG-3`). A `getHopCount()` call with no intervening `await` right after the turn's last `onEvent` could read a ref one event behind.
2. `hopStart`'s "current count + 1" assumed the very next logged event always opens a new hop. It doesn't — `groupEventsIntoHops()` merges consecutive same-agent events into one hop card. `runQaWithQualityGate()`'s own first event (`qa_answer`, Marcus) merges into the hop the caller's preceding `intent_routing` event (also Marcus) already opened, so "current + 1" labeled a hop that didn't exist yet.
3. For the hypothesis-test path specifically, the inner function's own `hopEnd` was captured *before* the outer caller's own trailing `logEvent(buildHopEvent("hypothesis_test", "priya", ...))` call (~L2784) — meaning even a perfectly-synchronous ref would have undercounted that path by one real hop, structurally, every time.

**What to expect after the fix:** the chat's hop badge and wrap-up summary always match Column 3's real running count, for the Q&A path, the hypothesis-test path, and every ack bubble — because they're now reading the same gold count Column 3 itself renders from, not a separately-tracked approximation.

function groupEventsIntoHops(ordered) {
  const hops = [];
  for (const evt of ordered) {
    const last = hops[hops.length - 1];
    if (evt.type === "question_boundary") {
      hops.push({ agentId: evt.agentId, events: [evt], isBoundary: true });
      continue;
    }
    if (last && !last.isBoundary && last.agentId === evt.agentId) {
      last.events.push(evt);
    } else {
      hops.push({ agentId: evt.agentId, events: [evt] });
    }
  }
  const total = hops.filter(h => !h.isBoundary).length;
  let seen = 0;
  return hops.map(h => {
    if (h.isBoundary) return h;
    seen += 1;
    return { ...h, events: [...h.events].reverse(), hopNumber: total - (seen - 1) };
  });
}
function currentHopCount(ordered) {
  return groupEventsIntoHops(ordered).filter(h => !h.isBoundary).length;
}

function makeHarness() {
  const ref = { current: [] };
  const pending = new Map();
  function logEvent(evt, { replaces } = {}) {
    const prev = ref.current;
    let next;
    if (replaces) {
      const id = prev.length;
      pending.set(replaces.awaitingAgentId, { id, key: replaces.key });
      next = [...prev, { ...evt, id }];

      const p = pending.get(evt.agentId);

        pending.delete(evt.agentId);
        next = prev.map(e => (e.id === p.id ? { ...evt, id: p.id } : e));
      } else {
        next = [...prev, { ...evt, id: prev.length }];
      }
    }
    ref.current = next;
    return next;
  }
  return { ref, logEvent };
}
