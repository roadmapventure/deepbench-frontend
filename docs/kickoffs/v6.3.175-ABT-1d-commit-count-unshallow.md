## 2. CONTEXT

`ABT-1c` moved the platform-stats recount onto the Vercel build, and it works: the live build log for commit `07fd3db` shows `prebuild` running the script and writing the row. Three of the four repo-fact tiles now refresh on every push to `dev`.

The fourth — "Commits to dev" — does not, and correctly so. **Vercel clones with `git clone --depth=10`** ([documented behavior](https://vercel.com/docs/git)), so `git rev-list --count HEAD` returns ~10 in CI. `ABT-1c`'s guard catches that and preserves the stored value rather than corrupting the tile (live log line: `platform-stats: commit count not trusted (shallow clone) — preserving stored value`). That guard is correct and must stay.

The consequence is that the tile freezes at whatever a full-depth checkout last wrote (1530 today) and slowly goes stale — the exact drift `SH-13`/`MOB-001` documented on the old About panel, which this whole `ABT-1` effort exists to end.

**This session's fix:** before counting, try to deepen the repository (`git fetch --unshallow`). If it succeeds, the count is real and gets written; if it fails for any reason — no credentials in the build container, no network, already complete — nothing changes and `ABT-1c`'s guard still preserves the stored value. **The attempt cannot make anything worse**, which is what makes it worth trying rather than guessing at an undocumented Vercel setting. `VERCEL_DEEP_CLONE` was investigated and rejected: it does not appear in Vercel's documentation, and this session will not depend on an unverified variable.

Whether it works in the Vercel container is genuinely unknown and will be settled by reading the next build's log — an outcome this kickoff deliberately does not assume.

## 5. TASKS (2)

### Task 1 — `scripts/platform-stats.js`: attempt to deepen before counting

Immediately before the existing shallow check, if `git rev-parse --is-shallow-repository` reports `true`, attempt **once**:

```
git fetch --unshallow --quiet
```

- Wrap in try/catch — a throw is expected and fine, never fatal in either strict or soft mode.
- Give it a bounded `timeout` (e.g. `timeout: 20000` on `execSync`) so a hanging fetch can never stall a deploy.
- Log exactly one line either way: `platform-stats: deepened shallow clone for an accurate commit count` or `platform-stats: could not deepen shallow clone (<short reason>) — commit count will be preserved`.
- Then re-run the existing shallow check and counting logic **unchanged**. If the repo is still shallow, or the count still comes out lower than the stored value, `ABT-1c`'s existing guard omits `commits_dev` exactly as it does today.

Do not restructure or "simplify" the existing guard — it is proven and is the safety net for this change.

## 8. NODE.JS TEST (save as `test-abt-1d.mjs`, run `node --env-file=.env.local test-abt-1d.mjs`, delete before committing)

```js
// test-abt-1d.mjs — S-ABT-1d verification
import { execSync } from "node:child_process";
import { readFileSync, mkdtempSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";
import assert from "node:assert";
let pass = 0;
const ok = (c, m) => { assert.ok(c, m); console.log("PASS:", m); pass++; };

const src = readFileSync("scripts/platform-stats.js", "utf8");
ok(/--unshallow/.test(src), "unshallow attempt present");
ok(/is-shallow-repository/.test(src), "ABT-1c shallow guard still present");
ok(/--soft/.test(src), "ABT-1c soft mode still present");
ok(/VERCEL_GIT_COMMIT_REF/.test(src), "ABT-1c preview guard still present");
ok(!/VERCEL_DEEP_CLONE/.test(src), "no dependency on the unverified VERCEL_DEEP_CLONE");
ok(/timeout/.test(src), "fetch attempt is time-bounded");

const url = process.env.SUPABASE_URL || process.env.VITE_SUPABASE_URL;
const key = process.env.SUPABASE_ANON_KEY || process.env.VITE_SUPABASE_ANON_KEY;
const get = async () => (await (await fetch(`${url}/rest/v1/platform_stats?id=eq.1&select=*`,
  { headers: { apikey: key, Authorization: `Bearer ${key}` } })).json())[0];
const before = await get();

// Real shallow clone, no reachable origin credentials: unshallow must fail HARMLESSLY,
// the guard must still preserve, and the process must still exit 0 in soft mode.
const dir = mkdtempSync(join(tmpdir(), "abt1d-"));
const clone = join(dir, "repo");
execSync(`git clone --depth 1 file://${process.cwd().replace(/\\/g, "/")} "${clone}"`, { stdio: "pipe" });
const out = execSync(`node "${join(clone, "scripts/platform-stats.js")}" --soft`,
  { cwd: clone, encoding: "utf8", env: { ...process.env, SUPABASE_URL: url, SUPABASE_ANON_KEY: key } });
console.log(out);
ok(/deepened|could not deepen/.test(out), "logs exactly one deepen outcome");
const afterShallow = await get();
ok(afterShallow.commits_dev >= before.commits_dev, "shallow run never lowered commits_dev");
ok(afterShallow.dev_toolchain_services === before.dev_toolchain_services, "toolchain preserved");

// Full-depth run still writes a real count.
execSync("node scripts/platform-stats.js", { encoding: "utf8" });
const after = await get();
ok(after.commits_dev >= before.commits_dev, `full-depth count intact (${after.commits_dev})`);

console.log(`ALL TESTS PASS (${pass})`);
```

Then `npm run build` must still succeed with the prebuild line first.
