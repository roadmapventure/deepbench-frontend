## CONTEXT

**Root-caused via 40 real `ci-routing-intent` deliverable rows queried directly from Supabase, not guesswork — and the problem is wider than `AA-112`'s original description (EMEA qa/forecast flip only).** The exact same Japan seed-question text ("Japan is Apple's fastest-growing GEO in 2025 — what is driving that?") classified as `qa` (most runs), `theory` (4 of 6 runs where the literal hypothesis text was captured), and once as `forecast` — a real 3-way instability, not a two-way edge case.

Cause: `ci-routing-intent`'s Supabase `skill_profiles.method` field is **`"Extract a candidate hypothesis if the user wrote a claim unprompted in the message — pre-fill, never auto-submit."`** — that's the entire instruction. It says how to extract a hypothesis; it says nothing about how to *distinguish* `qa` from `theory` from `forecast`. The design doc (§3) only gives one-line intent definitions ("Q/A: a genuine question", "Run a Theory: user wants to test a hunch") with no discriminating rule for a message that states a fact and asks why — which is exactly what all 3 MI seed questions look like, and exactly the boundary the model can't reliably resolve today.

**Fix is a Supabase content change** (the `method` field), not a code/harness bug — there's no bug to patch, the model is reasoning correctly over genuinely insufficient instructions.
