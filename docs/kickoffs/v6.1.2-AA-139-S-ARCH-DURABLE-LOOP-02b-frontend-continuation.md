# CONTEXT

**The gap this closes:** `callCapability()` and `resolveConfirmation()` both POST to `/api/capabilities/execute` and treat the response as always-terminal — `if (result.status) return result; return result.content || {};`. As of `v6.1.1`, that response can now legitimately be `{status: 'in_progress', job_id}` when the harness checkpointed mid-chain. Every one of `callCapability()`'s 9 live call sites (routing, Q&A answer, quality gate, failure triage, display hand-off, hypothesis generation/test, memory consolidation, data analysis) and `resolveConfirmation()`'s 1 call site (HITL accept/reject/edit) would currently treat that shape as a malformed/empty result — the same class of silent failure the original incident exposed, just one layer further down the stack now that the harness itself survives.

**The fix is one shared helper, not nine call-site patches.** Both `callCapability()` and `resolveConfirmation()` already funnel through a single `fetch()` each — this session adds one `resolveInProgress()` function that both call on their raw response before their existing unwrap logic runs. Every existing caller of either function keeps its exact current contract (always eventually resolves to a terminal result, or throws) with zero changes anywhere else in the file — the continuation is invisible to `runIntentPipeline()`, `runQaWithQualityGate()`, `onCommit()`, `onResolveConfirmation()`, etc.

**Deliberately no new UI this session** (per `feedback-no-ui-decisions` — visual changes need John's explicit sign-off, not a silent addition here). The existing `setAIStatus("Marcus is thinking…")` already covers the loading window for the whole `submit()` call; a checkpointed chain just makes that window somewhat longer while it continues in the background, same as any other slower-than-usual response. Progress-per-hop UI (e.g. showing "Marcus answered → Owen reviewing…" as steps complete) is a real, available future enhancement — flagged here, not built here.

## Task 1 — Add the shared `resolveInProgress()` helper

In `src/screens/MarketIntelligenceScreen.jsx`, add near `callCapability()` (before it, so both functions below can reference it):

```js
const MAX_CONTINUE_ITERATIONS = 10; // client-side safety cap -- generous headroom over a real
// chain's expected hop count (harness's own MAX_LOOP_DEPTH is 5), guards against an unbounded
// client loop if something's genuinely wrong server-side rather than duplicating that ceiling.

// FEATURE: AA-139 (S-ARCH-DURABLE-LOOP-02b) -- a chain that risked the shared 60s Vercel ceiling
// checkpoints server-side (S-ARCH-DURABLE-LOOP-02a) instead of dying silently, returning
// {status:'in_progress', job_id} instead of a terminal result. This continues it until a terminal
// status, so every existing caller keeps its current contract unchanged -- none of them ever need
// to know a checkpoint happened. Shared by callCapability() and resolveConfirmation() -- one
// implementation, not two copies of the same loop.
async function resolveInProgress(result) {
  let iterations = 0;
  while (result.status === "in_progress") {
    if (++iterations > MAX_CONTINUE_ITERATIONS) {
      throw new Error(`Chain did not complete after ${MAX_CONTINUE_ITERATIONS} continuations (job_id: ${result.job_id})`);
    }
    const res = await fetch("/api/capabilities/execute", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ action: "continue", job_id: result.job_id }),
    });
    if (!res.ok) throw new Error(`continue (job_id: ${result.job_id}) failed: ${res.status}`);
    result = await res.json();
  }
  return result;
}
```

# NODE.JS TEST

Per `STANDARDS.md` Section 4, Category L applies (this session modifies code that calls an `api/` endpoint and adds retry-shaped logic) — using the "Retry logic tests" template that section specifies. Per Section 4's "Pure Node.js only — no app imports" rule, `MarketIntelligenceScreen.jsx` can't be imported directly (it pulls in React/JSX-only syntax elsewhere in the file that plain Node can't parse) — this test reproduces `resolveInProgress()`'s exact body verbatim and exercises it against a mocked `fetch`. **If `resolveInProgress()`'s implementation changes, this copy must be updated to match** (noted inline).

```js
// test-durable-loop-frontend.mjs — run with: node test-durable-loop-frontend.mjs
import assert from 'node:assert';

const MAX_CONTINUE_ITERATIONS = 10;

// Verbatim copy of MarketIntelligenceScreen.jsx's resolveInProgress() — keep in sync, see kickoff Task 1.
async function resolveInProgress(result) {
  let iterations = 0;
  while (result.status === "in_progress") {
    if (++iterations > MAX_CONTINUE_ITERATIONS) {
      throw new Error(`Chain did not complete after ${MAX_CONTINUE_ITERATIONS} continuations (job_id: ${result.job_id})`);
    }
    const res = await fetch("/api/capabilities/execute", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ action: "continue", job_id: result.job_id }),
    });
    if (!res.ok) throw new Error(`continue (job_id: ${result.job_id}) failed: ${res.status}`);
    result = await res.json();
  }
  return result;
}

function mockFetch(responses) {
  let calls = [];
  global.fetch = async (url, options) => {
    calls.push({ url, body: JSON.parse(options.body) });
    const next = responses[calls.length - 1];
    return { ok: next.ok !== false, status: next.status || 200, json: async () => next.body };
  };
  return () => calls;
}

async function testAlreadyTerminalNoFetch() {
  const getCalls = mockFetch([]); // no continue call should ever fire
  const result = await resolveInProgress({ status: "final_delegation", headline: "done" });
  assert.strictEqual(result.status, "final_delegation");
  assert.strictEqual(getCalls().length, 0, "must not call continue when already terminal");
  console.log("[already-terminal] PASS — zero continue calls for a terminal first result");
}

async function testInProgressThenComplete() {
  const getCalls = mockFetch([
    { body: { status: "complete", result: { headline: "final" } } },
  ]);
  const result = await resolveInProgress({ status: "in_progress", job_id: "job-123" });
  assert.strictEqual(result.status, "complete");
  const calls = getCalls();
  assert.strictEqual(calls.length, 1, "must call continue exactly once");
  assert.deepStrictEqual(calls[0].body, { action: "continue", job_id: "job-123" }, "continue payload must be exactly {action, job_id}");
  console.log("[in-progress-then-complete] PASS — one continue call, correct payload, terminal result returned");
}

async function testMultipleContinuations() {
  const getCalls = mockFetch([
    { body: { status: "in_progress", job_id: "job-456" } },
    { body: { status: "in_progress", job_id: "job-456" } },
    { body: { status: "final_delegation", headline: "done after 3" } },
  ]);
  const result = await resolveInProgress({ status: "in_progress", job_id: "job-456" });
  assert.strictEqual(result.status, "final_delegation");
  assert.strictEqual(getCalls().length, 3, "must continue exactly as many times as needed");
  console.log("[multiple-continuations] PASS — chain resolved across 3 continue calls");
}

async function testPerpetualInProgressThrows() {
  const responses = Array.from({ length: MAX_CONTINUE_ITERATIONS + 2 }, () => ({ body: { status: "in_progress", job_id: "job-stuck" } }));
  mockFetch(responses);
  await assert.rejects(
    () => resolveInProgress({ status: "in_progress", job_id: "job-stuck" }),
    /did not complete after 10 continuations/,
    'must throw a clear error after MAX_CONTINUE_ITERATIONS, not loop forever'
  );
  console.log("[perpetual-in-progress] PASS — throws after", MAX_CONTINUE_ITERATIONS, "continuations instead of looping forever");
}

async function testContinueHttpFailureThrows() {
  mockFetch([{ ok: false, status: 500, body: {} }]);
  await assert.rejects(
    () => resolveInProgress({ status: "in_progress", job_id: "job-err" }),
    /continue \(job_id: job-err\) failed: 500/,
    'must surface a clear error on a failed continue call'
  );
  console.log("[continue-http-failure] PASS — throws with clear message on non-2xx continue response");
}

async function main() {
  await testAlreadyTerminalNoFetch();
  await testInProgressThenComplete();
  await testMultipleContinuations();
  await testPerpetualInProgressThrows();
  await testContinueHttpFailureThrows();
  console.log('ALL TESTS PASS');
}
main().catch(e => { console.error('FAIL:', e); process.exit(1); });
```
