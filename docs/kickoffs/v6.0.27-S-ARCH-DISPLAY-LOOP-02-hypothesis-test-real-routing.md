## CONTEXT

Today, `runHypothesisTest()` bundles Priya's stress-test analysis and Alex's formatting into one call via `format_skill_profile_slug: "intelligence-review-format"` / `display_agent_id: "alex"` — a static, harness-level override (the `AA-77` format-last pattern). Alex never actually runs a separate model call; he just gets credited on a response Priya generated herself under his borrowed schema. This is the exact `AR-4.3`/hardcoding violation `AA-115` already fixed for Q&A — Column 2 is now the only place on the Market Intelligence screen still doing it.

**Resolved with John, 2026-07-06:** genuine multi-candidate routing, extending `AA-115`'s real mechanism as-is (Alex is one option Michelle reasons over, not guaranteed) — not a documented fixed assignment. **Also resolved:** the AI - Hypothesis Test card gets the same "Formatted by [Agent] [Role]" byline + avatar Q&A's card already has, since routing is no longer guaranteed to be Alex.

**Two blockers found and resolved this design session, before scoping tasks:**

1. **`intelligence-review-format` is invisible as a candidate today.** Michelle's roster broker (`lib/project-manager.js`'s `fetchRoster()`) only surfaces skill profiles where `skill_type_slug = 'intent'` as selectable intents per agent. `intelligence-review-format` is currently `skill_type_slug = 'format'` — confirmed live via Supabase query this session. Reclassifying it to `'intent'` is required for Alex to be a real, pickable candidate at all (not just a fallback nobody could ever *not* pick). Verified this doesn't conflict with `SE-04`'s (still unbuilt) Format Skill Exclusivity audit — that rule is about *which agent* holds a Format Skill (display/editor only, never a content specialist), not the `skill_type_slug` value; Alex remains the sole owner either way.
2. **Priya's own `hyp-hypothesis-test-intent` has no schema today** (`traits: {can_request_help: true}` only — confirmed live) — it currently only produces structured output because the bundled override force-injects Alex's schema. Removing the override without giving Priya her own schema would mean her raw call falls back to free text, breaking `supports`/`complicates`/`consider` rendering entirely. **Mirroring the Q&A precedent exactly:** Marcus's own `ci-answer-intent` has a real, separate, simpler schema (`answer`/`citations`/`confidence_tier`/`needs_review`/`review_reason`) distinct from Alex's presentational `qa-answer-format` schema (`headline`/`body`/`key_data_points`). Priya needs the same split: her own genuine analytical schema (this session, Task 1b), separate from Alex's existing presentational schema (`intelligence-review-format`, unchanged — already has everything needed, including `visualization` from `S-ARCH-VIZ-01`).

**New intent needed**, mirroring `ci-answer-display-intent` exactly: `hyp-hypothesis-test-display-intent` — `schema: null`, `can_request_help: true`, no separate `objective`/`method` text needed (confirmed live: `ci-answer-display-intent` and `hyp-hypothesis-test-intent` both carry `objective: null, method: null` today and work correctly in production — the general "you can request help" framing already lives in the shared `hyp-identity`/`hyp-behavior`/`hyp-knowledge` profiles assembled alongside every `hypothesis-evaluation` intent call, so this new intent doesn't need to repeat it).

```js
async function runHypothesisTest({ hypothesis, intent, flaggedQuestion, flaggedAnswer, priorHypothesisTest, onEvent }) {
  const analysis = await callCapability({
    capability_slug: "hypothesis-evaluation", intent_slug: "hyp-hypothesis-test-intent", agent_id: "priya",
    task_context: {
      hypothesis, intent,
      flagged_question: flaggedQuestion || "", flagged_answer: flaggedAnswer || "",
      prior_hypothesis_test: priorHypothesisTest || null,
    },
  });

  const display = await callCapability({
    capability_slug: "hypothesis-evaluation", intent_slug: "hyp-hypothesis-test-display-intent", agent_id: "priya",
    task_context: { supports: analysis.supports, complicates: analysis.complicates, consider: analysis.consider, confidence: analysis.confidence },
  });
  if (display.selection) {
    onEvent({ type: "agent_selection", agentId: "priya", secondaryAgentId: display.selection.selected_by_agent_id, data: display.selection });
  }
  onEvent({ type: "display_format", agentId: display.selection?.selected_by_agent_id || "priya", secondaryAgentId: display.display_agent_id, data: display });

  return display; // final_delegation shape: {...intelligence-review-format's fields, display_agent_card, display_agent_id, selection}
}
```
