## CONTEXT

Live-measured 2026-07-07 (John's own MI screen test, direct `ai_activity_log` query): a single Forecast→"Use this hypothesis" interaction spent ~44s in delegation/hand-off overhead beyond Priya's real 27.5s analytical call. The two largest pieces of that overhead were both `hyp-hypothesis-test-display-intent` turns — Priya's own reasoning about whether/how to hand off to a Display agent:

- depth0: **8.0s**
- depth1 (after Michelle's PM-broker turn resolves candidates): **19.3s**

Checked directly against Supabase `skill_profiles`: `hyp-hypothesis-test-display-intent` has `max_tokens: 4000` and no brevity instruction in its `method` text. This is the *exact* bug pattern `AA-120` already found and fixed on a sibling intent, `ci-answer-display-intent` (which today correctly runs `max_tokens: 800` plus an explicit "keep reasoning to 1-2 sentences" instruction). Both intents do the identical job — decide whether to `request_help`/`delegate_to_agent` for display formatting, nothing more — so there is no reason for one to carry 5x the token ceiling of the other. `hyp-hypothesis-test-display-intent` was simply never touched when `AA-120` shipped that fix (it retrofitted `ci-answer-display-intent` specifically, not the pattern generally).

**Root cause of the long turns:** with no schema tool offered on this intent, `request-receivable.js`'s `buildCallBody()` sets `tool_choice: { type: 'auto', ... }` — the model is free to generate plain text before (or instead of) calling `request_help`/`delegate_to_agent`. A high `max_tokens` ceiling gives it room to do that; `AA-120`'s own fix (cut the ceiling + explicitly tell the model this is a routing decision, not an analysis) already proved this closes most of the gap on `ci-answer-display-intent`. This session applies the identical, already-proven fix to the sibling intent.

**This is a Supabase data change, not a code change** — no `api/` files are touched. Config-only, per the established pattern (`AA-120`, `AA-108`, `AA-118` all made comparable Skill Profile data adjustments as part of their sessions).

```js
// test-s-arch-loop-latency-03.mjs — AA-124 (partial) verification (pure Node)
let failures = 0;
function check(label, cond) {
  if (cond) { console.log(`PASS: ${label}`); }
  else { console.error(`FAIL: ${label}`); failures++; }
}

const SUPABASE_URL = process.env.SUPABASE_URL;
const SUPABASE_SERVICE_KEY = process.env.SUPABASE_SERVICE_KEY;
if (!SUPABASE_URL || !SUPABASE_SERVICE_KEY) {
  console.error('FAIL: SUPABASE_URL/SUPABASE_SERVICE_KEY not set -- cannot verify');
  process.exit(1);
}
const headers = { apikey: SUPABASE_SERVICE_KEY, Authorization: `Bearer ${SUPABASE_SERVICE_KEY}` };

// ---- Category M: cross-reference the Supabase row matches what this session changed ----
async function checkSkillProfileRow() {
  const res = await fetch(`${SUPABASE_URL}/rest/v1/skill_profiles?slug=eq.hyp-hypothesis-test-display-intent&select=max_tokens,method,schema:traits->schema,can_request_help:traits->can_request_help`, { headers });
  const [row] = await res.json();
  check('hyp-hypothesis-test-display-intent row found', !!row);
  check('max_tokens trimmed to 800', row?.max_tokens === 800);
  check('method now includes the brevity instruction', typeof row?.method === 'string' && row.method.includes('this is a routing decision, not an analysis'));
}

// ---- Category L: one live round trip, confirm the display-intent turns are now faster ----
async function checkLiveCall() {
  const DEV_URL = process.env.DEEPBENCH_DEV_URL;
  if (!DEV_URL) { console.warn('SKIP: live call -- DEEPBENCH_DEV_URL not set'); return; }
  const before = new Date().toISOString();
  const res = await fetch(`${DEV_URL}/api/capabilities/execute`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'x-vercel-protection-bypass': process.env.VERCEL_BYPASS || '' },
    body: JSON.stringify({
      capability_slug: 'hypothesis-evaluation', intent_slug: 'hyp-hypothesis-test-display-intent', agent_id: 'priya',
      task_context: { supports: 'Test supports text.', complicates: 'Test complicates text.', consider: 'Test consider text.', confidence: 'moderate' },
      tenant_id: 'global',
    }),
  }).catch(() => null);
  check('live call did not fail', !!res && res.ok);
  const logRes = await fetch(`${SUPABASE_URL}/rest/v1/ai_activity_log?ai_type=eq.agent-turn&feature=like.hypothesis-evaluation:hyp-hypothesis-test-display-intent*&created_at=gte.${before}&select=feature,latency_ms&order=created_at.asc`, { headers });
  const rows = await logRes.json();
  check('at least one hyp-hypothesis-test-display-intent agent-turn row logged', rows.length > 0);
  rows.forEach(r => console.log(`[info] ${r.feature}: ${r.latency_ms}ms`));
  if (rows.length > 0) {
    const maxLatency = Math.max(...rows.map(r => r.latency_ms));
    check('no single display-intent turn exceeds 10s post-fix (was 8.0s/19.3s pre-fix)', maxLatency < 10000);
  }
}

await checkSkillProfileRow();
await checkLiveCall();

if (failures > 0) { console.error(`\n${failures} FAILURE(S)`); process.exit(1); }
console.log('\nALL TESTS PASS');
```
