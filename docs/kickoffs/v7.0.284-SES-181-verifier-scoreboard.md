# THE THING THIS PANEL MUST NOT CLAIM

The charter's bar is *"over a rolling 30 deliveries: the verifier's catch rate ≥ John's baseline
Rework+Reverse rate"*. Measured before a line changed:

| Window | Value |
|---|---|
| last 30 verdicts | 9 `block` → **30.0%** |
| last 30 decided ship cards | 0 `rework`/`reverse` → **0.0%** |
| deliveries carrying **both** a verdict and a tap of John's | **5** (verifier blocked on 4, John reworked 0) |

Read carelessly that is *"30% ≥ 0% — the keystone is met"*, and it would be the most expensive
sentence on the page. Two reasons it is false, both of which the panel must say out loud:

1. **The two rates count different populations.** The lane began Aug 25 and has graded 20 tickets;
   John's tap history is 115 decided ship cards going back much further. Like-for-like the overlap
   is **five deliveries** — not a rolling thirty.
2. **A `block` is a mechanical gate failing** (build / regression / hygiene), not a defect John
   would necessarily have reworked. So `verifier ≥ John` is **necessary** for the charter's bar and
   never **sufficient**.

Same rule as §14's cost showing `—` and a NULL `plain_*` drawing a red defect line: absent must look
absent, and *not yet assertable* must look like that rather than like a pass.
