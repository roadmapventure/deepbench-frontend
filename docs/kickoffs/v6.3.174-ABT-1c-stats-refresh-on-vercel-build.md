## 2. CONTEXT

`ABT-1a` shipped the About screen's live metric grid. Four of its eleven tiles are repo facts (lines of code, source files, governance docs, commits to dev) that a browser can't compute, so they're read from the single-row `platform_stats` Supabase table. `ABT-1b` built `scripts/platform-stats.js` (already on `dev`) to recount them, plus a GitHub Action to run it on every push to `dev` — **but the Action can never be pushed from this machine: the only GitHub credential is a classic PAT with `repo` and not `workflow` scope, so GitHub rejects any push containing `.github/workflows/*`.** Re-verified 2026-07-28: `X-OAuth-Scopes: repo`. Fixing that is an account-credential change John has declined to make, and it should not be required.

**The insight this session acts on:** the Action's only job was "run the recount whenever `dev` changes." Vercel already builds the site on every push to `dev` — same trigger, no GitHub permissions involved. Moving the recount into the build removes the blocker entirely and deletes a whole moving part (no workflow file, no CI secrets/variables to keep in sync). The `SUPABASE_URL`/`SUPABASE_ANON_KEY` repo variables created by `ABT-1b` become dead and are irrelevant either way; Vercel already has `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` set (the app bundle needs them at build time), which the script already falls back to.

**Two risks this session must engineer against, both non-negotiable:**
1. **A stats refresh must never break a deploy.** It's a cosmetic side-quest; the site shipping matters infinitely more.
2. **A shallow CI checkout must never write a wrong commit count.** Vercel does not guarantee full git history, so `git rev-list --count HEAD` can legitimately return a small number (e.g. 10). Writing that would visibly corrupt the "Commits to dev" tile.

## 5. TASKS (3)

### Task 1 — `scripts/platform-stats.js`: add `--soft` mode (never fail the caller)

Accept a `--soft` flag (`process.argv.includes("--soft")`). In soft mode **every** failure path — missing env, git failure, non-2xx PATCH, echo mismatch, thrown exception — logs a single clear `platform-stats: skipped — <reason>` line and **exits 0**. Without the flag, behavior is exactly as today (exit 1 on failure), so the local/manual invocation stays strict and the Node test keeps its teeth.

Wrap the whole body so an unexpected throw is caught in soft mode too — a `fetch` DNS failure inside a Vercel build must not surface as a non-zero exit.

### Task 2 — `scripts/platform-stats.js`: guard the commit count + scope which builds may write

- **Never regress `commits_dev`.** Before PATCHing, GET the current row. If the freshly computed `commits_dev` is **less than** the stored value, omit `commits_dev` from the PATCH body entirely (keep every other field) and log `platform-stats: commit count looks truncated (computed N < stored M) — preserving stored value`. Commit count on `dev` only ever increases, so a lower number always means a shallow clone, never a real regression. Also omit it if `git rev-parse --is-shallow-repository` returns `true` or the `git` call throws.
- **Only `dev`/production builds may write.** If `process.env.VERCEL` is set and `process.env.VERCEL_GIT_COMMIT_REF` is present and is neither `dev` nor `main`, log `platform-stats: skipped — preview build for branch <ref>` and exit 0 without writing. A feature-branch preview must not overwrite the row with that branch's state. A local run (no `VERCEL` env) is unaffected.
- `dev_toolchain_services` stays absent from the PATCH body, exactly as today (John-set value, preserved by omission).

### Task 3 — `package.json`: run it before every build

Add a `prebuild` script (npm runs it automatically before `build`; do not change `build` itself):
```json
"prebuild": "node scripts/platform-stats.js --soft"
```
No shell operators (`;`, `&&`) — they aren't portable to Windows, where sessions run `npm run build` locally. Soft mode is what makes this safe. A local Windows `npm run build` has no Supabase env loaded (`.env.local` isn't auto-read by plain `node`), so it will log a skip line and continue — that is the correct, expected local behavior, not a failure to fix.

## 8. NODE.JS TEST (full code — save as `test-abt-1c.mjs`, run `node --env-file=.env.local test-abt-1c.mjs`, delete before committing)

```js
// test-abt-1c.mjs — S-ABT-1c verification (Categories B, C, F + live write)
import { execSync } from "node:child_process";
import { readFileSync } from "node:fs";
import assert from "node:assert";
let pass = 0;
const ok = (c, m) => { assert.ok(c, m); console.log("PASS:", m); pass++; };

const pkg = JSON.parse(readFileSync("package.json", "utf8"));
ok(pkg.scripts.prebuild === "node scripts/platform-stats.js --soft", "prebuild wired with --soft");
ok(pkg.scripts.build === "vite build", "build script itself unchanged");
const src = readFileSync("scripts/platform-stats.js", "utf8");
ok(/--soft/.test(src), "script honors --soft");
ok(/is-shallow-repository/.test(src), "shallow-clone guard present");
ok(/VERCEL_GIT_COMMIT_REF/.test(src), "preview-branch guard present");
ok(!/dev_toolchain_services\s*[:,]/.test(src.split("const body")[1]?.split("}")[0] ?? ""), "dev_toolchain_services never in PATCH body");

const url = process.env.SUPABASE_URL || process.env.VITE_SUPABASE_URL;
const key = process.env.SUPABASE_ANON_KEY || process.env.VITE_SUPABASE_ANON_KEY;
assert.ok(url && key, "Supabase env present");
const get = async () => (await (await fetch(`${url}/rest/v1/platform_stats?id=eq.1&select=*`,
  { headers: { apikey: key, Authorization: `Bearer ${key}` } })).json())[0];

const before = await get();

// 1. Soft mode with NO env must exit 0 and write nothing.
const clean = { ...process.env };
delete clean.SUPABASE_URL; delete clean.SUPABASE_ANON_KEY;
delete clean.VITE_SUPABASE_URL; delete clean.VITE_SUPABASE_ANON_KEY;
let softExit = 0;
try { execSync("node scripts/platform-stats.js --soft", { env: clean, encoding: "utf8" }); }
catch (e) { softExit = e.status ?? 1; }
ok(softExit === 0, "soft mode exits 0 with no Supabase env (a deploy can never break on it)");

// 2. Preview-branch guard: a non-dev Vercel build must not write.
const preview = { ...process.env, VERCEL: "1", VERCEL_GIT_COMMIT_REF: "some-feature-branch" };
execSync("node scripts/platform-stats.js --soft", { env: preview, encoding: "utf8" });
const afterPreview = await get();
ok(afterPreview.updated_at === before.updated_at, "preview build for a non-dev branch wrote nothing");

// 3. Real run writes, preserves toolchain, never regresses commits.
const out = execSync("node scripts/platform-stats.js", { encoding: "utf8" });
console.log(out);
const after = await get();
ok(after.lines_of_code > 20000, `lines_of_code recounted (${after.lines_of_code})`);
ok(after.governance_docs > 300, `governance_docs recounted (${after.governance_docs})`);
ok(after.commits_dev >= before.commits_dev, `commits_dev never regressed (${before.commits_dev} → ${after.commits_dev})`);
ok(after.dev_toolchain_services === before.dev_toolchain_services, "dev_toolchain_services preserved");
ok(after.updated_by === "platform-stats-action", "updated_by stamped");

console.log(`ALL TESTS PASS (${pass})`);
```

Then run `npm run build` and confirm the prebuild line appears in its output and the build still succeeds.
