## 2. CONTEXT

From the same design-session walkthrough as `CHI-03a`: the user needs feedback that something is happening after their HITL actions (submitting a theory, resolving a hypothesis test), and Marcus — the only voice Chat has ever spoken in — should be the one giving it, tailored to what the user actually did (John's explicit call: "this has got to feel like you are talking to a person," rejecting a static string after seeing a concrete before/after comparison).

**Two new moments, both Marcus-voiced, both live (real LLM calls, not static strings):**
1. **Submission ack** — fires when a hypothesis test starts (`onSelectHypothesis`'s `startTest` branch), tailored to the theory text the user just submitted.
2. **Resolution ack** — fires at the *real* final resolution moment. **Important correction found while reading the code for this design session:** "Store as Forecast" is not itself the final resolution — it kicks off Nadia's `ConfirmationCard` draft-review. The actual resolution points are `onDiscard()` (Info Only, immediate) and `onResolveConfirmation()`'s accept/reject branches (Store as Forecast → Nadia's card resolves). The ack fires at both of these, not at the "Store as Forecast" button click.

**Confirmed generic, no new server-side logging code needed:** `execute.js` (~L95-104) calls `logActivity()` unconditionally for every capability dispatch, keyed dynamically by whatever `capability_slug`/`intent_slug` is passed — no allowlist. Both new intents are logged automatically the moment they're called through `callCapability()`. `MI_LOOP_SCOPE.featurePrefixes` (`MarketIntelligenceScreen.jsx`) already has a blanket `"channel-intelligence:"` prefix (not narrowly scoped per-intent, unlike `screen-controls:`'s entries) — both new intents are already covered, no new prefix entry needed.

**What's actually needed for AI Audit wiring:** only the display-layer `SERVICE_CATALOG`/`AI_TYPE_TO_SERVICE` entries (Task 4) — without them, calls would still log correctly but land in `LOG-14`'s auto-fallback bucket instead of Marcus's existing `channel-intelligence` service in the By-Service view.

### Task 3 — Wire the resolution ack (`onDiscard()` and `onResolveConfirmation()`'s accept/reject branches)

Replace `CHI-03a`'s static placeholder pushes with real calls. `onDiscard()`:
```jsx
callCapability({
  capability_slug: "channel-intelligence", intent_slug: "ci-resolution-ack-intent", agent_id: "marcus",
  task_context: { resolution: "info_only", theory: hypFlow?.chosenText || "" },
}).then(ack => setMessages(prev => [...prev, { role: "assistant", kind: "non_qa", text: ack.ack_text }]))

  });
```
`onResolveConfirmation()`, accept branch (`resolution === "accept"`):
```jsx
callCapability({
  capability_slug: "channel-intelligence", intent_slug: "ci-resolution-ack-intent", agent_id: "marcus",
  task_context: { resolution: "stored", theory: hypFlow?.chosenText || "" },
}).then(ack => setMessages(prev => [...prev, { role: "assistant", kind: "non_qa", text: ack.ack_text }]))
  .catch(e => {
    console.error("[MarketIntelligenceScreen] ci-resolution-ack-intent", e.message);
    setMessages(prev => [...prev, { role: "assistant", kind: "non_qa", text: "Got it — that's been stored as a forecast." }]);
  });
```
Reject branch (`resolution === "reject"`) — identical shape, `resolution: "rejected"`, fallback text `"Got it — that proposal was rejected, nothing was stored."`.

All three calls are fire-and-forget relative to the surrounding function (`.then()`/`.catch()`, not `await`ed) — they narrate after the real state change (`setHypFlow(null)` for the resolution paths) has already happened, never blocking or gating it.

```js
// test-CHI-03b.mjs — pure Node.js, no app imports
let pass = 0, fail = 0;
function assert(desc, cond) {
  if (cond) { console.log(`  ✓ ${desc}`); pass++; }
  else       { console.error(`  ✗ ${desc}`); fail++; }
}

// Mirrors the three call-site task_context shapes (MarketIntelligenceScreen.jsx, Tasks 2/3).
function buildAckTaskContext(moment, theory) {
  if (moment === "submission") return { intent_slug: "ci-submission-ack-intent", task_context: { submitted_theory: theory } };
  if (moment === "info_only") return { intent_slug: "ci-resolution-ack-intent", task_context: { resolution: "info_only", theory } };
  if (moment === "stored") return { intent_slug: "ci-resolution-ack-intent", task_context: { resolution: "stored", theory } };
  if (moment === "rejected") return { intent_slug: "ci-resolution-ack-intent", task_context: { resolution: "rejected", theory } };
}

assert("submission ack carries the submitted theory", buildAckTaskContext("submission", "x").task_context.submitted_theory === "x");
assert("info_only resolution ack has the right resolution tag", buildAckTaskContext("info_only", "x").task_context.resolution === "info_only");
assert("stored resolution ack has the right resolution tag", buildAckTaskContext("stored", "x").task_context.resolution === "stored");
assert("rejected resolution ack has the right resolution tag", buildAckTaskContext("rejected", "x").task_context.resolution === "rejected");
assert("all three resolution moments use the same intent slug", new Set(["info_only","stored","rejected"].map(m => buildAckTaskContext(m,"x").intent_slug)).size === 1);
assert("submission and resolution use distinct intent slugs", buildAckTaskContext("submission","x").intent_slug !== buildAckTaskContext("stored","x").intent_slug);

console.log(`\n${pass + fail} tests — ${pass} passed, ${fail} failed`);
if (fail > 0) process.exit(1);
else console.log("ALL TESTS PASS");
```
