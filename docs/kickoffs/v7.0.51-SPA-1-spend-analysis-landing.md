## 2. CONTEXT

The Spend Analysis nav item (desktop dropdown + mobile) routes to `/work/1/analyze` — task 1 is the Austin FY2025 demo task. `AnalyzerScreen.jsx`'s desktop landing component `DataSourceScreen` (stage `"overview"`) already renders a full data-source chooser: three cards — Load Demo (City of Austin), Fetch State Data, Upload Your Own File. But its mount effect (`AZ-18`, Austin demo pre-load) sees `taskId === "1"`, immediately fetches `/Austin_2025Data_.csv`, and calls `processFile(..., autoAnalyze=true)`, jumping straight to the dashboard. The user never sees the chooser.

John wants the chooser to be the landing: choosing Spend Analysis should offer demo / live fetch / upload, with Austin still one click away.

**Critical fact verified against Supabase this design session:** `tasks` row `id=1` has `csv_path = 'global/1/Austin_2025Data_.csv'`. Therefore deleting only the demo branch is NOT enough — execution would fall through to the `SH-07` Storage auto-load path, query that row, and auto-load anyway. The demo task must skip auto-load entirely.

Mobile (`MobileAnalyzerHome`) keeps its own copy of the auto-load **unchanged** — the mobile landing has no Load Demo card, so removing its auto-load would strand mobile users with no one-tap Austin. Tracked separately as `MOB-10`.

## 5. TASKS (2)

### Task 1 — Demo task skips auto-load in `DataSourceScreen` (desktop only)

In `src/screens/AnalyzerScreen.jsx`, inside `DataSourceScreen`'s mount effect (the one logging `"Auto-load check:"`), make `taskId === "1"` a no-op early return instead of the Austin fetch branch. The effect currently reads:

```js
useEffect(() => {
  console.log("Auto-load check:", { taskId, autoLoaded });
  if (autoLoaded) { console.log("Already loaded, skipping"); return; }
  if (!taskId) { console.log("No taskId, skipping"); return; }
  console.log("Starting auto-load for taskId:", taskId);
  setAutoLoaded(true);
  if (taskId === "1") {
    console.log("Demo task detected, loading Austin CSV");
    (async () => {
      try {
        const res = await fetch("/Austin_2025Data_.csv");
        if (!res.ok) throw new Error("Could not load demo file");
        const blob = await res.blob();
        // autoAnalyze=true: full parse, skip mapping screen, go direct to dashboard
        processFile(new File([blob], "Austin_2025Data_.csv", { type: "text/csv" }), null, true);
      } catch (e) { setError("Demo failed: " + e.message); }
    })();
    return;
  }
  setStorageLoading(true);
  // ... SH-07 Storage path — DO NOT TOUCH
```

Replace the entire `if (taskId === "1") { ... return; }` block with:

```js
  // FEATURE: SPA-1 — demo task lands on the data-source chooser; no auto-load.
  // tasks row id=1 HAS a csv_path in Supabase, so falling through to the
  // SH-07 Storage path below would auto-load anyway — the early return is load-bearing.
  if (taskId === "1") return;
```

Everything above it (the `autoLoaded` / `!taskId` guards, `setAutoLoaded(true)`) and everything below it (the `SH-07` Storage path for non-demo tasks) stays byte-identical. The `loadDemo` click handler on the City of Austin card stays byte-identical — it is now the only way the demo loads on desktop.
