**`tool_choice`-forcing ruled out by direct verification, not assumed:** `agent-selection-intent`'s `traits.can_request_help` is `null` in live Supabase — confirmed via `execute_sql`. That means `canRequestHelp` is already `false` for this call, `harnessTools` is empty, and per `buildCallBody()` (`request-receivable.js:80`), `tool_choice` is **already forced** to the schema tool on both the first attempt and the retry (the retry body inherits `callBody`'s `tool_choice` unchanged). The model has no competing tool to route to instead — forcing `tool_choice` is not an available lever here because it's already true and has not prevented the omission.

**Budget theory (the fix this session ships, per John's explicit call — ship directly, no A/B measurement):** `agent-selection-intent`'s required-field schema, confirmed live via `execute_sql`, is ordered `reasoning` (string, 300 char) → `candidates` (array, one entry per viable roster candidate, up to 7 fields each) → `recommended_agent_id` → `recommended_capability_slug`. Models tend to emit JSON keys in schema-declaration order, so the two fields that keep going missing are structurally the *last* two written — the same "runs out of budget before reaching the tail of the required-fields list" shape `AA-161` proved (with real `output_tokens` measurement) for `intelligence-review-format`, at an even tighter cap here (1200 vs. the 1500 that was already too tight there). No real output-token measurement exists for this specific call's failures (not logged) — this session ships on the schema-order argument plus the `AA-161` precedent, not a fresh A/B test, per John's call.

**Cost/latency consideration (why this bump is smaller than `AA-161`'s 2x):** `AA-159` (found 2026-07-08, unscheduled) flagged `agent-selection-intent` as the **#3 largest cumulative platform LLM time sink today** — 146 calls, 14.4% of all real platform LLM time, purely from call *volume* (every hand-off hop invokes it). A large `max_tokens` bump raises worst-case latency/cost on every one of those calls, not just the failing ~20%. This session raises the cap by roughly +1000 tokens (1200→2200, ~1.8x) rather than mirroring `AA-161`'s full 2x-to-3000 — enough headroom for the schema-order theory without doubling worst-case cost on a call this frequent. If re-verification below still shows failures after this change, the next lever is a larger bump or `AA-159`'s own volume-reduction work, not immediately re-guessing bigger.

const BASE = 'https://deepbench-frontend-git-dev-roadmapventures-projects.vercel.app';
const BYPASS = 'deepbenchDeploymentProtectionByp';

async function callCapability(body) {
  const res = await fetch(`${BASE}/api/capabilities/execute`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'x-vercel-protection-bypass': BYPASS },
    body: JSON.stringify({ ...body, tenant_id: 'global' }),
  });
  return { status: res.status, ok: res.ok, json: await res.json().catch(() => null) };
}

async function runOnce(i) {
  const analysis = await callCapability({
    capability_slug: 'hypothesis-evaluation', intent_slug: 'hyp-hypothesis-test-intent', agent_id: 'priya',
    task_context: {
      hypothesis: "The EMEA retail partner's co-op utilization figure of 55% is wrong — it should be 78%, the source chunk used last quarter's data by mistake.",
      intent: 'correct', flagged_question: '', flagged_answer: '', prior_hypothesis_test: null,
    },
  });
  if (!analysis.ok) return { attempt: i, stage: 'hyp-hypothesis-test-intent', status: analysis.status, detail: analysis.json };
  const content = analysis.json.content || analysis.json;
  const display = await callCapability({
    capability_slug: 'hypothesis-evaluation', intent_slug: 'hyp-hypothesis-test-display-intent', agent_id: 'priya',
    task_context: { supports: content.supports, complicates: content.complicates, consider: content.consider, confidence: content.confidence },
  });
  if (!display.ok) return { attempt: i, stage: 'hyp-hypothesis-test-display-intent', status: display.status, detail: display.json };
  return { attempt: i, stage: 'PASS', status: display.status };
}

  console.log(JSON.stringify(r));
  if (r.stage === 'PASS') passCount++;
}
console.log(`\n${passCount}/5 PASS`);
