## 2. CONTEXT

Found live 2026-07-21 during `CHI-42`'s own live verification (not this session's discovery — flagged by the prior session, traced end-to-end in this one, not assumed).

**Repro:** MI screen, hypothesis flow → "Have Priya generate a few theories" → select a hypothesis → "Have Priya test this theory" → "Store as Forecast". Elena Cho (The Reasoner) and Nadia Farouk (Data Expert) complete successfully, producing a `ConfirmationCard` with `proposed_action.chunk_id: "geo-revenue-analysis-2025"`. Clicking **Accept** returns HTTP 500:
```
{"error":"library-write handler: writeLibrary failed -- supersedes_id lookup failed: {\"code\":\"22P02\", ... \"invalid input syntax for type uuid: \\\"geo-revenue-analysis-2025\\\"\"}"}
```

**Root cause, traced this session, confirmed live against Supabase (not assumed):** `writeLibrary()`'s `insert` operation (`lib/librarian.js:266-271`) runs a raw Postgres lookup — `the_library?id=eq.<supersedes_id>` — whenever `params.supersedes_id` is truthy, with zero format validation first. In this repro, `supersedes_id` is populated with the new entry's own human-readable `chunk_id` slug, not a real `the_library` row id (confirmed: Nadia's own `proposed_action` has no `supersedes_id` key at all — `action`, `content`, `chunk_id`, `confidence`, `version_note` only — so it's constructed downstream, by Eleanor Voss's own follow-up library-write step, from `version_note`'s "Supersedes any prior GEO revenue analysis entry" prose, without first looking up the real prior row). A non-UUID id throws `22P02`; `writeLibrary()`'s own `catch` (L325-327) absorbs it into `{success:false, error: err.message, ...}`, but `api/_lib/handlers/library-write.js`'s `handle()` (L23-24) unconditionally re-throws any `!result.success` as an `Error` carrying that raw message — which is what reaches the client as a raw, unstructured Postgres error string.

**This is the identical bug shape `AA-189` (✅ Done) already fixed, at the sibling call site.** `AA-189` added a UUID-format guard to `writeTheReasoning()`'s `source_chunk_ids` check (`lib/search-harness.js`) for the exact same reason — a human-readable, agent-supplied label reaching a raw `the_library?id=...` Postgres filter with no format check. `AA-189`'s own kickoff doc explicitly named `supersedes_id` as "the same category of check as AG-33's `supersedes_id` fix on `the_library` itself" while scoping only `source_chunk_ids` — this session closes that named, left-open sibling gap. `AA-189`'s own archive entry's live-verification test was this identical "Store as Forecast → Accept" flow; it passed then because the crash under test (`source_chunk_ids`) was already fixed — this is a later stage of the same flow `AA-189` never covered.

**Fix, confirmed with John (design-session walkthrough):** validate `supersedes_id` is UUID-shaped before the Postgres lookup. A malformed id can never resolve to a real `the_library` row anyway, so treat it exactly like the existing cross-room-mismatch case immediately below it in the same function — reuse the existing `denied-supersedes-cross-room` tier verbatim, no new response shape, no new consumer-side branch. This does not silently treat a malformed `supersedes_id` as "no supersede, just insert fresh" (a candidate considered and rejected this session) — `version_note`'s own text asserts a real supersession is intended, so silently downgrading it to a new insert would mask a real data-integrity mismatch instead of surfacing it, the same "fail safe, never fake" principle already applied elsewhere in this codebase.

**What this does and does not fix:** this closes the raw-Postgres-error-leak half of the bug — the client and logs get the same clean, named `denied-supersedes-cross-room` tier `AA-189` already established for the sibling case, not a leaked `22P02` string. It does **not** by itself un-stick a `ConfirmationCard` that already reached this failure and got marked `accepted` — that is `LOO-17` (logged separately, `docs/FEATURES.md`), out of scope here, its own follow-up design session per the one-feature-per-session rule. `DAT-6` alone still surfaces as an error to the user (via `AA-189`'s existing `onResolveConfirmation` catch) — it is a strictly smaller, cleaner failure than today's raw crash, not a full recovery.

**No existing UUID-validation helper found to reuse.** `AA-189` itself confirmed the same at the time ("No existing UUID-validation helper found in the codebase") and inlined its own `UUID_RE` locally in `lib/search-harness.js` rather than extracting a shared helper. This session follows the same precedent — the identical regex is inlined locally in `lib/librarian.js` too, not extracted into a new shared file. Deliberate, flagged choice (Tier 2): a shared-helper extraction would touch a second working, already-verified file (`search-harness.js`) for no functional gain, just to remove one duplicated one-line regex.

**Harness-vs-service check:** `writeLibrary()` is `the_library`'s sole write broker (`ARCHITECTURE.md` §19c, Eleanor-exclusive) — this validation belongs exactly where it's being added, no extraction needed, same conclusion `AA-189` reached for `writeTheReasoning()`.

## 5. TASKS

### Task 1 — `lib/librarian.js`: validate `supersedes_id` is UUID-shaped before querying Postgres

```js
      if (params.supersedes_id) {
        // FEATURE: DAT-6 -- supersedes_id is constructed downstream of Nadia's own structured
        // output (Eleanor's follow-up library-write step), never format-validated before this
        // point. A non-UUID id (here, the new entry's own human-readable chunk_id slug) used to
        // reach the Postgres `id=eq.<...>` filter below and throw a raw 22P02 syntax error --
        // library-write.js's handle() then re-throws that raw message unconditionally. A
        // malformed id can never resolve to a real the_library row anyway, so it's treated
        // exactly like the existing cross-room-mismatch case immediately below -- same graceful
        // denial, no new tier. Same shape as AA-189's source_chunk_ids guard (search-harness.js).
        const UUID_RE = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;
        if (typeof params.supersedes_id !== "string" || !UUID_RE.test(params.supersedes_id)) {
          const tier = "denied-supersedes-cross-room";
          logActivity({ agentId: 'eleanor', aiType: 'librarian-write', feature: `librarian-write:${operation}`, latencyMs: Date.now() - startTime });
          return { success: false, _librarian: { granted: false, tier } };
        }

        const supersedeRes = await fetch(
          `${supabaseUrl}/rest/v1/the_library?id=eq.${encodeURIComponent(params.supersedes_id)}&select=data_room_tag`,
          { headers }
        );
        if (!supersedeRes.ok) throw new Error("supersedes_id lookup failed: " + (await supersedeRes.text()).slice(0, 200));
        const [supersededRow] = await supersedeRes.json();
        if (!supersededRow || supersededRow.data_room_tag !== targetTag) {
          const tier = "denied-supersedes-cross-room";
          logActivity({ agentId: 'eleanor', aiType: 'librarian-write', feature: `librarian-write:${operation}`, latencyMs: Date.now() - startTime });
          return { success: false, _librarian: { granted: false, tier } };
        }
      }
```

Only the new `UUID_RE`/`if` block is inserted, immediately after `if (params.supersedes_id) {` and before the existing `fetch` call. Nothing else in the function changes — the existing cross-room check below it is untouched.

## 6. DESIGN RULES

- Reuse the existing `"denied-supersedes-cross-room"` tier verbatim for the malformed-format case — do not invent a new tier, it's semantically the same outcome ("this supersede reference will never resolve to a real row"). Mirrors `AA-189`'s identical design rule for `denied-source-chunk-cross-room-or-missing`.
- Do not silently treat a malformed `supersedes_id` as "no supersede intended" — `version_note` asserts a real supersession, so a malformed id must deny, not silently downgrade to a fresh insert.
- Inline the `UUID_RE` regex locally (matches `AA-189`'s precedent) — do not extract a shared helper this session.
