## 1. CONTEXT

`buildCallBody()`/`callModel()` (`api/prompt/request-receivable.js`) force `tool_choice` to `{ type: 'tool', name: schemaTool.name }` only when a capability has a schema and **no** harness tools available. The moment a capability also has `can_request_help: true` (harness tools present), `tool_choice` switches to `{ type: 'auto' }` — necessary so the model can legitimately choose `request_help`/`delegate_to_agent` instead of answering directly. But `'auto'` also means the model can satisfy "call a tool" by calling its **own schema tool** with an empty or partial input object. `parseModelTurn()` only checks that *a* `tool_use` block exists — it never checks that the tool's `input` actually contains the schema's required fields. That input flows straight through `callModel()` → `sendRequest()` (`parsedResponse = turn.tool_input`) into the handler with zero validation, silently writing a deliverable with missing/undefined content. No error anywhere in the chain.

This was found live during `S-MARKET-INTEL-01a` and tracked informally as `task_a8249f13` in `CLAUDE-STATE.md`'s queue (never given its own `FEATURES.md` row until this session — Backlog Capture rule). It sits in the same continuity/information-transfer bug family as `AA-126`/`AA-142`/`AA-144`/`AA-141`/`AA-145`/`AA-135` — data that should carry through a hop silently goes missing instead of failing loudly.

**Confirmed blast radius (queried live against Supabase `skill_profiles`, 2026-07-08):** 10 Intent Skill Profiles combine `can_request_help: true` with a schema. Two (`ci-answer-display-intent`, `hyp-hypothesis-test-display-intent`) also carry `delegation_required: true` and are already fully protected by `AA-142`'s retry-once-then-throw guard — that guard fires on ANY non-delegate completion, content-empty or not, before reaching `sendRequest()`. The other **8 are unprotected and exposed today**: `ci-routing-intent`, `ci-answer-intent` (Marcus's main Q&A path), `intake-commit-intent`, `intake-failure-intent`, `hyp-hypothesis-test-intent` (Priya's stress test), `data-patch-execute-intent`, `data-escalate-execute-intent`, `qg-review-intent` (Owen's Proofreader — runs on every Q&A/hypothesis turn). This is the widest-blast-radius unfixed gap in the continuity bug family: it can silently corrupt the two highest-traffic MI-loop capabilities (Marcus's answer, Owen's guardrail review).

## 5. TASKS (2 of 4 max, 1 file)

### Task 1 — `api/prompt/request-receivable.js`: extend `parseModelTurn()` to validate schema-tool required fields

Replace the function (currently lines 90–105) with:

```js
// FEATURE: AA-147 -- validates a schema-tool call's required fields before accepting it. Needed
// because tool_choice is 'auto' (not forced) whenever harness tools are also offered (buildCallBody(),
// ~line 75) -- the model can technically satisfy "call a tool" by calling its own schema tool with an
// empty or partial input object, which previously passed straight through to sendRequest() and got
// written to a deliverable with missing/undefined content, no error surfaced anywhere (confirmed live
// in S-MARKET-INTEL-01a). Reuses callModel()'s existing retry-once-then-throw path below by throwing
// the same class of error as "No tool_use block in response" -- no new retry logic. Presence-only
// check (does the key exist on the input object) -- does not reject a legitimately empty string/array
// on a required field, only a field missing entirely. request_help/delegate_to_agent calls are exempt
// -- their own required-field completeness is a separate, pre-existing concern, out of this session's
// scope.
export function parseModelTurn(responseData, hasSchemaTool, schemaTool) {
  const toolUseBlock = responseData.content?.find(b => b.type === 'tool_use');
  if (toolUseBlock) {
    const isHarnessTool = toolUseBlock.name === 'request_help' || toolUseBlock.name === 'delegate_to_agent';
    if (!isHarnessTool && schemaTool && toolUseBlock.name === schemaTool.name) {
      const required = schemaTool.input_schema?.required || [];
      const missing = required.filter(key => !(key in (toolUseBlock.input || {})));
      if (missing.length > 0) {
        throw new Error(`Schema tool "${schemaTool.name}" called with missing required field(s): ${missing.join(', ')}`);
      }
    }
    return {
      is_delegate_call: isHarnessTool,
      tool_name: toolUseBlock.name,
      tool_use_id: toolUseBlock.id,
      tool_input: toolUseBlock.input,
    };
  }
  if (hasSchemaTool) throw new Error('No tool_use block in response');
  const textBlock = responseData.content?.find(b => b.type === 'text');
  if (!textBlock) throw new Error('No text block in response');
  return { is_delegate_call: false, tool_name: null, tool_use_id: null, tool_input: textBlock.text };
}
```

## 8. NODE.JS TEST

`test-s-arch-schema-guard-01.mjs` (import `parseModelTurn` from `api/prompt/request-receivable.js`, delete before commit):

```js
import assert from 'node:assert';
import { parseModelTurn } from './api/prompt/request-receivable.js';

const schemaTool = {
  name: 'ci-answer-format',
  input_schema: { type: 'object', required: ['headline', 'body', 'confidence_tier'], properties: {} },
};

function withToolUse(name, input) {
  return { content: [{ type: 'tool_use', id: 'tu_1', name, input }] };
}

// 1. Fully populated schema call -- no throw, tool_input passed through unchanged
{
  const input = { headline: 'x', body: 'y', confidence_tier: 'Sourced' };
  const turn = parseModelTurn(withToolUse('ci-answer-format', input), true, schemaTool);
  assert.deepEqual(turn.tool_input, input);
  assert.equal(turn.is_delegate_call, false);
}

// 2. Empty object {} on the schema tool -- throws naming all 3 required fields
{
  assert.throws(
    () => parseModelTurn(withToolUse('ci-answer-format', {}), true, schemaTool),
    /Schema tool "ci-answer-format" called with missing required field\(s\): headline, body, confidence_tier/
  );
}

// 3. One required field missing -- throws naming exactly that field, not the others
{
  const input = { headline: 'x', body: 'y' };
  assert.throws(
    () => parseModelTurn(withToolUse('ci-answer-format', input), true, schemaTool),
    /missing required field\(s\): confidence_tier$/
  );
}

// 4. Harness tool call (delegate_to_agent) with empty input -- validation skipped, no throw
{
  const turn = parseModelTurn(withToolUse('delegate_to_agent', {}), true, schemaTool);
  assert.equal(turn.is_delegate_call, true);
  assert.deepEqual(turn.tool_input, {});
}

// 5. No schemaTool provided (capability has can_request_help but no schema) -- guard inert, no crash
{
  const turn = parseModelTurn(withToolUse('request_help', { skill_needed: 'x', task_description: 'y', reasoning: 'z' }), false, undefined);
  assert.equal(turn.is_delegate_call, true);
}

// 6. hasSchemaTool=true, no tool_use block at all -- existing behavior unchanged
{
  assert.throws(
    () => parseModelTurn({ content: [{ type: 'text', text: 'oops' }] }, true, schemaTool),
    /No tool_use block in response/
  );
}

console.log('ALL TESTS PASS (6/6)');
```
