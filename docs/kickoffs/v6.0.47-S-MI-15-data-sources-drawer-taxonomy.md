# SESSION: S-MI-15 (v6.0.47) — Data Sources Drawer + Display-Label Taxonomy Relabel

## 1. CONTEXT

John asked for a 3rd-column drawer listing the Data Room's available data, so an Apple stakeholder watching the demo understands what's actually loaded. This is backlog item `MI-15`, never built. Design-session discussion (self-contained recap, no need to re-read the chat):

- **No interactivity.** Explicitly not a clickable/hint-question mechanism (John: "by no means is it to be interactive... just like a real library index card booth"). Read-only reference list only.
- **Live Supabase check found two real accuracy problems with the original v4-mockup-carried spec**, both fixed here:
  1. `the_library` has 7 leftover `status='archived'` test-artifact rows (from `S-LIBRARIAN-04`'s write-capability tests) mixed in with the 20 real `status='active'` baseline rows. Must filter to `status='active'` or the drawer shows fake demo content as if it were real Data Room content.
  2. The v4 mockup's "chunk count per row" and "source citation" fields don't correspond to anything real: there's no chunking mechanism (one row = one whole document), and the `source` column is internal provenance (`user`/`agent`/`test`), not a bibliographic citation. Both dropped from scope — do not add either.
- **The drawer surfaced a platform-wide labeling problem**, which is most of this session's scope: `data_type` (`sourced`/`inferred`/`synthesized`/`learned`) and the same vocabulary on `confidence_tier` (Q&A answers) were confusing John. Full multi-turn resolution, final locked matrix in `docs/STYLE-GUIDE.md` Section 19 (read this before writing any code — it has the exact mapping table and the "why" for each decision) and `docs/APPLE-AGENT-1-v5-DESIGN.md` §6. Summary:
  - **This is a display-layer relabel only.** The stored `data_type` value in `the_library`, the `confidence_tier` enum on answers, and every one of the 7 live Skill Profiles that reference this vocabulary in their LLM-facing schema (`ci-answer-intent`, `data-escalate-intent`, `intelligence-review-format`, `library-write-intent`, `qa-answer-format`, `qg-review-intent`, `solution-catalog`) are **unchanged**. Do not touch any Supabase `skill_profiles` row this session. Do not rename any enum value anywhere.
  - `sourced` → **"Sourced"** (unchanged)
  - `inferred` → **"Analysis"**
  - `synthesized` + `the_library.is_baseline = true` → **"Source Simulation"**
  - `synthesized` + `is_baseline = false`, OR any `confidence_tier` context (an answer has no baseline concept) → **"Analysis"**
  - `learned` (`the_reasoning` row) → **"Learned"** (unchanged)
  - `na` (`confidence_tier` only) → no equivalent label needed on `the_library`; render as `T.muted` "—" if it ever needs display (not expected live today)
  - **"Analysis" is the only type with a who-tag** (Human vs. AI), sourced from the existing `the_library.source` column (`user`→"Human", `agent`→"AI"). No who-tag on the other three types — Sourced's trust comes from the citation regardless of author, Source Simulation is inherently a one-time demo-seed action, Learned is always the Reasoner's own automatic write. A `confidence_tier` context has no `source` column — no who-tag there, it's implicitly AI (an answer is always agent-generated).
- **Two pre-existing render sites already show the raw, un-relabeled values** and must be fixed for consistency (found via Architect Review, not optional cleanup):
  - `EvidenceColumn`'s static layer legend (`MarketIntelligenceScreen.jsx` ~line 454-472) — currently hardcodes `["Sourced","Inferred","Synthesized","Learned"]` with colors.
  - `describePipelineEvent()`'s Q&A/format summary text (`MarketIntelligenceScreen.jsx` ~line 102, ~128) — currently interpolates the raw `confidence_tier` value directly into the string, e.g. `` confidence_tier: ${evt.data.confidence_tier} ``.
