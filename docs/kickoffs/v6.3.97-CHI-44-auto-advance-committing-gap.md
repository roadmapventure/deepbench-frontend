**Two fixes, confirmed live with John, both smaller in final scope than first proposed:**

**Fix 1 — auto-advance theory selection (no second click).** Today, `onSelectHypothesis(text)` (no second arg) lands on a `"ready"` stage requiring a separate, explicit "Have Priya test this theory →" click before `onSelectHypothesis(text, {startTest:true})` actually runs the test — a deliberate `MI-51` choice at the time ("theory testing is no longer auto-fired on selection"). John's direct call (his walkthrough's #4, confirmed live 2026-07-21): reverse this — selecting a theory (candidate click, or the "write your own" Save button) should immediately start the test, same auto-fire precedent already established by the news-card flow. This makes the `"ready"` stage's render block (L1897–1908) and `onSelectHypothesis`'s `!startTest` early-return branch dead code — both removed, not left unreachable.

**Side effect on `CHI-42`'s narration:** today two separate `kind:"user_action"` bubbles fire for this flow across two clicks ("You selected a theory to test." on select, "You asked Priya to test that theory." on the separate test-button click). Since this is now one physical click, collapse to a single bubble — "You selected a theory to test." — fired once, before the network call. The second bubble's text is retired, not duplicated.

**Fix 2 — the "committing" gap, narrowed after a live walkthrough with John.** Originally scoped as "give `committing` its own visible placeholder" — but John correctly pointed out `onCommit()` already calls `setStatus("Elena is consolidating this into memory…")` then `setStatus("Nadia is drafting a data patch…")`, which is Column 1's existing, accurate, live elapsed-timer strip — already visible, already correct, untouched by this session. **Confirmed scope: Column 2 just must not go visually blank — it doesn't need its own new status text duplicating what Chat already says.** The actual gap: `showSubmittedTheory` (L1712)'s condition — `stage === "testing" || stage === "result" || confirmation` — doesn't include `"committing"`, so the submitted-theory block (showing what theory you're actually committing) disappears the instant you click "Store as Forecast," leaving Column 2 looking empty/frozen during the wait even though nothing else is wrong. **The entire fix is adding `"committing"` to that condition.**

In `onSelectHypothesis()` (L3217), delete the `!startTest` early-return branch:

becomes:
```jsx
const onSelectHypothesis = async (text) => {
  if (!hypFlow) return;
```
