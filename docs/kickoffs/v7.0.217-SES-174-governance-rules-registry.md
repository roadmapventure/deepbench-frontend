## Design — the schema (applied via Supabase migration `ses174_governance_rules`)
```
public.governance_rules (
  id            text primary key,                       -- HR-<slug> | B1..B42 | CAP-<slug>
  statement     text not null,                          -- one imperative sentence, faithful to source
  canonical_doc text not null,                          -- authoritative home, e.g. CLAUDE.md#hard-rules
  enforcement   text not null check in (hook|script|reviewer|prose),
  status        text not null default 'live' check in (live|retired|superseded),
  superseded_by text references governance_rules(id),   -- required iff status='superseded'
  source_group  text not null check in (claude-md-hard-rules|runner-gov-register|standards-caps),
  created_at, updated_at timestamptz
  constraint ck_governance_superseded check ((status='superseded') = (superseded_by is not null))
)
```
- **`superseded_by` is a self-FK, not prose** — a retired rule points at its successor row, so "retiring
  a rule is a status flip" is literally one UPDATE, and the CHECK makes the two fields inseparable.
- **Grants locked (DAT-18 / SES-101 pattern):** this is a runner/dev-internal registry, never read with
  the browser anon key, so `anon`/`authenticated` hold **zero** privileges and `service_role`/`postgres`
  hold full DML. Asserted both directions (`has_table_privilege`): anon SELECT=false, authenticated
  INSERT=false, service_role INSERT=true. Default privileges are already closed since DAT-18, so the
  lock is fail-closed for any future column too.
- **`source_group`** is provenance (which corpus a rule came from) — it lets SES-176's tripwire scope its
  "no rule text outside its canonical home" check and lets a completeness audit prove all three corpora
  were seeded.

## QA — discriminating
State the test, then ask "would it pass if the change did nothing?":
- Registry has rows and every `B1..B42` present in the doc is a row (a no-op change → empty table → fails).
- The retirement mechanic: on a rolled-back fixture, flip one rule to `superseded` with a `superseded_by`
  and prove the CHECK rejects `superseded` with a NULL successor and `live` with a non-NULL one (a table
  with no CHECK would accept both → fails).
- Grants: anon/authenticated denied, service_role permitted (a table left on default grants would let
  the anon key read/write it → fails).
