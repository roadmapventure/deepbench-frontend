## 2. CONTEXT

LOG-95 (v6.3.184) shipped correctly — verified live: streamed rows now carry span identity, and Supabase confirms Michelle Manning (PM)'s selection call for the QA run classifies as "Request Routing" in `ai_call_patterns`. But her drawer row still showed no pattern line. Root cause (confirmed against `ai_activity_log` timestamps, not inferred): LOG-79's module-level per-trace cache (`_tracePatternCache` in MarketIntelligenceScreen.jsx) fetches the span→names map ONCE, when the first `RoutingActivityLine` for that trace mounts. LOG-95 made streamed rows mount **mid-flight** — so the map is fetched and frozen seconds before late-arriving executions (the PM's selection at trace+8s, the formatter at trace+13s) write their log rows. The cache never refetches; the single LOG-79 retry fires only when the trace has ZERO rows, which is never the case here (the requester's row lands first). LOG-79's assumption ("rows are written before the response returns") was valid when every consumer mounted post-response; LOG-95 legitimately broke it.

**Constraint (§19p/§19l unchanged):** refetch until the mounted row's span appears or a bounded retry budget is exhausted — then stop, honestly blank. Never poll unboundedly (a genuinely-unclassified span never appears and must not cause infinite queries); never fabricate; no per-agent logic; the Displayer view stays a plain view queried with the same two cheap selects.

### Task 1 — `src/lib/tracePatterns.js`: pure retry-decision helper

```js
// LOG-95b -- bounded span-miss refetch decision (§19p read side). A span absent from the map
// after maxTries refetches is honestly unclassified (§19l) -- stop, never poll unboundedly.
export function needsSpanRefetch(map, spanId, tries, maxTries = 3) {
  if (spanId == null || !map || typeof map !== 'object') return false;
  if (Object.prototype.hasOwnProperty.call(map, spanId)) return false;
  return tries < maxTries;
}
```

**2b.** The hook's effect: after each resolved map, if `needsSpanRefetch(map, spanId, tries)` — invalidate this trace's cache entry and refetch after 2500ms; stop when the span appears, the component unmounts, or 3 refetches are spent. Exact shape (replace the existing effect body; import `needsSpanRefetch` alongside the existing `fetchTracePatterns` import):

```js
function useTracePatterns(traceId, spanId) {
  const [spanPatterns, setSpanPatterns] = useState(() => (traceId && _tracePatternCache.get(traceId)) || EMPTY_TRACE_PATTERNS);
  useEffect(() => {
    if (!traceId) { setSpanPatterns(EMPTY_TRACE_PATTERNS); return; }
    let cancelled = false;
    let tries = 0;
    let timer = null;
    const attempt = () => {
      fetchTracePatternsCached(traceId).then(map => {
        if (cancelled) return;
        setSpanPatterns(map);
        // FEATURE: LOG-95b -- streamed rows mount mid-flight (LOG-95), so the trace map can be
        // frozen before this row's execution logged. Bounded refetch: invalidate + retry up to
        // 3 times, 2.5s apart, then accept honestly-unclassified (§19l). needsSpanRefetch is
        // pure -- tests/regression/LOG-95b-span-refetch.js.
        if (needsSpanRefetch(map, spanId, tries)) {
          tries += 1;
          _tracePatternCache.delete(traceId);
          timer = setTimeout(attempt, 2500);
        }
      });
    };
    attempt();
    return () => { cancelled = true; if (timer) clearTimeout(timer); };
  }, [traceId, spanId]);
  return spanPatterns;
}
```

Notes that are part of the spec: `_tracePatternPromises` already dedupes concurrent fetches, so several lines missing their spans in the same window share one network round trip per cycle — do not add extra coordination. Deleting the cache entry only forces the *next* `fetchTracePatternsCached` call to hit the network; lines whose spans already resolved keep rendering from their own state. Do not touch `fetchTracePatterns`/`buildSpanPatternMap` (LOG-79, regression-covered).
