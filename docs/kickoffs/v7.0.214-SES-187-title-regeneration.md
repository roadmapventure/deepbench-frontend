## 2. CONTEXT

**Premise revalidated live at pick time, measured not quoted.** Census over
`public.backlog_items WHERE queue IS NOT NULL` at `02:49Z`, **592 open numbered rows**:

| Shape of the stored `title` | Rows |
|---|---|
| retired declaration marker (`` `Post-beta` ``, `Beta-gate (bucket N)`) | **53** |
| provenance sentence (`New, found 2026-07-27 (…)`, `Found 2026-07-22 (…)`) | **102** |
| `title IS NULL` | 0 |
| falls back through `backlog_display_title()` | 50 |

**155 rows** carry one of the two broken shapes. The ticket's "~170" is the right order of
magnitude and its diagnosis is exactly right: the markdown→DB import populated `title` from the
description's **leading bolded clause**, which on these rows is the lifecycle marker or the
provenance note, not the subject. The subject is the clause *after* it.

Only 50 of the 155 are visible as broken through `backlog_display_title()` — that function falls
back to the description gist for the retired-marker shape but **returns the stored string for the
provenance shape**, because a provenance sentence is a non-empty, non-marker title as far as it can
tell. So on 102 rows John reads a dated session note where a ticket's name should be.

**The ticket's method claim is false, and that is this session's finding.** `SES-187` says *"one
mechanical pass: derive a real one-line title per row from its description."* That was tested
before anything was written — strip the leading bold marker, strip an optional parenthetical
caveat, take the first bolded clause if present else the first sentence, cut on a word boundary at
110 chars — run over all 155 rows. Roughly half the output is right. The other half:

- `LOG-126` → `Post-beta` — the marker again; that row's description is *only* the marker
- `DAT-15` → `latent, not live: nothing reads the_reasoning, so no wrong content can reach…` — a
  caveat presented as the ticket's name
- `LAV-17` → `Shrunk 2026-08-07 (S-LAV-28, v7.0.61): two of its three re-measured carriers…` —
  provenance again, one clause further in
- `LOG-54` → `John's call on §19j was "ship Priya Nair's — …` — a quotation
- `CHI-70` → `…is pure ephemeral React state: MarketIntelligenceScreen.jsx:3007, const` and
  `CHI-47` → `…overwritten on every new` — cut mid-clause

A plausible-but-wrong title is **worse than the visibly broken one**: `runner-cycle.md`'s own rule
says a fallback *"is a signal about the ticket, not a formatting problem to patch by hand… do not
invent a title to make the row look finished — that hides the population."* A regex that grabs a
caveat and calls it a name is that failure with a script's authority behind it.

So the derivation is judgment (a Fable 5 subagent reading each row's own description, per register
B21), and the part that must not be judgment — the gate every proposed title passes before it can
reach the board, and the `§19v` before-image on each write — is the shipped script.

## 6. DESIGN RULES

- **`id`, never `backlog_id`, is the write key.** `backlog_id` carries no unique constraint on this
  board — `CHI-48` occupies two rows (`SES-97`) — so `UPDATE … WHERE backlog_id = …` writes both.
- **The gate rejects rather than repairs.** Every rule in `validate()` corresponds to a failure
  observed in the mechanical run above: banned openers, a date, a version, a session slug, markdown,
  a trailing period, a dangling function word or comma, a title identical to the broken one, and
  length outside 30–110. None of them may be softened to raise the accept rate.
- **Before-image first, its success authorises the write** (`§19v`). The image is built from the
  row fetched live by the script, never from the subagent's copy.
- **`title` only.** `description` is untouched, so nothing this session writes can destroy the
  source the titles were derived from — the whole change is re-derivable and reversible.
