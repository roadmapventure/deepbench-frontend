## CONTEXT

John read a live Priya (CI-02) response and objected to third-person phrasing under "Consider also" — text like "Three things the director should pressure-test..." — and asked for direct-address voice ("I would recommend...") platform-wide, suspecting it might be a configuration issue.

**Root cause, confirmed by live Supabase query (not just kickoff-doc text, which was stale for this exact row — the doc still says `hyp-stress-test-intent`, but `S-MI-14` renamed the live slug to `hyp-hypothesis-test-intent`):** six `skill_profiles` rows across five agents still contain literal third-person "director" phrasing in their `objective`/`method` fields — the instructional text the model reads before generating its response:
- `qg-identity` (Owen) — "...before it reaches the director."
- `qg-review-intent` (Owen) — "...before it is shown to the director."
- `reasoner-identity` (Reasoner) — "when a director commits a Forecast or Correct decision..."
- `ci-routing-intent` (Marcus) — "Classify the director's message..." / "...if the director wrote a claim..."
- `intake-failure-intent` (Sam) — "...offer the director an Escalate path..."
- `hyp-hypothesis-test-intent` (Priya) — **the literal source of what John saw:** "...and what the director should still consider before acting."

**This is not new terminology debt — it's an incomplete rename.** `S-MI-14` (v6.0.25, shipped) already decided platform-wide: `"director"` → `"user"`. Its sweep covered `MarketIntelligenceScreen.jsx`, `agents.js`, and specific docs, but explicitly never touched `skill_profiles.objective`/`method` text in Supabase — that table wasn't in its file list. Confirmed via full grep this session: `src/`, `api/`, and every other `skill_profiles`/`agent_configs` row are clean. The 4 other code hits for "director" (`useAIActivity.js`/`agent-directory`, `AboutPanel.jsx`'s locked "procurement director" tagline, `nigp-lookup.js`'s NIGP category text, `execute.js`'s `agent-directory` comment) are confirmed unrelated — do not touch (see Scope Rules).

**Second, deeper problem — this is why John's "configuration" instinct is right:** there is currently no platform-wide voice rule at all. `api/prompt/db-assembly.js`'s `assemblePrompt()` builds every prompt purely from per-agent/per-capability Skill Profile data — nothing tells any agent, ever, to address the user directly rather than in third person. (Side finding, not fixed this session: `skill_profiles.tone`/`.confidence` columns are populated on 11 rows but never read by `buildSections()` — dead columns, logged to `docs/FEATURES.md` as a separate non-blocking item.)

**The fix, approved by John:**
1. Add one new, always-injected `VOICE` section to `assemblePrompt()` — same unconditional-push pattern already used for `WORK ORDER`/`TASK DETAILS` (platform-wide constant text, not sourced from any Skill Profile row, zero per-agent upkeep as new agents/capabilities are added).
2. Finish the `director`→`user` rename on the 6 flagged rows, and give Priya's `hyp-hypothesis-test-intent` row an explicit direct-address instruction for its `consider` output (the field that actually produced the third-person text John flagged).

### Task 1 — `api/prompt/db-assembly.js`: add the global VOICE section

In `assemblePrompt()`, immediately after the existing `runtime_context` block (~line 456, right before the `return { ... }` statement), add:

```js
// FEATURE: AA-127 — VOICE section, always appended last, every call, every agent. Fixes
// third-person bleed-through ("the user should...") into generated output — the model was
// mirroring third-person framing from its own instructional text (see AA-127 in
// docs/FEATURES.md). Platform-wide constant, not sourced from any Skill Profile row — same
// unconditional-append pattern as the WORK ORDER/TASK DETAILS/runtime_context sections above,
// deliberately placed after all of them so it is always the final thing the model reads.
sections.push({
  slug: 'voice',
  label: 'VOICE',
  skill_profile_slug: null,
  type: 'stored',
  content: `Speak directly to the user — the human you are working with — in second person ("you") or first person for your own analysis ("I recommend", "I'd flag", "Worth confirming"). Never refer to them in third person (e.g. "the user should..."). This applies to every piece of text you generate, including structured fields like "consider"/"complicates"/"supports", not just conversational replies.`,
  fetch_instruction: null,
  required: true,
  order: 100,
});
```

Do not call `sections.sort()` again after this push — the goal is for `VOICE` to land as the literal last array element (maximum recency), exactly like the `runtime_context` block already does by not re-sorting after its own push.

```js
// test-s-arch-voice-01.mjs — S-ARCH-VOICE-01 (AA-127) verification (pure Node, no app imports)
const SUPABASE_URL = process.env.SUPABASE_URL;
const SUPABASE_SERVICE_KEY = process.env.SUPABASE_SERVICE_KEY;

let failures = 0;
function check(label, cond) {
  if (cond) { console.log(`PASS: ${label}`); }
  else { console.error(`FAIL: ${label}`); failures++; }
}

// ---- Category M-lite: cross-reference consistency (no stray "director" left anywhere it matters) ----
async function checkSupabase() {
  if (!SUPABASE_URL || !SUPABASE_SERVICE_KEY) {
    console.warn('SKIP: Supabase checks — SUPABASE_URL/SUPABASE_SERVICE_KEY not set');
    return;
  }
  const headers = { apikey: SUPABASE_SERVICE_KEY, Authorization: `Bearer ${SUPABASE_SERVICE_KEY}` };
  const slugs = ['qg-identity', 'qg-review-intent', 'reasoner-identity', 'ci-routing-intent', 'intake-failure-intent', 'hyp-hypothesis-test-intent'];

  for (const slug of slugs) {
    const res = await fetch(`${SUPABASE_URL}/rest/v1/skill_profiles?slug=eq.${slug}&select=slug,objective,method`, { headers });
    const [row] = await res.json();
    check(`${slug} exists`, !!row);
    const combined = `${row?.objective || ''} ${row?.method || ''}`;
    check(`${slug} has zero remaining "director" (case-insensitive)`, !/director/i.test(combined));
  }

  const priyaRes = await fetch(`${SUPABASE_URL}/rest/v1/skill_profiles?slug=eq.hyp-hypothesis-test-intent&select=objective`, { headers });
  const [priyaRow] = await priyaRes.json();
  check('hyp-hypothesis-test-intent objective instructs direct-address "consider" voice', /never in third person/i.test(priyaRow?.objective || ''));

  // Confirm no OTHER row picked up a stray edit
  const allRes = await fetch(`${SUPABASE_URL}/rest/v1/skill_profiles?objective=ilike.*director*&select=slug`, { headers });
  const allRows = await allRes.json();
  const methodRes = await fetch(`${SUPABASE_URL}/rest/v1/skill_profiles?method=ilike.*director*&select=slug`, { headers });
  const methodRows = await methodRes.json();
  check('zero skill_profiles rows anywhere still contain "director" in objective', allRows.length === 0);
  check('zero skill_profiles rows anywhere still contain "director" in method', methodRows.length === 0);
}

// ---- Category L (scoped): one live call proving the new VOICE section reaches a real model call
// and the renamed Priya row no longer produces third-person "director"/"the user should" framing.
// Scoped to ONE live round trip (STANDARDS.md Section 4's 2026-07-02 addendum) — this is the one
// genuinely novel path (the VOICE section has never existed before); Owen/Marcus/Sam/Reasoner's
// rows are the same rename pattern already proven live by S-MI-14, no incremental mechanism risk. ----
async function checkLiveCall() {
  const DEV_URL = process.env.DEEPBENCH_DEV_URL;
  if (!DEV_URL) { console.warn('SKIP: live capability call — DEEPBENCH_DEV_URL not set'); return; }
  const res = await fetch(`${DEV_URL}/api/capabilities/execute`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'x-vercel-protection-bypass': process.env.VERCEL_BYPASS || '' },
    body: JSON.stringify({
      capability_slug: 'hypothesis-evaluation', intent_slug: 'hyp-hypothesis-test-intent', agent_id: 'priya',
      task_context: { hypothesis: 'EMEA co-op budget should be reallocated toward digital channels for Q3.', intent: 'theory', flagged_question: '', flagged_answer: '', prior_stress_test: null },
      tenant_id: 'global',
    }),
  });
  const body = await res.json().catch(() => ({}));
  check('Live call returns 200', res.status === 200);
  check('Live call did not error', !body.error);
  const considerText = body?.final_delegation?.consider?.text || body?.consider?.text || '';
  check('Live "consider" text is non-empty', considerText.length > 0);
  check('Live "consider" text has zero "the director should" / "the user should" third-person framing', !/the (director|user) (should|may|will|would)/i.test(considerText));
}

await checkSupabase();
await checkLiveCall();

if (failures > 0) { console.error(`\n${failures} FAILURE(S)`); process.exit(1); }
console.log('\nALL TESTS PASS');
```
