### What is still inference, stated plainly so the next cycle does not inherit false confidence

This is the record's **fourth** confident ruling on the same question, and the previous three were each wrong. Three things are therefore labelled rather than asserted:

1. **No prompt has ever been directly captured.** John's testimony says he allowed permissions; it does not name which sessions, which prompts, or what the dialog said. The model is the best fit to seven observations, not a screenshot.
2. **`v7.0.115`'s 35-minute clearance has no identified clearer.** John was active in that window, but nobody recorded a tap on that prompt. It is explained by plausible inference, not testimony.
3. **`ba8f2ce3`'s fast Write/Edit calls are not ordered against his approval.** They may have been fast because they post-dated it, or because `Write`/`Edit` under `.claude/` never prompts at all. The record does not sequence them, and this cycle does not pretend otherwise.

### The strongest argument against what this ships

Stated because it is good, and because a rule shipped without its counter-case is how the last three flips happened. **A standing prohibition permanently exiles all `.claude/` skill and rule maintenance to scarce attended sessions — and that is precisely the drift this week demonstrated:** the `session-hygiene` skill has been telling every session to scan three files that have held zero ticket rows since `v7.0.113`, and it has stayed broken through five consecutive cycles that each declined to touch it. The prohibition guarantees more of that. Worse, it is being rebuilt on an inferred mechanism (above), and the confirming experiment is cheap — `SES-95`'s text is already written and pushed, so **one attended run settles it**, where a prohibition guarantees the platform never learns.

The counter-case is answered, not dismissed: the rule this cycle ships is **not** "never edit `.claude/`". It is "**an unattended** cycle never does". The edit stays legitimate work; it acquires a precondition — a human in the session — and `SES-95` is re-scoped to say so instead of being carded into silence.
