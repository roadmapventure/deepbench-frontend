# TASKS

**Task 1 — the function (migration `ses194_stall_watchdog`, not a repo file).**
`public.stall_watchdog(p_cycle_id uuid)` closes **one** open peer with no attributable write for **24 hours**, releases its `backlog_items` claims and any `runner_lease` it held, and returns `closed_cycle` / `frozen_hours` / `last_step` / `claims_released` / `lease_released`.

**The threshold is register B37's evidence bar, implemented and not widened** — *"a row may be closed `failed` by someone else only after 24h of no writes attributable to it… and the closing note must say what evidence was used."* The 20-minute tripwire **notifies**; the 24-hour bar **closes**. That gap is the design, not an oversight to tune away, and it is the single thing most likely to be edited by a later cycle that watches two peers sit frozen for two hours — which is exactly what this cycle watched, and correctly did nothing about.

Mechanics that are load-bearing: the guarded `UPDATE … WHERE id = … AND ended_at IS NULL` **is** the atomic claim, the same shape as `stall_notified_at`, so exactly one peer closes a given row; the before-image and the close sit in one subtransaction that rolls **both** back on a lost race, so §19v's *no before-image, no write* holds in both directions and a lost race leaves no stray ledger row; the lease release deliberately gets no before-image (register B42 — the lease is ledger state, its own columns are its audit trail); `ORDER BY started_at LIMIT 1` keeps the sweep self-limiting, the shape step 4b and step 8d already use.

**Task 2 — the resume guard (`docs/runbooks/runner-cycle.md`).**
The heartbeat statement becomes `UPDATE … WHERE id = '<your id>' AND ended_at IS NULL RETURNING id`, checked at **every** step boundary because a resume can land anywhere. **0 rows → abort cleanly:** no push, no counter claim, **no re-opening your own row** (the mirror image of what B37 forbids a successor doing to you), release any claim still held, push the session branch not `dev`, end. Same file gains the watchdog call in step 0b with the four properties above and an explicit *B37 is intact* clause — a sanctioned exception is how a prohibition gets read as lifted.

**Task 3 — the guard (`tests/regression/SES-194-stall-watchdog.js`).** Task 4 — QA + close-out + one batched push.
