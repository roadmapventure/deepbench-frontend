## 1. CONTEXT

Root-caused this design session, live-confirmed against Supabase (`ai_activity_log`, project `rallojeqnkgtxgsdsnqm`): John noticed the AI Audit screen's By-Pattern counts and costs looked implausible (RAG: 2,137 calls / $0.95; Structured Output: 1,948 calls / $7.15). Investigating why surfaced two separate findings:

**Finding 1 — Eleanor Voss's Librarian (`queryLibrary()`/`writeLibrary()`) never logs real cost.** 1,970 of the table's 7,738 rows (1,925 reads + 45 writes) are Librarian calls. Every one of them calls a real, billed OpenAI `text-embedding-3-small` embedding (`lib/vector-search.js`'s `embedText()`) before doing the actual vector search or write — but `logLibrarianCall()`/`logLibrarianWrite()` (`lib/librarian.js`) never include `model`, `input_tokens`, or `cost_usd` in their `ai_activity_log` insert. This is also why the "Embeddings" pattern shows "No calls yet" in the Architect Checklist tab despite real embedding calls happening on every single Data Room query — `embedText()` itself discards the token-usage figure OpenAI's own response already includes (`data.usage`), so there's nothing to log even if the write site wanted to.

**Finding 2 — there is no shared server-side logging function at all, contradicting a LOCKED architecture rule.** `docs/ARCHITECTURE.md` §12/§13 (both `[LOCKED]`) state: *"Every Layer 3 capability route logs to `ai_activity_log` via `logAICall()`. No exceptions — AI and deterministic alike."* In the real codebase this has never been true server-side. Grepped every `ai_activity_log` write site — there are 9 independent server-side call sites, each hand-rolling its own `fetch('.../ai_activity_log', ...)` with its own bespoke payload shape and its own `patterns_used` logic (`lib/project-manager.js`, `lib/librarian.js` ×2, `api/extract.js`, `api/capabilities/execute.js`, `api/prompt/request-receivable.js` ×2, `api/prompt/ai-enrichment.js` ×2). The only function actually named `logAICall()` is client-side only (`src/hooks/useAIActivity.js`), a different runtime that server code can't import. This absence of a single chokepoint is confirmed to already be causing live drift, not just a theoretical risk: `api/prompt/ai-enrichment.js:294` hardcodes `patterns_used: ['reflection']`, but `AI-50c` (yesterday, v6.2.28) renamed that catalog slug to `reflect` in `PATTERN_CATALOG` — nobody updated the write site, so every real, fully-costed Reflection call (18 rows, confirmed via direct query) has been silently invisible in the By Pattern section since that rename shipped.

**Decision (John's explicit go-ahead this design session):** fix the root cause, not just Librarian's symptom. Build one shared server-side logging primitive that Layer 3 routes call through — the missing half of the already-LOCKED §12/§13 rule — and migrate the single highest-volume, highest-risk consumer (Librarian) onto it as the first real proof. The remaining 8 write sites (including the `reflection`/`reflect` string fix, which lives in one of them) are deliberately out of scope for this session — see Section 6 — and are queued as explicit follow-up sessions in `docs/FEATURES.md` (see Section 9 close-out) so the sequence isn't lost between sessions.

**Cost computation itself is not part of this fix and does not need touching.** Confirmed this design session: `computeCallCost()` (`src/hooks/useAIActivity.js`) is already the single, correctly-centralized source of cost math, used consistently by every client-side consumer (`hydrateFromSupabase()`, `logAICall()`, `useAgents.js`'s `buildActivitySummary()`) and deliberately run at read time, not write time (`AA-181`'s design — no backfill migration needed). The bug this session fixes is upstream of pricing: if a write site never captures `input_tokens`/`model` in the first place, there is nothing for that one correct formula to price. This session's job is capture, not pricing.

### Task 1 — New file `lib/activity-log.js`: the shared `logActivity()` service

Create this file with exactly one exported function. Reads Supabase credentials from `process.env` itself (matches every existing write site's own pattern) so callers never need to thread `supabaseUrl`/`supabaseKey` through:

```js
// DeepBench v6.2.46 | lib/activity-log.js | AA-190 -- shared server-side ai_activity_log writer
// FEATURE: AA-190 -- closes the gap between ARCHITECTURE.md SS12/SS13 (LOCKED: "Every Layer 3
// capability route logs to ai_activity_log via logAICall(). No exceptions.") and reality: 9
// independent hand-rolled fetch() call sites existed server-side with no shared function at all,
// each with its own bespoke payload shape and patterns_used logic. This is the missing
// server-side half of that rule -- src/hooks/useAIActivity.js's logAICall() is the client-side
// half and is a separate runtime (cannot be imported here). Does NOT compute cost_usd -- cost
// stays computed at read time by the single existing computeCallCost() (useAIActivity.js,
// AA-181's design) from whatever input_tokens/output_tokens this function captures. This
// function's only job is making sure every site captures the same fields, consistently.
export function logActivity({
  tenantId = 'global',
  agentId = null,
  aiType,
  feature = null,
  model = null,
  inputTokens = null,
  outputTokens = null,
  latencyMs = null,
  taskId = null,
  knowledgeTier = null,
  patternsUsed = [],
}) {
  const supabaseUrl = process.env.SUPABASE_URL;
  const supabaseKey = process.env.SUPABASE_SERVICE_KEY;
  if (!supabaseUrl || !supabaseKey || !aiType) return;
  fetch(`${supabaseUrl}/rest/v1/ai_activity_log`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', apikey: supabaseKey, Authorization: `Bearer ${supabaseKey}`, Prefer: 'return=minimal' },
    body: JSON.stringify({
      tenant_id: tenantId,
      agent_id: agentId,
      ai_type: aiType,
      feature,
      model,
      input_tokens: inputTokens,
      output_tokens: outputTokens,
      latency_ms: latencyMs,
      task_id: taskId,
      knowledge_tier: knowledgeTier,
      patterns_used: patternsUsed.length > 0 ? patternsUsed : null,
      created_at: new Date().toISOString(),
    }),
  }).catch(() => {});
}
```

### Task 2 — `lib/vector-search.js`: capture and surface the OpenAI usage OpenAI already returns

**2a. `embedText()`** (currently returns just the raw `embedding` array) — return usage alongside it:

```js
async function embedText(text, openaiKey) {
  const res = await fetch('https://api.openai.com/v1/embeddings', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${openaiKey}` },
    body: JSON.stringify({ model: 'text-embedding-3-small', input: text }),
  });
  if (!res.ok) throw new Error('OpenAI embedding failed: ' + (await res.text()).slice(0, 200));
  const data = await res.json();
  const embedding = data.data?.[0]?.embedding;
  if (!embedding) throw new Error('No embedding returned from OpenAI');
  // FEATURE: AA-190 -- OpenAI's embeddings response already includes usage.total_tokens; this
  // was being discarded, the root cause of Librarian's calls carrying zero token/cost data.
  return { embedding, usage: data.usage || null };
}
```

**2b. `embedContent()`** — now a pass-through of the new `{ embedding, usage }` shape (was previously a pass-through of the raw array):

```js
export async function embedContent(text, openaiKey) {
  return embedText(text, openaiKey);
}
```

**2c. `embedAndSearch()`** — destructure the new shape from `embedText()`, thread `usage` through every return path (including the early-return/no-match paths, so a caller can still log the embedding cost even when the RPC search itself finds nothing):

```js
export async function embedAndSearch({ rpcName, queryText, dataRoomTag, tenantId, matchCount, supabaseUrl, supabaseKey, openaiKey, formatEntry, contextIntro }) {
  if (!queryText || !dataRoomTag) return { context: "", chunks: [], matchCount: 0, usage: null };
  const { embedding: queryEmbedding, usage } = await embedText(queryText, openaiKey);
  const rpcRes = await fetch(`${supabaseUrl}/rest/v1/rpc/${rpcName}`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', apikey: supabaseKey, Authorization: `Bearer ${supabaseKey}` },
    body: JSON.stringify({
      query_embedding: queryEmbedding, match_threshold: 0.3, match_count: matchCount,
      p_tenant_id: tenantId || 'global', p_data_room_tag: dataRoomTag,
    }),
  });
  if (!rpcRes.ok) return { context: "", chunks: [], matchCount: 0, usage };
  const matches = await rpcRes.json();
  if (!matches || matches.length === 0) return { context: "", chunks: [], matchCount: 0, usage };

  const contextLines = matches.map(formatEntry);
  const context = `${contextIntro}\n\n${contextLines.join("\n\n")}`;

  return {
    context,
    chunks: matches.map(m => ({ id: m.id, title: m.title || null, similarity: m.similarity, data_room_tag: m.data_room_tag })),
    matchCount: matches.length,
    usage,
  };
}
```

No other lines in this file change. `lib/search-harness.js` (the only other caller of `embedAndSearch()`) is unaffected — `usage` is an additive field, not a rename or removal of anything it currently reads.
