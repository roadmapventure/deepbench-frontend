## Tasks (≤ 4)

1. **Schema.** Apply migration `sesse_83a_backlog_items_schema` — creates
   `public.backlog_items` with the directive's column list, a CHECK constraint on
   `status IN ('done','partial','missing')`, a CHECK on `tier IN ('now','next','later')`,
   and — in the same migration — an explicit `REVOKE ALL PRIVILEGES ON TABLE
   public.backlog_items FROM anon, authenticated` (the `.claude/rules/supabase-column-grants.md`
   default-grant trap: newly created tables auto-grant broadly; a same-migration REVOKE is
   the only fail-closed guard). RLS off (there is no legitimate `anon`/`authenticated`
   access path — this is a service-key-only table).

2. **Parse `docs/FEATURES.md` into rows.** Node parser (scratchpad, not committed) that
   walks every markdown-table line matching `^\| [A-Z][A-Z0-9]*-[0-9]+ \|`. Table has
   five columns (ID, Type, Feature, Status, Session); descriptions carry embedded pipes
   (`LOG-82`, `LOG-104`), so parse by re-joining the middle when a row has >6 pipe
   segments. Extracts:
   - `backlog_id` = column 1 text.
   - `type` = column 2 text.
   - `title` = first bolded run of column 3, else first sentence, truncated to 240 chars.
   - `priority_class` = the leading `**P[1-9] - Name.**` marker if present, else NULL.
   - `description` = full column 3 text.
   - `status` (canonical, 3 values) — mapping:
     `✅ Done` → `done`; `✅ Shipped (SQL-only, via MCP)` → `done`;
     `➡️ Superseded (...)` → `done`; `🔶 Partial` → `partial`;
     `🔶 Duplicate (merge proposed)` → `partial`; `❌ Missing` → `missing`;
     `— N/A` → `missing`.
   - `session_ref` = column 5 text.
   - `harvest_link` = first `docs/harvests/*.md` reference in the description, else NULL.
   - `row_ordinal` = 1-based file position (stable ordering; disambiguates the two
     `CHI-48` rows that FEATURES.md deliberately carries — Data-type L139 vs UI-type L244,
     called out by `SES-30`'s duplicate-ID note).
   - Insert with `source_file = 'docs/FEATURES.md'`, `tier = 'now'`.

3. **Insert 277 rows** via `execute_sql` (chunked if the statement exceeds the MCP
   payload). No before-images: the table is new and empty — there are no prior row states
   to preserve.

4. **QA reconciliation (discriminating; would fail if the import did nothing).**
   - a) `select count(*) = 277` matches `grep -c '^| [A-Z]...' docs/FEATURES.md`.
   - b) `select backlog_id, count(*) from backlog_items group by 1 having count(*) > 1` =
     exactly one row, `CHI-48`, count 2 — matches the file's known duplicate.
   - c) Re-run the Node parser, re-map status → canonical, join to DB on
     `(source_file, row_ordinal)`: for every row, `db.status = parser.status_mapped`
     (this is the byte-for-byte reconciliation — file's raw status maps to stored
     canonical through the documented mapping, checked programmatically per row).
   - d) `select backlog_id, priority_class from backlog_items where priority_class is
     not null` = every row whose description starts with a `**P[1-9] - Name.**` marker,
     matched byte-for-byte against the same regex over the file.
   - e) `select privilege_type from information_schema.role_table_grants where table_name
     = 'backlog_items' and grantee in ('anon','authenticated')` = 0 rows — the SES-78a
     lesson enforced.
   - f) Discriminating check: if I dropped the REVOKE, (e) would return rows; if I
     mapped `⇢ Superseded` to `partial` instead of `done`, (c) would flag a
     mismatch. So the QA is real, not decorative.
