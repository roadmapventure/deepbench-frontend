## 2. CONTEXT

**Measured by the M6 milestone gate review (Chief Architect lens, 2026-09-02):** the claim (`runner-cycle.md` step 5; `session-setup.md` 2c) and the release (step-9 tail; 2c) both write `updated_at = now()` on `backlog_items`. `reverse_decision()` refuses any row whose live `updated_at` is later than the image it would restore from — the right guard against clobbering a later legitimate write — **and still returns `outcome = 'applied'`** with the row counted `refused`. So every decision that touched or filed a ticket becomes un-restorable the moment the continuous drain claims it (minutes, not days), and a reversed gate review would delete its drain and scope rows (no `updated_at`) while the claimed successor tickets survive: an epic with orphaned members and no drain. The runbook's 7b paragraph names this exact failure for the two-statement case and closes it with the one-`DO`-block rule; the claim write reopens it afterwards.

**Decided (M6-01):** (1) a claim or release is not a judgment write (7b's own definition) and stops touching `updated_at`; (2) `reverse_decision()` compares the live `updated_at` against the **decision's `decided_at`** — every write the decision made happened in that transaction, so `now()` was frozen at `decided_at`; anything strictly later is a genuinely later write — and reports the refusals that matter in their own counter and a new `outcome = 'partial'`; (3) the ses-286a guard grows an arm for the claimed-after-decision case.
