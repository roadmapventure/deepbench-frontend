## CONTEXT

Patch to `S-CHI-56` (v6.3.120), found during this design session's own mandatory live Category L verification — a real, reproduced bug, not a hypothetical.

**Root cause analysis (per `CLAUDE-DESIGN.md` Step 5c — required before any patch):** live-tested a second question after the first one succeeded. The second call hit a pre-existing, unrelated backend flake (`api/prompt/request-receivable.js`'s "Parse failed and retry also failed" — a long-documented retry-exhaustion path, confirmed by grep to predate this session, e.g. `S-ARCH-RETRY-CATCH-01`/`AA-151`; not caused by `CHI-56`). During that retried call, 4 real console errors fired: `FEATURE: CHI-07 — event type "delegation_complete" logged with no durationMs and is not declared non-measurable...`.

**The actual gap:** `lastEventAtRef` (`S-CHI-56`'s new ref tracking the previous delegation-family event's arrival time) is only ever updated inside `onDelegationProgress` itself — nothing seeds it at the start of a turn. `resolveDelegationDuration()` correctly returns `null` when `lastEventAtMs == null` (its own documented "first event, no prior tick to diff against" case) — but `buildHopEvent`'s pre-existing guard (`~L949-958`, unchanged by `CHI-56`, predates this session) treats **any** `null` `durationMs` for a type no longer in `NON_MEASURABLE_EVENT_TYPES` as an undeclared caller bug and logs the error. `delegation_complete`/`delegation`/`delegation_return` were removed from that set by `CHI-56` (correctly — they're measurable now), which means their legitimate first-tick `null` now trips a guard that used to never apply to them.

**Why this is a real gap, not just a cosmetic console-error fix:** a hop that resolves to `null` because it's genuinely the first delegation-family event with nothing to diff against still renders with **no time at all** in the Agent Routing drawer — directly violating this cluster's own hard requirement ("a hop is an instance that has work and time, no matter how brief," John, confirmed in the original `CHI-56` design conversation). Suppressing the console error alone would leave the missing-time problem unfixed.

**The fix:** seed `lastEventAtRef.current = turnStart` at the top of `submit()`, right where `turnStart` itself is already captured. Two things this fixes at once:
1. The first delegation-family event of *any* turn now always has a real reference point (the turn's own start) to diff against — no more `null`, no more console error, and a real, non-zero duration renders for it.
2. **Also fixes a subtler, not-yet-observed data-quality issue in the original `CHI-56` design:** without this seed, the first delegation-family event of a *new* turn would diff against whatever the *previous* turn's last delegation-family event was — silently folding the user's own between-questions think-time into that hop's reported duration. Seeding to `turnStart` makes every hop's duration mean "time from this question starting to this hand-off," the same honest semantic every other hop type already has, rather than an inflated, misleading number for the first delegation-family hop of every non-first question.

**Architect Review:** grepped for other callers of `onDelegationProgress`/`lastEventAtRef` before scoping this — `analyzeNewsCard()`/`fetchNewsCards()` also pass `onDelegationProgress` as their `onProgress` callback, but neither is in this session's or `CHI-56`'s scope (per `CHI-56`'s own SCOPE RULES, only `submit()`/`onGoodThanks()` were migrated). Those 2 flows keep today's actual behavior (a possible first-tick `null`/console-error on a very cold, first-ever-in-session news fetch) until Session 2 migrates them too — not silently expanding this patch's scope beyond the one flow that's actually broken and reproducible today.

## NODE.JS TEST

Full code, save as `test-chi-56-patch.mjs`, run with `node test-chi-56-patch.mjs`, delete before committing.

```js
// test-chi-56-patch.mjs — pure Node, mirrors the exact seed/diff logic (no app imports needed;
// resolveDelegationDuration's own real behavior is already covered by CHI-56's original test —
// this test proves the SEEDING behavior specifically: that a turn's first delegation-family event
// never hits the null/no-prior-tick case once lastEventAtRef is seeded to turnStart).

let pass = 0, fail = 0;
function assert(cond, label) {
  if (cond) { pass++; console.log(`PASS: ${label}`); }
  else { fail++; console.log(`FAIL: ${label}`); }
}

function resolveDelegationDuration(nowMs, lastEventAtMs) {
  if (lastEventAtMs == null) return null;
  return Math.max(0, nowMs - lastEventAtMs);
}

// --- Simulates submit()'s own sequence: turnStart captured, then seeded into lastEventAtRef ---
const turnStart = 1000;
let lastEventAtRef = { current: null };
lastEventAtRef.current = turnStart; // the patch's own one line

// --- First delegation-family event of the turn, arriving 250ms later ---
const firstTickAt = 1250;
const firstDuration = resolveDelegationDuration(firstTickAt, lastEventAtRef.current);
assert(firstDuration === 250, "first delegation-family event of a turn: real duration since turn start, not null");
lastEventAtRef.current = firstTickAt;

// --- Second event in the same turn, 400ms after the first (unaffected by the seed, same as before) ---
const secondTickAt = 1650;
const secondDuration = resolveDelegationDuration(secondTickAt, lastEventAtRef.current);
assert(secondDuration === 400, "second delegation-family event: still diffs against the previous event, unaffected by the seed");

// --- Without the seed (the pre-patch bug): first event has no prior tick, resolves null ---
const unseededRef = { current: null };
assert(resolveDelegationDuration(firstTickAt, unseededRef.current) === null, "confirms the bug this patch fixes: without seeding, the first event legitimately resolves null (which then trips buildHopEvent's undeclared-type guard)");

// --- Cross-turn think-time is no longer folded in: turn 2's first event diffs against turn 2's own start, not turn 1's last event ---
const turn2Start = 5000; // long after turn 1 ended -- if unseeded, a diff against turn 1's last tick (1650) would wrongly include ~3.35s of user think-time
lastEventAtRef.current = turn2Start; // patch's seed line, called again at the top of the next submit()
const turn2FirstTickAt = 5100;
assert(resolveDelegationDuration(turn2FirstTickAt, lastEventAtRef.current) === 100, "turn 2's first delegation-family event: duration measured from turn 2's own start (100ms), not inflated by think-time since turn 1's last event");

console.log(`\n${pass} PASS, ${fail} FAIL`);
if (fail > 0) { console.log("ALL TESTS PASS: NO — fix before committing"); process.exit(1); }
console.log("ALL TESTS PASS");
```
