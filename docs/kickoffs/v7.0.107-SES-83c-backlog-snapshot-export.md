## Why a snapshot at all (the value case, in John's terms)

`backlog_items` now holds all 553 open backlog tickets and is the thing every later automation
step reads. It lives in one Supabase project with **no repo-side copy** — `SES-81` already flagged
that backup gap. A generated markdown snapshot committed at each ship point gives three things
the table alone cannot: a git history of how the board changed cycle by cycle, an offline copy
readable without credentials, and a restore path if the table is ever lost or corrupted. It also
pre-pays for phases (d)/(e): the moment the files stop carrying tickets, this snapshot **is** the
git-history copy.

## Tasks (≤ 4)

1. **`scripts/export-backlog-snapshot.js`** — reads every `backlog_items` ticket through PostgREST
   with the service key (paginated, so a table that outgrows PostgREST's max-rows never truncates
   silently), emits one markdown document grouped by `tier` → `source_file`, ordered by
   `(source_file, row_ordinal)`. All 11 tracked fields per ticket, so the document restores the
   table rather than merely describing it. Flags: `--out=<path>`, `--check`, `--json`.
2. **Determinism.** Two runs against an unchanged table must produce **byte-identical** output, or
   the "commit it at every ship point" rule would spray meaningless diffs across git history and
   nobody would read them. So: no wall-clock timestamp in the body — provenance is the ticket
   counts plus a `sha256` of the payload, and git supplies the time. The script writes only when
   content actually changed and says so.
3. **Lossless cells.** 14 of the 553 descriptions contain a literal `|` (and `MOB-14` carries a
   whole malformed source row inside its description — a pre-existing `docs/FEATURES.md` artifact,
   preserved faithfully, not repaired here). Cells escape `\` then `|` then any newline, and the
   snapshot documents the inverse so a restore is mechanical.
4. **Runbook step + QA.** `docs/runbooks/runner-cycle.md` step 7 gains the export as part of the
   ship commit set. QA per the bar below.

## QA bar (discriminating — would it still pass if the change did nothing?)

- `node scripts/export-backlog-snapshot.js` against the **live** table writes 553 tickets; a
  second run reports `unchanged` and leaves the file byte-identical (`sha256` equal). If the
  script did nothing, there would be no file at all — and if it were non-deterministic, run two
  would rewrite.
- **Round-trip proof (the discriminating one):** a reader parses the generated file back into
  ticket objects and compares all 11 fields of all 553 tickets against a fresh PostgREST fetch.
  Zero mismatches means the snapshot is a restore, not a summary. A snapshot that dropped the
  escaped-pipe descriptions would fail exactly here — which is why the 14 pipe-carrying tickets
  are called out as a named sub-count in the evidence.
- `--check` after mutating the file by one character exits **1** (drift detected); `--check` on
  the clean file exits **0**. Without the mutation half, "exit 0" would prove nothing.
- Missing-env run exits **2**, distinct from drift's 1 — an unrunnable check must never read as a
  pass (`check-deploy-current.js` set this precedent).
- `npm install && npm run build` green; `tests/regression/run-all.js` green.
- Proof type: **LIVE** against the real table (the seam is the real PostgREST endpoint with the
  service key), not a fixture.
