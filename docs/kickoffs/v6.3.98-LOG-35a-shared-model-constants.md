## 2. CONTEXT

**Root cause:** every real Claude call site in this codebase declares its own model-name string literal independently — `api/brief.js`, `lib/agent-run.js`, `api/prompt/ai-enrichment.js`, `api/prompt/db-assembly.js`, `api/prompt/request-receivable.js`, `api/web-memory.js` all do this. `src/hooks/useAIActivity.js`'s `MODEL_ID_NORMALIZE` exists purely as a safety net for this — it maps known-stale strings back to canonical ones, which only works for drift someone has already noticed and added an entry for. Nothing structurally prevents the next file from writing a new stale literal.

**This session's fix:** one shared module holding the canonical values, so there's exactly one place to update when a model version changes — matches this repo's existing `shared/ai-patterns.js` precedent (a shared canonical-values module other files import from, not duplicate).

**Scope of this half (`a`):** create the shared module, and migrate the two files whose hardcoded values are already confirmed stale (`SES-010`'s `check-model-ids.js` first run, `LOG-35`'s own `docs/FEATURES.md` row) — `api/brief.js` (2 call sites) and `lib/agent-run.js` (`SONNET_MODEL`/`HAIKU_MODEL` constants + 2 docstring mentions). Both become canonical *and* stop being independently-typed literals, closing this exact drift class for these two files permanently, not just for today.

**Deliberately not migrated this session:** `api/prompt/ai-enrichment.js`, `api/prompt/db-assembly.js`, `api/prompt/request-receivable.js` — their current literals are already canonical (confirmed via `check-model-ids.js`, zero findings in those files), so migrating them isn't fixing a bug, it's a pure refactor with no correctness gain. Worth doing eventually for full consistency, but out of scope for a session whose job is fixing `LOG-35`'s actual findings — flagged as a natural follow-up, not logged as a new backlog ID (per John's standing call to skip ID bookkeeping for this class of internal-consistency cleanup).
