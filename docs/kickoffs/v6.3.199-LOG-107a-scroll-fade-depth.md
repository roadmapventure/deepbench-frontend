## 2. CONTEXT — why the shipped fade is literally invisible

John, looking at the deployed AI Audit panel: *"i don't see the gradient."* His screenshot shows the bouncing `⌄` chevron rendering correctly at the bottom edge — so the hint mounts and `canScrollMore` is true. Only the gradient is missing.

**Measured live on the deployed panel, not inferred:**

```
fade gradient : linear-gradient(transparent, rgb(248, 242, 226) 70%)
panel background:                            rgb(248, 242, 226)   // T.card
fade height   : 26px
```

The gradient fades to **exactly the colour it is painted on**. Over blank panel background it is a no-op; it only becomes perceptible where text physically scrolls beneath it. That works on the Channel Intelligence screen — dense, continuous prose is always passing under the edge — but this panel's drawers are bordered rows separated by gaps, so the bottom 26 px is usually empty `T.card`. Nothing to dissolve, nothing to see.

**This is not an opacity tweak.** A same-colour fade cannot signal depth over its own background at any strength. **John's call: a soft navy shadow.**

**Constraint that shapes the fix:** `ScrollFadeHint` is shared with `MarketIntelligenceScreen.jsx`, where the current look is correct and approved. The new treatment must be **opt-in and default-off**, so CHI renders byte-identically to today.

### Task 1 — `ScrollFadeHint` gains an opt-in depth variant (`src/components/SharedUI.jsx`)

**Purely additive.** Existing callers pass nothing new and must render exactly as before — same 26 px, same background-coloured gradient, same chevron.

```jsx
// FEATURE: LOG-107a -- `depth` variant. The default gradient fades to the caller's own background
// colour, which is invisible wherever that background is what sits behind it -- fine on CHI (dense
// prose is always dissolving under the edge) but a no-op on the AI Audit panel, whose bordered rows
// leave blank T.card in the last 26px (John: "i don't see the gradient"; measured: gradient fades to
// rgb(248,242,226) on a rgb(248,242,226) panel). `depth` instead darkens the edge with a soft navy,
// so it reads as "content continues under here" regardless of what is behind it. Opt-in and
// default-off: MarketIntelligenceScreen keeps its existing look untouched.
export const ScrollFadeHint = ({ show, bg, depth = false, height = undefined }) => !show ? null : (
  <div style={{
    position:"absolute",left:0,right:0,bottom:0,
    height: height ?? (depth ? 48 : 26),
    background: depth
      ? `linear-gradient(to bottom, ${T.navy}00, ${T.navy}1a)`
      : `linear-gradient(to bottom, transparent, ${bg} 70%)`,
    display:"flex",alignItems:"flex-end",justifyContent:"center",paddingBottom:2,pointerEvents:"none"}}>
    <span style={{fontFamily:mono,fontSize:10,color:T.brass,animation:"dbounce 1.4s ease-in-out infinite"}}>⌄</span>
  </div>
);
```

`T.navy` is `#12243c`; `${T.navy}00` is fully transparent navy and `${T.navy}1a` is ~10% — an 8-digit hex, same idiom `LOG-107` already used for the header hover tint (`${T.brass}0f`). Starting from transparent *navy* rather than the keyword `transparent` avoids the grey midpoint some engines interpolate toward when blending `transparent` with a colour.

**Do not change** the chevron, its animation, `pointerEvents`, positioning, or the default branch in any way.
