# 5. TASKS (1 total, 1 file: `src/screens/RosterScreen.jsx`)

### Task 1 — Add the scroll-hint overlay to the mobile filter chip row

- The mobile chip row (lines 259–284) currently renders as a single `<div style={{display:"flex",overflowX:"auto",...}}>` with no wrapping positioned container.
- Wrap it in a `position:"relative"` container, exactly matching `AboutPanel.jsx`'s structure:
  ```jsx
  {isMobile && (
    <div style={{position:"relative"}}>
      <div style={{display:"flex",overflowX:"auto",gap:6,paddingBottom:10,marginBottom:12,borderBottom:`1px dashed ${T.lineSoft}`}}>
        {/* existing navItems.map(...) chip buttons — unchanged */}
      </div>
      <div style={{position:"absolute",top:0,bottom:11,right:0,width:28,background:`linear-gradient(to right, transparent, ${T.paperDeep} 70%)`,display:"flex",alignItems:"center",justifyContent:"flex-end",paddingRight:3,pointerEvents:"none"}}>
        <span style={{fontFamily:mono,fontSize:10,color:T.brass}}>›</span>
      </div>
    </div>
  )}
  ```
- Only two values differ from `AboutPanel.jsx`'s original: the gradient's solid end-color (`T.paperDeep` — Roster's content column background — instead of `T.cardAlt`), and `bottom:11` instead of `bottom:1` (Roster's row has `marginBottom:12`/`paddingBottom:10` producing a taller row than the About panel's tab bar — the hint's vertical span should cover the chip row itself, not the `marginBottom` gap below it or the dashed border). Everything else (`width:28`, `pointerEvents:"none"`, the `›` chevron, its size/color) is copied verbatim from `SH-21`'s block — do not invent new values.
- Static, not scroll-position-aware — same as `SH-21`. Always renders when `isMobile` is true, regardless of whether the row actually overflows at a given viewport width (same accepted behavior as the About panel precedent).
