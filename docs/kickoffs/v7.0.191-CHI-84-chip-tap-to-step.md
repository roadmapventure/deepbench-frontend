## 4. TASKS (max 4)

### Task 1 — Hoist the scroll math into a shared helper (reuse, not a parallel copy)

Extract the element-scroll block inside `useDrawerStack`'s effect (~2198–2202: `querySelector('[data-drawer-key="..."]')` + `getBoundingClientRect` math + `scrollTo({behavior:"smooth"})`) into a module-scope helper, e.g. `scrollDrawerIntoView(container, key)` returning the element it scrolled to (or null). The hook calls the helper for its element branch; its `else { scrollTo top 0 }` branch stays in the hook unchanged. Behavior must be byte-identical for the existing auto-open path.

### Task 2 — The chip becomes a control; the jump signal lifts to the top level

- `StepChip` gains an optional `onTap` prop. When absent: exactly today's spans (drawer titles unchanged — assert visually identical). When present: render as a `<button>` (no default button chrome — `border:"none",background:"none",padding:0,cursor:"pointer"`, same inner spans), with hover state (local `useState`): number square background `T.brass` → `T.brassDeep`, label gains `textDecoration:"underline", textUnderlineOffset:2`. Colors from `src/tokens.js` only. Add an `aria-label` naming the step (`Jump to step ${n} ${label}`).
- Add `key` to each of the three `stepRef` constructors: `"hyp-candidates"`, `"hyp-result"`, `"hyp-draft"` (the same string each drawer already uses as `scrollKey`).
- Top-level screen component: `const [stepJump, setStepJump] = useState(null)` and `const onStepChipTap = (key) => setStepJump(prev => ({ key, seq: (prev?.seq ?? 0) + 1 }))` — `seq` makes a repeat tap on the same chip a fresh signal. Thread `onStepChipTap` → `InteractColumn` (both desktop and mobile-bare instances) → `MessageBubble`; the bubble's chip (~1934) passes `onTap={() => onStepChipTap(msg.stepRef.key)}` **only when `msg.stepRef.key` exists** (older messages persisted without `key` render as today's inert chip — never a crash).

### Task 3 — Desktop jump effect in EvidenceColumn (open + scroll + pulse, then consume)

`EvidenceColumn` gains props `stepJump` and `onStepJumpConsumed`. New effect on `[stepJump]`:
1. If `stepJump == null`, return.
2. `handleDrawerToggle(stepJump.key)(true)` — the existing manual-open path.
3. In a `setTimeout(..., 0)` (**never `requestAnimationFrame`** — the QA browser pane runs `document.hidden` and rAF freezes there; a timer fires regardless): call `scrollDrawerIntoView(evidenceScrollRef.current, stepJump.key)`, and on the returned element apply the landing pulse: `el.style.animation = "borderPulse 1.4s ease-in-out 1"`, cleared on a one-shot `animationend` listener. `borderPulse` already exists in `GLOBAL_CSS` (`src/tokens.js`) — reuse it, do not add a keyframe.
4. Call `onStepJumpConsumed()` (top level sets `stepJump` back to `null`). Consumption is what prevents a re-jump when the mobile `EvidenceColumn` remounts on a later tab switch.

### Task 4 — Mobile wiring + Node test

- `MobileBody` receives `stepJump` and, in an effect on `[stepJump]`, calls its existing `selectTab("evidence")` when `stepJump != null` (use `selectTab`, not `setMobileTab` directly, so the unseen-flash bookkeeping behaves as a real tab press).
