## 2. CONTEXT

Two bugs John found live-walking the desktop Market Intelligence screen (Column 2 = `EvidenceColumn`, the "Theory Evidence" panel):

**MI-54 — Column 2 grows past the fold.** `InteractColumn` (Column 1) wraps its content in a card with `flex:1, minHeight:0` and an inner `overflowY:"auto"` scroll region (lines 1342/1352) — the card's height matches the grid row, only messages scroll internally. `EvidenceColumn` (Column 2, line 849) has no such wrapper: once a theory flow is active, its content (submitted hypothesis, Priya's test result, key data points, the Discard/Track/Make-Permanent buttons, and the confirmation card) just stacks and grows the whole page. The action buttons end up below the fold along with everything else.

**MI-53 — Nadia's confirmation card shows raw markdown.** Traced the root cause (see design-session transcript): `data-patch-intent`'s Skill Profile has `requires_human_confirmation: true` but, unlike `ci-answer-intent`/`hyp-hypothesis-test-intent`, has no paired `*-display-intent` — it was never given the real Display-Agent hand-off (`request_help` → Michelle's `agent-selection-intent` → `delegate_to_agent(is_final:true)`) that `ci-answer-display-intent`/`hyp-hypothesis-test-display-intent` already provide for Marcus's and Priya's cards. So `ConfirmationCard` (`SharedUI.jsx`) renders Nadia's raw tool-call output — `proposed_action.content`, which is free-text prose containing `**bold**` markdown — through a fully generic `Object.entries(proposedAction).map(...String(v))` dump with zero markdown handling. This is a direct violation of the locked rule at `ARCHITECTURE.md` §19 rule 14/15 ("Display agents are the single source of truth for all presentation output") that was never closed when `MI-01d` first built the generic confirmation gate — `requires_human_confirmation` predates the Display-Agent-hop pattern entirely.

**Fix direction (John's explicit call, 2026-07-14 design session): wire the same real Display-Agent hop onto `data-patch-intent`'s confirmation flow that `ci-answer-intent`/`hyp-hypothesis-test-intent` already have** — not a frontend markdown parser patch. This is additive: a new `data-patch-display-intent` trigger intent (mirrors `ci-answer-display-intent`/`hyp-hypothesis-test-display-intent` exactly — `schema: null, can_request_help: true, delegation_required: true`) and a new `data-patch-review-format` Format Skill on Alex Reeves (mirrors `qa-answer-format`, minus the citations/needs_review fields that don't apply to a correction-review recommendation). Michelle reasons over real candidates same as always — nothing hardcoded.

**Orchestration lives in the frontend, matching existing precedent exactly** — `runQaWithQualityGate()`/`runHypothesisTest()` both make two sequential `callCapability()` calls (content, then display) from the screen itself; `execute.js`'s generic `requiresHumanConfirmation` branch is not modified, so every other current/future confirmation-gated capability is unaffected by this session.

```jsx
// FEATURE: MI-53 — real Display-Agent hop for Nadia's pending_confirmation proposal, same
// request_help -> Michelle -> delegate_to_agent(is_final:true) pattern as ci-answer-display-intent/
// hyp-hypothesis-test-display-intent. Mirrors those two call sites' AA-137 string-decline fallback
// exactly -- a real "I won't format this" decline must still render, never a blank card.
async function formatDataPatchProposal(proposedAction, onProgress) {
  const display = await callCapability({
    capability_slug: "data-analysis", intent_slug: "data-patch-display-intent", agent_id: "nadia",
    task_context: {
      action: proposedAction?.action ?? null,
      content: proposedAction?.content ?? null,
      confidence: proposedAction?.confidence ?? null,
      version_note: proposedAction?.version_note ?? null,
    },
    onProgress,
  });
  if (typeof display === "string" || typeof display.content === "string") {
    const rawText = typeof display === "string" ? display : display.content;
    return {
      headline: null, body: [{ text: rawText }],
      displayAgentCard: typeof display === "string" ? null : display.display_agent_card,
      displayAgentId: typeof display === "string" ? null : display.display_agent_id,
    };
  }
  return {
    headline: display.headline, body: display.body,
    displayAgentCard: display.display_agent_card, displayAgentId: display.display_agent_id,
  };
}
```
