## 1. CONTEXT

`AI-50` (found 2026-07-14, `MI-52`'s design session): neither the AI Audit screen's "By Pattern" view (`useAIActivity.js`'s `byPattern`) nor the MI screen's Agent Routing subline reflect real per-call pattern usage — both are static rollups from `SERVICE_CATALOG`'s hand-tagged, per-*service* pattern lists (e.g. every `channel-intelligence` call is credited with all 5 of that service's tags — Structured Output, RAG, Case-Based Reasoning, Agent Delegation, Streaming — whether or not that specific call used any of them). John confirmed live this makes `byPattern`'s bucket-cost sum ~3x the real Total Cost ($62.10 vs $21.03 at the time of that check) and asked to fix it for real, not just cosmetically.

**The real, per-call data already exists** — `skill_profiles.technical_services` (jsonb) is a live, already-populated-for-many-rows column declaring which AI patterns a specific **Intent**-type Skill Profile actually uses (confirmed live: `ci-answer-intent` → `["rag","structured-output"]`, `ci-routing-intent` → `["structured-output"]` — genuinely different per intent, unlike the coarse per-service tags). `db-assembly.js`'s `assemblePrompt()` already filters `skillProfiles` down to exactly the one matching Intent-type row when `intent_slug` is passed (confirmed at the existing `if (intentSlug) { ... skillProfiles = skillProfiles.filter(...) }` gate) — the data is one field away from being surfaced, it's just never read out of that row today.

**This session (AI-50a) threads that already-loaded data through the existing call chain into `ai_activity_log.patterns_used`.** No schema change (`patterns_used` already exists), no new Supabase query (the Skill Profile row is already fetched). Two more sessions follow, not part of this one:
- **AI-50b (content pass):** populate `technical_services` for the 5 real Intent-type Skill Profiles still empty (`agent-selection-intent`, `ci-answer-display-intent`, `hyp-generation-intent`, `hyp-hypothesis-test-display-intent`, `hyp-hypothesis-test-intent`) — a domain-judgment task, not code.
- **AI-50c (frontend consumers):** rewrite `useAIActivity.js`'s `byPattern` and `MarketIntelligenceScreen.jsx`'s hand-duplicated `SERVICE_LABEL` to read the now-real `patterns_used` per row instead of the static `SERVICE_CATALOG`/`SERVICE_LABEL` rollups — splitting each call's cost evenly across however many real patterns *that specific call* used (John's explicit call: real multi-pattern attribution, cost divided evenly across genuinely-simultaneous patterns, so bucket sums reconcile exactly to Total Cost). Also fixes two catalog gaps found this session: `PATTERN_CATALOG`'s `'reflection'` slug doesn't match the real data value `'reflect'`, and `"intelligent-synthesis"` (a real `technical_services` value on `prompt-synthesis`) has no `PATTERN_CATALOG` entry at all.

**Known, deliberate scope boundary — not fixed in AI-50a/b/c:** `execute.js`'s `resumeCapability()` (checkpoint/resume path for long delegation chains) reconstructs its own `enriched` object by hand from a persisted `durable_hops` row (`{ system_prompt, format_contract, llm }` only) instead of re-running `enrichPrompt()` — so a **resumed** call will fall back to mechanical-only pattern detection (`buildPatternsUsed()`), missing the intent's declared `technical_services`, until `durable_hops` also persists this field. Real gap, out of scope here (would add a schema/migration question); flagged for a future session, not silently ignored.

**Why this session doesn't touch `execute.js` at all:** `execute.js`'s `sendRequest()` call already passes the *entire* `enriched` object as `prompt_request` (`sendRequest({ prompt_request: enriched, ... })`). Once `ai-enrichment.js`'s `enrichPrompt()` includes the new field in what it returns, it rides through to `request-receivable.js` automatically — no call-site change needed. (This shrank the session from the 4-file exception John approved down to 3 files; noting the change since he explicitly signed off on the bundle before this deeper trace.)

## 7. NODE.JS TEST

Save as `test-AI-50a.mjs` at the repo root, run with `node test-AI-50a.mjs`, then delete the file.

```js
import { buildSections } from './api/prompt/db-assembly.js';
import { buildPatternsUsed } from './api/prompt/request-receivable.js';

let failures = 0;
function assertDeepEqual(actual, expected, label) {
  const a = JSON.stringify([...actual].sort());
  const e = JSON.stringify([...expected].sort());
  if (a !== e) {
    failures++;
    console.error(`FAIL: ${label} — expected ${e}, got ${a}`);
  } else {
    console.log(`PASS: ${label}`);
  }
}

// --- buildSections(): intentTechnicalServices capture ---

const baseSkillProfiles = [
  { skill_type_slug: 'identity', slug: 'ci-identity', traits: {} },
  { skill_type_slug: 'intent', slug: 'ci-answer-intent', traits: {}, technical_services: ['rag', 'structured-output'] },
];

const matched = buildSections(baseSkillProfiles, 'marcus', [], null, 'ci-answer-intent');
assertDeepEqual(matched.intentTechnicalServices, ['rag', 'structured-output'], 'buildSections: captures the matched intent\'s technical_services');

// Wrong intent_slug passed (doesn't match the intent row present) -- must NOT pick it up
const unmatched = buildSections(baseSkillProfiles, 'marcus', [], null, 'ci-routing-intent');
assertDeepEqual(unmatched.intentTechnicalServices, [], 'buildSections: does not capture technical_services for a non-matching intent_slug');

// No intent_slug passed at all -- must default to empty, not throw
const noIntentSlug = buildSections(baseSkillProfiles, 'marcus', [], null, null);
assertDeepEqual(noIntentSlug.intentTechnicalServices, [], 'buildSections: no intent_slug passed defaults to []');

// Intent row with technical_services missing/null (unpopulated Skill Profile, e.g. AI-50b's gap list) -- must default to [], not throw
const emptyTechServices = buildSections(
  [{ skill_type_slug: 'intent', slug: 'hyp-generation-intent', traits: {}, technical_services: null }],
  'priya', [], null, 'hyp-generation-intent'
);
assertDeepEqual(emptyTechServices.intentTechnicalServices, [], 'buildSections: null technical_services on the matched intent defaults to []');

// --- buildPatternsUsed() merge (the request-receivable.js call-site logic) ---

function mergePatterns(isJson, guardrailsRan, delegationOccurred, intentTechnicalServices) {
  return Array.from(new Set([
    ...buildPatternsUsed(isJson, guardrailsRan, delegationOccurred),
    ...intentTechnicalServices,
  ]));
}

assertDeepEqual(
  mergePatterns(true, false, false, ['rag', 'structured-output']),
  ['structured-output', 'tool-use', 'rag'],
  'merge: mechanical (isJson) + real intent patterns, deduped (structured-output appears once)'
);
assertDeepEqual(
  mergePatterns(false, true, true, []),
  ['prompt-chaining', 'guardrails', 'agent-delegation'],
  'merge: real patterns empty (unpopulated Skill Profile) falls back to mechanical detection only'
);
assertDeepEqual(
  mergePatterns(false, false, false, []),
  [],
  'merge: nothing fired, nothing declared -- empty array, not null/undefined'
);

if (failures > 0) {
  console.error(`\n${failures} test(s) FAILED`);
  process.exit(1);
} else {
  console.log('\nALL TESTS PASS');
}
```
