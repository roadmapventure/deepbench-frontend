## CONTEXT

`S-ARCH-VIZ-01` built and live-proved the generic visualization mechanism: Alex's `intelligence-review-format` schema now optionally returns `visualization: {chart_type, chart_data, caption}`, reasoned per call, and `ChartRenderer`/`CHART_RENDERERS` exist in `SharedUI.jsx` — but nothing calls them yet. This session is the first concrete consumer: `EvidenceColumn` (Column 2 of the Market Intelligence screen) swaps its old hardcoded plain-text `projected_state` block for one generic `<ChartRenderer/>` call.

**This is not a hardcoded chart component.** The line this session adds to `EvidenceColumn` doesn't know or care that the data came from a Stress Test — it renders whatever `chart_type`/`chart_data`/`caption` the schema returned, exactly as any other future screen consuming any other capability's `visualization` output would. The only thing specific to this screen is that it's the first place in the codebase to actually call the shared renderer.

**Also closes out the schema migration `S-ARCH-VIZ-01` deliberately left incomplete:** `projected_state` stays required in the live schema until this session, because `EvidenceColumn` was still its only reader. This session removes it from the schema (Task 2) in the same session it stops being read (Task 1) — no window where the two are out of sync.
