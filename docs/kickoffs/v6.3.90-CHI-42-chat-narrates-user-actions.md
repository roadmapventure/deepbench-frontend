## CONTEXT

First of a 5-item cluster (`CHI-42`–`CHI-46`) found during a live screenshot walkthrough of the Apple 36-month-financing chat chain (`design-evidence-drawers-0721`, John, 2026-07-21) — 10 numbered UX gaps in `MarketIntelligenceScreen.jsx`'s Chat/Evidence interaction loop. This is the smallest, independently-shippable piece; `CHI-43`–`46` (Evidence Column drawer-stack, auto-advance theory test, hop-badge relocation, news-card drawers) are separate future kickoffs that build on top of this one but do not depend on it landing first.

**The problem:** Chat (`InteractColumn`/`MessageBubble`) only ever narrates an agent's *eventual* response — e.g. `onResolveConfirmation`'s existing ack ("Got it — that's been stored as a forecast," pushed via `setMessages` only after `resolveConfirmation()` resolves). There is no feedback at the *moment the user clicks* — e.g. clicking "Store as Forecast" (`onCommit`) produces zero chat feedback for the entire multi-second Elena→Nadia async chain. This reads as the app not acknowledging the user's own action.

**The fix:** a new bubble type — pushed synchronously, before any network call, at each of six existing user-decision points. Confirmed live with John, in order:
1. Right-aligned, labeled "You" — same alignment/label mechanics as real typed input (`STYLE-GUIDE.md` §36's existing "You" rule), so it reads as part of the same visual family.
2. **Not** solid `T.navy` (that's reserved for real typed input) — fill is `T.navyMid`, an already-existing, already-reused lighter-navy token. No new color.
3. **Not** `role:"user"` — a new `kind:"user_action"` instead. This is a real, mechanically-confirmed bug avoidance, not just taxonomy: `conversationContext()` (L2993–2994) builds `` `${m.role}: ${m.text}` `` for *every* message with string `text`, with no other filter, and feeds it as `runtime_context` into Marcus's own next prompt (`runQaWithQualityGate`/`runIntentPipeline`). A `role:"user"` narration bubble would get replayed into Marcus's own conversation history as fabricated user speech the user never actually typed. `kind:"user_action"` messages must be excluded from `conversationContext()`'s filter.
4. **Confirmed scope (John, "go with A")**: this session does *not* change what already happens after the click — Marcus's existing async acks (with their hop badge + elapsed time) are completely unchanged. The only change is the new instant bubble landing *before* them. No new "patch a message in place once its work resolves" mechanism — that idea (Option B) was explicitly not chosen.

Full exact copy for all nine action points (six handlers, three of which branch) confirmed live with John below (Task 2).

// test-chi-42.mjs — pure Node, no app imports. Reimplements the exact pure logic this session
// ships (isUser derivation, background-color selection, conversationContext's filter) so it can

let pass = 0, fail = 0;
function assert(cond, label) {
  if (cond) { pass++; console.log(`PASS: ${label}`); }
  else { fail++; console.log(`FAIL: ${label}`); }
}

// --- Mirrors of the real logic this session changes ---
function isUserFor(msg) {
  return msg.role === "user" || msg.kind === "user_action";
}
function backgroundFor(msg, T) {
  const isUser = isUserFor(msg);
  if (msg.kind === "user_action") return T.navyMid;
  if (isUser) return T.navy;
  return msg.needs_review ? "#f3e6cc" : T.card;
}
function conversationContext(messages) {
  return messages.filter(m => typeof m.text === "string" && m.kind !== "user_action")
    .map(m => `${m.role}: ${m.text}`).join("\n");
}
const T = { navy: "#12243c", navyMid: "#1a2e4a", card: "#fdfbf6" };

// --- Category A/B: isUser/background derivation for all 4 real message shapes ---

}
{
  assert(backgroundFor({ role: "user" }, T) === T.navy, "real typed input renders solid navy");
  assert(backgroundFor({ role: "assistant", kind: "user_action" }, T) === T.navyMid, "user_action bubble renders navyMid, not solid navy");
  assert(backgroundFor({ role: "assistant", kind: "non_qa" }, T) === T.card, "Marcus ack renders T.card, unaffected by this session");
}

// --- Category C: conversationContext() exclusion — the core bug this session prevents ---
{
  const messages = [
