## 2. CONTEXT — the QA failure and its confirmed root cause

`LOG-98` shipped and its shimmer skeletons, gated empty states, and rolling counters all work. **But live QA on the deployed preview found the header tiles frozen on fabricated values and never resolving:** Total Calls `917`, Total Cost `$1,100.00`, Patterns Logged `668`, Models in Use `398`, Services `0`, Active Agents `0` — all stable across repeated samples seconds apart, while the real values are 22,536 / ~$140 / 6 / 3 / 31 / 22.

**Root cause, confirmed by direct probe, not inferred:** `document.hidden === true` and `requestAnimationFrame` never fires in that state (probe: a `requestAnimationFrame` callback did not run within 1200 ms while `document.visibilityState === 'hidden'`). `RollingNumber`'s reveal phase is driven **solely** by `requestAnimationFrame`, and it is the only code path that sets `revealed = true` / `display = target`. With no frames:

- the rolling `setInterval` (timers are not frame-gated) runs while `loading` is true and leaves `display` at some pseudo-random value;
- `loading` flips false, the interval is cleaned up;
- the reveal never runs, so `revealed` stays `false` and the render falls to `format(display)` — the frozen fake number, permanently.

Browsers throttle/suspend `rAF` for backgrounded, minimized, or occluded tabs. So this is **not only a harness artifact**: a real user who opens AI Audit and switches tabs while it loads returns to invented numbers presented as real data — strictly worse than the false zeros `LOG-98` set out to remove. The animation may be decorative; **arriving at the true value must not be.**

## 5. TASKS (1)

### Task 1 — Make the reveal frame-independent (`src/components/AIActivityPanel.jsx`, `RollingNumber` only)

Add a timer-based backstop that locks the true value even when no frames are delivered, and make the non-revealed render path safe. Replace the reveal effect and the render tail with:

```jsx
  // Reveal phase — one ease-out count-up from 0 to the real value, then lock.
  // FEATURE: LOG-98a -- requestAnimationFrame is suspended for hidden/backgrounded/occluded tabs,
  // and rAF was previously the ONLY path that set the final value, so a panel that finished loading
  // while the tab was hidden froze forever on a fabricated rolling number displayed as real data
  // (confirmed live: document.hidden === true, no rAF callback within 1200ms). The animation is
  // decorative; landing on the true value is not. This timer fires regardless of frames and is the
  // authoritative finish; the rAF loop only smooths the way there.
  useEffect(() => {
    if (loading || reduced || revealed) return;
    const target = Number(value) || 0;
    const DURATION = 600;
    const start = performance.now();
    let raf;
    const step = now => {
      const t = Math.min(1, (now - start) / DURATION);
      const eased = 1 - Math.pow(1 - t, 3);
      setDisplay(target * eased);
      if (t < 1) raf = requestAnimationFrame(step);
      else { setDisplay(target); setRevealed(true); }
    };
    raf = requestAnimationFrame(step);
    const backstop = setTimeout(() => { setDisplay(target); setRevealed(true); }, DURATION + 150);
    return () => { cancelAnimationFrame(raf); clearTimeout(backstop); };
  }, [loading, reduced, revealed, value]);

  if (reduced) return <>{loading ? "—" : format(Number(value) || 0)}</>;
  if (loading) return <span style={{opacity:0.75}}>{format(display)}</span>;
  // FEATURE: LOG-98a -- second guard for the same failure class: once loading is over, a
  // not-yet-revealed tile shows the mid-animation `display` only while it is still plausibly
  // animating. `display` is never allowed to outlive the reveal window as the visible value.
  return <>{format(revealed ? Number(value) || 0 : display)}</>;
```

The only functional change is the `backstop` timer plus its cleanup. Do **not** alter the rolling phase, the `reduced` branch, the tile array, the skeletons, or anything else from `LOG-98`.

Update the file's version-header comment block (new top line: `// DeepBench v6.3.189 | AIActivityPanel.jsx | LOG-98a -- RollingNumber reveal no longer depends on requestAnimationFrame (hidden tabs froze tiles on fabricated values)`).
