## 2. CONTEXT

The Column 3 "Agents" drawer (`AuditColumn`, `RO`/`MI-18`/`MI-31` lineage) shows each active agent's per-kind latency breakdown: a "Baseline" rollup row first, then one row per `stats.byKind` entry (already sorted descending by `avgLatency`, `MI-31`), then indented per-model sub-rows when a kind used more than one model (`AA-149`).

Every row today uses `justifyContent:"space-between"`, which right-justifies the whole value string against the drawer's right edge. John's finding (2026-07-09, live on the real Column 3): this is hard to read because the value strings have different lengths ("12.3s avg (5 calls, max 18.2s)" vs "6.1s avg (3 calls)"), so being flush against the same right edge does **not** line up the leading number between rows — the "6" in a 6-second row doesn't sit under the "2" in a 12-second row above it, even though both are single-decimal seconds values.

**Approved design (mockup reviewed and confirmed by John):**
- Move the value block to sit left-justified, immediately after a **fixed-width label column** (not flush against the drawer's right edge).
- Render the leading number in its own **fixed-width, right-aligned box** — this is what actually makes the decimal point (and therefore the units digit) land in the same horizontal position on every row, regardless of whether the number is 1 or 2 digits before the decimal.
- Long labels (e.g. a full `formatKindLabel()` output, or a long model name in the `AA-149` sub-rows) truncate with an ellipsis rather than widening the column — approved by John over wrapping or widening.
- Apply the same treatment to all three row types: Baseline, byKind, and the `AA-149` per-model sub-rows.

**Measured real values (live-checked against the actual dev build, 1280px viewport, this worktree):** the drawer's row content width is ~319px. A real label already in production data, "Data Room Custody" (18 chars), measures ~92px in the row's 9px mono font. Some `formatKindLabel()` outputs run longer (e.g. a hyphenated multi-word intent slug) and will legitimately truncate — expected and approved, not a bug.

```js
// FEATURE: MI-43 — shared row renderer for the Agents drawer's per-agent latency stats
// (Baseline, byKind, AA-149 byModel sub-rows). Fixed-width label column (ellipsis-truncated)
// + fixed-width right-aligned leading number is what makes the decimal point/units digit land
// in the same horizontal position across rows, regardless of label length or 1-vs-2-digit
// seconds values — replaces the old justifyContent:"space-between" full-string right-justify,
// which right-aligned the whole string and never actually lined up the numbers (John, 2026-07-09).
function LatencyStatRow({ label, valueNumber, restText, indent, fontSize }) {
  return (
    <div style={{display:"flex",gap:6,fontFamily:mono,fontSize:fontSize ?? 9,color:indent?T.mutedDeep:T.muted,paddingLeft:indent?10:0}}>
      <span style={{width:110,flexShrink:0,whiteSpace:"nowrap",overflow:"hidden",textOverflow:"ellipsis"}}>{label}</span>
      <span style={{display:"flex",color:T.navy,fontWeight:700}}>
        <span style={{display:"inline-block",minWidth:34,textAlign:"right",flexShrink:0}}>{valueNumber}</span>
        <span>{restText}</span>
      </span>
    </div>
  );
}
```

## 6. DESIGN RULES

- Label column: `width:110px`, `flexShrink:0`, `whiteSpace:"nowrap"`, `overflow:"hidden"`, `textOverflow:"ellipsis"` — truncates long labels/model names, does not wrap or push the value column
- Number box: `display:"inline-block"`, `minWidth:34px`, `textAlign:"right"`, `flexShrink:0` — `minWidth` (not fixed `width`) so a rare 3-digit-second value doesn't clip, it just grows past 34px
- Row gap (label-to-value): `gap:6px` (was `gap:8` under the old `space-between` layout — kept close, not a meaningful visual change)
- Colors, font, font-size, indent, and border/spacing on the outer rows are unchanged: `T.muted`/`T.mutedDeep` for labels, `T.navy`/`fontWeight:700` for values, `mono` font family, 9px top-level / 8px sub-row, `paddingLeft:10` on sub-rows — all preserved via `LatencyStatRow`'s `indent`/`fontSize` props
- Do not change the existing descending-avgLatency sort on `byKind` or `byModel` — already correct, out of scope for this session

## 8. NODE.JS TEST

```js
// test-S-MI-43.mjs
// Tests the row value-string computation in isolation — no app imports.
// Mirrors LatencyStatRow's caller-side formatting exactly (Category C: string
// safety on potentially-null avgLatency).

function baselineRow(baseline) {
  return {
    valueNumber: (baseline.avgLatency/1000).toFixed(1),
    restText: `s avg (${baseline.calls} call${baseline.calls === 1 ? "" : "s"}, max ${(baseline.maxLatency/1000).toFixed(1)}s)`,
  };
}

function byKindRow(k) {
  return {
    valueNumber: k.avgLatency != null ? (k.avgLatency/1000).toFixed(1) : "—",
    restText: `${k.avgLatency != null ? "s avg" : ""} (${k.calls} call${k.calls === 1 ? "" : "s"}${k.latencyCount > 1 ? `, max ${(k.maxLatency/1000).toFixed(1)}s` : ""})`,
  };
}

function byModelRow(km) {
  return {
    valueNumber: km.avgLatency != null ? (km.avgLatency/1000).toFixed(1) : "—",
    restText: `${km.avgLatency != null ? "s avg" : ""} (${km.calls} call${km.calls === 1 ? "" : "s"})`,
  };
}

let pass = 0;
let fail = 0;

function assert(desc, cond) {
  if (cond) { console.log(`  ✓ ${desc}`); pass++; }
  else       { console.error(`  ✗ ${desc}`); fail++; }
}

// T1: baseline row — matches pre-existing text exactly (regression check)
{
  const r = baselineRow({ avgLatency: 12300, calls: 5, maxLatency: 18200 });
  assert('T1a: valueNumber is "12.3"', r.valueNumber === "12.3");
  assert('T1b: restText matches old combined string tail', r.restText === "s avg (5 calls, max 18.2s)");
}

// T2: baseline singular call
{
  const r = baselineRow({ avgLatency: 2600, calls: 1, maxLatency: 4300 });
  assert('T2: singular "call" (not "calls")', r.restText === "s avg (1 call, max 4.3s)");
}

// T3: byKind row — normal case, single model (no ", max" suffix since latencyCount not > 1)
{
  const r = byKindRow({ avgLatency: 6100, calls: 3, latencyCount: 1, maxLatency: 6100 });
  assert('T3a: valueNumber is "6.1"', r.valueNumber === "6.1");
  assert('T3b: restText has no max clause', r.restText === "s avg (3 calls)");
}

// T4: byKind row — multiple latency samples, includes max clause
{
  const r = byKindRow({ avgLatency: 10000, calls: 80, latencyCount: 80, maxLatency: 49700 });
  assert('T4: restText includes max clause', r.restText === "s avg (80 calls, max 49.7s)");
}

// T5: byKind row — null avgLatency (Category C: string safety on undefined/null)
{
  const r = byKindRow({ avgLatency: null, calls: 2, latencyCount: 0, maxLatency: 0 });
  assert('T5a: valueNumber is em-dash placeholder', r.valueNumber === "—");
  assert('T5b: restText has no "s avg" prefix, calls text still present', r.restText === " (2 calls)");
}

// T6: byModel sub-row — normal case
{
  const r = byModelRow({ avgLatency: 19500, calls: 15 });
  assert('T6a: valueNumber is "19.5"', r.valueNumber === "19.5");
  assert('T6b: restText matches', r.restText === "s avg (15 calls)");
}

// T7: byModel sub-row — null avgLatency
{
  const r = byModelRow({ avgLatency: null, calls: 4 });
  assert('T7a: valueNumber is em-dash placeholder', r.valueNumber === "—");
  assert('T7b: restText has no "s avg" prefix', r.restText === " (4 calls)");
}

console.log(`\n${pass + fail} tests — ${pass} passed, ${fail} failed`);
if (fail > 0) process.exit(1);
else console.log('ALL TESTS PASS');
```
