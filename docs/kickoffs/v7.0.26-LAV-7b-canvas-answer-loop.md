## 2. CONTEXT
John's round-2 UX/UI pass, items 5 and 9, plus the readability enhancement for item 3 that came out of the design conversation. Three real changes to the canvas overlay:

1. **Legend + view-mode toggle move to top-right** of the canvas, one row, sitting left of the Agent Routing rail (their old top-left slot is freed for the Answer drawer).
2. **A new "Answer" drawer, top-left, closed by default** — John's explicit call: *"the purpose of this screen is to show the agent communication, not the answer... if the user chooses to see the answer, they can open the drawer."* Reuses `QaEvidenceCard` (round-1's reuse pattern) verbatim — no new answer-rendering component.
3. **A looping arrowhead on any delegation that is genuinely still open** (dispatched, no return yet), traveling repeatedly from the dispatching agent to the target until the real return event closes it — John's own design, replacing the single 900ms pulse as the *readable* signal for "communication in progress." A minimum-lap floor (900ms — the canvas's one existing motion duration) guarantees even a near-instant hop shows one full readable pass before its open-visual clears; a genuinely long-open delegation keeps looping for its real duration, no ceiling.

**What this session does NOT touch:** `LAV-5b`'s lit-edge mechanism (the line that stays solid in its meaning color until the next pulse, with `EDGE_MEANING_LABEL` riding it) keeps governing every edge that is **not** currently open — a completed report-back, a terminal hand-off, a re-dispatch. The new open-loop treatment only applies to edges genuinely mid-flight; it takes visual precedence over the lit-edge look for exactly as long as an edge is open, and hands back to the existing mechanism the moment it closes (past its floor).

### Task 3 — Which edges are "open," and the minimum-lap floor
```js
// FEATURE: LAV-7b -- the real open/closed state of every delegation, straight off deriveNetwork's
// existing openByTarget (targetId -> dispatcherId while unreturned) -- no new event tracking.
const openEdgeKeys = useMemo(
  () => new Set([...net.openByTarget.entries()].map(([to, from]) => edgeKey(from, to))),
  [net]);

// FEATURE: LAV-7b -- the VISUAL open state, decoupled from the real one by a floor: once an edge
// opens it stays visually open for at least LOOP_LAP_MS even if the real delegation already
// closed, so a near-instant hop still shows one full readable pass. Never a ceiling -- a genuinely
// long-open delegation keeps looping for its real duration untouched.
const LOOP_LAP_MS = 900; // same duration as Pulse's existing `dur` -- one motion language, not two
const openSinceRef = useRef(new Map()); // edgeKey -> ms timestamp first observed open
const [visuallyOpenKeys, setVisuallyOpenKeys] = useState(() => new Set());
useEffect(() => {
  const now = Date.now();
  setVisuallyOpenKeys(prev => {
    const next = new Set(prev);
    for (const k of openEdgeKeys) {
      if (!openSinceRef.current.has(k)) openSinceRef.current.set(k, now);
      next.add(k);
    }
    return next;
  });
  const timers = [];
  for (const [k, since] of openSinceRef.current) {
    if (openEdgeKeys.has(k)) continue; // still really open -- nothing to schedule
    const remaining = LOOP_LAP_MS - (now - since);
    const clear = () => {
      openSinceRef.current.delete(k);
      setVisuallyOpenKeys(prev => { const n = new Set(prev); n.delete(k); return n; });
    };
    if (remaining <= 0) clear(); else timers.push(setTimeout(clear, remaining));
  }
  return () => timers.forEach(clearTimeout);
}, [openEdgeKeys]);
```
Reset `openSinceRef.current` and `visuallyOpenKeys` to empty on the same ledger-reset condition the existing pulse effect already uses (`runHops.length < seenRef.current`, i.e. a new question boundary) — add the two clears alongside `setPulses([])`/`setLitEdge(null)` in that existing branch, not a new effect.

### Task 4 — `LoopingArrow` + wiring into the edge render
```jsx
// FEATURE: LAV-7b -- a small arrowhead traveling repeatedly from `d`'s start to its end while
// mounted (the caller controls mounting via visuallyOpenKeys -- this component has no opinion on
// when it should stop). Position via getPointAtLength (same technique Pulse already uses);
// rotation via a 1px look-ahead sample so the arrow visibly points along the direction of travel.
function LoopingArrow({ d, color }) {
  const pathRef = useRef(null);
  const arrowRef = useRef(null);
  useEffect(() => {
    const path = pathRef.current, arrow = arrowRef.current;
    if (!path || !arrow) return undefined;
    const total = path.getTotalLength() || 1;
    let raf = 0;
    const t0 = performance.now();
    const frame = (now) => {
      const len = ((now - t0) % LOOP_LAP_MS) / LOOP_LAP_MS * total;
      const p = path.getPointAtLength(len);
      const ahead = path.getPointAtLength(Math.min(total, len + 1));
      const angle = (Math.atan2(ahead.y - p.y, ahead.x - p.x) * 180) / Math.PI;
      arrow.setAttribute("transform", `translate(${p.x} ${p.y}) rotate(${angle})`);
      raf = requestAnimationFrame(frame);
    };
    raf = requestAnimationFrame(frame);
    return () => cancelAnimationFrame(raf);
  }, [d]);
  return (
    <g>
      <path ref={pathRef} d={d} fill="none" stroke="none"/>
      <polygon ref={arrowRef} points="-6,-4 6,0 -6,4" fill={color} filter="url(#lavGlow)"/>
    </g>
  );
}
```
In the edge-render map (where `lit`/`stroke`/`label` are computed today): add `const open = visuallyOpenKeys.has(e.key)`. When `open` is true, it takes precedence over the lit-edge look: draw the base path **solid** in `DISPATCH_COLOR` (not dashed, not `e.color`/`litEdge.color`) and render a `<LoopingArrow d={ePath(a,b)} color={DISPATCH_COLOR}/>` alongside it; render NO `EDGE_MEANING_LABEL` text for an open edge (the moving arrow already says "in progress" — a static word next to a moving arrow would read as contradictory, per John's own "let me read it easier" framing, not clutter it further). When `open` is false, render exactly as `LAV-5b` already does (lit-edge-or-resting, with its label) — this session changes nothing about that branch.

## 8. NODE.JS TEST (full code — save as `test-lav-7b.mjs`, delete before commit)
```js
// S-LAV-7b inline test: visually-open floor logic (pure state-machine, no DOM/rAF needed to test
// the timing contract) + open-edge precedence rule. Pure Node -- logic mirrored exactly from the
// kickoff spec; committed implementation must match verbatim in behavior.
function step({ openSince, visuallyOpen, openEdgeKeys, now, LOOP_LAP_MS = 900 }) {
  const nextOpenSince = new Map(openSince);
  const nextVisual = new Set(visuallyOpen);
  for (const k of openEdgeKeys) {
    if (!nextOpenSince.has(k)) nextOpenSince.set(k, now);
    nextVisual.add(k);
  }
  const toSchedule = [];
  for (const [k, since] of nextOpenSince) {
    if (openEdgeKeys.has(k)) continue;
    const remaining = LOOP_LAP_MS - (now - since);
    if (remaining <= 0) { nextOpenSince.delete(k); nextVisual.delete(k); }
    else toSchedule.push({ key: k, remaining });
  }
  return { openSince: nextOpenSince, visuallyOpen: nextVisual, toSchedule };
}
let pass = true;
const check = (name, got, want) => {
  const ok = JSON.stringify(got) === JSON.stringify(want);
  if (!ok) { pass = false; console.error(`FAIL ${name}: got ${JSON.stringify(got)} want ${JSON.stringify(want)}`); }
  else console.log(`ok ${name}`);
};
// A hop opens and closes within the same 50ms tick -- must still float visually-open with a
// scheduled clear at the floor, not disappear instantly.
let s = step({ openSince: new Map(), visuallyOpen: new Set(), openEdgeKeys: new Set(["a>b"]), now: 1000 });
check("opens immediately", [...s.visuallyOpen], ["a>b"]);
s = step({ openSince: s.openSince, visuallyOpen: s.visuallyOpen, openEdgeKeys: new Set(), now: 1050 });
check("closes-fast stays visually open, schedules floor", [...s.visuallyOpen], ["a>b"]);
check("scheduled remaining ~= 850ms", s.toSchedule[0].remaining, 850);
// A hop that's been open past the floor clears immediately on real close.
s = step({ openSince: new Map([["a>b", 1000]]), visuallyOpen: new Set(["a>b"]), openEdgeKeys: new Set(), now: 2500 });
check("closes after floor clears immediately", [...s.visuallyOpen], []);
// A genuinely long-open edge keeps looping (no ceiling) as long as it's really still open.
s = step({ openSince: new Map([["a>b", 1000]]), visuallyOpen: new Set(["a>b"]), openEdgeKeys: new Set(["a>b"]), now: 30000 });
check("still-open edge has no ceiling", [...s.visuallyOpen], ["a>b"]);
console.log(pass ? "ALL TESTS PASS" : "TESTS FAILED");
if (!pass) process.exit(1);
```
