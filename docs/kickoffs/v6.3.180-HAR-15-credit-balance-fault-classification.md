## 2. CONTEXT

**The problem, in one line:** when the Anthropic account runs out of credits, every model call fails instantly and the platform reports it as a generic bug with the advice "try again" — advice that can never work.

Verified live this session against Supabase (`durable_hops`, `status = 'failed'`), not taken from the `chi-e2e-design` census on trust: **42 credit-balance rows**, in two bursts — 30 on 2026-07-20 and 12 on 2026-07-28 02:06 UTC. Every one carries the identical body:

```
Anthropic call failed: 400

Detail: {"type":"error","error":{"type":"invalid_request_error","message":"Your credit
balance is too low to access the Anthropic API. Please go to Plans & Billing to upgrade
or purchase credits."},"request_id":"req_…"}
```

This was the single largest cause of end-to-end run failures in the 14-day census. The **ops half is already closed** (John enabled Anthropic auto-reload, 2026-07-28); this session is the code half.

**What the user sees today, traced end to end and confirmed in code:** `postToAnthropicWithRetry()` throws with `.detail` set to that raw JSON. `execute.js` forwards `.detail` untouched on both error paths (L1293 SSE, L1415 JSON). The screen's `describeCaughtError()` (`CHI-77`) concatenates message + status + detail, so Column 3's Pipeline Log renders the raw Anthropic blob including the internal `request_id`, and the chat bubble says *"Something went wrong completing your answer — try again."*

**Why this is load-bearing, not cosmetic — the finding that justifies doing it now.** `postToAnthropicWithRetry()` correctly refuses to retry a 400, but it throws with **`status: 502`**, and `502` is a member of `TRANSIENT_ANTHROPIC_STATUS` (`{429, 500, 502, 503, 529}`). So a permanent, un-retryable failure currently presents to every downstream caller as a transient one. `HAR-17` (Task Success Rate) — in design concurrently, `worktree har-17-design` — is building "classify first, then resume a transient hop once," and `.claude/rules/transient-failure-recovery.md` states: *"Never auto-retry a permanent-class failure (400s, incl. credit-balance)."* Any `HAR-17` classifier keying on status would auto-retry precisely the class the rule forbids, burning its one recovery and a fresh time budget on a call that cannot succeed.

**This session therefore owns the classification contract `HAR-17` consumes.** `HAR-17` must key on `failureClass`, never on `status`.

**Design decision (John, 2026-07-28):** *add* the truth rather than overwrite it. `status: 502` stays — it is honest as **our own** API's semantic ("an upstream dependency failed"); overwriting it with `400` would make `/api/capabilities/execute` claim the *client's* request was malformed and would change the route's external HTTP contract. The real upstream status travels alongside it instead.

**Precedent being extended, not invented (Architect Review, "search by shape"):** `DAT-7` already established this exact idiom on this exact screen — `onResolveConfirmation` branches on a structured field of the caught error (`e.detail?.tier.startsWith("denied-")`) to replace "try again" with honest advice, for the same reason: *"a denied write will fail identically forever; the generic 'try again' message is actively wrong advice for it."* `lib/librarian.js` supplies the matching producer-side idiom (a stable slug on a graceful denial). This session follows both rather than introducing a parallel mechanism.

### Task 1 — Classify at the throw site (`api/prompt/request-receivable.js`)

1. Add a pure, exported classifier immediately after the existing constants at ~line 203 (`API_RETRY_BACKOFF_MS`):

```js
// FEATURE: HAR-15 -- classify an Anthropic HTTP failure once, at the only place that has the real
// status AND the real body, so no consumer downstream has to re-derive it from an English message.
// Pure and exported so the Node test can import the real implementation (STANDARDS.md Section 5).
//
// Matching on the credit-balance phrase rather than on error.type: `invalid_request_error` covers
// every malformed-request rejection too, so the type alone cannot single this class out. The phrase
// is the actual discriminator; all 42 real rows verified 2026-07-28 carry it verbatim.
export function classifyAnthropicFailure(status, bodyText) {
  const body = typeof bodyText === 'string' ? bodyText : '';
  if (status === 400 && /credit balance is too low/i.test(body)) {
    return { failureClass: 'permanent', faultCode: 'anthropic-credit-exhausted' };
  }
  if (TRANSIENT_ANTHROPIC_STATUS.has(status)) {
    return { failureClass: 'transient', faultCode: 'anthropic-transient' };
  }
  return { failureClass: 'permanent', faultCode: 'anthropic-request-rejected' };
}
```

```js
// test-har-15.mjs — S-HAR-15 (v6.3.180) — fault classification
// Categories: A (data shape), M (screen copy ↔ classifier contract)
import { readFileSync } from 'node:fs';
import { classifyAnthropicFailure } from './api/prompt/request-receivable.js';

let pass = 0, fail = 0;
const ok = (name, cond, detail = '') => {
  if (cond) { pass++; console.log(`  PASS  ${name}`); }
  else { fail++; console.log(`  FAIL  ${name} ${detail}`); }
};

// The exact body shape from all 42 real durable_hops rows (verified 2026-07-28).
const CREDIT_BODY = '{"type":"error","error":{"type":"invalid_request_error","message":"Your credit balance is too low to access the Anthropic API. Please go to Plans & Billing to upgrade or purchase credits."},"request_id":"req_011CdTdw1BPrwXPvMd4LrBgi"}';
const MALFORMED_BODY = '{"type":"error","error":{"type":"invalid_request_error","message":"model: unknown model id"}}';
const OVERLOAD_BODY = '{"type":"error","error":{"type":"overloaded_error","message":"Overloaded"}}';

const credit = classifyAnthropicFailure(400, CREDIT_BODY);
ok('credit-balance 400 -> permanent', credit.failureClass === 'permanent', JSON.stringify(credit));
ok('credit-balance 400 -> anthropic-credit-exhausted', credit.faultCode === 'anthropic-credit-exhausted');

const malformed = classifyAnthropicFailure(400, MALFORMED_BODY);
ok('other 400 -> permanent', malformed.failureClass === 'permanent');
ok('other 400 is NOT the credit code', malformed.faultCode !== 'anthropic-credit-exhausted');

for (const s of [429, 500, 502, 503, 529]) {
  ok(`${s} -> transient`, classifyAnthropicFailure(s, OVERLOAD_BODY).failureClass === 'transient');
}
ok('401 -> permanent (auth is never retried)', classifyAnthropicFailure(401, '').failureClass === 'permanent');

// Defensive: a non-string body must not throw (STANDARDS.md String Safety).
let threw = false;
try { classifyAnthropicFailure(400, null); } catch { threw = true; }
ok('null body does not throw', !threw);
ok('null body 400 is not misread as credit-exhaustion',
   classifyAnthropicFailure(400, null).faultCode !== 'anthropic-credit-exhausted');

// M. Contract: the screen keys on the same slug the classifier emits, and no longer dumps detail
// for this class. A drift here is exactly the two-classifiers bug this session exists to prevent.
const screen = readFileSync('src/screens/MarketIntelligenceScreen.jsx', 'utf8');
ok('screen keys on anthropic-credit-exhausted', screen.includes('anthropic-credit-exhausted'));
ok('screen defines one shared CREDIT_EXHAUSTED_TEXT', (screen.match(/CREDIT_EXHAUSTED_TEXT\s*=/g) || []).length === 1);
ok('all 5 error bubbles route through faultAdvice', (screen.match(/faultAdvice\(/g) || []).length >= 5);

const exec = readFileSync('api/capabilities/execute.js', 'utf8');
ok('execute.js forwards faultCode on both error paths', (exec.match(/faultCode/g) || []).length >= 2);
ok('execute.js still returns e.status (contract unchanged)', exec.includes('res.status(e.status || 500)'));

const rr = readFileSync('api/prompt/request-receivable.js', 'utf8');
ok('throw still carries status: 502 (our API semantic unchanged)', /status:\s*502/.test(rr));
ok('retry gate untouched', rr.includes('const TRANSIENT_ANTHROPIC_STATUS = new Set([429, 500, 502, 503, 529]);'));

console.log(fail === 0 ? `\nALL TESTS PASS (${pass})` : `\n${fail} FAILURES (${pass} passed)`);
if (fail > 0) process.exit(1);
```
