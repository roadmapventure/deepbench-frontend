## 3. What ships

**Table-side only. No `src/`, `api/` or `lib/` change; no schema change; no migration.**

1. **98 `runner_before_images` rows** (`table_name='backlog_items'`, `pk_value` = the row's

   before-image, no write.
2. **98 `UPDATE`s**, keyed on the primary key `id`, never on `backlog_id`.
   **`backlog_id` is not unique** — `CHI-48` occupies two rows (`SES-86` phase 2's own QA found
   it; filed as `SES-30`), and exactly one of them carries the defective title, so
   `UPDATE … WHERE backlog_id = 'CHI-48'` would write **both**. The `UPDATE` is additionally
   predicated on the bare-class title pattern, so a row already repaired cannot be touched twice.

**`updated_at` is deliberately NOT stamped, and this is a considered call rather than an
oversight.** `SES-87`'s background revalidation sweep (step 8c) uses
`updated_at < now() - INTERVAL '30 days'` as its *age trigger* for the sinking tail. Stamping all
98 rows would hide them from that sweep for a month — and this pass changes how a ticket
**reads**, never what it **claims**: every new title is derived from a description that was
already sitting in the row. The precedent is explicit and in the same family:
`recompute_backlog_queue()` deliberately does not touch `updated_at` either (`SES-86` phase 2,
`v7.0.130`), for the same reason — a bulk mechanical pass must not eat a signal it does not
own. The snapshot diff does not depend on it: `scripts/export-backlog-snapshot.js` is
deterministic over the payload's own content, so a title change produces a diff regardless.

## 4. QA — four arms, and one of them is a negative control

- **A. The defect is gone.** `count(*) WHERE title ~ '^P[0-9]+ - <bare class>'` → **98 before,
  0 after**. (Would it pass if the change did nothing? No — it is 98.)
- **B. What replaced it is well-formed.** All 98 repaired titles non-empty, length within
  30–120 chars, none matching `^P[0-9]+ - `, none beginning with a provenance opener.
- **C. NEGATIVE CONTROL — the ticket's own rule, run read-only against the same 98 rows.**
  Assert it produces **47** provenance-shaped titles and **3** NULLs. This is what makes the
  arm above discriminating rather than a presence check: it proves the shipped rule is *not*
  the specified one and shows the cost of the difference, in numbers, on the live rows.
- **D. ANTI-FABRICATION.** For every one of the 98, assert that a distinctive token from the new
  title (length ≥ 6, lowercased) actually appears in that row's **own** `description`. A title
  invented from nothing fails this; a title derived from the row passes. This is the arm that
  makes "authored" checkable instead of trusted.
- **E. Blast radius.** Row count still 605; rows still matching `^P[0-9]+ - ` = **1**, and it is
  `ADM-1` by name; before-image count for this cycle = 98.
