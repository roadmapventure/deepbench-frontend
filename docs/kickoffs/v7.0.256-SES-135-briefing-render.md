## The test builds the real page and renders it

Not a fixture and not a checked-in snapshot: it runs the shipped `scripts/build-briefing.mjs`
against the shipped `docs/runbooks/briefing-template.html` and live Supabase, then executes the
result in jsdom as a browser would. A render test that reads a snapshot passes forever while the
builder rots.

Five assertions:

| clause | what it catches |
|---|---|
| `no-swallowed-markup` | zero `script` elements inside `#page` — the whole `SES-208` class, structurally |
| `section-order` | rendered sections strictly ascending (`2 < 2b < 3 … 9 < 9.1 < 10`), none the template does not declare, every unconditional one present |
| `counter-agrees` | the masthead's decisions count equals the `data-awaits` element count |
| `plain-contract` | every card has a plain-language block that is either three labelled fields **or** the red defect line — never empty |
| `reading-slots` | every meter reading in `briefing-state` actually appears in the rendered page |

**Credentialed, and it says so.** Building the page needs `SUPABASE_URL` / `SUPABASE_SERVICE_KEY`.
Without them the test declares itself **not-run** rather than passing vacuously — both arms verified.
That is `SES-61`'s rule (shipped two cycles ago) doing its job on its first new consumer.

## Measured, not asserted

- **Negative control on the real pre-fix page** (`SES-208`'s, rendered before that fix):
  `no-swallowed-markup` fails with **1 script element holding 51,860 characters**, and
  `section-order` fails naming **6 missing unconditional sections** (10, 11, 12, 13, 14, 15).
  So the test catches the live defect that motivated it.
- **A wrong first draft, found and reported rather than quietly fixed.** The order clause first
  derived its expectation from the template's *source* order — and failed against a page that was
  correct, because `orphanThreads()` defines §9.1's marker near the top of the script while
  `render()` emits it after §9. Source position is not render order. The clause now asserts the
  property that actually holds — strict ascent under a key where `2 < 2b < 3` and `9 < 9.1 < 10` —
  which also cannot go stale when `SES-178`'s "extend, never renumber" rule appends a section.
  Unit-checked in both directions.
- `npm run build` green; suite green.
