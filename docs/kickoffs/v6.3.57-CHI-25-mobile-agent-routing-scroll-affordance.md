## 2. CONTEXT

John's live report (mobile Channel Intelligence screen): the pinned Agent Routing feed at the bottom of the mobile chat only shows about one hop at a time, and it's not apparent to the user that the feed scrolls to reveal hop history.

**Root cause, confirmed by reading the code and by live-measuring the real deployed dev preview (not asserted from memory):** the feed's outer container is a fixed `height:118` (`MarketIntelligenceScreen.jsx:2453`). The header row measures 24px live, leaving a 92px `clientHeight` scroll body (78px of that is real content once its own 7px top/bottom padding is subtracted). A scroll affordance already exists (`MI-50`, `STYLE-GUIDE.md` §21 amendment, 2026-07-14) — a bottom-edge fade gradient + bouncing chevron, shown only when there's real unscrolled content below — but because a single hop card can render as a complete-looking unit inside that space, the fade sits below something that already reads as "finished," not "cut off."

**Live measurement, this session, mobile viewport (375×812), real Q&A chain against the deployed dev preview (`https://deepbench-frontend-git-dev-roadmapventures-projects.vercel.app`, Japan-GEO example question, 6 real hops returned):** actual rendered hop-card heights (`getBoundingClientRect()`) were `75, 110, 99, 42, 42, 99` px — a real spread, not uniform, since a hop's height depends on how many activity lines/how much text it carries. Cumulative offsets from the scroll body's own top edge: hop 0 spans 7–82px, hop 1 spans 88–199px. A container tall enough to show hop 0 in full plus roughly the first half of hop 1, with the fade cutting across that visibly-truncated second card, works out to a **176px** outer container height (up from 118px) — an increase of 58px, taken from the chat pane above it (the feed is a fixed-height sibling, not `flex`, so growing it directly shrinks the chat area without any other layout fighting).

**Honest caveat, not glossed over:** hop heights vary (42–110px in this one sample), so 176px is a representative target tuned against real live data, not a guarantee that every hop is bisected identically — a short hop (42px) may show fully with a larger peek of hop 2; a tall hop (110px) may show with less of hop 2 visible. Either case still produces the intended effect (a visibly cut-off second element), which is what actually signals scrollability — the exact split ratio isn't the mechanism.

**Desktop/mobile parity:** N/A — desktop's `AuditColumn` (`MarketIntelligenceScreen.jsx:2108`) uses an unrelated, already-adequate pattern: a resizable `<Drawer>` with `maxHeight={280}` that comfortably shows multiple hops. This is a mobile-only fix to `MobileBody`'s own separate pinned-feed markup; no desktop change.

**Architect Review — duplicate-functionality check:** no new component, hook, or affordance mechanism introduced. The existing `MI-50` fade/chevron logic (`routingCanScrollMore` state, the `checkRoutingScroll()` handler) is reused completely unchanged — this fix only changes the one `height` value the affordance renders inside of.
