## 2. CONTEXT

Found live 2026-07-16 (John's screenshot of the Agent Routing drawer, design session `continuity-ux-0716`): within a single hop card, activity lines render in reverse chronological order — Owen's hop showed his closing "routing this to Marcus" delegation line *before* the review activity that actually happened first.

**Root cause, confirmed by reading `groupEventsIntoHops()` (`MarketIntelligenceScreen.jsx:796-817`):** the function is fed `ordered = [...events].reverse()` — newest-first, by design, so hop *cards* stack newest-first. But when the loop merges consecutive same-agent events into one hop, it just `push`es each event onto that hop's own `events` array in whatever order it's iterating (newest-first) — so within a hop, `events` inherits the same newest-first order the outer list uses, when it should read chronologically (oldest first) for a human scanning one hop's own activity top-to-bottom.

One shared function, called from both the desktop drawer (`AuditColumn`, L2079-2113) and the mobile pinned feed (L2301-2428) — fixing it here fixes both call sites, no per-site patch.

**Two side effects found while tracing this, confirmed in scope with John (not separate work, consequences of the one fix):**
1. `RoutingHopCard`'s left-border color (`lastColor`, L1838) reads `hop.events[hop.events.length - 1]`. Under the current bug that's actually the *oldest* event in the hop. Once within-hop order is fixed, that index becomes the true last/most-recent event — matching what the variable name already implies was intended. Multi-event hops' border color will now reflect the hop's final state instead of its first.
2. `RoutingHopCard`'s React `key` is `hop.events[0].id` (L2107, L2428). Currently that's the newest event, which changes every time a new event streams into a still-growing hop — forcing an unneeded remount each time. After the fix, index 0 is the oldest/first event in the hop, stable for that hop's whole lifetime, so a growing hop no longer remounts on every new activity line.

**Not the same as `CHI-17`** (Michelle's raw-reasoning line, deferred) or `CHI-11` (AI-pattern-tag accuracy, separate unscoped investigation) — cross-referenced only, out of scope here.

### Task 1 — `groupEventsIntoHops()`: reverse each hop's own `events` array before returning (`MarketIntelligenceScreen.jsx:796-817`)

Current code:

```js
function groupEventsIntoHops(ordered) {
  const hops = [];
  for (const evt of ordered) {
    const last = hops[hops.length - 1];
    if (evt.type === "question_boundary") {
      hops.push({ agentId: evt.agentId, events: [evt], isBoundary: true });
      continue;
    }
    if (last && !last.isBoundary && last.agentId === evt.agentId) {
      last.events.push(evt);
    } else {
      hops.push({ agentId: evt.agentId, events: [evt] });
    }
  }
  const total = hops.filter(h => !h.isBoundary).length;
  let seen = 0;
  return hops.map(h => {
    if (h.isBoundary) return h;
    seen += 1;
    return { ...h, hopNumber: total - (seen - 1) };
  });
}
```

Change only the final `hops.map` — add `events: [...h.events].reverse()` to the non-boundary branch's returned object (boundary hops always have exactly 1 event; leave them untouched, no need to reverse a 1-item array):

```js
function groupEventsIntoHops(ordered) {
  const hops = [];
  for (const evt of ordered) {
    const last = hops[hops.length - 1];
    if (evt.type === "question_boundary") {
      hops.push({ agentId: evt.agentId, events: [evt], isBoundary: true });
      continue;
    }
    if (last && !last.isBoundary && last.agentId === evt.agentId) {
      last.events.push(evt);
    } else {
      hops.push({ agentId: evt.agentId, events: [evt] });
    }
  }
  const total = hops.filter(h => !h.isBoundary).length;
  let seen = 0;
  return hops.map(h => {
    if (h.isBoundary) return h;
    seen += 1;
    // FEATURE: CHI-09 — h.events was accumulated in the same newest-first order as `ordered`
    // (each new same-agent event gets pushed onto the end), so within a hop the events read
    // newest-first too. Hop *cards* stay newest-first (unchanged); only this hop's own
    // activity-line order flips to chronological (oldest first), matching how a human reads
    // "what happened during this hop" top to bottom.
    return { ...h, events: [...h.events].reverse(), hopNumber: total - (seen - 1) };
  });
}
```

No other line changes. `RoutingHopCard`'s `lastColor` (`hop.events[hop.events.length - 1]`) and both call sites' `key={hop.events[0].id}` need no edits themselves — they inherit the corrected behavior automatically because they read from the now-reordered `events` array.
