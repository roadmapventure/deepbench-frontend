## The ticket asked for a sibling survey, and the survey found a SECOND site

`SES-222`'s own words: *"CHECK THE SIBLING SPLICES IN THE SAME PASS rather than assuming."* Every
builder→template pair that carries database text was read, both sides:

| Splice | Builder side | Template side | Verdict |
|---|---|---|---|
| §8 `queueRow` arg 3 — epic name | raw | `esc(epic)` | correct — and it is the **internal control**: the same M0 string renders right in §8 and wrong in §15 |
| §8 `queueRow` arg 4 — `priority_class` | `H()` then `'`→`&rsquo;` | `esc(cls)` | **DOUBLE — second defect, fixed here** |

| §11 `classRow` arg 2 — class name | `H()` then `'`→`&rsquo;` | spliced **raw** | correct — the builder is the only escaper here |
| §15 `msRow` arg 1 — epic name | `H()` | `esc(name)` | **DOUBLE — the filed defect** |

| §16 `svRow` — label | builder literal | `esc(label)` | correct |

**The second defect is real and is not the ampersand.** `H()` does not touch apostrophes, but the
`.replace(/'/g, '&rsquo;')` that follows it does — and `esc(cls)` then turns that entity into
`&amp;rsquo;`. The live class string `P1 - Improves John's Skills` therefore renders as
`P1 - Improves John&rsquo;s Skills`. **Honest scope of it:** §8 shows the top 12 of the queue and no
`P1` ticket is in today's top 12, so this one is **latent today and live the moment a `P1` ticket
reaches the head of the board** — which is the class named after John. Stated as latent rather than
claimed as a visible fix.

## The fix, and the rule it restores

`SES-208` (`v7.0.255`) already wrote the rule, next to `esc()` itself: **escape what came out of the
database, never what the builder composed — and never twice.** Both defects are the builder escaping
database text that the template also escapes. The fix puts each on the side the rule names:

1. `:498` — `${J(H(r.name))}` → `${J(r.name)}`
2. `:425` — `${J(H(b.priority_class).replace(/'/g, '&rsquo;'))}` → `${J(b.priority_class)}`

The dropped `&rsquo;` substitution is **not** load-bearing for JS quoting: `J()` already escapes a
backslash and then an apostrophe (`:175`), so the single-quoted literal stays well-formed. Verified
by reading `J()`, not assumed.

## The edit this ship forbids

**Do not "consistency-fix" `classRow` (`:453`) or the §8 title (`:425` arg 7) by dropping their
`H()` too.** Those two are the mirror image: their template sides splice **raw**, so the builder is
the only escaper and removing it renders ticket prose and class names as live markup — the
`SES-208` defect facing the other way. The template comment at `:218-219` says this outright
(*"That asymmetry is deliberate and a sweeper must not 'fix' it"*), and the guard pins it: a patch
that over-corrects fails `sibling-classRow-still-escapes` and `sibling-section8-title-still-escapes`.
