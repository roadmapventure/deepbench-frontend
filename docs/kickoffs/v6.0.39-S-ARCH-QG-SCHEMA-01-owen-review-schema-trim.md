## CONTEXT

While evaluating whether fixing Owen's latency would help platform speed, pulled real content from `deliverables` for recent `qg-review-intent` calls (both a genuine live guardrail block and a passing review, both 2026-07-07). Both show the same pattern: `eval.critique` runs 500-650 characters of multi-sentence prose on *every* call regardless of pass/fail, and `guardrail.reason` runs even longer on a block (~950 characters, enumerated (1)(2)(3) reasoning). Neither field has a `maxLength` in `qg-review-intent`'s schema — the same uncapped-free-text-field class as `AA-113`/`AA-120`/`AA-124`/`AA-128`, just never checked here because no real block existed to measure against until today.

**This is a broader win than the earlier fixes:** `AI-43`/`AA-124`/`AA-128` each targeted a hand-off/routing decision (Priya's display-intent, Michelle's PM broker) that only fires on specific paths. `eval.critique` and `guardrail.reason` generate on **every single Q&A review, pass or fail** — trimming them helps every Q&A interaction's Owen hop, not just a rare retry chain.

**Not the same problem as Owen's ~50s regenerate-chain** (confirmed separately, via the 04:23-04:24 historical trace: 7.7s review → ~36s gap for Marcus's real regeneration → 13.7s re-review ≈ 57s). That chain's cost is Marcus's real regeneration work, not Owen's own field verbosity — this session does not touch it, and does not claim to.

**Two different caps, two different reasons:**
- `eval.critique`: already passed through `shapeForLog()` before reaching the Pipeline Log (`AA-125`) — the model's full text is never actually shown to the user today. Capping this is a pure generation-time win with zero display-quality tradeoff.
- `guardrail.reason`: confirmed via `AA-130`'s diff (`MarketIntelligenceScreen.jsx`'s `buildFailureText()`) to be concatenated **raw, unshaped** directly into the failure banner text: `` `${base}${reason} Try rephrasing the question.` ``. Today, a real block would show all ~950 characters of enumerated reasoning directly in that banner — arguably bad UX regardless of speed. Capping this is both a speed win and a UX improvement, not a tradeoff.

## TASKS (1)

### Task 1 — Supabase: cap `qg-review-intent`'s `critique` and `guardrail.reason`

Run directly via Supabase MCP (`execute_sql`), same `jsonb_set` pattern as `AA-128`:

```sql
UPDATE skill_profiles
SET traits = jsonb_set(
  jsonb_set(
    traits,
    '{schema,properties,eval,properties,critique,maxLength}',
    '400'::jsonb
  ),
  '{schema,properties,guardrail,properties,reason,maxLength}',
  '300'::jsonb
)
WHERE slug = 'qg-review-intent';
```

`critique` gets `400` (generation-time trim only, no display consumer — matches the reasoning-field range `AA-113`/`AA-128` already established, sized up slightly since this field legitimately covers up to 5 scoring dimensions). `guardrail.reason` gets `300` (tighter — it's shown raw in a user-facing failure banner via `AA-130`, so it should read as a concise explanation, not an enumerated essay). Nothing else in `traits` changes — `schema.required`, `eval.scores`'s per-dimension `minimum`/`maximum`, `guardrail.result`/`rule_violated` enums, and `method` all stay exactly as they are. Verify with a direct re-query after the update.

## NODE.JS TEST

Pure Node, talks to real Supabase. Save as `test-s-arch-qg-schema-01.mjs`, run with `node --env-file=.env.local test-s-arch-qg-schema-01.mjs`, delete before committing.

```js
// test-s-arch-qg-schema-01.mjs — AA-131 verification (pure Node)
let failures = 0;
function check(label, cond) {
  if (cond) { console.log(`PASS: ${label}`); }
  else { console.error(`FAIL: ${label}`); failures++; }
}

const SUPABASE_URL = process.env.SUPABASE_URL;
const SUPABASE_SERVICE_KEY = process.env.SUPABASE_SERVICE_KEY;
if (!SUPABASE_URL || !SUPABASE_SERVICE_KEY) {
  console.error('FAIL: SUPABASE_URL/SUPABASE_SERVICE_KEY not set -- cannot verify');
  process.exit(1);
}
const headers = { apikey: SUPABASE_SERVICE_KEY, Authorization: `Bearer ${SUPABASE_SERVICE_KEY}` };

async function checkSchemaRow() {
  const res = await fetch(`${SUPABASE_URL}/rest/v1/skill_profiles?slug=eq.qg-review-intent&select=traits`, { headers });
  const [row] = await res.json();
  check('qg-review-intent row found', !!row);
  const schema = row?.traits?.schema;
  check('eval.critique gains maxLength: 400', schema?.properties?.eval?.properties?.critique?.maxLength === 400);
  check('guardrail.reason gains maxLength: 300', schema?.properties?.guardrail?.properties?.reason?.maxLength === 300);
  check('eval.scores dimensions unchanged (still 1-5 integers)', schema?.properties?.eval?.properties?.scores?.properties?.accuracy?.maximum === 5 && schema?.properties?.eval?.properties?.scores?.properties?.accuracy?.minimum === 1);
  check('guardrail.result enum unchanged', JSON.stringify(schema?.properties?.guardrail?.properties?.result?.enum) === JSON.stringify(['pass', 'block']));
  check('final_answer shape unchanged', schema?.properties?.final_answer?.type?.includes('object') && schema?.properties?.final_answer?.type?.includes('null'));
  check('method text unchanged (still describes the retry-once rule)', typeof row?.method === 'string' && row.method.includes('Never retry more than once'));
}

async function checkLiveCall() {
  const DEV_URL = process.env.DEEPBENCH_DEV_URL;
  if (!DEV_URL) { console.warn('SKIP: live call -- DEEPBENCH_DEV_URL not set'); return; }
  const before = new Date().toISOString();
  const res = await fetch(`${DEV_URL}/api/capabilities/execute`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'x-vercel-protection-bypass': process.env.VERCEL_BYPASS || '' },
    body: JSON.stringify({
      capability_slug: 'quality-gate', intent_slug: 'qg-review-intent', agent_id: 'owen',
      task_context: { answer: 'Test answer for AA-131 verification with a citation [id: test-123].', citations: ['test-123'], confidence_tier: 'sourced', agent_id: 'marcus', capability_slug: 'channel-intelligence', intent_slug: 'ci-answer-intent' },
      tenant_id: 'global',
    }),
  }).catch(() => null);
  check('live call did not fail', !!res && res.ok);
  const logRes = await fetch(`${SUPABASE_URL}/rest/v1/ai_activity_log?ai_type=eq.agent-turn&feature=like.quality-gate:qg-review-intent*&created_at=gte.${before}&select=feature,latency_ms&order=created_at.asc`, { headers });
  const rows = await logRes.json();
  check('at least one qg-review-intent agent-turn row logged', rows.length > 0);
  rows.forEach(r => console.log(`[info] ${r.feature}: ${r.latency_ms}ms`));

  const delivRes = await fetch(`${SUPABASE_URL}/rest/v1/deliverables?agent_id=eq.owen&created_at=gte.${before}&select=content&order=created_at.desc&limit=1`, { headers });
  const [deliv] = await delivRes.json();
  if (deliv?.content) {
    const critiqueLen = deliv.content.eval?.critique?.length || 0;
    const reasonLen = deliv.content.guardrail?.reason?.length || 0;
    console.log(`[info] critique length: ${critiqueLen}, guardrail.reason length: ${reasonLen}`);
    check('critique respects the new 400-char cap', critiqueLen <= 400);
    check('guardrail.reason respects the new 300-char cap', reasonLen <= 300);
  } else {
    console.warn('SKIP: no deliverable content found to measure -- live call likely SKIPped above');
  }
}

await checkSchemaRow();
await checkLiveCall();

if (failures > 0) { console.error(`\n${failures} FAILURE(S)`); process.exit(1); }
console.log('\nALL TESTS PASS');
```
