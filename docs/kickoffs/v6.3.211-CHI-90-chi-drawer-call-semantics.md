## 2. CONTEXT

John's decision (2026-07-28, design session): **the Channel Intelligence Agents drawer counts calls the same way the AI Audit screen does — real model calls only.**

The two surfaces disagree today because `LOG-81` (v6.3.203) redefined "call" for AI Audit and deliberately left the shared aggregation core alone. `buildActivitySummary()` — the `LOG-21` core both screens run through — still increments `d.calls` for every scoped log row. AI Audit doesn't feel it: its `byAgent.calls` comes from `countableCallsByAgent` (line ~1074–1084), computed outside the core, and it discards the core's `.calls` entirely. The CHI drawer displays the core's `.calls` directly, so it alone kept operations semantics.

## 5. TASKS (3)

### Task 1 — gate the displayed count, keep a raw one (`src/hooks/useAIActivity.js`)

Inside `buildActivitySummary()`'s row loop, the entry-creation line stays exactly as it is (`if (!map[row.agent_id]) map[row.agent_id] = {...}`) so every agent keeps a map entry regardless — only the increment is gated.

1. Add `operations: 0` to the initializer object literal alongside `calls: 0`.
2. Replace the bare `d.calls++` with:
   ```js
   // FEATURE: CHI-90 -- `calls` is the displayed model-call count, the same definition
   // AI Audit's byAgent uses (LOG-81's isCountableCall). `operations` keeps the raw
   // every-logged-row count this field used to hold: it is what tells the CHI drawer an
   // agent did work on this screen at all, so an agent whose contribution is entirely
   // deterministic can never be labelled "not yet used on this screen" (Task 2).
   // isPairedDup is stamped by hydrateFromSupabase() for AI Audit's entries; here the
   // paired Set computed above is the equivalent per-row source.
   d.operations++;
   if (isCountableCall({ model: row.model, isPairedDup: paired.has(row.id) })) d.calls++;
   ```
   `isCountableCall` is already defined in this file — import nothing, add no second predicate.
3. Update the file's top version-header comment to name `CHI-90` and this change.

### Task 2 — the active/potential split keys on work done (`src/screens/MarketIntelligenceScreen.jsx`)

In `AuditDrawersBody()`, `activeIds`/`potentialIds` currently filter on `agentActivity[id]?.calls > 0`. Switch **the filter and only the filter** to `.operations`:

```js
const activeIds = PROPOSED_MI_AGENT_IDS
  .filter(id => agentActivity[id]?.operations > 0)
  .sort((a, b) => (agentActivity[b]?.calls || 0) - (agentActivity[a]?.calls || 0));
const potentialIds = PROPOSED_MI_AGENT_IDS.filter(id => !agentActivity[id]?.operations);
```

The sort stays on `.calls` (rank by model calls, matching the displayed number) and `StatCell val={stats?.calls ?? 0}` is untouched — it now shows the gated count, which is the point of the session. Add a `// FEATURE: CHI-90` comment on the filter explaining that "not yet used on this screen" is a claim about activity, not about model calls.

**No agent moves between the two lists today** (lowest countable count is Dan Bingham — AI Prompt Strategist at 28). This task exists so that stays true if an agent's screen contribution ever becomes wholly deterministic — the case `LOG-81` explicitly called out and accepted for AI Audit (`useAIActivity.js` ~line 1072), where `calls: 0` is harmless because the agent still renders. Here it would silently relabel a working agent as unused.

### Task 3 — persisted regression test (`tests/regression/CHI-90-drawer-call-semantics.js`)

Category M (cross-reference consistency): the rule being locked is that the CHI drawer and AI Audit's `byAgent` resolve a call the same way. Follow the existing convention exactly (see `tests/regression/LOG-80-by-llm-model-accuracy.js`): version-header comment, `selfRun` import, placeholder Supabase env, default-exported `run()`, real implementation imported — never a reimplementation. Assert against `buildActivitySummary()` directly:

1. A null-model row increments `operations` but not `calls`.
2. A model row increments both.
3. A paired `agent-turn` dup (same agent, `feature: 'request-receivable'` wrapper within `PAIR_WINDOW_MS`, both timestamps before `PAIR_LEGACY_CUTOFF_MS`) increments `operations` but not `calls`.
4. An agent with **only** null-model rows still gets a map entry with `operations > 0` and `calls === 0` — the Task 2 guarantee.
5. `calls` equals the count of the same rows filtered through the exported `isCountableCall` — i.e. the two surfaces cannot drift apart again without failing this test.

Register it in `tests/regression/run-all.js` per that file's existing pattern.

## 8. NODE.JS TEST (full code — `test-chi-90.mjs`, delete before commit)

```js
// test-chi-90.mjs -- CHI-90 CHI drawer call semantics (v6.3.211). Run from worktree root: node test-chi-90.mjs
process.env.VITE_SUPABASE_URL ||= 'http://localhost:54321';
process.env.VITE_SUPABASE_ANON_KEY ||= 'test-placeholder';
const { buildActivitySummary, isCountableCall, PAIR_WINDOW_MS } = await import('./src/hooks/useAIActivity.js');

let pass = 0, fail = 0;
const t = (name, cond) => { if (cond) { pass++; } else { fail++; console.error('FAIL: ' + name); } };

const M = 'claude-haiku-4-5-20251001';
// Pre-cutoff so the AI-51 timestamp-pairing heuristic is in force (PAIR_LEGACY_CUTOFF_MS = 2026-07-16).
const T0 = Date.parse('2026-07-10T12:00:00Z');
const at = ms => new Date(T0 + ms).toISOString();

const rows = [
  // eleanor: 2 deterministic library reads (no model), 1 real model call
  { id: 1, agent_id: 'eleanor', ai_type: 'librarian', feature: 'librarian', model: null, created_at: at(0),    latency_ms: 12, cost_usd: null },
  { id: 2, agent_id: 'eleanor', ai_type: 'librarian', feature: 'librarian', model: null, created_at: at(50),   latency_ms: 9,  cost_usd: null },
  { id: 3, agent_id: 'eleanor', ai_type: 'agent-turn', feature: 'data-room-custody:x', model: M, created_at: at(9e5), latency_ms: 800, cost_usd: 0.02 },
  // marcus: a terminal turn logged twice -- wrapper + agent-turn within PAIR_WINDOW_MS
  { id: 4, agent_id: 'marcus', ai_type: 'channel-intelligence', feature: 'request-receivable', model: M, created_at: at(0),   latency_ms: 900, cost_usd: 0.05 },
  { id: 5, agent_id: 'marcus', ai_type: 'agent-turn',           feature: 'channel-intelligence:a', model: M, created_at: at(500), latency_ms: 900, cost_usd: 0.05 },
  // michelle: directory lookups only -- entirely deterministic contributor
  { id: 6, agent_id: 'michelle', ai_type: 'agent-directory', feature: 'agent-directory', model: null, created_at: at(0),  latency_ms: 5, cost_usd: null },
  { id: 7, agent_id: 'michelle', ai_type: 'agent-directory', feature: 'agent-directory', model: null, created_at: at(30), latency_ms: 6, cost_usd: null },
];
const turns = new Map();
for (const r of rows) {
  if (r.ai_type !== 'agent-turn') continue;
  if (!turns.has(r.agent_id)) turns.set(r.agent_id, []);
  turns.get(r.agent_id).push(new Date(r.created_at).getTime());
}
const s = buildActivitySummary(rows, turns);

// --- 1. deterministic rows count as operations, never as calls
t('eleanor operations counts every row',      s.eleanor.operations === 3);
t('eleanor calls excludes the 2 no-model',    s.eleanor.calls === 1);

// --- 2. the AI-51 duplicate half is excluded from calls but is a real logged row
t('marcus operations counts both halves',     s.marcus.operations === 2);
t('marcus calls counts the pair once',        s.marcus.calls === 1);

// --- 3. an entirely-deterministic agent keeps an entry and reads as active (Task 2)
t('michelle still has a summary entry',       !!s.michelle);
t('michelle operations > 0 (renders active)', s.michelle.operations === 2);
t('michelle calls is 0 (no model calls)',     s.michelle.calls === 0);

// --- 4. cost semantics untouched by this session
t('eleanor cost from the model row only',     Math.abs(s.eleanor.totalCost - 0.02) < 1e-9);
t('eleanor avgCost ignores no-model rows',    Math.abs(s.eleanor.avgCost - 0.02) < 1e-9);
t('marcus cost counts the pair once',         Math.abs(s.marcus.totalCost - 0.05) < 1e-9);
t('michelle avgCost is null (no priced rows)',s.michelle.avgCost === null);

// --- 5. the drawer and AI Audit resolve a call identically -- the anti-drift assertion
const paired = new Set([5]); // id 5 is the dup half, per the fixture above
for (const agentId of ['eleanor', 'marcus', 'michelle']) {
  const expected = rows.filter(r => r.agent_id === agentId)
    .filter(r => isCountableCall({ model: r.model, isPairedDup: paired.has(r.id) })).length;
  t(`${agentId} calls === isCountableCall filter`, s[agentId].calls === expected);
}

// --- 6. shared-core guarantee: byKind is NOT gated (latency visibility preserved)
t('eleanor byKind still sees library reads',  (s.eleanor.byKind?.librarian?.calls ?? 0) === 2);
t('PAIR_WINDOW_MS unchanged',                 PAIR_WINDOW_MS === 2000);

console.log(`\n${fail === 0 ? 'ALL TESTS PASS' : 'FAILURES'}: ${pass} passed, ${fail} failed`);
process.exit(fail === 0 ? 0 : 1);
```
