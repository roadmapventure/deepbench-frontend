## 2. CONTEXT

`S-MI-45` added `WelcomeSplash.jsx`'s mobile sizing (`panelMobile`: `75vw × 75vh`, vs. desktop's `80vw/max960/88vh`). It inherited `overflowY: "auto"` from the desktop `panel` object via `...panel` spread — on a real phone, the hero body's desktop-sized typography and spacing (headline `clamp(36px,4vw,58px)`, 36px margins, 15px CTA padding, 48-56px hero padding) overflows a `75vh`-tall mobile panel badly, so it scrolls.

John's direct instruction, verbatim constraints:
1. **All content needs to be on the screen, or something shortened** — either fits without cutting anything, or (if it truly doesn't fit) shorten copy. In practice: it fits. A rough budget at a realistic phone height (~700-844px device → ~525-630px panel) leaves comfortable margin once padding/type/margins are properly scaled for mobile — confirmed by the arithmetic below, not guessed. **No copy is shortened or removed in this session.**
2. **It should not be a scrollable splash screen.** Not "avoid triggering scroll" — actually prevent it. `panelMobile.overflowY` locks to `"hidden"`, not `"auto"`. This is a structural guarantee: if a future content addition doesn't fit, it gets silently clipped (a visible bug someone will notice and fix by shrinking further) rather than silently starting to scroll again (which defeats the point of this session).
3. **Don't change its size or behavior.** `panelMobile`'s `width`/`height` (`75vw`/`75vh`) stay exactly as `S-MI-45` locked them. The overlay (backdrop blur, click-to-dismiss), the × button, and the `sessionStorage` gate are all unchanged — same component, same interactions, same copy. This session touches typography/spacing values only, plus the one `overflowY` override.

**Rough fit budget (why this works without cutting content):** at a mid-range phone (~390×844), `75vh ≈ 633px`. Scaling every hero-body style to roughly 40-60% of its desktop value (see Task 1's exact numbers) brings the full stack — header (~40px) + eyebrow (~20px) + 3-line headline (~82px) + 3-line subhead (~65px) + CTA button (~54px) + capability strip (~40px) + padding — to roughly 300-350px total, well under the 525-630px realistic budget even at a smaller phone. **Live-verify this exact math in Task 1's checklist — if it's tighter than expected on a real device, shrink further rather than falling back to scroll or cutting copy.**

`STYLE-GUIDE.md` §23's 2026-07-13 amendment is already locked and is the source of truth for the rule above.

**5c — Wire the mobile branch in the JSX.** `isMobile` is already available (imported and called in `S-MI-45`). Swap every style prop to its mobile variant when `isMobile` is true — the cleanest approach is a small per-render style resolver rather than a long ternary chain in the JSX:

  const isMobile = useIsMobile();

    if (sessionStorage.getItem(STORAGE_KEY)) return;

  function dismiss() {
    sessionStorage.setItem(STORAGE_KEY, "1");
    setVisible(false);
  }

  if (!visible) return null;

  // FEATURE: SH-22 — mobile uses a fully separate, smaller style scale so the whole
  // panel fits within the fixed 75vh with zero scroll; panel size/behavior unchanged.
  const s = isMobile ? {

  };

  return (
    <div style={overlay} onClick={(e) => { if (e.target === e.currentTarget) dismiss(); }}>
      <div style={s.panel}>
        <button style={s.close} onClick={dismiss} aria-label="Close">×</button>

        <div style={s.header}>
          <div style={logoWrap}>
            <div style={s.logoMark}>DB</div>
            <span style={s.logoName}>DeepBench</span>
          </div>
        </div>

        <div style={s.body}>
          <div style={s.eyebrow}>
            <span style={s.eyebrowLine} />
            AI Consulting Management Platform
          </div>

          <h1 style={s.headline}>
            Your consulting practice,<br />
            running at{" "}
            <em style={{ fontStyle: "italic", color: T.brass }}>full capacity</em>
            <br />
            around the clock.
          </h1>

          <p style={s.subhead}>
            DeepBench gives your practice an AI workforce — agents that carry your methodology,

            only you can do.
          </p>

          <button style={s.cta} onClick={dismiss}>
            Start or see your Consulting Management practice in action
            <svg width="14" height="14" viewBox="0 0 14 14" fill="none" style={{ marginLeft: 8, flexShrink: 0 }}>
